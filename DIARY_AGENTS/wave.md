# Wave 공통 절차

`spec-wave`, `design-wave`, `testcase-wave`가 공통으로 따르는 절차다. `testcode-wave`는 이 문서에서 `대상 문서 탐색`만 따른다. 단계 순서와 게이트는 [DIARY_AGENTS.md](../DIARY_AGENTS.md)의 `작업 iterator`, 문서 종류별 소유 범위는 [docs/README.md](../docs/README.md)를 따른다.

## 대상 문서 탐색

사용자가 지정한 파일, 화면 또는 기능을 우선 범위로 삼는다. 지정 범위가 없으면 다음 순서로 찾는다.

1. `docs/README.md`와 해당 폴더의 `README.md` 목록에서 대상 문서를 찾는다.
2. 목록에 없으면 `rg --files docs`로 기능명과 일치하는 slug를 찾는다.
3. 대상 문서가 링크하는 상위 문서와 공통 문서를 함께 읽는다.

같은 slug는 `docs/spec`, `docs/design`, `docs/testcase`에서 같은 대상을 가리킨다. `docs/spec`은 `client`, `common`, `server` 하위 폴더에 같은 slug가 여러 개 있을 수 있으며, 폴더 구분은 [docs/spec/README.md](../docs/spec/README.md)를 따른다. 범위를 추론할 수 없거나 대상 후보가 여러 개면 작성 전에 사용자에게 확인한다.

## 작성 전 검토

각 wave는 작성보다 충돌과 공백 식별을 우선한다. 다음은 어느 wave에서든 작성을 멈추는 조건이다.

- 상위 문서가 정하지 않은 제품 판단이 필요하다.
- 상위 문서와 다른 결과를 요구해야 한다.
- 같은 대상에 대해 기존 문서가 서로 다른 결과를 정의한다.
- 같은 용어가 문서마다 다른 의미로 쓰인다.

보고 형식은 [confirm.md](confirm.md)를 따르고, `근거` 자리에는 비교한 문서 이름을 쓴다.

## 문서에 남기지 않는 것

검토는 작성 전 내부 절차다. 산출 문서에는 다음을 남기지 않는다.

- 충돌 검토 결과나 별도 검토 섹션(충돌이 없을 때)
- 관련 없는 기존 문서의 요약, 외부 문서 조사 과정, 구현 근거
- 상위 문서 문장의 반복. 맥락이 필요하면 한 문장으로 줄이고 상위 문서를 링크한다.

외부 공식 문서가 판단 기준이면 문서 마지막 `참고` 섹션에 다시 확인할 링크만 남긴다.

## 문서 계층화

같은 내용을 두 문서 이상이 반복하면 그 내용을 소유하는 공통 문서로 분리하고, 나머지 문서는 링크로 참조한다. 어떤 내용을 분리할지는 각 wave 문서가 정하며, 분리 자체의 절차는 다음을 따른다.

분리 대상을 발견하면 임의로 나누기 전에 무엇을 어디로 옮길지와 옮긴 뒤 각 문서에 남는 내용을 사용자에게 설명하고 결정을 받는다. 문서 소유 범위가 바뀌면 그 문서를 읽는 다른 wave의 기준도 함께 바뀌기 때문이다.

분리할 때 다음을 지킨다.

- 공통 문서는 자신이 소유하는 내용만 담고, 화면마다 다른 결정은 각 문서에 남긴다.
- 참조하는 문서에서는 반복 문장을 지우고, 그 문서에만 있는 차이만 남긴다.
- 공통 문서를 참조하는 문서 목록을 공통 문서에 적어 어디에 영향을 주는지 드러낸다.
- 새 문서는 해당 폴더 `README.md` 목록에 등록하고, 상대 문서 종류의 문서에도 같은 계층이 있으면 서로 연결한다.

한 문서가 서로 다른 대상을 함께 다루어 커지고 있으면 대상별로 나누는 것도 같은 절차로 검토한다.

## 다이어그램

글보다 그림으로 명확해지는 결정은 Mermaid 다이어그램을 함께 둔다. 어떤 내용에 다이어그램을 쓸지는 각 wave 문서가 정하며, 표기는 다음으로 통일한다.

- 분기와 처리 순서는 `flowchart`, 상태와 상태 전이는 `stateDiagram-v2`를 쓴다.
- 노드 라벨은 큰따옴표로 감싸고, 줄바꿈은 `<br/>`을 쓴다.
- 간선 라벨은 `-- 라벨 -->` 형태로 쓴다.
- `stateDiagram-v2`의 상태는 `Id: 표시 이름` 형태로 선언하고 전이 라벨은 `: 라벨`로 쓴다.

다음을 지킨다.

- 다이어그램은 본문 설명을 대체하지 않는다. 정확한 값, 문구, 예외는 글로 남긴다.
- 분기가 둘 이하이거나 순서가 한 줄로 읽히는 내용에는 다이어그램을 두지 않는다.
- 다이어그램에 그 문서가 소유하지 않는 결정을 그리지 않는다.

## 미확정 표기

확정되지 않은 내용은 단정하지 않고 `미정` 또는 `사용자 확인 필요`로 표시한다. 미확정 결정이 남은 초안은 정식 문서와 README 목록에 반영하지 않는다.

## 완료 후 반영

문서를 새로 만들거나 이름을 바꾸면 해당 폴더 `README.md`의 목록과 다른 문서의 링크를 함께 갱신한다.
