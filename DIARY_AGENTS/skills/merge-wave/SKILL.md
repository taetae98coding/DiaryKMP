# Merge Wave

현재 브랜치를 대상 브랜치로 fast-forward 머지하는 게이트다. 리베이스와 컨플릭 해결은 `rebase-wave`가, 커밋 생성은 `commit-wave`가 소유하고 이 wave는 하지 않는다.

## 대상 브랜치

`rebase-wave`에서 확정한 대상 브랜치를 그대로 쓴다.

이 wave만 단독으로 요청받아 확정된 대상 브랜치가 없으면 `git branch -a`로 후보를 제시하고 사용자가 고른 브랜치만 대상으로 삼는다. 현재 브랜치가 대상 브랜치와 같으면 머지할 것이 없으므로 중단하고 보고한다.

## 선행 조건

1. `git status`로 작업 트리를 확인한다. 추적 중인 파일에 staged 또는 unstaged 변경이 있으면 커밋되지 않은 작업 결과이므로 머지하지 않고 보고한 뒤 지시를 받는다. untracked 파일은 목록만 보고하고 진행한다.
2. `git merge-base --is-ancestor <대상 브랜치> HEAD`로 대상 브랜치가 현재 브랜치의 조상인지 확인한다. 조상이 아니면 리베이스되지 않았거나 리베이스 이후에 대상 브랜치가 움직인 것이므로 머지하지 않고 보고한 뒤 `rebase-wave`부터 다시 시작한다.

## 머지

머지는 항상 `git merge --ff-only <현재 브랜치>`로 하고, 실행 위치는 대상 브랜치가 어디에 체크아웃돼 있는지에 따라 정한다. `git worktree list --porcelain`으로 확인한다.

- 다른 worktree에 체크아웃돼 있으면 그 worktree에서 `git -C <경로> merge --ff-only <현재 브랜치>`로 실행한다. 그 worktree에 커밋되지 않은 변경이 있으면 머지하지 않고 보고한 뒤 지시를 받는다.
- 어느 worktree에도 체크아웃돼 있지 않으면 현재 worktree에서 대상 브랜치로 전환해 머지하고, 머지 후 원래 브랜치로 돌아온다.

fast-forward가 되지 않으면 머지하지 않고 보고한다. 리베이스 이후에 대상 브랜치가 움직였다는 뜻이므로 `rebase-wave`부터 다시 시작한다.

머지 뒤 `push`, 브랜치 삭제, 태그 생성은 사용자 지시가 있을 때만 한다. `push --force`는 어떤 경우에도 하지 않는다.

## 실패 처리

머지에 실패하면 대상 브랜치를 건드리지 않은 상태 그대로 두고 실패한 명령과 핵심 오류를 보고한다. 되돌리거나 강제하는 명령을 임의로 실행하지 않는다.

대상 브랜치로 전환한 뒤 실패했으면 원래 브랜치로 돌아온 상태에서 보고한다.
