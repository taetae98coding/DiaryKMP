# Testcase Wave

`docs/testcase`의 테스트 케이스 문서를 작성하거나 갱신한다.

공통 절차는 `DIARY_AGENTS/wave.md`를 따른다. 문서 탐색, 멈추는 조건, 문서에 남기지 않을 내용은 그 문서가 소유하고, 충돌·공백 보고 형식은 `DIARY_AGENTS/confirm.md`가 소유한다.

문서 소유권, 케이스 항목, 고유 ID 형식은 `docs/testcase/README.md`를 따른다.

## 원칙

확정된 스펙을 기대 결과의 유일한 근거로 삼는다. 스펙만 지정된 경우 `docs/spec/<slug>.md`에 대응하는 `docs/testcase/<slug>.md`를 대상으로 한다.

QA 전문가가 코드를 보지 않고도 실행 조건과 기대 결과를 이해할 수 있게 쓴다. 각 케이스는 하나의 구분 가능한 행동이나 규칙을 검증하고, 같은 입력과 기대 결과를 `feature`, `domain`, `data`에 반복하지 않는다.

## 블랙박스 테스트 가능성 판정

다음을 모두 만족하는 동작만 작성한다.

- 스펙에 입력, 사용자 행동, 사전 상태 또는 발생 조건이 정의되어 있다.
- 기대 결과를 화면, 공개된 상태, 반환 결과, 외부 경계의 요청이나 응답으로 표현할 수 있다.
- 외부 시스템의 응답 조건을 제어하면 실제 네트워크, 데이터베이스, 파일 시스템, 플랫폼 SDK 또는 브라우저 없이 반복 실행할 수 있다.
- 구현 구조를 몰라도 Given, When, Then을 이해하고 동일한 결과를 판정할 수 있다.

다음은 작성하지 않는다.

- 클래스 호출, 함수 위임, 내부 Effect 발행, 내부 상태 객체 변경만 확인하는 항목
- mock 호출 횟수, fixture 값, DTO 매핑처럼 자동화 구현만 설명하는 항목
- 실제 화면의 픽셀, 색상, 크기, 위치, 간격, 애니메이션을 확인하는 항목
- 실제 로그인 창, 브라우저, OS 동작, 플랫폼 SDK, 서버, 데이터베이스, 파일 시스템, 네트워크의 결과를 확인하는 항목
- 여러 화면이나 실제 앱 전체를 통과해야 하는 통합 또는 E2E 항목
- 사람의 주관적인 시각 판단이 필요한 항목

외부 연동이 있는 스펙은 실제 연동 성공 여부 대신, 앱이 외부 경계에 요청한 내용과 제어된 성공·취소·실패 응답에 따른 관찰 가능한 결과를 쓴다. 기술 스펙에 공개된 요청·응답 필드는 블랙박스 계약으로 쓸 수 있다.

같은 Given과 When에서 Then을 반복 판정할 수 없으면 케이스를 억지로 만들지 않고 `작성하지 않는 이유`를 남긴다.

## 코드 확인 범위

스펙에서 케이스 초안을 먼저 도출한 뒤, 다음 목적으로만 코드를 읽는다.

- 기존 문서가 최신 스펙과 구현 범위를 빠뜨렸는지 확인
- 현재 테스트 환경에서 결정적으로 자동화할 수 있는지 확인
- 이미 존재하는 테스트 코드와 고유 ID의 추적 관계 확인

코드에서 발견한 동작을 요구사항으로 추가하지 않고, 확인 결과를 본문에 쓰지 않는다. 스펙과 코드가 다르면 테스트 케이스를 코드에 맞추지 말고 불일치를 사용자에게 알린다.

## 케이스 도출

1. 스펙에서 확정된 사용자 행동, 조건, 규칙, 상태 전이, 데이터 계약을 찾는다.
2. 사용자 진행 상태가 있는 기능은 화면 재생성, 앱 재실행, 백그라운드 복귀 경계의 정책이 스펙에 있는지 확인한다. 있으면 각 경계를 독립 후보로 만들고, 없으면 정책 공백으로 알린다.
3. 각 후보의 관찰자와 외부에서 확인할 결과를 정한다.
4. 각 후보를 Given, When, Then으로 표현한다.
5. 구현 내부에서만 관찰할 수 있거나 결정적으로 자동화할 수 없는 후보를 제외한다.
6. 책임에 따라 `feature`, `domain`, `data` 중 한 영역에만 배치한다.
7. 정상, 오류, 취소, 재시도, 경계값은 스펙이 다른 결과를 정의할 때만 나눈다.
8. 같은 결과를 공유하는 조건은 테스트 데이터 표로 묶고, 결과가 다르면 별도 케이스로 나눈다.

영역 구분은 다음을 기준으로 한다.

- `feature`: 화면에서 수행하는 행동과 그 결과로 관찰하는 화면 상태, 문구, 노출 여부, 진행 상태, 오류 안내, 화면 전환
- `domain`: UI나 저장 방식과 무관한 제품 규칙의 입력 조건과 판정 결과
- `data`: 스펙에 명시된 데이터 계약의 요청, 응답, 저장 결과 또는 유지 여부

## 고유 ID 부여

새 ID를 부여하기 전에 저장소의 모든 테스트 케이스 문서와 Git 이력에서 기존 ID를 검색한다.

- 같은 행동을 명확히 표현하는 수정은 ID를 유지한다.
- 기대 행동의 의미가 달라지거나 영역이 바뀌면 새 ID를 부여한다.
- 새 케이스는 해당 영역에서 사용된 가장 큰 번호 다음 번호를 쓴다.
- ID 중복을 발견하면 임의로 변경하지 말고 위치와 정리 선택지를 사용자에게 알린다.

## 다이어그램

표기와 공통 제약은 `DIARY_AGENTS/wave.md`의 `다이어그램`을 따른다. 테스트 케이스에서는 여러 케이스가 하나의 판정 기준이나 상태 전이를 나누어 덮을 때, 그 묶음의 앞에 어느 경로를 어느 ID가 덮는지 드러내는 다이어그램을 둘 수 있다.

- 판정 분기: 각 결과 노드에 그 결과를 검증하는 ID를 적어 덮지 않은 분기를 드러낸다.
- 상태 전이: 각 전이 라벨에 그 전이를 검증하는 ID를 적는다.

다음을 지킨다.

- 다이어그램은 스펙이 정의한 경로만 그린다. 스펙에 없는 경로를 그려 케이스를 늘리지 않는다.
- 다이어그램이 개별 케이스의 `Given`, `When`, `Then`을 대체하지 않는다.
- 케이스가 셋 이하이거나 경로가 갈리지 않는 묶음에는 두지 않는다.
- 덮지 않은 경로가 드러나면 임의로 케이스를 만들지 말고, 자동화할 수 있는지 판정한 뒤 케이스를 추가하거나 `작성하지 않는 이유`를 남긴다.

## 문서 계층화

절차는 `DIARY_AGENTS/wave.md`의 `문서 계층화`를 따른다. 테스트 케이스 문서는 기준 스펙과 1:1로 두는 것이 기본이며, 다음을 지킨다.

- 여러 화면이 공유하는 공통 스펙에는 전용 문서를 두지 않고, 그 스펙을 사용하는 화면 문서에 케이스를 둔다. 어느 문서가 갖는지는 `docs/testcase/README.md`에 등록한다.
- 이때 케이스의 `근거`는 케이스가 실제로 검증하는 화면 스펙의 절을 가리키고, 공통 스펙에 위임된 규칙이라는 사실은 문서 상단에 한 문장으로 적는다.
- 스펙이 공통 스펙으로 분리되어도 ID의 `SPEC`은 그 케이스가 있는 문서의 기준 스펙 slug를 유지한다. 문서를 옮기지 않았다면 ID를 다시 부여하지 않는다.
- 문서가 커져도 같은 기준 스펙의 케이스를 여러 파일로 나누지 않는다. 나누면 `SPEC`과 파일의 대응이 깨져 ID 중복 검색이 어려워진다. 문서 크기가 문제면 스펙 자체의 분리를 먼저 검토한다.

## 문서 형식

```markdown
# Login 테스트 케이스

기준 스펙: [Login 화면 스펙](../spec/login.md)

## feature

### TC-LOGIN-FEATURE-001: Google 로그인을 시작한다

- 근거: `feature > 로그인 진행`
- Given: 로그인 요청이 진행 중이지 않고 Login 화면이 표시되어 있다.
- When: 사용자가 Google 로그인 버튼을 선택한다.
- Then: 현재 플랫폼의 Google 로그인 흐름이 한 번 시작된다.
```

케이스 항목의 종류와 `작성하지 않는 이유`에 적을 내용은 `docs/testcase/README.md`가 소유한다.

## 기존 문서 갱신

대상 스펙과 전체 케이스를 다시 비교한다.

- 유효한 행동과 ID는 유지하고 구현 용어만 블랙박스 표현으로 바꾼다.
- 같은 외부 행동을 중복 검증하는 케이스는 하나로 통합한다.
- 독립된 외부 결과가 없는 케이스와 스펙에서 제거된 행동의 케이스는 삭제하고 ID를 재사용하지 않는다.
- 스펙 행동은 유효하지만 자동화할 수 없으면 `작성하지 않는 이유`와 함께 유지한다.

## 완료 전 확인

- 모든 기대 결과가 확정된 스펙에 근거하고, 기준 스펙 링크와 각 케이스의 근거가 정확함
- 외부 연동 케이스의 Given에 제어할 응답 조건이 드러남
- 사용자 진행 상태가 있는 기능의 실행 경계 정책과 케이스 누락 여부를 확인함
- 모든 ID가 고유하며 기존 ID가 재번호화되거나 재사용되지 않음
- 공통 스펙의 케이스 위치가 `docs/testcase/README.md`에 등록됨
