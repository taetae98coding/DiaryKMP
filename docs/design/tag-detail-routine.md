# TagDetail 루틴 탭 디자인

기준 스펙: [TagDetail 루틴 탭 스펙](../spec/client/tag-detail-routine.md)

화면 전체의 구조, 상단 바, 탭 행, 페이지 전환과 떠 있는 버튼의 교체는 [TagDetail 화면 디자인](./tag-detail.md)이 소유한다. 이 문서는 루틴 탭 안의 표현만 정한다.

## 탭 구성

루틴 탭 안은 위에서부터 완료된 루틴 진입 줄과 루틴 목록을 세로로 쌓는다. 기준 스펙에 따라 사용자가 고를 수 있는 정렬이 없으므로 진입 줄에 정렬 컨트롤은 두지 않는다. 진입 줄과 첫 루틴 사이의 간격은 목록의 [화면 세로 여백](./dimens.md)이 만든다. RoutineHome의 필터 버튼과 보기 전환은 이 탭에 두지 않으며, 이 탭에는 달력 보기가 없다.

루틴 탭은 대상 태그의 조회 상태와 관계없이 같은 구성을 표시한다. 태그를 아직 조회하지 못해 상단 바에 제목이 없는 동안에도 진입 줄과 목록은 같은 기준으로 표시한다.

## 완료된 루틴 진입

탭 줄 바로 아래, 루틴 목록 위에 완료된 루틴 진입 줄을 두고 그 끝 쪽에 완료된 루틴 진입 버튼을 둔다. 줄의 높이와 좌우 바깥 여백, 시작 쪽을 비워 두는 것은 [RoutineHome 화면 디자인](./routine-home.md)의 `완료된 루틴 진입`과 같고, 버튼의 해부구조, 폭, 상태, 조작과 접근성은 [목록 진입 버튼 디자인](./list-entry-button.md)을 따른다.

버튼의 라벨에는 `문구와 접근성`의 완료된 루틴 진입 라벨을 쓴다.

버튼을 누르면 같은 태그의 TagRoutineFinishedList 화면을 표시하고, 화면의 구조와 문구는 [TagRoutineFinishedList 화면 디자인](./tag-routine-finished-list.md)을 따른다.

대상 태그를 아직 조회하지 못해 상단 바에 제목이 없는 동안에도, 표시 범위를 넓혀 두었어도, 목록이 비어 있어도 버튼은 같은 모양으로 표시한다. 다른 탭을 선택한 동안에는 이 줄과 버튼이 보이지 않는다.

## 루틴 추가

루틴 추가는 [TagDetail 화면 디자인](./tag-detail.md)의 `떠 있는 버튼`에 따라 루틴 탭을 선택한 동안 떠 있는 루틴 추가 버튼으로 제공한다. 버튼에는 추가를 나타내는 플러스 아이콘을 쓰며, 이는 [RoutineHome 화면 디자인](./routine-home.md)의 추가 버튼과 같은 아이콘이다. 대상 태그의 완료 여부와 삭제 여부는 이 버튼의 노출을 바꾸지 않는다.

루틴 추가를 선택하면 RoutineAdd 화면을, 루틴 카드를 선택하면 RoutineDetail 화면을 표시한다. 두 화면은 창 너비와 관계없이 TagDetail 화면과 함께 배치하지 않고 단독으로 표시한다. RoutineHome에서 진입할 때 쓰는 [Routine 목록·상세 배치 디자인](./routine-list-detail.md)은 이 경로에 적용하지 않는다.

RoutineAdd 화면은 대상 태그를 태그 입력에 이미 고른 상태로 시작한다. 그 표현은 [항목 태그 입력 컴포넌트 디자인](./entity-tag-input.md)의 태그 칩을 따르며, 별도의 강조나 잠금 표시를 두지 않아 사용자가 그 태그를 해제할 수 있음을 드러낸다.

## 목록

루틴 카드의 컬러 원형 표시와 제목, 카드 문구, 달성률과 진행 막대의 표현, 카드 문구의 언어별 표기와 바뀔 때의 표현은 [RoutineHome 화면 디자인](./routine-home.md)의 `루틴 카드`를 따르고, 카드는 같은 문서의 `루틴 목록`에 따라 1열 목록으로 놓는다.

카드에는 빠른 기록 버튼을 두지 않는다. 버튼이 있던 자리는 비워 두지 않고 제목과 카드 문구가 카드의 가로 폭을 모두 쓴다. 카드를 길게 눌러도 양을 입력하는 창이 열리지 않으며, 카드는 누르는 조작과 `완료·삭제 제스처와 피드백`의 스와이프만 받는다. 시작 전인 루틴의 카드도 진행 중인 루틴의 카드와 같은 조작을 받는다.

카드에는 그 루틴이 연결한 태그를 표시하지 않는다. 이 목록에 있는 루틴은 모두 표시 범위 안 태그와 연결되어 있어 태그 표시가 항목을 구분해 주지 않기 때문이다.

목록에는 완료되지 않은 루틴만 놓인다. 목록은 세로로만 스크롤하고, 진행 상태로 항목을 묶는 헤더는 두지 않는다. 진행 중과 시작 전의 구분은 카드 문구가 알린다.

## 자리 표시

아직 준비되지 않은 자리에는 [페이지 조회 목록의 자리 표시 디자인](./paged-list-placeholder.md)에 따라 자리 표시 카드를 표시한다. 자리 표시 카드의 비움 형태는 [RoutineHome 화면 디자인](./routine-home.md)의 `자리 표시`와 같다.

## 빈 상태와 조회 실패

기준 스펙의 `빈 상태` 조건을 만족하면 목록 자리에 [목록 빈 상태 디자인](./list-empty-state.md)의 빈 상태를 표시한다. 아이콘과 제목·보조 문구는 그 문서의 표가 소유한다. 빈 상태에서도 진입 줄의 완료된 루틴 진입 버튼과 떠 있는 루틴 추가 버튼은 같은 자리에 그대로 표시한다.

조회 실패에는 별도 오류 안내나 재시도 버튼을 표시하지 않는다. 조회에 실패해 표시할 루틴이 없을 때도 같은 빈 상태를 사용한다.

목록의 스크롤 위치는 다른 탭에 다녀와도 그대로 유지한다.

## 완료·삭제 제스처와 피드백

[SwipeToFinishAndDelete 컴포넌트 디자인](./swipe-to-finish-and-delete.md)에 따라 카드를 왼쪽에서 오른쪽으로 스와이프하면 완료하고, 오른쪽에서 왼쪽으로 스와이프하면 삭제한다.

완료 또는 삭제 뒤의 피드백과 실행 취소는 스낵바로 표시한다. 스낵바는 [TagDetail 화면 디자인](./tag-detail.md)의 화면 공통 자리를 사용하고, 떠 있는 버튼에 가리지 않는 자리에 둔다.

실행 취소로 돌아온 카드는 기준 스펙의 `루틴 노출과 순서`에 맞는 자리에 다시 나타난다.

## 새로고침

목록을 아래로 당겨 새로고침하며, 당기는 조작과 진행 표시는 [새로고침 디자인](./sync-refresh.md)을 따른다. 목록이 빈 상태일 때도 같은 자리에서 당길 수 있다. 완료된 루틴 진입 줄은 당김 컨테이너에 넣지 않는다.

## 키보드 단축키

루틴 탭을 선택한 동안 물리 키보드로 `Command + A`를 눌러 루틴을 추가한다. 단축키 표는 [TagDetail 화면 디자인](./tag-detail.md)의 `키보드 단축키`가 소유한다.

다른 탭을 선택한 동안에는 이 단축키를 처리하지 않는다.

## 문구와 접근성

한국어 환경과 그 외 기본 환경에서는 다음 문구를 사용한다.

| 문구 | 한국어 | 그 외 기본 |
| --- | --- | --- |
| 완료된 루틴 진입 라벨 | `완료된 루틴` | `Finished routines` |
| 추가 버튼 접근성 이름 | `루틴 추가` | `Add routine` |
| 완료 안내 | `루틴이 완료되었습니다.` | `Routine finished.` |
| 삭제 안내 | `루틴이 삭제되었습니다.` | `Routine deleted.` |
| 실행 취소 동작 | `실행 취소` | `Undo` |
| 완료 스와이프 아이콘 접근성 이름 | `루틴 완료` | `Finish routine` |
| 삭제 스와이프 아이콘 접근성 이름 | `루틴 삭제` | `Delete routine` |

루틴 카드의 접근성 이름은 [RoutineHome 화면 디자인](./routine-home.md)의 `루틴 카드`에서 빠른 기록 버튼의 이름을 뺀 것을 따른다. 빈 상태 문구는 [목록 빈 상태 디자인](./list-empty-state.md)의 문구 표가 소유한다.
