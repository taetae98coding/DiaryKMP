# SettingGemini 화면 디자인

기준 스펙: [SettingGemini 화면 스펙](../spec/client/setting-gemini.md), [Gemini 모델 목록 조회 스펙](../spec/client/gemini-model-list.md)

## 화면 구조

SettingGemini의 단독·목록/상세 배치와 표시 상태에 따른 뒤로가기 동작 노출은 [Setting 목록·상세 배치 디자인](./setting-list-detail.md)을 따른다.

화면 상단에는 제목이 있는 상단 바를 두고, 뒤로가기 동작을 제공하는 상태에서는 상단 바에 함께 배치한다.

본문에는 API 키 입력, 모델 선택 줄, 시스템 프롬프트 입력을 이 순서로 세로로 배치하고 각 사이에 [구성요소 간격](./dimens.md)을 둔다. 본문이 표시 영역보다 길어지면 위아래로 스크롤할 수 있다.

이 순서는 사용자가 값을 채우는 순서와 같다. 모델을 고르려면 API 키가 먼저 있어야 하므로 API 키 입력을 맨 위에 둔다.

저장 동작은 본문 위에 떠 있는 버튼으로 표시한다. 시스템 프롬프트가 길어져 본문을 스크롤해도 저장 동작이 같은 자리에 남아 있게 하기 위한 것이다.

저장된 설정을 확인하기 전이거나 읽지 못한 상태에서는 본문의 세 입력과 저장 버튼을 자리까지 함께 표시하지 않고 상단 바만 남긴다. 별도의 로딩 안내나 오류 안내도 표시하지 않는다.

## API 키 입력

API 키 입력은 `API 키` 라벨이 붙은 단일 줄 텍스트 입력을 카드 안에 두고 본문 좌우 폭을 모두 사용한다. 입력의 밑줄은 표시하지 않는다.

입력한 값은 기본적으로 한 글자씩 가려서 표시한다. 입력의 끝 쪽에는 가림을 켜고 끄는 버튼을 두어 사용자가 지금 넣은 값을 확인할 수 있게 한다. 버튼의 아이콘은 가려진 동안 눈 모양을, 보이는 동안 눈에 사선이 그어진 모양을 쓴다.

가림을 끈 상태는 화면을 떠나거나 화면이 재생성되면 다시 가린 상태로 되돌린다. 사용자가 켜 둔 것을 잊고 화면을 열어 두는 일을 막기 위한 것이다.

소프트 키보드는 일반 텍스트 키보드를 요청하고 자동 수정과 자동 대문자 변환을 사용하지 않는다. 키보드의 동작 키는 다음으로 표시하고, 누르면 시스템 프롬프트 입력으로 초점을 옮긴다.

## 모델 선택

모델 선택 줄은 카드 안에 두고 본문 좌우 폭을 모두 사용하며, [카드 내용](./styles.md) 안쪽 여백 안에서 `모델` 라벨 아래에 현재 선택한 모델을 한 줄로 표시하고, 줄 끝에 다음 단계로 이어짐을 알리는 오른쪽 화살표 아이콘을 둔다. 줄 전체를 누를 수 있는 자리로 두고 버튼 역할을 제공한다.

현재 선택한 모델은 표시 이름이 아니라 모델 식별자로 표시하고, 폭을 넘으면 끝을 줄임표로 줄인다. 저장되는 값이 식별자이고, 모델 목록을 받아 오기 전에는 표시 이름을 알 수 없기 때문이다. 모델을 고르지 않았으면 선택하지 않았다는 문구를 대신 표시한다.

사용자가 이 줄을 누르면 모델 선택 다이얼로그를 연다. 받아 둔 모델 목록이 없으면 다이얼로그를 열면서 모델을 불러온다. 사용자가 이 줄을 누르는 것이 곧 기준 스펙의 모델 조회 실행이다.

API 키 입력이 비어 있거나 공백만 있는 상태에서 이 줄을 누르면 다이얼로그를 열지 않고 API 키 입력이 필요하다는 안내를 스낵바로 표시한다. 줄을 비활성 상태로 남기지 않는 것은 눌러 보기 전에는 사용자가 왜 누를 수 없는지 알기 어렵기 때문이다.

모델을 불러온 뒤 그 목록에 현재 선택한 모델이 없으면 현재 모델 아래에 목록에 없는 모델이라는 보조 문구를 작은 글씨와 오류 색으로 표시한다. 이 문구는 한 번이라도 목록을 받아 온 뒤에만 표시하고, 선택 자체는 바꾸지 않는다.

## 모델 선택 다이얼로그

다이얼로그 위쪽에는 `모델 선택` 제목을 두고, 그 아래 내용 영역의 끝 쪽에 목록을 다시 불러오는 버튼을 아이콘 버튼으로 둔다. 아이콘은 새로고침 모양을 쓴다.

다이얼로그 본문에는 모델을 세로 목록으로 표시하고, 목록 전체 높이가 본문보다 크면 세로로 스크롤할 수 있게 한다. 항목 사이에는 [항목 간격](./dimens.md)을 둔다.

각 항목의 시작 쪽에는 라디오 버튼을 두고, 그 옆에 위에서 아래로 모델의 표시 이름, 모델 식별자, 설명을 둔다. 표시 이름이 비어 있는 모델은 표시 이름 자리에 모델 식별자를 표시한다. 표시 이름은 한 줄, 식별자는 그 아래 작은 글씨와 낮은 강조 색으로 한 줄, 설명은 그 아래 같은 글씨와 색으로 최대 두 줄까지 표시하고 넘치면 끝을 줄임표로 줄인다. 설명이 없는 모델에서는 설명 줄의 자리를 남기지 않는다. 항목의 위아래에는 `8dp` 안쪽 여백을 둔다.

현재 선택한 모델의 항목만 라디오 버튼을 선택 상태로 표시한다. 항목 전체를 누를 수 있는 자리로 두고, 누르면 그 모델을 현재 선택으로 정하면서 다이얼로그를 닫는다. 모델을 고르는 것이 곧 확인이므로 확인 버튼을 두지 않는다.

사용자는 다이얼로그 바깥을 누르거나 뒤로가기로 다이얼로그를 닫을 수 있고, 이때 선택은 바뀌지 않는다. 닫기 버튼은 두지 않는다.

다이얼로그의 너비와 높이는 다른 선택 다이얼로그와 같이 대화상자 컴포넌트의 기본값을 따른다. 모델이 많아 목록이 길어지면 다이얼로그를 늘리지 않고 목록 영역만 스크롤한다.

다이얼로그를 닫아도 받아 둔 모델 목록은 남는다. 다시 열면 불러오지 않고 남아 있는 목록을 그대로 보여 주며, 사용자는 다시 불러오기 버튼으로만 새로 불러온다.

### 다이얼로그 본문의 상태 표현

| 상태 | 다이얼로그 본문의 표시 |
| --- | --- |
| 불러오는 중이고 받아 둔 목록이 없음 | 가운데 정렬한 진행 표시 |
| 불러오는 중이고 받아 둔 목록이 있음 | 직전 목록을 그대로 두고 다시 불러오기 버튼만 진행 표시로 바꿈. 진행 표시는 [공통 여백과 간격](./dimens.md)의 `진행 표시 크기`로 두고 둘레에 `12dp` 여백을 두어 아이콘 버튼과 같은 자리를 차지한다 |
| 모델 있음 | 모델 항목 목록 |
| 모델 없음 | 가운데 정렬한 안내 문구 |
| API 키가 유효하지 않아 실패 | 가운데 정렬한 안내 문구와 다시 시도 버튼 |
| 그 밖의 이유로 실패 | 가운데 정렬한 안내 문구와 다시 시도 버튼 |

가운데 정렬하는 진행 표시, 안내 문구, 실패 안내는 최소 높이 `120dp`인 본문 영역의 가운데에 둔다. 실패 안내는 두 경우 모두 같은 자리에 같은 크기로 표시하고 문구만 다르게 둔다. 목록이 스스로 다시 불러와지지 않으므로 실패 안내에는 다시 시도 버튼을 함께 둔다.

받아 둔 목록이 있는 상태에서 다시 불러오기에 실패하면 다이얼로그를 실패 안내로 바꾸지 않고 직전 목록을 그대로 둔 채 실패를 스낵바로 알린다. 사용자가 이미 고를 수 있던 목록을 잃지 않게 하기 위한 것이다.

## 시스템 프롬프트 입력

시스템 프롬프트 입력은 `시스템 프롬프트` 라벨이 붙은 여러 줄 텍스트 입력을 카드 안에 두고 본문 좌우 폭을 모두 사용한다. 입력의 밑줄은 표시하지 않는다.

입력의 높이는 다섯 줄 분량을 기본으로 하고 내용이 늘어나면 함께 늘어난다. 최대 높이는 두지 않으며 본문 스크롤로 나머지를 볼 수 있게 한다.

소프트 키보드는 일반 텍스트 키보드를 요청하고, 키보드의 동작 키는 줄바꿈으로 표시한다. 여러 줄을 입력하는 자리이므로 동작 키로 저장을 실행하지 않는다.

## 저장 동작

저장 버튼은 떠 있는 버튼으로 두고 아이콘은 다른 화면의 저장 동작과 같은 확인 모양을 쓴다. 설정 목록과 함께 표시할 때도 상세 영역 안에 둔다.

편집 중인 API 키, 모델, 시스템 프롬프트 중 하나라도 저장된 값과 다를 때만 저장 버튼을 표시한다. 세 값이 모두 같으면 저장 버튼을 자리까지 감춘다. 버튼이 나타나고 사라지는 표현은 [나타나고 사라지는 버튼 디자인](./button-visibility.md)을 따라 다른 상세 화면의 수정 버튼과 같다.

저장 처리 중에는 저장 버튼의 확인 아이콘을 진행 표시로 바꾼다. 처리 중에도 표시 조건은 그대로 적용하므로, 처리하는 동안 사용자가 세 값을 저장된 값과 같게 되돌리면 진행 표시까지 함께 사라진다.

저장에 성공하면 편집 중인 값이 저장된 값과 같아지므로 저장 버튼은 같은 전환으로 사라진다. 저장에 실패하면 편집 중인 값이 그대로 남아 저장 버튼도 그대로 표시한다.

저장 성공과 저장 실패 피드백은 스낵바로 표시한다.

## 표시 영역과 소프트 키보드

본문, 저장 버튼과 스낵바는 상태 표시 영역, 시스템 탐색 영역과 카메라 컷아웃 등 기기가 가리는 영역을 침범하지 않게 배치한다.

소프트 키보드가 나타나면 세 요소를 키보드 위 영역에 맞춰 배치하고, 초점이 있는 입력이 키보드에 가리지 않도록 본문을 세로로 스크롤한다. 키보드가 닫히면 원래 표시 영역으로 되돌린다.

모델 선택 다이얼로그가 열려 있는 동안에는 소프트 키보드를 닫는다.

## 초점과 키보드 단축키

화면이 열릴 때는 어느 입력에도 초점을 두지 않으므로 소프트 키보드도 열지 않는다. 저장된 값을 확인하러 들어오는 경우가 많아 곧바로 입력을 시작한다고 보지 않기 때문이다.

저장에는 키보드 단축키를 두지 않는다. 시스템 프롬프트 입력이 `Enter`를 줄바꿈으로 사용해 공통 제출 단축키를 그대로 쓸 수 없고, 이 화면만 다른 단축키를 두면 사용자가 익힌 조작과 어긋난다.

모델 선택 다이얼로그가 열려 있는 동안에는 `Esc`로 다이얼로그를 닫을 수 있다.

## 문구와 접근성

한국어 환경과 그 외 기본 환경에서는 다음 문구를 사용한다.

| 문구 | 한국어 | 그 외 기본 |
| --- | --- | --- |
| 상단 바 제목 | `Gemini 설정` | `Gemini Settings` |
| 뒤로가기 접근성 이름 | `뒤로가기` | `Navigate up` |
| API 키 입력 라벨 | `API 키` | `API key` |
| API 키 표시 버튼 접근성 이름 | `API 키 표시` | `Show API key` |
| API 키 가리기 버튼 접근성 이름 | `API 키 가리기` | `Hide API key` |
| 모델 라벨 | `모델` | `Model` |
| 모델 미선택 표시 | `선택 안 함` | `Not selected` |
| 목록에 없는 모델 보조 문구 | `불러온 목록에 없는 모델입니다` | `This model isn't in the loaded list` |
| API 키 미입력 안내 | `API 키를 입력해 주세요.` | `Please enter an API key.` |
| 모델 선택 다이얼로그 제목 | `모델 선택` | `Select model` |
| 다시 불러오기 버튼 접근성 이름 | `모델 다시 불러오기` | `Reload models` |
| 모델 불러오는 중 접근성 이름 | `모델 불러오는 중` | `Loading models` |
| 모델 없음 안내 | `사용할 수 있는 모델이 없습니다` | `No available models` |
| API 키 오류 안내 | `API 키를 확인해 주세요` | `Check your API key` |
| 모델 불러오기 실패 안내 | `모델을 불러오지 못했습니다` | `Couldn't load models` |
| 다시 시도 버튼 | `다시 시도` | `Retry` |
| 시스템 프롬프트 입력 라벨 | `시스템 프롬프트` | `System prompt` |
| 저장 버튼 접근성 이름 | `저장` | `Save` |
| 저장 성공 안내 | `저장되었습니다.` | `Saved.` |
| 저장 실패 안내 | `저장하지 못했습니다.` | `Couldn't save.` |

모델 선택 줄의 접근성 이름은 `모델` 라벨과 현재 선택한 모델을 이어 읽히게 두고, 목록에 없는 모델 보조 문구가 표시되는 동안에는 그 문구까지 이어 읽히게 한다.

모델 항목의 접근성 이름은 표시 이름, 모델 식별자, 설명을 이어 읽히게 두고, 설명이 없으면 표시 이름과 식별자만 읽히게 한다. 선택 상태는 색이 아니라 항목의 선택 여부로도 알 수 있게 한다.

API 키 입력이 가려져 있는 동안에도 화면 낭독 도구가 입력한 값을 글자 단위로 읽지 않게 한다.
