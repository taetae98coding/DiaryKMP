# 목록 정렬 디자인

기준 스펙: [목록 정렬 스펙](../spec/client/list-sort.md)

이 문서는 목록 위에 두는 정렬 줄의 구조와 자리, 정렬 선택 Bottom Sheet의 구성과 조작, 정렬 아이콘과 문구를 소유한다. 목록 항목의 표현과 목록 자체의 배치는 각 화면 디자인이 소유한다.

적용 대상과 목록마다 고를 수 있는 정렬은 [목록 정렬 스펙](../spec/client/list-sort.md)의 `적용 대상`을 따른다.

## 정렬 줄

정렬 줄은 목록 영역 맨 위에 높이가 고정된 한 줄로 두고, 목록을 스크롤해도 사라지지 않는다. 목록에 항목이 없는 동안의 표시는 `항목이 없는 동안의 정렬 줄`을 따른다. 목록 위에 겹쳐 띄우지 않고 자리를 차지하는 줄로 두어 첫 항목을 가리지 않게 한다. 이는 [WebDetail 화면 디자인](./web-detail.md)의 `표시 방식 줄`과 같은 기준이다.

줄의 시작 쪽에는 현재 정렬을 나타내는 컨트롤 하나를 두고, 끝 쪽은 비워 둔다. 다른 목록으로 이동하는 진입 버튼을 둔 화면에서는 [목록 진입 버튼 디자인](./list-entry-button.md)에 따라 그 버튼을 끝 쪽에 두고 같은 줄의 시작 쪽에 정렬 컨트롤을 둔다. 같은 목록을 다른 방식으로 보여 주는 전환 버튼을 둔 화면도 그 버튼을 끝 쪽에 둔다. 지금은 [TagDetail 장소 탭 디자인](./tag-detail-place.md)의 보기 모드 전환 버튼이 여기에 해당한다. 줄을 둘로 나누면 목록이 쓸 수 있는 높이만 줄기 때문이다. 컨트롤에는 현재 정렬의 아이콘, 현재 정렬의 이름, 선택 목록을 열 수 있음을 뜻하는 아래 방향 화살표 아이콘을 시작 쪽에서부터 이 순서로 두고, 세 요소 사이에는 각각 `4dp` 간격을 둔다. 이름을 함께 두는 것은 아이콘만으로는 어떤 기준으로 정렬되어 있는지 알기 어렵기 때문이다.

이름에는 `문구와 접근성`의 정렬 이름을 그대로 쓰고 줄바꿈하지 않는다. 컨트롤 전체가 하나의 누를 수 있는 대상이며, 누르면 `정렬 선택 Bottom Sheet`를 연다.

컨트롤은 배경을 채우지 않는 글자 버튼으로 두고, 모양은 좌우 끝이 반원인 완전히 둥근 모양으로 한다. 누르는 동안 드러나는 배경이 줄 안에서 하나의 알약으로 읽혀 어디까지가 누를 수 있는 자리인지 드러나기 때문이다. 같은 줄 끝 쪽에 두는 [목록 진입 버튼 디자인](./list-entry-button.md)의 버튼도 같은 모양을 쓴다.

끝 쪽 컨트롤은 라벨을 함께 두는 글자 버튼이거나 아이콘만 두는 아이콘 버튼이며, 어느 쪽인지는 그 버튼을 쓰는 화면 디자인이 정한다. 같은 줄의 끝 쪽에 다른 컨트롤을 함께 둔 화면에서 줄의 폭이 모자라면, 끝 쪽 컨트롤은 내용에 맞는 폭을 그대로 유지하고 정렬 컨트롤이 먼저 줄어든다. 정렬 컨트롤이 줄어들 때도 이름은 한 줄을 유지한 채 끝을 줄임표로 줄이고, 아이콘과 아래 방향 화살표 아이콘은 감추지 않는다. 정렬 컨트롤은 지금 적용된 기준을 다시 확인하는 표시이고 함께 둔 컨트롤은 눌러서 다른 화면으로 넘어가는 대상이므로, 폭이 모자랄 때는 정렬 이름이 먼저 양보한다.

줄의 좌우 바깥에는 [공통 여백과 간격 디자인](./dimens.md)의 `화면 가로 여백`을 두어, 정렬 컨트롤의 시작 쪽 끝과 끝 쪽 컨트롤의 끝 쪽 끝을 그 아래 목록 항목의 좌우 끝과 같은 세로선에 맞춘다. 정렬 줄이 목록에 딸린 줄로 읽히게 하고, 목록을 스크롤할 때 항목과 정렬 컨트롤의 가장자리가 어긋나 보이지 않게 하기 위한 것이다. 이는 아래에 두는 웹 페이지가 영역의 좌우를 모두 쓰는 [WebDetail 화면 디자인](./web-detail.md)의 표시 방식 줄과 다른 기준이다.

정렬 줄에는 배지나 숫자를 두지 않고, 현재 정렬이 처음 정렬과 다르다는 것을 색으로 구분하지도 않는다. 정렬은 항상 하나가 선택되어 있어 적용 여부를 구분할 상태가 없기 때문이다. 이는 적용 여부를 색으로 구분하는 [필터 Bottom Sheet 디자인](./filter-bottom-sheet.md)의 필터 아이콘 버튼과 다른 기준이다.

## 항목이 없는 동안의 정렬 줄

[목록 정렬 스펙](../spec/client/list-sort.md)의 `준비 중과 빈 상태에서의 정렬`에 따라 정렬을 고를 수 없는 동안, 곧 목록에 표시된 항목이 하나도 없는 동안에는 정렬 컨트롤을 감춘다. 목록을 처음 준비하느라 [페이지 조회 목록의 자리 표시 디자인](./paged-list-placeholder.md)의 표시만 있는 동안과 [목록 빈 상태 디자인](./list-empty-state.md)의 안내를 표시하는 동안이 여기에 해당한다. 누를 수 없는 컨트롤을 비활성으로 남겨 두지 않는 것은, 고를 대상이 없는 자리에서 흐린 컨트롤이 눌리지 않는 이유를 사용자가 찾게 되기 때문이다.

끝 쪽 컨트롤을 둔 줄에서는 정렬 컨트롤만 감추고 줄은 그대로 둔다. 끝 쪽 컨트롤은 항목이 있을 때와 같은 자리, 같은 모양으로 줄의 끝 쪽에 남으며, 줄의 높이도 바뀌지 않는다. 다른 목록으로 이동하는 버튼과 보기 모드 전환 버튼은 목록이 비어 있어도 쓸 수 있어야 하기 때문이다.

끝 쪽 컨트롤이 없는 줄은 정렬 컨트롤을 감추는 동안 줄 자체도 자리를 차지하지 않고, 그 아래 목록 영역이 줄의 자리까지 올라온다. 빈 줄 높이만큼의 여백이 목록 위에 남지 않게 하기 위한 것이다.

이미 항목이 표시된 목록을 다시 준비하는 동안에는 정렬 컨트롤을 감추지 않는다. 정렬을 바꾸거나 목록의 내용이 바뀔 때마다 컨트롤이 사라졌다 나타나 줄이 흔들리지 않게 하기 위한 것이다.

정렬 컨트롤을 감추고 다시 나타낼 때는 애니메이션 없이 곧바로 바꾼다. 다시 나타날 때는 사용자가 고른 기준의 아이콘과 이름을 표시한다.

## 정렬 줄의 자리

정렬 줄은 화면마다 다음 자리에 둔다. 어느 화면에서도 목록보다 위, 그 목록을 담는 영역 안에 두어 상단 바와 탭 줄을 밀어내지 않는다.

| 화면 | 자리 |
| --- | --- |
| MemoFinishedList, TagFinishedList, TagMemoFinishedList, WebHome, ContactHome, PlaylistHome | 상단 바 바로 아래, 목록 위 |
| MemoHome, TagHome | 상단 바 바로 아래 완료된 목록 진입 버튼과 같은 줄, 목록 위 |
| TagDetail 웹 탭 | 탭 줄 바로 아래, 그 탭의 목록 위 |
| TagDetail 장소 탭 | 탭 줄 바로 아래 보기 모드 전환 버튼과 같은 줄, 장소 보기 모드 영역 위 |
| TagDetail 메모 탭 | 탭 줄 바로 아래 완료된 메모 진입 버튼과 같은 줄, 목록 위 |
| ContactDetail·PlaceDetail·WebDetail 메모 탭 | 탭 줄 바로 아래, 그 탭의 목록 위 |
| SearchHome 네 유형 | 유형 탭 줄 바로 아래, 그 유형의 결과 목록 위 |
| PlaceHome | 장소 목록 영역 맨 위, 격자 위 |

PlaceHome의 정렬 줄은 보기 모드에 따라 정해지는 장소 목록 영역 안에 둔다. 지도 모드에서는 지도 영역이 아니라 장소 목록 영역의 맨 위에 두고, 목록 모드에서는 본문 맨 위에 둔다. 보기 모드를 바꿔도 컨트롤의 표시 내용은 바뀌지 않으며, 모드 전환의 교차 페이드에 정렬 줄도 함께 포함된다.

TagDetail 장소 탭의 정렬 줄은 같은 보기 모드를 쓰면서도 장소 목록 영역 안이 아니라 그 위에 둔다. 전환 버튼이 정렬 줄에 있어 장소 목록 영역이 표시되지 않는 동안에도 남아 있어야 하기 때문이며, 그 이유는 [TagDetail 장소 탭 디자인](./tag-detail-place.md)의 `정렬 줄의 자리`가 소유한다. 이 탭의 정렬 줄은 모드 전환의 교차 페이드에 포함되지 않는다.

목록과 상세를 함께 표시하는 배치에서는 정렬 줄을 목록 영역 안에만 두고 상세 영역에는 두지 않는다.

## 정렬 선택 Bottom Sheet

정렬 컨트롤을 누르면 현재 화면 위에 정렬 선택 Bottom Sheet를 표시한다. Bottom Sheet의 표시, 드래그 핸들과 제목의 배치, 닫는 조작, 적응형 배치는 [필터 Bottom Sheet 디자인](./filter-bottom-sheet.md)의 `Bottom Sheet 표시`, `닫는 조작`, `적응형 배치`와 같은 기준을 쓴다.

제목 아래에는 그 목록이 제공하는 정렬을 위에서부터 기본순, 제목순, 최근 수정순 순서로 한 줄씩 둔다. 기본순을 두지 않는 목록에서는 제목순이 첫 줄이 된다. 제목순 대신 이름순을 쓰는 목록에서는 같은 자리에 이름순을 둔다. 목록의 처음 정렬을 첫 줄에 두어 목록 순서와 처음 상태를 맞춘다.

각 줄에는 시작 쪽에 그 정렬의 아이콘, 가운데에 정렬 이름, 끝 쪽에 선택 여부를 나타내는 라디오 버튼을 두고, 아이콘과 정렬 이름 사이에는 `16dp` 간격을 둔다. 현재 정렬의 줄만 선택 상태로 표시하며, 두 줄 이상이 동시에 선택 상태가 되지 않는다.

각 줄에는 보조 문구를 두지 않는다. 정렬 이름만으로 결과를 예상할 수 있고, 잘못 골라도 다시 고르면 되돌아오기 때문이다.

줄 전체가 하나의 누를 수 있는 대상이며, 아이콘을 눌러도 그 정렬이 선택된다. 줄을 누르면 그 기준으로 바뀌고 Bottom Sheet가 곧바로 닫힌다. 이는 여러 필터를 이어서 바꾸도록 열린 상태를 유지하는 [필터 Bottom Sheet 디자인](./filter-bottom-sheet.md)의 `닫는 조작`과 다른 기준이며, 하나만 고르면 끝나는 선택이기 때문이다. [WebDetail 화면 디자인](./web-detail.md)의 `표시 방식 선택 Bottom Sheet`와 같은 기준이다.

각 줄은 [공통 스타일](./styles.md)의 `Bottom Sheet 선택 줄`을 따른다. 내용은 좌우를 제목과 같은 자리에 맞추고, 누르는 동안 드러나는 배경은 그 여백을 넘어 Bottom Sheet의 좌우 끝까지 채운다. 누를 수 있는 자리가 줄 전체인데 배경이 여백만큼 안쪽에서 끝나면, 여백 위를 눌렀을 때 아무 반응이 없는 것처럼 보이기 때문이다.

현재 정렬과 같은 줄을 눌러도 Bottom Sheet는 닫히고, 목록은 그대로 둔다.

## 아이콘

| 정렬 | 아이콘 |
| --- | --- |
| 기본순 | 길이가 다른 가로 줄이 위에서부터 짧아지며 쌓인 정렬 아이콘 |
| 제목순, 이름순 | 알파벳 두 글자와 아래 방향 화살표를 나란히 둔 아이콘 |
| 최근 수정순 | 반시계 방향 화살표를 두른 시계 아이콘 |

같은 아이콘을 정렬 줄의 컨트롤과 Bottom Sheet의 줄에 함께 쓴다. 아래 방향 화살표 아이콘은 [WebDetail 화면 디자인](./web-detail.md)의 표시 방식 컨트롤이 쓰는 것과 같다.

## 전환

정렬을 바꾸면 목록은 새 순서의 처음부터 다시 표시한다. 항목이 자리를 옮기는 이동 애니메이션은 두지 않고, 목록을 준비하는 동안의 표시는 [페이지 조회 목록의 자리 표시 디자인](./paged-list-placeholder.md)을 따른다.

컨트롤의 아이콘과 이름은 새 정렬의 것으로 곧바로 바뀌며, 바뀌는 동안 컨트롤의 폭이 달라지는 것은 그대로 둔다.

## 접근성

정렬 컨트롤은 이름에 현재 정렬을 표시하므로 접근성 이름에는 이 컨트롤이 무엇을 고르는 것인지만 두고, 현재 값은 이름이 알린다. 컨트롤 안의 아이콘에는 접근성 이름을 따로 두지 않아 이름과 두 번 읽히지 않게 한다.

Bottom Sheet의 각 줄은 정렬 이름을 하나의 선택 대상으로 읽히게 하고, 현재 정렬인지는 라디오 버튼의 선택 상태로 알린다. 줄 안의 아이콘에도 접근성 이름을 따로 두지 않는다.

키보드나 포인터를 사용하는 환경에서는 정렬 컨트롤에 초점을 이동해 `Enter` 또는 `Space`로 Bottom Sheet를 열 수 있다.

한국어 환경과 그 외 기본 환경에서 다음 문구를 사용한다.

| 항목 | 한국어 | 그 외 기본 |
| --- | --- | --- |
| 정렬 컨트롤 접근성 이름 | `목록 정렬` | `List sort` |
| Bottom Sheet 제목 | `정렬` | `Sort` |
| 기본순 이름 | `기본순` | `Default` |
| 제목순 이름 | `제목순` | `Title` |
| 이름순 이름 | `이름순` | `Name` |
| 최근 수정순 이름 | `최근 수정순` | `Recently updated` |

정렬 이름은 같은 정렬을 제공하는 모든 화면에서 같은 문구를 쓴다. 목록이 담는 항목의 종류를 이름에 넣지 않는 것은 사용자가 이미 어느 목록을 보고 있는지 알고 있고, 화면마다 이름이 달라지면 같은 기준이 다른 기준처럼 보이기 때문이다.

제목순과 이름순은 예외다. 두 기준은 항목을 가리키는 값의 오름차순이라는 같은 순서이지만, 그 값을 화면에서 부르는 이름이 다르다. 연락처를 담는 목록은 화면 어디에서도 그 값을 `이름`이라 부르므로 정렬도 `이름순`으로 알리고, 그 밖의 목록은 `제목`이라 부르므로 `제목순`으로 알린다. 어느 목록이 어느 이름을 쓰는지는 [목록 정렬 스펙](../spec/client/list-sort.md)의 `적용 대상`이 정한다. 사용자가 화면에서 읽은 값의 이름과 정렬 이름이 어긋나면 무엇을 기준으로 놓인 목록인지 다시 확인하게 되기 때문이다.
