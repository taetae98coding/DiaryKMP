# 메모 Gemini 작성 도우미 디자인

기준 스펙: [메모 Gemini 작성 도우미 스펙](../spec/memo-gemini.md)

이 문서는 MemoAdd 화면과 MemoDetail 화면이 함께 쓰는 작성 도우미의 여는 버튼, 다이얼로그 구조, 상태별 표시와 문구를 소유한다. 두 화면 디자인은 이 버튼을 상단 바 어느 자리에 두는지만 남긴다.

## 이 문서를 참조하는 문서

- [MemoAdd 화면 디자인](./memo-add.md)
- [MemoDetail 화면 디자인](./memo-detail.md)

## 여는 버튼

작성 도우미를 여는 버튼은 화면 상단 바의 끝 쪽 액션 자리에 아이콘 버튼으로 둔다. 아이콘은 반짝임 모양을 쓴다. 생성한 내용을 제안하는 동작을 뜻하는 표현으로 널리 쓰여, 사용자가 다른 동작 버튼과 구분하기 쉽다.

저장된 Gemini 설정을 아직 확인하지 못한 동안에는 이 버튼을 자리까지 함께 감추고, 별도의 로딩 안내도 표시하지 않는다.

인증 정보나 모델이 비어 있어도 버튼은 그대로 표시한다. 누르면 다이얼로그를 열지 않고 Gemini 설정이 필요하다는 안내를 스낵바로 표시한다. 버튼을 비활성 상태로 남기지 않는 것은 눌러 보기 전에는 사용자가 왜 누를 수 없는지 알기 어렵기 때문이며, 이는 [SettingGemini 화면 디자인](./setting-gemini.md)의 모델 선택 줄과 같은 기준이다.

## 다이얼로그 구조

도우미는 대화상자 하나로 표시하고, 위에서 아래로 제목, 내용 영역, 동작 줄을 둔다.

제목과 동작 줄은 상태가 바뀌어도 자리를 지키고 내용 영역만 바뀐다. 사용자가 프롬프트를 적고 기다렸다 결과를 보는 동안 다이얼로그가 통째로 바뀌지 않게 하기 위한 것이다.

다이얼로그의 너비는 대화상자 컴포넌트의 기본값을 따르고 창 크기에 따라 다른 너비를 지정하지 않는다. 높이는 내용에 맞추되 표시할 수 있는 높이를 넘지 않게 하고, 내용이 그보다 길면 내용 영역 안에서 세로로 스크롤한다.

상태가 바뀌어 내용 높이가 달라지면 다이얼로그 크기를 곧바로 바꾸지 않고 크기 전환으로 이어 준다.

사용자는 다이얼로그 바깥을 누르거나 뒤로가기로 다이얼로그를 닫을 수 있다. 상단에 닫기 버튼은 두지 않는다.

## 상태별 표시

| 상태 | 내용 영역 | 동작 줄 |
| --- | --- | --- |
| 프롬프트 입력 | 프롬프트 입력. 직전 생성이 실패했으면 그 아래에 실패 안내 | `생성` 버튼 |
| 생성 중 | 가운데 정렬한 진행 표시와 안내 문구 | `취소` 버튼 |
| 결과 확인 | 생성된 제목, 설명, 날짜·시간 결과 | `닫기` 버튼 |
| 결과 확인이고 생성된 내용이 하나도 없음 | 가운데 정렬한 안내 문구 | `닫기` 버튼 |

동작 줄의 버튼은 상태마다 하나씩만 두고 끝 쪽에 둔다. 상태마다 사용자가 할 수 있는 일이 하나로 정해져 있어 고를 것이 없고, 닫기는 바깥 누르기와 뒤로가기로도 할 수 있기 때문이다.

## 프롬프트 입력

프롬프트 입력은 여러 줄 텍스트 입력으로 내용 영역의 좌우 폭을 모두 사용하고, 입력 위에 `프롬프트` 라벨을 둔다.

입력의 높이는 세 줄 분량을 기본으로 하고 내용이 늘어나면 다섯 줄 분량까지 함께 늘어난다. 그보다 길어지면 입력 안에서 세로로 스크롤한다. 다이얼로그 안이라 쓸 수 있는 높이가 화면보다 좁으므로 [SettingGemini 화면 디자인](./setting-gemini.md)의 시스템 프롬프트 입력보다 낮게 시작한다.

입력이 비어 있으면 무엇을 적는 자리인지 알리는 안내 문구를 자리 표시 문구로 둔다. 프롬프트가 비어 있어도 `생성` 버튼은 그대로 누를 수 있다.

입력에 내용이 있으면 끝 쪽에 내용을 한 번에 지우는 지우기 버튼을 표시한다. 나타나고 사라지는 표현은 [나타나고 사라지는 버튼 디자인](./button-visibility.md)을 따라 앱의 다른 입력과 같다.

직전 생성이 실패했으면 입력 아래에 실패 안내를 작은 글씨의 보조 문구로 표시한다. 인증 정보가 유효하지 않은 실패와 그 밖의 실패는 같은 자리에 같은 크기로 표시하고 문구만 다르게 둔다. 사용자가 프롬프트를 고치거나 다시 생성을 실행하면 이 문구를 지운다.

실패를 스낵바가 아니라 다이얼로그 안에 표시하는 것은, 실패한 뒤에도 다이얼로그가 열린 채로 남아 스낵바가 다이얼로그 뒤에 가리기 때문이다.

## 생성 중

내용 영역에는 진행 표시와 안내 문구를 가운데 정렬로 둔다. 프롬프트 입력은 표시하지 않는다.

동작 줄의 버튼을 `취소`로 바꾼다. 취소를 누르면 프롬프트 입력 상태로 돌아가고 적었던 프롬프트가 그대로 남는다.

## 결과 확인

내용 영역에는 생성된 제목, 설명, 날짜·시간을 이 순서로 세로로 둔다. 순서는 [메모 본문 배치 디자인](./memo-form.md)의 입력 순서와 같아, 사용자가 결과와 반영될 자리를 같은 순서로 읽는다.

각 결과 사이에는 [구성요소 간격](./dimens.md)을 둔다.

생성된 내용이 비어 있는 결과는 자리까지 함께 표시하지 않는다.

각 결과는 위에서 아래로 라벨 줄과 생성된 내용을 둔다. 라벨 줄에는 시작 쪽에 라벨을, 끝 쪽에 `반영` 텍스트 버튼을 둔다.

- 제목: 생성된 제목을 최대 두 줄까지 표시하고 넘치면 끝을 줄임표로 줄인다.
- 설명: 생성된 설명을 마크다운으로 해석해 표시한다. 해석 범위와 줄바꿈 처리, 제목 크기는 [설명 입력 컴포넌트 디자인](./description-input.md)의 미리보기 페이지와 같다. 반영한 뒤 설명 입력의 미리보기에서 보게 될 모습과 같은 표현으로 보여 주기 위한 것이다.
- 날짜·시간: 시작과 종료를 표시하고, 종일 기간이면 날짜만, 날짜·시간 기간이면 날짜와 시간을 함께 표시한다. 라벨 문구와 표시 형식은 [DiaryDateTimeInput 컴포넌트 디자인](./diary-date-time-input.md)의 `문구`와 `표시 형식`을 따른다.

`반영` 버튼을 누르면 그 내용만 화면의 입력으로 들어가고 다이얼로그는 열린 채로 남는다. 반영했음은 스낵바가 아니라 그 결과의 라벨 줄 라벨 옆에 확인 아이콘을 표시해 알린다. 다이얼로그가 열려 있어 스낵바가 보이지 않고, 어느 결과를 반영했는지는 그 자리에서 알려 주는 편이 읽기 쉽기 때문이다.

확인 아이콘이 나타난 뒤에도 `반영` 버튼은 그대로 둔다. 사용자가 입력을 직접 고친 뒤 생성된 내용으로 되돌릴 수 있어야 하기 때문이다.

## 초점과 키보드

다이얼로그를 열면 프롬프트 입력에 초점을 두고 소프트 키보드를 함께 연다. 사용자가 프롬프트를 적으려고 연 자리이기 때문이다.

프롬프트 입력의 소프트 키보드는 일반 텍스트 키보드를 요청하고, 키보드의 동작 키는 줄바꿈으로 표시한다.

프롬프트 입력에 초점이 있는 동안 사용자는 물리 키보드에서 `Cmd`(또는 `Meta`)와 `Enter`를 함께 눌러 생성을 실행할 수 있다. 다이얼로그가 열려 있는 동안 이 단축키는 화면의 메모 추가나 메모 수정이 아니라 생성을 실행한다.

생성 중 상태로 바뀌면 소프트 키보드를 닫는다. 결과 확인 상태에서는 다시 열지 않는다.

물리 키보드 환경에서는 `Esc`로 다이얼로그를 닫을 수 있고, 생성 중에 닫으면 취소와 같이 요청을 멈춘다.

## 표시 영역

다이얼로그는 상태 표시 영역, 시스템 탐색 영역과 카메라 컷아웃 등 기기가 가리는 영역을 침범하지 않게 배치한다.

소프트 키보드가 열리면 다이얼로그 전체를 키보드 위 영역에 맞춰 배치하고, 줄어든 높이보다 내용이 길면 내용 영역을 세로로 스크롤한다. 키보드가 닫히면 원래 크기로 되돌린다.

## 문구와 접근성

한국어 환경과 그 외 기본 환경에서 다음 문구를 사용한다.

| 문구 | 한국어 | 그 외 기본 |
| --- | --- | --- |
| 작성 도우미 버튼 접근성 이름 | `작성 도우미` | `Writing assistant` |
| 다이얼로그 제목 | `작성 도우미` | `Writing assistant` |
| Gemini 설정 필요 안내 | `Gemini 설정을 먼저 완료해 주세요.` | `Please finish Gemini settings first.` |
| 프롬프트 입력 라벨 | `프롬프트` | `Prompt` |
| 프롬프트 자리 표시 문구 | `어떤 메모를 만들까요?` | `What memo should I write?` |
| 생성 버튼 | `생성` | `Generate` |
| 취소 버튼 | `취소` | `Cancel` |
| 닫기 버튼 | `닫기` | `Close` |
| 생성 중 안내 | `생성하고 있습니다` | `Generating` |
| API 키 오류 안내 | `API 키를 확인해 주세요` | `Check your API key` |
| 생성 실패 안내 | `생성하지 못했습니다` | `Couldn't generate` |
| 결과 없음 안내 | `생성된 내용이 없습니다` | `Nothing was generated` |
| 결과 제목 라벨 | `제목` | `Title` |
| 결과 설명 라벨 | `설명` | `Description` |
| 반영 버튼 | `반영` | `Apply` |
| 반영됨 접근성 이름 | `반영됨` | `Applied` |

API 키 오류 안내는 [SettingGemini 화면 디자인](./setting-gemini.md)의 같은 문구를 그대로 쓴다. 사용자가 두 화면에서 같은 원인을 같은 문장으로 읽게 하기 위한 것이다.

각 결과의 `반영` 버튼 접근성 이름은 `반영`과 그 결과의 라벨을 이어 읽히게 둔다. 버튼이 셋까지 같은 문구로 나열되므로 무엇을 반영하는 버튼인지 구분할 수 있어야 하기 때문이다.

생성 중 진행 표시에는 `생성 중 안내` 문구를 접근성 이름으로 함께 둔다.

날짜·시간 결과의 접근성 이름은 종일 여부와 시작·종료를 이어 읽히게 둔다.
