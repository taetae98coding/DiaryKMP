# WebAdd 화면 디자인

기준 스펙: [WebAdd 화면 스펙](../spec/client/web-add.md)

화면 구조, 태그 입력의 자리, 표시 영역과 소프트 키보드, 초점과 단축키, 진행과 피드백, 여러 항목을 담는 입력의 공통 표현은 [항목 추가 화면 공통 디자인](./entity-add.md)을 따른다.

## 화면 구조

WebAdd 화면은 창 너비에 따라 단독으로 표시하거나 [Web 목록·상세 배치 디자인](./web-list-detail.md)에 따라 웹 목록과 함께 상세 영역에 표시한다.

뒤로가기 버튼의 노출 조건은 [목록·상세 배치 공통 디자인](./list-detail-pane.md)의 `버튼 노출`을 따른다.

본문에는 단일 줄 제목 입력, 설명 입력, 단일 줄 URL 입력, 요청 헤더 입력, 태그 입력을 순서대로 배치한다.

입력 순서는 웹 항목을 가리키는 이름인 제목과 설명을 먼저 두고, 주소인 URL과 그 주소를 불러올 때 함께 보내는 요청 헤더를 뒤에 이어 둔다. 요청 헤더는 개수에 따라 높이가 변하는 유일한 입력이므로 제목·설명·URL 아래에 둔다. 태그 입력을 가장 마지막에 두는 기준은 [항목 추가 화면 공통 디자인](./entity-add.md)의 `태그 입력의 자리`를 따른다.

태그 입력의 구성과 조작은 [항목 태그 입력 컴포넌트 디자인](./entity-tag-input.md)을 따른다.

설명 입력의 구성과 표현은 [설명 입력 컴포넌트 디자인](./description-input.md)을 따른다.

## URL 입력

URL은 단일 줄 텍스트 입력으로 배치하고, 입력한 값이 있으면 내용을 한 번에 지우는 지우기 버튼을 끝 쪽에 표시한다. 지우기 버튼이 나타나고 사라지는 표현은 [나타나고 사라지는 버튼 디자인](./button-visibility.md)을 따른다.

URL 입력에는 주소 입력에 맞춘 소프트 키보드를 요청해 `/`와 `.`을 바로 입력할 수 있게 한다. 소프트 키보드 종류는 입력기에 대한 요청일 뿐이므로 값의 형식을 보장하지 않으며, 입력 중에는 값이 주소 형식인지 검사해 막거나 오류 색을 표시하지 않는다.

## 요청 헤더 입력

요청 헤더는 [항목 추가 화면 공통 디자인](./entity-add.md)의 `여러 항목을 담는 입력`에 따라 하나의 카드에 담는다.

헤더 항목 하나는 한 행에 단일 줄 이름 입력, 단일 줄 값 입력, 그 항목을 삭제하는 버튼을 순서대로 배치한다. 이름 입력과 값 입력은 삭제 버튼을 뺀 남은 폭을 균등하게 나눠 가진다.

## 표시 영역과 소프트 키보드

칩 영역의 높이 기준은 [항목 태그 입력 컴포넌트 디자인](./entity-tag-input.md)을 따른다.

배치는 창 너비, 창 높이와 기기 자세에 따라 달라지지 않는다.

## 진행과 피드백

추가에 성공하면 제목, 설명과 URL을 비우고 헤더 항목을 모두 없앤다.

## 문구와 접근성

[항목 추가 화면 공통 디자인](./entity-add.md)의 `문구와 접근성`에 더해 한국어 환경과 그 외 기본 환경에서는 다음 문구를 사용한다.

| 문구 | 한국어 | 그 외 기본 |
| --- | --- | --- |
| 상단 바 제목 | `웹 추가` | `Add Web` |
| 추가 버튼 접근성 이름 | `웹 추가` | `Add web` |
| URL 입력 이름 | `URL` | `URL` |
| 요청 헤더 영역 이름 | `요청 헤더` | `Request headers` |
| 헤더 이름 입력 이름 | `이름` | `Name` |
| 헤더 값 입력 이름 | `값` | `Value` |
| 헤더 이름 입력 접근성 이름 | `{순서}번째 헤더 이름` | `Header {순서} name` |
| 헤더 값 입력 접근성 이름 | `{순서}번째 헤더 값` | `Header {순서} value` |
| 헤더 추가 버튼 접근성 이름 | `헤더 추가` | `Add header` |
| 헤더 삭제 버튼 접근성 이름 | `헤더 삭제` | `Remove header` |
| 추가 성공 안내 | `웹이 추가되었습니다.` | `Web added.` |
| 제목 미입력 안내 | `제목을 입력해 주세요.` | `Please enter a title.` |
| URL 미입력 안내 | `URL을 입력해 주세요.` | `Please enter a URL.` |
| 헤더 이름 미입력 안내 | `헤더 이름을 입력해 주세요.` | `Please enter a header name.` |

제목 입력의 이름과 표현은 [제목 입력 디자인](./title-input.md)을, 설명 입력은 [설명 입력 컴포넌트 디자인](./description-input.md)을 따른다.

두 입력을 하나의 접근성 대상으로 합치지 않는다. 합치면 이름과 값을 각각 입력할 수 없기 때문이다.

태그 입력의 칩 라벨과 태그 선택 목록의 문구는 [항목 태그 입력 컴포넌트 디자인](./entity-tag-input.md)을 따른다.
