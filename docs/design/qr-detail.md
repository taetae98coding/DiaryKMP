# QrDetail 화면 디자인

기준 스펙: [QrDetail 화면 스펙](../spec/client/qr-detail.md), [QR 목록·상세 배치 스펙](../spec/client/qr-list-detail.md), [항목 공유 공통 스펙](../spec/client/entity-share.md)

QrDetail은 [QrAdd 화면 디자인](./qr-add.md)과 같은 본문을 쓰고, 상단 바 액션과 떠 있는 버튼, 상태 전환과 피드백만 다르다. 두 화면이 같은 자리에 같은 입력을 두어 사용자가 QR을 추가할 때와 고칠 때 같은 방식으로 조작한다.

## 화면 구조

QrDetail 화면은 [QrHome 화면](./qr-home.md)에서 이어지는 세부 화면으로, 창 너비에 따라 단독으로 표시하거나 [QR 목록·상세 배치 디자인](./qr-list-detail.md)에 따라 QR 목록과 함께 상세 영역에 표시한다. [TagDetail QR 탭](./tag-detail-qr.md)에서 진입한 QrDetail 화면은 창 너비와 관계없이 단독으로 표시한다. 공통 내비게이션 영역은 [TopLevelNavigation 디자인](./top-level-navigation.md)의 `세부 화면에서의 노출`에 따라 숨긴다.

뒤로가기 버튼의 노출 조건은 [목록·상세 배치 공통 디자인](./list-detail-pane.md)의 `버튼 노출`을 따르므로, 단독으로 표시할 때만 뒤로가기 버튼을 둔다.

화면 상단에는 상단 바를 두고, 시작 쪽에 뒤로가기 동작을, 그 바로 뒤에 저장된 QR 제목을 시작 쪽에 맞춰 표시한다. 제목은 [항목 상세 화면 공통 디자인](./entity-detail.md)의 `상단 바 제목`에 따라 표시한다. 조회가 완료되면 상단 바 끝 쪽에 공유 버튼, QR 실행 버튼, 되돌리기 버튼, QR 스캔 버튼, 삭제 버튼을 이 순서로 둔다. 공유 버튼을 그리는 조건은 `공유 버튼`을 따른다. QR 실행 버튼은 실행할 수 있는 내용이 있을 때만 두며, 버튼이 없을 때는 나머지 버튼이 끝 쪽으로 모인다. 되돌리기 버튼과 QR 스캔 버튼의 순서와 표현은 [QrAdd 화면 디자인](./qr-add.md)의 `되돌리기 버튼`, `QR 스캔 버튼`과 같고, 삭제 버튼을 끝 쪽 모서리에 두는 것은 [항목 상세 화면 공통 디자인](./entity-detail.md)의 `삭제 버튼의 자리`를 따른다. 이 버튼들은 선택한 탭과 관계없이 같은 자리에 둔다.

상단 바 아래 본문의 QR 그림, 탭 행, 정보 탭과 QR 탭의 구성, 간격, 스크롤과 위치 지도의 표현은 [QrAdd 화면 디자인](./qr-add.md)의 `화면 구조`, `QR 그림`, `탭 행`, `정보 탭`, `QR 탭`을 그대로 따른다. 정보 탭의 태그 입력도 같은 자리에 둔다. 그 문서에서 추가 성공으로 입력이 다시 채워지는 경우는 이 화면에 없다.

## 태그 입력

태그 입력의 구성과 조작은 [항목 태그 입력 컴포넌트 디자인](./entity-tag-input.md)을 따른다.

칩 영역에는 저장된 연결을 그대로 표시하고, 사용자가 항목을 누르면 저장된 연결이 곧바로 바뀌어 칩 영역에 이어서 나타난다. 반영에는 진행 표시를 두지 않으므로 수정 버튼과 삭제 버튼의 진행 표시와 섞이지 않는다.

태그를 연결하거나 해제해도 수정 버튼의 표시 여부, 되돌리기 버튼의 활성 상태와 QR 그림은 바뀌지 않는다.

태그 칩을 누르면 그 태그의 TagDetail 화면으로 이동하고, 뒤로가면 이 QR의 상세로 돌아온다. 이동한 화면은 태그 디테일 탭이 선택된 상태로 시작하고, 돌아오면 정보 탭이 선택된 상태로 돌아온다.

조회 중에는 태그 입력을 표시하지 않는다. 조회 상태에 따른 표시는 `상태 전환과 동작 표시`를 따른다.

```mermaid
flowchart TB
    top["상단 바<br/>뒤로가기 · 저장된 제목 · 공유 · QR 실행 · 되돌리기 · QR 스캔 · 삭제"]
    qr["QR 그림"]
    tabs["탭 행<br/>정보 · QR"]
    content["선택한 탭의 내용"]
    fab["떠 있는 수정 버튼<br/>오른쪽 아래, 바뀐 내용이 있을 때만"]
    top --> qr --> tabs --> content
    content ~~~ fab
```

## QR 실행 버튼

QR 실행 버튼은 실행할 동작을 뜻하는 아이콘만 표시하고 라벨은 두지 않는다. 모양과 크기는 플랫폼 기본 아이콘 버튼을 따르고, 버튼의 이름을 알려 주는 설명 표시는 [아이콘 버튼 설명 디자인](./icon-button-tooltip.md)을 따른다. 아이콘과 이름은 동작마다 다음과 같다.

| 동작 | Material Symbols 아이콘 |
| --- | --- |
| 웹 주소 열기 | `open_in_new` |
| 전화 걸기 | `call` |
| 메일 쓰기 | `mail` |
| 문자 보내기 | `sms` |
| 지도에서 보기 | `map` |
| 연락처에 추가 | `person_add` |
| 캘린더에 추가 | `calendar_add_on` |
| Wi-Fi 연결 | `wifi` |

입력 중인 QR 값이 바뀌어 실행할 동작이 바뀌면 아이콘과 이름도 바로 바뀌며, 버튼이 나타나고 사라지는 것은 다른 상단 바 버튼처럼 전환 효과 없이 바뀐다. 버튼은 실행 중에도 진행 표시로 바꾸지 않고, 수정이나 삭제를 처리하는 동안에도 잠그지 않는다.

iOS에서 연락처나 일정 화면은 이 화면 위에 아래에서 올라오는 시스템 화면으로 뜨고, 사용자가 저장하거나 취소하면 내려가 이 화면이 그대로 보인다. Wi-Fi 연결은 Android와 iOS 모두 시스템의 확인 창이 이 화면 위에 뜨며, 확인 창이 닫히면 이 화면이 그대로 보인다.

## 공유 버튼

공유 버튼의 아이콘, 비활성과 숨김 표현, 공유 시트가 나타나는 모습과 공유하지 못했을 때의 안내는 [항목 공유 공통 디자인](./entity-share.md)을 따른다. 공유 버튼은 QR 실행 버튼보다 시작 쪽에 두어, 공유를 제공하지 않는 환경에서 버튼이 빠져도 QR 실행 버튼부터 삭제 버튼까지의 자리가 바뀌지 않게 한다. 이는 [WebDetail 화면 디자인](./web-detail.md)이 공유 버튼을 외부로 열기 버튼보다 시작 쪽에 두는 것과 같은 기준이다. 웹에서 브라우저가 PNG 이미지를 공유할 수 없으면 공유 버튼을 그리지 않는다.

조회 중에는 다른 상단 바 버튼과 같이 공유 버튼도 표시하지 않는다. 이는 [항목 공유 공통 디자인](./entity-share.md)의 `비활성`에 따른 것이다. 조회가 끝나면 다른 버튼과 함께 나타난다.

QR 값이 비어 있어도 공유 버튼은 활성 표현을 유지하고, 누르면 공유 시트를 열지 않고 `진행과 피드백`의 QR 내용 미입력 안내를 표시한다. 수정 버튼과 달리 진행 표시를 거치지 않고 곧바로 QR 탭으로 바꾼다.

수정이나 삭제를 처리하는 동안에도 공유 버튼은 잠그거나 흐리게 바꾸지 않는다.

### 공유하는 이미지

공유하는 이미지는 QR 그림과 같은 QR 값을 담은 정사각형 PNG 이미지다. 화면의 QR 그림과 달리 이미지 바탕을 투명하게 두지 않는다.

| 요소 | 표현 |
| --- | --- |
| 크기 | 가로·세로 1024px |
| 바탕 | 흰색 `#FFFFFF`. 다크 테마에서도 같다 |
| QR 모듈 | 검은색 `#000000`. 한 칸을 같은 정수 픽셀 크기의 정사각형으로 그려 칸 경계가 흐려지지 않게 한다 |
| 여백 | QR 둘레에 사방 같은 너비로 QR 네 칸 이상. 1024px를 칸 크기로 나누고 남는 픽셀은 여백에 더해 QR을 가운데에 둔다 |
| 그 밖의 요소 | 제목, 설명, 로고와 테두리를 그리지 않는다 |

칸 크기는 QR 칸 수에 사방 네 칸씩 여백을 더한 칸 수로 1024px를 나눈 몫이다. 예를 들어 가로 21칸인 QR은 여백을 더해 29칸이므로 한 칸이 35px이고, QR은 735px, 사방 여백은 144px 또는 145px다.

## 삭제 버튼

상단 바 끝 쪽 모서리의 버튼에는 삭제를 뜻하는 Material Symbols `delete` 아이콘만 표시하고 라벨은 두지 않는다. 모양과 크기는 플랫폼 기본 아이콘 버튼을 따르고, 버튼의 이름을 알려 주는 설명 표시는 [아이콘 버튼 설명 디자인](./icon-button-tooltip.md)을 따른다.

삭제를 처리하는 동안에는 삭제 아이콘을 진행 표시로 바꾼다. 삭제 전에 확인 대화상자를 두지 않으며, 이는 [TagDetail 화면 디자인](./tag-detail.md)의 삭제와 같은 기준이다.

## 수정 버튼

수정 버튼은 [QrAdd 화면 디자인](./qr-add.md)의 추가 버튼과 같은 오른쪽 아래 자리에 떠 있는 버튼으로 두고 체크 아이콘을 쓴다. 이는 [PlaceDetail 화면 디자인](./place-detail.md)과 [WebDetail 화면 디자인](./web-detail.md)의 수정 버튼과 같은 표현이다.

수정 버튼은 입력한 제목, 설명 또는 QR 값이 저장 내용과 다를 때만 표시하며, 어느 탭을 보고 있든 같은 자리에 둔다. 나타나고 사라지는 표현은 [나타나고 사라지는 버튼 디자인](./button-visibility.md)을 따른다. QR 값이 비어 있어도 저장 내용과 다르므로 버튼을 표시하고, QR 내용이 필요하다는 안내는 수정을 실행한 시점에만 제공한다.

수정을 처리하는 동안에는 수정 버튼의 체크 아이콘을 진행 표시로 바꾼다. 처리 중에도 입력, 탭 행, 되돌리기 버튼과 QR 스캔 버튼을 잠그거나 흐리게 바꾸지 않으며, 수정과 삭제는 서로를 비활성으로 만들지 않는다.

수정 버튼이 표시된 동안의 수정 실행 단축키는 [항목 상세 화면 공통 디자인](./entity-detail.md)의 `수정 실행 단축키`를 따른다.

## 상태 전환과 동작 표시

```mermaid
stateDiagram-v2
    Loading: 조회 중 · 로딩 진행 표시
    Unchanged: 내용 표시 · 수정 버튼 없음
    Changed: 내용 표시 · 수정 버튼 표시
    Updating: 수정 버튼이 진행 표시
    Deleting: 삭제 버튼이 진행 표시
    [*] --> Loading: 화면 진입
    Loading --> Unchanged: 조회 성공, 교차 전환
    Unchanged --> Changed: 입력이 저장 내용과 달라짐
    Changed --> Unchanged: 입력이 저장 내용과 같아짐
    Changed --> Updating: 수정 실행
    Updating --> Unchanged: 수정 성공, 성공 안내
    Updating --> Changed: 제목을 비운 채 수정 성공
    Updating --> Changed: QR 값이 비어 있음, QR 내용 안내
    Unchanged --> Deleting: 삭제 실행
    Changed --> Deleting: 삭제 실행
    Deleting --> [*]: 삭제 성공, 진입하기 전 화면으로 복귀
```

조회 중에는 본문 가운데에 로딩 진행 표시만 두고 QR 그림, 탭 행, 태그 입력을 포함한 탭 내용, 수정 버튼을 표시하지 않는다. 상단 바에는 단독으로 표시할 때의 뒤로가기만 두고 제목과 공유·QR 실행·되돌리기·QR 스캔·삭제 버튼을 표시하지 않는다. 조회 중 상태와 내용 표시 상태는 서로 겹쳐 바뀌는 교차 전환을 사용한다.

조회가 완료되면 정보 탭을 선택한 상태로 저장된 제목과 설명, 저장된 태그 연결을 채우고, QR 그림에 저장된 QR 값을 그리며, QR 탭의 포맷 선택과 포맷 입력을 저장된 QR 값에서 채운다. 글자 입력의 커서는 값의 끝에 둔다. 진입할 때는 입력 초점을 두지 않으므로 소프트 키보드도 열지 않는다.

삭제에 성공하면 단독으로 표시하고 있었으면 진입하기 전 화면(QrHome 또는 TagDetail QR 탭)으로 돌아가고, 목록과 함께 표시하고 있었으면 상세 영역이 [QR 목록·상세 배치 디자인](./qr-list-detail.md)의 선택 전 표시로 되돌아간다. 돌아간 화면에는 삭제 안내 스낵바를 표시하지 않는다.

## 진행과 피드백

수정 성공, QR 내용 미입력, 카메라 권한 안내, QR 실행 실패 안내와 공유하지 못했을 때의 안내는 모두 짧게 보이는 스낵바로 화면 아래쪽에 표시하며, 스낵바에는 동작 버튼을 두지 않는다. 새 안내를 표시할 때 이미 보이는 스낵바가 있으면 즉시 새 안내로 바꾼다. 이는 [QrAdd 화면 디자인](./qr-add.md)의 `진행과 피드백`과 같은 기준이다.

QR 내용 미입력도 수정을 실행한 결과로 판단하므로 수정 처리와 같은 진행 표시를 거친 뒤 QR 탭으로 바꾸고, 초점을 옮길 입력이 보이도록 본문을 스크롤한 뒤 안내를 표시한다. 공유 버튼으로 실행했을 때는 진행 표시 없이 곧바로 QR 탭으로 바꾸고, 같은 방식으로 스크롤한 뒤 같은 안내를 표시한다.

사용자가 공유를 마치거나 공유 시트를 닫으면 아무것도 표시하지 않고, 입력, 선택한 탭, 본문의 스크롤 위치와 수정 버튼의 표시는 공유하기 전 그대로 둔다.

제목을 비운 채 수정해 저장된 제목이 유지되는 경우에는 별도의 안내를 표시하지 않고 수정 성공 피드백만 표시한다.

수정에 성공해도 입력, 선택한 탭, 본문의 스크롤 위치와 위치 지도의 표시는 그대로 둔다.

## 시스템 영역과 적응형 배치

상단 바는 상태 표시줄 영역을 피해 배치한다. 본문, 수정 버튼과 스낵바의 배치, 소프트 키보드 처리와 창 크기에 따른 표현은 [QrAdd 화면 디자인](./qr-add.md)의 `시스템 영역과 적응형 배치`를 따르며, 그 문서의 추가 버튼은 이 화면의 수정 버튼으로 읽는다. 수정 버튼이 보이지 않는 동안에도 본문 아래쪽 여백은 줄이지 않아 버튼이 나타날 때 본문이 움직이지 않게 한다.

## 문구와 접근성

[QrAdd 화면 디자인](./qr-add.md)의 `문구와 접근성`에 있는 탭, 포맷, 포맷별 입력, QR 내용 미입력 안내, 카메라 권한 안내, 되돌리기·QR 스캔 버튼, 위치 지도 문구를 그대로 쓰고, 공유 버튼의 접근성 이름과 공유하지 못했을 때의 안내는 [항목 공유 공통 디자인](./entity-share.md)의 `문구`를 따르며, 다음 문구를 더한다.

| 항목 | 한국어 | 그 외 기본 |
| --- | --- | --- |
| 상단 바 제목 | 저장된 QR 제목 | 저장된 QR 제목 |
| 뒤로가기 접근성 이름 | `뒤로가기` | `Navigate up` |
| 삭제 버튼 접근성 이름 | `QR 삭제` | `Delete QR code` |
| 수정 버튼 접근성 이름 | `QR 수정` | `Update QR code` |
| 웹 주소 열기 버튼 접근성 이름 | `브라우저에서 열기` | `Open in browser` |
| 전화 걸기 버튼 접근성 이름 | `전화 걸기` | `Call` |
| 메일 쓰기 버튼 접근성 이름 | `메일 쓰기` | `Write email` |
| 문자 보내기 버튼 접근성 이름 | `문자 보내기` | `Send message` |
| 지도에서 보기 버튼 접근성 이름 | `지도에서 보기` | `Show on map` |
| 연락처에 추가 버튼 접근성 이름 | `연락처에 추가` | `Add to contacts` |
| 캘린더에 추가 버튼 접근성 이름 | `캘린더에 추가` | `Add to calendar` |
| Wi-Fi 연결 버튼 접근성 이름 | `Wi-Fi 연결` | `Connect to Wi-Fi` |
| QR 실행 실패 안내 | `QR을 실행하지 못했습니다.` | `Couldn't open the QR code.` |
| 수정 성공 안내 | `QR이 수정되었습니다.` | `QR code updated.` |
| 로딩 진행 표시 접근성 이름 | `QR 불러오는 중` | `Loading QR code` |

제목 입력의 이름과 표현은 [제목 입력 디자인](./title-input.md)을, 설명 입력은 [설명 입력 컴포넌트 디자인](./description-input.md)을 따른다. QR 그림은 화면 낭독 도구가 읽지 않는다.

태그 입력의 칩 라벨과 태그 선택 목록의 문구는 [항목 태그 입력 컴포넌트 디자인](./entity-tag-input.md)을 따른다.
