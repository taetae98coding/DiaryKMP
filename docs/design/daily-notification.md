# 일일 알림 디자인

기준 스펙: [일일 알림 스펙](../spec/client/daily-notification.md)

이 문서는 알림이 사용자에게 보이는 문구와 표현을 소유한다. 알림이 언제 발생하고 어떤 기기로 보내며 무엇을 오늘의 메모·루틴·디데이로 삼는지는 [일일 알림 스펙(server)](../spec/server/daily-notification.md)이, 알림에 담기는 정보의 의미는 [일일 알림 스펙(common)](../spec/common/daily-notification.md)이 소유한다.

알림은 앱 화면이 아니라 Android와 iOS의 알림 표시 영역에 놓이므로, 배치와 크기는 플랫폼의 기본 알림 표현을 그대로 따르고 이 문서에서 따로 정하지 않는다.

## 알림 구성

알림은 제목 한 줄과 본문으로 구성한다. 본문을 두는 경우는 [일일 알림 스펙(common)](../spec/common/daily-notification.md)의 `알림 내용`을 따른다.

### 제목

제목은 기준 스펙의 `알림 내용`이 가르는 경우에 따라 다르다.

| 경우 | 한국어 | 영어 |
| --- | --- | --- |
| 목록인 종류가 하나 이상 | `오늘 <요약>가 있어요` | `Today: <요약>` |
| 세 종류가 모두 없음 | `오늘 확인할 일이 없어요` | `Nothing to check today` |
| 목록인 종류가 없고 확인 안내인 종류가 있음 | `오늘 일정을 확인하세요` | `Check today's schedule` |

`<요약>`은 목록인 종류를 메모, 루틴, 디데이 순으로 `, `(쉼표와 공백)로 이어 쓴다. `N`은 그 종류의 개수다.

| 종류 | 한국어 | 영어(1개) | 영어(2개 이상) |
| --- | --- | --- | --- |
| 메모 | `메모 N개` | `1 memo` | `N memos` |
| 루틴 | `루틴 N개` | `1 routine` | `N routines` |
| 디데이 | `디데이 N개` | `1 D-day` | `N D-days` |

한국어 요약은 늘 `개`로 끝나므로 조사는 `가`를 쓴다. 예를 들어 `오늘 메모 2개, 루틴 3개, 디데이 1개가 있어요`, `오늘 루틴 1개가 있어요`이고, 영어는 `Today: 2 memos, 3 routines, 1 D-day`, `Today: 1 routine`이다.

앱 이름은 두 플랫폼 모두 알림 머리말에 자동으로 붙으므로 문구에 다시 넣지 않는다. 날짜도 넣지 않는다.

문구의 언어와 한국어로 보는 언어 태그의 기준은 [일일 알림 스펙(server)](../spec/server/daily-notification.md)의 `알림 문구의 언어`를 따른다. 문구는 서버가 만들어 보내고 기기는 받은 그대로 표시하므로, 기기에 설치된 앱의 언어 리소스는 이 문구에 쓰이지 않는다.

### 본문

본문은 종류마다 묶음 하나를 두고, 묶음은 메모, 루틴, 디데이 순으로 놓는다. 묶음 사이에 빈 줄을 두지 않는다. 각 묶음은 머리말 한 줄로 시작한다.

| 종류 | 한국어 머리말 | 영어 머리말 |
| --- | --- | --- |
| 메모 | `[메모]` | `[Memos]` |
| 루틴 | `[루틴]` | `[Routines]` |
| 디데이 | `[디데이]` | `[D-days]` |

목록인 종류의 묶음은 머리말 뒤에 오늘의 항목을 기준 스펙의 순서대로 한 줄에 하나씩 나열한다. 각 줄은 `- `(하이픈과 공백)으로 시작하고 줄 끝에 문장 부호를 붙이지 않는다.

| 종류 | 줄 | 예 |
| --- | --- | --- |
| 메모 | `- <제목>` | `- 치과 예약` |
| 루틴 | `- <제목> · <진행>` | `- 물 마시기 · 오늘 0 / 2000ml` |
| 디데이 | `- <제목> · <그 날의 문구>` | `- 연애 · 300일` |

`·`의 앞뒤에는 공백을 하나씩 둔다.

루틴의 `<진행>`은 목표량이 있으면 `<주기 이름> <합계> / <목표량><단위>`, 없으면 `<주기 이름> <합계><단위>`다. 숫자와 단위 사이를 띄우지 않고, 숫자에는 자릿수를 나누는 기호를 넣지 않으며, 단위는 사용자가 적은 글자 그대로 쓴다. 단위가 비어 있으면 숫자만 쓴다. [루틴 앱 스펙](../spec/client/routine.md)의 `양의 문구`와 같은 표현이다. 달성률은 쓰지 않는다.

| 주기 | 한국어 주기 이름 | 영어 주기 이름 |
| --- | --- | --- |
| `매일`, `평일만`, `주말만` | `오늘` | `Today` |
| `매주` | `이번 주` | `This week` |
| `매월` | `이번 달` | `This month` |

디데이의 `<그 날의 문구>`는 기준일 당일이면 두 언어 모두 `D-Day`다. 기념일이면 다음과 같다. `N`은 [디데이 앱 스펙](../spec/client/dday.md)의 `기념일 문구`가 정한 숫자다.

| 간격 | 한국어 | 영어(1) | 영어(2 이상) |
| --- | --- | --- | --- |
| 일 간격 | `N일` | `1 day` | `N days` |
| 12의 배수가 아닌 개월 간격 | `N개월` | `1 month` | `N months` |
| 12의 배수인 개월 간격 | `N주년` | `1 year` | `N years` |

확인 안내인 종류의 묶음은 머리말 뒤에 안내 한 줄만 둔다. 이 줄은 `- `로 시작하지 않는다.

| 종류 | 한국어 | 영어 |
| --- | --- | --- |
| 메모 | `앱에서 오늘의 메모를 확인하세요` | `Check today's memos in the app` |
| 루틴 | `앱에서 오늘의 루틴을 확인하세요` | `Check today's routines in the app` |
| 디데이 | `앱에서 오늘의 디데이를 확인하세요` | `Check today's D-days in the app` |

```text
[메모]
- 치과 예약
- 주간 회의 자료 정리
[루틴]
- 물 마시기 · 오늘 0 / 2000ml
- 운동 · 이번 주 2 / 3회
- 독서 · 이번 달 120쪽
[디데이]
- 연애 · 300일
- 시험 · D-Day
```

루틴을 정하지 못하고 디데이가 없는 날의 본문은 다음과 같다.

```text
[메모]
- 치과 예약
[루틴]
앱에서 오늘의 루틴을 확인하세요
```

제목과 단위는 줄이거나 바꾸지 않고 저장된 그대로 쓴다. 나열하는 개수에 상한을 두지 않고, 표시 영역에 들어가지 않는 부분은 각 플랫폼의 기본 동작대로 줄바꿈하거나 말줄임한다. 서버와 앱이 따로 자르지 않는다.

## 아이콘

Android에서는 상태 표시줄과 알림에 단색 런처 아이콘과 같은 그림의 알림 전용 아이콘(`ic_notification`)을 작은 아이콘으로 쓰고, 색은 시스템 기본값을 따른다. 큰 아이콘이나 별도의 이미지는 두지 않는다. 서버가 알림에 이 아이콘을 지정하고, 앱도 이 아이콘을 서버 알림의 기본 아이콘으로 정해 두며, 앱이 앞에 있을 때 직접 표시하는 알림에도 같은 아이콘을 쓴다.

iOS에서는 시스템이 알림에 붙이는 앱 아이콘을 그대로 쓰고 앱이 따로 아이콘을 지정하지 않는다.

## 표시 방식

알림은 소리를 내지 않고 화면에만 표시한다. 진동과 배지도 쓰지 않는다. Android에서는 화면 위로 잠깐 떠오르는 표시를 쓰지 않고, iOS에서는 알림 배너로 표시한다. 알림 권한을 알림 표시로만 한정하는 [알림 권한 요청 스펙](../spec/client/notification-permission.md)의 `요청 범위`와 같은 결정이다.

플랫폼별로 이 표시 방식에 해당하는 설정은 다음과 같다.

| 플랫폼 | 표시 방식 |
| --- | --- |
| Android | 소리와 화면 위 떠오름이 없고 알림 목록과 상태 표시줄에만 남는 중요도. 아래 `Android 알림 채널`이 이 중요도를 가진다 |
| iOS | 알림 배너만 사용하고 소리와 배지는 사용하지 않음 |

본문이 있는 알림의 플랫폼별 표현은 다음과 같다.

| 플랫폼 | 본문 표현 |
| --- | --- |
| Android | 접힌 알림에는 본문 첫 줄(첫 묶음의 머리말)이 보이고, 알림을 펼치면 긴 글 형식으로 여러 줄이 보인다. 펼쳤을 때 보이는 줄 수는 시스템이 정한다 |
| iOS | 알림 배너와 알림 센터의 본문 자리에 그대로 표시한다. 배너에서 보이는 줄 수와 길게 눌러 펼쳤을 때 보이는 줄 수는 시스템이 정한다 |

앱이 앞에 있는 동안 도착한 알림도 위 표현을 그대로 따른다. Android에서는 앱이 같은 채널, 아이콘, 제목, 본문과 긴 글 형식으로 직접 표시하고, iOS에서는 알림 배너와 알림 센터에 표시하며 소리와 배지는 쓰지 않는다. 앱 화면 안에는 별도의 안내를 두지 않는다.

알림은 사용자가 직접 지울 수 있고, 알림을 선택해 앱이 열리면 알림 목록에서 사라진다. 사용자가 지우지 않고 두면 다음 날 알림이 그 자리를 대신하며, 두 플랫폼 모두 이 알림은 알림 목록에 하나만 남는다. 기준 스펙의 `하루에 표시되는 알림`을 표현한 것이다.

## Android 알림 채널

Android 시스템의 알림 설정에서 사용자가 이 알림을 구분해 끌 수 있도록 전용 알림 채널을 하나 둔다. 서버가 보내는 알림은 이 채널로 표시된다.

| 요소 | 한국어 | 영어 |
| --- | --- | --- |
| 채널 이름 | `일일 알림` | `Daily reminder` |
| 채널 설명 | `매일 아침 오늘의 메모, 루틴과 디데이를 알려 줍니다.` | `Reminds you every morning of today's memos, routines, and D-days.` |

채널 이름과 설명은 기기의 앱 언어를 따른다. 채널은 이 알림에만 쓰고 다른 알림과 공유하지 않는다.

`표시 방식`의 배지를 쓰지 않는 것은 채널을 새로 만드는 기기에 적용된다. 채널이 이미 만들어져 있는 기기에서는 앱이 채널의 배지 설정을 바꾸지 않으므로 그 기기의 배지 설정이 그대로 유지된다.

## 접근성

화면 낭독기는 알림의 제목 문구를 읽고, 본문이 있으면 본문을 이어서 읽는다. 문구 자체가 안내와 내용이므로 별도의 접근성 이름이나 설명을 덧붙이지 않는다.

알림을 선택하는 조작에는 별도의 접근성 이름을 두지 않고, 각 플랫폼이 알림에 기본으로 제공하는 열기 동작을 그대로 쓴다.
