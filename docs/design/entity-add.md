# 항목 추가 화면 공통 디자인

기준 스펙: [항목 추가 화면 공통 스펙](../spec/entity-add.md)

이 문서는 새 항목 하나를 입력해 추가하는 화면들이 공통으로 쓰는 화면 구조, 표시 영역과 소프트 키보드 처리, 초점과 단축키, 진행과 피드백 표현을 소유한다. 각 화면 문서는 본문에 두는 입력의 종류와 순서, 그 화면에서만 다른 표현과 문구만 남긴다.

이 문서를 따르는 디자인 문서는 다음과 같다.

- [ContactAdd 화면 디자인](./contact-add.md)
- [PlaceAdd 화면 디자인](./place-add.md)
- [RoutineAdd 화면 디자인](./routine-add.md)
- [TagAdd 화면 디자인](./tag-add.md)
- [WebAdd 화면 디자인](./web-add.md)

## 화면 구조

추가 화면은 목록에서 이어지는 세부 화면이며, [TopLevelNavigation 디자인](./top-level-navigation.md)의 공통 내비게이션은 표시하지 않는다.

화면 상단에는 제목과 뒤로가기 버튼이 있는 상단 바를 둔다. 상단 바에는 추가 동작을 실행하는 컨트롤을 두지 않고, 추가 동작은 떠 있는 버튼으로 표시한다.

본문의 입력은 세로로 배치하고 각 입력 사이에 [공통 구성요소 간격](./dimens.md)을 둔다. 입력은 본문 가로 폭을 모두 사용한다.

## 태그 입력의 자리

태그 입력을 제공하는 화면에서는 태그 입력을 본문 가장 마지막에 둔다. 태그는 항목의 내용이 아니라 그 항목을 분류하는 정보이므로 내용 입력을 모두 지난 뒤에 둔다.

개수에 따라 높이가 변하는 입력은 고정 높이 입력보다 아래에 두어 위쪽 입력의 자리가 흔들리지 않게 한다. 그런 입력이 늘거나 줄면 태그 입력의 자리가 함께 위아래로 옮겨지지만, 태그 입력이 가장 아래에 있어 다른 입력의 자리는 흔들리지 않는다.

칩 영역의 구성과 조작은 그 화면이 쓰는 태그 입력 컴포넌트 디자인을 따른다.

## 표시 영역과 소프트 키보드

본문, 추가 버튼과 스낵바는 상태 표시 영역, 시스템 탐색 영역과 카메라 컷아웃 등 기기가 가리는 영역을 침범하지 않게 배치한다.

소프트 키보드가 나타나면 세 요소를 키보드 위 영역에 맞춰 배치한다. 입력 컴포넌트의 전체 높이가 표시 영역보다 크면 본문을 세로로 스크롤할 수 있게 한다. 개수에 따라 높이가 변하는 입력이 늘어 본문이 표시 영역을 넘는 경우도 같게 다룬다. 키보드가 닫히면 원래 표시 영역으로 되돌린다.

고른 태그가 늘어 태그 입력의 칩 영역이 커지면 본문 높이도 함께 커지므로, 다른 입력이 늘어난 경우와 같이 본문을 세로로 스크롤한다.

## 초점과 키보드 단축키

초점을 어느 입력에 두고 언제 옮기는지는 기준 스펙이 정한다. 이 문서는 초점이 옮겨 갈 때의 표현만 정한다.

초점을 옮길 때 그 입력이 표시 영역 밖에 있으면 함께 보이도록 본문을 스크롤하고, 그 입력에 맞는 소프트 키보드를 연다.

물리 키보드 환경에서는 `Cmd` 또는 `Meta`와 `Enter`를 함께 눌러 추가 동작을 실행할 수 있다.

## 진행과 피드백

추가 처리 중에는 추가 버튼의 추가 아이콘을 진행 표시로 바꾼다. 처리 중에도 입력을 잠그거나 흐리게 바꾸지 않는다.

추가 성공과 미입력 피드백은 모두 스낵바로 표시한다. 새 피드백을 표시할 때 이미 보이는 스낵바가 있으면 표시 시간이 지나기를 기다리지 않고 즉시 새 피드백으로 바꾼다.

미입력 안내는 어떤 입력이 필요한지를 문구로 구분하고, 여러 항목을 담는 입력에서는 어느 항목이 비어 있는지를 문구에 담지 않는다.

값이 필요한 입력이라도 비어 있는 상태에 오류 색이나 필수 표시를 상시로 두지 않고, 필요한 안내는 추가를 실행한 시점에만 제공한다.

## 문구와 접근성

한국어 환경과 그 외 기본 환경에서 다음 문구를 사용한다.

| 문구 | 한국어 | 그 외 기본 |
| --- | --- | --- |
| 뒤로가기 버튼 접근성 이름 | `뒤로가기` | `Navigate up` |

상단 바 제목, 추가 버튼 접근성 이름, 각 입력의 이름과 안내 문구는 화면마다 다르므로 각 화면 문서가 정한다.

각 입력의 이름과 표현은 그 입력 컴포넌트의 디자인을 따르고, 지우기 버튼의 접근성 이름은 지우기 버튼을 제공하는 입력 컴포넌트의 공용 문구를 그대로 사용한다.

같은 라벨을 반복해 읽히는 항목이 여러 개 있는 입력에서는 접근성 이름에 항목의 순서를 함께 담아 어느 항목인지 구분할 수 있게 한다. 순서는 위에서부터 `1`부터 세고, 항목을 추가하거나 삭제하면 남은 항목의 순서를 다시 센다.

## 여러 항목을 담는 입력

개수에 따라 높이가 변하는 입력은 하나의 카드에 담아 다른 입력과 구분한다. 카드 최상단에는 영역 이름을 시작 쪽에, 항목을 추가하는 버튼을 끝 쪽에 둔 행을 두고, 그 아래에 항목을 위에서부터 차례로 쌓는다. 항목이 하나도 없으면 이름 행만 표시하고 빈 상태 안내는 두지 않는다.

각 항목은 한 행에 그 항목의 입력들과 항목을 삭제하는 버튼을 순서대로 배치한다. 입력은 삭제 버튼을 뺀 남은 폭을 나눠 가지며, 값이 있으면 지우기 버튼을 표시한다.

추가 버튼을 선택하면 빈 항목이 마지막 자리에 나타나고, 삭제 버튼을 선택하면 그 항목만 사라진다. 항목이 늘거나 줄어 카드 높이가 바뀔 때는 높이가 자연스럽게 이어지도록 애니메이션으로 전환하고, 항목의 시작 쪽 위 모서리를 기준으로 삼아 남은 항목이 옆으로 밀리지 않게 한다.

추가에 성공해 입력을 비우면 카드는 이름 행만 남은 상태로 되돌아간다. 태그 입력의 칩 영역은 고른 태그를 그대로 유지하므로 되돌아가지 않는다.
