# MusicAdd 화면 디자인

기준 스펙: [MusicAdd 화면 스펙](../spec/music-add.md), [Playlist 목록·상세 배치 스펙](../spec/playlist-list-detail.md)

화면 구조, 표시 영역과 소프트 키보드, 초점과 단축키, 진행과 피드백은 [항목 추가 화면 공통 디자인](./entity-add.md)을 따른다.

## 화면 구조

MusicAdd 화면은 창 너비에 따라 단독으로 표시하거나 [Playlist 목록·상세 배치 디자인](./playlist-list-detail.md)에 따라 곡 목록과 함께 상세 영역에 표시한다.

뒤로가기 버튼의 노출 조건은 [목록·상세 배치 공통 디자인](./list-detail-pane.md)의 `버튼 노출`을 따른다.

본문에는 링크 입력, 단일 줄 제목 입력, 단일 줄 가수 입력을 순서대로 배치한다.

입력 순서는 사용자가 먼저 붙여 넣는 링크를 맨 위에 두고, 그 링크로 채워지는 제목과 가수를 아래에 이어 둔다. 제목을 가수보다 위에 두는 것은 제목이 곡을 가리키는 이름이고 가수가 같은 제목의 곡을 구분하는 값이기 때문이다. 이 화면에는 태그 입력을 두지 않는다.

## 링크 입력

링크 입력은 하나의 카드에 담고, 카드 안에 단일 줄 텍스트 입력과 불러오기 버튼과 썸네일 미리보기를 위에서부터 차례로 둔다.

텍스트 입력에는 값이 있으면 내용을 한 번에 지우는 지우기 버튼을 끝 쪽에 표시한다. 지우기 버튼이 나타나고 사라지는 표현은 [나타나고 사라지는 버튼 디자인](./button-visibility.md)을 따른다.

링크 입력에는 주소 입력에 맞춘 소프트 키보드를 요청해 `/`와 `.`을 바로 입력할 수 있게 한다. 소프트 키보드 종류는 입력기에 대한 요청일 뿐이므로 값의 형식을 보장하지 않는다. 입력 중에는 값이 YouTube 영상 링크인지 검사해 막거나 오류 색을 표시하지 않으며, 형식 안내는 사용자가 불러오기나 추가를 실행한 뒤 문구로만 알린다.

## 불러오기 버튼

불러오기 버튼은 링크 카드 안에서 텍스트 입력 바로 아래, 카드의 끝 쪽에 둔다. 링크로 실행하는 동작이므로 링크와 같은 카드에 두고, 제목·가수 입력이나 화면 아래쪽에 따로 떼어 두지 않는다.

불러오기 버튼은 라벨이 있는 버튼으로 표시하고 아이콘만 두지 않는다. 링크를 채우는 것과 곡을 추가하는 것은 결과가 다르므로, 떠 있는 추가 버튼과 헷갈리지 않게 무엇을 하는 버튼인지 라벨로 드러낸다. 떠 있는 추가 버튼보다 약한 강조를 사용해 화면의 주된 동작이 곡 추가임을 유지한다.

불러오기 버튼은 링크 값과 관계없이 언제나 같은 자리에 같은 모양으로 표시하고 비활성 표현을 쓰지 않는다. 링크가 비어 있거나 형식을 만족하지 않는 것은 사용자가 버튼을 눌렀을 때 문구로 알린다.

## 썸네일 미리보기

썸네일 미리보기는 링크 카드의 맨 아래, 불러오기 버튼 아래에 둔다. 불러오기의 결과이므로 그 버튼 바로 아래에 두고, 제목·가수 입력 사이에 끼워 넣지 않는다.

미리보기는 카드의 가로 폭을 모두 쓰고 `16:9` 비율로 표시한다. [PlaylistHome 화면 디자인](./playlist-home.md)의 곡 카드 썸네일과 같은 비율과 채움 방식을 써서, 사용자가 추가하기 전에 목록에서 보일 모습을 그대로 확인하게 한다.

썸네일이 없으면 미리보기 자리를 두지 않고 카드에서 완전히 비운다. 불러오기 전에는 링크 입력과 불러오기 버튼만 있는 카드이고, 불러오기에 성공해 썸네일이 채워지면 카드가 그만큼 아래로 늘어난다. 높이가 바뀔 때는 [항목 추가 화면 공통 디자인](./entity-add.md)의 `여러 항목을 담는 입력`이 항목 높이 변화에 쓰는 것과 같은 전환을 사용해 제목·가수 입력이 튀지 않고 이어서 내려가게 한다.

이미지를 아직 받아오는 중이거나 주소를 열 수 없으면 [PlaylistHome 화면 디자인](./playlist-home.md)의 `썸네일`과 같게 빈 자리로 표시한다. 미리보기는 확인만 하는 자리이므로 누를 수 있는 요소로 두지 않고, 썸네일만 지우거나 바꾸는 컨트롤도 두지 않는다.

## 진행과 피드백

불러오기를 처리하는 동안에는 불러오기 버튼의 라벨 자리를 진행 표시로 바꾸고 버튼의 크기와 자리는 그대로 둔다. 처리 중에도 링크, 제목, 가수 입력을 잠그거나 흐리게 바꾸지 않으며, 사용자는 곡 추가와 뒤로가기를 그대로 실행할 수 있다.

불러오기 성공은 제목과 가수와 썸네일이 불러온 영상의 값으로 바뀌는 것으로 드러나므로 별도의 스낵바를 표시하지 않는다. 이미 값이 있던 자리도 덮어쓰므로, 무엇을 덮어쓸지 되묻는 확인 대화상자도 두지 않는다.

불러오기 실패 안내는 [항목 추가 화면 공통 디자인](./entity-add.md)의 `진행과 피드백`에 따라 미입력 안내와 같은 스낵바로 표시한다.

추가에 성공하면 링크, 제목, 가수와 썸네일 미리보기를 비운다. 미리보기가 사라지면서 링크 카드는 불러오기 전의 높이로 돌아간다.

## 표시 영역과 소프트 키보드

배치는 창 너비, 창 높이와 기기 자세에 따라 달라지지 않는다.

## 문구와 접근성

[항목 추가 화면 공통 디자인](./entity-add.md)의 `문구와 접근성`에 더해 한국어 환경과 그 외 기본 환경에서는 다음 문구를 사용한다.

| 문구 | 한국어 | 그 외 기본 |
| --- | --- | --- |
| 상단 바 제목 | `곡 추가` | `Add Music` |
| 뒤로가기 접근성 이름 | `뒤로가기` | `Navigate up` |
| 추가 버튼 접근성 이름 | `곡 추가` | `Add music` |
| 링크 입력 이름 | `링크` | `Link` |
| 가수 입력 이름 | `가수` | `Artist` |
| 불러오기 버튼 라벨 | `불러오기` | `Fetch` |
| 불러오기 버튼 접근성 이름 | `링크로 곡 정보 불러오기` | `Fetch music info from link` |
| 썸네일 미리보기 접근성 이름 | `썸네일 미리보기` | `Thumbnail preview` |
| 추가 성공 안내 | `곡이 추가되었습니다.` | `Music added.` |
| 링크 미입력 안내 | `링크를 입력해 주세요.` | `Please enter a link.` |
| 링크 형식 안내 | `YouTube 영상 링크를 입력해 주세요.` | `Please enter a YouTube video link.` |
| 제목 미입력 안내 | `제목을 입력해 주세요.` | `Please enter a title.` |
| 가수 미입력 안내 | `가수를 입력해 주세요.` | `Please enter an artist.` |
| 불러오기 실패 안내 | `링크에서 곡 정보를 불러오지 못했습니다.` | `Could not fetch music info from the link.` |

불러오기 버튼의 접근성 이름은 라벨보다 길게 두어 무엇을 불러오는 버튼인지 낭독으로도 알 수 있게 한다.

썸네일 미리보기는 영상의 내용을 글로 옮길 수 없으므로 이미지 자체를 설명하지 않고 그 자리가 무엇인지만 접근성 이름으로 알린다. 썸네일이 없어 미리보기가 없을 때는 낭독 도구에도 남기지 않는다.

불러오기가 진행되는 동안에는 버튼이 처리 중임을 낭독 도구에 알리고, 버튼의 이름은 바꾸지 않는다.

제목 입력의 이름과 표현은 그 입력 컴포넌트의 디자인을 따른다.
