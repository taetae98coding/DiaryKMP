# 항목 목록 화면 공통 디자인

기준 스펙: [항목 목록 화면 공통 스펙](../spec/client/entity-home.md), [SwipeToFinishAndDelete 컴포넌트 스펙](../spec/client/swipe-to-finish-and-delete.md), [페이지 조회 목록의 자리 표시 스펙](../spec/client/paged-list-placeholder.md), [목록 빈 상태 스펙](../spec/client/list-empty-state.md), [새로고침 스펙](../spec/client/sync-refresh.md)

이 문서는 `더보기`에서 이어지고, 항목을 2열 카드 격자로 보여 주며, 카드에서 삭제만 제공하는 항목 목록 화면들이 함께 쓰는 화면 구조, 추가 버튼, 카드 조작, 삭제 스와이프, 자리 표시·빈 상태·새로고침 표현, 격자와 시스템 영역, 단축키와 공통 문구를 소유한다. 상단 바의 제목과 동작 버튼, 정렬 줄을 두는지, 카드 내용과 격자 종류(고정·지그재그), 자리 표시 카드의 비움 형태, 빈 상태 아이콘과 문구, 화면에만 있는 표현은 각 화면 문서가 정한다.

완료 여부를 가진 [MemoHome 목록](./memo-home.md)과 [TagHome 목록](./tag-home.md), 보기 모드를 가진 [PlaceHome 화면](./place-home.md), 목록을 서버에서 불러오는 [FileHome 화면](./file-home.md), 노출하는 항목이 없는 [RoutineHome 화면](./routine-home.md)은 이 문서를 따르지 않는다.

## 화면 구조

화면은 `더보기`에서 이어지는 세부 화면이며, 공통 내비게이션 영역은 [TopLevelNavigation 디자인](./top-level-navigation.md)의 `세부 화면에서의 노출`에 따라 숨긴다. 창 너비에 따라 단독으로 표시하거나 각 화면의 목록·상세 배치 디자인에 따라 상세 영역과 자리를 나눠 표시한다.

화면 상단에는 제목과 뒤로가기 동작이 있는 상단 바를 둔다. 상단 바 끝 쪽의 동작 버튼과 정렬 줄은 각 화면 문서가 정한다.

## 추가 버튼

본문 오른쪽 아래에 항목 추가를 실행하는 플로팅 액션 버튼을 겹쳐 표시한다. 버튼에는 추가를 뜻하는 더하기 아이콘을 표시하고, 목록의 상태와 관계없이 같은 자리에 같은 모양으로 표시한다. 버튼의 노출 조건은 [목록·상세 배치 공통 디자인](./list-detail-pane.md)의 `버튼 노출`을 따른다.

## 카드

카드 안의 글줄은 각각 한 줄을 유지하며, 카드에서 사용할 수 있는 폭을 넘으면 기본 이동 속도와 간격으로 가로 이동을 시작하고 카드가 표시되는 동안 횟수 제한 없이 반복한다. 접근성에는 생략하지 않은 전체 글을 제공한다.

카드 전체를 누를 수 있는 자리로 둔다. 누르는 동안에는 카드에 기본 눌림 표현만 두고, 누른 뒤 카드를 선택된 상태로 남기는 표시는 두지 않는다.

## 삭제 스와이프

사용자는 카드를 오른쪽에서 왼쪽으로 스와이프해 삭제한다. 이 문서를 따르는 항목에는 완료 여부가 없으므로 왼쪽에서 오른쪽으로 미는 조작에는 반응하지 않는다.

스와이프 중 상태 아이콘, 삭제 기준, 취소와 비활성 표현은 [SwipeToFinishAndDelete 컴포넌트 디자인](./swipe-to-finish-and-delete.md)을 따른다. 자리 표시 카드는 스와이프가 시작되지 않는다.

삭제가 성립하면 카드를 격자에서 없애고, 결과 안내와 실행 취소 동작을 스낵바로 표시한다. 실행 취소 동작이 있는 스낵바는 Material 기본의 긴 표시 시간을 쓴다. 이미 보이는 스낵바가 있으면 표시 시간이 지나기를 기다리지 않고 즉시 새 안내로 바꾼다. 스낵바는 플로팅 액션 버튼에 가리지 않는 자리에 둔다. 표현은 [MemoHome 목록 디자인](./memo-home.md)의 완료·삭제 스낵바와 같다.

삭제가 저장되지 못하면 스낵바를 표시하지 않는다.

실행 취소로 돌아온 카드는 스와이프 전 모양으로 정렬 기준에 맞는 자리에 다시 나타난다.

목록이 갱신될 때 카드가 자리를 옮기면 기본 항목 이동 애니메이션으로 옮긴다.

## 자리 표시

아직 준비되지 않은 자리에는 [페이지 조회 목록의 자리 표시 디자인](./paged-list-placeholder.md)에 따라 자리 표시 카드를 표시한다. 자리 표시 카드의 접근성 처리도 그 문서를 따른다. 자리 표시 카드에서 무엇을 비워 두고 어떤 높이를 차지하는지는 각 화면 문서가 정한다.

## 빈 상태

표시할 항목이 하나도 없으면 격자 자리에 [목록 빈 상태 디자인](./list-empty-state.md)의 빈 상태를 표시하고, 격자와 빈 상태 사이의 전환도 그 문서를 따른다. 빈 상태의 아이콘과 문구는 각 화면 문서가 정한다.

빈 상태에서도 플로팅 액션 버튼을 표시하는 동안에는 그 버튼을 같은 자리에 같은 모양으로 두고, 비활성 표현을 사용하지 않는다.

## 새로고침

목록 영역을 [새로고침 디자인](./sync-refresh.md)의 당김 새로고침 컨테이너로 감싼다. 컨테이너가 감싸는 범위는 각 화면 문서가 정한다.

진행 표시는 목록 영역 위쪽 가로 가운데에 겹쳐 표시하고 격자를 밀어내지 않는다. 진행 표시의 모양과 크기, 임계값, 나타나고 사라지는 모션, 진행 중 조작 가능 여부는 [새로고침 디자인](./sync-refresh.md)을 그대로 따르며 화면마다 따로 정하지 않는다.

격자는 맨 위에 있을 때만 당김이 시작된다. 격자 대신 빈 상태를 표시하는 동안에는 스크롤할 것이 없으므로 당김이 곧바로 시작된다.

진행 표시가 나타나 있는 동안에도 화면의 조작을 그대로 할 수 있고 어떤 요소도 비활성으로 표시하지 않는 것은 [새로고침 디자인](./sync-refresh.md)의 `다른 상태 표현과의 관계`를 따른다. 목록과 상세를 함께 표시하는 배치에서 당김과 진행 표시는 같은 문서의 `적응형 배치`에 따라 목록 영역에만 둔다.

## 격자와 적응형 배치

카드는 화면 너비와 관계없이 한 행에 두 개씩 표시되는 2열 격자로 배치하고, 카드 사이에는 가로와 세로로 각각 [공통 항목 간격](./dimens.md)을 둔다. 격자 바깥 여백은 [공통 화면 가로 여백과 세로 여백](./dimens.md)을 따른다. 고정 격자와 지그재그 격자 중 무엇을 쓰는지는 각 화면 문서가 정한다.

격자는 창 너비, 창 높이와 자세에 관계없이 2열을 유지하므로 목록 영역이 넓어지면 카드가 함께 넓어진다. 목록이 상세 영역과 자리를 나눠 쓰는 배치와 그 자리에서의 버튼 노출은 각 화면의 목록·상세 배치 디자인이 정한다.

본문은 시스템 상태 영역과 디스플레이 컷아웃에 가려지지 않는 자리에 두고, 격자의 마지막 카드가 플로팅 액션 버튼에 가리지 않게 배치한다. 격자 내용 아래쪽 여백은 [공통 여백과 간격 디자인](./dimens.md)의 `플로팅 액션 버튼 아래 여백` 사용 기준을 따른다.

## 키보드 단축키

물리 키보드 환경에서는 `Command + A`를 눌러 추가 버튼과 같은 동작을 실행한다. 키 조합과 처리 조건은 [목록 추가 단축키 디자인](./list-add-shortcut.md)을 따른다.

## 문구와 접근성

한국어 환경과 그 외 기본 환경에서 다음 문구를 함께 사용한다. 상단 바 제목, 추가 버튼과 삭제 스와이프 아이콘의 접근성 이름, 빈 상태 문구, 삭제 안내는 각 화면 문서가 정한다.

| 항목 | 한국어 | 그 외 기본 |
| --- | --- | --- |
| 뒤로가기 접근성 이름 | `뒤로가기` | `Navigate up` |
| 실행 취소 동작 | `실행 취소` | `Undo` |
