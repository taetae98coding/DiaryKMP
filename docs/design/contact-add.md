# ContactAdd 화면 디자인

기준 스펙: [ContactAdd 화면 스펙](../spec/contact-add.md)

화면 구조, 표시 영역과 소프트 키보드, 초점과 단축키, 진행과 피드백, 여러 항목을 담는 입력의 공통 표현은 [항목 추가 화면 공통 디자인](./entity-add.md)을 따른다.

## 화면 구조

ContactAdd 화면은 창 너비에 따라 단독으로 표시하거나 [Contact 목록·상세 배치 디자인](./contact-list-detail.md)에 따라 연락처 목록과 함께 상세 영역에 표시한다.

뒤로가기 버튼의 노출 조건은 [목록·상세 배치 공통 디자인](./list-detail-pane.md)의 `버튼 노출`을 따른다.

본문에는 단일 줄 이름 입력, 설명 입력, 키 입력, 신발 사이즈 입력, 생일 입력, 전화번호 입력을 순서대로 배치한다.

입력 순서는 연락처를 가리키는 이름과 설명을 먼저 두고, 높이가 정해진 키·신발 사이즈·생일을 그 아래에, 개수에 따라 높이가 변하는 전화번호를 가장 아래에 둔다. 개수에 따라 높이가 변하는 입력을 아래에 두는 기준은 [항목 추가 화면 공통 디자인](./entity-add.md)의 `태그 입력의 자리`가 정한 것과 같다.

생일은 구분 전환이 나타나면 한 행이 늘어나지만 늘어나는 폭이 한 행으로 정해져 있어, 사용자가 넣은 개수만큼 끝없이 늘어나는 전화번호와 같은 자리로 다루지 않는다.

설명 입력의 구성과 표현은 [설명 입력 컴포넌트 디자인](./description-input.md)을 따른다.

## 이름 입력

이름은 단일 줄 텍스트 입력으로 배치하고, 입력한 값이 있으면 내용을 한 번에 지우는 지우기 버튼을 끝 쪽에 표시한다. 지우기 버튼이 나타나고 사라지는 표현은 [나타나고 사라지는 버튼 디자인](./button-visibility.md)을 따른다.

## 키와 신발 사이즈 입력

키와 신발 사이즈는 각각 별개의 카드에 담은 단일 줄 텍스트 입력으로 배치하고, 입력한 값이 있으면 내용을 한 번에 지우는 지우기 버튼을 끝 쪽에 표시한다. 지우기 버튼이 나타나고 사라지는 표현은 [나타나고 사라지는 버튼 디자인](./button-visibility.md)을 따른다.

두 입력의 이름에는 단위를 함께 적어 값이 비어 있는 동안에도 어떤 단위로 입력해야 하는지 보이게 한다.

키 입력에는 소수점을 포함한 숫자 소프트 키보드를, 신발 사이즈 입력에는 숫자 소프트 키보드를 요청한다. 소프트 키보드 종류는 입력기에 대한 요청일 뿐이므로, 물리 키보드나 붙여넣기로 들어온 값도 기준 스펙의 `키와 신발 사이즈 입력`이 정한 문자와 자리 수만 반영한다. 반영하지 않는 입력에는 오류 색이나 안내를 표시하지 않고, 값이 바뀌지 않는 것으로만 드러낸다.

## 생일 입력

생일은 하나의 카드에 담고, 첫 행에 고른 생일을 두고 생일을 골랐을 때만 두 번째 행에 달력 구분 전환을 둔다.

첫 행의 시작 쪽에 생일 영역 이름을, 끝 쪽에 고른 생일을 표시하는 버튼과 생일을 지우는 버튼을 순서대로 둔다. 생일 버튼은 남은 폭에서 내용만큼만 차지한다.

생일을 아직 고르지 않았으면 생일 버튼에 고르지 않았음을 알리는 문구를 표시하고 지우기 버튼과 구분 전환은 표시하지 않는다. 생일을 고르면 버튼에 고른 날짜를 표시하고 지우기 버튼과 구분 전환을 함께 표시한다. 지우기 버튼이 나타나고 사라지는 표현은 [나타나고 사라지는 버튼 디자인](./button-visibility.md)을 따른다.

생일 버튼을 누르면 날짜 선택 다이얼로그를 표시한다. 다이얼로그의 조작과 확인·취소 결과의 표현은 [DiaryDateTimeInput 컴포넌트 디자인](./diary-date-time-input.md)의 `날짜 선택`을 따르고, 고른 날짜와 다이얼로그 문구의 표시 형식도 그 문서의 `표시 형식`과 `문구`를 따른다.

생일이 바뀔 때의 값 전환 표현도 [DiaryDateTimeInput 컴포넌트 디자인](./diary-date-time-input.md)의 `값 변경 전환`을 따른다.

## 달력 구분 전환

구분 전환은 두 번째 행의 끝 쪽에 두고, 시작 쪽에 양력 칸과 그 다음에 음력 칸을 좌우로 나란히 붙여 항상 하나만 선택된 상태로 표시한다. 두 칸은 각각 내용만큼만 차지한다. 기본값인 양력을 앞에 둔다. 두 항목 중 하나만 선택된 상태로 표시하는 기준은 [DiaryMap 컴포넌트 디자인](./diary-map.md)의 제공자 전환 컨트롤과 같다.

두 라벨을 모두 보이게 두는 것은 사용자가 지금 어느 달력이 골라져 있는지와 바꿀 수 있는 다른 달력이 무엇인지를 함께 읽게 하려는 것이다. 고른 쪽만 표시하면 누를 수 있는 컨트롤인지 드러나지 않는다.

구분 전환 행은 생일을 고르면 아래로 펼치며 점차 나타내고, 생일을 지우면 즉시 조작할 수 없게 한 뒤 위로 줄이며 점차 사라지게 한다. 이 표현은 [DiaryDateTimeInput 컴포넌트 디자인](./diary-date-time-input.md)의 `사용 여부 전환`이 기간 선택 영역에 쓰는 것과 같다.

선택하지 않은 칸을 누르면 그 구분이 선택되고, 이미 선택된 칸을 눌러도 선택은 바뀌지 않는다.

구분을 바꿔도 첫 행의 날짜 표시는 바뀌지 않는다. 기준 스펙의 `생일`이 정한 대로 음력과 양력 사이에 날짜를 환산하지 않으므로, 사용자가 보는 연·월·일은 구분에 따라 달라지지 않는다.

날짜 선택 다이얼로그는 구분과 무관하게 같은 양력 달력으로 표시한다. 음력을 고른 상태에서 다이얼로그를 열어도 달력의 요일과 월 구성을 그대로 두며 음력 달력으로 바꾸지 않는다.

## 전화번호 입력

전화번호는 [항목 추가 화면 공통 디자인](./entity-add.md)의 `여러 항목을 담는 입력`에 따라 하나의 카드에 담는다.

전화번호 항목 하나는 한 행에 단일 줄 번호 입력과 그 항목을 삭제하는 버튼을 순서대로 배치한다. 번호 입력은 삭제 버튼을 뺀 남은 폭을 모두 사용한다.

번호 입력에는 전화번호 입력에 맞춘 소프트 키보드를 요청해 숫자와 `+`, `-`를 바로 입력할 수 있게 한다. 소프트 키보드 종류는 입력기에 대한 요청일 뿐이므로 값의 형식을 보장하지 않으며, 입력 중에는 값이 전화번호 형식인지 검사해 막거나 오류 색을 표시하지 않는다.

## 표시 영역과 소프트 키보드

배치는 창 너비, 창 높이와 기기 자세에 따라 달라지지 않는다.

## 진행과 피드백

추가에 성공하면 이름, 설명, 키와 신발 사이즈를 비우고 고른 생일을 지우며 전화번호 항목을 모두 없앤다. 생일 행은 고르지 않은 표시로 되돌아가고 구분 전환은 사라진다.

## 문구와 접근성

[항목 추가 화면 공통 디자인](./entity-add.md)의 `문구와 접근성`에 더해 한국어 환경과 그 외 기본 환경에서는 다음 문구를 사용한다.

| 문구 | 한국어 | 그 외 기본 |
| --- | --- | --- |
| 상단 바 제목 | `연락처 추가` | `Add Contact` |
| 추가 버튼 접근성 이름 | `연락처 추가` | `Add contact` |
| 이름 입력 이름 | `이름` | `Name` |
| 키 입력 이름 | `키 (cm)` | `Height (cm)` |
| 신발 사이즈 입력 이름 | `신발 사이즈 (mm)` | `Shoe size (mm)` |
| 생일 영역 이름 | `생일` | `Birthday` |
| 생일 미선택 표시 | `선택 안 함` | `Not set` |
| 생일 지우기 버튼 접근성 이름 | `생일 지우기` | `Clear birthday` |
| 달력 구분 전환 접근성 이름 | `생일 달력` | `Birthday calendar` |
| 양력 칸 라벨 | `양력` | `Solar` |
| 음력 칸 라벨 | `음력` | `Lunar` |
| 전화번호 영역 이름 | `전화번호` | `Phone numbers` |
| 번호 입력 이름 | `번호` | `Number` |
| 번호 입력 접근성 이름 | `{순서}번째 번호` | `Number {순서}` |
| 전화번호 추가 버튼 접근성 이름 | `전화번호 추가` | `Add phone number` |
| 전화번호 삭제 버튼 접근성 이름 | `전화번호 삭제` | `Remove phone number` |
| 추가 성공 안내 | `연락처가 추가되었습니다.` | `Contact added.` |
| 이름 미입력 안내 | `이름을 입력해 주세요.` | `Please enter a name.` |
| 전화번호 미입력 안내 | `전화번호를 입력해 주세요.` | `Please enter a phone number.` |

설명 입력의 이름과 표현은 그 입력 컴포넌트의 디자인을 따른다.

생일 버튼은 고른 날짜나 미선택 표시를 그대로 읽히게 두고 별도의 접근성 이름을 두지 않는다. 앞에 있는 생일 영역 이름이 무엇을 고르는 버튼인지 이미 알려 준다.

구분 전환의 두 칸도 라벨을 그대로 읽히게 두고 칸마다 접근성 이름을 두지 않는다. 대신 전환 컨트롤 전체에 접근성 이름을 두어 두 칸이 무엇을 고르는 것인지 알려 주고, 어느 칸이 골라져 있는지는 선택 상태로 전달한다.
