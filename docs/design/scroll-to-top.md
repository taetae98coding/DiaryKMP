# 맨 위로 돌아가기 디자인

기준 스펙: [맨 위로 돌아가기 스펙](../spec/client/scroll-to-top.md)

이 문서는 맨 위로 돌아가기의 조작 수단, 조작한 위치가 화면에 대응되는 기준, 돌아가는 움직임과 피드백을 소유한다. 대상 화면과 돌아가는 자리, 돌아가지 않는 경우는 기준 스펙이 정한다.

## 조작 수단

iPhone과 iPad에서 화면 맨 위의 상태 표시줄을 한 번 누른다. 기기가 모든 앱에 같은 방식으로 제공하는 조작이므로 앱은 이 조작을 위한 버튼이나 안내를 따로 두지 않는다.

기기가 상태 표시줄을 표시하지 않는 동안에는 조작 수단이 없다. iPhone을 가로로 돌렸을 때가 그렇다.

## 조작 위치

상태 표시줄에서 누른 지점의 가로 위치가 기준 스펙의 `돌아가는 본문`이 말하는 조작한 위치다. 누른 지점에서 아래로 곧게 내린 선이 지나는 본문이 조작한 위치 아래에 놓인 본문이다.

| 배치 | 누른 위치와 돌아가는 화면 |
| --- | --- |
| 본문 하나만 표시 | 상태 표시줄 어디를 눌러도 그 본문이 돌아간다. |
| 본문을 위아래로 나누어 표시 | 상태 표시줄 어디를 눌러도 한 번에 위쪽 본문 하나만 돌아가고, 다시 누르면 그 아래 본문이 돌아간다. |
| 본문을 좌우로 나누어 표시 | 누른 지점 아래의 본문만 돌아간다. |
| 목록과 상세 영역을 나란히 표시 | 목록 위를 누르면 목록이, 상세 영역 위를 누르면 상세 영역의 화면이 돌아간다. 두 영역의 너비는 [목록·상세 배치 공통 디자인](./list-detail-pane.md)의 `크기 조절`로 사용자가 조절한 비율을 따른다. |
| 넓은 화면의 iPad에서 사이드바가 화면 옆자리를 차지 | 사이드바 위를 누르면 어느 화면도 돌아가지 않는다. 사이드바 옆에 놓인 화면은 위의 경우들과 같다. |
| 넓은 화면의 iPad에서 사이드바가 화면 위에 겹쳐 펼쳐짐 | 사이드바 위를 누르면 그 아래에 놓인 화면이 돌아간다. 사이드바 밖의 위치는 위의 경우들과 같다. |

사이드바가 화면 옆자리를 차지할지 화면 위에 겹쳐 펼쳐질지는 [TopLevelNavigation 디자인](./top-level-navigation.md)의 `iOS 내비게이션`대로 시스템이 창 환경에 따라 정한다.

## 움직임

화면 본문은 돌아가는 자리까지 스크롤 애니메이션으로 이동해 어디에서 올라왔는지 보여 준다. 본문에 놓인 내용은 그대로이고 보는 자리만 옮기는 것이므로 [TopLevelNavigation 디자인](./top-level-navigation.md)의 `목록이 돌아가는 움직임`과 같은 움직임을 쓴다.

이미 맨 위를 보고 있으면 아무 움직임도 일어나지 않는다.

## 피드백

이 조작만의 피드백은 두지 않는다. 진동, 스낵바, 안내 문구 없이 사용자는 본문이 올라가는 움직임으로 결과를 확인한다. 화면 위에 창이 떠 있어 돌아가지 않을 때도 따로 알리지 않는다.
