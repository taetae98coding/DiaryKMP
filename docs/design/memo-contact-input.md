# 메모 연락처 입력 컴포넌트 디자인

기준 스펙: [메모 연락처 입력 컴포넌트 스펙](../spec/client/memo-contact-input.md)

## 구성과 배치

연락처 입력에는 현재 선택한 연락처의 칩과 연락처 추가 칩을 표시하는 칩 영역을 둔다. 연락처 추가 칩이 연락처 입력임을 드러내므로 별도의 라벨은 두지 않는다.

칩 영역을 담는 카드, 칩 영역의 높이와 여백, 칩의 정렬과 줄바꿈, 선택 상태가 바뀔 때의 전환은 [메모 웹 입력 컴포넌트 디자인](./memo-web-input.md)의 `구성과 배치`를 그대로 따른다. 태그 입력·웹 입력과 같은 구성을 쓰고 다루는 대상만 다르게 두어, 사용자가 같은 폼 안에서 같은 방식으로 대상을 고른다.

연락처 입력을 폼의 어느 자리에 두는지는 [메모 본문 배치 디자인](./memo-form.md)이 소유한다.

## 연락처 칩

연락처 칩에는 연락처의 이름만 표시한다. 연락처에는 저장된 컬러가 없으므로 [메모 태그 입력 컴포넌트 디자인](./memo-tag-input.md)의 태그 칩이 두는 컬러 원형 표시에 해당하는 요소는 두지 않고, 그 자리를 비워 두지도 않는다. 이는 [메모 웹 입력 컴포넌트 디자인](./memo-web-input.md)의 웹 칩과 같은 기준이다.

연락처의 즐겨찾기 여부는 칩에 표시하지 않는다. 즐겨찾기는 [ContactHome 화면 디자인](./contact-home.md)의 목록에서 어느 연락처가 앞에 놓였는지 알리기 위한 표시이고, 칩은 이 메모에 연결한 연락처를 알리는 자리이므로 두 표시가 섞이지 않게 한다. 생일과 전화번호도 같은 기준으로 칩에 두지 않는다.

이름이 칩에서 쓸 수 있는 폭을 넘었을 때의 표시와 칩 하나의 최대 폭은 [칩 이름 표시 디자인](./chip.md)을 따른다.

연락처 칩을 누르면 그 연락처의 ContactDetail 화면으로 이동한다. 칩에는 버튼 역할과 연락처 상세로 이동함을 알리는 동작 접근성 이름을 제공한다. 칩을 눌러도 연락처 선택 목록은 열지 않는다.

## 연락처 추가 칩

칩 영역의 연락처 칩 흐름 마지막에는 연락처 추가 칩을 표시한다. 선택 상태가 바뀌어 칩이 자리를 옮겨도 연락처 추가 칩은 항상 마지막에 둔다.

연락처 추가 칩에는 추가를 나타내는 플러스 아이콘과 `연락처 선택` 라벨을 표시한다. 선택한 연락처가 없으면 칩 영역에는 연락처 추가 칩만 표시한다.

연락처 추가 칩을 누르면 기준 스펙의 `추가 항목의 동작 판정`에 따라 연락처 선택 목록을 열거나 ContactAdd 화면으로 이동한다. 어느 동작으로 이어지든 칩의 표현은 같으며, 동작에 따라 라벨이나 아이콘을 바꾸지 않는다. 칩에는 버튼 역할과 연락처 선택으로 이어짐을 알리는 동작 접근성 이름을 제공한다.

ContactAdd 화면으로 이동할 때 별도의 안내나 전환 표시를 두지 않고 바로 이동한다.

## 연락처 선택 목록

연락처 추가 칩으로 연락처 선택 목록이 열리면 다음과 같이 표시한다.

목록을 담는 대화상자의 구조와 여백, 목록이 차지하는 자리의 높이와 그 안의 스크롤, 항목이 들어오고 빠질 때의 애니메이션, 항목을 눌러 선택을 바꾸는 조작, 확인 버튼을 두지 않고 바깥 누름과 뒤로가기로 닫는 조작은 [메모 웹 입력 컴포넌트 디자인](./memo-web-input.md)의 `웹 선택 목록`을 그대로 따른다.

목록의 각 항목은 [선택 목록 항목 디자인](./picker-row.md)을 따르고, 연락처의 이름을 첫 줄에, 첫 번째 전화번호를 보조 줄에 표시한다. 컬러 원형 표시는 두지 않는다.

같은 이름의 연락처가 여러 개일 수 있으므로 목록에는 전화번호를 함께 두어 사용자가 어느 연락처인지 가릴 수 있게 한다. 칩에는 폭이 좁아 전화번호를 두지 않는다.

전화번호가 하나도 없는 연락처는 보조 줄을 두지 않고 이름만 표시한다. 그 항목의 높이와 이름의 위치는 [선택 목록 항목 디자인](./picker-row.md)의 `글자와 간격`을 따른다.

목록에는 연락처의 생일과 즐겨찾기 여부를 표시하지 않는다. 연락처를 고르는 데 필요한 것은 어느 연락처인지 가리는 이름과 전화번호이고, 목록의 순서도 `연락처 선택 목록의 순서`에 따라 즐겨찾기와 무관하기 때문이다.

## 연락처 선택 목록의 순서

목록은 기준 스펙의 `선택할 수 있는 연락처`가 정한 이름 오름차순으로만 놓는다. ContactHome 화면과 달리 즐겨찾기를 앞으로 옮기지 않으므로, 목록에 즐겨찾기를 알리는 표시나 구분선도 두지 않는다.

## 연락처 선택 목록의 검색 입력

목록 제목 바로 아래, 목록 위에 검색 입력을 상시 표시한다. 자리, 구성, 자리 표시 문구의 역할, 목록과의 간격, 초점과 소프트 키보드 동작은 [태그 선택 입력 공통 디자인](./tag-select-input.md)의 `태그 선택 목록의 검색 입력`과 같고, 자리 표시 문구만 이 목록의 문구를 쓴다.

## 연락처 선택 목록의 검색 결과 없음

검색어를 입력해 나타낼 연락처가 없어지면 목록 자리에 안내 문구를 표시한다. 안내의 구성, 배치, 전환은 [태그 선택 입력 공통 디자인](./tag-select-input.md)의 `태그 선택 목록의 검색 결과 없음`과 같고, 문구만 이 목록의 문구를 쓴다. 표시하는 조건은 기준 스펙의 `연락처 검색`을 따른다.

안내를 표시하는 동안에도 검색 입력과 연락처 추가 버튼은 같은 자리에 그대로 두어 사용자가 검색어를 고치거나 연락처를 추가할 수 있게 한다.

## 연락처 선택 목록의 연락처 추가 버튼

목록 아래에 연락처 추가 버튼을 둔다. 버튼의 자리, 스크롤과 무관하게 고정되는 배치, 아이콘과 폭 전체를 쓰는 텍스트 버튼 형태, 목록과의 간격, 나타낼 연락처가 없어도 그대로 두는 기준은 [메모 웹 입력 컴포넌트 디자인](./memo-web-input.md)의 `웹 선택 목록의 웹 추가 버튼`을 그대로 따른다.

버튼에는 `연락처 추가` 라벨을 표시한다. 칩의 `연락처 선택`과 라벨을 가르는 기준도 그 문서와 같다. 칩은 선택 목록을 여는 동작을, 이 버튼은 ContactAdd 화면으로 이동하는 동작을 나타낸다.

버튼을 누르면 목록을 닫고 ContactAdd 화면으로 이동한다. 이동할 때 별도의 안내나 전환 표시를 두지 않는다. 버튼에는 버튼 역할과 연락처 추가로 이어짐을 알리는 동작 접근성 이름을 제공한다.

## 연락처 선택 목록의 준비 상태

아직 준비되지 않은 자리에는 [페이지 조회 목록의 자리 표시 디자인](./paged-list-placeholder.md)에 따라 자리 표시 항목을 둔다. 이 목록의 자리 표시 항목은 이름과 전화번호를 비워 두고, 체크 표시는 선택하지 않은 상태로 표시한다.

목록을 처음 불러오거나 다음 연락처를 이어서 불러오는 데 실패해도 별도의 오류 표시나 재시도 동작을 두지 않고 이미 나타난 항목을 그대로 표시한다.

검색어가 비어 있는데 나타낼 연락처가 없으면 목록 영역을 비워 두고 별도의 안내 문구를 두지 않는다. 검색어를 입력해 나타낼 연락처가 없어졌을 때의 표시는 `연락처 선택 목록의 검색 결과 없음`을 따른다.

목록을 닫았다가 다시 열면 스크롤 위치를 이어받지 않고 목록의 맨 위에서 시작한다.

## 반영 표시

선택과 해제에는 진행 표시를 두지 않는다. 항목을 누르면 체크 표시가 곧바로 바뀌고, 반영된 결과는 칩 영역에 이어서 나타난다.

| 연락처 추가 동작 접근성 이름 | `연락처 추가` | `Add contact` |
