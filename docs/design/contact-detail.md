# ContactDetail 화면 디자인

기준 스펙: [ContactDetail 화면 스펙](../spec/contact-detail.md)

## 화면 구조

ContactDetail 화면은 창 너비에 따라 단독으로 표시하거나 [Contact 목록·상세 배치 디자인](./contact-list-detail.md)에 따라 연락처 목록과 함께 상세 영역에 표시한다. 공통 내비게이션 영역은 [TopLevelNavigation 디자인](./top-level-navigation.md)에 따라 숨긴다.

화면 상단에는 저장된 연락처 이름을 제목으로 두는 상단 바를 둔다. 뒤로가기 버튼의 노출 조건은 [목록·상세 배치 공통 디자인](./list-detail-pane.md)의 `버튼 노출`을 따르므로, 단독으로 표시할 때만 뒤로가기 버튼을 둔다.

조회가 완료되면 상단 바 끝 쪽에 즐겨찾기 버튼과 삭제 버튼을 이 순서로 둔다. 두 버튼은 선택한 탭과 관계없이 같은 자리에 그대로 표시한다. 상단 바에는 이 두 버튼만 두고 수정 동작을 실행하는 컨트롤과 한 탭에서만 쓰는 동작은 두지 않는다. 수정은 `떠 있는 버튼`에 따라 연락처 디테일 탭에 떠 있는 버튼으로 제공한다.

상단 바의 연락처 이름은 한 줄을 유지한다. 이름이 사용할 수 있는 폭을 넘으면 기본 이동 속도와 간격으로 가로 이동을 시작하고, 화면에 표시되는 동안 횟수 제한 없이 반복한다. 접근성에는 생략하지 않은 전체 이름을 제공한다. 이는 [ContactHome 화면 디자인](./contact-home.md)의 연락처 카드 이름과 같은 기준이다.

화면은 위에서부터 상단 바, 탭 행, 페이지 영역을 세로로 쌓는다. 떠 있는 버튼과 스낵바는 페이지 영역 위에 겹쳐 표시하고 두 탭이 함께 사용한다. 이는 [TagDetail 화면 디자인](./tag-detail.md)의 화면 구조와 같은 기준이다.

```mermaid
flowchart TB
    top["상단 바<br/>뒤로가기 · 연락처 이름 · 즐겨찾기 · 삭제"]
    tabs["탭 행<br/>연락처 디테일 · 메모"]
    pager["페이지 영역<br/>선택한 탭의 내용"]
    fab["떠 있는 버튼<br/>선택한 탭에 따라 바뀜"]

    top --> tabs --> pager
    pager -.- fab
```

## 탭 행

상단 바 바로 아래에 탭 행을 둔다. 탭 행은 화면의 가로 폭을 모두 차지하고, 두 탭이 왼쪽부터 연락처 디테일, 메모 순서로 폭을 균등하게 나눠 가진다. 탭 순서는 페이지 순서와 같게 둔다.

각 탭은 아이콘만 표시하고 라벨 문구는 두지 않는다. 연락처 디테일 탭에는 [ContactHome 화면 디자인](./contact-home.md)이 연락처를 가리킬 때 쓰는 연락처 아이콘을, 메모 탭에는 [MemoHome 목록 디자인](./memo-home.md)의 메모 아이콘을 쓴다. 선택된 탭의 강조 표시는 Material 기본 탭 표현을 따른다.

탭 행은 연락처 조회 상태와 관계없이 항상 같은 모양으로 표시하고, 비활성 표현을 사용하지 않는다. 목록과 함께 표시하는 배치에서도 탭 행은 상세 영역 안 상단 바 바로 아래에 같은 모양으로 둔다.

## 페이지 전환

사용자는 탭 행에서 보고 싶은 탭을 선택하거나 페이지 영역 위에서 좌우로 스와이프해 두 탭을 오간다. 전환 표현, 선택된 탭 표시가 바뀌는 시점, 이미 보고 있는 탭을 다시 선택했을 때의 결과는 [TagDetail 화면 디자인](./tag-detail.md)의 `페이지 전환`과 같다.

두 탭의 내용은 모두 세로로만 스크롤하므로 입력 위나 목록 위에서 좌우로 스와이프해도 탭이 전환된다.

## 연락처 디테일 탭

연락처 디테일 탭의 본문에는 단일 줄 이름 입력, 설명 입력, 키 입력, 신발 사이즈 입력, 생일 입력, 고향 입력, 전화번호 입력을 위에서부터 이 순서로 둔다. 입력의 순서와 그 이유, 각 입력의 구성과 조작, 소프트 키보드 요청, 입력 사이 간격은 모두 [ContactAdd 화면 디자인](./contact-add.md)의 `화면 구조`, `이름 입력`, `키와 신발 사이즈 입력`, `생일 입력`, `달력 구분 전환`, `고향 입력`, `전화번호 입력`을 따른다. 두 화면이 같은 자리에 같은 입력을 두어 사용자가 연락처를 추가할 때와 고칠 때 같은 방식으로 조작한다.

본문 바깥에는 [공통 화면 가로 여백과 세로 여백](./dimens.md)을 둔다. 본문의 내용이 화면 높이를 넘으면 본문 안에서 세로로 스크롤한다. 상단 바와 탭 행은 함께 스크롤되지 않고 자리를 지킨다.

## 메모 탭

메모 탭 안의 정렬 줄, 목록, 빈 상태, 완료·삭제 제스처와 피드백, 새로고침, 단축키의 표현은 [항목 상세 메모 탭 공통 디자인](./entity-detail-memo.md)을 따른다. 이 목록의 빈 상태 문구는 [목록 빈 상태 디자인](./list-empty-state.md)의 문구 표가 `ContactDetail 메모 탭의 연락처별 메모 목록`으로 정한다.

메모 탭에서 이동한 MemoAdd 화면과 MemoDetail 화면은 [Contact 목록·상세 배치 디자인](./contact-list-detail.md)의 상세 영역에 두지 않고 창 너비와 관계없이 단독으로 표시한다.

## 진입 시 표시 내용

조회가 완료되면 이름, 설명, 키, 신발 사이즈, 고향 입력에 저장된 값을 채우고, 생일 행에는 저장된 생일을 저장된 달력 구분이 골라진 상태로, 전화번호 입력에는 저장된 전화번호를 저장된 순서대로 채운다. 상단 바의 즐겨찾기 버튼에는 저장된 즐겨찾기 여부를 표시한다.

저장된 키와 신발 사이즈가 없거나 저장된 고향이 비어 있으면 그 입력을 비운 채로, 저장된 생일이 없으면 생일 행을 고르지 않은 표시로 두고 구분 전환을 표시하지 않는다. 저장된 전화번호가 하나도 없으면 전화번호 카드는 이름 행만 남은 상태로 둔다.

저장된 값이 이미 채워져 있어도 입력을 읽기 전용으로 바꾸지 않으며, 값을 지우는 지우기 버튼과 생일을 지우는 버튼, 달력 구분 전환도 그대로 제공한다.

이름이 비어 있는 상태에 오류 색이나 필수 표시를 상시로 두지 않는다. 이름을 비운 채 수정하면 저장된 기존 이름이 쓰이므로 사용자가 고쳐야 하는 상태가 아니다.

## 떠 있는 버튼

떠 있는 버튼은 선택한 탭에 따라 하나만 표시한다.

| 선택한 탭 | 떠 있는 버튼 | 표시 조건 |
| --- | --- | --- |
| 연락처 디테일 탭 | 수정 버튼 | 입력 내용과 저장 내용이 다를 때만 |
| 메모 탭 | 메모 추가 버튼 | 항상 |

탭을 전환할 때는 [나타나고 사라지는 버튼 디자인](./button-visibility.md)의 전환으로 이전 탭의 버튼이 사라지고 새 탭의 버튼이 나타난다. 연락처 디테일 탭에서 수정 버튼을 표시하던 중 메모 탭으로 전환하면 수정 버튼이 사라지고 메모 추가 버튼이 나타나며, 돌아오면 수정 버튼이 다시 나타난다.

메모 추가 버튼의 아이콘과 접근성 이름은 [항목 상세 메모 탭 공통 디자인](./entity-detail-memo.md)의 `메모 추가`를 따른다.

## 수정 버튼

수정 버튼은 연락처 디테일 탭을 선택한 동안 페이지 영역의 끝 쪽 아래 모서리에 떠 있는 버튼으로 두고 체크 아이콘을 쓴다. 이는 [PlaceDetail 화면 디자인](./place-detail.md), [WebDetail 화면 디자인](./web-detail.md), [MemoDetail 화면 디자인](./memo-detail.md)의 수정 버튼과 같은 표현이다.

수정 버튼은 입력 내용이 저장 내용과 다를 때만 표시하며, 나타나고 사라지는 표현은 [나타나고 사라지는 버튼 디자인](./button-visibility.md)을 따른다. 번호가 비어 있는 전화번호 항목이 있어도 저장 내용과 다르므로 버튼을 표시하고, 전화번호가 필요하다는 안내는 수정을 실행한 시점에만 제공한다.

수정을 처리하는 동안에는 수정 버튼의 체크 아이콘을 진행 표시로 바꾼다. 처리 중에도 입력을 잠그거나 흐리게 바꾸지 않으며, 삭제 버튼과 서로를 비활성으로 만들지 않는다.

물리 키보드 환경에서는 수정 버튼이 표시된 동안 `Cmd` 또는 `Meta`와 `Enter`를 함께 눌러 수정 반영을 실행할 수 있다. 이는 [항목 추가 화면 공통 디자인](./entity-add.md)의 `초점과 키보드 단축키`가 정한 추가 실행 단축키와 같은 기준이다.

본문의 마지막 입력이 수정 버튼에 가리지 않게 배치한다.

## 상단 바 액션

즐겨찾기 버튼에는 지금 즐겨찾기이면 채워진 별 아이콘을, 즐겨찾기가 아니면 윤곽선 별 아이콘을 쓴다. 버튼의 크기와 표현은 삭제 버튼과 같다. 두 아이콘은 같은 자리에서 서로를 대체하므로 버튼의 자리와 크기는 상태에 따라 바뀌지 않는다.

즐겨찾기 버튼을 누르면 곧바로 즐겨찾기가 바뀌며, 확인 대화상자를 두지 않는다. 즐겨찾기 변경을 처리하는 동안 아이콘을 진행 표시로 바꾸고, 처리가 끝나면 바뀐 상태의 아이콘으로 되돌린다.

아이콘이 바뀔 때는 교차 전환을 쓴다. 채움과 윤곽선의 차이만으로 상태가 갈리므로, 바뀌는 순간을 사용자가 놓치지 않게 한다.

즐겨찾기가 바뀌었음을 스낵바로 알리지 않는다. 아이콘이 바로 바뀌는 것이 결과를 충분히 알리고, 기준 스펙의 `즐겨찾기`도 별도 안내를 두지 않는다.

즐겨찾기 변경에 실패하면 아이콘을 바꾸기 전 상태로 되돌리고 별도의 안내는 표시하지 않는다. 이는 삭제 실패와 같은 기준이다.

즐겨찾기 변경을 처리하는 동안에도 뒤로가기 버튼과 본문의 입력, 수정 버튼과 삭제 버튼은 그대로 누를 수 있고 어떤 요소도 비활성으로 표시하지 않는다.

즐겨찾기 버튼을 삭제 버튼보다 시작 쪽에 두는 것은 즐겨찾기가 되돌릴 수 있는 조작이고 삭제는 그렇지 않기 때문이다. 되돌릴 수 없는 조작을 상단 바의 가장 끝, 사용자가 마지막으로 닿는 자리에 둔다.

삭제 버튼에는 휴지통 아이콘을 쓰고, 삭제를 처리하는 동안 아이콘을 진행 표시로 바꾼다. 표현과 크기는 [PlaceDetail 화면 디자인](./place-detail.md)의 삭제 버튼과 같다.

삭제 전에 확인 대화상자를 두지 않으며, 이는 [PlaceDetail 화면 디자인](./place-detail.md)과 [WebDetail 화면 디자인](./web-detail.md)의 삭제와 같은 기준이다.

삭제를 처리하는 동안에도 뒤로가기 버튼과 본문의 입력, 수정 버튼과 즐겨찾기 버튼은 그대로 누를 수 있고 어떤 요소도 비활성으로 표시하지 않는다. 삭제에 실패하면 삭제 버튼의 진행 표시만 아이콘으로 되돌리고 별도의 안내는 표시하지 않는다.

삭제에 성공하면 단독으로 표시하고 있었으면 진입하기 전 화면으로 돌아가고, 목록과 함께 표시하고 있었으면 상세 영역이 [Contact 목록·상세 배치 디자인](./contact-list-detail.md)의 선택 전 표시로 되돌아간다.

## 상태 전환과 표시

```mermaid
stateDiagram-v2
    Loading: 조회 중 · 본문 전체 로딩 진행 표시
    Content: 내용 표시 · 입력과 상단 바 액션, 동작 버튼 표시

    [*] --> Loading: 화면 진입
    Loading --> Content: 조회 성공, 교차 전환
```

연락처를 조회하는 동안에는 연락처 디테일 탭 본문 가운데에 로딩 진행 표시를 두고 어떤 입력도 표시하지 않으며, 상단 바에도 연락처 이름과 즐겨찾기 버튼, 삭제 버튼을 표시하지 않는다. 수정 버튼도 표시하지 않는다. 이는 [PlaceDetail 화면 디자인](./place-detail.md)의 조회 중 표현과 같은 기준이다.

조회 중에도 탭 행과 메모 탭은 그대로 표시한다. 메모 탭을 선택한 동안에는 메모 추가 버튼도 그대로 표시한다.

조회에 성공하면 입력과 즐겨찾기 버튼, 삭제 버튼을 표시하고 로딩 진행 표시를 감춘다. 두 상태 사이에는 교차 전환을 쓴다. 이 전환은 연락처 디테일 탭 안에서만 일어나고 상단 바, 탭 행과 메모 탭의 표시는 바꾸지 않는다.

연락처를 조회할 수 없거나 조회에 실패하면 조회 중 표시를 그대로 유지하고, 실패 안내나 다시 시도 버튼을 두지 않는다.

대상 연락처가 다른 경로에서 삭제 상태가 되어도 내용 표시 상태를 그대로 두고, 삭제되었음을 알리는 표시나 비활성 표현을 두지 않는다.

## 진행과 피드백

수정 성공과 전화번호 미입력 피드백은 모두 스낵바로 표시한다. 스낵바는 두 탭이 함께 사용하므로 메모 탭에서 발생한 완료·삭제 피드백도 같은 자리에 표시한다. 즐겨찾기 변경은 스낵바를 표시하지 않으며, 그 이유는 `상단 바 액션`이 소유한다. 목록과 함께 표시할 때 스낵바를 두는 자리는 [목록·상세 배치 공통 디자인](./list-detail-pane.md)의 `진행과 피드백`을 따른다.

새 피드백을 표시할 때 이미 보이는 스낵바가 있으면 표시 시간이 지나기를 기다리지 않고 즉시 새 피드백으로 바꾼다. 이는 [ContactAdd 화면 디자인](./contact-add.md)이 따르는 [항목 추가 화면 공통 디자인](./entity-add.md)의 피드백과 같은 기준이다.

전화번호 미입력도 수정을 실행한 결과로 판단하므로 수정 처리와 같은 진행 표시를 거친 뒤 피드백을 표시한다. 어느 전화번호 항목의 번호가 비어 있는지는 문구에 담지 않고, 입력 초점도 옮기지 않는다.

이름을 비운 채 수정해 저장된 기존 이름이 유지되는 경우에는 별도의 안내를 표시하지 않고 수정 성공 피드백만 표시한다.

수정에 성공해도 입력 내용을 비우거나 되돌리지 않으며, 수정 버튼은 입력이 저장 내용과 같아졌으므로 사라진다. 상단 바 제목은 새로 저장된 이름으로 바뀐다.

## 표시 영역과 소프트 키보드

본문, 수정 버튼과 스낵바는 상태 표시 영역, 시스템 탐색 영역과 카메라 컷아웃 등 기기가 가리는 영역을 침범하지 않게 배치한다.

소프트 키보드가 나타나면 본문을 키보드 위 영역에 맞춰 배치한다. 상단 바와 탭 행은 함께 스크롤되지 않고 자리를 지킨다. 초점을 옮길 때의 스크롤과 키보드 표현은 [항목 추가 화면 공통 디자인](./entity-add.md)의 `초점과 키보드 단축키`를 따른다. 진입할 때는 어느 입력에도 초점을 두지 않으므로 소프트 키보드도 열지 않는다.

## 적응형 배치

탭 행과 페이지 영역의 구성, 그리고 본문의 배치는 창 너비, 창 높이와 기기 자세에 따라 달라지지 않으며, 상세 영역과 자리를 나눠 좁아져도 입력의 순서와 구성은 그대로 둔다. 이는 [ContactAdd 화면 디자인](./contact-add.md)의 `표시 영역과 소프트 키보드`와 같은 기준이다.

목록과 자리를 나눠 쓰는 배치와 그 자리에서의 버튼 노출은 [Contact 목록·상세 배치 디자인](./contact-list-detail.md)이 정한다.

## 키보드 단축키

물리 키보드 환경에서는 선택한 탭에 따라 다음 단축키를 제공한다.

| 선택한 탭 | 단축키 | 동작 |
| --- | --- | --- |
| 연락처 디테일 탭 | `Command + Enter` | 수정 반영 |
| 메모 탭 | `Command + A` | 메모 추가 |

수정 단축키는 수정 버튼이 표시된 동안에만 처리한다. 한 번에 한 탭만 선택되므로 두 단축키가 겹쳐 처리되지 않는다.

## 문구와 접근성

탭은 아이콘만 표시하므로 각 탭 아이콘에 접근성 이름을 둔다. 선택된 탭은 선택 상태로 읽히게 한다.

한국어 환경과 그 외 기본 환경에서 다음 문구를 사용한다.

| 항목 | 한국어 | 그 외 기본 |
| --- | --- | --- |
| 상단 바 제목 | 저장된 연락처 이름 | 저장된 연락처 이름 |
| 연락처 디테일 탭 접근성 이름 | `연락처 디테일` | `Contact detail` |
| 메모 탭 접근성 이름 | `메모` | `Memo` |
| 뒤로가기 버튼 접근성 이름 | `뒤로가기` | `Navigate up` |
| 즐겨찾기 추가 버튼 접근성 이름 | `즐겨찾기에 추가` | `Add to favorites` |
| 즐겨찾기 해제 버튼 접근성 이름 | `즐겨찾기에서 제거` | `Remove from favorites` |
| 삭제 버튼 접근성 이름 | `연락처 삭제` | `Delete contact` |
| 수정 버튼 접근성 이름 | `연락처 수정` | `Update contact` |
| 수정 성공 안내 | `연락처가 수정되었습니다.` | `Contact updated.` |

이름 입력, 키 입력, 신발 사이즈 입력, 생일 영역과 생일 지우기 버튼, 달력 구분 전환과 두 칸의 라벨, 고향 입력, 전화번호 영역과 번호 입력, 전화번호 추가·삭제 버튼의 이름과 접근성 이름, 전화번호 미입력 안내 문구는 [ContactAdd 화면 디자인](./contact-add.md)의 문구를 그대로 쓴다. 같은 입력과 같은 판단 기준을 두 화면에서 다른 문구로 안내하지 않는다.

설명 입력의 이름과 표현은 그 입력 컴포넌트의 디자인을 따른다.

상단 바 제목은 저장된 이름을 그대로 읽히게 두고 별도의 접근성 이름을 두지 않는다.
