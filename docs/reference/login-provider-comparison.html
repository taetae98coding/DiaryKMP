Google 로그인과 Apple 로그인 비교

기준 커밋 d17675ee 위의 appleLogin 작업 트리(Android·JVM·wasmJs Apple 로그인 추가 직후) · 최종 확인 2026-09-24

제품 관점의 행위와 정책은 Login 스펙이, 화면 표현은 Login 디자인이 소유한다. 이 자료는 두 로그인 수단의 구현 구조만 대조한다. 스펙과 어긋나면 이 자료를 고친다.

모듈과 파일

버전은 gradle/libs.versions.toml이 소유한다. 여기서는 어떤 artifact가 어느 수단·플랫폼에 들어오는지만 적는다.

차이의 요지. Google은 플랫폼마다 Google이 제공하는 SDK나 스크립트에 기댄다. Apple은 iOS 밖에서 제공하는 SDK가 웹용 JS 하나뿐이고 그것도 등록된 https 도메인에서만 동작하므로, 이 저장소는 SDK 대신 표준 OAuth 인가 URL과 플랫폼 기본 API만으로 흐름을 구성했다. 결과적으로 Apple 쪽 외부 의존성은 androidx.browser 하나다.

왜 Apple만 서버 콜백을 거치는가

Apple의 웹 Sign in with Apple은 Return URL을 https 도메인으로만 등록할 수 있고 localhost·IP·커스텀 scheme을 받지 않는다. 또 id_token을 직접 받으려면 response_type=code id_token이어야 하고, 이때 Apple은 response_mode=form_post만 허용한다. 그래서 https 주소를 가진 서버 함수가 POST를 받아 앱 복귀 주소로 넘기는 한 단계가 필요하다. Google은 루프백과 postmessage를 허용하므로 이 단계가 없다.

중계 함수는 id_token을 검증하거나 저장하지 않는다. 검증은 두 수단이 공유하는 issueSessionFromIdToken이 Supabase signInWithIdToken으로 한다. 복귀 주소 허용 목록이 엄격한 이유는, 임의 주소로 넘기면 공격자가 자기 nonce로 만든 시도의 id_token을 받아 세션을 얻을 수 있기 때문이다.
