왜 정렬 속성이 3개인가

justifyContent · alignItems · alignContent — 가로/세로로 나눈 게 아니라 축(main/cross)과 대상(아이템/줄)의 조합입니다.

기준 Compose Multiplatform 1.12.0 · 최종 확인 2026-08-27 · 기준과 최종 확인을 적는 이유는 docs/reference/README.md가 소유합니다.

핵심: 2 × 2에서 실제로 필요한 3칸

FlexBox는 아이템을 main axis 방향으로 흘리고, 공간이 부족하면 cross axis 방향으로 줄을 쌓습니다. direction(Row)이면 main = 가로, cross = 세로이고, direction(Column)이면 둘이 서로 바뀝니다. 그래서 "가로 정렬 / 세로 정렬"이라고 이름 붙일 수 없습니다.

아이템을 줄 안에서줄 묶음을 컨테이너 안에서
main axis justifyContent 필요 없음 — 줄은 main 방향으로 꽉 차 있음
cross axis alignItems (개별 override: alignSelf) alignContent
justifyContent

한 줄 안에서 아이템을 main 방향으로 배치

줄에 남는 main 여유 공간을 어떻게 쓸지 결정. 여유가 없으면(줄이 꽉 찼으면) 효과 없음.

alignItems

아이템을 자기 줄 안에서 cross 방향으로 배치

같은 줄 아이템들의 cross 크기가 다를 때만 눈에 보임. 모두 같은 높이면 변화 없음.

alignContent

줄 전체를 컨테이너 안에서 cross 방향으로 배치

줄이 2개 이상이고 컨테이너에 cross 여유 공간이 있을 때만 효과. 둘 중 하나라도 없으면 무효.

각 속성이 "먹는" 조건

    
3개가 따로 있는 이유는 각각 효과를 내는 조건이 다르기 때문입니다. 그래서 하나로 합칠 수 없습니다.

    

      

        
속성움직이는 대상효과가 나타나는 조건무효인 경우

        
          

            justifyContent
            줄 안의 아이템들 (main)
            줄에 main 여유 공간이 있을 때
            아이템이 줄을 꽉 채웠거나 grow로 다 늘어났을 때
          

          

            alignItems
            아이템 하나하나 (cross)
            같은 줄 아이템의 cross 크기가 서로 다를 때
            모든 아이템 높이가 같을 때 (칩 목록이 대표적)
          

          

            alignContent
            줄 묶음 전체 (cross)
            줄이 2개 이상 그리고 컨테이너에 cross 여유 공간이 있을 때
            줄이 1개이거나, cross 크기가 콘텐츠에 맞춰질 때
          

        
      

    


    

      
FlowRow에서 넘어올 때 헷갈리는 지점

      

        FlowRow는 Arrangement 하나에 간격과 정렬을 같이 담았고, cross 축은
        verticalArrangement(= 줄 묶음)와 itemVerticalAlignment(= 아이템)로 이미 둘로 나뉘어 있었습니다.
        FlexBox는 그걸 이름으로 드러낸 것뿐이고, 개수가 늘어난 게 아닙니다.
      

      

        

          
FlowRowFlexBox

          
            
horizontalArrangement = spacedBy(8.dp, CenterHorizontally)gap(8.dp) + justifyContent(Center)

            
verticalArrangement = spacedBy(8.dp, CenterVertically)gap(8.dp) + alignContent(Center)

            
itemVerticalAlignment = Alignment.CenterVerticallyalignItems(Center)

          
        

      

    


    

      
1.12.0 실측 버그

      

        cross 축에 min 제약이 없는 상태(Modifier.fillMaxWidth()만 걸렸거나
        verticalScroll 안에 있는 경우)에서 alignContent(Center)를 주면
        첫 줄이 줄 간격 합의 절반만큼 위로 밀려 잘립니다. 밀리는 양은
        (줄 수 - 1) × gap ÷ 2이고, gap 8dp / 2줄 기준으로 첫 줄 top이 -4dp로 측정됐습니다.
      

      

        내부 계산이 totalCrossAxisSpace = max(totalLinesCrossSize, crossAxisMin)인데
        freeSpace = totalCrossAxisSpace - totalLinesCrossSize - totalGap으로 gap을 한 번 더 빼기 때문입니다.
        crossAxisMin이 0이면 freeSpace가 -totalGap이 되고
        Center는 그 절반을 첫 줄의 시작 위치로 씁니다. 위 체크박스에서
        "cross 크기를 콘텐츠에 맞춤"을 켜고 alignContent를 Center로 바꾸면 같은 조건이 재현됩니다.
        (이 HTML은 CSS flexbox로 그리므로 실제 음수 오프셋까지 재현하지는 않고, 경고만 표시합니다.)
      

      

        1.12.0-beta03에서 실측한 동작이고, 1.12.0 소스의 FlexBox.kt가
        1.12.0-rc01과 동일해 계산이 그대로여서 2026-08-27에 기준 버전을 올렸습니다. 그래서 이 저장소의 DiaryFlexBox는
        alignContent(Start)로 고정합니다. 스크롤 영역 안에서는 밀린 만큼이 스크롤 위치 0보다 위에 남아 닿을 수 없습니다.
