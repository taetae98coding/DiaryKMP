# 항목 상세 화면 공통 스펙

이 문서는 저장된 항목 하나를 확인하고 수정하는 상세 화면들이 공통으로 보장하는 조회 상태, 내용 수정과 삭제의 결과, 외부 변경의 반영, 연결 입력의 반영, 여러 개 입력하는 값, 요청 제한, 수정 동작의 제공 기준과 저장·동기화 계약을 다룬다. 어떤 입력을 제공하는지, 무엇이 수정 대상인지, 조회 중에 무엇을 실행할 수 없는지, 그 화면에만 있는 동작이 무엇인지는 화면마다 다르므로 각 화면 스펙에서 다룬다.

이 문서를 따르는 화면 스펙은 문서 끝의 `이 문서를 참조하는 문서`에 둔다.

디자인: [항목 상세 화면 공통 디자인](../../design/entity-detail.md)

이 문서에서 `상세 대상`은 그 화면이 다루는 항목 하나를 가리킨다. `제목`은 상세 대상이 반드시 가져야 하는 이름 값을 가리키며, ContactDetail에서는 연락처의 이름이다.

이 문서에서 `연결 입력`은 상세 대상과 다른 항목의 연결을 확인하고 바꾸는 입력을 가리킨다. 태그 입력이 여기에 해당하며, MemoDetail의 웹 입력, 연락처 입력과 장소 카드도 해당한다. 연결 입력 가운데 태그 입력에만 있는 규칙은 `태그 입력`, `태그 입력에 표시하는 태그`, `태그 연결의 반영`, `태그 입력의 조회`, `태그 연결의 저장`, `태그 연결 결과의 표시`에 둔다.

태그를 고르는 입력의 행동과 판정 기준은 [태그 선택 입력 공통 스펙](./tag-select-input.md)을, 연결의 규칙과 저장·동기화 계약은 [항목 연결 공통 스펙](../common/entity-link.md)을 따른다.

연결 입력을 제공할지는 화면마다 다르다. 연결 입력을 제공하지 않는 화면에는 이 문서의 연결 입력과 태그 입력 관련 규칙을 적용하지 않으며, 어느 화면이 어떤 연결 입력을 제공하는지는 각 화면 스펙에서 밝힌다.

## feature

### 진입할 때의 입력 초점

사용자가 먼저 저장된 내용을 확인하는 화면이므로 진입할 때 어느 입력에도 입력 초점을 두지 않는다.

### 조회 상태

처음에는 상세 대상 조회 중 상태를 제공한다. 조회 중에 실행할 수 없는 동작은 각 화면 스펙이 정한다.

조회에 성공하면 내용 표시 상태로 바뀐다. 상세 대상을 조회할 수 없거나 조회에 실패하면 조회 중 상태를 유지하며, 별도의 오류 안내나 다시 시도 동작은 제공하지 않는다.

화면에 상세 대상과 따로 조회하는 탭이 있으면 조회 상태는 그 탭에 적용하지 않는다. 어느 탭이 조회 상태와 무관한지는 각 화면 스펙이 정한다.

### 내용 수정

사용자는 변경한 내용을 반영할 수 있다. 처리 중에는 진행 상태를 표시한다.

수정에 성공하면 화면과 입력 내용을 유지하고 성공 피드백을 제공한다. 화면 제목은 새로 저장된 제목으로 갱신된다.

수정 성립 조건을 만족했는데도 저장에 실패하면 화면과 입력 내용을 유지하고 진행 상태만 해제한다. 저장 실패를 알리는 별도 안내는 제공하지 않으며, 사용자는 수정을 다시 실행할 수 있다. 수정 성립 조건을 만족하지 않은 경우의 안내는 각 화면 스펙이 정한다.

수정 시점에 제목이 비어 있거나 공백만 있을 때의 결과는 `domain > 수정되는 내용`을 따른다.

### 삭제

사용자는 상세 대상을 삭제할 수 있다. 삭제를 실행하기 전에 확인을 되묻지 않는다.

삭제를 처리하는 동안에는 진행 상태를 표시한다. 처리하는 동안에도 다른 종류의 동작은 `domain > 요청 제한`에 따라 그대로 실행할 수 있다.

삭제에 성공하면 뒤로가기와 같은 결과로 상세 화면에서 빠져나가 진입하기 전 화면으로 돌아가고, 삭제한 항목은 그 화면의 목록에서 사라진다. 목록과 상세 영역을 함께 표시하는 상태에서는 상세 영역이 선택한 항목이 없을 때의 상태로 되돌아가며, 그 상태는 각 목록·상세 배치 스펙의 `상세 영역의 구성`을 따른다.

이 화면에서 삭제한 항목에는 목록 화면의 삭제 안내와 실행 취소를 제공하지 않으며, 상세 화면도 삭제를 되돌리는 동작을 제공하지 않는다. 삭제한 항목에서 수정 중이던 내용은 유지하지 않는다.

삭제에 실패하면 화면에 머무르며 입력 내용을 유지하고 진행 상태만 해제한다. 별도의 오류 안내는 제공하지 않으며, 사용자는 삭제를 다시 실행할 수 있다.

### 외부 변경

화면이 열려 있는 동안 같은 상세 대상의 저장 내용이 다른 경로에서 바뀌면 화면 제목을 최신 저장 제목으로 갱신한다. 입력 중인 내용은 덮어쓰지 않는다.

같은 상세 대상의 연결이 다른 경로에서 바뀌면 연결 입력에 최신 연결을 반영한다.

다른 기기에서 삭제한 항목이 서버에서 내려받아져 상세 대상이 삭제 상태가 되어도 화면은 내용 표시 상태를 유지한다. 사용자는 입력 중이던 내용을 잃지 않고 화면의 동작을 그대로 실행할 수 있으며, 화면에서 밀려나거나 조회 중 상태로 되돌아가지 않는다. 기준은 `domain > 상세 대상`을 따른다.

입력 중인 내용 밖에 저장된 값을 그대로 보여 주는 표시가 있으면 그 표시는 최신 저장 값으로 바뀐다. 어떤 표시가 그런지는 각 화면 스펙이 정한다.

### 연결 입력

사용자가 연결 입력에서 반영한 연결과 해제는 상세 대상의 저장된 연결로 즉시 반영된다. 다른 입력의 수정 반영과 달리 별도의 반영 동작이 필요하지 않으며, 수정 반영 동작을 제공할지 판정할 때도 연결은 포함하지 않는다.

연결과 해제를 반영하는 동안에도 사용자는 화면의 다른 동작을 그대로 실행할 수 있다.

연결과 해제에 성공해도 별도로 안내하지 않는다. 반영된 결과가 연결 입력에 나타나는 것으로 충분하다.

연결이나 해제의 저장에 실패하면 별도 안내나 다시 시도 동작 없이 연결 입력이 저장된 연결을 그대로 보여 준다. 사용자는 같은 항목을 다시 연결하거나 해제할 수 있다.

연결 입력에서 항목을 골라 연결하는 행동과 연결된 항목을 눌러 그 항목의 상세로 이동하는 흐름은 각 연결 입력의 컴포넌트 스펙이 정한다.

### 태그 입력

태그 입력의 반영 시점과 다른 동작과의 관계는 `연결 입력`을 따른다.

연결한 태그를 누르면 그 태그의 TagDetail 화면으로 이동하고, 뒤로가면 이 항목의 상세로 돌아온다.

### 진행 상태 유지

연결은 이미 저장된 값이므로 화면이 재생성되거나 앱을 다시 실행해도 연결 입력은 저장된 연결을 그대로 다시 표시한다. 태그 선택 목록이 열려 있었으면 열림 상태와 검색어를 [태그 선택 입력 공통 스펙](./tag-select-input.md)의 기준에 따라 유지한다.

수정이나 삭제를 처리하는 동안, 그리고 저장된 내용이 갱신되어 화면이 다시 그려질 때도 사용자가 보고 있던 화면 위치를 유지한다.

화면을 떠난 뒤 다시 들어오거나 앱을 종료한 뒤 새로 진입하면 수정 중이던 내용을 복원하지 않고 저장된 내용으로 다시 시작한다. 화면 재생성과 시스템이 앱을 정리한 뒤 복원할 때 무엇을 유지하는지는 각 화면 스펙이 정한다.

사용자가 이 화면에서 삭제를 실행했을 때는 `삭제`에 따라 화면을 떠나므로 이 규칙이 적용되지 않는다.

## domain

### 상세 대상

상세 대상을 정하는 계정 기준은 `data > 대상 조회`를 따른다.

삭제 여부는 상세 대상을 정하는 기준이 아니다. 삭제 상태인 항목도 상세 대상으로 조회하며, 상세 대상이 삭제 상태로 바뀌어도 화면은 내용 표시 상태를 유지한다. 사용자가 수정 중인 내용을 배경에서 진행되는 동기화가 치우지 않게 하기 위한 것이며, 이때의 화면 동작은 `feature > 외부 변경`을 따른다.

사용자가 이 화면에서 삭제를 실행했을 때는 `feature > 삭제`에 따라 화면을 떠나므로 이 규칙이 적용되지 않는다.

수정과 화면에서 실행하는 그 밖의 동작은 삭제 여부를 바꾸지 않으므로, 삭제 상태가 된 항목을 이 화면에서 수정해도 그 항목은 삭제 상태로 남는다.

### 입력 내용 채우기

입력 내용은 상세 대상을 처음 조회한 값으로 한 번만 채운다. 같은 상세 대상의 저장 내용이 바뀌어도 다시 채우지 않는다. 상세 대상이 다른 항목으로 바뀌면 새 대상의 값으로 채운다.

어떤 입력을 어떤 값으로 채우는지는 각 화면 스펙이 정한다.

### 연결 입력에 표시하는 항목

연결 입력이 표시 대상으로 삼는 항목은 상세 대상과 해제되지 않은 연결을 가진 항목 중 현재 사용자 계정과 연결되고 삭제되지 않은 항목이다. 삭제된 항목은 연결이 남아 있어도 표시하지 않는다. 이 기준은 연결 입력의 표시에만 적용되며 저장된 연결을 바꾸지 않는다.

완료 상태가 없는 항목은 이 기준이 새로 연결할 수 있는 항목의 기준과 같으므로, 표시하지만 새로 연결할 수 없는 항목은 생기지 않는다. 완료된 항목을 어떻게 다루는지는 태그의 경우 `태그 입력에 표시하는 태그`가 정한다.

새로 연결할 수 있는 항목은 각 연결 입력의 컴포넌트 스펙이 정한다.

### 태그 입력에 표시하는 태그

태그 입력이 표시 대상으로 삼는 태그는 `연결 입력에 표시하는 항목`에 더해 완료된 태그도 포함한다. 어떤 태그가 조회되는지는 [항목 연결 공통 스펙](../common/entity-link.md)의 `연결된 항목의 조회`를 따르므로 완료된 태그도 표시하고 삭제된 태그는 표시하지 않는다.

새로 연결할 수 있는 태그는 [태그 선택 입력 공통 스펙](./tag-select-input.md)의 `선택할 수 있는 태그`를 따른다.

### 연결의 반영

연결을 실행하면 상세 대상과 고른 항목의 연결을 만들고, 해제를 실행하면 그 연결을 해제한다. 만들고 해제할 때 기록되는 내용은 [항목 연결 공통 스펙](../common/entity-link.md)의 `연결의 상태와 시각`을 따른다.

연결과 해제는 상세 대상의 저장 내용과 상태, 수정 시각을 바꾸지 않는다. 연결의 다른 쪽 항목의 내용과 수정 시각도 바꾸지 않는다. 수정 중이던 입력 내용도 바꾸지 않는다. 다만 메모의 대표 태그가 함께 바뀌는 경우는 `태그 연결의 반영`을 따른다.

상세 대상이 완료되었거나 삭제된 상태여도 사용자는 연결을 확인하고 바꿀 수 있다. 연결과 해제는 완료 여부와 삭제 여부를 되돌리지 않는다.

### 태그 연결의 반영

태그의 연결과 해제는 `연결의 반영`을 따른다.

메모의 대표 태그로 지정된 태그의 연결을 해제해 대표 태그 지정도 함께 해제되는 경우와, 연결되지 않은 태그를 대표 태그로 지정해 연결도 함께 만들어지는 경우는 [메모 태그 앱 스펙](./memo-tag.md)의 `대표 태그와의 관계`와 [메모 대표 태그 스펙](../common/memo-primary-tag.md)을 따른다. 이때는 대표 태그가 바뀌므로 메모의 수정 시각이 갱신된다.

### 수정되는 내용

수정 시점에 제목이 비어 있거나 공백만 있으면 저장된 기존 제목을 유지한 채 나머지 수정 대상만 반영한다. 제목은 상세 대상이 반드시 가져야 하는 정보이므로 비우는 수정을 허용하지 않고, 제목을 비운 것은 기존 제목을 사용하는 것이므로 수정을 막지 않는다. 제목 입력은 비운 그대로 남아 저장된 제목과 계속 다르므로 수정 동작도 계속 제공된다.

삭제 여부, 생성 시각과 계정 연결은 내용 수정으로 바뀌지 않는다. 연결 입력이 다루는 연결도 내용 수정으로 바뀌지 않는다.

어떤 값이 수정 대상인지, 제목 말고도 비우는 수정을 허용하지 않는 값이 있는지는 각 화면 스펙에서 정한다.

### 수정 동작의 제공 기준

입력한 값이 저장된 내용과 하나라도 다르면 수정 동작을 제공한다. 어떤 값을 비교하는지는 각 화면 스펙에서 정한다.

연결은 수정 동작의 제공 기준에 넣지 않는다. 연결하거나 해제하는 것만으로는 수정 동작이 나타나지 않고, 이미 나타난 수정 동작도 사라지지 않는다.

### 여러 개 입력하는 값

상세 대상이 순서 있는 여러 개의 하위 값을 가지면 사용자는 그 값을 항목 하나씩 추가하고 삭제하고 입력한다. 항목을 다루는 행동, 필수 값이 빈 항목이 있을 때 아무것도 반영하지 않고 알리는 결과와 입력 초점은 [항목 추가 화면 공통 스펙](./entity-add.md)의 `여러 개 입력하는 값`을, 순서를 지키고 같은 값을 합치지 않으며 필수 값이 없는 항목을 조용히 빼지 않는 기준은 같은 문서의 `여러 개 입력하는 값의 기록`을 따른다. 그 문서의 추가는 이 화면의 수정으로 읽는다. 아래는 수정 화면에만 있는 기준이다.

화면에 처음 들어오면 저장된 하위 값이 저장된 순서대로 모두 항목에 채워진다. 같은 값이 여러 개 있어도 하나로 합치지 않고 각각의 항목으로 채운다. 저장된 하위 값이 하나도 없으면 항목이 하나도 없는 상태로 시작한다.

수정 동작의 제공 기준에서는 항목의 값, 순서와 개수를 함께 비교한다. 값이 같아도 순서가 다르면 다른 것으로 보고, 필수 값이 비어 있는 항목이 추가되어 있어도 저장된 내용과 다른 것으로 본다.

수정은 사용자가 배치한 순서대로 모든 항목을 반영하며, 항목이 하나도 없으면 빈 목록으로 반영한다. 저장할 때는 저장된 목록을 반영한 목록으로 바꾸므로, 항목을 모두 지운 수정을 반영하면 하위 값은 하나도 남지 않는다.

화면이 재생성되어도 항목의 값과 순서를 유지한다. 그 밖의 유지 기준은 `feature > 진행 상태 유지`를 따른다.

어떤 값이 여러 개 입력하는 값인지, 항목 하나가 무엇으로 이루어지며 어느 값이 필수인지, 필수 값이 빈 항목이 있을 때 무엇을 알리는지는 각 화면 스펙이 정한다.

### 삭제

삭제는 상세 대상의 삭제 여부를 삭제로 바꾸고 수정 시각을 삭제 시점으로 갱신한다. 상세 대상의 내용과 다른 상태는 바꾸지 않는다.

삭제한 항목은 각 목록 화면의 노출 기준에 따라 목록에서 사라진다.

### 요청 제한

화면이 제공하는 동작은 종류별로 요청을 제한한다. 한 종류를 처리하는 동안 같은 종류의 요청은 처리하지 않지만 다른 종류의 요청은 제한하지 않는다. 어떤 동작을 같은 종류로 보는지는 각 화면 스펙에서 정한다.

연결과 해제는 이 제한에 포함하지 않는다. 사용자는 다른 동작이 처리 중이어도 연결과 해제를 실행할 수 있고, 서로 다른 항목의 연결과 해제를 이어서 실행할 수 있다. 같은 항목에 대한 같은 요청이 처리 중이면 그 요청은 다시 처리하지 않는다.

앱의 데이터를 바꾸지 않는 동작은 제한 대상이 아니다.

## data

### 대상 조회

상세 대상은 현재 사용자 계정과 연결된 항목 하나다. 계정 조회 규칙은 [계정 조회 스펙](./account.md)을 따르며, 현재 계정을 확인할 수 없으면 상세 대상을 조회할 수 없는 것으로 다룬다. 이 조회는 삭제 여부를 가리지 않으므로 삭제 상태인 항목도 조회된다.

저장된 내용이 바뀌면 사용자가 아무것도 하지 않아도 조회 결과가 갱신되어 화면 제목에 반영된다. 다른 화면에서 고친 내용과 다른 기기에서 고쳐 내려받은 내용도 같다. 상세 화면에 들어오는 것만으로는 서버에서 다시 가져오지 않으며, 서버와 맞추는 계기는 [데이터 동기화 스펙](../common/data-sync.md)을 따른다.

### 연결 입력의 조회

연결 입력에 표시하는 항목은 기기에 저장된 자료에서 상세 대상과 연결된 항목을 조회해 표시한다. 이 조회는 새로 연결할 수 있는 항목의 조회와 분리되어 있다. 정렬은 연결 종류마다 각 연결 스펙이 정한다.

저장된 연결이나 연결된 항목의 내용·상태가 바뀌면 조회 결과가 갱신되어 연결 입력에 반영된다. 다른 화면이나 다른 기기에서 바뀐 연결도 기기에 반영되면 사용자가 아무것도 하지 않아도 연결 입력에 나타난다.

연결된 항목을 조회하지 못하면 연결 입력은 연결된 항목이 없는 것처럼 보이며, 별도의 오류 안내는 제공하지 않는다.

### 태그 입력의 조회

표시 대상 태그의 조회는 `연결 입력의 조회`를 따른다. 조회 기준과 정렬은 [항목 태그 연결 앱 스펙](./entity-tag.md)의 `연결된 태그의 조회`를 따르며, 이 조회는 페이지로 나누지 않는다.

태그 선택 목록은 현재 사용자 계정의 미완료·미삭제 태그와, 상세 대상이 이미 연결한 완료된 태그를 함께 사용자가 목록을 내리는 만큼 나누어 불러온다. 정렬과 페이지 조회 흐름은 [태그 선택 입력 공통 스펙](./tag-select-input.md)의 `태그 목록 조회`를 따른다.

### 연결의 저장

사용자가 연결하거나 해제하면 그 결과를 즉시 저장한다. 저장 방식과 해제된 연결이 기기에 남는 규칙은 [항목 연결 앱 스펙](./entity-link.md)의 `연결의 저장`과 [항목 연결 공통 스펙](../common/entity-link.md)의 `연결의 상태와 시각`을 따른다.

연결과 해제를 저장하면 그 연결이 업로드 대기로 기록되고 백그라운드 동기화가 시작된다. 동기화 규칙은 [항목 연결 공통 스펙](../common/entity-link.md)의 `동기화`를 따른다. 화면에는 동기화 진행 상태나 대기 여부를 표시하지 않으며, 동기화가 진행 중이거나 실패해도 사용자가 바꾼 연결은 되돌아가지 않는다.

연결과 해제의 저장은 상세 대상의 저장 내용과 수정 시각을 바꾸지 않으므로, 상세 대상 자체를 업로드 대기로 만들지 않는다. 메모의 대표 태그가 함께 바뀌는 경우는 `태그 연결의 저장`을 따른다.

### 태그 연결의 저장

태그의 연결과 해제의 저장은 `연결의 저장`을 따른다.

메모의 대표 태그가 함께 바뀌는 경우에는 [메모 태그 앱 스펙](./memo-tag.md)의 `대표 태그를 함께 바꾸는 저장`과 [메모 대표 태그 스펙](../common/memo-primary-tag.md)의 `동기화`에 따라 메모도 업로드 대기가 된다.

### 연결 결과의 표시

연결을 만들면 연결한 항목 쪽에서 상세 대상을 보여 주는 목록에 상세 대상이 노출 기준에 맞게 나타나고, 연결을 해제하면 그 목록에서 사라진다. 어느 목록에 나타나는지는 각 화면 스펙에서 정한다.

연결은 상세 대상이 자기 목록과 검색 결과에 나타나는 기준을 바꾸지 않는다.

### 태그 연결 결과의 표시

태그 연결의 결과는 `연결 결과의 표시`를 따른다. 태그 연결이 자기 목록과 검색 결과의 기준을 바꾸지 않는 것은 [항목 태그 연결 공통 스펙](../common/entity-tag.md)의 `연결의 의미`를 따른다.

### 수정과 삭제의 저장

수정을 반영하면 상세 대상의 수정 대상 값과 수정 시각을 기기에 저장해 기존 값을 바꾼다. 삭제를 실행하면 상세 대상의 삭제 여부와 수정 시각을 기기에 저장하며, 항목 자체와 계정 연결, 다른 항목과의 연결은 기기에서 지우지 않는다.

수정과 삭제는 현재 사용자 계정과 연결된 상세 대상에만 반영한다. 그런 항목이 기기에 없으면 아무것도 바꾸지 않는다.

### 저장 실패

저장에 실패한 동작은 성공한 것으로 다루지 않는다. 기기에 저장된 상세 대상의 내용과 연결은 바뀌지 않고, 성공 피드백도 제공하지 않는다. 삭제에 실패하면 상세 대상은 삭제되지 않은 채로 남는다.

### 수정과 삭제의 동기화

수정과 삭제를 기기에 반영하면 상세 대상은 업로드 대기로 기록되고, 사용자가 기다리지 않아도 되도록 백그라운드 동기화가 곧바로 시작된다. 삭제한 항목도 서버에서 제거하지 않고 삭제 상태로 반영한다.

수정과 삭제의 성공 여부는 기기에 저장한 결과로만 판단하며 서버 반영 결과를 기다리지 않는다. 동기화에 실패해도 기기에 반영된 수정과 삭제는 되돌아가지 않고 다음 동기화 계기에서 다시 시도된다. 업로드 단위, 충돌 기준과 실패 시 재시도는 [데이터 동기화 스펙](../common/data-sync.md)의 규칙을 따른다.

같은 항목을 여러 기기에서 다르게 바꾼 경우 어느 내용을 최신으로 볼지는 [데이터 동기화 스펙](../common/data-sync.md)의 `충돌 기준`을 따른다. 내려받기로 서버의 더 늦은 수정 내용이 반영되면 그 결과는 각 화면 스펙의 `결과의 표시`와 같은 기준으로 나타나며, 화면에서 입력 중인 내용은 `feature > 외부 변경`에 따라 덮어쓰지 않는다.

로그인하지 않은 상태에서 수정하거나 삭제한 항목은 서버에 반영되지 않고 기기 안에만 유지된다.

화면에서 실행하는 그 밖의 동작 가운데 상세 대상을 바꾸는 동작이 같은 방식으로 동기화되는지는 각 화면 스펙이 정한다.
