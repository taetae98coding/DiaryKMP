# DDayHome 화면 스펙

이 문서는 `더보기`의 `디데이` 바로가기로 진입하는 DDayHome 화면의 내용과 행동을 다룬다. 항목 목록 화면이 공통으로 따르는 노출 기준, 목록 갱신과 조회, 추가·상세로 이동, 목록에서의 삭제와 실행 취소, 화면 유지는 [항목 목록 화면 공통 스펙](./entity-home.md)을 따르며, 이 문서에는 디데이 목록에만 있는 내용을 둔다. 바로가기 항목의 표시와 선택은 [MoreHome 화면 스펙](./more-home.md)에서, 디데이가 갖는 정보는 [디데이 스펙](../common/dday.md)에서, 카드 문구와 목록 순서를 정하는 계산은 [디데이 앱 스펙](./dday.md)에서, 디데이를 작성해 추가하는 흐름은 [DDayAdd 화면 스펙](./dday-add.md)에서, 저장한 디데이를 확인하고 수정하고 삭제하는 흐름은 [DDayDetail 화면 스펙](./dday-detail.md)에서, 디데이 목록과 상세를 함께 사용하는 배치는 [DDay 목록·상세 배치 스펙](./dday-list-detail.md)에서, 목록 카드에서 삭제를 실행하는 상호작용의 공통 규칙은 [SwipeToFinishAndDelete 컴포넌트 스펙](./swipe-to-finish-and-delete.md)에서, 목록이 비어 있을 때의 안내는 [목록 빈 상태 스펙](./list-empty-state.md)에서, 필터를 열고 바꾸는 행동의 공통 결과는 [목록 필터 반영 스펙](./list-filter.md)에서, 태그 필터의 선택 방식과 판정 규칙은 [태그 필터 스펙](./tag-filter.md)에서, 목록을 당겨 새로고침하는 행동과 동기화 진행 표시는 [새로고침 스펙](./sync-refresh.md)에서, 디데이를 서버와 맞추는 규칙은 [데이터 동기화 스펙](../common/data-sync.md)에서 다룬다.

디자인: [DDayHome 화면 디자인](../../design/dday-home.md)

이번 범위는 `더보기`에서 DDayHome으로 이동하고, 계정에 저장된 디데이를 기기에서 불러와 카드 문구와 함께 목록으로 표시하고, 태그 필터로 목록을 좁히고, 목록을 당겨 새로고침하고, DDayHome에서 디데이 추가와 디데이 상세로 이동하고, 목록에서 디데이를 삭제하고 되돌리는 것까지다. 사용자가 목록의 정렬을 고르는 기능은 제공하지 않는다.

## feature

### 진입

사용자는 `더보기` 화면의 `디데이` 바로가기를 선택해 이 화면으로 이동한다.

### 화면 내용

사용자는 화면에서 자신이 `디데이` 기능으로 들어왔음을 알 수 있는 제목을 확인한다. 제목은 `더보기`에서 고른 바로가기 항목과 같은 이름을 쓴다.

화면에는 제목, 뒤로가기, 필터 열기, 디데이 목록과 디데이 추가만 둔다.

### 디데이 목록

사용자는 DDayHome에서 계정에 저장된 디데이 전체를 목록으로 볼 수 있다. 사용자는 각 카드에서 그 디데이의 제목과 카드 문구를 확인하고, 카드는 디데이의 컬러로 서로 구분해 보여 준다. 카드 문구는 [디데이 앱 스펙](./dday.md)의 `카드 문구`를 `domain > 오늘 기준`이 정한 오늘로 계산한 것이다.

디데이의 설명, 기준일, 기준일을 1일로 세기, 반복 간격, 종료일, 달력에 없는 날짜 처리와 연결한 태그는 목록에 표시하지 않는다. 목록에서는 어떤 디데이인지 알아보는 데 필요한 제목과, 남은 날이나 지난 날을 한눈에 볼 수 있는 카드 문구만 보여 준다.

종료일이 지난 디데이도 목록에서 빠지지 않고 카드 문구와 함께 계속 보인다. 목록에서의 자리는 `domain > 목록 정렬`을 따른다.

목록이 나타나는 순서, 아직 준비되지 않은 자리와 추가한 디데이가 목록에 나타나는 조건은 [항목 목록 화면 공통 스펙](./entity-home.md)의 `목록 표시`를 따른다.

사용자는 목록의 디데이를 선택해 그 디데이의 [DDayDetail 화면](./dday-detail.md)으로 이동한다. 준비되지 않은 자리와 돌아왔을 때의 목록은 [항목 목록 화면 공통 스펙](./entity-home.md)의 `상세로 이동`을 따르며, 상세에서 수정한 결과가 반영된 카드 문구와 순서를 본다.

목록과 상세를 함께 사용할 수 있는 환경에서는 이동하지 않고 상세 영역이 그 디데이의 상세로 바뀌며, 그 기준은 [DDay 목록·상세 배치 스펙](./dday-list-detail.md)의 `상세 영역의 구성`을 따른다.

### 태그 필터

사용자는 DDayHome에서 필터를 열어 태그를 골라 목록을 좁힐 수 있다. 태그를 고르면 목록은 고른 태그 중 하나 이상과 연결된 디데이만 보여 준다. 선택할 수 있는 태그, 여러 태그를 고를 때의 판정, 선택 전체 해제, 필터 안의 태그 추가와 선택할 수 없게 된 태그의 처리는 [태그 필터 스펙](./tag-filter.md)을 따르며, 그 문서의 메모는 이 화면에서 디데이로 읽는다. 판정에 쓰는 연결은 `domain > 태그 필터 기준`을 따른다.

필터를 열고 닫는 행동, 선택의 반영 시점, 필터가 적용되었는지 알리는 기준, 필터를 바꾼 뒤 목록을 처음부터 보게 되는 결과는 [목록 필터 반영 스펙](./list-filter.md)을 따른다. 필터는 목록이 비어 있어도 언제나 열 수 있다.

태그 필터는 목록에 놓이는 디데이의 범위만 좁히며 목록 순서는 바꾸지 않는다.

### 빈 상태

목록 불러오기가 끝났고 `domain > 목록에 노출하는 디데이`와 태그 필터에 맞는 디데이가 하나도 없으면 목록 자리에 비어 있음을 알린다. 필터를 적용하지 않았으면 아직 디데이가 없으며 새로 추가할 수 있음을, 필터를 적용했으면 고른 태그에 맞는 디데이가 없으며 필터를 바꾸면 다른 디데이를 볼 수 있음을 알린다. 판정 시점, 빈 상태에서 할 수 있는 행동, 목록과의 전환, 좁힌 상태의 기준은 [목록 빈 상태 스펙](./list-empty-state.md)을 따른다.

빈 상태에서도 사용자는 디데이 추가, 필터 열기와 당겨서 새로고침을 그대로 실행할 수 있다.

### 새로고침

목록을 당겨 새로고침하는 행동과 결과는 [항목 목록 화면 공통 스펙](./entity-home.md)의 `새로고침`을 따른다.

### 디데이 추가로 이동

사용자는 디데이 추가를 선택해 [DDayAdd 화면](./dday-add.md)으로 이동한다. 디데이 추가는 모든 플랫폼에서 제공한다. 언제 제공하는지, 추가 단축키, 목록과 상세를 함께 사용하는 동안의 추가 수단과 돌아왔을 때의 결과는 [항목 목록 화면 공통 스펙](./entity-home.md)의 `추가로 이동`을 따른다. 추가한 디데이가 적용한 태그 필터의 조건을 만족하지 않으면 목록에 나타나지 않는다.

### 삭제

사용자는 목록의 디데이를 삭제할 수 있다. 디데이에는 완료 여부가 없으므로 삭제 방향만 제공하며, 삭제와 실행 취소의 결과는 [항목 목록 화면 공통 스펙](./entity-home.md)의 `삭제`를 따른다. 실행 취소로 돌아온 디데이는 `domain > 목록 정렬`에 맞는 자리에 다시 나타나고, 삭제하기 전의 태그 연결을 그대로 가진다.

### 안내와 실행 취소

삭제의 안내와 실행 취소는 [항목 목록 화면 공통 스펙](./entity-home.md)의 `안내와 실행 취소`를 따른다. [DDayDetail 화면 스펙](./dday-detail.md)의 `삭제`가 여기에 해당하는 상세 화면의 삭제다.

### 뒤로가기

뒤로가기의 결과는 [항목 목록 화면 공통 스펙](./entity-home.md)의 `뒤로가기`를 따르며, 상세 영역과 함께 표시되는 상태에서의 결과는 [DDay 목록·상세 배치 스펙](./dday-list-detail.md)의 `뒤로가기`를 따른다.

## domain

### 목록에 노출하는 디데이

노출 기준은 [항목 목록 화면 공통 스펙](./entity-home.md)의 `목록에 노출하는 항목`을 따른다. 디데이에는 더하는 상태 조건이 없다. 종료일이 지났는지, 반복 간격이 있는지, 다가오는 날짜가 있는지는 노출 기준에 쓰지 않는다.

### 태그 필터 기준

태그 필터는 디데이와 태그의 해제되지 않은 연결로 판정한다. 연결의 규칙은 [디데이 태그 스펙](../common/dday-tag.md)을 따르며, 태그와 태그의 연결을 따라 판정하지 않는다.

선택한 태그가 없으면 노출 기준을 만족하는 디데이를 모두 표시하고, 선택한 태그가 있으면 그중 하나 이상과 연결된 디데이만 표시한다. 선택한 태그와 연결되어 있어도 노출 기준을 만족하지 않는 디데이는 표시하지 않는다.

DDayHome에는 태그 필터 선택을 판정에서 무시하는 다른 필터가 없으며, 태그 추가 동작을 막는 조건도 없다.

필터 선택은 [목록 필터 반영 스펙](./list-filter.md)의 `필터 선택 유지`에 따라 현재 사용자 계정별로 유지하며, MemoHome과 CalendarHome의 태그 필터 선택과 공유하지 않는다.

### 목록 정렬

목록은 [디데이 앱 스펙](./dday.md)의 `목록 순서`에 따라 제목 오름차순으로 놓는다. 사용자가 고를 수 있는 다른 정렬은 없다. 카드 문구, 종료일이 지났는지와 기념일은 정렬에 영향을 주지 않는다.

### 오늘 기준

카드 문구에 쓰는 오늘은 [디데이 앱 스펙](./dday.md)의 `오늘`이다.

오늘은 DDayHome에 들어오거나, 다른 화면이나 다른 앱에서 DDayHome으로 돌아올 때마다 다시 정한다. 예를 들어 자정 이전에 화면을 벗어났다가 자정 이후에 돌아오면 바뀐 오늘로 카드 문구를 다시 정한다. 이 기준은 [CalendarHome 스펙](./calendar-home.md)의 `오늘 기준`과 같다.

화면을 보는 동안 자정이 지나도 오늘은 다시 정하지 않는다. 사용자가 보고 있는 동안 카드 문구가 저절로 바뀌지 않게 하기 위한 것이다.

목록과 상세를 함께 사용하는 동안 상세 영역에서 화면이 바뀌는 것은 DDayHome을 떠난 것이 아니므로 오늘을 다시 정하지 않는다.

### 목록 갱신

목록의 자동 갱신은 [항목 목록 화면 공통 스펙](./entity-home.md)의 `목록 갱신`을 따른다. 디데이의 제목, 컬러, 기준일, 기준일을 1일로 세기, 반복 간격, 종료일이나 달력에 없는 날짜 처리가 바뀌면 그 카드의 문구도 함께 다시 정하고, 제목이 바뀌면 목록에서의 자리도 바뀐다. 태그 필터를 적용한 동안 디데이의 태그 연결이 바뀌면 그 디데이는 사용자가 필터를 다시 고르지 않아도 목록에서 사라지거나 나타난다.

`오늘 기준`에 따라 오늘을 다시 정하면 그 오늘로 모든 카드의 문구를 다시 정한다. 목록 순서는 바뀌지 않는다.

### 삭제와 실행 취소의 상태 전이

목록의 삭제와 실행 취소는 [항목 목록 화면 공통 스펙](./entity-home.md)의 `삭제와 실행 취소의 상태 전이`를 따른다. 디데이의 정보는 바꾸지 않으며, 태그 연결이 남는 기준은 [디데이 태그 스펙](../common/dday-tag.md)을 따른다.

### 화면 유지

목록 위치와 태그 필터 선택의 유지는 [항목 목록 화면 공통 스펙](./entity-home.md)의 `화면 유지`를 따른다.

## data

### 삭제와 실행 취소의 저장

삭제와 실행 취소의 저장과 동기화는 [항목 목록 화면 공통 스펙](./entity-home.md)의 `삭제와 실행 취소의 저장`을 따른다. 태그 연결은 기기에서 지우지 않는다.

### 목록 조회

목록에 표시할 디데이는 현재 사용자 계정을 기준으로 기기에 저장된 디데이에서 `domain`의 노출 기준과 태그 필터를 만족하는 디데이를 `domain > 목록 정렬`에 따라 조회한다. 카드 문구는 기기에 따로 기록해 두지 않고 조회한 디데이의 정보로 그때그때 정한다.

저장된 디데이나 디데이와 태그의 연결이 바뀌면 조회 결과도 그에 맞게 갱신되어 목록에 반영된다. 태그 필터를 바꾸면 바뀐 기준으로 다시 조회한다.

목록을 조회하지 못하면 노출할 디데이가 없는 것과 같게 다루고 별도의 오류 안내는 제공하지 않는다. 이때의 표시는 [목록 빈 상태 스펙](./list-empty-state.md)의 `빈 상태 판정 기준`을 따른다.

서버에서 디데이를 다시 가져오는 계기는 [항목 목록 화면 공통 스펙](./entity-home.md)의 `목록 조회`를 따른다.
