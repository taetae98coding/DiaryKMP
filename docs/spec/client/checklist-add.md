# ChecklistAdd 화면 스펙

이 문서는 사용자가 제목, 설명과 체크 항목을 입력해 새 체크리스트를 추가하는 ChecklistAdd 화면의 내용과 행동, 그리고 체크리스트와 체크 항목이 갖는 정보를 다룬다. ChecklistAdd로 진입하는 흐름과 추가한 체크리스트가 목록에 나타나는 것은 [ChecklistHome 화면 스펙](./checklist-home.md)에서, 저장한 체크리스트의 항목을 체크하고 관리하는 흐름은 [ChecklistDetail 화면 스펙](./checklist-detail.md)에서, 체크리스트를 서버와 맞추는 규칙은 [데이터 동기화 스펙](../common/data-sync.md)에서 다룬다. 제목 입력 자체의 동작은 [제목 입력 스펙](./title-input.md)을, 설명 입력 자체의 동작은 [설명 입력 컴포넌트 스펙](./description-input.md)을 따른다.

작성 상태 유지, 뒤로가기, 저장 실패, 추가 요청 제한, 계정 연결과 저장 계약은 [항목 추가 화면 공통 스펙](./entity-add.md)을 따른다. 그 문서의 `대상 항목`은 체크리스트다. 체크리스트는 태그와 연결되지 않으므로 이 화면은 태그 입력을 제공하지 않고, 그 문서의 태그 입력 관련 규칙은 적용하지 않는다.

디자인: [ChecklistAdd 화면 디자인](../../design/checklist-add.md)

## feature

### 진입

사용자는 ChecklistHome 화면의 체크리스트 추가를 선택해 이 화면으로 이동한다. 처음 들어오면 제목, 설명, 항목 입력이 비어 있고 넣어 둔 체크 항목이 없다. 사용자가 체크리스트의 주제부터 바로 적을 수 있도록 입력 초점을 제목 입력에 둔다.

### 화면 내용

사용자는 화면에서 체크리스트를 추가하는 화면에 들어왔음을 알 수 있는 제목을 확인한다.

화면에는 화면 제목, 뒤로가기, 제목 입력, 설명 입력, 넣어 둔 체크 항목 목록, 항목 입력, 항목 넣기와 체크리스트 추가만 둔다.

### 제목과 설명 입력

사용자는 제목 입력에 체크리스트의 주제를 적고, 설명 입력에 덧붙일 설명을 적는다. 각 입력의 동작은 [제목 입력 스펙](./title-input.md)과 [설명 입력 컴포넌트 스펙](./description-input.md)을 따른다.

### 체크 항목 넣기

사용자는 항목 입력에 체크 항목의 내용을 한 줄로 적고 항목 넣기를 실행해 그 내용을 넣어 둔 체크 항목 목록의 맨 끝에 놓는다. 물리 키보드나 화면 키보드에서 입력을 마치는 키를 눌러도 항목 넣기와 같은 결과다.

항목을 넣으면 항목 입력이 비워지고 입력 초점은 항목 입력에 남아, 사용자가 곧바로 다음 항목을 적을 수 있다.

항목 입력이 비어 있거나 공백만 있으면 항목 넣기를 제공하지 않으며, 입력을 마치는 키를 눌러도 항목을 넣지 않는다.

같은 내용의 항목을 이미 넣었더라도 새 항목으로 넣는다.

### 넣어 둔 체크 항목

사용자는 넣어 둔 체크 항목을 넣은 순서대로 확인한다. 이 화면의 체크 항목은 아직 저장되지 않았으므로 체크할 수 없고, 모두 체크되지 않은 상태로 추가된다.

사용자는 넣어 둔 체크 항목을 하나씩 빼낼 수 있다. 빼낸 항목은 목록에서 사라지고 남은 항목의 순서는 그대로다. 빼내기 전에 확인을 되묻지 않는다. 넣어 둔 항목의 내용을 고치려면 빼낸 뒤 다시 넣는다.

넣어 둔 체크 항목이 없으면 그 목록 자리는 비워 두며 별도의 안내를 표시하지 않는다.

### 체크리스트 추가

사용자는 체크리스트 추가를 실행해 입력한 제목, 설명과 넣어 둔 체크 항목으로 새 체크리스트를 추가한다. 추가 성립 조건은 `domain > 추가 성립 조건`을 따른다.

추가를 처리하는 동안에는 진행 상태를 표시한다. 추가에 성공하면 화면을 유지한 채 제목, 설명, 항목 입력을 비우고 넣어 둔 체크 항목도 모두 비운다. 사용자가 다음 체크리스트 입력을 바로 이어갈 수 있도록 입력 초점을 제목 입력으로 옮기며 성공 피드백을 제공한다. 추가한 체크리스트는 ChecklistHome으로 돌아가면 목록에 나타난다. 저장에 실패했을 때의 결과는 [항목 추가 화면 공통 스펙](./entity-add.md)의 `저장 실패`를 따른다.

### 제목 미입력

제목이 비어 있거나 공백만 있는 상태에서 추가를 실행하면 체크리스트를 추가하지 않고 제목 입력이 필요함을 알리며, 입력 초점을 제목 입력으로 옮긴다. 입력 중이던 설명, 넣어 둔 체크 항목과 항목 입력은 그대로 남는다.

### 뒤로가기

사용자가 뒤로가면 ChecklistHome 화면으로 돌아간다. 입력 중이던 내용과 넣어 둔 체크 항목은 저장되지 않는다.

### 작성 상태 유지 대상

[항목 추가 화면 공통 스펙](./entity-add.md)의 `작성 상태 유지`가 유지하는 대상은 입력 중이던 제목, 설명, 항목 입력과 넣어 둔 체크 항목의 내용과 순서다.

화면 재생성과 백그라운드 복귀 뒤에도 이 대상을 유지하고, 시스템이 앱을 메모리에서 정리한 뒤 화면을 복원해도 모두 복원한다. 이 화면은 태그 입력을 제공하지 않으므로 복원에서 제외하는 입력이 없다.

표시 중이던 제목 미입력 안내와 추가 결과 피드백은 화면 재생성이나 앱 재실행 뒤에 다시 표시하지 않는다.

## domain

### 체크리스트의 정보

체크리스트는 사용자가 정한 주제 하나와 그 주제에서 확인할 체크 항목들로 이루어진다.

| 정보 | 내용 |
| --- | --- |
| 제목 | 체크리스트의 주제. 반드시 있어야 하며, 비어 있거나 공백만 있을 수 없다 |
| 설명 | 주제에 덧붙이는 글. 비어 있을 수 있다 |
| 삭제 여부 | 체크리스트를 삭제했는지 |

체크리스트는 [데이터 동기화 스펙](../common/data-sync.md)의 `항목과 연결의 상태와 시각`에 따라 생성 시각과 수정 시각을 가진다. 체크 항목을 넣거나 빼거나 체크하는 것은 체크리스트의 수정이 아니며, 체크리스트의 수정 시각을 바꾸지 않는다.

### 체크 항목의 정보

체크 항목은 하나의 체크리스트에 속하며, 속한 체크리스트는 처음 만들 때 정해지고 바뀌지 않는다.

| 정보 | 내용 |
| --- | --- |
| 속한 체크리스트 | 이 항목이 들어 있는 체크리스트 |
| 내용 | 확인할 일. 한 줄이며 비어 있거나 공백만 있을 수 없다 |
| 체크 여부 | 사용자가 그 일을 확인했는지 |
| 삭제 여부 | 항목을 체크리스트에서 뺐는지 |

체크 항목도 체크리스트와 같은 기준으로 생성 시각과 수정 시각을 가진다. 체크 항목은 체크리스트와 따로 저장되고 따로 동기화되는 항목이므로, 한 체크리스트의 여러 항목을 서로 다른 기기에서 바꿔도 각 항목의 변경이 따로 반영된다.

체크 항목의 추가순은 생성 시각 오름차순이다. 생성 시각이 같은 항목끼리의 순서는 정하지 않는다.

### 추가 성립 조건

체크리스트는 제목을 가져야 추가할 수 있다. 제목이 비어 있거나 공백 문자로만 이루어져 있으면 추가하지 않는다.

설명과 체크 항목은 추가 성립 조건이 아니다. 설명이 비어 있거나 넣어 둔 체크 항목이 하나도 없어도 체크리스트를 추가할 수 있으며, 항목은 ChecklistDetail에서 이어서 넣을 수 있다.

같은 제목, 설명과 체크 항목의 체크리스트를 이미 추가했더라도 새 체크리스트로 추가한다.

### 추가되는 체크리스트의 내용

새 체크리스트에는 제목과 설명을 앞뒤 공백을 포함해 입력한 그대로 기록한다. 설명이 비어 있으면 빈 설명으로 기록한다.

넣어 둔 체크 항목은 새 체크리스트에 속한 새 체크 항목으로 함께 만든다. 각 항목에는 넣을 때의 내용을 그대로 기록하고, 체크되지 않고 삭제되지 않은 상태로 만든다.

추가를 실행할 때 항목 입력에 넣지 않은 내용이 남아 있고 그 내용이 비어 있지 않고 공백만 있지도 않으면, 그 내용도 넣어 둔 체크 항목의 맨 끝 항목으로 함께 만든다. 사용자가 마지막 항목을 적고 넣기를 잊은 채 추가해도 그 항목을 잃지 않게 하기 위한 것이다.

체크리스트의 생성 시각과 수정 시각은 [항목 추가 화면 공통 스펙](./entity-add.md)의 `추가되는 항목의 내용`에 따라 추가한 시각으로 기록한다. 함께 만드는 체크 항목은 넣어 둔 순서가 추가순으로 유지되도록 맨 앞 항목부터 생성 시각을 차례로 조금씩 늦게 기록하며, 각 항목의 수정 시각은 그 항목의 생성 시각과 같다.

### 항목의 계정 연결

새 체크리스트와 함께 만드는 체크 항목은 모두 현재 사용자 계정과 연결한다. 계정 연결의 기준은 [항목 추가 화면 공통 스펙](./entity-add.md)의 `항목의 계정 연결`을 따른다.

## data

### 체크리스트 생성과 저장

저장 흐름은 [항목 추가 화면 공통 스펙](./entity-add.md)의 `생성과 저장`을 따른다. 이때 함께 반영되는 것은 새 체크리스트, 함께 만드는 체크 항목과 그 모두의 현재 사용자 계정 연결이며, 일부만 저장된 기기 상태는 남지 않는다.

체크리스트의 제목과 설명, 체크 항목의 내용과 체크 여부는 저장되며, 체크리스트를 조회하면 그 체크리스트의 체크 항목도 함께 조회할 수 있다. 화면의 항목 입력에 남아 있던 내용은 `domain > 추가되는 체크리스트의 내용`에 따라 항목으로 만든 경우에만 저장된다.

### 동기화

동기화는 [항목 추가 화면 공통 스펙](./entity-add.md)의 `동기화`를 따른다. 체크리스트와 체크 항목은 서로 다른 종류로 업로드 대기가 되며, 체크 항목은 속한 체크리스트가 먼저 반영된 뒤에 올라간다. 순서는 [데이터 동기화 앱 스펙](./data-sync.md)의 `동기화 단계와 처리 순서`를 따른다.
