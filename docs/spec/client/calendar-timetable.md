# CalendarTimetable 화면 스펙

이 문서는 캘린더 홈 화면이나 일일 메모 알림으로 연 시간표 화면의 형식과 시작 날짜, 방향키로 날짜 이동, 년도와 월 안내, 공휴일 표시와 선택, 날씨 동기화와 표시, 날씨 선택, 디데이 표시와 선택, 연락처 생일 표시와 선택, 메모 표시와 선택, 태그 필터 적용, 기간 선택을 통한 메모 추가 시작, 현재 시각 기준, 시간표 닫기를 다룬다. 캘린더 홈 화면에서 시간표로 들어가는 행동은 [CalendarHome 스펙](./calendar-home.md)의 `시간표 열기`에서, 일일 메모 알림을 선택해 시간표로 들어가는 행동은 [일일 메모 알림 스펙](./daily-memo-notification.md)의 `알림에서 앱 열기`에서 다룬다. 날짜 구성, 시간대 안내, 아이템 배치, 좌우로 넘겨 보는 날짜 이동, 기간 선택, 현재 시각 위치 표시는 [Timetable 컴포넌트 스펙](./timetable.md)을 따르며, 이 문서는 시간표 화면에 적용되는 부분만 다룬다. 시간표에 표시할 메모를 정하는 기준은 [캘린더 메모 표시 스펙](./calendar-memo.md)을, 표시할 디데이를 정하는 기준은 [캘린더 디데이 표시 스펙](./calendar-dday.md)을, 표시할 생일을 정하는 기준은 [캘린더 연락처 생일 표시 스펙](./calendar-contact-birthday.md)을 따른다.

디자인: [CalendarTimetable 디자인](../../design/calendar-timetable.md)

## feature

### 형식과 시작 날짜

시간표는 [Timetable 컴포넌트 스펙](./timetable.md)의 하루 형식과 주간 형식 중 하나로 표시된다. 형식은 시간표를 연 방법으로 정해지며, 시간표 안에서 형식을 바꾸지 않는다.

하루 형식은 캘린더 홈 화면에서 누른 날짜를 먼저 표시한다. 주간 형식은 캘린더 홈 화면에서 누른 주를 먼저 표시한다. 일일 메모 알림으로 연 시간표는 하루 형식이며 알림이 발생한 날을 먼저 표시한다. 이 날짜는 [일일 메모 알림 스펙](./daily-memo-notification.md)의 `알림으로 여는 날짜`를 따른다. 시간표를 보는 중에 알림을 선택하면 보던 시간표 자리에 새 시간표가 열리며, 이는 그 문서의 `알림에서 앱 열기`를 따른다.

시간표는 어디에서 열었든 화면 너비와 관계없이 단독으로 표시한다.

### 방향키로 날짜 이동

물리 키보드를 쓰는 환경에서는 왼쪽 방향키로 이전, 오른쪽 방향키로 다음으로 표시 날짜를 옮길 수 있다. 한 번에 옮기는 날짜는 [Timetable 컴포넌트 스펙](./timetable.md)의 `날짜 이동`에서 좌우로 넘길 때와 같다.

같은 문서의 `이동 범위`를 벗어나는 방향의 방향키 입력은 무시하고 보던 날짜를 그대로 유지한다.

### 년도와 월 안내

사용자는 표시 중인 날짜의 년도와 월을 확인할 수 있다. 주간 형식에서 한 주가 두 달에 걸치면 그 주 일요일이 속한 달을 안내한다. 다른 날짜로 이동하면 안내도 이동한 날짜 기준으로 갱신된다.

### 오늘 강조와 현재 시각

시간표는 `domain`의 오늘 기준으로 정한 현재 시각을 Timetable에 지정한다. 따라서 오늘에 해당하는 날짜는 주요 날짜로 강조되고, 오늘이 표시되면 오늘의 열에서 현재 시각의 위치를 확인할 수 있다. 표시 방식은 [Timetable 컴포넌트 스펙](./timetable.md)의 `날짜 안내`와 `현재 시각 표시`를 따른다.

### 공휴일 날짜 강조

시간표에서 공휴일에 해당하는 날짜는 [Timetable 컴포넌트 스펙](./timetable.md)의 `날짜 안내`에 따라 일반 날짜와 구분해 강조한다. 강조하는 날짜는 `domain`의 공휴일 표시 대상을 따른다.

아직 표시할 공휴일이 없으면 공휴일 강조 없이 표시하고, 공휴일이 준비되면 사용자가 별도 조작을 하지 않아도 반영한다. 다른 날짜로 이동하면 이동한 날짜에 필요한 공휴일을 반영한다.

### 공휴일 이름 표시

시간표에는 공휴일 이름을 Timetable의 종일 아이템으로 표시한다. 여러 날에 걸친 공휴일은 기간 전체를 하나로 이어 표시한다. 공휴일 여부가 참인 이름과 거짓인 이름은 [CalendarHome 스펙](./calendar-home.md)의 `공휴일 이름 구분`과 같이 서로 구분한다.

아직 표시할 공휴일이 없으면 이름도 표시하지 않고, 공휴일이 준비되면 사용자가 별도 조작을 하지 않아도 이름을 표시한다.

### 공휴일 이름 선택

사용자가 표시된 공휴일 이름을 선택하면 [CalendarHome 스펙](./calendar-home.md)의 `공휴일 이름 선택`과 같이 그 이름으로 검색한 결과가 앱 밖의 브라우저에서 열린다. 검색 주소는 같은 문서의 `공휴일 이름 검색 주소`를 따른다.

검색 결과가 열려도 시간표는 보던 날짜와 시간대를 그대로 유지한다. 브라우저를 열지 못했을 때의 결과는 같은 문서의 `공휴일 이름 선택`과 같다.

### 날씨 표시

시간표에는 현재 위치의 날짜별 날씨를 Timetable의 `날짜 정보`로 각 날짜의 요일과 일 아래에 표시한다. 날짜별 날씨에서 보여 주는 아이콘과 온도, 아이콘 순서, 가로 스크롤은 [CalendarHome 스펙](./calendar-home.md)의 `날씨 표시`와 같다.

날짜별 날씨가 없는 날짜에는 날씨 없이 요일과 일만 보인다. 아직 표시할 날씨가 없으면 날씨 없이 시간표를 표시하고, 날씨가 준비되거나 바뀌면 사용자가 별도 조작을 하지 않아도 반영한다. 다른 날짜로 이동하면 이동한 날짜의 날씨를 보여 준다.

### 날씨 선택

사용자가 표시된 날씨를 선택하면 [CalendarHome 스펙](./calendar-home.md)의 `날씨 선택`과 같이 현재 위치의 날씨를 검색한 결과가 앱 밖의 브라우저에서 열린다. 어느 날짜의 날씨를 선택해도 같은 검색 결과가 열리며, 검색 주소는 같은 문서의 `날씨 검색 주소`를 따른다.

검색 결과가 열려도 시간표는 보던 날짜와 시간대를 그대로 유지한다. 브라우저를 열지 못했을 때의 결과는 같은 문서의 `날씨 선택`과 같다.

날씨 위에서 길게 누르면 날씨 선택을 실행하지 않고 `기간 선택으로 메모 추가 시작`의 날짜 선택이 시작된다.

### 디데이 표시

시간표에는 디데이의 기준일 당일과 기념일을 Timetable의 종일 아이템으로 그 날짜 하루에 표시한다. 어떤 디데이가 표시되는지, 어떤 날짜를 차지하는지, 어떤 문구와 색상을 사용하는지는 [캘린더 디데이 표시 스펙](./calendar-dday.md)을 따른다. 사용자는 각 아이템에서 디데이의 제목과 그 날짜의 문구를 함께 확인하며, 그 기준과 한 디데이의 같은 날짜를 하나로 합치는 것은 [CalendarHome 스펙](./calendar-home.md)의 `디데이 표시`와 같다.

아직 표시할 디데이가 없으면 디데이 없이 시간표를 표시하고, 디데이가 준비되거나 바뀌면 사용자가 별도 조작을 하지 않아도 반영한다. 다른 날짜로 이동하면 이동한 날짜에 해당하는 디데이를 보여 준다.

### 디데이 선택

사용자가 표시된 디데이를 선택하면 그 디데이의 DDayDetail 화면으로 이동한다. DDayDetail 화면의 내용과 행동은 [DDayDetail 화면 스펙](./dday-detail.md)을 따른다.

시간표에서 이동한 DDayDetail 화면은 디데이 목록과 함께 표시하지 않는다.

사용자가 DDayDetail 화면에서 뒤로 가거나 그 디데이를 삭제하면 시간표로 돌아오고, 시간표는 보던 날짜와 시간대를 그대로 유지한다. 고친 디데이는 바뀐 날짜와 문구, 색상으로, 삭제한 디데이는 사라진 상태로 사용자가 별도 조작을 하지 않아도 시간표에 반영된다.

디데이 위에서 길게 누르면 아무 동작도 하지 않는다. 디데이 선택도 `기간 선택으로 메모 추가 시작`의 날짜 선택도 시작되지 않는다.

### 생일 표시

시간표에는 연락처의 생일을 Timetable의 종일 아이템으로 그 생일 하루에 표시한다. 어떤 연락처의 생일이 표시되는지, 어떤 날짜를 차지하는지, 해마다 반복하는 기준과 음력 생일이 차지하는 날짜는 [캘린더 연락처 생일 표시 스펙](./calendar-contact-birthday.md)을 따른다. 사용자는 각 아이템에서 생일인 연락처의 이름을 확인하며, 이름이 같은 연락처를 구분하는 방식은 [CalendarHome 스펙](./calendar-home.md)의 `생일 표시`와 같다.

아직 표시할 생일이 없으면 생일 없이 시간표를 표시하고, 연락처가 준비되거나 바뀌면 사용자가 별도 조작을 하지 않아도 반영한다. 다른 날짜로 이동하면 이동한 날짜에 해당하는 생일을 보여 준다.

### 생일 선택

사용자가 표시된 생일을 선택하면 그 연락처의 ContactDetail 화면으로 이동한다. ContactDetail 화면의 내용과 행동은 [ContactDetail 화면 스펙](./contact-detail.md)을 따른다.

시간표에서 이동한 ContactDetail 화면은 연락처 목록과 함께 표시하지 않는다.

사용자가 ContactDetail 화면에서 뒤로 가거나 그 연락처를 삭제하면 시간표로 돌아오고, 시간표는 보던 날짜와 시간대를 그대로 유지한다. 삭제한 연락처의 생일은 사용자가 별도 조작을 하지 않아도 시간표에서 사라진다.

생일 위에서 길게 누르면 생일 선택을 실행하지 않고 `기간 선택으로 메모 추가 시작`의 날짜 선택이 시작된다.

### 메모 표시

시간표에는 공휴일, 날씨, 디데이, 연락처 생일과 사용자의 메모를 표시한다.

어떤 메모가 표시되는지와 표시 색상은 [캘린더 메모 표시 스펙](./calendar-memo.md)을 따른다.

메모는 `domain`의 메모 자리에 따라 Timetable의 시각 아이템이나 종일 아이템으로 표시된다.

### 메모 표시 갱신

아직 표시할 메모가 없으면 메모 없이 시간표를 표시하고, 메모가 준비되거나 바뀌면 사용자가 별도 조작을 하지 않아도 반영한다. 다른 화면에서 메모를 추가하거나 고치거나 지우면 시간표로 돌아왔을 때 새로고침하지 않아도 바뀐 내용을 본다.

시간표에는 당겨서 새로고침이 없다. 서버에서 받은 메모가 기기에 반영되는 시점은 [데이터 동기화 스펙](../common/data-sync.md)을 따르며, 반영되면 사용자가 별도 조작을 하지 않아도 시간표에 나타난다.

표시 중인 날짜에 메모가 하나도 없으면 [Timetable 컴포넌트 스펙](./timetable.md)의 `아이템 표시`에 따라 빈 시간표를 보여 준다.

### 태그 필터

시간표에는 캘린더 홈 화면의 태그 필터가 그대로 적용된다. 필터 선택에 따라 표시하는 메모와 디데이는 [CalendarHome 스펙](./calendar-home.md)의 `태그 필터`를 따른다.

필터는 메모와 디데이 표시에 적용되며 공휴일, 생일과 날씨 표시에는 영향을 주지 않는다.

시간표에서는 필터를 열거나 바꿀 수 없다. 필터는 캘린더 홈 화면에서 바꾼다.

### 메모 선택

사용자가 표시된 메모를 선택하면 해당 메모의 MemoDetail 화면으로 이동한다. MemoDetail 화면의 내용과 행동은 [MemoDetail 화면 스펙](./memo-detail.md)을 따른다.

시간표에서 이동한 MemoDetail 화면은 메모 목록과 함께 표시하지 않는다.

여러 날에 걸친 메모를 어느 날짜 부분에서 선택하든 같은 메모가 선택되는 것은 [Timetable 컴포넌트 스펙](./timetable.md)의 `아이템 표시`를 따른다.

사용자가 MemoDetail 화면에서 뒤로 가거나 그 메모를 삭제하면 시간표로 돌아오고, 시간표는 보던 날짜와 시간대를 그대로 유지한다.

### 기간 선택으로 메모 추가 시작

사용자는 시간표에서 기간을 골라 새 메모 작성을 시작할 수 있다. 기간을 고르는 행동은 [Timetable 컴포넌트 스펙](./timetable.md)의 `기간 선택`을 따른다.

사용자가 선택을 완료하면 MemoAdd 화면으로 이동한다. 시간대 선택으로 고른 기간은 날짜·시간 기간으로, 날짜 선택으로 고른 기간은 종일 기간으로 입력된 상태로 시작하며, 화면의 내용과 행동은 [MemoAdd 화면 스펙](./memo-add.md)을 따른다.

시간표에서 이동한 MemoAdd 화면은 메모 목록과 함께 표시하지 않는다.

사용자가 MemoAdd 화면에서 뒤로 가거나 메모를 추가하고 돌아오면 시간표는 선택된 기간 없이 보던 날짜와 시간대를 그대로 보여 준다. 추가한 메모는 `메모 표시 갱신`에 따라 시간표에 나타난다.

선택이 중단될 때의 결과는 [Calendar 날짜 선택 스펙](./calendar-select.md)의 `선택 완료로 화면을 옮기는 경우`를 따르며, 시간대 선택으로 고른 기간에도 같게 적용한다. 선택이 취소되면 시간표는 `보던 날짜와 시간대 유지`에 따라 보던 날짜와 시간대를 그대로 보여 준다.

### 시간표 닫기

사용자가 시간표에서 뒤로 가면 시간표를 열기 전의 화면으로 돌아온다.

캘린더 홈 화면에서 연 시간표에서 뒤로 가면 캘린더 홈 화면으로 돌아온다. 캘린더 홈 화면은 [CalendarHome 스펙](./calendar-home.md)의 `보던 달 유지`에 따라 시간표를 열기 전에 보던 달을 그대로 보여 주며, 시간표에서 옮긴 날짜를 따라 달을 바꾸지 않는다.

일일 메모 알림으로 연 시간표에서 뒤로 가면 [일일 메모 알림 스펙](./daily-memo-notification.md)의 `알림에서 앱 열기`에 따라 알림을 선택하기 전에 보던 화면이나 캘린더 홈 화면으로 돌아온다. 보던 시간표 자리에 열린 시간표에서 뒤로 가면 보던 시간표 아래에 있던 화면으로 돌아온다.

## domain

### 오늘 기준

오늘과 현재 시각은 사용자의 현재 시간대를 기준으로 정한다.

오늘은 시간표에 들어오거나 다른 화면이나 다른 앱에서 시간표로 돌아올 때마다 다시 정한다. 시간표를 보는 동안 자정이 지나면 현재 시각 표시는 바뀐 오늘의 열로 옮겨 가고, 날짜 강조도 바뀐 오늘을 따른다.

현재 시각은 적어도 1분마다 다시 정한다.

### 공휴일 표시 대상

공휴일 표시 대상 연도는 `data`의 표시 중인 날짜의 메모 조회와 같은 조회 기간에 들어가는 날짜의 연도다. 예를 들어 하루 형식으로 2026년 12월 31일을 보고 있으면 2026년과 2027년이 대상이다.

표시 대상 연도에서 이름을 표시하는 공휴일과 날짜를 강조하는 공휴일의 기준은 [CalendarHome 스펙](./calendar-home.md)의 `공휴일 표시 대상`을 따른다. 적용 국가와 숨김으로 고른 공휴일도 캘린더 홈 화면과 같다.

### 공휴일 자리

공휴일 이름은 기간 전체를 차지하는 종일 아이템으로 지정한다. 차지하는 날짜가 모두 같은 메모, 디데이, 생일, 공휴일 이름 사이의 순서는 [CalendarHome 스펙](./calendar-home.md)의 `같은 기간 아이템 순서`와 같으므로 메모, 디데이, 생일, 공휴일 이름 순으로 위쪽 줄부터 놓인다.

### 디데이 자리

디데이는 기준일 당일이나 기념일이 차지하는 하루를 기간으로 하는 종일 아이템으로 지정한다. 같은 날짜의 디데이끼리는 [캘린더 디데이 표시 스펙](./calendar-dday.md)의 `조회 결과 정렬` 순서로 놓인다.

### 디데이 표시 대상

디데이 조회 기간은 `data`의 표시 중인 날짜의 메모 조회와 같은 조회 기간이다. 이 기간을 표시 대상 기간으로 삼아 [캘린더 디데이 표시 스펙](./calendar-dday.md)의 노출 기준과 [CalendarHome 스펙](./calendar-home.md)의 `태그 필터 기준`을 적용하며, 그중 표시 중인 날짜에 드는 기준일 당일과 기념일만 시간표에 나타난다.

### 디데이 조회 실패

디데이를 조회하지 못하면 디데이 없이 시간표를 표시하고 사용자에게 별도로 알리지 않는다. 조회 실패는 공휴일, 메모, 생일, 날씨 표시를 막지 않는다.

### 생일 자리

생일은 차지하는 하루를 기간으로 하는 종일 아이템으로 지정한다.

### 생일 표시 대상

생일 조회 기간은 `data`의 표시 중인 날짜의 메모 조회와 같은 조회 기간이다. 이 기간을 표시 대상 기간으로 삼아 [캘린더 연락처 생일 표시 스펙](./calendar-contact-birthday.md)의 노출 기준, 반복 연도와 달력에 없는 날짜를 적용하며, 그중 표시 중인 날짜에 드는 생일만 시간표에 나타난다. 태그 필터는 생일 표시 대상에 영향을 주지 않는다.

### 음력 자료 동기화 대상

음력 생일을 양력 날짜에 놓기 위해, 생일 조회 기간의 시작일이 속한 양력 연도부터 종료일이 속한 양력 연도까지의 음력 자료를 동기화 대상으로 정한다. 따라서 대상 연도는 `공휴일 표시 대상`의 연도와 같다. 표시 대상은 마지막으로 표시된 날짜를 기준으로 정한다.

### 생일 조회 실패

생일을 조회하지 못하면 생일 없이 시간표를 표시하고 사용자에게 별도로 알리지 않는다. 조회 실패는 공휴일, 메모, 디데이, 날씨 표시를 막지 않는다. 음력 자료를 동기화하지 못해도 사용자에게 별도로 알리지 않고, 다른 대상 연도의 동기화와 시간표의 다른 표시를 막지 않는다.

### 메모 자리

시각이 있는 기간인 메모는 시각 아이템으로, 종일 기간인 메모는 종일 아이템으로 지정한다. 기간 형태는 [캘린더 메모 표시 스펙](./calendar-memo.md)의 `기간 형태`를 따른다.

시각이 있는 기간이면 시작 날짜와 종료 날짜가 달라도 시각 아이템으로 지정한다. 시간표는 시각을 보여 주는 화면이므로, 여러 날에 걸친 메모도 날짜마다 차지하는 시간대에 표시한다. 따라서 하루 일정과 그 밖의 메모로 나누는 [CalendarHome 스펙](./calendar-home.md)의 `메모 기간 형태 구분`은 시간표에 적용하지 않는다. 날짜마다 차지하는 시간대는 [Timetable 컴포넌트 스펙](./timetable.md)의 `시각 아이템 시간대`를 따른다.

시각 아이템의 시작과 종료는 메모 기간의 시작과 종료 날짜·시각 그대로이고, 종일 아이템의 기간은 메모 기간의 시작 날짜부터 종료 날짜까지다. 메모는 [캘린더 메모 표시 스펙](./calendar-memo.md)의 `조회 결과 정렬` 순서대로 Timetable에 지정하므로, 차지하는 시간대가 모두 같은 시각 아이템 메모는 그 순서대로 놓인다.

사용자가 메모의 기간을 바꾸어 자리가 달라지면 사용자가 별도 조작을 하지 않아도 바뀐 자리에 표시한다.

### 보던 날짜와 시간대 유지

화면이 재생성될 때 보던 형식과 날짜, 시간대를 유지하는 기준은 [Timetable 컴포넌트 스펙](./timetable.md)의 `보던 날짜와 시간대 유지`를 따른다. 다른 화면이나 다른 앱에 다녀와도 보던 형식과 날짜, 시간대를 그대로 본다. 사용자가 앱을 종료하고 다시 실행해 시간표를 새로 열면 오전 8시부터 본다.

### 날씨 표시 대상

날씨 표시 대상은 [CalendarHome 스펙](./calendar-home.md)의 `날씨 표시 대상`과 같이 저장된 날씨로 만든 캘린더 날짜별 날씨 전체이며, 표시 중인 날짜와 겹치는 날짜의 날씨만 화면에 나타난다. 날짜를 옮겨도 날씨를 다시 조회하지 않는다.

### 날씨 표시 실패

날씨를 동기화하거나 저장된 날씨를 읽지 못했을 때와 지역명을 확인하지 못했을 때의 결과는 [CalendarHome 스펙](./calendar-home.md)의 `날씨 표시 실패`와 같다. 사용자에게 별도로 알리지 않고, 날씨 실패는 공휴일이나 메모 표시를 막지 않는다.

### 메모 조회 실패

메모를 조회하지 못하면 메모 없이 시간표를 표시하고 사용자에게 별도로 알리지 않는다. 사용자는 계속 날짜를 옮기고 시간대를 스크롤할 수 있다.

### 공휴일 동기화 실패

공휴일을 동기화하거나 조회하지 못하면 공휴일 없이 시간표를 표시하고 사용자에게 별도로 알리지 않는다. 한 연도의 실패는 다른 대상 연도의 공휴일 표시를 막지 않는다.

## data

### 표시 중인 날짜의 공휴일 동기화

시간표에 들어오거나(다른 화면에서 돌아올 때 포함) 표시 중인 날짜가 바뀌면 공휴일 표시 대상 연도의 최신 공휴일을 원격에서 받아 기기에 저장한다. 다른 앱에 다녀오는 것만으로는 공휴일을 다시 동기화하지 않는다.

각 연도의 동기화, 이미 성공한 연도의 재조회 생략, 실패 시 기기에 저장해 둔 공휴일 유지 규칙은 [공휴일 동기화 스펙](./holiday-fetch.md)을 따른다. 표시한 날짜가 바뀔 때마다 그 날짜의 대상 연도를 요청하되, 화면은 같은 연도의 동기화가 이 화면의 요청으로 이미 진행 중이면 그 연도를 다시 요청하지 않는다. 그 밖에 같은 연도의 동기화가 이미 진행 중일 때의 처리는 [연도별 자료 동기화 스펙](./yearly-data-sync.md)의 `진행 중인 요청`을 따른다. 표시 대상은 마지막으로 표시된 날짜를 기준으로 정한다.

### 표시 중인 날짜의 공휴일 조회

시간표에 표시하는 공휴일은 기기에 저장해 둔 공휴일에서 표시 대상 연도별로 조회한 결과를 합쳐 사용한다. 조회 규칙과 저장된 공휴일, 노출 설정, 국가 설정이 바뀔 때의 반영은 [CalendarHome 스펙](./calendar-home.md)의 `표시 중인 달의 공휴일 조회`와 같다.

### 현재 위치의 날씨 동기화

시간표에 들어오거나, 다른 화면이나 다른 앱에서 시간표로 돌아올 때마다 현재 위치의 날씨와 지역명을 동기화한다. 위치 확인, 조회, 저장, 실패 시 기존 날씨 유지 규칙과 `동기화 간격`은 [현재 날씨 동기화 스펙](./weather-fetch.md)을 따르므로, 마지막 동기화 성공 후 1시간이 지나지 않았으면 조회 없이 끝나고 이미 표시하던 날씨가 그대로 유지된다. 날짜를 옮기는 것만으로는 동기화하지 않는다.

시간표는 위치 권한을 요청하지 않고, 당겨서 새로고침도 없다. 날씨 동기화가 이미 진행 중이면 새 동기화를 시작하지 않는 것은 [CalendarHome 스펙](./calendar-home.md)의 `날씨 중복 동기화 방지`와 같다.

### 날짜별 날씨와 지역명 조회

시간표에 표시하는 날씨와 날씨 검색어에 쓰는 지역명은 [CalendarHome 스펙](./calendar-home.md)의 `날짜별 날씨 조회`, `지역명 조회`와 같이 저장된 날씨와 지역명을 사용한다. 동기화 결과로 저장된 날씨나 지역명이 바뀌면 사용자가 별도 조작을 하지 않아도 시간표에 반영한다.

### 표시 중인 날짜의 생일 조회

시간표에 표시하는 생일은 `domain`의 생일 조회 기간을 기준으로 기기에 저장된 연락처에서 조회한다. 조회 대상과 데이터 정렬은 [캘린더 연락처 생일 표시 스펙](./calendar-contact-birthday.md)의 `data` 영역을 따른다. 시간표에 들어오는 것만으로는 서버에서 연락처를 다시 가져오지 않는다.

같은 날짜를 보고 있는 동안 기기에 저장된 연락처가 바뀌거나 계정이 바뀔 때의 반영은 [CalendarHome 스펙](./calendar-home.md)의 `표시 중인 달의 생일 조회`와 같다. 날짜를 옮기면 옮긴 날짜를 기준으로 조회 기간을 다시 정한다.

### 표시 중인 날짜의 디데이 조회

시간표에 표시하는 디데이는 `domain`의 디데이 조회 기간을 기준으로 기기에 저장된 디데이에서 조회한다. 조회 대상과 데이터 정렬은 [캘린더 디데이 표시 스펙](./calendar-dday.md)의 `data` 영역을 따르고, 태그 필터를 반영한 조회는 [CalendarHome 스펙](./calendar-home.md)의 `표시 중인 달의 디데이 조회`와 같다. 시간표에 들어오는 것만으로는 서버에서 디데이를 다시 가져오지 않는다.

같은 날짜를 보고 있는 동안 기기에 저장된 디데이나 디데이와 태그의 연결이 바뀌거나 계정이 바뀔 때의 반영은 [CalendarHome 스펙](./calendar-home.md)의 `표시 중인 달의 디데이 조회`와 같다. 캘린더의 필터 선택이 바뀌어도 사용자가 별도 조작을 하지 않아도 바뀐 내용을 시간표에 반영한다. 날짜를 옮기면 옮긴 날짜를 기준으로 조회 기간을 다시 정한다.

### 표시 중인 날짜의 음력 자료 동기화

시간표에 들어오거나(다른 화면에서 돌아올 때 포함) 표시 중인 날짜가 바뀌면 `domain`의 음력 자료 동기화 대상에 해당하는 각 연도의 음력 자료를 원격에서 받아 기기에 저장한다. 다른 앱에 다녀오는 것만으로는 다시 동기화하지 않는다.

각 연도의 동기화, 이미 성공한 연도의 재조회 생략, 실패 시 기기에 저장해 둔 음력 자료 유지 규칙은 [음력 자료 동기화 스펙](./lunar-fetch.md)을 따른다. 화면은 같은 연도의 동기화가 이 화면의 요청으로 이미 진행 중이면 그 연도를 다시 요청하지 않으며, 그 밖에 같은 연도의 동기화가 이미 진행 중일 때의 처리는 [연도별 자료 동기화 스펙](./yearly-data-sync.md)의 `진행 중인 요청`을 따른다.

### 표시 중인 날짜의 메모 조회

시간표에 표시하는 메모는 기기에 저장된 메모에서 조회한다. 조회 대상, 표시 색상, 데이터 정렬은 [캘린더 메모 표시 스펙](./calendar-memo.md)의 `data` 영역을 따르고, 태그 필터를 반영한 조회는 [CalendarHome 스펙](./calendar-home.md)의 `표시 중인 달의 메모 조회`와 같다.

조회 기간은 표시 중인 날짜와 그 앞뒤로 한 번씩 넘겼을 때 보이는 날짜를 포함한다. 하루 형식은 전날부터 다음 날까지, 주간 형식은 이전 주 일요일부터 다음 주 토요일까지다. 넘기는 동안 함께 보이는 이웃 날짜의 메모도 조회 기간이 감싼다. 날짜를 옮기면 옮긴 날짜를 기준으로 조회 기간을 다시 정한다.

같은 날짜를 보고 있는 동안 기기에 저장된 메모가 바뀌거나 계정이 바뀔 때의 반영은 [CalendarHome 스펙](./calendar-home.md)의 `표시 중인 달의 메모 조회`와 같다. 캘린더의 필터 선택이 바뀌어도 사용자가 별도 조작을 하지 않아도 바뀐 내용을 시간표에 반영한다.

시간표에 들어오는 것만으로는 서버에서 메모를 다시 가져오지 않는다.
