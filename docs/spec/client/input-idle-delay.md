# 입력 정지 대기 시간 스펙

이 문서는 사용자가 값을 입력하는 동안 글자마다 반응하지 않고 입력을 멈춘 뒤에 반응하는 기능이, 얼마나 기다려 입력이 멈췄다고 보는지를 다룬다.

무엇을 기다렸다가 반영하는지, 반영한 뒤에 무엇이 바뀌는지, 기다리지 않는 예외가 있는지는 이 문서를 참조하는 각 문서가 소유한다.

## 적용 대상

사용자가 입력을 멈춘 뒤에 반영하는 기능은 앱 안에서 모두 이 문서의 대기 시간을 따른다. 지금 적용되는 곳은 다음과 같다.

| 스펙 | 기다린 뒤 반영하는 것 |
| --- | --- |
| [검색어 일치 판정](./search-match.md) | 입력한 검색어를 목록에 반영 |
| [PlaceAdd 화면](./place-add.md) | 직접 입력한 좌표를 지도에 반영 |
| [장소 검색 다이얼로그 컴포넌트](./place-search-dialog.md) | 입력한 검색어와 지도의 보이는 영역을 외부 장소 검색에 반영 |

같은 방식으로 기다렸다가 반영하는 기능을 새로 만들면 대기 시간을 따로 정하지 않고 이 문서를 따르며, 그 스펙을 이 표에 더한다.

## domain

### 대기 시간

사용자가 마지막으로 입력한 뒤 `200`밀리초가 지나면 입력이 멈춘 것으로 본다.

기다리는 동안 사용자가 다시 입력하면 기다리는 시간을 처음부터 다시 센다. 따라서 사용자가 이어서 입력하는 동안에는 중간 값이 반영되지 않고, 마지막으로 입력한 값만 한 번 반영된다.

### 값을 하나로 두는 기준

대기 시간은 적용 대상 모두에서 같다. 기능마다 다른 값을 쓰면 같은 조작이 화면마다 다르게 느껴지고, 사용자는 자신이 입력한 값이 언제 반영되는지 예측할 수 없다.

반영 대상이 기기 안에 있는지 외부 서비스에 있는지도 이 값을 가르지 않는다. 이 시간은 사용자가 다음 글자를 이어서 입력할지 판단하는 데 필요한 시간이고, 반영에 드는 비용에서 나온 값이 아니다.

반영에 드는 비용을 줄여야 하면 대기 시간을 늘리지 않고 그 비용을 줄이는 쪽에서 해결한다. 대기 시간을 늘리면 사용자가 입력을 멈춘 뒤에도 화면이 반응하지 않는 시간만 길어진다.
