# 장소 앱 스펙

이 문서는 장소의 좌표를 입력받는 화면이 공통으로 지키는 좌표의 읽기, 정밀도와 성립 판단, 그리고 좌표가 성립하지 않을 때의 결과를 다룬다. 장소가 갖는 정보와 좌표의 유효 범위는 [장소 스펙](../common/place.md)을 따른다.

좌표를 어떤 방법으로 정하는지, 지점 표시와 지도에 반영되는 시점은 [PlaceAdd 화면 스펙](./place-add.md)이, 좌표 오류 때 저장하지 않는 동작이 무엇인지는 각 화면 스펙이 정한다. 이 문서를 따르는 화면은 문서 끝의 `이 문서를 참조하는 문서`에 둔다. 좌표를 기기에 저장하는 흐름은 각 화면 스펙의 `data`가 소유하므로 이 문서에는 `data` 영역을 두지 않는다.

## feature

### 좌표 오류

좌표가 성립하지 않는 상태에서 장소를 추가하거나 수정하면 장소를 저장하지 않고 좌표를 어떻게 입력해야 하는지 알리는 피드백을 제공한다. 다음은 모두 좌표가 성립하지 않는 상태이며, 하나의 피드백으로 같게 안내한다.

- 위도나 경도가 비어 있다.
- 입력한 값을 십진수로 읽을 수 없다.
- 십진수로 읽을 수 있으나 좌표가 표현할 수 있는 범위를 벗어난다.

피드백은 위도와 경도가 각각 어떤 범위의 숫자여야 하는지 함께 알려 사용자가 무엇을 고쳐야 하는지 알 수 있게 한다.

피드백은 좌표를 고치는 방법으로 지도에서 위치를 고르는 것도 함께 알린다.

입력 중이던 제목, 설명, 컬러, 주소와 좌표는 유지하므로 사용자는 좌표를 고친 뒤 다시 시도할 수 있다. 지도가 보고 있는 위치도 바뀌지 않는다.

고쳐야 할 자리가 위도 입력, 경도 입력과 지도로 나뉘어 하나로 정해지지 않으므로, 입력 초점은 옮기지 않고 사용자가 보고 있던 입력에 그대로 둔다.

## domain

### 좌표의 성립

좌표는 [장소 스펙](../common/place.md)의 `좌표의 유효 범위` 안에 있을 때만 성립한다.

좌표가 성립하는지는 좌표를 만든 화면이 아니라 장소를 추가하거나 수정하는 규칙이 판단한다. 이렇게 하면 좌표를 어디에서 만들어 오더라도 같은 기준으로 걸러진다.

### 좌표를 읽는 방법

직접 입력한 위도와 경도는 각각 부호가 붙을 수 있는 순수 십진수로만 읽는다. 앞에 `+`나 `-`가 한 번 올 수 있고, 그 뒤에는 숫자가 하나 이상 오며, 소수점을 쓰면 소수점 뒤에도 숫자가 하나 이상 와야 한다. 앞뒤 공백은 무시한다.

이 형식이 아닌 값은 십진수로 읽을 수 없는 값으로 다룬다. 지수 표기(`1e1`), 16진 표기(`0x1p3`), 숫자 뒤에 붙인 글자(`37.5f`), `NaN`이나 `Infinity` 같은 글자, 쉼표를 소수점으로 쓴 값이 여기에 해당한다.

### 좌표의 정밀도

장소의 좌표는 위도와 경도를 각각 소수 여섯째 자리까지 다룬다. 직접 입력한 값이 그보다 길면 여섯째 자리로 반올림한 값을 입력한 좌표로 삼으며, 성립 여부의 판단과 저장, 저장된 좌표와의 비교는 모두 반올림한 값으로 한다. 지도에서 고르거나 검색에서 가져온 좌표도 같은 자리수로 다룬다.

좌표를 저장하는 규칙도 여섯째 자리로 반올림한 값을 저장한다. 그래서 어느 화면에서 만든 좌표든 같은 자리수로 저장된다.
