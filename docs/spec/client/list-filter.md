# 목록 필터 반영 스펙

이 문서는 사용자가 화면에서 필터를 열고 바꾸는 행동에 공통으로 보장하는 결과를 다룬다. 선택이 반영되는 시점, 필터가 적용되었는지 알리는 기준, 필터 선택의 유지와 초기화, 필터를 바꾼 뒤 목록을 어디서부터 보게 되는지가 여기에 들어간다.

각 화면이 어떤 필터를 제공하고 그 필터가 무엇을 걸러 내는지는 각 화면 스펙이 다룬다. 여러 화면이 함께 쓰는 태그 필터의 선택 방식과 판정 규칙은 [태그 필터 스펙](./tag-filter.md)이, 표시할 항목이 하나도 없을 때의 안내는 [목록 빈 상태 스펙](./list-empty-state.md)이 다룬다.

디자인: [필터 Bottom Sheet 디자인](../../design/filter-bottom-sheet.md)

## 적용 대상

| 스펙 | 필터 | 목록 위치 되돌림 |
| --- | --- | --- |
| [TagHome 목록](./tag-home.md) | 최상위 태그 필터 | 적용한다 |
| [MemoHome 목록](./memo-home.md) | 유무 필터, 태그 필터 | 적용한다 |
| [CalendarHome 화면](./calendar-home.md) | 태그 필터 | 적용하지 않는다 |

`목록 위치 되돌림`은 `필터 반영`과 `domain`의 되돌림 규칙을 가리킨다. CalendarHome에는 이 규칙을 적용하지 않는다. 캘린더는 처음부터 순서대로 읽는 목록이 아니라 날짜로 자리가 정해진 화면이며, 아이템 영역의 스크롤을 언제 되돌리는지는 [CalendarHome 화면 스펙](./calendar-home.md)과 [CalendarWeekOfMonth 컴포넌트 스펙](./calendar-week-of-month.md)이 소유한다. 그 밖의 규칙은 세 화면에 모두 적용한다.

[SearchHome 화면 스펙](./search-home.md)의 질의와 [장소 보기 모드 스펙](./place-view-mode.md)의 지도 보이는 영역도 목록의 범위를 좁히지만 사용자가 필터로 조작하는 것이 아니므로 이 문서가 정하지 않는다. [TagDetail 화면 스펙](./tag-detail.md)의 `표시 범위`도 필터와 같은 자리에서 열지만, 하나를 고르면 끝나는 선택이며 그 반영과 유지는 그 문서가 소유한다.

## feature

### 필터 열기와 선택

사용자는 화면에서 필터를 열어 현재 선택을 확인하고 바꿀 수 있다. 필터는 목록이 비어 있어도, 필터를 적용해 두었어도 언제나 열 수 있다.

선택을 바꾸면 바로 화면에 반영되며 별도의 확정 동작은 필요하지 않다. 선택을 바꿔도 필터는 열린 채로 남아 사용자는 필터 아래에 보이는 화면에서 결과를 확인하며 이어서 다른 필터를 바꿀 수 있다.

사용자는 언제든 필터를 닫고 화면으로 돌아갈 수 있다. 필터를 닫아도 선택은 그대로 남고, 다시 열면 닫기 전의 선택이 보인다.

필터 안의 동작으로 다른 화면으로 이동하면 필터는 닫힌다. 그 화면에서 돌아와도 필터는 다시 열리지 않으며, 사용자는 필터를 다시 열어 이어서 고른다. 필터 안에서 다른 화면으로 이동하는 동작은 [태그 필터 스펙](./tag-filter.md)의 `태그 추가`뿐이다.

### 필터 적용 알림

필터를 여는 동작은 지금 필터가 적용되어 있는지를 함께 알린다. 사용자는 필터를 열지 않고도 화면이 좁혀진 상태인지 알 수 있다. 어떤 필터가 적용되었는지나 몇 개를 골랐는지는 알리지 않는다. 적용 여부의 기준은 `domain`의 `필터 적용 상태`를 따른다.

### 필터 반영

필터를 바꾸면 그 목록은 좁힌 범위의 항목으로 다시 놓인다. 사용자는 목록의 처음부터 좁힌 결과를 확인한다. 이는 [목록 정렬 스펙](./list-sort.md)의 `정렬 반영`에서 정렬을 바꾼 뒤 목록의 처음부터 새 순서를 확인하는 것과 같은 기준이다. 필터를 바꾸지 않았을 때 목록이 보던 자리를 지키는 기준은 [페이지 조회 목록의 자리 표시 스펙](./paged-list-placeholder.md)의 `자동 갱신`과 `보던 자리 유지`를 따른다.

사용자가 목록을 아래로 이동해 둔 상태에서 필터를 바꿔도 마찬가지다. 이전 위치에 있던 항목이 좁힌 결과에 그대로 남아 있어도 그 자리를 따라가지 않는다. 좁힌 범위에서 무엇이 첫 항목이 되었는지는 필터를 바꾸기 전 위치에서 알 수 없으므로, 사용자가 결과를 처음부터 확인하게 한다.

필터가 열린 채로 목록이 처음부터 다시 놓이므로, 사용자는 필터를 닫은 뒤에도 처음부터 놓인 목록을 본다.

되돌린 뒤에도 목록에서 할 수 있는 행동은 그대로다. 항목을 열고, 완료하고, 삭제하고, 실행 취소하고, 당겨서 새로고침하고, 목록을 이어서 이동하는 것이 달라지지 않는다.

좁힌 결과에 표시할 항목이 하나도 없으면 목록 자리에 빈 상태를 표시하며, 그 기준은 [목록 빈 상태 스펙](./list-empty-state.md)을 따른다.

## domain

### 필터 적용 상태

필터가 적용된 상태는 선택이 처음 상태와 다른 상태다. 화면마다 다음을 기준으로 판정한다.

| 화면 | 적용된 상태 | 적용되지 않은 상태 |
| --- | --- | --- |
| TagHome | 최상위 태그만 보기를 켰다 | 최상위 태그만 보기를 껐다 |
| MemoHome | 유무 필터의 세 축 중 하나라도 `전체`가 아니거나, 태그 필터에서 선택한 태그가 하나 이상 있다 | 세 축이 모두 `전체`이고 선택한 태그가 없다 |
| CalendarHome | 태그 필터에서 선택한 태그가 하나 이상 있다 | 선택한 태그가 없다 |

선택한 태그를 셀 때는 [태그 필터 스펙](./tag-filter.md)의 `선택할 수 없게 된 태그`에 따라 판정에서 무시되는 선택을 세지 않는다. MemoHome에서 태그 축이 `없음`이어서 태그 필터 선택이 목록 판정에 쓰이지 않는 동안에도, 선택한 태그가 남아 있으면 적용된 상태로 본다.

[목록 빈 상태 스펙](./list-empty-state.md)의 `빈 이유의 구분`에서 좁힌 상태로 보는 기준도 이 표와 같다.

### 필터 선택 유지

필터 선택은 사용자가 필터에서 직접 바꿀 때만 바뀐다. 필터를 닫거나, 화면이 회전하거나 재생성되거나, 앱이 백그라운드에 다녀오거나, 다른 화면에 다녀와도 선택은 그대로이며, 앱을 종료하고 다시 실행해도 이어진다.

필터 선택은 필터를 제공하는 화면별로 독립이다. 한 화면에서 고른 선택은 다른 화면에 적용하지 않는다. 같은 태그 필터를 쓰는 MemoHome과 CalendarHome도 서로의 선택을 공유하지 않는다.

선택을 누구 기준으로 유지하는지는 필터마다 다르다.

| 화면 | 필터 | 유지 단위 | 처음 상태 |
| --- | --- | --- | --- |
| TagHome | 최상위 태그 필터 | 현재 사용자 계정 | 꺼짐 |
| MemoHome | 태그 필터 | 현재 사용자 계정 | 선택한 태그 없음 |
| MemoHome | 유무 필터 | 기기 하나에 하나, 계정과 무관 | 세 축 모두 `전체` |
| CalendarHome | 태그 필터 | 현재 사용자 계정 | 선택한 태그 없음 |

계정별로 유지하는 필터는 로그인이나 로그아웃으로 현재 사용자 계정이 바뀌면 바뀐 계정에 유지된 선택을 적용하고, 그 계정에서 한 번도 고른 적이 없으면 처음 상태로 시작한다. 한 계정에서 고른 선택은 다른 계정에 적용하지 않으며, 로그아웃했다가 같은 계정으로 다시 로그인하면 그 계정에서 고른 선택이 다시 적용된다.

기기 하나에 하나를 유지하는 필터는 현재 사용자 계정이 바뀌어도 고른 상태를 그대로 이어서 적용한다.

### 필터 선택 초기화

필터 선택이 사용자의 조작 없이 처음 상태로 돌아가는 경우는 [데이터 동기화 스펙](./data-sync.md)의 `강제 전체 재동기화`뿐이다. 이때 그 계정의 기기 데이터와 함께 계정별로 유지하는 필터 선택이 지워져, 그 계정의 필터는 처음 상태로 돌아간다. 기기 하나에 하나를 유지하는 필터는 지우지 않는다.

선택한 태그가 완료되거나 삭제되어 선택할 수 없게 되는 것은 선택을 지우지 않는다. 그 기준은 [태그 필터 스펙](./tag-filter.md)의 `선택할 수 없게 된 태그`를 따른다.

### 필터 열림 유지

필터를 연 채로 화면이 회전하거나 시스템에 의해 화면이 재생성되어도, 앱이 백그라운드에 갔다가 돌아와도 필터는 열린 채로 남는다. 앱이 백그라운드에 있는 동안 시스템이 앱을 정리했다가 다시 만들어도 필터는 열린 채로 다시 보인다. 사용자가 앱을 종료하고 다시 실행하면 필터는 닫힌 상태로 시작한다.


### 되돌리는 시점

되돌림은 좁힌 결과가 목록에 놓이는 시점에 한 번 적용한다.

필터를 바꾼 직후에는 아직 이전 필터로 조회한 목록이 놓여 있다. 그 시점에 되돌리면 좁힌 결과가 도착하면서 사용자가 보던 항목을 따라 목록이 다시 내려가므로, 사용자는 목록이 위로 올라갔다가 되돌아오는 움직임을 보게 된다. 따라서 이전 결과가 남아 있는 동안에는 위치를 그대로 두고, 좁힌 결과가 놓일 때 되돌린다.

좁힌 결과를 준비하는 동안의 표시는 [페이지 조회 목록의 자리 표시 스펙](./paged-list-placeholder.md)을 따른다.

### 되돌리는 조건

되돌림은 그 목록에 적용되는 필터의 값이 실제로 달라졌을 때만 적용한다.

| 사용자 행동 | 되돌림 |
| --- | --- |
| 최상위 태그만 보기를 켜거나 끈다 | 되돌린다 |
| 유무 필터의 한 축을 다른 값으로 바꾼다 | 되돌린다 |
| 유무 필터의 한 축에서 이미 고른 값을 다시 고른다 | 되돌리지 않는다 |
| 태그 필터에서 태그를 선택하거나 선택을 해제한다 | 되돌린다 |
| 태그 필터에서 선택을 전체 해제한다 | 되돌린다 |

메모 목록에서 태그 축이 `없음`이어서 태그 필터가 목록에 적용되지 않는 동안에는 사용자가 태그 선택을 바꿀 수 없으므로 되돌릴 일도 없다. 적용 여부의 기준은 [MemoHome 목록 스펙](./memo-home.md)의 `필터 조합 기준`을 따른다.

### 되돌리지 않는 경우

필터를 바꾸지 않았는데 목록의 내용이 바뀌는 경우에는 되돌리지 않는다. 항목이 추가되거나 수정되거나 완료·삭제되거나 실행 취소로 돌아온 경우, 당겨서 새로고침하거나 서버에서 내려받은 내용이 기기에 반영된 경우가 모두 그렇다. 사용자는 보고 있던 위치에서 바뀐 내용을 확인한다.

필터가 그대로인 채 화면이 회전하거나 시스템에 의해 화면이 재생성되어도, 앱이 백그라운드에 갔다가 같은 화면으로 돌아와도 되돌리지 않는다. 상세나 검색으로 이동한 뒤 뒤로 돌아온 경우도 같다.

정렬을 바꿨을 때의 결과는 [목록 정렬 스펙](./list-sort.md)의 `정렬 반영`이 소유한다.

### 되돌림 범위

되돌림은 필터를 바꾼 그 목록에만 적용한다. 같은 종류의 항목을 보여 주는 다른 목록이나 다른 화면의 목록 위치는 바꾸지 않는다.

필터 선택은 `필터 선택 유지`에 따라 화면별로 독립이므로, 한 화면에서 필터를 바꾼 것이 다른 화면의 목록 위치를 되돌리지 않는다.

목록과 상세를 함께 표시하는 배치에서는 목록 영역만 되돌리고 상세 영역은 그대로 둔다. 사용자가 상세에서 보고 있던 항목은 필터를 바꿔도 계속 상세 영역에 남는다.

## data

### 필터 선택 저장

사용자가 필터의 선택을 바꾸면 `필터 선택 유지`의 유지 단위에 맞춰 기기에 즉시 저장한다. 계정별로 유지하는 필터는 계정마다, 화면마다 따로 저장해 서로 영향을 주지 않는다.

필터 선택은 기기에만 보관하며 서버와 동기화하지 않는다. 따라서 한 기기에서 고른 필터는 다른 기기에 반영되지 않는다. 동기화 대상 종류는 [데이터 동기화 스펙](../common/data-sync.md)이 소유하며 필터 선택은 그 대상에 포함되지 않는다.

선택을 저장하지 못하면 필터와 화면은 바꾸기 전의 선택을 그대로 보여 주며, 실패를 따로 알리지 않는다.

### 필터 선택 조회

필터를 열거나 필터를 제공하는 화면에 들어오면 유지된 선택을 조회해 표시한다. 유지된 선택이 없거나 조회하지 못하면 처음 상태로 본다.
