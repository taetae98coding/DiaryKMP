# TagDetail 웹 탭 스펙

이 문서는 사용자가 TagDetail 화면의 웹 탭에서 표시 범위 안 태그에 연결된 웹 항목을 확인하고, 상세 대상 태그를 초기값으로 사용해 웹 항목을 추가하는 행동을 다룬다. 화면 전체의 구성, 탭 전환과 유지, 화면 제목, 태그 디테일 탭의 행동과 세 목록 탭이 함께 쓰는 표시 범위는 [TagDetail 화면 스펙](./tag-detail.md)이 소유한다.

목록의 웹 항목 표시와 노출·정렬 기준은 [WebHome 화면 스펙](./web-home.md)을, 웹 항목 추가 행동은 [WebAdd 화면 스펙](./web-add.md)을, 웹 항목과 태그 연결의 의미는 [웹 태그 앱 스펙](./web-tag.md)을, 선택한 웹 항목의 상세는 [WebDetail 화면 스펙](./web-detail.md)을 따른다. 아직 준비되지 않은 자리의 처리는 [페이지 조회 목록의 자리 표시 스펙](./paged-list-placeholder.md)을, 목록이 비어 있을 때의 안내는 [목록 빈 상태 스펙](./list-empty-state.md)을, 목록을 당겨 새로고침하는 행동과 동기화 진행 표시는 [새로고침 스펙](./sync-refresh.md)을 따른다.

디자인: [TagDetail 웹 탭 디자인](../../design/tag-detail-web.md)

## feature

### 진입

사용자는 TagDetail 화면에서 웹 탭을 선택해 표시 범위 안 태그에 연결된 웹 목록을 확인한다. 탭을 선택하는 방법과 선택한 탭의 유지 기준은 [TagDetail 화면 스펙](./tag-detail.md)의 `탭 전환`과 `선택한 탭`을 따른다.

상세 대상 태그를 아직 조회하지 못했거나 조회에 실패해도 웹 탭의 목록과 동작은 그대로 제공한다.

### 웹 항목 추가

사용자는 웹 탭에서 언제든 웹 항목 추가를 시작할 수 있다. 상세 대상 태그의 완료 여부, 삭제 여부와 조회 결과는 웹 항목 추가 시작을 막지 않는다.

사용자가 웹 항목 추가를 선택하면 WebAdd 화면으로 이동한다. 이 경로로 진입한 WebAdd 화면은 창 너비와 관계없이 단독으로 표시하고, 그 화면에서는 주요 목적지의 공통 내비게이션을 제공하지 않는다. 웹 목록과 웹 추가를 함께 쓰는 배치는 WebHome에서 진입한 경우에만 적용하며 그 기준은 [Web 목록·상세 배치 스펙](./web-list-detail.md)을 따른다.

웹 탭에서 진입한 웹 추가 화면은 상세 대상 태그를 최초 선택한 상태로 시작한다. 사용자는 저장 전까지 태그 선택을 추가하거나 해제할 수 있다.

사용자가 웹 추가 화면에서 뒤로가면 웹 탭이 선택된 같은 태그의 TagDetail 화면으로 돌아간다.

웹 항목 추가는 웹 탭을 선택한 동안에만 제공한다. 다른 탭에서는 웹 항목 추가를 실행할 수 없다.

### 목록 표시

목록에는 현재 사용자 계정과 연결된 웹 항목 중 표시 범위 안 태그 하나 이상과 해제되지 않은 연결을 가지며 삭제되지 않은 웹 항목만 표시한다. 표시 범위가 무엇을 정하는지는 [TagDetail 화면 스펙](./tag-detail.md)의 `표시 범위`를 따른다.

한 웹 항목이 표시 범위 안 여러 태그와 연결되어 있어도 목록에는 한 번만 나타난다.

사용자가 표시 범위를 바꾸면 목록을 새 범위 기준으로 다시 표시하고, 범위를 넓혀 새로 들어온 웹 항목은 지금 정렬 기준에 맞는 위치에 나타난다.

정렬은 [WebHome 화면 스펙](./web-home.md)의 `목록 정렬`을 따른다.

아직 준비되지 않은 자리의 처리는 [페이지 조회 목록의 자리 표시 스펙](./paged-list-placeholder.md)을 따른다.

최초 조회나 추가 조회에 실패하면 이미 표시된 웹 항목을 유지하며 별도 재시도 동작은 제공하지 않는다.

### 빈 상태

목록을 불러오기가 끝났고 `목록 표시`의 노출 기준을 만족하는 웹 항목이 하나도 없을 때 목록 자리에 이 태그에 연결된 웹 항목이 아직 없음을 알린다. 불러오는 중에는 빈 상태를 표시하지 않는다. 판정 시점, 빈 상태에서 할 수 있는 행동, 목록과의 전환은 [목록 빈 상태 스펙](./list-empty-state.md)을 따른다.

빈 상태에서도 사용자는 웹 항목 추가를 그대로 실행할 수 있으며, 추가한 웹 항목이 이 목록의 노출 기준을 만족하면 빈 상태가 사라지고 목록에 나타난다.

대상 태그를 조회하지 못해 화면 제목을 표시하지 못하는 것은 빈 상태 판정에 영향을 주지 않는다.

### 웹 상세 확인

사용자가 웹 항목을 선택하면 선택한 웹 항목의 WebDetail 화면으로 이동한다. WebDetail 화면은 창 너비와 관계없이 단독으로 표시하고, 그 화면에서는 주요 목적지의 공통 내비게이션을 제공하지 않는다.

WebDetail 화면에서 뒤로가면 웹 탭이 선택된 같은 태그의 TagDetail 화면으로 돌아간다.

사용자가 WebDetail 화면에서 웹 항목을 삭제하거나 이 태그와의 연결을 해제한 뒤 돌아오면, 그 웹 항목은 이 목록의 노출 기준에 따라 목록에서 사라진다. WebDetail에서 삭제에 성공하면 뒤로가기와 같은 결과로 웹 탭이 선택된 TagDetail 화면으로 돌아온다.

### 새로고침

사용자는 웹 목록을 당겨 새로고침할 수 있다. 새로고침 대상과 진행 표시 기준은 [새로고침 스펙](./sync-refresh.md)을 따른다.

목록이 비어 있을 때도 당길 수 있다. 새로고침 중에 다시 당겼을 때의 결과도 같은 스펙을 따른다.

새로 받은 웹 항목이 지금 노출 기준을 만족하면 사용자가 별도 조작을 하지 않아도 목록에 나타난다. 다른 화면에서 바뀐 웹 항목과 연결도 당기지 않아도 목록에 바로 반영된다.

### 정렬 선택

사용자는 목록 위에서 현재 정렬을 확인하고 다른 기준으로 바꿀 수 있다. 고를 수 있는 기준과 정렬 선택·반영·유지의 결과는 [목록 정렬 스펙](./list-sort.md)을 따른다.

## domain

### 상세 대상 태그와 연결

웹 탭의 상세 대상은 TagDetail 화면의 상세 대상 태그와 같은 태그다. 대상이 결정되는 기준은 [TagDetail 화면 스펙](./tag-detail.md)의 `상세 대상과 내용 표시`를 따른다.

목록에는 표시 범위가 정한 태그 집합 중 하나 이상과 해제되지 않은 연결을 가진 웹 항목만 포함한다. 집합을 만드는 기준은 [TagDetail 화면 스펙](./tag-detail.md)의 `표시 범위`가 소유한다.

집합 안 태그가 완료되거나 삭제되어도 기존 웹 항목 연결은 유지되므로 웹 탭의 노출 기준은 바뀌지 않는다. 다만 삭제된 태그는 집합에 들어가지 않으므로, 상세 대상 태그가 아닌 하위 태그가 삭제되면 그 태그로만 연결된 웹 항목은 목록에서 사라진다.

상세 대상이 다른 태그로 바뀌면 목록을 새 대상 태그를 기준으로 만든 집합의 웹 항목으로 바꾼다.

### 웹 항목 추가의 초기값

웹 항목 추가 시작은 상세 대상 태그의 상태와 무관하게 항상 허용한다.

대상 태그는 웹 추가 화면의 최초 선택 태그일 뿐, 저장해야 하는 필수 관계가 아니다. 대상 태그를 선택한 것으로 표시할 수 있는지는 [항목 추가 화면 공통 스펙](./entity-add.md)의 `태그 선택과 추가 성립 조건`을 따르므로, 완료되었거나 삭제된 대상 태그는 선택되지 않은 상태로 시작한다.

최종 웹-태그 관계는 저장 시점에 사용자가 선택한 상태로 확정한다. 따라서 대상 태그를 해제하면 새 웹 항목과 연결하지 않는다. 그 밖의 저장 규칙은 [WebAdd 화면 스펙](./web-add.md)을 따른다.

### 웹 항목 노출과 정렬

표시 범위 안 태그와 연결된 웹 항목 중 삭제되지 않은 웹 항목만 노출한다. 표시 범위는 담을 태그만 정하고 이 노출 기준을 대체하지 않는다.

웹 항목에는 완료 여부가 없으므로 완료된 웹 항목을 모아 보는 목록도 두지 않는다.

정렬은 [WebHome 화면 스펙](./web-home.md)의 `목록 정렬`을 따른다.

위 순서는 사용자가 정렬을 고르지 않았을 때의 순서이며, 사용자가 고를 수 있는 다른 기준과 그 순서는 [목록 정렬 스펙](./list-sort.md)이 정한다.

### 태그 연결의 변경과 목록

웹 탭은 목록에서 웹 항목의 태그 연결을 바꾸는 동작을 제공하지 않는다. 사용자는 웹 항목을 선택해 [WebDetail 화면](./web-detail.md)에서 연결을 바꾼다.

웹 탭이 목록에 담을 웹 항목을 고를 때 사용하는 연결은 웹 항목과 태그의 연결이며 그 기준은 [웹 태그 스펙](../common/web-tag.md)을 따른다. 태그와 태그의 연결은 웹 항목에 연결된 태그를 늘리지 않고 표시 범위가 정하는 집합에만 쓰이므로, 표시 범위가 `이 태그만`이면 이 목록에 영향을 주지 않는다.

## data

### 태그별 웹 항목 조회

현재 사용자 계정과 연결된 웹 항목 및 웹-태그 연결 중 표시 범위 안 태그 하나 이상과 해제되지 않은 연결을 가진 항목만 사용자가 목록을 내리는 만큼 나누어 불러온다. 표시 범위 안 여러 태그와 연결된 웹 항목도 조회 결과에 한 번만 담는다. 페이지를 이어서 조회하는 기준은 [페이지 조회 목록의 자리 표시 스펙](./paged-list-placeholder.md)의 `페이지 조회`를 따른다.

웹 항목이 추가되거나 내용, 삭제 여부 또는 태그 연결 상태가 바뀌면 목록을 노출 기준에 따라 자동 갱신하고, 바뀐 웹 항목이 놓이는 자리는 [목록 정렬 스펙](./list-sort.md)의 `정렬 반영`을 따른다. 표시 범위 안 태그를 정하는 태그와 태그의 연결이 바뀐 것도 같은 기준으로 갱신한다. 서버에서 내려받은 웹 항목과 연결이 기기에 반영된 것도 같은 기준으로 갱신한다.

연결이 해제된 웹 항목은 목록에서 사라지고, 연결이 복구되면 노출 기준을 만족할 때 정렬 기준에 맞는 위치에 다시 나타난다.

### 탭별 조회

웹 탭의 목록 조회는 태그 디테일 탭의 태그 조회, 메모 탭의 메모 조회, 장소 탭의 장소 조회와 서로 독립이다. 어느 한쪽이 실패해도 다른 쪽의 표시 기준은 바뀌지 않는다.

### 웹 항목 추가 결과

웹 탭에서 시작한 웹 추가 화면은 `domain > 웹 항목 추가의 초기값`에서 확정한 관계를 새 웹 항목과 함께 저장한다. 저장 방식은 [항목 연결 앱 스펙](./entity-link.md)의 `연결의 저장`을 따른다.

추가된 웹 항목이 상세 대상 태그와 연결되고 웹 탭의 노출 기준을 만족하면 현재 목록의 정렬 기준에 맞는 위치에 나타난다.
