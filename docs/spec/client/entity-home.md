# 항목 목록 화면 공통 스펙

이 문서는 계정에 저장된 항목을 기기에서 불러와 목록으로 보여 주는 홈 화면이 공통으로 따르는 노출 기준, 목록 갱신과 조회, 추가·상세로 이동, 목록에서의 삭제와 실행 취소, 화면 유지를 다룬다. 각 화면이 보여 주는 값, 정렬 기준, 필터, 검색 이동과 화면에만 있는 행동은 각 화면 스펙이 정하고, 이 문서와 다른 결과를 정하면 그 화면 스펙을 따른다.

나누어 불러오는 목록이 나타나는 순서와 아직 준비되지 않은 자리의 처리는 [페이지 조회 목록의 자리 표시 스펙](./paged-list-placeholder.md)을, 목록이 비어 있을 때의 안내는 [목록 빈 상태 스펙](./list-empty-state.md)을, 목록 카드에서 삭제를 실행하는 상호작용과 그 뒤의 안내는 [SwipeToFinishAndDelete 컴포넌트 스펙](./swipe-to-finish-and-delete.md)을, 정렬 선택은 [목록 정렬 스펙](./list-sort.md)을, 목록을 당겨 새로고침하는 조작은 [새로고침 스펙](./sync-refresh.md)을, 목록과 상세를 함께 사용하는 배치는 [목록·상세 배치 공통 스펙](./list-detail-pane.md)을 따른다.

디자인: [항목 목록 화면 공통 디자인](../../design/entity-home.md). 이 디자인은 적용 대상 중 ContactHome, QrHome, WebHome, ChecklistHome, PlaylistHome이 함께 쓰는 표현만 다룬다.

## 적용 대상

| 스펙 | 항목 | 진입 |
| --- | --- | --- |
| [ContactHome 화면](./contact-home.md) | 연락처 | `더보기` |
| [QrHome 화면](./qr-home.md) | QR | `더보기` |
| [WebHome 화면](./web-home.md) | 웹 항목 | `더보기` |
| [PlaceHome 화면](./place-home.md) | 장소 | `더보기` |
| [ChecklistHome 화면](./checklist-home.md) | 체크리스트 | `더보기` |
| [PlaylistHome 화면](./playlist-home.md) | 곡 | `더보기` |
| [MemoHome 목록](./memo-home.md) | 메모 | 공통 내비게이션의 `메모` |
| [TagHome 목록](./tag-home.md) | 태그 | 공통 내비게이션의 `태그` |

- PlaceHome은 두 보기 모드의 목록 표시, 목록 조회와 갱신, 추가·상세로 이동하는 결과를 [장소 보기 모드 스펙](./place-view-mode.md)에 맡기므로, 이 문서에서는 노출 기준, 삭제와 실행 취소, 저장, 뒤로가기만 따른다.
- MemoHome과 TagHome은 완료 여부를 가진 항목을 보여 주는 주요 목적지라 목록 표시, 완료, 화면 유지를 각 화면 스펙과 [TopLevelNavigation 스펙](./top-level-navigation.md)이 정한다. 이 문서에서는 `추가로 이동`, `상세로 이동`, `삭제`, `안내와 실행 취소`와 `삭제와 실행 취소의 저장`의 실행 취소를 저장하지 못한 결과만 따른다. 완료와 함께 다루는 상태 전이와 저장은 각 화면 스펙이 정한다.
- [FileHome 화면](./file-home.md)은 목록을 서버에서 불러오고 목록에서 삭제하지 않으며, [RoutineHome 화면](./routine-home.md)은 노출하는 항목이 없으므로 이 문서를 따르지 않는다.

## feature

### 목록 표시

사용자는 홈 화면에서 계정에 저장된 항목 전체를 목록으로 볼 수 있다. 각 항목에 무엇을 표시하는지는 각 화면 스펙이 정한다.

목록이 나타나는 순서와 아직 준비되지 않은 자리의 처리는 [페이지 조회 목록의 자리 표시 스펙](./paged-list-placeholder.md)을 따른다. 사용자는 목록을 계속 내려 계정의 항목을 모두 확인할 수 있다.

항목을 추가하면 그 항목이 `domain`의 `목록에 노출하는 항목`과 화면이 적용한 필터를 만족할 때 목록에 나타난다.

### 새로고침

사용자는 목록을 아래로 당겨 계정 데이터를 서버와 다시 맞추도록 요청할 수 있다. 당기는 조작이 시작하는 동기화, 진행 표시 기준과 실패 처리는 [새로고침 스펙](./sync-refresh.md)을 따른다.

새로고침으로 내려받은 항목은 사용자가 별도 조작을 하지 않아도 목록에 반영된다.

### 추가로 이동

사용자는 홈 화면에서 추가를 선택해 그 항목의 추가 화면으로 이동한다.

추가는 목록의 내용과 무관하게 언제나 실행할 수 있다. 노출할 항목이 없어 목록이 비어 있거나 필터를 걸어 두었어도 사용자는 추가로 이동할 수 있다.

물리 키보드를 쓰는 환경에서는 추가 단축키로도 추가를 실행할 수 있다. 그 기준은 [목록 추가 단축키 스펙](./list-add-shortcut.md)을 따른다.

목록과 상세를 함께 사용하는 환경에서 목록이 추가를 실행하는 수단을 제공할지는 [목록·상세 배치 공통 스펙](./list-detail-pane.md)의 `추가 진입 수단`을 따른다.

추가 화면에서 돌아오면 홈 화면으로 돌아오고, 추가한 항목이 반영된 목록을 본다.

### 상세로 이동

사용자는 목록의 항목을 선택해 그 항목의 상세 화면으로 이동한다. 아직 준비되지 않은 자리는 가리키는 항목이 없으므로 선택할 수 없으며, 그 자리의 처리는 [페이지 조회 목록의 자리 표시 스펙](./paged-list-placeholder.md)의 `자리 표시`를 따른다.

상세에서 돌아오면 홈 화면으로 돌아오고, 상세로 떠나기 전에 보던 목록을 그대로 본다. 상세에서 수정한 항목은 바뀐 내용으로, 상세에서 삭제한 항목은 사라진 채로 목록에 나타난다.

목록과 상세를 함께 사용하는 환경에서는 이동하지 않고 상세 영역이 선택한 항목의 상세로 바뀌며, 그 기준은 각 화면의 목록·상세 배치 스펙을 따른다.

### 삭제

사용자는 목록의 항목을 삭제할 수 있다. 목록 카드에서 삭제를 실행하는 상호작용은 [SwipeToFinishAndDelete 컴포넌트 스펙](./swipe-to-finish-and-delete.md)을 따르며, 완료 여부가 없는 항목은 삭제 방향만 제공한다. 삭제를 실행하기 전에 확인을 되묻지 않는다.

삭제하면 항목이 목록에서 사라지고 삭제되었음을 안내하며, 실행 취소 동작을 제공한다.

사용자가 실행 취소를 선택하면 항목은 삭제되지 않은 상태로 되돌아가 목록의 정렬 기준에 맞는 위치에 다시 나타난다.

아직 준비되지 않은 자리는 삭제할 수 없다.

목록과 상세를 함께 보는 동안 상세에 열려 있는 항목을 목록에서 삭제해도 상세 영역에 놓인 화면은 바뀌지 않는다.

상세 화면에서 삭제한 항목도 `domain`의 `목록에 노출하는 항목`에 따라 목록에서 사라진다.

### 안내와 실행 취소

삭제의 안내와 실행 취소는 [SwipeToFinishAndDelete 컴포넌트 스펙](./swipe-to-finish-and-delete.md)의 `안내와 실행 취소`를 따른다.

상세 화면의 삭제는 화면을 떠나는 동작이므로 실행 취소를 제공하지 않으며, 이 절은 그 규칙을 바꾸지 않는다.

### 뒤로가기

`더보기`에서 진입한 홈 화면에서 뒤로가기를 실행하면, 홈 화면이 단독으로 표시되는지 상세 영역과 함께 표시되는지와 관계없이 그 기능 화면 전체를 떠나 [TopLevelNavigation 스펙](./top-level-navigation.md)의 `더보기 하위 화면의 뒤로가기`에 따라 `더보기`로 돌아간다.

상세 영역과 함께 표시되는 상태에서 시스템 뒤로가기를 사용한 결과는 [목록·상세 배치 공통 스펙](./list-detail-pane.md)의 `뒤로가기`와 각 화면의 목록·상세 배치 스펙을 따른다.

## domain

### 목록에 노출하는 항목

목록에는 현재 사용자 계정과 연결되어 있고 삭제되지 않은 항목을 모두 노출한다. 각 화면 스펙이 상태 조건을 더하면 그 조건도 함께 만족해야 한다. 계정 조회 규칙은 [계정 조회 스펙](./account.md)을 따르며, 현재 계정을 확인할 수 없으면 노출하는 항목은 없다.

목록은 사용자가 확인하는 만큼 이어서 준비한다. 아직 준비되지 않은 구간의 항목도 노출 기준을 만족하는 항목에 포함되며, 사용자가 목록을 얼마나 확인했는지는 노출 기준과 정렬 기준을 바꾸지 않는다.

### 목록 갱신

항목이 추가되거나 수정되거나 저장 상태가 바뀌면 목록을 노출 기준과 화면이 적용한 필터, 정렬 기준에 따라 자동 갱신한다. 서버에서 내려받은 항목이 기기에 반영된 것도 저장 상태가 바뀐 것으로 보고 같은 기준으로 갱신한다.

### 삭제와 실행 취소의 상태 전이

목록의 삭제는 상세 화면의 삭제와 같은 상태 전이이며, 그 기준은 [항목 상세 화면 공통 스펙](./entity-detail.md)의 `삭제`를 따른다. 삭제는 항목의 삭제 여부를 삭제 상태로 바꾸는 것이며 항목 자체를 지우지 않고, 항목의 내용과 하위 항목은 바꾸지 않는다.

실행 취소는 삭제 여부를 미삭제로 되돌린다.

삭제와 실행 취소는 모두 항목의 수정 시각을 동작 시점으로 갱신한다. 따라서 최근 수정순을 고를 수 있는 목록에서는 실행 취소로 돌아온 항목이 앞쪽에 놓인다.

삭제와 실행 취소는 다른 항목과의 연결을 해제하지 않는다. 따라서 실행 취소한 항목은 삭제 전의 연결을 그대로 가진 채 돌아온다. 그 기준은 [항목 연결 공통 스펙](../common/entity-link.md)의 `항목의 상태 변화와 연결`을 따른다.

목록에서 실행하는 삭제와 실행 취소는 현재 사용자 계정과 연결된 항목에만 적용된다.

### 화면 유지

`더보기`에서 진입한 홈 화면은 화면이 회전하거나 다른 앱에 다녀와도, 그 화면에서 연 추가·상세·검색에서 돌아와도 사용자가 보던 목록 위치를 그대로 유지한다. 앱이 백그라운드에 있는 동안 시스템이 앱을 정리했다가 다시 만들면 목록 위치는 [페이지 조회 목록의 자리 표시 스펙](./paged-list-placeholder.md)의 `보던 자리 유지`에 따라 떠나기 전 위치로 다시 보인다. `더보기`로 나갔다가 다시 들어오거나 앱을 다시 실행하면 목록의 맨 위부터 보여 준다.

정렬 선택을 제공하는 화면의 정렬 유지 기준은 [목록 정렬 스펙](./list-sort.md)의 `정렬 선택 유지`를, 필터를 제공하는 화면의 필터 유지 기준은 [목록 필터 반영 스펙](./list-filter.md)의 `필터 선택 유지`를 따른다.

## data

### 삭제와 실행 취소의 저장

목록에서 항목을 삭제하거나 실행 취소하면 현재 사용자 계정과 연결된 그 항목의 삭제 여부와 수정 시각이 기기에 즉시 저장된다. 항목 자체와 계정 연결, 하위 항목, 다른 항목과의 연결은 기기에서 지우지 않는다.

저장하면 그 항목이 업로드 대기로 기록되고 화면 뒤에서 동기화가 시작되어, 같은 계정의 다른 기기에도 같은 상태로 보인다. 성공 여부는 기기에 저장한 결과로만 판단하며, 업로드 단위와 실패 시 재시도는 [데이터 동기화 앱 스펙](./data-sync.md)의 `업로드 흐름`과 `오프라인과 실패`를 따른다. 로그인하지 않은 상태에서 삭제하거나 되돌린 항목은 서버에 반영되지 않고 기기 안에만 유지된다.

실행 취소를 저장하지 못하면, 현재 계정을 확인할 수 없는 경우를 포함해 항목은 삭제된 채로 남아 목록에 다시 나타나지 않으며 별도의 안내는 제공하지 않는다.

### 목록 조회

목록에 표시할 항목은 현재 사용자 계정을 기준으로 기기에 저장된 항목에서 `domain`의 노출 기준과 화면이 적용한 필터, 정렬 순서로 사용자가 목록을 내리는 만큼 나누어 불러온다. 페이지를 이어서 조회하는 기준은 [페이지 조회 목록의 자리 표시 스펙](./paged-list-placeholder.md)의 `페이지 조회`를 따른다.

저장된 항목이 바뀌면 조회 결과도 그에 맞게 갱신되어 목록에 반영된다.

목록을 조회하지 못했을 때의 목록은 [페이지 조회 목록의 자리 표시 스펙](./paged-list-placeholder.md)의 `조회 실패`를 따르며, 별도의 오류 안내는 제공하지 않는다. 보이는 항목이 하나도 없을 때의 표시는 [목록 빈 상태 스펙](./list-empty-state.md)의 `빈 상태 판정 기준`을 따른다.

홈 화면에 진입하는 것만으로는 서버에서 항목을 다시 가져오지 않는다. 서버와 맞추는 조회는 사용자가 목록을 당겨 새로고침했을 때와 [데이터 동기화 앱 스펙](./data-sync.md)의 `동기화 계기`에서만 일어난다.
