# SettingPlaylist 화면 스펙

이 문서는 사용자가 설정 화면의 `플레이리스트` 항목에서 진입하는 SettingPlaylist 화면의 내용과 행동을 다룬다. 기기에 보관하는 설정 화면의 공통 행동과 저장 영역은 [기기 설정 화면 공통 스펙](./device-setting.md)을 따르고, 이 문서에는 이 설정에만 해당하는 내용을 둔다. 설정 항목의 표시와 선택은 [SettingHome 화면 스펙](./setting-home.md)에서, 설정 목록과 함께 사용할 때의 선택·뒤로가기 정책은 [Setting 목록·상세 배치 스펙](./setting-list-detail.md)에서, 세부 화면에서의 공통 내비게이션 노출 규칙은 [TopLevelNavigation 스펙](./top-level-navigation.md)에서 다룬다. 프록시가 제공되는 환경, 주소의 형태와 포트, 프록시의 상태는 [곡 다운로드 프록시 스펙](./music-download-proxy.md)에서, 저장한 주소로 곡을 내려받는 흐름은 [곡 다운로드 스펙](./music-download.md)에서 다룬다.

디자인: [SettingPlaylist 화면 디자인](../../design/setting-playlist.md)

이 화면은 플랫폼에 따라 하는 일이 다르다. 데스크톱 앱에서는 이 기기가 제공하는 프록시 주소를 확인하는 화면이고, Android와 iOS에서는 내려받기에 쓸 프록시 주소를 입력해 기기에 저장하는 화면이다. 저장한 주소로 실제로 곡을 내려받는 것은 [곡 다운로드 스펙](./music-download.md)에서 다룬다.

## feature

### 진입과 이동

사용자는 설정 화면의 `플레이리스트` 항목을 선택해 SettingPlaylist 화면으로 이동한다.

표시 관계는 [기기 설정 화면 공통 스펙](./device-setting.md)의 `표시 관계`를 따른다.

이 화면은 [곡 다운로드 스펙](./music-download.md)이 다운로드를 제공하는 플랫폼에서만 진입할 수 있다. 웹에서는 SettingHome이 `플레이리스트` 항목을 제공하지 않으므로 이 화면으로 이동하는 경로가 없다.

### 프록시 주소 확인 (데스크톱 앱)

데스크톱 앱에서 사용자는 이 기기가 제공하는 프록시 주소를 확인한다. 이 기기가 여러 네트워크에 연결되어 있으면 주소 후보를 모두 확인하며, 어느 후보가 다른 기기에 닿는지는 사용자가 다른 기기에서 시험해 고른다. 후보의 기준은 [곡 다운로드 프록시 스펙](./music-download-proxy.md)의 `프록시 주소`를 따른다.

사용자는 각 주소를 그대로 옮겨 적을 수 있도록 확인한다. 주소를 바꾸거나 입력하는 수단은 두지 않는다.

프록시 상태를 확인하기 전에는 주소와 안내를 표시하지 않으며 별도 로딩 상태로 전환하지 않는다.

프록시가 제공 중이지만 주소 후보가 하나도 없으면 다른 기기가 닿을 주소가 없음을 알린다. 프록시를 제공하지 못하는 상태면 프록시를 시작하지 못했음을 알리고, 사용자가 앱을 다시 실행해야 함을 함께 알린다. 두 상태 모두 화면에서 다시 시도하는 수단은 두지 않는다. 프록시가 스스로 다시 시도하지 않는 것은 [곡 다운로드 프록시 스펙](./music-download-proxy.md)의 `프록시 상태`를 따른다.

화면에 표시하는 주소 후보와 상태는 앱을 실행할 때 프록시를 시작하며 한 번 정한 것이다. 화면을 보고 있는 동안 네트워크가 바뀌어도 스스로 갱신하지 않고, 화면을 떠났다 다시 들어와도 새로 확인하지 않으며, 당겨서 새로고침하는 수단도 두지 않는다. 앱이 실행되는 동안 기기가 다른 네트워크로 옮겨 가거나 새 네트워크에 연결되었으면 사용자는 앱을 다시 실행해 새 주소 후보를 확인한다. 주소의 포트는 앱을 실행할 때마다 달라질 수 있으므로([곡 다운로드 프록시 스펙](./music-download-proxy.md)의 `프록시 주소`), 다른 기기에서 연결할 수 없을 때 사용자는 이 화면에서 지금 주소를 다시 확인한다.

### 프록시 주소 입력 (Android, iOS)

Android와 iOS에서 이 화면은 [기기 설정 화면 공통 스펙](./device-setting.md)의 `입력한 뒤 저장하는 설정`을 따른다. 화면에 진입하면 저장해 둔 프록시 주소가 입력된 상태로 시작하고, 한 번도 저장하지 않았으면 비어 있는 상태로 시작한다.

저장된 주소를 확인하기 전이거나 읽지 못했을 때는 [기기 설정 화면 공통 스펙](./device-setting.md)의 `저장된 값을 확인하기 전`에 따라 주소를 입력하는 기능과 저장 기능을 제공하지 않는다.

사용자는 프록시 주소를 한 줄로 입력하거나 바꿀 수 있다.

### 설정 저장 (Android, iOS)

사용자는 입력한 프록시 주소를 저장할 수 있다. 저장할 수 있는 때, 저장 중과 저장 결과의 피드백은 [기기 설정 화면 공통 스펙](./device-setting.md)의 `입력한 뒤 저장하는 설정`을 따른다.

### 뒤로가기

뒤로가기 결과와 Android·iOS에서 저장하지 않은 입력의 처리는 [기기 설정 화면 공통 스펙](./device-setting.md)의 `뒤로가기`를 따른다.

### 입력 상태 유지 (Android, iOS)

입력 중이던 주소의 유지는 [기기 설정 화면 공통 스펙](./device-setting.md)의 `입력한 뒤 저장하는 설정`을 따른다.

## domain

### 다운로드 프록시 설정

다운로드 프록시 설정은 Android와 iOS에서 곡을 내려받을 때 영상을 요청할 프록시의 주소다. 값은 사용자가 데스크톱 앱의 SettingPlaylist 화면에서 확인해 옮겨 적은 주소 한 줄이다.

사용자가 한 번도 저장하지 않았으면 비어 있다. 앱은 기본값을 제시하지 않으며, 같은 네트워크의 프록시를 스스로 찾지 않는다.

데스크톱 앱은 자기 곡을 프록시 없이 직접 받으므로 이 설정을 갖지 않는다.

### 저장 가능 상태

[기기 설정 화면 공통 스펙](./device-setting.md)의 `저장 가능 상태`를 따른다. 비교하는 값은 주소 하나이며, 한 번도 저장하지 않았으면 비어 있는 주소와 비교한다.

### 저장 성립 조건

저장 동작을 제공하는 상태에서 주소는 비어 있어도 된다. 비어 있는 주소를 저장하는 것은 저장해 둔 주소를 지우는 것과 같다.

주소가 프록시 주소의 형태를 갖추었는지, 그 주소의 프록시에 실제로 연결할 수 있는지는 저장 시점에 확인하지 않는다. 연결할 수 없는 주소로 다운로드를 실행했을 때의 결과는 [곡 다운로드 스펙](./music-download.md)의 `내려받기 준비`가 정한다.

### 편집 상태와 저장된 설정

[기기 설정 화면 공통 스펙](./device-setting.md)의 `편집 상태와 저장된 값`을 따른다.

### 유지와 초기화 기준

[기기 설정 화면 공통 스펙](./device-setting.md)의 `유지와 초기화 기준`을 따른다.

## data

### 저장 시점과 유지

사용자가 저장을 실행하면 그 시점의 주소가 기기에 저장된다. 사용자가 한 번도 저장하지 않았으면 저장된 값이 없고, 이때 주소는 비어 있는 것으로 다룬다. 저장된 값의 유지와 읽지 못했을 때의 구분은 [기기 설정 화면 공통 스펙](./device-setting.md)의 `저장 시점과 유지`를 따른다.

### 기기별 보관

다운로드 프록시 설정은 [기기 설정 화면 공통 스펙](./device-setting.md)의 `기기별 보관`을 따른다. 프록시 주소는 그 기기가 놓인 네트워크에 따라 다르기 때문이다.

### 환경별 저장 영역

설정을 저장하는 Android와 iOS는 [기기 설정 화면 공통 스펙](./device-setting.md)의 `환경별 저장 영역`이 정한 각 환경의 저장 영역을 쓴다. 데스크톱 앱은 이 설정을 저장하지 않는다.
