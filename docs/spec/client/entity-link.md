# 항목 연결 앱 스펙

이 문서는 두 항목을 잇는 연결 가운데 앱이 기기에 연결을 저장하는 규칙을 다룬다. 연결이 공통으로 가지는 성질, 상태와 시각, 조회에 포함되는 기준, 동기화 계약은 [항목 연결 공통 스펙](../common/entity-link.md)을 따르고, 연결 종류별 규칙은 그 문서가 나열한 각 연결 스펙을 따른다.

[항목 연결 공통 스펙](../common/entity-link.md)을 따르는 일곱 연결 종류가 모두 이 문서의 저장 규칙을 따른다. 이 문서를 참조하는 앱 스펙은 다음과 같다.

- [메모 태그 앱 스펙](./memo-tag.md)
- [메모 장소 앱 스펙](./memo-place.md)
- [메모 웹 앱 스펙](./memo-web.md)
- [메모 연락처 앱 스펙](./memo-contact.md)
- [태그 연결 앱 스펙](./tag-link.md)
- [항목 태그 연결 앱 스펙](./entity-tag.md)
- [항목 추가 화면 공통 스펙](./entity-add.md)
- [항목 상세 화면 공통 스펙](./entity-detail.md)
- [MemoDetail 화면 스펙](./memo-detail.md)
- [TagDetail 웹 탭 스펙](./tag-detail-web.md)
- [TagDetail 장소 탭 스펙](./tag-detail-place.md)

사용자가 연결을 만들고 해제하는 조작은 각 입력 컴포넌트 스펙과 화면 스펙이 소유하므로 이 문서에는 `feature`와 `domain` 영역을 두지 않는다.

## data

### 연결의 저장

연결은 양쪽 항목과 별개의 항목으로 기기에 저장된다. 이미 같은 연결이 있으면 덮어쓰고, 없으면 새로 추가한다.

항목을 추가하면서 연결을 함께 만들면 새 항목, 그 항목과 현재 사용자 계정의 연결, 그리고 함께 만드는 연결이 기기의 하나의 저장 작업으로 반영된다. 이 저장은 전부 반영되거나 전혀 반영되지 않는다. 항목만 저장되고 연결이 빠지거나, 연결만 저장되고 항목이 없는 기기 상태는 남지 않는다.

이미 저장된 항목의 연결을 하나씩 만들거나 해제할 때는 그 연결과 계정의 업로드 대기 여부만 함께 반영하고, 같은 항목의 다른 연결은 바꾸지 않는다. 업로드 대기의 기준은 [데이터 동기화 앱 스펙](./data-sync.md)의 `동기화 상태`를 따른다.

한 연결과 다른 항목을 함께 바꿔야 하는 경우에도 기기의 하나의 저장 작업으로 함께 반영해 한쪽만 반영된 기기 상태가 남지 않게 한다.
