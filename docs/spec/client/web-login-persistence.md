# 앱 안 웹 로그인 유지 스펙

이 문서는 사용자가 앱 안 웹 표시 수단에서 사이트에 로그인한 상태가 앱을 종료하고 다시 시작해도 이어지는 규칙을 다룬다. 웹 표시 수단으로 웹 페이지를 보는 화면의 행동은 [WebDetail 화면 스펙](./web-detail.md)에서, 앱이 활성 상태인지의 판정은 [앱 활성 상태 스펙](./app-active-state.md)에서, 기능 실패를 기록하는 정책은 [기능 실패 로깅 스펙](./usecase-failure-logging.md)에서 다룬다.

이번 범위는 사이트가 웹 표시 수단에 남긴 로그인 정보를 앱이 언제 보관하고 언제 되돌리는지, 플랫폼마다 무엇이 유지되는지까지다. 사용자가 로그인 정보를 확인하거나 지우는 수단은 이번 범위에서 다루지 않는다. 사용자가 직접 하는 행동이 없으므로 `feature` 영역은 생략한다.

## domain

### 로그인 정보

로그인 정보는 사이트가 로그인 상태를 유지하려고 웹 표시 수단에 남긴 쿠키와 사이트 저장 공간이다. 쿠키는 만료 시각이 있는 쿠키와, 만료 시각 없이 브라우저를 닫을 때까지만 쓰도록 만든 세션 쿠키로 나뉜다.

앱 안 웹 표시 수단의 로그인 정보는 화면마다 따로 있지 않고 앱 전체에 하나다. 한 화면에서 로그인한 사이트는 다른 화면의 웹 표시 수단에서도 로그인된 상태로 열린다.

로그인 정보는 Diary 계정과 무관하다. Diary에서 로그아웃하거나 다른 계정으로 바꿔도 지우지 않고 그대로 이어진다.

### 플랫폼별 유지 범위

앱을 종료하고 다시 시작했을 때 남는 로그인 정보는 다음과 같다.

| 플랫폼 | 만료 시각이 있는 쿠키 | 사이트 저장 공간 | 세션 쿠키 |
| --- | --- | --- | --- |
| iOS | 남는다 | 남는다 | 남는다 |
| 데스크톱 앱(macOS) | 남는다 | 남는다 | 남는다 |
| Android | 남는다 | 남는다 | 웹 표시 수단이 직접 연 페이지의 주소에 해당하는 것만 남는다 |
| 웹 | 브라우저가 정한다 | 브라우저가 정한다 | 브라우저가 정한다 |

만료 시각이 지난 쿠키는 어느 플랫폼에서도 남지 않는다.

세션 쿠키는 원래 앱을 종료하면 사라지지만, 이 앱은 사용자가 앱을 다시 시작해도 로그인 상태를 이어 가도록 세션 쿠키도 보관했다가 되돌린다. 사이트가 로그인 상태를 세션 쿠키로만 유지해도 앱을 다시 시작한 뒤 로그인된 상태로 열린다.

Android에서는 웹 표시 수단의 세션 쿠키를 주소 하나씩만 확인할 수 있다. 그래서 웹 표시 수단이 직접 연 페이지의 주소에 해당하는 세션 쿠키만 보관하고, 페이지 안에서 다른 주소로 보낸 요청이 남긴 세션 쿠키는 보관하지 못할 수 있다. 기기의 웹 표시 수단이 세션 쿠키를 확인하는 기능을 제공하지 않으면 Android에서는 세션 쿠키를 보관하지 않는다.

웹에서는 앱 안 웹 표시 수단이 브라우저 안에 다른 사이트를 끼워 넣는 방식이라 앱이 그 사이트의 로그인 정보를 다룰 수 없다. 무엇이 남는지는 사용자가 쓰는 브라우저가 정하며, 앱은 이를 보관하거나 되돌리지 않는다.

### 보관과 되돌리기 계기

| 계기 | 하는 일 |
| --- | --- |
| 앱이 활성 상태에서 벗어남 | 지금의 세션 쿠키를 보관하고, 웹 표시 수단의 로그인 정보를 기기에 바로 기록한다 |
| 앱이 종료됨 | 앱이 활성 상태에서 벗어날 때와 같다 |
| 앱을 시작함 | 보관해 둔 세션 쿠키를 웹 표시 수단에 되돌린다 |

활성 상태는 [앱 활성 상태 스펙](./app-active-state.md)의 `활성 상태`를 따른다. 활성 상태에서 벗어날 때마다 보관하므로, 앱이 화면 뒤에 있는 동안 시스템이 앱을 정리해도 마지막으로 벗어난 때의 로그인 정보가 이어진다.

되돌리는 동안 앱이 활성 상태에서 벗어나거나 종료되면 되돌리기가 끝난 뒤에 보관한다. 되돌리기 전에 보관하면 아직 되돌리지 않은 세션 쿠키가 빠진 채 이전에 보관해 둔 것을 덮어쓰기 때문이다.

보관을 기다리거나 보관하는 동안 다시 활성 상태에서 벗어나면 새로 보관하지 않고 진행 중인 보관 하나로 합친다. 진행 중인 보관이 끝난 뒤 다시 벗어나면 그때 다시 보관한다.

보관할 때는 이전에 보관해 둔 세션 쿠키를 모두 지금의 세션 쿠키로 바꾼다. 그 사이 사이트에서 로그아웃해 사라진 세션 쿠키는 다음 실행에 되돌리지 않는다.

되돌릴 때 웹 표시 수단에 이름, 사이트, 경로가 같은 쿠키가 이미 있으면 보관해 둔 값으로 바꾼다.

### 되돌리는 동안

앱을 시작하면 보관해 둔 세션 쿠키가 있는지 확인한 뒤 되돌린다. 확인과 되돌리기가 끝나기 전에는 웹 표시 수단이 주소를 열지 않는다. 되돌리기 전에 연 페이지는 사이트가 로그인되지 않은 상태로 보여 사용자가 로그아웃된 것으로 오해하기 때문이다. 이 동안 화면이 무엇을 보여 주는지는 [WebDetail 화면 스펙](./web-detail.md)의 `로그인 정보 되돌리기`를 따른다.

되돌리기가 성공하든 실패하든 끝나면 웹 표시 수단이 주소를 연다. 보관해 둔 세션 쿠키가 없으면 확인하는 대로 끝나고 웹 표시 수단에 아무것도 넣지 않는다. 웹처럼 세션 쿠키를 보관하지 않는 플랫폼에서도 보관해 둔 것이 없으므로 같다.

### 실패

보관하거나 되돌리지 못해도 사용자에게 알리지 않고 다시 시도하지 않는다. 웹 표시 수단은 남아 있는 로그인 정보로 그대로 쓸 수 있고, 다음 계기에 다시 보관하거나 되돌린다. 보관에 실패하면 이전에 보관해 둔 세션 쿠키를 그대로 둔다.

실패는 [기능 실패 로깅 스펙](./usecase-failure-logging.md)에 따라 기록한다.

## data

### 보관하는 정보

세션 쿠키마다 이름, 값, 사이트, 경로, 보안 연결 전용 여부, 스크립트 접근 금지 여부, 사이트 간 전송 정책을 보관한다. Android에서는 세션 쿠키를 확인할 주소를 찾을 수 있도록, 웹 표시 수단이 직접 연 페이지의 주소 가운데 보관할 세션 쿠키가 있는 사이트의 주소도 함께 보관한다.

만료 시각이 있는 쿠키와 사이트 저장 공간은 웹 표시 수단이 기기에 직접 기록하므로 앱이 따로 보관하지 않는다.

### 저장 위치

보관한 세션 쿠키는 이 기기의 앱 저장 영역에 둔다. 서버로 보내지 않고 [데이터 동기화 스펙](../common/data-sync.md)의 동기화 대상도 아니므로, 한 기기에서 로그인한 사이트가 다른 기기에서 로그인된 상태로 열리지 않는다.

앱을 지우거나 앱 데이터를 지우면 보관한 세션 쿠키와 웹 표시 수단의 로그인 정보가 함께 사라진다.
