# 완료 목록 공통 스펙

이 문서는 완료된 항목만 모아 보여 주는 목록 화면들이 공통으로 보장하는 진입, 노출 기준, 빈 상태, 정렬과 실행 경계를 다룬다. 어떤 항목을 모으는지, 목록에서 어떤 동작을 제공하는지, 어느 화면에서 진입하는지는 화면마다 다르므로 각 화면 스펙에서 다룬다.

이 문서를 따르는 화면 스펙은 다음과 같다.

- [MemoFinishedList 화면 스펙](./memo-finished-list.md)
- [TagFinishedList 화면 스펙](./tag-finished-list.md)
- [TagMemoFinishedList 화면 스펙](./tag-memo-finished-list.md)

이 문서에서 `짝이 되는 목록`은 같은 대상을 완료되지 않은 상태로 보여 주는 목록을 가리키고, `대상 항목`은 그 목록이 모으는 메모 또는 태그 하나를 가리킨다.

디자인: [완료 목록 공통 디자인](../../design/finished-list.md)

목록을 당겨 새로고침하는 행동과 동기화 진행 표시는 [새로고침 스펙](./sync-refresh.md)을, 아직 준비되지 않은 자리의 처리는 [페이지 조회 목록의 자리 표시 스펙](./paged-list-placeholder.md)을 따른다.

## feature

### 진입과 이동

사용자는 짝이 되는 목록에서 완료된 항목 확인을 선택해 완료 목록 화면으로 이동한다.

완료된 항목이 하나도 없어도 사용자는 이 화면으로 이동할 수 있다.

완료 목록 화면에서는 주요 목적지의 공통 내비게이션을 제공하지 않는다.

사용자가 뒤로가면 진입하기 전의 짝이 되는 목록으로 돌아간다.

### 내용 갱신

목록은 항목을 한 번에 모두 불러오지 않고, 사용자가 목록 끝에 다가가면 이어서 더 보여 준다. 이어서 불러오는 기준은 [페이지 조회 목록의 자리 표시 스펙](./paged-list-placeholder.md)의 `페이지 조회`를 따른다.

이 기기에서 항목을 완료하거나 다시 시작하거나 삭제하거나 고치면, 그 일을 어느 화면에서 했든 목록은 새로고침하지 않아도 바로 바뀐 내용을 보여 준다. 다른 기기에서 바꾼 내용은 이 기기가 서버와 맞춘 뒤 같은 기준으로 나타난다. 이때 보던 자리를 지키는 기준은 [페이지 조회 목록의 자리 표시 스펙](./paged-list-placeholder.md)의 `data > 자동 갱신`을 따른다.

### 새로고침

사용자는 목록을 아래로 당겨 새로고침할 수 있다. 새로고침은 서버와 한 번 맞추는 것이며, 진행 표시와 진행 중에 다시 당겼을 때의 결과는 [새로고침 스펙](./sync-refresh.md)을 따른다.

이 화면에 들어오거나 다른 화면에서 돌아오는 것만으로는 새로고침하지 않는다.

### 불러오기 실패

목록을 불러오지 못해도 별도 오류 안내나 다시 시도 동작은 제공하지 않는다. 이미 보이는 항목은 그대로 두고, 보이는 항목이 하나도 없으면 `빈 상태`의 안내를 보여 준다.

### 빈 상태

완료된 대상 항목이 하나도 없으면 목록 자리에 완료한 항목이 아직 없음을 알린다. 판정 시점, 빈 상태에서 할 수 있는 행동, 목록과의 전환은 [목록 빈 상태 스펙](./list-empty-state.md)을 따른다.

빈 상태에서도 사용자는 목록을 당겨 새로고침하고 뒤로가기로 짝이 되는 목록으로 돌아갈 수 있다.

빈 상태에 쓰는 문구는 화면마다 다르므로 각 화면 스펙에서 정한다.

### 추가 미제공

완료 목록 화면에서는 새 항목을 추가할 수 없다. 새로 추가하는 항목은 완료되지 않은 상태로 만들어져 이 목록의 노출 기준을 만족하지 않기 때문이다.

같은 이유로 빈 상태에서도 항목 추가를 권하지 않는다. 항목 추가는 짝이 되는 목록에서만 제공한다.

### 상세 확인

사용자가 항목을 선택하면 그 항목의 상세 화면으로 이동한다. 상세 화면에서는 주요 목적지의 공통 내비게이션을 제공하지 않는다.

상세 화면에서 뒤로가면 완료 목록 화면으로 돌아가며, 목록에서 보던 자리는 상세로 떠나기 전 그대로다.

사용자가 상세 화면에서 항목을 다시 시작하거나 삭제한 뒤 돌아오면, 그 항목은 이 목록의 노출 기준에 따라 목록에서 사라진다.

### 정렬 선택

사용자는 목록 위에서 현재 정렬을 확인하고 다른 기준으로 바꿀 수 있다. 고를 수 있는 기준과 정렬 선택·반영·유지의 결과는 [목록 정렬 스펙](./list-sort.md)을 따른다.

## domain

### 노출 기준

현재 사용자 계정과 연결된 대상 항목 중 완료되었고 삭제되지 않은 항목만 노출한다.

이 기준은 짝이 되는 목록의 노출 기준과 완료 여부만 반대이며, 삭제된 항목을 감추는 규칙은 같다. 따라서 완료되었더라도 삭제된 항목은 이 목록에도 나타나지 않고, 한 항목이 두 목록에 함께 나타나지 않는다.

짝이 되는 목록이 태그 연결이나 필터로 범위를 좁히는 경우, 그 조건을 이 목록에도 적용하는지는 각 화면 스펙에서 정한다.

### 정렬

정렬은 짝이 되는 목록의 정렬 기준을 따른다.

완료한 시점은 정렬에 사용하지 않는다. 따라서 나중에 완료한 항목이 목록에서 먼저 오지 않고, 짝이 되는 목록과 같은 기준으로 자리가 정해진다.

위 순서는 사용자가 정렬을 고르지 않았을 때의 순서이며, 사용자가 고를 수 있는 다른 기준과 그 순서는 [목록 정렬 스펙](./list-sort.md)이 정한다.

### 대상 항목

목록에는 현재 사용자 계정과 연결된 항목만 표시되며, 목록에서 실행하는 동작도 현재 사용자 계정과 연결된 항목에만 적용된다.

### 실행 경계

이 화면은 사용자가 이어서 작성하는 내용을 가지지 않으므로 화면을 벗어나면 유지할 진행 상태가 없다.

화면이 회전하거나 재생성되거나 앱이 백그라운드에 다녀오면 저장된 내용을 기준으로 목록을 다시 표시하며, 정렬 선택과 보던 자리는 그대로다. 앱이 백그라운드에 있는 동안 시스템이 앱을 정리했다가 다시 만들면 정렬은 [목록 정렬 스펙](./list-sort.md)의 `정렬 선택 유지`에 따라 처음 정렬로 돌아가고, 목록 위치는 [페이지 조회 목록의 자리 표시 스펙](./paged-list-placeholder.md)의 `보던 자리 유지`에 따라 떠나기 전 위치로 다시 보인다. 짝이 되는 목록으로 돌아갔다가 다시 진입하면 정렬은 [목록 정렬 스펙](./list-sort.md)의 `정렬 선택 유지`에 따라 처음 정렬로 돌아가고 목록은 맨 위부터 보인다. 앱을 종료하고 다시 실행하면 사용자는 짝이 되는 목록에서 다시 진입한다.

## data

### 목록 조회

목록은 기기에 저장된 항목 중 `domain`의 노출 기준을 만족하는 항목만 `domain`의 정렬 순서로 나누어 불러와 표시한다. 페이지를 이어서 조회하는 기준은 [페이지 조회 목록의 자리 표시 스펙](./paged-list-placeholder.md)의 `페이지 조회`를 따른다.

항목의 완료 여부나 삭제 여부가 바뀌면 목록을 노출 기준과 정렬 기준에 따라 자동으로 갱신한다. 정렬에 쓰는 값이 바뀔 때도 같다.

조회에 실패했을 때의 결과는 `불러오기 실패`를 따른다.
