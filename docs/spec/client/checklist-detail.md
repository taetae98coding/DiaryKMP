# ChecklistDetail 화면 스펙

이 문서는 사용자가 선택한 체크리스트에서 체크 항목을 체크하고 해제하고, 항목을 넣고 빼고, 모든 체크를 한 번에 해제하고, 항목의 순서를 고르고, 제목과 설명을 수정하고, 그 체크리스트를 삭제하는 ChecklistDetail 화면의 내용과 행동을 다룬다. ChecklistDetail로 진입하는 흐름과 삭제한 체크리스트가 목록에서 사라지는 것은 [ChecklistHome 화면 스펙](./checklist-home.md)에서, 체크리스트 목록과 상세를 함께 사용하는 배치는 [Checklist 목록·상세 배치 스펙](./checklist-list-detail.md)에서, 체크리스트와 체크 항목이 갖는 정보와 추가순은 [ChecklistAdd 화면 스펙](./checklist-add.md)에서, 정렬을 고르고 바꾸는 행동의 공통 규칙은 [목록 정렬 스펙](./list-sort.md)에서, 대상 체크리스트를 정하는 계정 기준은 [계정 조회 스펙](./account.md)에서, 체크리스트와 체크 항목을 서버와 맞추는 규칙은 [데이터 동기화 스펙](../common/data-sync.md)에서 다룬다. 제목 입력 자체의 동작은 [제목 입력 스펙](./title-input.md)을, 설명 입력 자체의 동작은 [설명 입력 컴포넌트 스펙](./description-input.md)을 따른다.

이번 범위는 ChecklistHome의 체크리스트 목록에서 체크리스트를 선택해 상세로 이동하고, 체크 항목을 확인하고 체크하고 해제하고, 항목을 넣고 빼고, 리셋으로 모든 체크를 해제하고, 항목 정렬을 고르고, 제목과 설명을 수정하고, 체크리스트를 삭제하는 것까지다. 이미 넣은 체크 항목의 내용을 고치는 것은 이번 범위에 포함하지 않는다. 체크리스트는 태그와 연결되지 않으므로 이 화면은 태그 입력을 제공하지 않고, 메모 탭처럼 연결된 항목을 보여 주는 탭도 두지 않는다.

목록과 상세를 함께 사용하는 동안에는 체크리스트 상세가 목록과 함께 놓이며, 그 배치는 [Checklist 목록·상세 배치 스펙](./checklist-list-detail.md)을 따른다.

진입할 때의 입력 초점, 내용 수정의 반영과 성공 결과, 요청 제한과 저장 계약은 [항목 상세 화면 공통 스펙](./entity-detail.md)을 따른다. 태그 입력을 제공하지 않으므로 그 문서의 태그 입력 관련 규칙은 적용하지 않는다.

디자인: [ChecklistDetail 화면 디자인](../../design/checklist-detail.md)

## feature

### 진입과 내용

사용자는 ChecklistHome 화면의 체크리스트 목록에서 체크리스트를 선택해 그 체크리스트의 ChecklistDetail 화면으로 이동한다. 목록과 상세를 함께 사용할 수 있는 환경에서는 이동하지 않고 목록과 함께 표시된 상세 영역에서 같은 내용을 사용하며, 그 기준은 [Checklist 목록·상세 배치 스펙](./checklist-list-detail.md)을 따른다.

체크리스트 조회에 성공하면 사용자는 저장된 제목과 설명을 확인하고 수정할 수 있고, 체크 항목을 확인하고 체크하고 관리할 수 있으며, 그 체크리스트를 삭제할 수 있다. 화면 제목에는 대상 체크리스트의 최신 저장 제목을 표시한다.

### 화면 내용

화면에는 화면 제목, 뒤로가기, 리셋, 삭제, 제목 입력, 설명 입력, 수정 반영 동작, 정렬 선택, 체크 항목 목록, 각 체크 항목의 항목 빼기, 항목 입력과 항목 넣기만 둔다. 수정 반영 동작은 `내용 수정`이 정한 조건에서만 둔다.

### 조회 상태

처음에는 체크리스트 조회 중 상태를 제공하며 입력, 체크, 항목 넣기와 빼기, 리셋, 정렬 선택, 내용 수정과 삭제를 실행할 수 없다.

조회에 성공하면 내용 표시 상태로 바뀐다. 체크리스트를 조회할 수 없거나 조회에 실패하면 조회 중 상태를 유지하며, 별도의 오류 안내는 제공하지 않는다.

### 체크 항목 목록

사용자는 대상 체크리스트의 체크 항목을 모두 한 목록으로 확인한다. 각 항목에서 내용과 체크 여부를 확인한다. 어떤 항목을 보여 주는지는 `domain > 목록에 노출하는 체크 항목`을, 순서는 `정렬`을 따른다.

체크 항목 목록은 나누어 불러오지 않고 한 번에 모두 보여 준다.

체크 항목 목록 불러오기가 끝났고 노출할 체크 항목이 하나도 없으면 목록 자리에 아직 체크 항목이 없으며 항목 입력으로 넣을 수 있음을 알린다. 불러오는 동안에는 이 안내를 보여 주지 않는다. 빈 상태에서도 사용자는 항목 넣기, 제목·설명 수정과 삭제를 그대로 실행할 수 있다.

### 체크와 체크 해제

사용자는 체크 항목을 선택해 체크되지 않은 항목은 체크하고, 체크된 항목은 체크를 해제한다. 별도의 반영 동작 없이 선택하는 즉시 저장되며, 확인을 되묻지 않는다.

체크 상태가 바뀌면 그 항목은 지금 선택된 정렬 기준에 맞는 자리로 옮겨진다. 추가순에서는 자리가 바뀌지 않고, 체크 안 된 항목 우선에서는 체크한 항목이 체크된 항목 묶음으로, 체크를 해제한 항목이 체크 안 된 항목 묶음으로 옮겨진다.

체크 변경을 저장하지 못하면 별도 안내 없이 그 항목은 저장된 체크 상태를 그대로 보여 준다. 사용자는 다시 선택할 수 있다.

### 항목 넣기

사용자는 항목 입력에 새 체크 항목의 내용을 한 줄로 적고 항목 넣기를 실행해 대상 체크리스트에 체크 항목을 추가한다. 물리 키보드나 화면 키보드에서 입력을 마치는 키를 눌러도 항목 넣기와 같은 결과다. 항목 넣기는 별도의 반영 동작 없이 즉시 저장되며, 제목과 설명의 수정 반영과는 무관하다.

항목 입력이 비어 있거나 공백만 있으면 항목 넣기를 제공하지 않으며, 입력을 마치는 키를 눌러도 항목을 넣지 않는다. 같은 내용의 항목이 이미 있어도 새 항목으로 넣는다.

항목 넣기를 처리하는 동안에는 진행 상태를 표시한다. 처리하는 동안에도 사용자는 항목 입력을 고칠 수 있고 화면의 다른 동작을 그대로 실행할 수 있으며, 다시 실행한 항목 넣기는 `domain > 요청 제한`에 따라 처리하지 않는다.

항목을 넣으면 새 항목이 체크되지 않은 상태로 지금 선택된 정렬 기준에 맞는 자리에 나타나고, 항목 입력이 비워지며 입력 초점은 항목 입력에 남는다.

항목 넣기를 저장하지 못하면 항목을 추가하지 않고 항목 입력의 내용을 그대로 두며, 별도 안내는 제공하지 않는다. 사용자는 같은 내용으로 다시 넣을 수 있다.

### 항목 빼기

사용자는 체크 항목을 하나씩 체크리스트에서 뺄 수 있다. 별도의 반영 동작 없이 즉시 저장되며, 빼기 전에 확인을 되묻지 않고 실행 취소도 제공하지 않는다.

뺀 항목은 목록에서 사라지고 남은 항목의 순서는 지금 선택된 정렬 기준을 그대로 따른다.

항목 빼기를 저장하지 못하면 별도 안내 없이 그 항목은 목록에 그대로 남는다. 사용자는 다시 뺄 수 있다.

### 리셋

사용자는 리셋을 실행해 대상 체크리스트의 모든 체크를 한 번에 해제할 수 있다. 리셋은 노출하는 체크 항목 중 체크된 항목이 하나라도 있을 때만 실행할 수 있다.

리셋을 선택하면 모든 체크를 해제할지 되묻는다. 사용자가 해제를 확정하면 리셋을 실행하고, 취소하거나 확인을 닫으면 아무것도 바꾸지 않는다. 되묻는 동안 다른 경로의 변경으로 체크된 항목이 모두 사라져도 확인은 그대로 열려 있으며, 이때 해제를 확정하면 `domain > 리셋`에 따라 바뀌는 항목이 없다.

리셋을 처리하는 동안에는 진행 상태를 표시한다. 리셋에 성공하면 모든 항목이 체크되지 않은 상태로 보이고, 지금 선택된 정렬 기준에 맞는 자리로 옮겨진다. 넣어 둔 항목, 항목의 내용과 입력 중이던 제목, 설명, 항목 입력은 바뀌지 않는다.

리셋을 저장하지 못하면 별도 안내 없이 진행 상태만 해제하고 항목은 저장된 체크 상태를 그대로 보여 준다. 사용자는 리셋을 다시 실행할 수 있다.

### 정렬

사용자는 체크 항목 목록의 정렬을 추가순과 체크 안 된 항목 우선 중에서 고를 수 있다. 처음 정렬은 추가순이다. 정렬을 고르고 바꾸는 행동, 바꾼 결과, 선택 유지와 항목이 없을 때의 정렬 선택은 [목록 정렬 스펙](./list-sort.md)을 따른다. 각 정렬의 순서는 `domain > 체크 항목 정렬`을 따른다.

### 내용 수정

사용자가 입력한 제목 또는 설명이 저장된 내용과 하나라도 다를 때만 수정 반영 동작을 제공한다. 비교 기준은 `domain > 수정 동작의 제공 기준`을 따른다. 수정 시점에 제목이 비어 있거나 공백만 있으면 저장된 기존 제목을 유지한 채 설명만 반영한다.

수정에 성공하면 화면, 입력 내용과 체크 항목 목록을 유지하고 성공 피드백을 제공한다. 화면 제목은 새로 저장된 제목으로 갱신된다. 수정에 실패했을 때의 결과는 [항목 상세 화면 공통 스펙](./entity-detail.md)의 `내용 수정`을 따른다.

체크, 항목 넣기와 빼기, 리셋은 이미 저장된 값을 바꾸는 동작이므로 수정 반영 동작의 제공 여부에 영향을 주지 않는다.

### 삭제

사용자는 대상 체크리스트를 삭제할 수 있다. 실행하기 전에 확인을 되묻지 않는다.

삭제를 처리하는 동안에는 진행 상태를 표시한다.

삭제에 성공하면 뒤로가기와 같은 결과로 ChecklistDetail 화면에서 빠져나가 ChecklistHome 화면으로 돌아가고, 삭제한 체크리스트는 목록에서 사라진다. 목록과 상세 영역을 함께 표시하는 상태에서는 상세 영역이 선택한 체크리스트가 없을 때의 상태로 되돌아가며, 그 상태는 [Checklist 목록·상세 배치 스펙](./checklist-list-detail.md)의 `상세 영역의 구성`을 따른다. 이 화면에서 삭제한 체크리스트에는 ChecklistHome의 삭제 안내와 실행 취소를 제공하지 않는다.

삭제한 체크리스트에서 수정 중이던 내용은 유지하지 않는다.

삭제에 실패하면 화면에 머무르며 진행 상태만 해제한다. 사용자는 삭제를 다시 실행할 수 있다.

### 외부 변경

화면이 열려 있는 동안 같은 체크리스트의 저장 내용이 다른 경로에서 바뀌면 화면 제목을 최신 저장 제목으로 갱신한다. 입력 중인 제목, 설명과 항목 입력은 덮어쓰지 않는다.

체크 항목 목록은 저장된 상태를 그대로 보여 주므로, 다른 기기에서 넣거나 빼거나 체크한 항목이 서버에서 내려받아져 기기에 반영되면 사용자가 아무것도 하지 않아도 목록에 바로 나타난다.

다른 기기에서 삭제한 체크리스트가 서버에서 내려받아져 대상 체크리스트가 삭제 상태가 되어도 화면은 내용 표시 상태를 유지한다. 사용자는 입력 중이던 내용을 잃지 않고 체크, 항목 넣기와 빼기, 리셋, 수정과 삭제를 그대로 실행할 수 있으며, 화면에서 밀려나거나 조회 중 상태로 되돌아가지 않는다.

### 진행 상태 유지

화면 재생성과 백그라운드 복귀 뒤에도 입력 중이던 제목, 설명과 항목 입력, 고른 정렬, 리셋 확인이 열려 있었는지를 유지한다. 시스템이 앱을 메모리에서 정리한 뒤 화면을 복원하면 입력 중이던 제목, 설명과 항목 입력은 복원하고, 정렬은 [목록 정렬 스펙](./list-sort.md)의 `정렬 선택 유지`에 따라 처음 정렬로 되돌아가며, 리셋 확인은 닫힌 상태로 시작한다.

수정 결과 피드백은 화면 재생성이나 앱 재실행 뒤에 다시 표시하지 않는다.

체크, 항목 넣기와 빼기, 리셋, 수정이나 삭제를 처리하는 동안, 그리고 저장된 내용이 갱신되어 화면이 다시 그려질 때도 사용자가 보고 있던 화면 위치를 유지한다.

화면을 떠난 뒤 다시 들어오거나 앱을 종료한 뒤 새로 진입하면 수정 중이던 내용과 항목 입력을 복원하지 않고 저장된 내용과 처음 정렬로 다시 시작한다.

### 뒤로가기

사용자가 뒤로가면 ChecklistHome 화면으로 돌아간다. 반영하지 않은 제목과 설명의 수정, 항목 입력에 적어 두고 넣지 않은 내용은 저장되지 않는다.

목록과 상세 영역을 함께 표시하는 상태에서 뒤로가기를 실행하면 상세 영역은 선택한 체크리스트가 없을 때의 화면인 체크리스트 추가로 되돌아간다.

## domain

### 상세 대상과 내용 표시

상세 대상을 정하는 계정 기준은 [항목 상세 화면 공통 스펙](./entity-detail.md)의 `대상 조회`를 따른다.

삭제 여부는 상세 대상을 정하는 기준이 아니다. 삭제 상태인 체크리스트도 상세 대상으로 조회하며, 대상 체크리스트가 삭제 상태로 바뀌어도 화면은 내용 표시 상태를 유지한다. 이때의 화면 동작은 `외부 변경`을 따른다.

수정, 체크, 항목 넣기와 빼기, 리셋은 체크리스트의 삭제 여부를 바꾸지 않으므로, 삭제 상태가 된 체크리스트에서 이 동작을 실행해도 그 체크리스트는 삭제 상태로 남는다.

### 목록에 노출하는 체크 항목

체크 항목 목록에는 대상 체크리스트에 속하고 현재 사용자 계정과 연결되어 있으며 삭제되지 않은 체크 항목을 모두 노출한다. 체크된 항목과 체크되지 않은 항목을 모두 노출한다.

### 체크 항목 정렬

| 정렬 | 순서 |
| --- | --- |
| 추가순 | [ChecklistAdd 화면 스펙](./checklist-add.md)의 `체크 항목의 정보`가 정한 추가순 |
| 체크 안 된 항목 우선 | 체크되지 않은 항목을 앞 묶음에, 체크된 항목을 뒤 묶음에 놓고, 각 묶음 안은 추가순 |

정렬은 노출하는 항목의 집합을 바꾸지 않는다. 체크 안 된 항목 우선에서도 체크된 항목은 목록에서 사라지지 않고 뒤에 놓인다.

### 입력 내용 채우기

제목과 설명 입력은 대상 체크리스트를 처음 조회한 값으로 한 번만, 저장된 그대로 채운다. 같은 체크리스트의 저장 내용이 바뀌어도 다시 채우지 않는다. 항목 입력은 비어 있는 상태로 시작한다.

### 수정 성립 조건

체크리스트는 제목을 반드시 가져야 하므로 제목을 비우는 수정을 허용하지 않고 저장된 기존 제목을 사용한다. 제목을 비운 것은 기존 제목을 사용하는 것이므로 수정을 막지 않으며, 이때도 설명은 입력한 대로 반영한다.

### 수정되는 내용

수정은 대상 체크리스트의 제목과 설명을 바꾸고 체크리스트의 수정 시각을 수정 시점으로 기록한다. 제목과 설명은 앞뒤 공백을 포함해 입력한 그대로 기록한다. 설명이 비어 있으면 빈 설명으로 기록한다.

체크 항목, 삭제 여부, 생성 시각과 계정 연결은 내용 수정으로 바뀌지 않는다.

### 수정 동작의 제공 기준

입력한 제목 또는 설명이 저장된 내용과 하나라도 다르면 수정 동작을 제공한다. 글자는 공백과 줄바꿈까지 그대로 비교한다.

항목 입력, 고른 정렬과 체크 항목은 비교에 넣지 않는다.

제목을 비운 채 수정해 저장된 기존 제목이 유지되면, 비어 있는 제목 입력이 저장된 제목과 계속 다르므로 수정 동작도 계속 제공된다.

### 체크 변경

체크는 대상 체크 항목의 체크 여부를 체크로, 체크 해제는 체크하지 않음으로 바꾸고 그 항목의 수정 시각을 동작 시점으로 갱신한다. 항목의 내용과 삭제 여부, 체크리스트의 내용과 수정 시각은 바꾸지 않는다.

### 항목 넣기의 내용

새 체크 항목은 대상 체크리스트에 속하고, 내용은 항목 입력에 적은 그대로 기록하며, 체크되지 않고 삭제되지 않은 상태로 만든다. 생성 시각과 수정 시각은 넣은 시각으로 동일하게 기록하고, 현재 사용자 계정과 연결한다. 체크리스트의 내용과 수정 시각은 바꾸지 않는다.

### 항목 빼기

항목 빼기는 대상 체크 항목의 삭제 여부를 삭제로 바꾸고 그 항목의 수정 시각을 동작 시점으로 갱신한다. 항목의 내용과 체크 여부, 체크리스트의 내용과 수정 시각은 바꾸지 않는다.

### 리셋

리셋은 대상 체크리스트에 노출하는 체크 항목 중 체크된 항목을 모두 체크하지 않음으로 바꾸고, 바꾼 항목마다 수정 시각을 리셋 시점으로 갱신한다. 이미 체크되지 않은 항목과 삭제된 항목은 바꾸지 않으며 수정 시각도 그대로다. 체크리스트의 내용과 수정 시각은 바꾸지 않는다.

리셋은 체크 해제를 여러 항목에 함께 적용하는 것이며, 바꾼 항목들은 한 번에 함께 저장된다. 일부 항목만 체크가 해제된 상태는 남지 않는다.

### 삭제

삭제는 대상 체크리스트의 삭제 여부를 삭제로 바꾸고 수정 시각을 삭제 시점으로 갱신한다. 제목, 설명과 체크 항목은 바꾸지 않는다.

삭제한 체크리스트는 [ChecklistHome 화면 스펙](./checklist-home.md)의 `목록에 노출하는 체크리스트`에 따라 목록에서 사라진다.

### 요청 제한

[항목 상세 화면 공통 스펙](./entity-detail.md)의 `요청 제한`에서 같은 종류로 보는 것은 내용 수정, 삭제, 리셋, 항목 넣기이며, 네 종류는 서로를 제한하지 않는다.

체크 변경과 항목 빼기는 항목마다 따로 제한한다. 한 항목의 체크 변경을 처리하는 동안 그 항목의 체크 변경은 다시 처리하지 않고, 한 항목의 빼기를 처리하는 동안 그 항목의 빼기는 다시 처리하지 않는다. 서로 다른 항목의 체크 변경과 빼기는 이어서 실행할 수 있다.

정렬 선택은 앱의 데이터를 바꾸지 않으므로 제한 대상이 아니다.

## data

### 대상 체크리스트와 체크 항목 조회

상세에 표시할 체크리스트는 기기에 저장된 체크리스트 중 현재 사용자 계정과 연결된 대상 체크리스트 하나다. 이 조회는 삭제 여부를 가리지 않으므로 삭제 상태인 체크리스트도 조회된다.

체크 항목은 기기에 저장된 체크 항목 중 `domain > 목록에 노출하는 체크 항목`에 맞는 항목을 지금 선택된 정렬 순서로 한 번에 조회한다. 저장된 체크 항목이 바뀌면 조회 결과가 갱신되어 목록에 반영된다. 체크 항목을 조회하지 못하면 노출할 체크 항목이 없는 것과 같게 다루고 별도의 오류 안내는 제공하지 않는다.

ChecklistDetail에 진입하는 것만으로는 서버에서 체크리스트나 체크 항목을 다시 가져오지 않는다. 서버와 맞추는 조회는 [데이터 동기화 스펙](../common/data-sync.md)이 정한 계기에서만 일어난다.

### 변경의 저장

수정을 반영하면 대상 체크리스트의 제목, 설명과 수정 시각을 기기에 저장해 기존 값을 바꾼다. 삭제를 실행하면 대상 체크리스트의 삭제 여부와 수정 시각을 기기에 저장하며, 체크리스트 자체, 체크 항목과 계정 연결은 기기에서 지우지 않는다.

체크 변경과 항목 빼기는 대상 체크 항목의 체크 여부 또는 삭제 여부와 수정 시각을 기기에 저장한다. 뺀 항목과 그 계정 연결은 기기에서 지우지 않는다. 항목 넣기는 새 체크 항목과 그 항목의 현재 사용자 계정 연결을 한 번에 함께 기기에 저장한다. 리셋은 바꾼 모든 체크 항목의 체크 여부와 수정 시각을 한 번에 함께 기기에 저장한다.

모든 변경은 현재 사용자 계정과 연결된 대상 체크리스트와 그 체크리스트의 체크 항목에만 반영한다. 그런 체크리스트나 체크 항목이 기기에 없으면 아무것도 바꾸지 않는다.

저장에 실패한 변경은 성공으로 다루지 않으며 기기에 저장된 체크리스트와 체크 항목은 바뀌지 않는다.

### 결과의 표시

수정한 제목, 체크 변경, 넣고 뺀 항목과 리셋 결과는 [ChecklistHome 화면 스펙](./checklist-home.md)의 체크리스트 목록처럼 그 체크리스트를 조회하는 모든 곳에 반영된다. 제목이 바뀌면 같은 문서의 `목록 정렬`에 따라 목록에서 자리를 옮기고, 체크 항목이 바뀌면 목록의 진행 정도가 바뀐다.

### 변경의 동기화

수정과 삭제를 기기에 반영하면 그 체크리스트가, 체크 변경, 항목 넣기와 빼기, 리셋을 기기에 반영하면 바뀐 체크 항목이 업로드 대기로 기록되고 백그라운드 동기화가 시작된다. 삭제한 체크리스트와 뺀 체크 항목도 서버에서 제거하지 않고 삭제 상태로 반영한다.

모든 변경의 성공 여부는 기기에 저장한 결과로만 판단하며 서버 반영 결과를 기다리지 않는다. 업로드 단위, 충돌 기준과 실패 시 재시도는 [데이터 동기화 스펙](../common/data-sync.md)의 규칙을 따른다. 체크 항목의 충돌은 항목 하나 단위로 판정하므로, 같은 체크리스트의 서로 다른 항목을 여러 기기에서 바꾸면 각 변경이 모두 남는다. 내려받기로 서버의 더 늦은 수정 내용이 반영되면 그 결과는 `결과의 표시`와 같은 기준으로 나타나며, 화면에서 입력 중인 내용은 `외부 변경`에 따라 덮어쓰지 않는다.

로그인하지 않은 상태에서 바꾼 체크리스트와 체크 항목은 서버에 반영되지 않고 기기 안에만 유지된다.
