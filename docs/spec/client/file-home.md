# FileHome 화면 스펙

이 문서는 `더보기`의 `파일` 바로가기로 진입하는 FileHome 화면에서 사용자가 올린 파일을 확인하고 새 파일을 올리는 화면으로 이동하는 내용과 행동을 다룬다. 바로가기 항목의 표시와 선택은 [MoreHome 화면 스펙](./more-home.md)에서, 제목과 설명을 적고 파일을 골라 올리는 화면은 [FileAdd 화면 스펙](./file-add.md)에서, 올릴 수 있는 파일과 올리기의 진행, 목록을 서버에서 불러오는 규칙은 [파일 보관 스펙](./file-storage.md)에서, 올리는 동안과 끝난 뒤의 알림은 [파일 올리기 알림 스펙](./file-upload-notification.md)에서, 계정 상태를 결정하는 규칙은 [계정 조회 스펙](./account.md)에서, 세부 화면에서의 공통 내비게이션 노출과 뒤로가기는 [TopLevelNavigation 스펙](./top-level-navigation.md)에서 다룬다.

디자인: [FileHome 화면 디자인](../../design/file-home.md)

이번 범위는 올린 파일을 목록으로 확인하고, 파일을 올리는 FileAdd 화면으로 이동하는 것까지다. 목록의 파일을 선택해 열거나 내려받는 것, 파일의 제목, 설명이나 이름을 바꾸거나 지우는 것, 여러 파일을 한 번에 올리는 것, 진행 중인 올리기를 사용자가 취소하는 것은 이번 범위에서 다루지 않는다.

## feature

### 진입

사용자는 `더보기` 화면의 `파일` 바로가기를 선택해 FileHome 화면으로 이동한다. 파일 올리기 알림을 선택해 들어올 수도 있으며, 그 기준은 [파일 올리기 알림 스펙](./file-upload-notification.md)의 `알림에서 앱 열기`를 따른다. 화면 상단에는 `파일` 제목과 뒤로가기가 있다.

화면에서 보이는 내용은 `domain > 계정 상태에 따른 화면`에 따라 계정 상태마다 다르다.

### 게스트 상태

로그인하지 않은 상태에서는 파일 목록과 파일 추가를 제공하지 않고, 로그인하면 파일을 올리고 확인할 수 있다는 안내만 본문에 표시한다. 안내는 로그인 화면으로 이동하는 동작을 제공하지 않는다. 사용자는 `더보기` 화면으로 돌아가 로그인할 수 있다.

### 파일 목록

로그인한 상태에서는 사용자가 올린 파일을 목록으로 확인한다. 목록의 각 파일에서 사용자는 제목, 파일 이름, 파일 크기, 올린 날짜와 시각을 확인한다. 설명은 목록에서 보여 주지 않는다. 목록의 순서와 노출 기준은 [파일 보관 스펙](./file-storage.md)의 `domain > 목록에 노출하는 파일`을 따른다.

목록의 파일은 아직 선택할 수 없고, 선택해도 아무 일도 일어나지 않는다.

목록은 화면에 들어올 때 서버에서 불러온다. 목록은 앞부분부터 나타나고, 사용자가 목록의 끝으로 이동하면 그다음 파일을 이어서 불러와 붙인다. 사용자는 목록을 계속 이동해 올린 파일을 모두 확인할 수 있다.

다른 기기에서 올린 파일은 목록을 처음부터 다시 불러올 때 보인다. 목록을 다시 불러오는 계기는 `domain > 목록을 다시 불러오는 계기`를 따른다.

### 당겨서 새로고침

로그인한 상태에서 사용자는 본문을 아래로 당겨 목록을 처음부터 다시 불러올 수 있다. 목록이 표시된 상태와 빈 상태, 처음 불러오기에 실패한 상태에서 모두 당길 수 있다. 목록을 처음 불러오는 중에는 당겨도 아무 일도 일어나지 않는다.

파일 목록이 표시된 상태에서 당기면 다시 불러오는 동안 진행 중임이 표시되고, 이전 목록은 그대로 보이며 계속 확인하고 이동할 수 있다. 새 결과가 오면 목록을 바꾼다.

빈 상태나 처음 불러오기에 실패한 상태에서 당기면 `목록 표시 조건`의 처음 불러오기와 같이 불러오는 중임을 표시한다.

다시 불러오는 동안 다시 당겨도 불러오기는 한 번만 진행된다.

### 목록 표시 조건

로그인한 상태의 본문은 다음 중 하나를 표시한다.

| 조건 | 표시 |
| --- | --- |
| 목록을 처음 불러오는 중이다 | 불러오는 중임을 표시한다 |
| 처음 불러오기에 실패했다 | 목록을 불러오지 못했다는 안내와 다시 시도 동작을 표시한다 |
| 처음 불러오기가 끝났고 올린 파일이 하나도 없다 | 아직 올린 파일이 없으며 새로 추가할 수 있다는 빈 상태 안내를 표시한다 |
| 처음 불러오기가 끝났고 올린 파일이 있다 | 파일 목록을 표시한다 |

파일 목록이 표시된 상태에서 이어서 불러오는 동안에는 목록 끝에 불러오는 중임을 표시하고, 이미 나타난 파일은 그대로 확인할 수 있다. 이어서 불러오기에 실패하면 목록 끝에 불러오지 못했다는 안내와 다시 시도 동작을 표시하고, 이미 나타난 파일은 그대로 남는다. 목록 끝의 다시 시도를 실행하면 실패한 이어서 불러오기를 다시 진행한다.

처음 불러오기의 다시 시도를 실행하면 목록을 처음부터 다시 불러오고, 그동안 불러오는 중임을 표시한다.

표의 처음 불러오기는 화면에 들어와 처음 불러오는 경우뿐 아니라, 파일이 하나도 표시되지 않은 상태(빈 상태나 처음 불러오기 실패)에서 목록을 처음부터 다시 불러오는 경우도 포함한다. 처음 불러오는 중에 목록을 처음부터 다시 불러오게 되면 진행 중이던 불러오기를 멈추고 처음부터 다시 불러오며, 그동안 계속 불러오는 중임을 표시한다.

목록의 계정이 바뀌어 처음부터 다시 불러올 때는 이전 계정의 파일을 보여 주지 않는다. 새 계정의 목록은 처음 불러오기와 같은 표시 조건을 따르며, 목록의 처음부터 보인다. 게스트가 되었다가 같은 계정으로 다시 로그인한 경우도 목록의 계정이 바뀐 것으로 본다.

이 목록은 [목록 빈 상태 스펙](./list-empty-state.md)과 [페이지 조회 목록의 자리 표시 스펙](./paged-list-placeholder.md)을 따르지 않는다. 두 문서는 기기에 저장된 자료를 불러오는 목록을 다루지만, 이 목록은 서버에서 불러오므로 불러오지 못한 것과 올린 파일이 없는 것을 구분해 알리고, 아직 불러오지 않은 파일의 자리를 미리 두지 않는다. 당겨서 새로고침도 [새로고침 스펙](./sync-refresh.md)의 동기화가 아니라 이 목록을 다시 불러오는 것이며, 실패하면 알린다.

### 목록이 표시된 상태의 다시 불러오기 실패

파일 목록이 표시된 상태에서 목록을 처음부터 다시 불러오다 실패하면 이전 목록을 그대로 두고, 목록을 불러오지 못했다는 안내를 다시 시도 동작과 함께 알린다. 안내의 다시 시도를 실행하면 목록을 처음부터 다시 불러오고, 그동안 `당겨서 새로고침`과 같이 이전 목록을 그대로 둔 채 진행 중임을 표시한다.

안내가 사라진 뒤에도 사용자는 당겨서 새로고침으로 다시 시도할 수 있다.

실패한 뒤 남아 있는 이전 목록은 실패하기 전과 같이 확인하고 이동할 수 있고, 목록 끝에 이르면 이어서 불러온다. 화면이 회전하거나 시스템이 화면을 재생성해도 이전 목록은 그대로 남는다.

### 파일 추가

로그인한 상태에서 사용자는 파일 추가를 실행해 FileAdd 화면으로 이동할 수 있다. 목록을 불러오는 중이거나, 불러오기에 실패했거나, 빈 상태일 때도 파일 추가를 실행할 수 있다. 제목과 설명을 적고 파일을 골라 올리는 행동은 [FileAdd 화면 스펙](./file-add.md)이 소유한다.

올리는 중인 파일이 있으면 진행 중임을 표시하고 파일 추가를 다시 실행할 수 없다. 이 화면에서 시작한 올리기뿐 아니라, 화면을 떠나기 전에 시작해 아직 끝나지 않은 올리기와 앱이 다시 시작되어 이어서 올리는 파일도 같다. 올리는 동안에도 목록은 그대로 확인하고 이동할 수 있다.

### 올리기 결과

FileHome 화면을 보고 있는 동안 올리기가 끝나면 다음과 같이 화면에서 결과를 확인한다. FileHome에서 연 FileAdd 화면을 보고 있는 동안 끝난 올리기의 결과는 [FileAdd 화면 스펙](./file-add.md)의 `feature > 올리기 결과`에 따라 FileAdd 화면에서 알린다. 화면을 보고 있지 않을 때 끝난 올리기는 알림을 제공하는 플랫폼에서는 알림으로 알리고, 알림을 제공하지 않는 플랫폼에서는 다음에 목록을 처음부터 다시 불러올 때 목록으로 확인한다. 어느 경우에도 나중에 화면에 들어와 그 결과를 화면에서 다시 알리지 않는다. 플랫폼별 제공 범위는 [파일 올리기 알림 스펙](./file-upload-notification.md)의 `feature > 제공 범위`를 따른다. 화면을 보고 있는지의 판정은 [파일 올리기 알림 스펙](./file-upload-notification.md)의 `domain > 파일 화면을 보고 있는 상태`를 따른다.

올리기에 성공하면 진행 중 표시가 사라지고, 목록을 처음부터 다시 불러오며 목록의 처음으로 돌아간다. 방금 올린 파일은 그 사이 다른 기기에서 더 늦게 올린 파일이 없으면 맨 앞에 보인다. 성공을 따로 알리지 않는다. 다시 불러오는 동안의 표시와 실패는 `목록 표시 조건`과 `목록이 표시된 상태의 다시 불러오기 실패`를 따르며, 다시 불러오기에 실패하면 목록의 처음으로 돌아가지 않는다.

FileAdd 화면을 보고 있는 동안 올리기에 성공해도 FileHome의 목록을 처음부터 다시 불러온다. FileAdd에서 돌아오면 다시 불러온 목록의 처음부터 보인다. 이 다시 불러오기에 실패하면 FileHome으로 돌아왔을 때 `목록이 표시된 상태의 다시 불러오기 실패`의 안내를 보이지 않고, 빈 상태나 처음 불러오기 실패였으면 `목록 표시 조건`에 따라 본문에 불러오지 못했다는 안내와 다시 시도 동작이 보인다.

올리기에 실패하면 화면을 유지하고 실패 이유를 알린다. 목록은 바뀌지 않으며 사용자는 파일 추가를 다시 실행할 수 있다. 알리는 실패 이유는 다음 둘로 구분한다.

| 실패 | 알리는 내용 |
| --- | --- |
| 고른 파일이 올릴 수 있는 크기를 넘는다 | 올릴 수 있는 최대 크기와 함께, 그 크기를 넘는 파일은 올릴 수 없다 |
| 그 밖의 이유로 올리지 못했다 | 파일을 올리지 못했다 |

올리는 동안 계정이 게스트가 되거나 다른 계정으로 바뀌면 [파일 보관 스펙](./file-storage.md)의 `domain > 올리기를 중단하는 계기`에 따라 올리기가 중단된다. 진행 중 표시는 사라지고 결과를 알리지 않는다.

### 뒤로가기

사용자가 뒤로가면 `더보기` 화면으로 돌아간다. 이는 [TopLevelNavigation 스펙](./top-level-navigation.md)의 `더보기 하위 화면의 뒤로가기`를 따른다. 알림을 선택해 들어온 경우도 같다.

올리는 동안 뒤로가도 올리기는 멈추지 않고 이어진다. 그 결과는 `올리기 결과`에 따라 알린다.

## domain

### 계정 상태에 따른 화면

화면의 내용은 [계정 조회 스펙](./account.md)이 결정한 계정 상태를 따른다.

| 계정 상태 | 화면 |
| --- | --- |
| 게스트·사용자로 확정하지 않음 | 제목과 뒤로가기만 표시하고 본문을 비운다. 파일 추가를 제공하지 않는다. |
| 게스트 | `feature > 게스트 상태`의 안내를 표시한다. |
| 사용자 | `feature > 파일 목록`과 `feature > 파일 추가`를 제공한다. |

계정 상태를 확인하지 못한 경우도 게스트·사용자로 확정하지 않은 것으로 보고, 이 화면에서 따로 알리지 않는다. 이때 진행 중인 올리기는 멈추지 않는다. 다시 확인된 계정이 이전과 같은 사용자이면 이미 불러온 목록을 다시 불러오지 않고 그대로 보여 준다.

계정 상태를 확정하지 않아 본문이 비어 있는 동안 FileHome 화면을 보고 있는 중에 올리기가 끝나면, 실패는 `feature > 올리기 결과`에 따라 실패 이유를 알린다. 성공이면 목록을 처음부터 다시 불러오고, 계정이 확인되면 다시 불러온 목록이 보인다. 본문이 비기 전에 파일 목록이 표시되어 있었으면, 이 다시 불러오기에 실패해도 따로 알리지 않고 계정이 확인되면 이전 목록이 그대로 보인다. 본문이 비기 전에 빈 상태나 처음 불러오기 실패였으면, 이 다시 불러오기는 `feature > 목록 표시 조건`의 처음 불러오기를 따르므로 실패하면 계정이 확인된 뒤 본문에 불러오지 못했다는 안내와 다시 시도 동작이 보인다.

사용자 상태에서는 세션 갱신 여부와 관계없이 목록을 불러오고 파일 추가를 제공한다. 세션이 갱신되지 않아 서버 요청이 실패하면 불러오기 실패나 올리기 실패로 알린다.

계정 상태가 바뀌면 사용자가 아무것도 하지 않아도 화면이 바로 바뀐 상태를 따른다. 게스트에서 사용자가 되거나 다른 계정으로 바뀌면 목록을 그 계정의 파일로 처음부터 다시 불러온다. 이때 앞선 계정의 목록을 다시 불러오던 중이었으면 그 불러오기는 그만두고, 앞선 계정의 파일은 새 계정의 목록에 나타나지 않는다.

### 목록을 다시 불러오는 계기

목록은 다음 경우에만 처음부터 다시 불러온다.

- 사용자가 FileHome 화면에 들어온다.
- FileHome 화면이나 FileHome에서 연 FileAdd 화면을 보고 있는 동안 파일 올리기에 성공한다.
- 목록의 계정이 바뀐다.
- 처음 불러오기에 실패한 뒤 사용자가 다시 시도를 실행한다.
- 목록이 표시된 상태에서 다시 불러오기에 실패한 뒤 사용자가 그 안내의 다시 시도를 실행한다.
- 사용자가 당겨서 새로고침한다.

그 밖의 경우에는 이미 불러온 목록을 그대로 보여 준다.

목록을 처음부터 다시 불러오는 동안 사용자가 다시 당기거나 안내의 다시 시도를 실행하면, 새로 불러오지 않고 진행 중인 불러오기를 이어 간다. 그동안 FileHome 화면이나 FileHome에서 연 FileAdd 화면을 보고 있는 중에 올리기에 성공하면 진행 중이던 불러오기를 멈추고 처음부터 다시 불러온다. 진행 중이던 불러오기는 방금 올린 파일이 보관되기 전에 시작되어 그 파일을 담지 못할 수 있기 때문이다. 이때 표시는 `feature > 올리기 결과`의 다시 불러오기를 따른다.

### 유지할 사용자 진행 상태

화면이 회전하거나 앱이 백그라운드에 갔다가 같은 화면으로 돌아오면 불러온 목록과 보던 자리를 그대로 유지하며 목록을 다시 불러오지 않는다. 화면이 회전하거나 시스템이 화면을 재생성하면 보이던 올리기 실패 안내와, 목록이 표시된 상태의 다시 불러오기 실패 안내는 닫히고 다시 나타나지 않는다. 앱이 백그라운드에 다녀오는 것은 이 안내를 닫지 않는다. 본문의 처음 불러오기 실패 안내와 목록 끝의 이어서 불러오기 실패 안내는 `feature > 목록 표시 조건`에 따라 계속 보인다.

목록이 보이는 채로 처음부터 다시 불러오는 동안 화면이 회전하거나 시스템이 화면을 재생성하면, 다시 불러오기는 멈추지 않고 이어진다. 당겨서 새로고침이나 안내의 다시 시도로 시작한 것이면 재생성된 화면에도 진행 중 표시가 보인다. 재생성된 뒤 다시 불러오기에 실패하면 재생성된 화면에서 실패 안내를 보인다. 올리기에 성공해 시작한 것이면 재생성된 화면에서도 새 목록이 나타나면 목록의 처음으로 돌아간다.

앱이 백그라운드에 있는 동안 시스템이 앱을 정리했다가 다시 만들면 FileHome 화면이 다시 보이고 목록은 처음부터 다시 불러온다. 목록은 떠나기 전에 보던 자리를 다시 보여 준다. 다만 새로 불러온 앞부분에 보던 파일이 없으면, 불러온 목록의 마지막 부분을 보여 주고 이어서 다음 파일을 불러온다.

FileAdd 화면에서 돌아오는 것은 화면을 떠나는 것이 아니므로, 보던 자리를 그대로 유지하고 목록을 다시 불러오지 않는다. 다만 FileAdd를 보는 동안 올리기에 성공했으면 `feature > 올리기 결과`에 따라 다시 불러온 목록의 처음부터 보인다.

화면을 떠났다가 다시 들어오거나 앱을 다시 실행하면 목록을 처음부터 다시 불러오고 목록의 처음부터 보인다.

올리기는 화면의 이런 변화와 관계없이 [파일 보관 스펙](./file-storage.md)의 `data > 올리기 진행 유지 범위`를 따르고, 화면에 다시 들어왔을 때 아직 올리는 중이면 진행 중 표시가 보인다.
