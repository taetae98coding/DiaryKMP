# FileDetail 화면 스펙

이 문서는 사용자가 올린 파일 하나의 정보를 확인하고, 제목, 설명과 파일 이름을 고치고, 그 파일을 기기에 내려받는 FileDetail 화면의 내용과 행동을 다룬다. FileDetail로 진입하는 FileHome 화면과 고친 내용이 목록에 보이는 방식은 [FileHome 화면 스펙](./file-home.md)에서, 파일 정보를 서버에서 불러오고 고치는 규칙은 [파일 보관 스펙](./file-storage.md)에서, 내려받기의 흐름과 저장 위치는 [파일 내려받기 스펙](./file-download.md)에서, 계정 상태를 결정하는 규칙은 [계정 조회 스펙](./account.md)에서 다룬다. 제목 입력과 설명 입력 자체의 동작은 [제목 입력 스펙](./title-input.md)과 [설명 입력 컴포넌트 스펙](./description-input.md)을 따른다.

이 화면은 기기에 저장한 항목이 아니라 서버에 보관한 파일을 다루므로 [항목 상세 화면 공통 스펙](./entity-detail.md)을 따르지 않는다.

디자인: [FileDetail 화면 디자인](../../design/file-detail.md)

이번 범위는 파일 정보를 확인하고, 제목, 설명과 파일 이름을 고치고, 파일을 내려받는 것까지다. 파일을 지우는 것, 파일 내용을 다른 파일로 바꾸는 것, 앱 안에서 파일을 열어 보는 것은 이번 범위에서 다루지 않는다.

## feature

### 진입

사용자는 로그인한 상태의 FileHome 화면에서 목록의 파일을 선택해 그 파일의 FileDetail 화면으로 이동한다. 화면 상단에는 화면 제목, 뒤로가기와 다운로드가 있다.

이 화면은 FileHome 목록과 함께 표시되거나 단독으로 표시될 수 있다. 두 상태 모두 공통 내비게이션을 제공하지 않으며, 표시 관계는 [File 목록·상세 배치 스펙](./file-list-detail.md)을 따른다. 목록과 함께 표시되는 동안에는 [목록·상세 배치 공통 스펙](./list-detail-pane.md)의 `함께 사용할 때의 행동`에 따라 뒤로가기 동작을 제공하지 않는다.

진입할 때 어느 입력에도 입력 초점을 두지 않는다. 사용자가 먼저 파일 정보를 확인하는 화면이기 때문이다.

### 불러오기와 표시 조건

화면에 들어오면 파일 정보를 서버에서 불러온다. 본문은 다음 중 하나를 표시한다.

| 조건 | 표시 |
| --- | --- |
| 불러오는 중이다 | 불러오는 중임을 표시한다 |
| 불러오기에 실패했다 | 파일을 불러오지 못했다는 안내와 다시 시도 동작을 표시한다 |
| 불러오기에 성공했다 | 파일 정보를 표시한다 |

다시 시도를 실행하면 다시 불러오고 그동안 불러오는 중임을 표시한다. 이 화면에는 당겨서 새로고침하는 수단이 없다. 파일이 지워졌거나 찾을 수 없는 경우도 불러오기 실패로 표시한다.

불러오는 중이거나 불러오기에 실패한 동안에는 수정과 다운로드를 실행할 수 없고, 화면 제목은 비어 있다.

### 파일 정보

불러오기에 성공하면 사용자는 제목, 설명, 파일 이름을 확인하고 고칠 수 있으며, 파일 크기와 올린 날짜와 시각을 확인한다. 파일 크기와 올린 시각은 고칠 수 없다. 화면 제목에는 마지막으로 저장된 제목을 표시한다.

제목과 파일 이름은 한 줄, 설명은 여러 줄로 입력한다.

화면을 보고 있는 동안 다른 기기에서 같은 파일을 고쳐도 화면은 스스로 바뀌지 않는다. 화면을 떠났다가 다시 들어오면 새로 불러온 정보를 본다.

### 수정

입력한 제목, 설명, 파일 이름 중 하나라도 저장된 값과 다를 때만 수정 동작을 제공한다. 비교는 입력한 그대로 하며 앞뒤 공백도 다른 값으로 본다.

수정을 실행하면 앱은 `domain > 수정 성립 조건`을 순서대로 확인하고, 처음 어긴 조건에 따라 다음과 같이 알린다. 어느 경우에도 입력한 내용은 지워지지 않는다.

| 어긴 조건 | 결과 |
| --- | --- |
| 제목이 없다 | 제목 입력이 필요하다고 알리고 입력 초점을 제목 입력으로 옮긴다 |
| 파일 이름이 없다 | 파일 이름 입력이 필요하다고 알리고 입력 초점을 파일 이름 입력으로 옮긴다 |
| 파일 이름이 너무 길다 | 파일 이름은 255자까지 입력할 수 있다고 알리고 입력 초점을 파일 이름 입력으로 옮긴다 |

조건을 모두 만족하면 입력한 세 값을 서버에 반영한다. 반영하는 동안 수정 동작에 진행 중임을 표시하고, 그동안 다시 수정을 실행해도 처리하지 않는다. 반영하는 동안에도 사용자는 입력을 계속 고칠 수 있고 다운로드를 실행할 수 있다.

반영에 성공하면 화면과 입력 내용을 그대로 두고 저장했다는 피드백을 제공한다. 반영한 값이 새 저장된 값이 되며, 화면 제목은 새 제목으로 바뀐다. 반영하는 동안 사용자가 입력을 더 고쳤으면 그 입력은 그대로 남고, 새 저장된 값과 다르면 수정 동작이 다시 보인다.

반영에 실패하면 화면과 입력 내용을 그대로 두고 저장하지 못했다고 알린다. 저장된 값은 바뀌지 않으며 사용자는 수정을 다시 실행할 수 있다.

고친 제목과 파일 이름이 FileHome 목록에 보이는 방식은 [FileHome 화면 스펙](./file-home.md)의 `feature > 고친 파일의 표시`를 따른다.

### 다운로드

사용자는 다운로드를 실행해 이 파일을 기기에 내려받을 수 있다. 내려받는 파일의 이름은 입력 중인 값이 아니라 마지막으로 저장된 파일 이름이다. 내려받는 흐름, 저장 위치와 이름이 겹칠 때의 처리는 [파일 내려받기 스펙](./file-download.md)을 따른다.

내려받는 동안 다운로드 동작에 진행 중임을 표시하고, 그동안 다시 다운로드를 실행해도 처리하지 않는다. 내려받는 동안에도 사용자는 입력을 고치고 수정을 실행할 수 있다.

결과는 다음과 같이 알린다.

| 결과 | 알리는 내용 |
| --- | --- |
| 성공 | 파일을 내려받았다는 안내와 저장한 파일 이름 |
| 저장 위치에 저장하지 못해 실패 | 다운로드 위치에 저장하지 못했으니 설정에서 다운로드 위치를 확인하라는 안내 |
| 그 밖의 이유로 실패 | 파일을 내려받지 못했다 |

웹에서는 내려받은 파일을 브라우저가 저장하므로, 성공하면 브라우저의 다운로드 표시로 확인하고 앱은 따로 알리지 않는다. 저장 위치에 저장하지 못한 실패는 웹에서 일어나지 않는다.

### 계정 상태

이 화면은 로그인한 상태에서만 들어올 수 있다. 화면을 보는 동안 계정 상태가 바뀌면 다음을 따른다.

| 바뀐 계정 상태 | 결과 |
| --- | --- |
| 게스트 | 화면을 닫고 FileHome 화면으로 돌아간다 |
| 다른 사용자 | 화면을 닫고 FileHome 화면으로 돌아간다. 이 파일은 바뀐 계정의 파일이 아니기 때문이다 |
| 게스트·사용자로 확정하지 않음 | 화면과 입력 내용을 그대로 둔다. 이때 수정이나 다운로드를 실행하면 실패로 알린다 |

화면을 닫으면 입력 중이던 내용은 남기지 않는다. 진행 중이던 수정과 다운로드는 `domain > 화면을 떠날 때`를 따른다.

### 뒤로가기

사용자가 뒤로가면 FileHome 화면으로 돌아간다. 저장하지 않은 입력은 남기지 않으며, 떠나기 전에 따로 확인하지 않는다. 목록과 상세 영역을 함께 표시하는 동안의 뒤로가기 결과는 [File 목록·상세 배치 스펙](./file-list-detail.md)의 `뒤로가기`를 따른다.

## domain

### 수정 성립 조건

수정은 다음 조건을 적힌 순서대로 모두 만족해야 서버에 반영한다.

1. 제목이 있다. 비어 있거나 공백 문자로만 이루어진 제목은 제목이 없는 것으로 본다.
2. 파일 이름이 있다. 비어 있거나 공백 문자로만 이루어진 이름은 파일 이름이 없는 것으로 본다.
3. 파일 이름이 255자 이하다. 글자 수는 서버와 같이 유니코드 문자 하나를 한 자로 센다. 여러 문자를 이어 만든 이모지는 이은 문자 수만큼 센다.

설명은 비워 둘 수 있고 제목과 설명의 길이는 제한하지 않는다. 세 값은 앞뒤 공백을 포함해 입력한 그대로 반영한다.

파일 이름에 기기에서 파일 이름으로 쓸 수 없는 글자가 있는지는 수정할 때 확인하지 않는다. 내려받을 때 그 글자를 처리하는 방법은 [파일 내려받기 스펙](./file-download.md)의 `domain > 저장하는 파일 이름`을 따른다.

### 요청 제한

수정과 다운로드는 서로 다른 종류의 요청이다. 한 종류를 처리하는 동안 같은 종류의 요청은 처리하지 않고, 다른 종류의 요청은 막지 않는다. 다시 시도는 불러오는 중에 다시 처리하지 않는다.

### 화면을 떠날 때

화면을 떠나면 진행 중이던 다운로드를 멈추고 받던 내용을 남기지 않는다. 결과도 알리지 않는다.

화면을 떠나도 이미 서버에 보낸 수정은 되돌리지 않는다. 서버가 반영했으면 저장되고, 결과는 알리지 않는다.

### 유지할 사용자 진행 상태

화면이 회전하거나 창 크기가 바뀌거나 앱이 백그라운드에 다녀와도 불러온 파일 정보, 입력 중이던 제목, 설명, 파일 이름과 설명 입력의 입력·미리보기 상태를 유지하고 파일 정보를 다시 불러오지 않는다. 진행 중이던 수정과 다운로드도 멈추지 않고 이어지며, 재생성된 화면에 진행 중 표시와 결과가 보인다. 다만 앱이 화면 뒤에 있는 동안 플랫폼이 내려받기를 끊으면 [파일 내려받기 스펙](./file-download.md)의 `domain > 진행 유지 범위`에 따라 실패로 끝나고, 앱으로 돌아오면 실패를 알린다.

시스템이 앱을 정리한 뒤 화면을 복원하면 파일 정보를 다시 불러오고, 입력 중이던 제목, 설명과 파일 이름은 복원한다. 진행 중이던 다운로드는 멈추며 받던 내용을 남기지 않는다.

화면을 떠났다가 다시 들어오거나 앱을 다시 실행하면 파일 정보를 새로 불러오고 저장된 값으로 시작한다.

## data

### 불러오는 정보

화면은 파일 하나의 정보를 서버에서 불러온다. 불러오는 정보와 계정 제한은 [파일 보관 스펙](./file-storage.md)의 `data > 파일 정보 불러오기`를 따른다.

### 고치는 정보

수정은 제목, 설명과 파일 이름을 함께 서버에 보낸다. 서버가 반영하는 규칙은 [파일 보관 스펙](./file-storage.md)의 `data > 파일 정보 고치기`를 따른다.
