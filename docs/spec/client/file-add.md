# FileAdd 화면 스펙

이 문서는 사용자가 제목과 설명을 적고 파일 하나를 골라 서버에 올리는 FileAdd 화면의 내용과 행동을 다룬다. FileAdd로 진입하는 FileHome 화면과 올린 파일의 목록은 [FileHome 화면 스펙](./file-home.md)에서, 올릴 수 있는 파일과 올리기의 진행은 [파일 보관 스펙](./file-storage.md)에서, 올리는 동안과 끝난 뒤의 알림은 [파일 올리기 알림 스펙](./file-upload-notification.md)에서 다룬다. 제목 입력과 설명 입력 자체의 동작은 [제목 입력 스펙](./title-input.md)과 [설명 입력 컴포넌트 스펙](./description-input.md)을 따른다.

이 화면은 기기에 항목을 저장하지 않고 서버에 곧바로 올리므로 [항목 추가 화면 공통 스펙](./entity-add.md)을 따르지 않는다.

디자인: [FileAdd 화면 디자인](../../design/file-add.md)

이번 범위는 제목, 설명과 파일 하나를 입력해 올리기를 시작하고 그 결과를 확인하는 것까지다. 여러 파일을 한 번에 고르는 것과, 진행 중인 올리기를 사용자가 취소하는 것은 이번 범위에서 다루지 않는다.

## feature

### 진입

사용자는 로그인한 상태의 FileHome 화면에서 파일 추가를 실행해 FileAdd 화면으로 이동한다. 그 기준은 [FileHome 화면 스펙](./file-home.md)의 `feature > 파일 추가`를 따른다. 화면 상단에는 제목과 뒤로가기가 있다.

화면에 처음 진입하면 제목과 설명이 비어 있고 고른 파일이 없는 상태로 시작한다. 사용자가 제목부터 바로 적을 수 있도록 입력 초점을 제목 입력에 한 번 둔다.

### 입력

사용자는 제목과 설명을 입력하거나 바꿀 수 있다. 제목은 한 줄, 설명은 여러 줄로 입력한다. 제목은 반드시 입력해야 하고 설명은 비워 둘 수 있다. 앱은 파일 이름으로 제목을 채우지 않는다.

### 파일 고르기

사용자는 파일 고르기를 실행해 기기가 제공하는 파일 선택 도구를 열고 파일 하나를 고를 수 있다. 파일을 고르면 화면에서 고른 파일의 이름과 크기를 확인한다.

이미 고른 파일이 있어도 다시 고를 수 있으며, 새로 고른 파일로 바뀐다. 고른 파일만 따로 비우는 동작은 제공하지 않는다.

파일을 고르지 않고 선택 도구를 닫으면 고른 파일은 바뀌지 않는다.

고른 파일이 `domain > 고를 수 있는 파일`을 만족하지 않으면 그 파일을 고르지 않은 것으로 두고 이유를 알린다. 이전에 고른 파일이 있으면 그대로 남는다.

| 이유 | 알리는 내용 |
| --- | --- |
| 파일의 이름이나 크기를 알 수 없다 | 파일을 읽지 못했다 |
| 파일이 올릴 수 있는 크기를 넘는다 | 올릴 수 있는 최대 크기와 함께, 그 크기를 넘는 파일은 올릴 수 없다 |

### 올리기 실행

사용자는 입력한 내용으로 올리기를 실행할 수 있다. 앱은 `domain > 올리기 성립 조건`을 순서대로 확인하고, 처음 어긴 조건에 따라 다음과 같이 알린다. 어느 경우에도 입력한 제목, 설명과 고른 파일은 지워지지 않는다.

| 어긴 조건 | 결과 |
| --- | --- |
| 제목이 없다 | 제목 입력이 필요하다고 알리고 입력 초점을 제목 입력으로 옮긴다 |
| 고른 파일이 없다 | 파일을 골라야 한다고 알린다. 입력 초점은 옮기지 않는다 |

조건을 모두 만족하면 입력한 제목과 설명으로 고른 파일의 올리기를 시작한다. 올리기는 화면과 관계없이 이어지며 그 규칙은 [파일 보관 스펙](./file-storage.md)을 따른다.

올리기를 시작하면 화면은 그대로 유지하고 제목, 설명과 고른 파일을 비운다. 설명 입력은 설명을 입력할 수 있는 상태로 돌아가고, 입력 초점은 제목 입력으로 옮긴다. 사용자는 화면을 떠나지 않고 다음 파일의 제목과 설명을 적고 파일을 고를 수 있다. 올리기를 시작한 것만으로는 따로 알리지 않는다.

### 올리는 중

올리는 중인 파일이 있으면 올리기 실행 자리에 진행 중임을 표시하고 올리기를 실행할 수 없다. 이 화면에서 시작한 올리기뿐 아니라, 화면에 들어오기 전에 시작해 아직 끝나지 않은 올리기와 앱이 다시 시작되어 이어서 올리는 파일도 같다. 그 기준은 [파일 보관 스펙](./file-storage.md)의 `domain > 한 번에 올리는 파일`을 따른다.

올리는 동안에도 제목과 설명을 입력하고 파일을 고를 수 있다. 올리기가 끝나면 진행 중 표시가 사라지고, 적어 둔 내용으로 올리기를 실행할 수 있다.

### 올리기 결과

FileAdd 화면을 보고 있는 동안 올리기가 끝나면 이 화면에서 결과를 알린다. 이 화면에서 시작한 올리기인지와 관계없다. 화면을 보고 있는지의 판정과, 보고 있지 않을 때 결과를 알리는 방법은 [파일 올리기 알림 스펙](./file-upload-notification.md)을 따른다.

| 결과 | 알리는 내용 |
| --- | --- |
| 성공 | 파일을 올렸다 |
| 고른 파일이 올릴 수 있는 크기를 넘어 실패 | 올릴 수 있는 최대 크기와 함께, 그 크기를 넘는 파일은 올릴 수 없다 |
| 그 밖의 이유로 실패 | 파일을 올리지 못했다 |

결과를 알려도 사용자가 그사이 적어 둔 제목, 설명과 고른 파일은 바뀌지 않는다. 실패한 올리기의 제목, 설명과 파일은 화면에 되살리지 않으므로, 사용자는 다시 입력하고 파일을 골라 올리기를 실행한다.

올리는 동안 계정이 게스트가 되거나 다른 계정으로 바뀌어 올리기가 중단되면 진행 중 표시가 사라지고 결과를 알리지 않는다.

### 계정 상태

이 화면은 로그인한 상태에서만 들어올 수 있다. 화면을 보는 동안 계정 상태가 바뀌면 다음을 따른다.

| 바뀐 계정 상태 | 결과 |
| --- | --- |
| 게스트 | 화면을 닫고 FileHome 화면으로 돌아간다. 적어 둔 내용은 남기지 않는다 |
| 다른 사용자 | 화면과 적어 둔 내용을 그대로 두고, 이후 올리기는 바뀐 계정으로 한다 |
| 게스트·사용자로 확정하지 않음 | 화면과 적어 둔 내용을 그대로 둔다. 이때 올리기를 실행하면 올리기를 시작하지 않고 파일을 올리지 못했다고 알리며, 적어 둔 내용은 지우지 않는다 |

### 뒤로가기

사용자가 뒤로가면 FileHome 화면으로 돌아간다. 적어 둔 제목, 설명과 고른 파일은 남기지 않는다.

올리는 동안 뒤로가도 올리기는 멈추지 않고 이어진다. 돌아간 FileHome 화면에서 결과를 확인하는 방법은 [FileHome 화면 스펙](./file-home.md)의 `feature > 올리기 결과`를 따른다.

## domain

### 고를 수 있는 파일

파일을 고르면 앱은 기기가 알려 주는 파일 이름과 크기를 읽는다. 다음을 모두 만족하는 파일만 고른 파일이 된다.

- 파일 이름과 크기를 읽을 수 있다.
- 크기가 [파일 보관 스펙](./file-storage.md)의 `domain > 올릴 수 있는 파일`이 정한 최대 크기 이하다. 크기가 0인 빈 파일도 고를 수 있다.

고를 때 확인을 통과한 파일도 올리기를 시작한 뒤 [파일 보관 스펙](./file-storage.md)의 `data > 올리기 흐름`에 따라 다시 확인한다. 고른 뒤 파일이 바뀌었을 수 있기 때문이다.

### 올리기 성립 조건

올리기는 다음 조건을 적힌 순서대로 모두 만족해야 시작한다.

1. 제목이 있다. 비어 있거나 공백 문자로만 이루어진 제목은 제목이 없는 것으로 본다.
2. 고른 파일이 있다.
3. 올리는 중인 파일이 없다. 올리는 중에는 올리기를 실행할 수 없으므로 `feature > 올리기 실행`의 안내 대상이 아니다.

제목과 설명은 길이를 제한하지 않는다. 입력한 제목과 설명은 앞뒤 공백을 포함해 입력한 그대로 올린다. 설명을 입력하지 않으면 빈 설명으로 올린다.

### 유지할 사용자 진행 상태

화면이 회전하거나 창 크기가 바뀌어도 입력 중이던 제목, 설명, 설명 입력의 입력·미리보기 상태와 고른 파일을 유지한다. 앱이 백그라운드에 다녀와도 같다.

시스템이 앱을 메모리에서 정리한 뒤 화면을 복원하면 입력 중이던 제목과 설명은 복원하고, 고른 파일은 복원하지 않는다. 앱이 다시 시작된 뒤에는 고른 파일을 다시 읽을 수 있다고 보장할 수 없기 때문이다. 다만 파일 선택 도구가 열려 있는 동안 시스템이 앱을 정리했다가 다시 만들면, 선택 도구에서 고른 파일은 복원된 화면의 고른 파일이 된다.

화면을 떠났다가 다시 들어오거나 앱을 다시 실행하면 처음 진입한 상태로 시작한다.

## data

### 올리는 내용

올리기를 시작하면 고른 파일과 함께 입력한 제목과 설명을 보낸다. 서버가 파일과 함께 제목과 설명을 보관하는 약속은 [파일 보관 스펙(common)](../common/file-storage.md)의 `올리는 파일`을 따른다.

올리기를 시작한 뒤에는 화면의 입력과 관계없이 시작할 때의 제목과 설명으로 올린다. [파일 보관 스펙](./file-storage.md)의 `data > 올리기 진행 유지 범위`에 따라 같은 파일을 처음부터 다시 올릴 때도 같다.
