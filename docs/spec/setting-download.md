# SettingDownload 화면 스펙

이 문서는 사용자가 설정 화면의 `다운로드` 항목에서 진입하는 SettingDownload 화면의 내용과 행동을 다룬다. 설정 항목의 표시와 선택은 [SettingHome 화면 스펙](./setting-home.md)에서, 설정 목록과 함께 사용할 때의 선택·뒤로가기 정책은 [Setting 목록·상세 배치 스펙](./setting-list-detail.md)에서, 세부 화면에서의 공통 내비게이션 노출 규칙은 [TopLevelNavigation 스펙](./top-level-navigation.md)에서 다룬다. 프록시가 제공되는 환경, 주소의 형태와 포트, 프록시의 상태는 [곡 다운로드 프록시 스펙](./music-download-proxy.md)에서, 저장한 주소로 곡을 내려받는 흐름은 [곡 다운로드 스펙](./music-download.md)에서 다룬다.

디자인: [SettingDownload 화면 디자인](../design/setting-download.md)

이 화면은 플랫폼에 따라 하는 일이 다르다. JVM 데스크톱에서는 이 기기가 제공하는 프록시 주소를 확인하는 화면이고, Android와 iOS에서는 내려받기에 쓸 프록시 주소를 입력해 기기에 저장하는 화면이다. 저장한 주소로 실제로 곡을 내려받는 것은 [곡 다운로드 스펙](./music-download.md)에서 다룬다.

## feature

### 진입과 이동

사용자는 설정 화면의 `다운로드` 항목을 선택해 SettingDownload 화면으로 이동한다.

SettingDownload 화면은 설정 목록과 함께 표시되거나 단독으로 표시될 수 있다. 두 상태 모두 공통 내비게이션을 제공하지 않으며, 표시 관계는 [Setting 목록·상세 배치 스펙](./setting-list-detail.md)을 따른다.

이 화면은 [곡 다운로드 스펙](./music-download.md)이 다운로드를 제공하는 플랫폼에서만 진입할 수 있다. 웹에서는 SettingHome이 `다운로드` 항목을 제공하지 않으므로 이 화면으로 이동하는 경로가 없다.

### 프록시 주소 확인 (JVM 데스크톱)

JVM 데스크톱에서 사용자는 이 기기가 제공하는 프록시 주소를 확인한다. 이 기기가 여러 네트워크에 연결되어 있으면 주소 후보를 모두 확인하며, 어느 후보가 다른 기기에 닿는지는 사용자가 다른 기기에서 시험해 고른다. 후보의 기준은 [곡 다운로드 프록시 스펙](./music-download-proxy.md)의 `프록시 주소`를 따른다.

사용자는 각 주소를 그대로 옮겨 적을 수 있도록 확인한다. 주소를 바꾸거나 입력하는 수단은 두지 않는다.

프록시가 제공 중이지만 사설 IPv4 주소가 하나도 없으면 다른 기기가 닿을 주소가 없음을 알린다. 프록시를 제공하지 못하는 상태면 프록시를 시작하지 못했음을 알리고, 사용자가 앱을 다시 실행해야 함을 함께 알린다. 두 상태 모두 화면에서 다시 시도하는 수단은 두지 않는다. 프록시가 스스로 다시 시도하지 않는 것은 [곡 다운로드 프록시 스펙](./music-download-proxy.md)의 `프록시 상태`를 따른다.

화면에 표시하는 주소와 상태는 화면에 들어온 시점의 것이며, 화면을 보고 있는 동안 네트워크가 바뀌어도 스스로 갱신하지 않는다. 사용자는 화면을 떠났다 다시 들어와 새로 확인한다. 주소의 포트는 앱을 실행할 때마다 달라질 수 있으므로([곡 다운로드 프록시 스펙](./music-download-proxy.md)의 `프록시 주소`), 다른 기기에서 연결할 수 없을 때 사용자는 이 화면에서 지금 주소를 다시 확인한다.

### 프록시 주소 입력 (Android, iOS)

Android와 iOS에서 화면에 진입하면 저장해 둔 프록시 주소가 입력된 상태로 시작한다. 한 번도 저장하지 않았으면 비어 있는 상태로 시작한다.

저장된 주소를 확인하기 전이거나 읽지 못했으면 주소를 입력하는 기능과 저장 기능을 제공하지 않으며 별도 로딩 또는 오류 상태로 전환하지 않는다.

사용자는 프록시 주소를 한 줄로 입력하거나 바꿀 수 있다.

### 설정 저장 (Android, iOS)

사용자는 입력한 프록시 주소를 저장할 수 있다.

입력한 주소가 저장된 주소와 다를 때만 저장할 수 있다. 같으면 저장 동작을 제공하지 않는다.

저장을 실행하기 전까지 입력한 내용은 저장되지 않는다.

저장하는 동안에는 진행 상태를 표시하며, 저장이 끝나기 전에는 같은 화면에서 전달된 저장 요청을 처리하지 않는다.

저장에 성공하면 화면을 유지한 채 저장되었다는 피드백을 제공하고, 입력한 내용은 비우지 않고 그대로 둔다. 입력한 내용이 곧 저장된 주소가 되므로 사용자가 값을 다시 바꾸기 전까지는 저장 동작을 제공하지 않는다.

저장에 실패하면 입력 중이던 주소를 그대로 유지하고 저장에 실패했다는 피드백을 제공하므로, 사용자는 그대로 다시 시도할 수 있다.

### 뒤로가기

단독으로 표시될 때와 설정 목록과 함께 표시될 때의 뒤로가기 결과는 모두 [Setting 목록·상세 배치 스펙](./setting-list-detail.md)의 `뒤로가기`를 따른다.

Android와 iOS에서 저장하지 않고 화면을 떠나면 입력 중이던 내용은 버려지고 저장된 주소는 바뀌지 않는다. 화면을 떠나기 전에 저장하지 않은 내용이 있다고 따로 확인하지 않는다.

### 입력 상태 유지 (Android, iOS)

화면이 회전하거나 시스템에 의해 재생성되어도 입력 중이던 주소를 유지한다.

사용자가 화면을 떠났다가 다시 들어오거나 앱을 종료한 뒤 새로 시작하면 저장된 주소로 다시 시작한다.

## domain

### 다운로드 프록시 설정

다운로드 프록시 설정은 Android와 iOS에서 곡을 내려받을 때 영상을 요청할 프록시의 주소다. 값은 사용자가 JVM 데스크톱의 SettingDownload 화면에서 확인해 옮겨 적은 주소 한 줄이다.

사용자가 한 번도 저장하지 않았으면 비어 있다. 앱은 기본값을 제시하지 않으며, 같은 네트워크의 프록시를 스스로 찾지 않는다.

JVM 데스크톱은 자기 곡을 프록시 없이 직접 받으므로 이 설정을 갖지 않는다.

### 저장 가능 상태

편집 중인 주소가 저장된 주소와 다를 때만 저장 동작을 제공한다. 같으면 저장 동작을 제공하지 않는다.

비교는 사용자가 넣은 그대로 본다. 앞뒤 공백을 지우거나 대소문자를 맞추지 않으므로 공백만 더해도 다른 값으로 본다.

한 번도 저장하지 않아 저장된 값이 없으면 비어 있는 주소와 비교한다. 그래서 화면에 처음 들어와 아무것도 입력하지 않은 상태에서는 저장 동작을 제공하지 않는다.

저장을 처리하는 동안에도 같은 기준을 적용한다. 저장이 끝나 저장된 주소가 편집 중인 값과 같아지면 저장 동작은 사라진다.

### 저장 성립 조건

저장 동작을 제공하는 상태에서 주소는 비어 있어도 된다. 비어 있는 주소를 저장하는 것은 저장해 둔 주소를 지우는 것과 같다.

주소가 프록시 주소의 형태를 갖추었는지, 그 주소의 프록시에 실제로 연결할 수 있는지는 저장 시점에 확인하지 않는다. 연결할 수 없는 주소로 다운로드를 실행했을 때의 결과는 [곡 다운로드 스펙](./music-download.md)의 `내려받기 준비`가 정한다.

### 편집 상태와 저장된 설정

화면에서 입력 중인 값은 저장된 주소와 별개의 편집 상태이며, 저장을 실행할 때만 저장된 주소에 반영된다.

### 유지와 초기화 기준

편집 상태는 화면이 전환 이력에 남아 있는 동안 화면 재생성과 백그라운드 복귀 후에도 유지한다.

사용자가 화면을 떠나 전환 이력에서 사라지거나 앱을 종료하고 다시 실행하면 편집 상태는 저장된 주소로 초기화한다.

## data

### 저장 시점과 유지

사용자가 저장을 실행하면 그 시점의 주소가 기기에 저장된다. 사용자가 한 번도 저장하지 않았으면 저장된 값이 없고, 이때 주소는 비어 있는 것으로 다룬다.

저장된 주소는 화면을 떠나거나 화면이 재생성되어도, 앱이 백그라운드에 다녀와도, 앱을 종료하고 다시 시작해도 유지된다.

저장된 값을 읽을 수 없으면 설정을 아직 확인하지 못한 상태로 다룬다. 이는 저장된 값이 없어 주소를 비어 있는 것으로 다루는 것과 구분된다.

### 기기별 보관

다운로드 프록시 설정은 사용자 계정이 아니라 기기에 보관하며 서버와 동기화하지 않는다. 로그인, 로그아웃, 계정 전환으로 바뀌지 않으며 다른 기기에도 반영되지 않는다. 프록시 주소는 그 기기가 놓인 네트워크에 따라 다르기 때문이다.

다운로드 프록시 설정은 [데이터 동기화 스펙](./data-sync.md)의 동기화 대상이 아니다.

### 환경별 저장 영역

설정을 저장하는 Android와 iOS는 [SettingMap 화면 스펙](./setting-map.md)의 `환경별 저장 영역`이 정한 각 환경의 저장 영역을 그대로 쓴다. JVM 데스크톱은 이 설정을 저장하지 않는다.
