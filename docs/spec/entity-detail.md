# 항목 상세 화면 공통 스펙

이 문서는 저장된 항목 하나를 확인하고 수정하는 상세 화면들이 공통으로 보장하는 태그 입력의 반영, 요청 제한, 수정 동작의 제공 기준과 저장 계약을 다룬다. 어떤 입력을 제공하는지, 무엇이 수정 대상인지, 그 화면에만 있는 동작이 무엇인지는 화면마다 다르므로 각 화면 스펙에서 다룬다.

이 문서를 따르는 화면 스펙은 다음과 같다.

- [ContactDetail 화면 스펙](./contact-detail.md)
- [MemoDetail 화면 스펙](./memo-detail.md)
- [MusicDetail 화면 스펙](./music-detail.md)
- [PlaceDetail 화면 스펙](./place-detail.md)
- [TagDetail 화면 스펙](./tag-detail.md)
- [WebDetail 화면 스펙](./web-detail.md)

이 문서에서 `상세 대상`은 그 화면이 다루는 항목 하나를 가리킨다.

태그를 고르는 입력의 행동과 판정 기준은 [태그 선택 입력 공통 스펙](./tag-select-input.md)을, 연결의 규칙과 저장·동기화 계약은 [항목 연결 공통 스펙](./entity-link.md)을 따른다.

태그 입력을 제공할지는 화면마다 다르다. 태그 입력을 제공하지 않는 화면에는 이 문서의 태그 입력 관련 규칙을 적용하지 않으며, 어느 화면이 태그 입력을 제공하지 않는지는 각 화면 스펙에서 밝힌다.

## feature

### 진입할 때의 입력 초점

사용자가 먼저 저장된 내용을 확인하는 화면이므로 진입할 때 어느 입력에도 입력 초점을 두지 않는다.

### 내용 수정

사용자는 변경한 내용을 반영할 수 있다. 처리 중에는 진행 상태를 표시한다.

수정에 성공하면 화면과 입력 내용을 유지하고 성공 피드백을 제공한다. 화면 제목은 새로 저장된 제목으로 갱신된다.

### 태그 입력

사용자가 반영한 연결과 해제는 상세 대상의 저장된 연결로 즉시 반영된다. 다른 입력의 수정 반영과 달리 별도의 반영 동작이 필요하지 않으며, 수정 반영 동작을 제공할지 판정할 때도 태그 연결은 포함하지 않는다.

연결과 해제를 반영하는 동안에도 사용자는 화면의 다른 동작을 그대로 실행할 수 있다.

연결한 태그를 누르면 그 태그의 TagDetail 화면으로 이동하고, 뒤로가면 이 항목의 상세로 돌아온다.

### 진행 상태 유지

태그 연결은 이미 저장된 값이므로 화면이 재생성되어도 저장된 연결을 그대로 다시 표시한다. 태그 선택 목록이 열려 있었으면 열림 상태와 검색어를 [태그 선택 입력 공통 스펙](./tag-select-input.md)의 기준에 따라 유지한다.

사용자가 이 화면에서 삭제를 실행했을 때는 각 화면 스펙의 `삭제`에 따라 화면을 떠나므로 이 규칙이 적용되지 않는다.

## domain

### 태그 입력에 표시하는 태그

태그 입력이 표시 대상으로 삼는 태그는 상세 대상과 저장된 연결을 가진 태그다. 어떤 태그가 조회되는지는 [항목 연결 공통 스펙](./entity-link.md)의 `연결된 항목의 조회`를 따르므로 완료된 태그도 표시하고 삭제된 태그는 표시하지 않는다.

새로 연결할 수 있는 태그는 [태그 선택 입력 공통 스펙](./tag-select-input.md)의 `선택할 수 있는 태그`를 따른다.

### 태그 연결의 반영

연결을 실행하면 상세 대상과 고른 태그의 연결을 만들고, 해제를 실행하면 그 연결을 해제한다. 만들고 해제할 때 기록되는 내용은 [항목 연결 공통 스펙](./entity-link.md)의 `연결의 상태와 시각`을 따른다.

연결과 해제는 상세 대상의 저장 내용과 상태, 수정 시각을 바꾸지 않는다. 수정 중이던 입력 내용도 바꾸지 않는다.

상세 대상이 완료되었거나 삭제된 상태여도 사용자는 태그 연결을 확인하고 바꿀 수 있다. 연결과 해제는 완료 여부와 삭제 여부를 되돌리지 않는다.

### 수정되는 내용

삭제 여부, 생성 시각과 계정 연결은 내용 수정으로 바뀌지 않는다.

어떤 값이 수정 대상인지는 각 화면 스펙에서 정한다.

### 수정 동작의 제공 기준

입력한 값이 저장된 내용과 하나라도 다르면 수정 동작을 제공한다. 어떤 값을 비교하는지는 각 화면 스펙에서 정한다.

태그 연결은 수정 동작의 제공 기준에 넣지 않는다. 태그를 연결하거나 해제하는 것만으로는 수정 동작이 나타나지 않고, 이미 나타난 수정 동작도 사라지지 않는다.

### 요청 제한

화면이 제공하는 동작은 종류별로 요청을 제한한다. 한 종류를 처리하는 동안 같은 종류의 요청은 처리하지 않지만 다른 종류의 요청은 제한하지 않는다. 어떤 동작을 같은 종류로 보는지는 각 화면 스펙에서 정한다.

태그의 연결과 해제는 이 제한에 포함하지 않는다. 사용자는 다른 동작이 처리 중이어도 연결과 해제를 실행할 수 있고, 서로 다른 태그의 연결과 해제를 이어서 실행할 수 있다.

앱의 데이터를 바꾸지 않는 동작은 제한 대상이 아니다.

## data

### 대상 조회

상세 대상은 현재 사용자 계정과 연결된 항목 하나다. 계정 조회 규칙은 [계정 조회 스펙](./account.md)을 따르며, 현재 계정을 확인할 수 없으면 상세 대상을 조회할 수 없는 것으로 다룬다.

저장된 내용이 바뀌면 조회 결과도 그에 맞게 갱신되어 화면 제목에 반영된다.

### 태그 입력의 조회

표시 대상 태그는 저장소에서 상세 대상과 연결된 태그를 조회해 표시한다. 조회 기준과 정렬은 [항목 연결 공통 스펙](./entity-link.md)의 `연결된 항목의 조회`를 따르며, 이 조회는 페이지로 나누지 않는다.

태그 선택 목록은 현재 사용자 계정의 미완료·미삭제 태그와, 상세 대상이 이미 연결한 완료된 태그를 함께 페이지 단위로 조회한다. 정렬과 페이지 조회 흐름은 [태그 선택 입력 공통 스펙](./tag-select-input.md)의 `태그 목록 조회`를 따른다.

저장된 연결이나 태그의 내용·상태가 바뀌면 두 조회 결과가 갱신되어 태그 입력에 반영된다.

### 태그 연결의 저장

사용자가 태그를 연결하거나 해제하면 그 결과를 즉시 저장한다. 저장 방식은 [항목 연결 공통 스펙](./entity-link.md)의 `연결의 저장`을 따른다.

연결과 해제를 저장하면 그 연결이 업로드 대기로 기록되고 백그라운드 동기화가 시작된다. 동기화 규칙은 [항목 연결 공통 스펙](./entity-link.md)의 `동기화`를 따른다.

연결과 해제의 저장은 상세 대상의 저장 내용과 수정 시각을 바꾸지 않으므로, 상세 대상 자체를 업로드 대기로 만들지 않는다.

### 태그 연결 결과의 표시

연결을 만들면 그 태그의 목록에 상세 대상이 노출 기준에 맞게 나타나고, 연결을 해제하면 그 목록에서 사라진다. 어느 목록에 나타나는지는 각 화면 스펙에서 정한다.

태그 연결은 상세 대상이 자기 목록과 검색 결과에 나타나는 기준을 바꾸지 않는다. 기준은 [항목 태그 연결 공통 스펙](./entity-tag.md)의 `연결의 의미`를 따른다.

### 저장 실패

저장에 실패하면 실패를 그대로 알리며 성공으로 바꾸지 않는다.
