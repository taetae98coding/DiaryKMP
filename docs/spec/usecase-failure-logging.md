# UseCase 실패 로깅 스펙

이 문서는 도메인 작업(UseCase)이 실패했을 때 그 사건을 로그로 남기는 정책을 다룬다. [앱 로깅](./app-logging.md)의 공통 창구와 기록 수단 체계 위에서 동작하며, 화면 없이 앱 내부에서 진행되므로 `feature` 영역을 생략하고, 로그는 저장·동기화되지 않으므로 `data` 영역도 생략한다.

## domain

### 도메인 작업 실패

도메인 작업은 메모 저장, 태그 조회처럼 사용자 행위 하나 또는 화면에 필요한 데이터 관찰 하나를 처리하는 앱 내부 작업이다.

도메인 작업이 실패하면 실패 사건 하나가 로그로 남는다. 한 번 실행하고 끝나는 작업과 지속 관찰하는 작업의 실패를 모두 남기며, 같은 작업이 여러 번 실패하면 실패할 때마다 남는다.

화면 이탈 등으로 작업이 중단(취소)된 것은 실패가 아니므로 로그로 남지 않는다.

로그를 남기는 것은 실패 처리에 영향을 주지 않는다. 실패는 로그와 무관하게 기존과 동일하게 호출한 쪽에 전달되고, 화면은 기존과 동일하게 실패를 표시한다.

### 실패 로그 내용

실패 로그에는 실패한 작업의 이름과 실패 원인이 담긴다.

작업에 입력된 값은 로그에 담지 않는다. 입력 값에는 비밀번호 같은 민감한 값이 포함될 수 있다.

### 콘솔 기록

실패 로그는 콘솔 로그로 남긴다. 태그는 실패한 작업의 이름을 사용하고, 오류 정보에 실패 원인을 담는다.

콘솔 기록 수단의 등록 정책은 [앱 로깅](./app-logging.md)을 따르므로, 콘솔 기록 수단이 등록되지 않은 배포 빌드에서는 콘솔에 실패 로그가 남지 않는다.

### 오류 보고

일부 도메인 작업의 실패는 콘솔 기록과 함께 오류 보고로도 남긴다. 어떤 작업이 오류 보고 대상인지는 그 작업을 정의한 기능 스펙이 정한다.

오류 보고 대상인 작업이 실패하면 콘솔 로그와 오류 보고가 함께 남는다. 오류 보고 대상이 아닌 작업의 실패는 콘솔 로그로만 남는다.

오류 보고에는 실패 원인을 담고, 실패한 작업의 이름은 오류 보고 메시지에 담아 어떤 작업이 실패했는지 구분한다.

오류 보고 기록 수단은 배포 빌드에서도 등록되므로, 콘솔 기록이 없는 배포 빌드에서도 오류 보고 대상인 작업의 실패는 남는다. 등록 정책과 플랫폼 제약은 [앱 로깅](./app-logging.md)의 오류 보고 기록을 따른다.
