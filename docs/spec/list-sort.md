# 목록 정렬 스펙

이 문서는 화면 본문을 차지하는 목록에서 사용자가 정렬 기준을 고르고 바꾸는 행동과 그 결과를 다룬다. 각 목록이 무엇을 노출하는지는 각 화면 스펙이 다루고, 아직 준비되지 않은 자리의 처리는 [페이지 조회 목록의 자리 표시 스펙](./paged-list-placeholder.md)이, 표시할 항목이 하나도 없을 때의 안내는 [목록 빈 상태 스펙](./list-empty-state.md)이 다룬다.

디자인: [목록 정렬 디자인](../design/list-sort.md)

항목을 고르기 위해 화면 안에서 여는 선택 목록에는 적용하지 않는다. [메모 태그 입력 컴포넌트 스펙](./memo-tag-input.md)의 태그 선택 목록, [메모 장소 카드 컴포넌트 스펙](./memo-place-card.md)의 장소 선택 목록, [태그 연결 입력 컴포넌트 스펙](./tag-link-input.md)의 태그 선택 목록, [항목 태그 입력 컴포넌트 스펙](./entity-tag-input.md)의 태그 선택 목록과 [태그 필터 스펙](./tag-filter.md)의 태그 목록은 각 문서가 정한 순서를 그대로 쓴다. 선택 목록은 사용자가 고르려고 잠시 여는 목록이므로 정렬을 바꿀 자리가 없다.

[CalendarHome 스펙](./calendar-home.md)의 날짜별 메모와 [HolidayHome 화면 스펙](./holiday-home.md)의 공휴일 목록에도 적용하지 않는다. 두 목록은 날짜가 순서를 정하므로 사용자가 고를 정렬이 없다.

## feature

### 정렬 선택

사용자는 적용 대상의 각 목록에서 지금 어떤 기준으로 정렬되어 있는지 확인하고, 그 목록이 제공하는 다른 기준으로 바꿀 수 있다. 목록마다 고를 수 있는 기준은 `적용 대상`이 정한다.

정렬 기준은 언제나 하나만 선택되어 있으며, 사용자가 선택을 비울 수는 없다.

사용자가 지금 선택되어 있는 기준을 다시 고르면 목록의 순서는 바뀌지 않는다.

### 정렬 반영

정렬 기준을 바꾸면 그 목록은 바뀐 기준의 순서로 다시 놓인다. 사용자는 목록의 처음부터 새 순서를 확인한다.

정렬을 바꿔도 목록이 노출하는 항목의 집합은 바뀌지 않는다. 필터, 질의, 지도의 보이는 영역처럼 목록의 범위를 좁히는 조건은 그대로 유지되며, 정렬은 좁힌 결과 안에서의 순서만 정한다.

정렬을 바꾼 뒤에도 목록에서 할 수 있는 행동은 그대로다. 항목을 열고, 완료하고, 삭제하고, 실행 취소하고, 당겨서 새로고침하는 것이 정렬 기준에 따라 달라지지 않는다.

목록의 내용이 바뀌면 지금 선택된 기준에 맞는 자리로 항목이 옮겨진다. 항목이 추가되거나 수정되거나 서버에서 내려받은 내용이 기기에 반영된 경우가 모두 그렇다.

### 정렬 선택 유지

정렬 선택은 사용자가 그 목록을 보고 있는 동안 유지한다. 화면이 회전하거나 시스템에 의해 화면이 재생성되어도, 앱이 백그라운드에 갔다가 같은 화면으로 돌아와도, 상세로 이동한 뒤 뒤로 돌아와도 유지한다.

화면을 떠난 뒤 다시 들어오면 그 목록의 처음 정렬로 되돌아간다. 정렬 선택은 저장소에 남기지 않으므로 앱을 다시 실행해도 마지막에 고른 기준은 남지 않는다.

한 목록에서 고른 기준은 그 목록에만 적용한다. 같은 종류의 항목을 보여 주는 다른 목록이나 다른 화면의 목록에는 적용하지 않는다.

여러 목록을 탭으로 나란히 두는 화면에서는 탭마다 선택을 따로 유지한다. 사용자가 탭을 옮겼다가 돌아오면 그 탭에서 고른 기준을 그대로 본다.

[장소 보기 모드 스펙](./place-view-mode.md)의 두 보기 모드는 같은 장소를 보는 한 자리의 목록이므로 정렬 선택을 함께 쓴다. 한 모드에서 고른 기준은 모드를 바꿔도 그대로 적용된다. 이는 PlaceHome 화면과 TagDetail 장소 탭에 모두 적용한다.

### 준비 중과 빈 상태에서의 정렬

목록을 준비하는 동안과 목록이 비어 있는 동안에도 사용자는 정렬 기준을 확인하고 바꿀 수 있다. 목록에 항목이 없다는 이유로 정렬 선택이 막히지 않는다.

## domain

### 정렬 기준

| 정렬 | 순서 |
| --- | --- |
| 기본순 | 그 목록이 사용자의 선택 없이 쓰는 순서 |
| 제목순 | 제목 오름차순 |
| 이름순 | 이름 오름차순 |
| 최근 수정순 | 수정 시각 내림차순 |

제목순과 이름순에서 값이 같은 항목끼리의 순서는 정하지 않는다. 태그의 이모지는 제목순에 영향을 주지 않는다.

제목순과 이름순은 항목을 가리키는 값의 오름차순이라는 같은 기준이며, 그 값을 무엇이라 부르는지만 다르다. 연락처는 자신을 가리키는 값을 이름으로 부르므로 이름순으로 알리고, 그 밖의 목록은 제목으로 부르므로 제목순으로 알린다. 어느 목록이 어느 이름을 쓰는지는 `적용 대상`이 정한다.

최근 수정순은 수정 시각이 늦은 항목을 먼저 놓는다. 수정 시각이 같은 항목끼리는 항목을 가리키는 값의 오름차순으로 놓고, 그 값까지 같은 항목끼리의 순서는 정하지 않는다.

수정 시각은 각 항목이 마지막으로 바뀐 시점이며, 항목을 완료하거나 다시 시작하거나 삭제하거나 되돌리는 것도 수정으로 본다. 항목의 태그 연결만 바뀐 경우는 그 항목의 수정으로 보지 않는다.

### 목록별 기본순

기본순의 실제 순서는 목록마다 다르다. 메모 목록의 기본순은 [MemoHome 목록 스펙](./memo-home.md)의 `정렬`이 정한 순서이며, 이 순서는 기간을 가진 메모를 사용자가 보는 순서대로 놓기 위한 것이므로 제목순과 다르다.

메모 목록이 아닌 목록의 기본순은 제목순 또는 이름순과 같으므로 사용자가 고를 수 있는 기준에서 뺀다. 같은 결과를 내는 기준을 두 개 두면 사용자가 둘의 차이를 찾게 된다.

### 처음 정렬

각 목록은 사용자가 아직 정렬을 고르지 않았을 때 다음 기준으로 시작한다.

| 목록 | 처음 정렬 |
| --- | --- |
| MemoHome 메모 목록 | 기본순 |
| MemoFinishedList 완료된 메모 목록 | 기본순 |
| TagDetail 메모 탭의 태그별 메모 목록 | 기본순 |
| TagMemoFinishedList 태그별 완료된 메모 목록 | 기본순 |
| ContactHome 연락처 목록 | 이름순 |
| 그 밖의 적용 대상 목록 | 제목순 |

처음 정렬은 각 목록이 사용자의 선택 없이 쓰는 순서와 같다. 사용자가 아무것도 고르지 않으면 그 목록이 원래 놓는 순서를 그대로 본다.

### 정렬과 그룹의 관계

정렬 기준은 목록이 항목을 묶어 표시하는 기준을 바꾸지 않는다. [MemoHome 목록 스펙](./memo-home.md)의 날짜 헤더는 기본순에서만 의미가 있는 묶음이므로, 기본순이 아닌 기준에서는 날짜 헤더를 두지 않고 항목만 순서대로 놓는다.

## data

### 정렬된 목록 조회

각 목록은 지금 선택된 정렬 기준을 조회 조건에 함께 넘겨 저장소에서 정렬된 순서로 조회한다. 조회한 뒤 기기에서 순서를 다시 매기지 않는다.

페이지 단위로 조회하는 목록은 선택된 기준의 순서대로 페이지를 이어서 조회한다. 페이지를 이어서 조회하는 기준은 [페이지 조회 목록의 자리 표시 스펙](./paged-list-placeholder.md)의 `페이지 조회`를 따른다.

정렬 기준이 바뀌면 그 목록의 조회를 새 기준으로 다시 시작하고, 이전 기준으로 준비해 둔 결과는 쓰지 않는다.

정렬 기준은 저장소에 남기지 않으며 서버와 동기화하지 않는다.
