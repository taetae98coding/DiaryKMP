# 위치 권한 요청 스펙

이 문서는 앱이 사용자에게 시스템 위치 권한을 요청하는 규칙을 다룬다. 모든 권한이 공유하는 요청 시점, 요청 기준, 요청 결과와 허용 여부 조회는 [권한 요청 공통 스펙](./permission.md)이 소유하고, 이 문서는 위치 권한에만 적용되는 부분을 다룬다.

확인한 위치를 무엇에 쓰는지는 [현재 위치 확인 스펙](./current-location.md)과 그 위치를 사용하는 기능의 스펙이 소유한다.

권한 요청은 시스템이 표시하므로 앱이 제공하는 화면이나 조작 수단이 없고, 저장하거나 동기화하는 데이터도 없다. 따라서 `data` 영역은 생략한다.

## feature

### 캘린더 홈 화면 진입 시 위치 권한 요청

사용자가 캘린더 홈 화면에 진입하면 위치 권한이 아직 허용되어 있지 않은 경우 시스템 위치 권한 요청이 표시된다. 요청에 응답했을 때 사용자가 보는 결과는 [권한 요청 공통 스펙](./permission.md)의 권한 요청 응답을 따른다.

요청에 응답한 뒤 캘린더 홈 화면에서 무엇이 달라지는지는 [CalendarHome 스펙](./calendar-home.md)의 위치 권한 요청이 다룬다.

## domain

### 요청 지점

위치 권한 요청 조건은 캘린더 홈 화면에 진입할 때 확인한다. 확인 시점과 다시 확인하는 기준은 [권한 요청 공통 스펙](./permission.md)의 요청 시점을 따른다.

캘린더 홈 화면 밖에서는 위치 권한을 요청하지 않는다. 지도를 표시하거나 현재 위치를 확인하는 과정에서도 요청하지 않는다.

### 요청 범위

지도처럼 정밀한 위치가 필요한 기능을 대비해 플랫폼이 제공하는 가장 정확한 위치 사용 권한을 요청한다. 시스템이 대략적인 위치만 허용하는 선택지를 제공해 사용자가 그렇게 허용한 경우에도 허용으로 본다.

웹은 위치 권한을 정확도별로 나누지 않으므로 하나의 위치 권한을 요청한다.

### 요청 제공 범위

위치 권한 요청은 Android, iOS와 웹에서 제공한다. 그 밖의 기준은 [권한 요청 공통 스펙](./permission.md)의 요청 제공 범위를 따른다.

웹에서 브라우저가 위치 기능을 제공하는지는 [현재 위치 확인 스펙](./current-location.md)의 디바이스 위치를 따른다.

### 요청 결과의 사용

사용자가 이번 요청에서 새로 허용한 경우에만 현재 위치의 날씨를 다시 동기화한다. 이미 허용되어 있어 요청을 표시하지 않았으면 다시 동기화하지 않는다. 재동기화가 동기화 간격을 어떻게 다루는지는 [현재 날씨 동기화 스펙](./weather-fetch.md)의 동기화 간격을 따른다.

요청 결과를 사용자 설정으로 저장하지 않으며, 앱 안에서 권한 상태를 다시 보여 주지 않는다. 거부해도 날씨는 [현재 위치 확인 스펙](./current-location.md)을 따라 공인 IP 기준 위치로 계속 제공된다.

### 허용 여부 조회

위치 권한 허용 여부는 요청과 별개로 확인할 수 있다. 확인 결과와 확인할 수 없는 환경의 처리는 [권한 요청 공통 스펙](./permission.md)의 허용 여부 조회를 따른다.

허용 여부에 따라 동작이 달라지는 기능은 [DiaryMap 컴포넌트 스펙](./diary-map.md)의 현 위치 표시와 [현재 위치 확인 스펙](./current-location.md)의 디바이스 위치다. 각 기능이 언제 확인하고 무엇에 반영할지는 그 문서가 정한다.
