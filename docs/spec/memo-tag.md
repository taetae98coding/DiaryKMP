# 메모 태그 스펙

이 문서는 하나의 메모가 여러 태그와 연결될 수 있다는 규칙 가운데 메모에만 해당하는 부분을 다룬다. 태그 연결이 공통으로 지키는 규칙은 [항목 태그 연결 공통 스펙](./entity-tag.md)을, 연결의 성질과 저장·동기화 계약은 [항목 연결 공통 스펙](./entity-link.md)을 따른다.

메모가 태그 하나를 대표 태그로 가지는 규칙은 [메모 대표 태그 스펙](./memo-primary-tag.md)을 따르고, 태그 자체의 추가·완료·삭제는 [TagAdd 화면 스펙](./tag-add.md)과 [TagDetail 화면 스펙](./tag-detail.md)을 따른다.

사용자가 태그를 고르고 해제하는 조작은 이 문서에서 다루지 않는다. 태그 선택의 행동과 정책은 [메모 태그 입력 컴포넌트 스펙](./memo-tag-input.md)에서, 구체적인 표현과 조작 수단은 [메모 태그 입력 컴포넌트 디자인](../design/memo-tag-input.md)에서 다룬다. 메모를 추가하면서 태그를 연결하는 행동은 [MemoAdd 화면 스펙](./memo-add.md)에서, 이미 저장된 메모의 태그 연결을 바꾸는 행동은 [MemoDetail 화면 스펙](./memo-detail.md)에서, 태그로 메모를 찾아보는 목록은 [TagDetail 메모 탭 스펙](./tag-detail-memo.md)에서 다룬다. 이 문서에는 사용자 조작이 없어 `feature` 영역을 생략한다.

메모와 장소의 연결은 이 문서가 다루는 연결과 별개이며 [메모 장소 스펙](./memo-place.md)이 소유한다.

## domain

### 연결이 바꾸지 않는 내용

연결은 메모와 태그 사이의 관계이며, 메모의 제목·설명·컬러·기간이나 태그의 이모지·제목·설명·컬러를 바꾸지 않는다.

### 대표 태그와의 관계

메모는 [항목 태그 연결 공통 스펙](./entity-tag.md)의 `대표 태그`에서 대표 태그를 갖는 유일한 예외이며, 사용자가 기기에서 지정하는 메모의 대표 태그는 그 메모와 연결된 태그 중 하나다.

사용자가 기기에서 대표 태그로 지정한 태그는 같은 저장 작업에서 그 메모의 연결된 태그에도 포함된다. 사용자 행동의 기기 저장 결과로 연결되지 않은 태그만 대표 태그로 지정된 상태는 허용하지 않는다.

사용자가 기기에서 태그와 메모의 연결을 해제하면 같은 저장 작업에서 그 태그의 대표 태그 지정도 함께 해제된다.

서버 동기화에서는 메모와 연결을 별도 종류로 반영하므로 이 관계가 항상 성립한다고 보장하지 않는다. 허용하는 중간 상태와 여러 기기 충돌 뒤의 복구 범위는 [데이터 동기화 스펙](./data-sync.md)의 `동기화 단계와 처리 순서`를 따른다.

## data

### 대표 태그를 함께 바꾸는 저장

연결 해제와 대표 태그 지정 해제, 대표 태그 지정과 연결 생성처럼 연결과 메모를 함께 바꿔야 하는 경우에도 기기의 하나의 저장 작업으로 함께 반영해 한쪽만 반영된 기기 상태가 남지 않게 한다.

대표 태그 지정이 포함된 메모와 그 태그 연결은 서로 다른 요청으로 동기화된다. 반영 순서에 따른 중간 상태, 실패한 연결의 재시도와 여러 기기 충돌 뒤의 복구 범위는 [데이터 동기화 스펙](./data-sync.md)의 `동기화 단계와 처리 순서`를 따른다.
