# FCM 토큰 등록 스펙

이 문서는 로그인한 사용자의 기기가 서버에서 푸시 알림을 받을 수 있도록 FCM 토큰과 함께 필요한 기기 정보를 서버에 등록하고, 로그인하지 않은 기기의 토큰을 서버에서 해제하는 규칙을 다룬다.

이 문서는 토큰의 등록과 해제까지만 다룬다. 등록된 토큰으로 서버가 어떤 알림을 언제 보내는지는 이 문서의 범위가 아니며, 알림마다 그 알림의 스펙이 소유한다. 현재 등록된 토큰으로 보내는 알림은 [일일 메모 알림 스펙](./daily-memo-notification.md)이 소유한다.

등록과 해제는 화면 없이 앱 내부에서 진행되고 사용자가 직접 조작하는 수단이 없으므로 `feature` 영역을 생략한다.

현재 사용자 계정과 세션 갱신 여부는 [계정 조회 스펙](./account.md)을, 로그인 완료 기준은 [Login 화면 스펙](./login.md)을, 로그아웃 절차는 [MoreHome 화면 스펙](./more-home.md)을 따른다.

## domain

### 제출

기기는 정해진 계기마다 자기 상태를 서버에 한 번 제출한다. 제출은 현재 계정 상태에 따라 등록과 해제 중 하나다.

- 등록: 현재 계정이 사용자이고 세션이 갱신된 상태면 토큰과 기기 정보를 그 계정에 연결한다.
- 해제: 현재 계정이 게스트면 서버에서 이 토큰을 지운다. 로그아웃한 기기에 이전 계정의 알림이 도착하지 않게 하기 위해서다.

사용자 정보는 있지만 세션이 아직 갱신되지 않은 동안에는 등록도 해제도 하지 않는다. 등록은 인증된 세션이 있어야 요청할 수 있고, 로그인한 사용자의 토큰을 지워서는 안 되기 때문이다. 세션이 갱신되면 다음 계기에 등록한다.

기기는 마지막으로 제출한 내용을 기억하지 않고 계기마다 현재 값을 그대로 다시 제출한다. 서버는 같은 토큰을 다시 받으면 새 값으로 바꾸고 없는 토큰의 해제를 정상으로 끝내므로, 같은 내용을 반복해 제출해도 결과는 달라지지 않는다.

계정 상태와 세션 갱신 여부의 기준은 [계정 조회 스펙](./account.md)을 따른다.

```mermaid
flowchart TD
    Trigger["제출 계기"] --> Platform{"Android 또는<br/>iOS인가"}
    Platform -- 아니오 --> Skip["제출하지 않음"]
    Platform -- 예 --> Token{"기기에 토큰이<br/>있는가"}
    Token -- 아니오 --> Skip
    Token -- 예 --> Account{"현재 계정"}
    Account -- "게스트" --> Delete["서버에 해제 요청"]
    Account -- "사용자, 세션 미갱신" --> Skip
    Account -- "사용자, 세션 갱신됨" --> Register["서버에 등록 요청"]
    Register --> Result{"성공했는가"}
    Delete --> Result
    Result -- 예 --> Done["끝"]
    Result -- 아니오 --> Retry["다음 계기에 다시 제출"]
```

### 등록하는 기기

토큰 제출은 Android와 iOS에서만 제공한다.

JVM 데스크톱과 웹에서는 토큰을 제출하지 않는다. JVM 데스크톱에는 FCM으로 알림을 받을 수단이 없고, 웹은 서버 푸시 알림을 제공하지 않는다. 두 환경에서 알림을 제공하지 않는다는 결정은 [일일 메모 알림 스펙](./daily-memo-notification.md)의 `알림을 받는 기기`가 소유한다.

제출하지 않는 환경에서도 앱의 다른 기능은 그대로 사용할 수 있고, 제출하지 않는다는 안내는 표시하지 않는다.

### 등록 정보

등록에는 다음 세 값을 함께 담는다. 서버가 알림을 보낼 때 어느 기기에 언제 어떤 언어로 보낼지 정하는 데 필요한 값이다.

| 값 | 뜻 |
| --- | --- |
| FCM 토큰 | FCM이 이 기기의 이 앱 설치에 발급한 값. 서버가 알림을 보낼 대상을 가리킨다. |
| 시간대 | 기기가 현재 사용하는 시간대의 식별자. 예: `Asia/Seoul` |
| 언어 | 기기가 현재 사용하는 언어 태그. 예: `ko-KR` |

시간대와 언어는 사용자가 앱 안에서 고르는 값이 아니라 기기 설정에서 오는 값이다. 앱은 이 값을 바꾸는 수단을 제공하지 않는다. 기기의 시간대나 언어가 바뀐 것은 그 자체로 계기가 아니며, 바뀐 뒤 처음 오는 계기의 등록에 새 값이 담긴다. 따라서 앱을 열지 않은 채 시간대를 바꾸면 다음에 앱을 열기 전까지 서버는 이전 시간대를 가진다.

FCM 토큰은 앱이 정하지 않고 FCM이 발급하며, 앱 설치 단위로 유지된다. FCM이 토큰을 새로 발급하면 이전 토큰은 더 이상 이 기기를 가리키지 않고, 새 토큰은 다음 계기의 제출에 담긴다. 해제에는 토큰만 담는다.

제출 시점에 기기가 아직 토큰을 받지 못했으면 그 계기에는 제출하지 않고 다음 계기에 제출한다. 토큰을 받아 오는 데 실패한 것은 제출 실패이며 `실패 처리`를 따른다.

알림 권한은 제출과 무관하다. 알림 권한이 거부되어 있어도 토큰은 등록한다. 권한이 거부된 기기에 서버가 알림을 보내면 사용자에게 보이지 않을 뿐이며, 그 판정은 각 알림의 스펙이 소유한다. 권한 요청 자체는 [알림 권한 요청 스펙](./notification-permission.md)을 따른다.

### 제출 계기

다음 계기에 제출한다.

- 앱이 시작되어 계정이 확인되었을 때
- 앱이 다시 활성 상태가 되어 계정이 확인되었을 때. 활성 상태의 기준은 [데이터 동기화 스펙](./data-sync.md)의 `동기화 계기`에 있는 플랫폼별 기준과 같다.
- 앱을 사용하는 동안 로그인이 완료되어 인증된 계정이 확인되었을 때
- 확인된 계정이 다른 계정으로 바뀌었을 때. 로그아웃되어 게스트로 바뀐 것도 여기에 든다.

같은 계정이 다시 확인되기만 한 것은 계기가 아니다. 다만 앱이 다시 활성 상태가 되면 계정이 그대로여도 계기가 된다. FCM이 토큰을 새로 발급한 것도 그 자체로는 계기가 아니며, 바뀐 토큰은 다음 계기에 제출된다.

### 한 토큰과 한 계정

하나의 토큰은 한 시점에 하나의 계정에만 연결된다.

같은 기기에서 다른 계정으로 로그인해 같은 토큰이 다른 계정으로 등록되면, 서버는 그 토큰의 연결 계정을 새 계정으로 바꾼다. 이전 계정에는 이 토큰이 남지 않는다.

한 계정은 여러 기기의 토큰을 가질 수 있다. 같은 계정으로 여러 기기에서 로그인하면 기기마다 토큰이 따로 등록되고, 한 기기의 등록이나 해제가 다른 기기의 토큰에 영향을 주지 않는다.

### 로그아웃과 해제

로그아웃은 토큰 해제를 기다리지 않는다. 로그아웃하면 세션이 제거되어 계정이 게스트로 바뀌고, 그 변화가 `제출 계기`가 되어 해제를 제출한다. 네트워크 연결이 없어도 로그아웃은 그대로 끝난다.

해제 제출이 실패하면 다음 계기에 다시 제출한다. 해제가 서버에 반영되기 전까지 서버는 이 토큰을 이전 계정의 기기로 보므로, 로그아웃한 뒤 다음 계기까지 그 계정의 알림이 이 기기에 도착할 수 있다. 서버가 오래 남은 토큰을 정리하는 기준은 [일일 메모 알림 스펙](./daily-memo-notification.md)의 `오래 남은 토큰의 정리`가 소유한다.

로그아웃 확인 다이얼로그에서 취소를 고르면 계정이 바뀌지 않으므로 해제하지 않는다. 다이얼로그 규칙은 [MoreHome 화면 스펙](./more-home.md)의 `로그아웃 확인`을 따른다.

### 실패 처리

제출에 실패해도 사용자에게 알리지 않고 앱의 다른 기능은 그대로 진행된다. 실패한 제출은 다음 계기에 다시 시도하며, 같은 계기 안에서 곧바로 다시 시도하지 않는다.

제출 실패는 오류 보고 대상이다. 오프라인이나 통신 오류로 인한 실패도 보고에서 제외하지 않는다. 보고 방식은 [UseCase 실패 로깅](./usecase-failure-logging.md)의 오류 보고를 따르고, 등록과 해제 중 무엇이 실패했는지는 보고에 담긴 실패 원인으로 구분한다.

앱 종료나 화면 이탈로 진행 중인 제출이 중단된 것은 실패가 아니며 보고하지 않는다. 중단된 제출은 다음 계기에 다시 시도된다.

### 실행 경계

화면이 재생성되거나 앱이 백그라운드에 갔다가 돌아오는 것만으로는 제출하지 않는다. 앱이 다시 활성 상태가 되어 계정이 확인되면 `제출 계기`에 따라 제출한다.

앱을 삭제하고 다시 설치하면 FCM 토큰이 새로 발급되므로 로그인 뒤 첫 계기에 새 토큰을 등록한다. 삭제 전 토큰은 서버에 남을 수 있으며, 그 정리는 [일일 메모 알림 스펙](./daily-memo-notification.md)의 `오래 남은 토큰의 정리`를 따른다.

## data

### 서버에 저장하는 정보

서버는 토큰 하나를 한 건으로 저장하고, 각 건은 연결된 계정, 시간대, 언어, 마지막으로 등록된 시각을 가진다.

같은 토큰이 다시 등록되면 새 건을 만들지 않고 그 건의 계정, 시간대, 언어, 시각을 새 값으로 바꾼다.

계정이 삭제되면 그 계정에 연결된 토큰 건도 함께 삭제된다.

토큰 건은 계정 데이터가 아니므로 [데이터 동기화 스펙](./data-sync.md)의 동기화 대상이 아니다. 기기로 내려받지 않고, 업로드 대기 상태를 갖지 않으며, 서버 변경 순번을 부여하지 않는다. 기기에도 제출 내용을 저장하지 않는다.

### 제출 요청

등록과 해제는 같은 제출 요청으로 보내고, 요청에 담긴 내용으로 구분한다.

- 등록 요청은 토큰, 시간대, 언어를 담고 인증된 로그인 세션으로 보낸다. 연결할 계정은 세션의 계정이며 요청에 따로 담지 않는다. 서버는 세션이 없거나 인증되지 않은 등록 요청을 거절한다.
- 해제 요청은 토큰만 담고 세션 없이 보낸다. 게스트 상태에는 세션이 없기 때문이다. 서버는 그 토큰 건을 연결 계정과 무관하게 지우고, 없는 토큰이면 아무것도 바꾸지 않은 채 성공으로 끝낸다.

해제 요청은 토큰만으로 처리되므로 토큰을 아는 쪽은 누구든 그 토큰을 해제할 수 있다. 토큰은 발급받은 기기와 서버만 알고, 해제되어도 알림이 오지 않는 것 이상의 영향이 없어 이를 받아들인다.
