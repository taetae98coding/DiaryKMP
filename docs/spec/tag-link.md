# 태그 연결 스펙

이 문서는 하나의 태그가 다른 태그로 향하는 단방향 연결을 가질 수 있다는 규칙 가운데 태그와 태그의 연결에만 해당하는 부분을 다룬다. 연결의 성질과 저장·동기화 계약은 [항목 연결 공통 스펙](./entity-link.md)을 따른다.

태그 자체의 추가·수정·완료·삭제는 [TagAdd 화면 스펙](./tag-add.md)과 [TagDetail 화면 스펙](./tag-detail.md)을 따르고, 메모·웹 항목·장소와 태그의 연결은 [항목 태그 연결 공통 스펙](./entity-tag.md)과 각 연결 스펙을 따른다.

사용자가 연결을 만들고 해제하는 조작과 연결된 태그를 화면에 보여 주는 방법은 [태그 연결 입력 컴포넌트 스펙](./tag-link-input.md)이 소유하므로 이 문서에는 `feature` 영역을 두지 않는다.

## domain

### 태그와 태그의 연결

태그 연결은 한 태그에서 다른 태그로 향하는 단방향 관계다. 연결은 출발 태그 하나와 도착 태그 하나를 가진다.

하나의 태그는 여러 태그로 향하는 연결을 가질 수 있고, 여러 태그로부터 향해 오는 연결을 받을 수 있다.

출발 태그와 도착 태그를 바꾼 반대 방향의 연결은 별개의 연결이다. 두 방향의 연결이 함께 있어도 허용하며, 한 방향을 해제해도 반대 방향은 해제되지 않는다.

태그를 자기 자신과 연결할 수 없다. 출발 태그와 도착 태그가 같은 연결은 만들 수 없다.

연결은 태그 사이의 관계이며, 어느 쪽 태그의 이모지·제목·설명·컬러도 바꾸지 않는다.

### 연결의 의미

태그 연결은 태그 사이의 관계를 나타내는 것으로 끝난다. [항목 연결 공통 스펙](./entity-link.md)의 `연결의 의미`는 태그 연결에서 다음에 적용된다.

- 태그별 메모, 웹 항목, 장소 조회 결과. 연결을 따라 다른 태그의 메모나 웹 항목이나 장소가 함께 조회되지 않는다. 사용자가 표시 범위를 넓혀 둔 동안의 TagDetail 화면 메모·웹·장소 탭만 예외이며, 그 기준은 [TagDetail 화면 스펙](./tag-detail.md)의 `표시 범위`를 따른다.
- 태그 필터와 캘린더 필터의 결과. 자세한 기준은 [태그 필터 스펙](./tag-filter.md)을 따른다.
- 메모와 태그의 연결, 웹 항목과 태그의 연결, 장소와 태그의 연결. 태그를 연결해도 그 항목들에 연결된 태그는 늘어나지 않는다. 각 연결의 규칙은 [항목 태그 연결 공통 스펙](./entity-tag.md)을 따른다.

위 예외를 빼면 연결을 따라 메모나 웹 항목이나 장소를 모으지 않으므로 연결이 순환을 이루어도 결과에 영향을 주지 않는다. 순환하는 연결과 여러 단계로 이어지는 연결에 별도의 제한을 두지 않으며, 연결을 따라가는 조회가 순환에서 어떻게 끝나는지는 `하위 태그의 조회`를 따른다.

### 연결된 태그의 조회

출발 태그를 기준으로 그 태그에서 향해 나가는 연결의 도착 태그를 조회한다. 조회에 포함되는 연결과 태그의 기준은 [항목 연결 공통 스펙](./entity-link.md)의 `연결된 항목의 조회`를 따르므로, 완료된 태그는 포함되고 삭제된 태그는 포함되지 않는다.

조회 결과는 태그 제목 오름차순으로 놓인다.

### 하위 태그의 조회

기준 태그의 `하위 태그`는 그 태그를 출발 태그로 하는 연결의 도착 태그다. 어떤 연결과 태그가 포함되는지는 `연결된 태그의 조회`와 같으므로 완료된 태그는 포함되고, 삭제된 태그와 기기에 아직 없는 태그는 포함되지 않는다.

기준 태그의 `후손 태그`는 하위 태그와, 그 하위 태그를 다시 기준으로 삼아 같은 조회를 연결이 이어지는 동안 반복해 얻은 태그 전체다. 조회에 포함되지 않는 태그에서는 더 따라가지 않으므로, 삭제된 태그를 지나 이어지는 연결은 후손 태그에 닿지 않는다.

이미 얻은 태그는 다시 따라가지 않는다. 따라서 연결이 순환을 이루거나 서로 다른 경로가 같은 태그에 닿아도 조회는 끝나며, 같은 태그가 결과에 두 번 나타나지 않는다.

기준 태그 자신은 하위 태그에도 후손 태그에도 포함되지 않는다. 기준 태그를 함께 다룰지는 이 조회를 사용하는 화면이 정한다.

이 조회를 사용하는 곳은 [TagDetail 화면 스펙](./tag-detail.md)의 `표시 범위`다.

### 향해 오는 연결의 존재 판정

한 태그를 기준으로 그 태그를 향해 오는 연결이 하나라도 있는지 판정할 수 있다. 이 판정은 [TagHome 목록 스펙](./tag-home.md)의 `최상위 태그 판정 기준`이 사용한다.

판정에는 해제되지 않은 연결만 세며, 출발 태그가 판정하는 계정과 연결되어 있고 삭제되지 않은 연결만 센다. 출발 태그가 완료된 연결은 센다. 따라서 향해 오는 연결이 모두 삭제된 태그에서 오면 그 태그는 향해 오는 연결이 없는 것으로 판정한다.

기기에 아직 없는 태그에서 오는 연결은 판정에 쓰지 않는다.

세는 기준은 `연결된 태그의 조회`와 방향만 반대이고 나머지는 같으며, 판정 결과는 향해 오는 연결이 있는지 없는지로만 쓰인다.

### 태그의 상태 변화와 연결

태그를 완료하거나 삭제해도 연결이 해제되지 않는 기준은 [항목 연결 공통 스펙](./entity-link.md)의 `항목의 상태 변화와 연결`을 따른다.

태그를 삭제하면 그 태그에서 향해 나가는 연결은 도착 태그의 `향해 오는 연결의 존재 판정`에서 빠지고, 실행 취소로 되살리면 다시 포함된다. 태그를 완료하거나 다시 시작하는 것은 그 판정을 바꾸지 않는다.

## data

### 내려받기 순서와 판정

기기에 아직 없는 태그를 가리키는 연결은 [항목 연결 공통 스펙](./entity-link.md)의 `내려받기 순서와 표시`에 따라 `연결된 태그의 조회`에 쓰이지 않으며, `향해 오는 연결의 존재 판정`에도 쓰이지 않는다. 그 태그가 기기에 반영되면 두 결과에 함께 나타난다.
