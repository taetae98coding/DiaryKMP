# 항목 추가 화면 공통 스펙

이 문서는 새 항목 하나를 입력해 추가하는 화면들이 공통으로 보장하는 작성 상태 유지, 추가 요청 제한, 계정 연결과 저장 계약을 다룬다. 어떤 입력을 제공하는지, 추가 성립 조건이 무엇인지, 조건을 만족하지 않을 때 무엇을 알리는지는 화면마다 다르므로 각 화면 스펙에서 다룬다.

이 문서를 따르는 화면 스펙은 다음과 같다.

- [ContactAdd 화면 스펙](./contact-add.md)
- [MemoAdd 화면 스펙](./memo-add.md)
- [MusicAdd 화면 스펙](./music-add.md)
- [PlaceAdd 화면 스펙](./place-add.md)
- [RoutineAdd 화면 스펙](./routine-add.md)
- [TagAdd 화면 스펙](./tag-add.md)
- [WebAdd 화면 스펙](./web-add.md)

이 문서에서 `대상 항목`은 그 화면이 추가하는 연락처, 메모, 곡, 장소, 루틴, 태그 또는 웹 항목 하나를 가리킨다.

태그를 함께 고르는 입력의 행동과 판정 기준은 [태그 선택 입력 공통 스펙](./tag-select-input.md)을, 함께 만들어지는 연결의 규칙은 [항목 연결 공통 스펙](./entity-link.md)을 따른다.

## feature

### 작성 상태 유지

화면이 회전하거나 시스템에 의해 재생성되어도 입력 중이던 내용과 사용자가 고른 선택을 유지한다.

앱을 종료한 뒤 화면에 새로 진입하면 이전 작성 내용을 복원하지 않고 새로운 입력 상태로 시작한다.

어떤 입력과 선택이 유지 대상인지, 시스템이 앱을 메모리에서 정리한 뒤 복원할 때 무엇을 복원하지 않는지는 각 화면 스펙에서 정한다.

### 뒤로가기

사용자가 뒤로가면 그 화면에 진입하기 전 화면으로 돌아간다.

### 태그 입력

태그 입력을 제공하는 화면에서 사용자가 반영한 선택은 추가할 대상 항목의 연결 대상으로만 반영되며, 이미 저장된 다른 항목의 태그 연결을 바꾸지 않는다. 선택한 태그가 실제로 연결되는 시점은 사용자가 추가를 실행할 때다.

태그 선택은 추가 성립 조건이 아니다. 태그를 하나도 고르지 않아도 대상 항목을 추가할 수 있다.

### 저장 실패

저장에 실패하면 실패를 그대로 알리며 성공으로 바꾸지 않는다.

## domain

### 태그 선택과 추가 성립 조건

선택할 수 있는 태그의 기준과 선택 여부의 판정은 [태그 선택 입력 공통 스펙](./tag-select-input.md)의 `domain`을 따른다.

추가 화면에서 표시 대상 태그는 선택할 수 있는 태그와 같다. 아직 저장되지 않은 항목의 연결이므로 사용자가 지금 고를 수 있는 태그만 표시하며, 완료되거나 삭제된 태그는 표시 대상으로 삼지 않는다.

### 추가되는 항목의 태그 연결

대상 항목을 추가하면 추가 시점에 고른 태그와 새 항목의 연결이 함께 만들어진다. 연결의 규칙과 기록되는 내용은 각 연결 스펙과 [항목 연결 공통 스펙](./entity-link.md)을 따른다.

연결되는 태그는 사용자가 고른 그대로다. 고른 뒤 태그가 완료되거나 삭제되어 태그 입력이 제외된 것으로 표시하고 있어도, 추가 시점에 그 선택을 다시 판정하지 않고 그대로 연결한다.

태그를 하나도 고르지 않았으면 연결 없이 항목이 추가된다.

### 추가 요청 제한

추가를 처리하는 동안에는 같은 화면에서 전달된 추가 요청을 처리하지 않는다. 이 제한은 한 번의 입력으로 같은 항목이 중복 추가되는 것을 막기 위한 것이며, 처리가 끝나면 사용자는 다시 추가할 수 있다.

### 추가되는 항목의 내용

새 항목에는 같은 종류의 다른 항목과 겹치지 않는 고유 식별자를 부여한다.

항목에는 사용자가 입력한 내용을 기록한다. 사용자가 입력하지 않은 선택 입력은 빈 값으로 기록하고, 사용자가 바꾸지 않은 무작위 초기값은 처음 제시한 값을 그대로 기록한다.

새 항목은 삭제되지 않은 상태로 생성한다. 완료 여부가 있는 항목은 완료되지 않은 상태로 생성한다.

생성 시각과 수정 시각은 항목이 추가된 시각으로 동일하게 기록한다.

어떤 값이 기록되는지는 각 화면 스펙에서 정한다.

### 항목의 계정 연결

항목은 특정 계정을 단일 소유자로 갖지 않으며 하나 이상의 계정이나 그룹과 연결될 수 있다. 하나의 항목이 여러 계정이나 그룹과 연결되어도 항목의 내용과 상태는 연결마다 복제되지 않고 공유된다.

새 항목은 현재 사용자 계정과 연결한다. 그룹과의 연결은 후속 범위에서 다룬다.

계정 조회 규칙은 [계정 조회 스펙](./account.md)을 따른다. 현재 계정을 확인할 수 없으면 계정과의 연결을 만들 수 없으므로 항목을 추가하지 않는다.

## data

### 생성과 저장

사용자가 추가 성립 조건을 만족하는 내용으로 추가를 실행하면 새 항목, 현재 사용자 계정의 연결, 그리고 함께 만드는 연결을 하나의 저장 작업으로 로컬 저장한다. 하나의 저장 작업으로 함께 반영하는 기준은 [항목 연결 공통 스펙](./entity-link.md)의 `연결의 저장`을 따르므로, 일부만 저장된 기기 상태는 남지 않는다.

이미 같은 식별자의 항목이 있으면 덮어쓰고 없으면 새로 추가하는 방식으로 저장한다.

항목에 딸린 순서 있는 목록은 항목과 함께 저장하며, 항목을 조회하면 저장한 순서 그대로 함께 조회된다.

### 동기화

추가한 항목은 계정과 연결된 항목으로 서버에 반영된다. 로컬 저장이 끝나면 그 항목과 함께 만들어진 연결이 업로드 대기로 기록되고 백그라운드 동기화가 시작되며, 업로드 단위와 충돌 기준, 실패 시 재시도는 [데이터 동기화 스펙](./data-sync.md)의 규칙을 따른다. 항목과 연결은 서로 다른 종류로 반영되며, 그 선후 관계와 허용하는 중간 상태는 같은 문서의 `동기화 단계와 처리 순서`를 따른다.

추가의 성공 여부는 로컬 저장 결과로만 판단하며 서버 반영 결과를 기다리지 않는다. 동기화에 실패해도 추가한 항목은 기기에서 사라지지 않고 다음 동기화 계기에서 다시 시도된다.

로그인하지 않은 상태에서 추가한 항목은 서버에 반영되지 않고 기기 안에만 유지된다.

[데이터 동기화 스펙](./data-sync.md)의 동기화 대상 종류에 없는 항목은 이 절을 적용하지 않고 기기 안에만 유지된다. 어떤 항목이 여기에 해당하는지는 각 화면 스펙에서 밝힌다.

### 태그 목록 조회

태그 입력의 선택 목록과 표시 대상 태그에 쓰는 태그 조회는 [태그 선택 입력 공통 스펙](./tag-select-input.md)의 `태그 목록 조회`를 따른다. 추가 화면은 선택할 수 있는 태그만 조회한다.
