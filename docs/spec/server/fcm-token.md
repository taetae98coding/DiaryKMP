# 푸시 알림 수신 등록 스펙

이 문서는 서버가 기기의 푸시 알림 수신 등록과 해제를 받아 검증하고 저장하는 처리를 다룬다.

주고받는 정보와 그 의미는 [푸시 알림 수신 등록 스펙(common)](../common/fcm-token.md)을, 앱이 언제 등록하고 해제하는지는 [푸시 알림 수신 등록 스펙(client)](../client/fcm-token.md)을 따른다. 오래 남은 등록을 정리하는 기준은 [일일 메모 알림 스펙(server)](./daily-memo-notification.md)의 `오래 남은 수신 정보의 정리`가 소유한다.

## domain

### 한 기기와 한 계정

하나의 푸시 알림 수신 정보는 한 시점에 하나의 계정에만 연결된다.

같은 기기에서 다른 계정으로 로그인해 같은 수신 정보가 다른 계정으로 등록되면, 서버는 그 수신 정보의 연결 계정을 새 계정으로 바꾼다. 이전 계정에는 이 기기가 남지 않는다.

한 계정은 여러 기기를 가질 수 있다. 같은 계정으로 여러 기기에서 로그인하면 기기마다 따로 등록되고, 한 기기의 등록이나 해제가 다른 기기의 등록에 영향을 주지 않는다.

## data

### 등록 처리

서버는 다음을 모두 만족하는 등록만 받는다.

- 인증된 로그인 세션으로 보낸 요청이다. 세션이 없거나 인증되지 않은 등록은 거절한다.
- 푸시 알림 수신 정보, 시간대, 언어가 모두 비어 있지 않다.

서버는 시간대 이름이 서버가 아는 이름인지 등록할 때 확인하지 않는다. 서버가 알아보지 못하는 시간대로 등록된 기기에는 알림을 보내지 않으며, 그 기준은 [일일 메모 알림 스펙(server)](./daily-memo-notification.md)의 `발송 대상`을 따른다.

받은 등록은 수신 정보 하나를 한 건으로 저장하고, 각 건은 연결된 계정, 시간대, 언어, 마지막으로 등록된 시각을 가진다.

같은 수신 정보가 다시 등록되면 새 건을 만들지 않고 그 건의 계정, 시간대, 언어, 마지막 등록 시각을 새 값으로 바꾼다.

### 해제 처리

서버는 해제를 로그인 세션 없이 받는다. 수신 정보가 비어 있으면 거절한다.

해제는 그 수신 정보의 건을 연결 계정과 무관하게 지운다. 등록되지 않은 수신 정보이면 아무것도 바꾸지 않고 성공으로 끝낸다.

해제는 수신 정보만으로 처리되므로 수신 정보를 아는 쪽은 누구든 그 기기를 해제할 수 있다. 수신 정보는 발급받은 기기와 서버만 알고, 해제되어도 알림이 오지 않는 것 이상의 영향이 없어 이를 받아들인다.

### 저장한 정보의 보호

앱은 서버에 저장된 등록 정보를 읽을 수 없고, 등록과 해제로만 다룬다. 다른 계정의 등록 정보도 알 수 없다.

계정이 삭제되면 그 계정에 연결된 등록 건도 함께 삭제된다.

등록 건은 계정 데이터가 아니므로 [데이터 동기화 스펙](../common/data-sync.md)의 동기화 대상이 아니다. 기기로 내려보내지 않고, 서버 변경 순번을 부여하지 않는다.

### 처리 실패

서버가 등록이나 해제를 처리하지 못하면 실패를 돌려주고 저장된 정보를 바꾸지 않는다. 다시 제출하는 기준은 [푸시 알림 수신 등록 스펙(client)](../client/fcm-token.md)의 `실패 처리`를 따른다.
