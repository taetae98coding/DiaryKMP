# 로그인 스펙

이 문서는 서버가 Google과 Apple의 인증 결과를 검증해 로그인 세션을 만들고 계정을 정하는 처리와, Apple 웹 로그인의 응답을 앱으로 넘겨주는 중계를 다룬다.

앱과 서버가 주고받는 정보와 그 의미는 [로그인 스펙(common)](../common/login.md)을, 사용자가 로그인하는 화면과 앱의 처리는 [Login 화면 스펙](../client/login.md)을 따른다. 로그인할 때 계정의 프로필 이미지를 정하는 규칙은 [프로필 이미지 변경 스펙(server)](./profile-image.md)의 `로그인 시 프로필 이미지`가 소유한다.

## domain

### 인증 수단과 계정 동일성

앱 계정의 동일성은 인증 수단이 아니라 검증된 이메일로 판단한다.

두 인증 수단이 같은 이메일을 제공하면 사용자가 Google 로그인과 Apple 로그인 중 무엇을 사용하든 같은 앱 계정으로 본다. 이미 그 이메일의 계정이 있으면 새 인증 수단을 기존 계정에 연결하고 새 계정을 만들지 않는다.

사용자가 Apple 로그인에서 이메일 가리기를 선택하면 Apple의 비공개 중계 이메일을 받게 되므로, 같은 사람이더라도 별개 계정으로 본다. 서버는 가리기 여부와 관계없이 받은 이메일을 그대로 계정 이메일로 쓰고, 사용자가 이메일 가리기를 선택하지 못하게 막지 않는다.

이때 받는 이메일은 같은 사용자와 같은 앱에 대해 유지되므로, 이후 Apple 로그인을 다시 해도 처음 만들어진 같은 계정으로 들어온다.

이렇게 나뉜 두 계정을 사용자가 하나로 합치는 방법은 아직 정의하지 않았다(미정).

### 처음 로그인하는 사용자

처음 로그인하는 사용자라면 검증된 인증 결과의 이메일로 앱 계정을 만든다. 로그인 수단이 프로필 이미지를 제공하면 그 이미지를 계정의 첫 프로필 이미지로 둔다. 기존 사용자는 기존 계정을 그대로 쓴다.

## data

### 인증 결과 검증

서버는 앱이 보낸 인증 결과를 해당 인증 제공자의 인증 정보로 검증하고, 검증에 성공한 경우에만 로그인 세션을 발급한다. 검증에 실패하면 세션을 발급하지 않고 요청을 거절한다.

| 인증 결과 | 서버가 확인하는 것 |
| --- | --- |
| Google 신원 증명 | Google이 이 앱을 대상으로 발급했는지, 같은 로그인 시도의 시도 확인 값과 맞는지 |
| Google 인가 코드 | 요청에 담긴 앱 식별 값이 서버가 아는 이 앱의 값인지. 인가 코드를 Google 신원 증명으로 바꾼 뒤 신원 증명과 같은 절차로 검증한다 |
| Apple 신원 증명 | Apple이 이 앱을 대상으로 발급했는지, 같은 로그인 시도의 시도 확인 값과 맞는지 |

이 앱을 대상으로 발급된 인증 결과는 플랫폼마다 발급 대상이 다르며, 서버는 앱이 지원하는 모든 플랫폼의 발급 대상을 이 앱으로 인정한다.

Google 인가 코드에 코드 확인 값이 함께 오면 서버는 그 값으로 인가 코드를 바꾼다. 코드 확인 값이 정해진 형식이 아니면 요청을 거절하고, 코드 확인 값이 맞지 않거나 인가 코드를 바꾸는 데 실패하면 세션을 발급하지 않는다. 서버가 모르는 앱 식별 값으로 온 인가 코드도 거절한다.

서버는 받은 인증 결과를 저장하지 않는다.

### 세션 발급

검증에 성공하면 서버는 계정을 정한 뒤 로그인 세션 정보를 앱에 돌려준다. 계정을 정하는 기준은 `domain > 인증 수단과 계정 동일성`과 `domain > 처음 로그인하는 사용자`를 따른다. 로그인 수단이 제공한 사용자 정보로 계정의 사용자 정보를 갱신하며, 그때의 프로필 이미지 규칙은 [프로필 이미지 변경 스펙(server)](./profile-image.md)을 따른다.

세션을 발급한 뒤 앱이 세션 설정에 실패해도 서버는 만든 계정을 자동으로 지우지 않는다.

### Apple 웹 로그인 중계

Apple은 웹 로그인의 응답을 보안 연결 주소로만 보내므로, 서버는 Apple의 응답을 대신 받아 앱으로 넘겨준다. 이 주소를 서버의 Apple 응답 수신 주소라 한다.

서버는 Apple이 응답을 보내는 방식(양식 전송)으로 온 요청만 받고, 그 밖의 방식이나 내용을 읽을 수 없는 요청은 거절한다. 요청이 Apple에서 왔는지는 확인하지 않으며, 넘긴 신원 증명은 `인증 결과 검증`에서 검증된다.

서버는 응답의 상태 값에서 앱 복귀 주소를 읽고, 그 주소가 다음 중 하나일 때만 응답을 넘긴다. 앱 복귀 주소를 읽을 수 없거나 그 외 주소이면 어떤 값도 넘기지 않고 요청을 거절한다.

| 플랫폼 | 허용하는 앱 복귀 주소 |
| --- | --- |
| Android | 앱 고유 이름(개발용과 배포용)로 시작하는 Apple 로그인 전용 앱 주소 |
| 데스크톱 | 기기 안에서만 열리는 로컬 주소(`127.0.0.1`)의 로그인 수신 경로 |
| 웹 | 로컬 개발 출처(`localhost`, `127.0.0.1`)와 서버가 허용 목록으로 둔 웹 앱 출처 |

넘기는 값은 응답의 신원 증명, 상태 값, 오류 세 가지 중 응답에 있는 것뿐이다. 그 밖의 값은 넘기지 않는다.

- Android와 데스크톱: 세 값을 붙인 앱 복귀 주소로 브라우저를 보낸다.
- 웹: 로그인 창을 연 앱 창에 세 값을 전달하되, 받는 창이 앱 복귀 주소의 출처일 때만 전달되도록 한다. 전달한 뒤 로그인 창을 닫는다.

중계는 응답을 저장하거나 검증하지 않는다. 로그인 세션 발급을 위한 검증은 앱이 신원 증명을 `인증 결과 검증`으로 보낸 뒤에만 이루어진다. 중계 결과는 브라우저에 저장해 두지 않는다.
