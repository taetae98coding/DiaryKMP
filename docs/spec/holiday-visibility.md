# 공휴일 노출 설정 스펙

이 문서는 캘린더에 표시할 공휴일을 사용자가 고르는 노출 설정의 규칙을 다룬다. 설정을 고르는 화면과 조작 방식은 [SettingHoliday 화면 스펙](./setting-holiday.md)에서 다룬다. 공휴일 자체의 원격 동기화와 로컬 캐시 규칙은 [공휴일 동기화 스펙](./holiday-fetch.md)과 [공휴일 로컬 캐시 스펙](./holiday-database.md)을, 어느 국가의 공휴일을 다룰지는 [공휴일 국가 설정 스펙](./holiday-country.md)을 따른다. 노출 설정은 국가 설정으로 고른 국가의 공휴일 안에서 개별 공휴일을 숨기는 설정이다.

이번 범위는 노출 설정의 개념과 저장 규칙, 그리고 캘린더가 그 설정을 반영한 공휴일을 조회하는 것까지다. 화면에서의 행동과 반응은 SettingHoliday 화면 스펙에서 다루므로 이 문서에서는 `feature` 영역을 생략한다.

## domain

### 노출 설정

공휴일 노출 설정은 캘린더에 표시할 공휴일을 사용자가 고르는 설정이다.

설정의 단위는 공휴일 이름의 선행·후행 공백을 포함한 모든 공백 문자를 제거한 key 하나다. 같은 key의 공휴일은 원래 이름의 공백이나 연도가 달라도 하나의 항목으로 다루므로, 한 번 고른 설정은 이후 연도의 같은 key에도 그대로 적용된다.

key가 다르면 서로 다른 항목이다. 따라서 `삼일절`과 `대체공휴일(삼일절)`은 각각 고른다.

각 항목은 노출과 숨김 중 하나의 상태를 가진다.

### 기본 노출

사용자가 한 번도 고르지 않은 key는 노출 상태다.

그래서 노출 설정을 한 번도 건드리지 않은 사용자는 저장된 공휴일을 모두 캘린더에서 그대로 본다.

새 연도의 공휴일에 처음 등장하는 key도 노출 상태로 시작한다.

### 노출 설정 적용 범위

노출 설정은 캘린더에 공휴일을 표시할지에 적용된다.

숨김으로 고른 공휴일은 캘린더에서 이름을 표시하지 않고 날짜 숫자도 강조하지 않는다. 예를 들어 사용자가 `어린이날`을 숨기면 캘린더에서 그 이름이 사라지고, 5월 5일 날짜 숫자도 일요일·공휴일 색상으로 강조되지 않는다.

이름을 눌러 검색 결과를 여는 동작은 캘린더에 표시된 이름에만 해당하므로, 숨긴 공휴일에는 해당하지 않는다.

황금연휴는 실제로 쉬는 날을 기준으로 찾는 기능이므로 노출 설정을 적용하지 않는다. 사용자가 어떤 공휴일을 숨겨도 [HolidayHome 화면 스펙](./holiday-home.md)의 황금연휴 판정과 이름 표시는 달라지지 않는다. 그래서 숨긴 공휴일은 캘린더에서 사라지지만 황금연휴에서는 여전히 쉬는 날로 쓰인다.

### 설정 유지

노출 설정은 화면이 재생성되거나 앱이 백그라운드에 다녀와도, 앱을 종료하고 다시 시작해도 유지된다.

## data

### 저장 시점과 유지

사용자가 어떤 key를 숨김으로 고르면 그 key가 기기에 저장되고, 다시 노출로 되돌리면 저장에서 제거된다. 별도 확인 동작 없이 바로 저장된다.

개별 항목을 바꿀 때는 그 key만 저장에 추가하거나 제거한다. 이때 다른 key의 기존 설정은 그대로 유지하며, 현재 공휴일 캐시에 없는 숨김 key도 제거하지 않는다.

[SettingHoliday 화면 스펙](./setting-holiday.md)의 세 일괄 선택은 계산한 전체 숨김 key 집합으로 기존 저장값을 교체한다. 이때 하나의 저장으로 교체하므로 일부 key만 바뀐 중간 상태가 사용자에게 보이지 않는다. 새 집합에 포함되지 않은 기존 key는 현재 공휴일 캐시에 없는 key를 포함해 모두 제거된다.

저장에는 사용자가 숨긴 key만 남는다. 노출 상태인 key는 저장하지 않으므로, 노출 설정을 한 번도 건드리지 않은 사용자에게는 저장된 것이 없다.

공휴일의 원래 이름과 공휴일 여부는 노출 설정에 저장하지 않고 [공휴일 로컬 캐시 스펙](./holiday-database.md)의 캐시에서 읽는다. 그래서 연도별 캐시가 교체되어도 노출 설정은 영향을 받지 않고, 노출 설정을 바꿔도 캐시는 바뀌지 않는다.

저장된 key가 더 이상 어느 연도의 공휴일에도 없으면 그 key는 어떤 공휴일에도 적용되지 않는다. 그 key가 다시 등장하면 이전에 고른 숨김이 그대로 적용된다. 쓰이지 않는 key를 따로 정리하지는 않지만, 이후 사용자가 세 일괄 선택 중 하나를 실행하면 전체 교체 결과에 포함되지 않아 제거된다.

### 캘린더 공휴일 조회

캘린더가 사용하는 공휴일은 적용 국가의 연도별 로컬 캐시에서 조회한 공휴일 중 이름 key를 숨기지 않은 공휴일만 제공한다. 적용 국가는 [공휴일 국가 설정 스펙](./holiday-country.md)의 `적용 국가`를 따르며, 적용 국가가 비어 있으면 빈 목록을 제공한다. 각 공휴일 이름의 key도 `domain > 노출 설정`과 같이 모든 공백 문자를 제거해 판단한다. 캐시 조회 규칙은 [공휴일 로컬 캐시 스펙](./holiday-database.md)의 연도별 캐시 조회를 따르고, 제공하는 순서도 캐시의 순서를 그대로 따른다.

숨긴 공휴일은 조회 결과에 들어가지 않으므로 캘린더는 이름 표시와 날짜 강조 어느 쪽에서도 그 공휴일을 다루지 않는다.

캐시가 바뀌거나 사용자가 노출 설정이나 국가 설정을 바꾸면, 사용자가 별도 조작을 하지 않아도 캘린더의 공휴일 표시가 바뀐 기준으로 다시 표시된다.

저장된 노출 설정을 읽을 수 없으면 어떤 공휴일을 숨겨야 하는지 알 수 없으므로 조회를 실패로 끝낸다. 저장된 국가 설정을 읽을 수 없을 때도 같다. 읽지 못한 설정을 아무것도 숨기지 않은 것으로 다루면 사용자가 숨긴 공휴일이 다시 나타나기 때문이다.

조회가 실패하면 캘린더는 그 연도의 공휴일 없이 표시하고 사용자에게 별도로 알리지 않는다. 이는 [CalendarHome 스펙](./calendar-home.md)의 표시 중인 달의 공휴일 조회에서 캐시 조회가 실패했을 때와 같다.

### 기기별 보관

노출 설정은 사용자 계정이 아니라 기기에 보관하며 서버와 동기화하지 않는다. 그래서 사용자가 로그인하거나 로그아웃하거나 다른 계정으로 바꿔도 노출 설정은 바뀌지 않고, 한 기기에서 바꾼 노출 설정이 다른 기기에 반영되지도 않는다.

노출 설정은 메모나 태그 같은 사용자 데이터와 함께 동기화되는 대상이 아니므로 [데이터 동기화 스펙](./data-sync.md)의 동기화 흐름에 포함하지 않는다.

각 환경에서 노출 설정을 보관하는 영역과 사라지는 경우는 기본 지도 설정과 같으므로 [SettingMap 화면 스펙](./setting-map.md)의 `환경별 저장 영역`을 따른다.
