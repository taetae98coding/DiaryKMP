# 로그인 스펙

이 문서는 로그인할 때 앱과 서버가 주고받는 인증 결과와 로그인 세션 정보, Apple 웹 로그인의 상태 값과 그 의미를 다룬다.

앱이 인증 결과를 얻고 세션을 설정하는 흐름은 [Login 화면 스펙](../client/login.md)이, 서버가 인증 결과를 검증해 세션을 발급하고 Apple 웹 로그인 응답을 중계하는 처리는 [로그인 스펙(server)](../server/login.md)이 소유한다.

## domain

### 인증 결과

인증 결과는 사용자가 Google이나 Apple에서 계정 선택과 동의를 마친 뒤 그 인증 제공자가 발급한 값이다. 앱은 인증 결과를 서버에 보내고, 서버는 검증에 성공한 인증 결과로만 세션을 발급한다.

| 인증 결과 | 뜻 |
| --- | --- |
| 신원 증명 | Google이나 Apple이 이 앱을 대상으로 발급한, 사용자가 누구인지 증명하는 값. 이메일이 담겨 있다. |
| 인가 코드 | Google이 발급한 한 번만 쓸 수 있는 코드. 서버가 Google에 보내 신원 증명으로 바꾼다. |

### 로그인 시도에 쓰는 값

앱은 로그인 시도마다 다음 값을 새로 만들고, 다른 로그인 시도에 다시 쓰지 않는다.

| 값 | 뜻 |
| --- | --- |
| 시도 확인 값 | 신원 증명이 이 로그인 시도에서 발급되었음을 확인하는 일회용 값. 앱은 이 값을 인증 제공자에게 알리고, 같은 값을 서버에도 보낸다. |
| 코드 확인 값 | 인가 코드가 이 로그인 시도에서 발급되었음을 확인하는 일회용 값. 데스크톱에서만 쓴다. 앱은 이 값에서 만든 대조 값을 Google에 알리고, 원래 값은 서버에 보낸다. |
| 상태 값 | Apple 웹 로그인의 응답이 이 로그인 시도의 것인지 확인하는 값. `상태 값`을 따른다. |

### 상태 값

Apple 웹 로그인의 상태 값은 로그인 시도마다 새로 만든 시도 식별 부분과 인증 결과가 돌아올 앱 복귀 주소를 함께 담는다. Apple은 상태 값을 바꾸지 않고 응답에 그대로 돌려준다.

- 서버는 상태 값에서 앱 복귀 주소를 읽어 응답을 넘길 곳을 정한다.
- 앱은 응답에 담겨 돌아온 상태 값이 이번 시도의 상태 값과 같은지 확인한다.

## data

### 세션 요청

앱은 인증 결과의 종류에 따라 다음 정보를 담아 서버에 세션을 요청한다. 세션 요청에는 로그인 세션이 필요하지 않다.

| 요청 | 담는 정보 |
| --- | --- |
| Google 신원 증명으로 로그인 | Google 신원 증명, 시도 확인 값 |
| Google 인가 코드로 로그인 | 인가 코드, Google에 등록한 이 앱의 식별 값, 인가 코드를 받은 복귀 주소, 데스크톱이면 코드 확인 값 |
| Apple 신원 증명으로 로그인 | Apple 신원 증명, 시도 확인 값 |

### 세션 응답

서버가 인증 결과를 검증하면 로그인 세션 정보를 돌려준다. 로그인 세션 정보는 서버 요청에 쓰는 접근 정보와, 접근 정보가 만료되었을 때 새로 받는 데 쓰는 갱신 정보 두 값이다.

검증에 실패하면 서버는 세션 정보 없이 실패를 돌려준다.

### Apple 웹 로그인 응답

Apple 웹 로그인이 끝나면 서버는 다음 세 값 중 응답에 있는 것을 앱 복귀 주소로 넘긴다.

| 값 | 뜻 |
| --- | --- |
| 신원 증명 | 사용자가 로그인을 마쳤을 때 Apple이 발급한 신원 증명 |
| 상태 값 | 로그인을 요청할 때 담은 상태 값 그대로 |
| 오류 | 로그인이 끝나지 않은 이유. 사용자가 취소했을 때는 취소를 뜻하는 값이 온다. |
