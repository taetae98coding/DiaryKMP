# 대표 태그 공통 스펙

이 문서는 메모와 디데이가 연결된 태그 하나를 대표 태그로 가질 수 있다는 규칙과, 대표 태그가 항목의 저장·동기화에 미치는 영향을 다룬다. 사용자가 기기에서 대표 태그를 지정하고 바꾸는 규칙, 대표 태그와 연결을 함께 바꾸는 저장, 대표 태그가 앱의 캘린더 표시 색상에 미치는 영향은 [대표 태그 앱 스펙](../client/primary-tag.md)이 소유한다.

이 문서에서 `대상 항목`은 대표 태그를 가질 수 있는 메모 또는 디데이 하나를 가리킨다. 다른 항목이 대표 항목을 갖지 않는다는 규칙은 [항목 연결 공통 스펙](./entity-link.md)의 `대표 항목`을 따른다. 대상 항목과 태그의 연결 규칙은 [메모 태그 스펙](./memo-tag.md)과 [디데이 태그 스펙](./dday-tag.md)을, 서버 동기화의 공통 규칙은 [데이터 동기화 스펙](./data-sync.md)을 따른다.

대표 태그를 고르고 해제하는 행동과 정책은 [대표 태그 입력 컴포넌트 스펙](../client/primary-tag-input.md)에서, 대상 항목을 추가하거나 수정하면서 대표 태그를 지정하는 흐름은 [MemoAdd 화면 스펙](../client/memo-add.md), [MemoDetail 화면 스펙](../client/memo-detail.md), [DDayAdd 화면 스펙](../client/dday-add.md), [DDayDetail 화면 스펙](../client/dday-detail.md)에서 다룬다. 이 문서에는 직접 수행하는 사용자 조작이 없어 `feature` 영역은 생략한다.

## domain

### 대표 태그

대상 항목은 태그 하나를 대표 태그로 가질 수 있다.

대표 태그가 없는 대상 항목도 허용되며, 대표 태그가 없는 것이 대상 항목의 기본 상태다.

하나의 대상 항목이 둘 이상의 태그를 대표 태그로 가질 수 없다.

대표 태그는 대상 항목이 가지는 값이다. 태그 쪽에서 자신을 대표 태그로 쓰는 항목을 지정하지는 않는다.

### 대표 태그 지정 권한

대상 항목에 대표 태그로 지정할 수 있는 태그는 그 항목을 변경하는 계정과 연결된 태그다.

계정과 연결되지 않은 태그는 대표 태그로 지정할 수 없다.

### 삭제와 대표 태그

태그를 삭제해도 그 태그를 대표 태그로 가진 대상 항목의 대표 태그 지정은 해제되지 않는다. 캘린더 표시 색상만 [대표 태그 앱 스펙](../client/primary-tag.md)의 `캘린더 표시 색상`에 따라 대상 항목 자신의 컬러로 돌아간다.

삭제한 태그가 영구히 제거되면 그 태그를 대표 태그로 가진 대상 항목의 대표 태그 지정은 해제된다. 영구히 제거된 태그는 되살릴 수 없어 지정을 유지할 대상이 없기 때문이다. 대상 항목 자체는 제거되지 않고 남으며, 대표 태그 외의 값은 바뀌지 않는다. 영구 제거의 기준과 해제가 각 기기에 전달되는 방식은 [데이터 동기화 서버 스펙](../server/data-sync.md)의 `삭제된 항목의 영구 제거`를 따른다.

대상 항목을 삭제하거나 메모를 완료해도 그 항목의 대표 태그 지정은 유지된다.

### 항목 변경과 대표 태그

대상 항목의 내용 수정, 메모의 완료와 다시 시작, 대상 항목의 삭제와 삭제 실행 취소는 대표 태그 지정을 바꾸지 않는다. 반대로 대표 태그 변경도 대상 항목의 다른 값을 바꾸지 않는다. 다른 값은 메모라면 제목·설명·컬러·기간과 완료 여부, 삭제 여부이고, 디데이라면 [디데이 스펙](./dday.md)의 `디데이의 정보`와 삭제 여부다.

### 동기화에서의 대표 태그와 연결

사용자가 기기에서 대표 태그와 연결을 함께 바꿀 때 지키는 관계는 [대표 태그 앱 스펙](../client/primary-tag.md)의 `대표 태그와 연결의 관계`가 소유한다.

서버 동기화에서는 대상 항목과 연결을 별도 종류로 반영하므로 이 관계가 항상 성립한다고 보장하지 않는다. 대표 태그 지정이 포함된 대상 항목과 그 태그 연결은 서로 다른 요청으로 동기화되며, 반영 순서에 따른 중간 상태와 여러 기기 충돌 뒤의 복구 범위는 [데이터 동기화 스펙](./data-sync.md)의 `종류 사이의 중간 상태`를, 실패한 연결의 재시도는 [데이터 동기화 앱 스펙](../client/data-sync.md)의 `동기화 단계와 처리 순서`를 따른다.

## data

### 대표 태그의 저장

대표 태그는 대상 항목의 값으로 그 항목과 함께 저장된다. 대표 태그가 없는 대상 항목은 대표 태그 값이 비어 있는 상태로 저장된다.

대표 태그가 바뀌면 대상 항목이 변경된 것으로 보고 그 항목의 수정 시각을 갱신한다.

### 동기화

대표 태그는 대상 항목의 일부로 동기화되며 별도의 업로드·내려받기 종류를 두지 않는다. 주고받는 정보와 충돌 기준은 [데이터 동기화 스펙](./data-sync.md)의 메모와 디데이 규칙을, 업로드 대기와 내려받기 흐름은 [데이터 동기화 앱 스펙](../client/data-sync.md)을 그대로 따른다.

대표 태그만 바뀌어도 대상 항목 전체가 하나의 항목으로 업로드된다. 같은 항목을 여러 기기에서 서로 다르게 바꾸면 수정 시각이 늦은 쪽의 내용이 대표 태그를 포함해 함께 최신으로 반영된다.

서버는 업로드된 대상 항목의 대표 태그가 업로드한 계정과 연결된 태그인지 확인하고, 이미 영구히 제거된 태그는 지정이 해제된 것으로 반영한다. 확인 기준은 [데이터 동기화 서버 스펙](../server/data-sync.md)의 `대표 태그 확인`을 따른다. 디데이에 대표 태그가 생기기 전 버전의 앱이 고쳐 올린 디데이는 서버에 저장된 대표 태그를 바꾸지 않으며, 그 기준은 같은 문서의 `이전 버전 앱의 디데이 요청`을 따른다.

### 내려받기 순서와 표시

대상 항목과 태그의 내려받기는 서로 순서를 두지 않으므로, 대표 태그를 가진 항목이 그 태그보다 먼저 기기에 반영될 수 있다.

이때 대상 항목은 사라지거나 잘못 보이지 않는다. [대표 태그 앱 스펙](../client/primary-tag.md)의 `캘린더 표시 색상`에 따라 항목 자신의 컬러로 표시되고, 태그가 내려받아지면 대표 태그의 컬러로 바뀐다.
