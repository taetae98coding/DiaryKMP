# 계정 탈퇴 스펙

이 문서는 계정을 탈퇴할 때 앱이 서버에 보내는 요청과 서버가 돌려주는 결과의 약속을 다룬다.

앱이 탈퇴를 확인하고 요청하고 결과를 이 기기에 반영하는 흐름은 [계정 탈퇴 스펙(client)](../client/account-deletion.md)이, 서버가 요청을 검증하고 계정과 데이터를 지우는 처리는 [계정 탈퇴 스펙(server)](../server/account-deletion.md)이 소유한다.

## domain

### 탈퇴

탈퇴는 계정과 그 계정이 서버에 남긴 데이터를 지우는 것이다. 탈퇴한 계정은 되살릴 수 없다. 같은 이메일로 다시 로그인하면 [로그인 스펙(server)](../server/login.md)의 `처음 로그인하는 사용자`에 따라 새 계정이 만들어지고, 탈퇴한 계정의 데이터는 이어지지 않는다.

계정을 비활성화하거나 일정 기간 보관한 뒤 지우는 단계는 두지 않는다. 서버는 탈퇴 요청을 처리하는 동안 바로 지운다.

### Apple 인가 코드

Apple 인가 코드는 사용자가 Apple 로그인 흐름에서 계정을 확인했을 때 Apple이 발급하는, 한 번만 쓸 수 있는 코드다. 서버는 이 코드를 Apple에 보내 이 앱의 Apple 로그인 권한을 확인하고 취소한다. 코드는 발급된 뒤 짧은 시간 안에만 쓸 수 있으므로 앱은 받은 즉시 탈퇴를 요청한다.

## data

### 탈퇴 요청

앱은 인증된 로그인 세션으로 탈퇴를 요청한다. 탈퇴 대상 계정은 세션의 계정이다.

| 요청 | 담는 정보 |
| --- | --- |
| Apple 재인증 없이 탈퇴 | 없음 |
| Apple 재인증을 거쳐 탈퇴 | Apple 인가 코드, 그 코드를 받은 이 앱의 Apple 식별 값 |

이 앱의 Apple 식별 값은 플랫폼에 따라 다르다. 기기의 Apple 계정 로그인을 쓰는 iOS는 앱의 식별 값을, Apple 웹 로그인을 쓰는 Android, 데스크톱, 웹은 웹 로그인용 식별 값을 보낸다. 개발용과 배포용은 서로 다른 값이다.

### 탈퇴 결과

서버는 탈퇴에 성공하면 성공을 돌려준다. 성공을 받은 뒤에는 그 계정의 로그인 세션을 더 이상 갱신할 수 없다.

서버는 탈퇴에 실패하면 실패를 돌려주고 계정을 지우지 않는다. 실패한 요청에서 이미 끝난 일부 처리가 남을 수 있으며, 그 범위는 [계정 탈퇴 스펙(server)](../server/account-deletion.md)의 `data > 처리 순서`를 따른다. 앱은 실패의 종류를 구분하지 않고 같은 탈퇴 실패로 다룬다.
