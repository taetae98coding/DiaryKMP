# 데이터 동기화 스펙

이 문서는 사용자 계정과 연결된 메모, 태그, 장소, 웹 항목, 연락처, 곡, 그리고 메모와 태그의 연결, 메모와 장소의 연결, 메모와 웹 항목의 연결, 메모와 연락처의 연결, 태그와 태그의 연결, 웹 항목과 태그의 연결, 장소와 태그의 연결을 기기와 서버가 주고받을 때 양쪽이 같은 의미로 해석해야 하는 계약을 다룬다. 동기화 대상, 항목과 연결의 상태와 시각의 의미, 여러 기기 사이의 충돌 기준, 삭제의 의미, 주고받는 정보와 그 의미를 이 문서가 소유한다.

앱이 언제 동기화하고 어떤 순서로 올리고 내려받는지, 실패와 재시도, 로그인·로그아웃 때 기기 자료를 어떻게 다루는지는 [데이터 동기화 앱 스펙](../client/data-sync.md)이, 서버가 요청을 확인하고 저장하고 접근을 제한하고 내려줄 범위를 정하는 규칙은 [데이터 동기화 서버 스펙](../server/data-sync.md)이 소유한다.

메모와 태그의 생성·수정·완료·삭제 자체의 규칙은 [MemoAdd 화면 스펙](../client/memo-add.md), [MemoDetail 화면 스펙](../client/memo-detail.md), [MemoHome 목록 스펙](../client/memo-home.md), [TagAdd 화면 스펙](../client/tag-add.md), [TagDetail 화면 스펙](../client/tag-detail.md)을, 장소의 추가·수정·삭제 자체의 규칙은 [PlaceAdd 화면 스펙](../client/place-add.md)과 [PlaceDetail 화면 스펙](../client/place-detail.md)을, 웹 항목의 추가·수정·삭제 자체의 규칙은 [WebAdd 화면 스펙](../client/web-add.md)과 [WebDetail 화면 스펙](../client/web-detail.md)을, 연락처의 추가·수정·삭제 자체의 규칙은 [ContactAdd 화면 스펙](../client/contact-add.md)과 [ContactDetail 화면 스펙](../client/contact-detail.md)을, 곡의 추가·수정·삭제 자체의 규칙은 [MusicAdd 화면 스펙](../client/music-add.md)과 [MusicDetail 화면 스펙](../client/music-detail.md)을 따른다. 연결의 공통 성질은 [항목 연결 공통 스펙](./entity-link.md)을, 메모와 태그의 연결 규칙은 [메모 태그 스펙](./memo-tag.md)을, 메모와 장소의 연결 규칙은 [메모 장소 스펙](./memo-place.md)을, 메모와 웹 항목의 연결 규칙은 [메모 웹 스펙](./memo-web.md)을, 메모와 연락처의 연결 규칙은 [메모 연락처 스펙](./memo-contact.md)을, 태그와 태그의 연결 규칙은 [태그 연결 스펙](./tag-link.md)을, 웹 항목과 태그의 연결 규칙은 [웹 태그 스펙](./web-tag.md)을, 장소와 태그의 연결 규칙은 [장소 태그 스펙](./place-tag.md)을, 메모가 가지는 대표 태그의 규칙은 [메모 대표 태그 스펙](./memo-primary-tag.md)을 따른다.

동기화는 화면 없이 진행되므로 이 문서에서는 `feature` 영역을 생략한다. 사용자가 동기화를 직접 요청하는 조작과 진행을 알리는 기준은 [새로고침 스펙](../client/sync-refresh.md)에서 다룬다.

메모, 태그, 장소, 웹 항목, 연락처, 곡과 일곱 종류의 연결은 모두 여러 계정이나 그룹과 같은 내용을 공유할 수 있지만, 이번 범위에서는 사용자 계정과의 연결만 서버에 반영한다. 그룹과의 연결 및 그룹을 통한 동기화는 후속 범위에서 다룬다.

한 사용자가 여러 기기에서 같은 계정의 데이터를 동기화하는 것을 지원한다. 여러 기기에서 같은 항목을 바꾼 경우도 이번 범위에 포함하며, 아래 `충돌 기준`으로 하나의 최신 상태를 정한다.

## domain

### 동기화 대상

동기화 대상은 로그인한 사용자 계정과 연결된 다음 열세 종류다.

| 종류 | 대상 |
| --- | --- |
| 태그 | 계정과 연결된 태그 |
| 장소 | 계정과 연결된 장소 |
| 웹 항목 | 계정과 연결된 웹 항목 |
| 연락처 | 계정과 연결된 연락처 |
| 곡 | 계정과 연결된 곡 |
| 메모 | 계정과 연결된 메모 |
| 메모와 태그의 연결 | 계정과 연결된 메모·태그 사이의 연결 |
| 메모와 장소의 연결 | 계정과 연결된 메모·장소 사이의 연결 |
| 메모와 웹 항목의 연결 | 계정과 연결된 메모·웹 항목 사이의 연결 |
| 메모와 연락처의 연결 | 계정과 연결된 메모·연락처 사이의 연결 |
| 태그와 태그의 연결 | 계정과 연결된 태그·태그 사이의 연결 |
| 웹 항목과 태그의 연결 | 계정과 연결된 웹 항목·태그 사이의 연결 |
| 장소와 태그의 연결 | 계정과 연결된 장소·태그 사이의 연결 |

열세 종류는 각각 별개의 종류로 주고받는다. 종류마다 올리는 요청과 내려받는 요청, 내려받기 위치를 따로 둔다.

태그와 장소와 웹 항목과 연락처와 곡은 다른 종류를 참조하지 않는 독립된 항목이고, 메모는 대표 태그로 태그를 참조하며, 일곱 연결 종류는 각각 메모와 태그, 메모와 장소, 메모와 웹 항목, 메모와 연락처, 태그와 태그, 웹 항목과 태그, 장소와 태그를 함께 참조한다. 이 참조 관계가 앱의 업로드 순서를 정한다. 순서는 [데이터 동기화 앱 스펙](../client/data-sync.md)의 `동기화 단계와 처리 순서`를 따른다.

웹 항목이 갖는 요청 헤더 목록은 웹 항목에 딸린 값이므로 별개의 종류로 두지 않고 웹 항목의 전체 상태에 포함해 함께 주고받는다. 연락처가 갖는 전화번호 목록도 같은 기준으로 연락처의 전체 상태에 포함한다.

게스트 상태의 데이터는 계정과 연결되지 않으므로 동기화 대상이 아니다.

### 항목과 연결의 상태와 시각

모든 항목과 연결은 생성 시각과 수정 시각을 가진다. 생성 시각은 처음 만든 시점이고, 수정 시각은 내용이나 상태가 마지막으로 바뀐 시점이다. 두 시각은 그 변경이 일어난 기기가 기록한다.

항목은 삭제 여부를 가지고, 메모와 태그는 완료 여부도 가진다. 연락처는 즐겨찾기 여부를 가진다. 연결은 해제 여부를 가지며, 해제된 연결의 의미는 [항목 연결 공통 스펙](./entity-link.md)의 `연결의 상태와 시각`을 따른다.

내용 수정, 완료·다시 시작, 삭제·실행 취소, 즐겨찾기 변경, 대표 태그 변경, 연결 생성·해제는 모두 수정 시각을 그 시점으로 갱신한다. 어떤 동작이 어떤 값을 바꾸는지는 각 화면 스펙이 정한다.

### 서버 변경 순번

서버는 사용자 계정마다 그 계정이 볼 수 있는 변경에 순번을 매긴다. 순번은 하나의 계정 안에서 중복되지 않고 항상 커지는 정수다.

서버 변경 순번은 수정 시각과 구분된다. 수정 시각은 여러 기기의 변경 중 최신 내용을 판단하는 데 쓰고, 서버 변경 순번은 서버가 받아들인 변경의 순서와 기기가 어디까지 내려받았는지를 판단하는 데 쓴다.

순번은 서버가 정하며 기기가 지정할 수 없다. 기기는 종류마다 마지막으로 기기에 저장을 마친 순번을 내려받기 위치로 기억한다. 순번을 매기는 기준은 [데이터 동기화 서버 스펙](../server/data-sync.md)의 `서버 변경 순번 부여`를 따른다.

### 주고받는 정보

기기가 올리는 정보는 항목이나 연결의 최신 전체 상태 한 건이다. 같은 항목을 여러 번 바꾼 뒤 올리면 중간 과정 없이 최종 상태 한 건만 전달된다.

| 종류 | 전체 상태에 담기는 정보 |
| --- | --- |
| 태그 | 이모지, 제목, 설명, 컬러, 완료 여부, 삭제 여부 |
| 메모 | 제목, 설명, 컬러, 기간, 대표 태그, 완료 여부, 삭제 여부 |
| 장소 | 제목, 설명, 컬러, 위도, 경도, 주소, 삭제 여부 |
| 웹 항목 | 제목, 설명, URL, 요청 헤더 목록(이름과 값), 삭제 여부 |
| 연락처 | 이름, 설명, 키, 신발 사이즈, 생일과 양력·음력 구분, 고향, 전화번호 목록, 즐겨찾기 여부, 삭제 여부 |
| 곡 | 링크, 제목, 가수, 썸네일, 삭제 여부 |
| 연결 | 연결이 잇는 두 항목, 해제 여부. 태그와 태그의 연결은 출발 태그와 도착 태그를 구분한다 |

모든 종류는 위 정보와 함께 항목을 가리키는 고유 식별 정보, 생성 시각과 수정 시각을 담는다.

메모의 기간은 하루 종일 여부, 시작, 끝 세 값이 모두 있거나 모두 없어야 하며, 시작은 끝보다 늦을 수 없다. 대표 태그가 없는 메모는 대표 태그를 비워서 보낸다. 연락처의 생일과 양력·음력 구분은 함께 있거나 함께 없어야 한다. 이 값들을 서버가 확인하는 기준은 [데이터 동기화 서버 스펙](../server/data-sync.md)의 `요청 확인`을 따른다.

웹 항목의 요청 헤더 목록과 연락처의 전화번호 목록은 사용자가 배치한 순서 그대로 전체를 담으며, 받는 쪽은 받은 목록으로 기존 목록을 통째로 바꾼다.

삭제된 항목과 해제된 연결도 삭제·해제 상태 그대로 주고받는다. 삭제와 해제는 항목을 없애는 것이 아니라 상태를 바꾸는 변경이다.

서버가 내려주는 정보는 항목이나 연결의 최신 전체 상태와 그 변경의 서버 변경 순번이다. 전체 상태에 담기는 정보는 올리는 정보와 같다.

### 내려받기의 주고받기

기기는 종류마다 내려받기 위치, 즉 마지막으로 저장을 마친 서버 변경 순번을 보낸다. 내려받은 적이 없으면 처음부터 받는다는 뜻으로 가장 작은 위치를 보낸다.

서버는 그 위치보다 뒤의 변경을 순번이 작은 것부터 한 번에 최대 100개 돌려준다. 돌려줄 변경이 없으면 빈 목록을 돌려주며, 기기는 빈 목록을 그 종류에서 더 받을 변경이 없다는 뜻으로 해석한다.

### 충돌 기준

같은 항목이나 연결이 기기와 서버에서 서로 다르게 바뀌어 있으면 수정 시각이 늦은 쪽을 최신으로 본다.

수정 시각이 같으면 서버를 최신으로 본다. 기기가 올린 내용은 서버 내용을 덮어쓰지 않고, 내려받은 내용은 기기 내용을 바꾼다.

서버에 더 늦은 수정 시각의 내용이 있으면 기기가 올린 내용은 서버 내용을 덮어쓰지 않는다. 반대로 기기에 더 늦은 수정 시각의 내용이 있으면 내려받은 내용은 기기 내용을 바꾸지 않는다.

충돌은 항목이나 연결 한 건의 전체 상태 단위로 판정한다. 한 항목 안의 값 일부만 골라 합치지 않는다.

하나의 항목이나 연결이 여러 계정 또는 그룹과 연결되어 있어도 같은 항목으로 판단한다. 어느 계정을 통해 변경하더라도 수정 시각 비교와 반영은 공유되는 항목 하나를 기준으로 한다.

정상적인 사용에서는 각 기기가 신뢰할 수 있는 현재 시각을 사용하는 것을 전제로 한다. 사용자가 기기 시각을 과거나 미래로 임의로 바꿔 정상적인 시각 순서를 벗어난 수정 시각을 만드는 행위는 어뷰징으로 판단하며, 그 변경의 반영과 자동 복구는 동기화 보장 범위에 포함하지 않는다.

### 삭제의 의미

삭제한 항목은 곧바로 없어지지 않고 삭제된 상태로 서버에 남는다. 다른 기기가 그 삭제를 내려받아야 같은 항목이 모든 기기에서 사라지기 때문이다. 해제한 연결도 같은 이유로 해제된 상태로 남는다.

서버는 삭제되거나 해제된 채 일정 기간이 지난 항목과 연결을 영구히 제거한다. 영구히 제거된 항목과 연결은 어느 기기에도 더 이상 전달되지 않으며, 제거되었다는 사실도 전달되지 않는다. 제거 기간과 절차는 [데이터 동기화 서버 스펙](../server/data-sync.md)의 `삭제된 항목의 영구 제거`를 따른다.

오래 동기화하지 못한 기기가 영구 제거로 전달받지 못한 삭제를 따라잡는 방법은 [데이터 동기화 앱 스펙](../client/data-sync.md)의 `강제 전체 재동기화`를 따른다.

태그가 영구히 제거되면 그 태그를 대표 태그로 가진 메모는 대표 태그 지정이 해제된 상태가 되며, 이 해제는 서버의 변경으로 각 기기에 전달된다. 기준은 [메모 대표 태그 스펙](./memo-primary-tag.md)의 `삭제와 대표 태그`를 따른다.

### 종류 사이의 중간 상태

열세 종류는 서로 다른 요청으로 주고받으며 하나로 묶여 반영되지 않는다. 따라서 관련 종류의 동기화가 모두 끝나기 전에는 다음과 같은 중간 상태가 서버나 다른 기기에 보일 수 있고, 이를 허용한다.

- 대표 태그가 지정된 새 메모가 먼저 반영되고 그 메모와 태그의 연결이 아직 반영되지 않아, 대표 태그 지정만 먼저 보인다.
- 새 장소나 새 웹 항목이나 새 연락처를 함께 골라 추가한 메모가 먼저 반영되고 그 연결이 아직 반영되지 않아, 장소나 웹 항목이나 연락처가 연결되지 않은 메모로 보인다.
- 연결이 가리키는 항목보다 연결이 먼저 기기에 내려받아진다. 이때의 표시 기준은 [항목 연결 공통 스펙](./entity-link.md)의 `내려받기 순서와 표시`를 따른다.

여러 기기에서 대표 태그가 포함된 메모와 그 태그의 연결을 서로 다르게 바꾸면 두 종류가 각자의 수정 시각으로 따로 충돌을 판정한다. 그 결과 모든 업로드 대기 항목이 해제된 뒤에도 대표 태그 지정과 연결 상태가 서로 맞지 않을 수 있다. 대표 태그 지정과 연결을 서버에서 함께 반영하거나, 이런 불일치를 따로 찾아 복구하는 기능은 이번 범위에 포함하지 않는다.

### 공유되는 항목과 접근

서버의 항목과 연결은 계정별 복사본이 아니라 연결된 모든 계정과 그룹이 공유하는 하나의 항목이다.

사용자 계정은 직접 연결된 항목과 연결만 조회하거나 변경할 수 있다. 서버가 이를 강제하는 기준은 [데이터 동기화 서버 스펙](../server/data-sync.md)의 `접근 제한`을 따른다.
