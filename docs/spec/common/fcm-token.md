# 푸시 알림 수신 등록 스펙

이 문서는 기기가 서버에서 푸시 알림을 받을 수 있도록 서버에 자기 정보를 등록하고 해제할 때 앱과 서버가 주고받는 정보와 그 의미를 다룬다.

앱이 언제 등록하거나 해제하는지는 [푸시 알림 수신 등록 스펙(client)](../client/fcm-token.md)이, 서버가 받은 정보를 어떻게 검증하고 저장하는지는 [푸시 알림 수신 등록 스펙(server)](../server/fcm-token.md)이 소유한다. 등록된 정보로 보내는 알림은 [일일 메모 알림 스펙(server)](../server/daily-memo-notification.md)이 소유한다.

## domain

### 푸시 알림 수신 정보

푸시 알림 수신 정보는 Firebase가 이 기기의 이 앱 설치에 발급한 값이며, 서버가 알림을 보낼 대상 기기를 가리킨다.

- 앱도 서버도 이 값을 정하지 않는다. Firebase가 발급하고, 앱 설치 단위로 유지된다.
- Firebase가 값을 새로 발급하면 이전 값은 더 이상 이 기기를 가리키지 않는다.
- 앱을 삭제하고 다시 설치하면 새 값이 발급된다.
- 이 값은 발급받은 기기와 서버만 알고, 화면에 표시하지 않는다.

### 등록 정보

등록에는 다음 세 값을 함께 담는다. 서버가 알림을 어느 기기에 언제 어떤 언어로 보낼지 정하는 데 필요한 값이다.

| 값 | 뜻 |
| --- | --- |
| 푸시 알림 수신 정보 | 알림을 받을 기기. `푸시 알림 수신 정보`의 값 |
| 시간대 | 기기가 현재 사용하는 시간대의 이름. 예: `Asia/Seoul`. 서버가 알림 시각과 알림 날짜를 정하는 기준이다. |
| 언어 | 기기가 현재 사용하는 언어 태그. 예: `ko-KR`. 서버가 알림 문구의 언어를 정하는 기준이다. |

시간대 이름은 IANA 시간대 데이터베이스의 이름을, 언어 태그는 BCP 47 형식을 따른다.

## data

### 제출 요청

기기가 서버에 보내는 제출은 등록과 해제 두 가지이며, 같은 제출 요청으로 보내고 담긴 내용으로 구분한다.

| 제출 | 담는 정보 | 로그인 세션 | 뜻 |
| --- | --- | --- | --- |
| 등록 | 푸시 알림 수신 정보, 시간대, 언어 | 인증된 세션으로 보낸다 | 이 기기를 세션의 계정에 연결한다 |
| 해제 | 푸시 알림 수신 정보만 | 세션 없이 보낸다 | 이 기기를 어느 계정에서든 뗀다 |

- 연결할 계정은 요청에 따로 담지 않고 로그인 세션의 계정으로 정한다.
- 시간대와 언어는 함께 담거나 함께 비운다. 둘 중 하나만 담은 제출은 등록도 해제도 아니며 거절된다.
- 해제를 세션 없이 보내는 것은 게스트 상태에는 세션이 없기 때문이다.

제출이 성공하면 서버는 따로 돌려주는 정보 없이 성공만 알린다. 서버가 저장한 정보는 앱으로 돌려주지 않는다.

### 같은 제출의 반복

같은 내용을 여러 번 제출해도 결과는 한 번 제출한 것과 같다. 같은 기기의 등록을 다시 받으면 새 값으로 바꾸고, 등록되지 않은 기기의 해제도 성공으로 끝나기 때문이다.

앱은 이 약속을 전제로 마지막 제출 내용을 기억하지 않고 계기마다 현재 값을 다시 제출하며, 서버는 이 약속을 지킨다.
