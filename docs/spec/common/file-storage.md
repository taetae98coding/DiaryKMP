# 파일 보관 스펙

이 문서는 파일을 올리고 올린 파일의 목록을 불러올 때 앱과 서버가 주고받는 파일과 목록의 약속을 다룬다.

앱이 파일을 올리고 목록을 불러오는 흐름은 [파일 보관 스펙(client)](../client/file-storage.md)이, 서버가 파일을 검증하고 보관하는 처리는 [파일 보관 스펙(server)](../server/file-storage.md)이 소유한다.

## data

### 올리는 파일

앱은 올리기 한 번에 파일 하나를 올린다.

| 약속 | 내용 |
| --- | --- |
| 내용 | 사용자가 고른 파일의 내용 그대로. 서버는 내용을 바꾸지 않는다. |
| 형식 | 제한하지 않는다. 앱은 기기가 알려 주는 형식을 함께 보내고, 모르면 형식을 알 수 없는 일반 파일로 보낸다. |
| 크기 | 50MB 이하. 크기가 0인 빈 파일도 받는다. 앱은 올리기 전에 크기를 확인하고, 서버도 넘는 파일을 거절한다. |
| 이름 | 공백만으로 이루어지지 않은 255자 이하의 파일 이름. 같은 계정 안에서 이름이 겹쳐도 된다. |
| 로그인 | 인증된 로그인 세션으로 올린다. 파일의 주인은 세션의 계정이다. |

### 파일 정보

서버는 보관한 파일마다 다음 정보를 가진다. 올리기에 성공하면 보관한 파일의 정보를 돌려주고, 목록을 불러오면 파일마다 같은 정보를 돌려준다.

| 정보 | 내용 |
| --- | --- |
| 식별자 | 파일마다 서버가 정하는 고유한 값. 이름이 같은 파일도 식별자로 구분한다. |
| 이름 | 올릴 때 보낸 파일 이름 |
| 형식 | 올릴 때 보낸 파일 형식 |
| 크기 | 서버가 받은 내용의 크기 |
| 올린 시각 | 서버가 파일을 보관한 시각 |

### 목록 요청

앱은 목록을 한 번에 가져올 개수와, 이어서 불러오는 경우 이미 받은 마지막 파일의 올린 시각과 식별자를 함께 보낸다. 처음 불러올 때는 마지막 파일 없이 보낸다.

서버는 세션 계정의 파일만 올린 시각이 늦은 순으로, 올린 시각이 같으면 식별자가 큰 순으로 정렬해 보낸 마지막 파일의 다음부터 요청한 개수까지 돌려준다. 마지막 파일을 순서의 기준으로만 쓰므로, 그 사이에 새 파일이 올라와도 이미 받은 파일이 다시 오거나 받지 않은 파일이 빠지지 않는다.

한 번에 가져올 수 있는 개수는 1개 이상 100개 이하다.
