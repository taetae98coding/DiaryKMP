# 현재 날씨 동기화 테스트 케이스

기준 스펙: [현재 날씨 동기화 스펙](../spec/client/weather-fetch.md)

현재 위치를 확인하는 규칙 자체의 케이스는 [현재 위치 확인 테스트 케이스](./current-location.md)에서 다룬다. 이 문서에서는 확인한 위치와 확인 실패가 날씨 동기화에서 어떻게 쓰이는지를 다룬다.

오류 보고가 남는 방식 자체의 케이스는 [기능 실패 로깅 테스트 케이스](./usecase-failure-logging.md)에서 다룬다. 이 문서에서는 현재 날씨 동기화가 오류 보고 대상인지를 다룬다.

## domain

### TC-WEATHER-FETCH-DOMAIN-001: 섭씨 단위로 요청한다

- 근거: `domain > 단위와 언어`
- Given: OpenWeatherMap 인증 정보가 준비되어 있다.
- When: 위치로 현재 날씨 또는 시간대별 예보 조회를 요청한다.
- Then: 외부 경계로 나가는 요청에 기온을 섭씨로 받는 단위 지정이 포함된다.

### TC-WEATHER-FETCH-DOMAIN-003: 같은 날짜의 날씨를 모두 묶어 시각 순서대로 제공한다

- 근거: `domain > 캘린더 날짜별 날씨`
- Given: 현재 날씨와 여러 날짜의 시간대별 예보가 저장되어 있다.
- When: 캘린더 날짜별 날씨를 확인한다.
- Then: 사용자의 현재 시간대를 기준으로 같은 날짜의 현재 날씨와 예보가 한 항목에 모두 포함되고, 날짜별 항목은 날짜가 이른 순서, 각 항목의 날씨는 시각이 이른 순서로 제공된다.

### TC-WEATHER-FETCH-DOMAIN-005: 오늘이 아닌 날짜는 최저·최고 기온을 제공한다

- 근거: `domain > 캘린더 날짜별 날씨`
- Given: 오늘이 아닌 같은 날짜에 서로 다른 최저·최고 기온을 가진 여러 시간대의 예보가 하루 전체에 걸쳐 저장되어 있다.
- When: 캘린더 날짜별 날씨를 확인한다.
- Then: 해당 날짜의 온도 표시는 날씨 정보 전체에서 가장 낮은 최저 기온과 가장 높은 최고 기온이고, 해당 날짜에 속한 예보의 모든 정보가 함께 제공된다.

### TC-WEATHER-FETCH-DOMAIN-006: 저장된 날씨가 없으면 날짜별 날씨도 없다

- 근거: `domain > 캘린더 날짜별 날씨`
- Given: 저장된 현재 날씨와 시간대별 예보가 없다.
- When: 캘린더 날짜별 날씨를 확인한다.
- Then: 날짜별 날씨가 하나도 제공되지 않는다.

### TC-WEATHER-FETCH-DOMAIN-007: 날씨 설명을 영어로 요청한다

- 근거: `domain > 단위와 언어`
- Given: OpenWeatherMap 인증 정보가 준비되어 있다.
- When: 현재 위치의 날씨 동기화를 요청한다.
- Then: 현재 날씨와 시간대별 예보 요청에 영어 문구 지정이 포함된다.

### TC-WEATHER-FETCH-DOMAIN-008: 디바이스 위치를 우선 사용해 날씨를 조회한다

- 근거: `domain > 위치 확인`
- Given: 디바이스 위치 확인이 특정 위도와 경도로 성공하도록 제어되어 있고, 공인 IP 기준 위치 확인은 다른 위도와 경도로 성공하도록 제어되어 있다.
- When: 현재 날씨 동기화를 요청한다.
- Then: 현재 날씨와 시간대별 예보 요청에 디바이스 위치의 위도와 경도가 포함되고, 공인 IP 기준 위치는 사용되지 않는다.

### TC-WEATHER-FETCH-DOMAIN-009: 디바이스에서 위치를 확인하지 못하면 공인 IP 기준 위치로 날씨를 조회한다

- 근거: `domain > 위치 확인`
- Given: 디바이스에서 위치를 확인할 수 없는 조건이 제어되어 있고, 공인 IP 기준 위치 확인은 특정 위도와 경도로 성공하도록 제어되어 있다.
- When: 현재 날씨 동기화를 요청한다.
- Then: 동기화는 디바이스 위치 조건 때문에 실패로 끝나지 않고, 현재 날씨와 시간대별 예보 요청에 공인 IP 기준 위도와 경도가 포함된다.
- 테스트 데이터:

  | 디바이스 위치 조건 | 기대 결과 |
  | --- | --- |
  | 디바이스가 위치 확인을 지원하지 않음 | 공인 IP 기준 위치 사용 |
  | 위치 권한이 허용되어 있지 않음 | 공인 IP 기준 위치 사용 |
  | 디바이스에서 위치를 확인하지 못함 | 공인 IP 기준 위치 사용 |

### TC-WEATHER-FETCH-DOMAIN-010: 오늘은 현재 시각과 가장 가까운 날씨의 기온을 제공한다

- 근거: `domain > 캘린더 날짜별 날씨`
- Given: 오늘의 현재 날씨와 시간대별 예보가 서로 다른 시각과 현재 기온으로 저장되어 있고, 날짜별 날씨를 만드는 현재 시각이 정해져 있다.
- When: 캘린더 날짜별 날씨를 확인한다.
- Then: 오늘 항목의 온도 표시는 현재 시각과 관측 또는 예보 시각의 차이가 가장 작은 날씨의 현재 기온 하나이고, 오늘에 속한 현재 날씨와 예보의 모든 정보가 함께 제공된다.

### TC-WEATHER-FETCH-DOMAIN-011: 현재 시각과 같은 거리의 날씨 중 이른 시각의 기온을 제공한다

- 근거: `domain > 캘린더 날짜별 날씨`
- Given: 오늘의 현재 시각보다 같은 시간만큼 이른 날씨와 늦은 날씨가 서로 다른 현재 기온으로 저장되어 있다.
- When: 캘린더 날짜별 날씨를 확인한다.
- Then: 오늘 항목의 온도 표시는 두 날씨 중 시각이 이른 날씨의 현재 기온 하나다.

### TC-WEATHER-FETCH-DOMAIN-012: 하루 전체가 예보 범위에 들어온 날짜만 최저·최고 기온을 제공한다

- 근거: `domain > 캘린더 날짜별 날씨`, `data > 저장된 날씨의 시간 구간`
- Given: 오늘이 아닌 마지막 날짜의 예보가 그 날짜의 0시부터 정해진 시각까지 3시간 간격으로 저장되어 있고, 그보다 늦은 날짜의 날씨는 저장되어 있지 않다.
- When: 캘린더 날짜별 날씨를 확인한다.
- Then: 해당 날짜 항목의 온도 표시가 기대 결과와 같다.
- 테스트 데이터:

  | 마지막 날짜의 마지막 예보 시각 | 기대 결과 |
  | --- | --- |
  | 21시 | 최저·최고 기온 제공 |
  | 18시 | 온도 표시 없음 |
  | 0시 | 온도 표시 없음 |

### TC-WEATHER-FETCH-DOMAIN-013: 하루 시작보다 늦게 예보가 시작한 날짜는 온도 표시를 제공하지 않는다

- 근거: `domain > 캘린더 날짜별 날씨`, `data > 저장된 날씨의 시간 구간`
- Given: 저장된 날씨 중 가장 이른 날씨가 오늘이 아닌 날짜의 0시보다 늦은 시각의 예보이고, 그 날짜의 남은 시간대와 이후 날짜의 예보는 하루 전체에 걸쳐 저장되어 있다.
- When: 캘린더 날짜별 날씨를 확인한다.
- Then: 가장 이른 날짜 항목은 온도 표시 없이 제공되고, 하루 전체가 들어온 이후 날짜 항목은 최저·최고 기온을 제공한다.

### TC-WEATHER-FETCH-DOMAIN-014: 온도 표시가 없는 날짜도 날씨 정보를 시각 순서대로 제공한다

- 근거: `domain > 캘린더 날짜별 날씨`
- Given: 오늘이 아닌 마지막 날짜에 하루의 일부 시간대만 여러 예보로 저장되어 있고, 그보다 늦은 날짜의 날씨는 저장되어 있지 않다.
- When: 캘린더 날짜별 날씨를 확인한다.
- Then: 해당 날짜 항목은 날짜별 항목 목록에 날짜 순서대로 남고, 그 날짜에 속한 예보의 모든 정보가 시각이 이른 순서로 제공된다.

### TC-WEATHER-FETCH-DOMAIN-015: 오늘은 하루 전체가 예보 범위에 들어오지 않아도 현재 기온을 제공한다

- 근거: `domain > 캘린더 날짜별 날씨`
- Given: 오늘의 날씨가 현재 시각 이후 일부 시간대만 저장되어 있고, 날짜별 날씨를 만드는 현재 시각이 정해져 있다.
- When: 캘린더 날짜별 날씨를 확인한다.
- Then: 오늘 항목의 온도 표시는 현재 시각과 차이가 가장 작은 날씨의 현재 기온 하나다.

### TC-WEATHER-FETCH-DOMAIN-016: 동기화가 실패하면 실패 원인을 담은 오류 보고가 남는다

- 근거: `domain > 동기화 실패 보고`
- Given: 오류 보고 기록 수단이 등록되어 있고, 현재 날씨 동기화가 특정 원인으로 실패하도록 준비되어 있다.
- When: 현재 날씨 동기화를 요청한다.
- Then: 그 원인을 담은 오류 보고가 한 번 남고, 보고 메시지로 현재 날씨 동기화 실패임을 구분할 수 있다.

### TC-WEATHER-FETCH-DOMAIN-017: 동기화가 성공하면 오류 보고가 남지 않는다

- 근거: `domain > 동기화 실패 보고`
- Given: 오류 보고 기록 수단이 등록되어 있고, 현재 날씨 동기화가 성공하도록 준비되어 있다.
- When: 현재 날씨 동기화를 요청한다.
- Then: 오류 보고가 남지 않는다.
### TC-WEATHER-FETCH-DOMAIN-018: 마지막 동기화 성공에서 1시간이 지나야 다시 조회한다

- 근거: `domain > 동기화 간격`
- Given: 날씨 동기화가 한 번 성공한 상태이고, 그 뒤로 지난 시간이 정해져 있다.
- When: 위치 권한 허용이 아닌 계기로 날씨 동기화를 요청한다.
- Then: 동기화는 성공으로 끝나고, 현재 날씨와 시간대별 예보 조회 여부가 기대 결과와 같다.
- 테스트 데이터:

  | 마지막 동기화 성공에서 지난 시간 | 기대 결과 |
  | --- | --- |
  | 59분 | 조회하지 않음 |
  | 1시간 | 다시 조회 |
  | 1시간 1분 | 다시 조회 |

### TC-WEATHER-FETCH-DOMAIN-019: 한 번도 성공하지 않았으면 계기와 무관하게 조회한다

- 근거: `domain > 동기화 간격`
- Given: 이번 실행에서 날씨 동기화에 성공한 적이 없다.
- When: 위치 권한 허용이 아닌 계기로 날씨 동기화를 요청한다.
- Then: 현재 날씨와 시간대별 예보를 조회한다.

### TC-WEATHER-FETCH-DOMAIN-020: 위치 권한 허용 계기는 간격과 무관하게 조회한다

- 근거: `domain > 동기화 간격`
- Given: 날씨 동기화가 성공한 뒤 아직 1시간이 지나지 않았다.
- When: 위치 권한 허용을 계기로 날씨 동기화를 요청한다.
- Then: 현재 위치를 확인하고 현재 날씨와 시간대별 예보를 다시 조회한다.

### TC-WEATHER-FETCH-DOMAIN-021: 실패한 동기화는 다음 요청의 조회를 막지 않는다

- 근거: `domain > 동기화 간격`, `data > 실패 처리`
- Given: 이번 실행의 첫 동기화가 실패했고, 이후 조회는 모두 성공하도록 제어되어 있다.
- When: 첫 요청에서 1시간이 지나지 않은 시점에 위치 권한 허용이 아닌 계기로 날씨 동기화를 다시 요청한다.
- Then: 현재 날씨와 시간대별 예보를 다시 조회하고 동기화가 성공한다.
- 테스트 데이터:

  | 첫 요청의 실패 지점 |
  | --- |
  | 현재 위치 확인 실패 |
  | 현재 날씨 조회 실패 |
  | 시간대별 예보 조회 실패 |

### TC-WEATHER-FETCH-DOMAIN-022: 조회한 동기화가 성공할 때마다 간격 기준 시각이 갱신된다

- 근거: `domain > 동기화 간격`
- Given: 날씨 동기화가 성공하고 1시간이 지나 다시 조회에 성공한 상태다.
- When: 두 번째 성공에서 1시간이 지나지 않은 시점에 위치 권한 허용이 아닌 계기로 날씨 동기화를 요청한다.
- Then: 동기화는 성공으로 끝나고 현재 날씨와 시간대별 예보를 조회하지 않는다.

### TC-WEATHER-FETCH-DOMAIN-023: 지역명만 실패한 동기화는 오류 보고를 남기지 않는다

- 근거: `domain > 동기화 실패 보고`
- Given: 오류 보고 기록 수단이 등록되어 있고, 위치 확인과 현재 날씨·시간대별 예보 조회는 성공하며 지역명 조회만 실패하도록 제어되어 있다.
- When: 현재 날씨 동기화를 요청한다.
- Then: 동기화가 성공으로 끝나고 오류 보고가 남지 않는다.

### TC-WEATHER-FETCH-DOMAIN-024: 간격 때문에 조회 없이 끝난 동기화는 오류 보고를 남기지 않는다

- 근거: `domain > 동기화 실패 보고`, `domain > 동기화 간격`
- Given: 오류 보고 기록 수단이 등록되어 있고, 날씨 동기화가 성공한 뒤 아직 1시간이 지나지 않았다.
- When: 위치 권한 허용이 아닌 계기로 현재 날씨 동기화를 다시 요청한다.
- Then: 동기화가 성공으로 끝나고 오류 보고가 남지 않는다.

### TC-WEATHER-FETCH-DOMAIN-025: 각 날씨의 아이콘은 대표 상태의 아이콘을 사용한다

- 근거: `domain > 캘린더 날짜별 날씨`, `domain > 현재 날씨`

- Given: 이전 실행에서 동기화한 지역명이 있었다.
- When: 앱을 새로 실행하고 동기화 전 저장된 지역명을 확인한다.
- Then: 지역명이 제공되지 않는다.

### TC-WEATHER-FETCH-DATA-028: 새 지역명을 날씨를 보여 주는 화면에 바로 반영한다

- 근거: `data > 현재 날씨 동기화`
- Given: 저장된 지역명을 보여 주고 있고, 현재 날씨·시간대별 예보와 지역명 `성남시` 조회가 모두 성공하도록 제어되어 있다.
- When: 현재 날씨 동기화를 요청한다.
- Then: 별도의 조회 요청 없이 `성남시`가 제공된다.

### TC-WEATHER-FETCH-DATA-029: 조회하지 않는 동기화는 현재 위치도 확인하지 않는다

- 근거: `data > 현재 날씨 동기화`
- Given: 날씨 동기화가 성공한 뒤 아직 1시간이 지나지 않았다.
- When: 위치 권한 허용이 아닌 계기로 날씨 동기화를 다시 요청한다.
- Then: 현재 위치 확인을 다시 요청하지 않고 동기화가 성공으로 끝난다.
