# FileDetail 테스트 케이스

기준 스펙: [FileDetail 화면 스펙](../spec/client/file-detail.md)

FileHome에서 파일을 선택해 이 화면으로 이동하는 케이스와 고친 값이 목록에 보이는 케이스는 [FileHome 테스트 케이스](./file-home.md)에서, 내려받은 파일의 이름과 저장 위치를 정하는 케이스는 [파일 내려받기 테스트 케이스](./file-download.md)에서, 서버와 주고받는 요청의 약속은 [파일 보관 테스트 케이스](./file-storage.md)에서 다룬다.

## feature

### TC-FILE-DETAIL-FEATURE-001: 불러오는 동안 불러오는 중임을 표시하고 수정과 다운로드를 제공하지 않는다

- 근거: `feature > 불러오기와 표시 조건`
- Given: 서버가 파일 정보 요청에 아직 응답하지 않는다.
- When: 사용자가 FileDetail 화면에 들어온다.
- Then: 본문에 불러오는 중임을 표시하고, 입력, 다운로드와 수정 동작은 표시되지 않으며 화면 제목은 비어 있다.

### TC-FILE-DETAIL-FEATURE-002: 불러오기에 실패하면 실패 안내와 다시 시도를 표시한다

- 근거: `feature > 불러오기와 표시 조건`
- Given: 사용자 언어가 한국어이고, 서버가 파일 정보 요청에 테스트 데이터의 응답을 돌려준다.
- When: 사용자가 FileDetail 화면에 들어온다.
- Then: 본문에 `파일을 불러오지 못했습니다`와 `다시 시도`가 표시되고, 입력, 다운로드와 수정 동작은 표시되지 않으며 화면 제목은 비어 있다.
- 테스트 데이터:

| 서버 응답 |
| --- |
| 찾을 수 없음 |
| 연결 실패 |

### TC-FILE-DETAIL-FEATURE-003: 다시 시도하면 다시 불러오고 그동안 불러오는 중임을 표시한다

- 근거: `feature > 불러오기와 표시 조건`
- Given: 처음 불러오기에 실패해 실패 안내가 표시되어 있고, 서버가 다음 파일 정보 요청에 아직 응답하지 않는다.
- When: 사용자가 `다시 시도`를 선택한다.
- Then: 파일 정보를 다시 요청하고, 본문에 불러오는 중임을 표시한다.

### TC-FILE-DETAIL-FEATURE-004: 불러오기에 성공하면 파일 정보를 표시한다

- 근거: `feature > 파일 정보`
- Given: 서버가 파일 정보 요청에 제목, 설명, 파일 이름, 크기와 올린 시각을 돌려준다.
- When: 사용자가 FileDetail 화면에 들어온다.
- Then: 제목, 설명, 파일 이름 입력에 돌려받은 값이 채워지고, 크기와 올린 날짜와 시각이 표시되며, 화면 제목에 돌려받은 제목이 표시되고 다운로드 동작이 표시된다.

### TC-FILE-DETAIL-FEATURE-005: 진입할 때 어느 입력에도 초점을 두지 않는다

- 근거: `feature > 진입`
- Given: 서버가 파일 정보 요청에 성공을 돌려준다.
- When: 사용자가 FileDetail 화면에 들어와 파일 정보가 표시된다.
- Then: 제목, 설명, 파일 이름 입력 중 어느 것에도 입력 초점이 없다.

### TC-FILE-DETAIL-FEATURE-006: 입력이 저장된 값과 다를 때만 수정 동작을 제공한다

- 근거: `feature > 수정`
- Given: 파일 정보가 표시되어 있다.
- When: 사용자가 입력을 테스트 데이터와 같이 바꾼다.
- Then: 수정 동작이 테스트 데이터의 결과와 같이 표시된다.
- 테스트 데이터:

| 입력 변경 | 수정 동작 |
| --- | --- |
| 바꾸지 않음 | 표시되지 않음 |
| 제목을 다른 값으로 바꿈 | 표시됨 |
| 설명을 다른 값으로 바꿈 | 표시됨 |
| 파일 이름을 다른 값으로 바꿈 | 표시됨 |
| 제목 끝에 공백을 더함 | 표시됨 |
| 파일 이름을 바꿨다가 저장된 값으로 되돌림 | 표시되지 않음 |

### TC-FILE-DETAIL-FEATURE-007: 수정 성립 조건을 어기면 안내하고 초점을 옮기며 서버에 보내지 않는다

- 근거: `feature > 수정`
- Given: 사용자 언어가 한국어이고, 파일 정보가 표시된 상태에서 사용자가 입력을 테스트 데이터와 같이 바꿨다.
- When: 사용자가 수정을 실행한다.
- Then: 테스트 데이터의 안내가 표시되고 입력 초점이 테스트 데이터의 입력으로 옮겨지며, 수정 요청을 서버에 보내지 않고 입력한 내용은 그대로 남는다.
- 테스트 데이터:

| 입력 | 안내 | 초점 |
| --- | --- | --- |
| 제목을 비움 | `제목을 입력해 주세요.` | 제목 입력 |
| 파일 이름을 비움 | `파일 이름을 입력해 주세요.` | 파일 이름 입력 |
| 파일 이름을 256자로 바꿈 | `파일 이름은 255자까지 입력할 수 있습니다.` | 파일 이름 입력 |

### TC-FILE-DETAIL-FEATURE-008: 수정에 성공하면 성공을 알리고 화면 제목을 바꾼다

- 근거: `feature > 수정`
- Given: 사용자 언어가 한국어이고, 사용자가 제목을 바꿨으며, 서버가 수정 요청에 바꾼 값을 담은 성공을 돌려준다.
- When: 사용자가 수정을 실행한다.
- Then: `파일이 수정되었습니다.`가 표시되고, 화면 제목이 새 제목으로 바뀌며, 입력한 내용은 그대로 남고 수정 동작은 사라진다.

### TC-FILE-DETAIL-FEATURE-009: 수정하는 동안 진행 중임을 표시하고 다시 실행해도 한 번만 보낸다

- 근거: `feature > 수정`, `domain > 요청 제한`
- Given: 사용자가 제목을 바꿨고, 서버가 수정 요청에 아직 응답하지 않는다.
- When: 사용자가 수정을 실행한 뒤 다시 실행한다.
- Then: 수정 동작에 진행 중임이 표시되고, 서버에 수정 요청은 한 번만 보낸다.

### TC-FILE-DETAIL-FEATURE-010: 수정하는 동안 더 고친 입력은 성공 뒤에도 남아 수정 동작이 다시 보인다

- 근거: `feature > 수정`
- Given: 사용자가 제목을 바꿔 수정을 실행했고, 서버가 그 요청에 아직 응답하지 않는다.
- When: 사용자가 설명을 더 고친 뒤 서버가 수정 요청에 성공을 돌려준다.
- Then: 더 고친 설명이 입력에 그대로 남고, 수정 동작이 다시 표시된다.

### TC-FILE-DETAIL-FEATURE-011: 수정에 실패하면 실패를 알리고 입력을 그대로 둔다

- 근거: `feature > 수정`
- Given: 사용자 언어가 한국어이고, 사용자가 제목을 바꿨으며, 서버가 수정 요청에 실패를 돌려준다.
- When: 사용자가 수정을 실행한다.
- Then: `파일을 수정하지 못했습니다.`가 표시되고, 입력한 내용과 화면 제목은 바뀌지 않으며 수정 동작이 그대로 표시된다.

### TC-FILE-DETAIL-FEATURE-012: 다운로드는 입력 중인 이름이 아니라 저장된 파일 이름으로 내려받는다

- 근거: `feature > 다운로드`
- Given: 저장된 파일 이름이 `report.pdf`이고, 사용자가 파일 이름 입력을 `memo.txt`로 바꿨지만 수정하지 않았다.
- When: 사용자가 다운로드를 실행한다.
- Then: 이 파일의 내려받기를 `report.pdf` 이름으로 한 번 시작한다.

### TC-FILE-DETAIL-FEATURE-013: 내려받는 동안 진행 중임을 표시하고 다시 실행해도 한 번만 내려받는다

- 근거: `feature > 다운로드`, `domain > 요청 제한`
- Given: 파일 정보가 표시되어 있고, 내려받기가 아직 끝나지 않는다.
- When: 사용자가 다운로드를 실행한 뒤 다시 실행한다.
- Then: 다운로드 동작에 진행 중임이 표시되고, 내려받기는 한 번만 시작한다.

### TC-FILE-DETAIL-FEATURE-014: 다운로드 결과를 알린다

- 근거: `feature > 다운로드`
- Given: 사용자 언어가 한국어이고, 내려받기가 테스트 데이터의 결과로 끝난다.
- When: 사용자가 다운로드를 실행한다.
- Then: 테스트 데이터의 안내가 표시되고 다운로드 동작의 진행 중 표시가 사라진다.
- 테스트 데이터:

| 결과 | 안내 |
| --- | --- |
| `report (1).pdf` 이름으로 저장해 성공 | `파일을 내려받았습니다: report (1).pdf` |
| 저장 위치에 저장하지 못해 실패 | `다운로드 위치에 저장하지 못했습니다. 설정에서 다운로드 위치를 확인해 주세요.` |
| 그 밖의 이유로 실패 | `파일을 내려받지 못했습니다.` |

### TC-FILE-DETAIL-FEATURE-015: 웹에서 내려받기에 성공하면 앱은 따로 알리지 않는다

- 근거: `feature > 다운로드`
- Given: 파일 정보가 표시되어 있고, 내려받기가 브라우저에 파일을 넘겨 성공으로 끝난다.
- When: 사용자가 다운로드를 실행한다.
- Then: 다운로드 동작의 진행 중 표시가 사라지고 안내는 표시되지 않는다.

### TC-FILE-DETAIL-FEATURE-016: 수정과 다운로드는 서로 막지 않는다

- 근거: `feature > 수정`, `feature > 다운로드`, `domain > 요청 제한`
- Given: 사용자가 제목을 바꿨고, 수정 요청과 내려받기가 모두 아직 끝나지 않는다.
- When: 사용자가 테스트 데이터의 순서로 두 동작을 실행한다.
- Then: 수정 요청과 내려받기가 모두 시작되고, 두 동작에 각각 진행 중임이 표시된다.
- 테스트 데이터:

| 순서 |
| --- |
| 수정을 실행한 뒤 다운로드를 실행 |
| 다운로드를 실행한 뒤 수정을 실행 |

### TC-FILE-DETAIL-FEATURE-017: 계정이 게스트나 다른 사용자로 바뀌면 화면을 닫는다

- 근거: `feature > 계정 상태`
- Given: 사용자 A로 파일 정보가 표시되어 있다.
- When: 계정 상태가 테스트 데이터와 같이 바뀐다.
- Then: FileDetail 화면을 닫고 FileHome 화면으로 돌아가는 동작이 한 번 실행된다.
- 테스트 데이터:

| 바뀐 계정 상태 |
| --- |
| 게스트 |
| 사용자 B |

### TC-FILE-DETAIL-FEATURE-018: 계정을 확정하지 않은 동안에는 화면을 그대로 두고 수정과 다운로드를 실패로 알린다

- 근거: `feature > 계정 상태`
- Given: 사용자 언어가 한국어이고, 사용자가 제목을 바꾼 상태에서 계정 상태가 게스트·사용자로 확정하지 않은 상태로 바뀌었다.
- When: 사용자가 테스트 데이터의 동작을 실행한다.
- Then: 화면과 입력 내용이 그대로 남고, 테스트 데이터의 안내가 표시되며 서버에 요청을 보내지 않는다.
- 테스트 데이터:

| 동작 | 안내 |
| --- | --- |
| 수정 | `파일을 수정하지 못했습니다.` |
| 다운로드 | `파일을 내려받지 못했습니다.` |

### TC-FILE-DETAIL-FEATURE-019: 뒤로가면 FileHome으로 돌아간다

- 근거: `feature > 뒤로가기`
- Given: 사용자가 입력을 바꾼 채 파일 정보가 표시되어 있다.
- When: 사용자가 뒤로가기를 선택한다.
- Then: 저장 여부를 묻지 않고 FileHome 화면으로 돌아가는 동작이 한 번 실행된다.

### TC-FILE-DETAIL-FEATURE-020: 불러오는 중에 다시 시도를 반복해도 한 번만 불러온다

- 근거: `domain > 요청 제한`
- Given: 처음 불러오기에 실패해 실패 안내가 표시되어 있고, 서버가 다음 파일 정보 요청에 아직 응답하지 않는다.
- When: 사용자가 `다시 시도`를 선택한 뒤 불러오는 동안 다시 시도를 한 번 더 요청한다.
- Then: 파일 정보 요청은 다시 시도 한 번에 대해서만 보낸다.

## domain

### TC-FILE-DETAIL-DOMAIN-001: 수정 성립 조건은 적힌 순서대로 처음 어긴 조건으로 판정한다

- 근거: `domain > 수정 성립 조건`
- Given: 사용자 언어가 한국어이고, 사용자가 제목과 파일 이름을 모두 비웠다.
- When: 사용자가 수정을 실행한다.
- Then: `제목을 입력해 주세요.`가 표시되고 입력 초점이 제목 입력으로 옮겨진다.

### TC-FILE-DETAIL-DOMAIN-002: 공백만 있는 제목과 파일 이름은 없는 것으로 본다

- 근거: `domain > 수정 성립 조건`
- Given: 사용자 언어가 한국어이고, 사용자가 테스트 데이터의 입력을 공백 문자로만 바꿨다.
- When: 사용자가 수정을 실행한다.
- Then: 테스트 데이터의 안내가 표시되고 서버에 수정 요청을 보내지 않는다.
- 테스트 데이터:

| 입력 | 안내 |
| --- | --- |
| 제목 | `제목을 입력해 주세요.` |
| 파일 이름 | `파일 이름을 입력해 주세요.` |

### TC-FILE-DETAIL-DOMAIN-003: 파일 이름의 길이는 유니코드 문자 수로 255자까지 받는다

- 근거: `domain > 수정 성립 조건`
- Given: 서버가 수정 요청에 성공을 돌려주고, 사용자가 파일 이름을 테스트 데이터의 값으로 바꿨다.
- When: 사용자가 수정을 실행한다.
- Then: 테스트 데이터의 결과가 된다.
- 테스트 데이터:

| 파일 이름 | 결과 |
| --- | --- |
| `a` 255자 | 서버에 수정 요청을 보낸다 |
| `a` 256자 | 서버에 보내지 않고 길이 안내를 표시한다 |
| 문자 하나로 이루어진 이모지 `😀` 255개 | 서버에 수정 요청을 보낸다 |
| 문자 다섯 개를 이은 이모지 `👨‍👩‍👧` 52개 | 서버에 보내지 않고 길이 안내를 표시한다 |

### TC-FILE-DETAIL-DOMAIN-004: 입력한 값을 앞뒤 공백을 포함해 그대로 보내고 설명은 비워 둘 수 있다

- 근거: `domain > 수정 성립 조건`
- Given: 서버가 수정 요청에 성공을 돌려주고, 사용자가 제목을 ` 보고서 `로, 파일 이름을 ` report.pdf`로 바꾸고 설명을 비웠다.
- When: 사용자가 수정을 실행한다.
- Then: 서버에 제목 ` 보고서 `, 파일 이름 ` report.pdf`, 빈 설명을 담은 수정 요청을 보낸다.

### TC-FILE-DETAIL-DOMAIN-005: 화면을 떠나면 진행 중이던 다운로드를 멈추고 결과를 알리지 않는다

- 근거: `domain > 화면을 떠날 때`
- Given: 다운로드를 실행해 내려받기가 아직 끝나지 않았다.
- When: 사용자가 화면을 떠난다.
- Then: 진행 중이던 내려받기가 멈추고, 결과를 알리는 안내가 표시되지 않는다.

### TC-FILE-DETAIL-DOMAIN-006: 화면이 재생성되거나 백그라운드에서 돌아와도 파일 정보와 입력을 유지하고 다시 불러오지 않는다

- 근거: `domain > 유지할 사용자 진행 상태`
- Given: 파일 정보가 표시된 상태에서 사용자가 제목, 설명과 파일 이름을 바꿨다.
- When: 테스트 데이터의 일이 일어난다.
- Then: 바꾼 제목, 설명과 파일 이름, 설명 입력의 입력·미리보기 상태가 그대로 보이고, 파일 정보를 다시 요청하지 않으며 수정 동작이 그대로 표시된다.

| 일 |
| --- |
| 화면이 회전하거나 창 크기가 바뀌어 화면이 재생성된다 |
| 앱이 백그라운드에 갔다가 돌아온다 |

### TC-FILE-DETAIL-DOMAIN-007: 진행 중인 수정과 다운로드는 화면이 재생성되어도 이어지고 결과가 보인다

- 근거: `domain > 유지할 사용자 진행 상태`
- Given: 사용자 언어가 한국어이고, 수정 요청과 내려받기가 모두 아직 끝나지 않았다.
- When: 화면이 회전해 재생성된 뒤 서버가 수정 요청에 성공을 돌려주고 내려받기가 실패로 끝난다.
- Then: 재생성된 화면에 진행 중 표시가 이어지다가, `파일이 수정되었습니다.`와 `파일을 내려받지 못했습니다.`가 차례로 표시된다.

### TC-FILE-DETAIL-DOMAIN-008: 시스템이 앱을 정리한 뒤 복원하면 다시 불러오고 입력은 복원한다

- 근거: `domain > 유지할 사용자 진행 상태`
- Given: 사용자가 제목을 `새 제목`으로 바꾼 상태에서 시스템이 앱을 정리했고, 서버가 다음 파일 정보 요청에 저장된 제목 `옛 제목`을 돌려준다.
- When: 화면이 복원된다.
- Then: 파일 정보를 다시 요청하고, 제목 입력에는 `새 제목`이, 화면 제목에는 `옛 제목`이 보이며 수정 동작이 표시된다. 다운로드 동작에는 진행 중임이 표시되지 않는다.

### TC-FILE-DETAIL-DOMAIN-009: 화면을 떠났다가 다시 들어오면 새로 불러온 저장된 값으로 시작한다

- 근거: `domain > 유지할 사용자 진행 상태`
- Given: 사용자가 입력을 바꾼 채 화면을 떠났다.
- When: 사용자가 같은 파일의 FileDetail 화면에 다시 들어온다.
- Then: 파일 정보를 새로 요청하고, 입력에는 새로 불러온 저장된 값이 채워지며 수정 동작은 표시되지 않는다.

### TC-FILE-DETAIL-DOMAIN-010: 화면을 떠나도 보낸 수정은 되돌리지 않고 결과를 알리지 않는다

- 근거: `domain > 화면을 떠날 때`
- Given: 수정을 실행해 서버가 수정 요청에 아직 응답하지 않았다.
- When: 사용자가 화면을 떠난 뒤 서버가 수정 요청에 성공을 돌려준다.
- Then: 되돌리는 요청을 보내지 않고, 결과를 알리는 안내가 표시되지 않는다.
