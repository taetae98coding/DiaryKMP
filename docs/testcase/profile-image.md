# 프로필 이미지 변경 테스트 케이스

기준 스펙: [프로필 이미지 변경 스펙(client)](../spec/client/profile-image.md), [프로필 이미지 변경 스펙(common)](../spec/common/profile-image.md), [프로필 이미지 변경 스펙(server)](../spec/server/profile-image.md)

각 케이스의 `근거`는 절이 있는 스펙 폴더를 앞에 붙여 `client > domain > 절 이름`처럼 적는다.

## domain

### TC-PROFILE-IMAGE-DOMAIN-001: 읽지 못하거나 JPEG로 바꾸지 못하거나 너무 큰 사진은 반영에 실패한다

- 근거: `client > domain > 반영할 수 있는 이미지`, `common > data > 올리는 이미지`
- Given: 계정의 프로필 이미지가 직전 주소이고, 사용자가 테스트 데이터의 사진을 골랐다.
- When: 그 사진과 남길 영역으로 프로필 이미지 반영을 시작한다.
- Then: 반영이 실패하고 계정의 프로필 이미지는 직전 주소를 유지한다.
- 테스트 데이터:

| 고른 사진 |
| --- |
| 기기가 읽지 못하는 형식의 사진 |
| 읽을 수 있지만 JPEG로 바꾸지 못하는 사진 |
| 최대 변 길이로 줄여 JPEG로 바꾼 뒤에도 5MB를 넘는 사진 |

- 작성하지 않는 이유: 읽지 못하거나 JPEG로 바꾸지 못하는 사진의 행은 TC-PROFILE-IMAGE-DATA-006이 앱 경계에서 자동화한다. 5MB를 넘는 사진의 행은 앱이 크기를 미리 거르지 않고 반영을 요청하며 받을 수 있는 크기를 서버가 판정하므로, 앱 경계에서는 서버가 돌려준 다른 실패와 구분할 수 없다. 서버에 크기별 이미지를 올려 응답을 비교하는 서버 정책 테스트 환경이 마련되면 작성한다.

### TC-PROFILE-IMAGE-DOMAIN-002: 바꾼 이미지는 정한 영역만 남기고 최대 변 길이까지 줄인 JPEG다

- 근거: `client > domain > 이미지 변환`
- Given: 사용자가 테스트 데이터의 사진을 고르고 남길 정사각형 영역을 정했다.
- When: 그 사진과 영역으로 반영할 이미지를 만든다.
- Then: 바꾼 이미지는 촬영 방향을 반영한 사진에서 정한 영역만 남긴 정사각형 JPEG이고, 화질은 `90`이며, 테스트 데이터의 기대 결과를 따른다.
- 테스트 데이터:

| 고른 사진 | 기대 결과 |
| --- | --- |
| 남긴 영역의 한 변이 1024px를 넘는 사진 | 한 변이 1024px로 줄어든다 |
| 남긴 영역의 한 변이 1024px 이하인 사진 | 해상도가 그대로 유지된다 |
| 여러 장면이 이어지는 사진 | 첫 장면만 남는다 |
| 투명한 부분이 있는 사진 | 투명한 부분이 불투명한 색으로 채워진다 |

- 작성하지 않는 이유: 여러 장면이 이어지는 사진의 행과 Android·iOS·웹에서 바꾼 결과만 자동화하지 않는다. 그 결과는 기기의 이미지 처리 수단이 정하고 바뀐 이미지의 화소를 읽어야 판정할 수 있다. 나머지 행과 정사각형 JPEG, 촬영 방향 반영은 데스크톱 앱의 이미지 변환으로, 반영이 JPEG·최대 변 길이 1024px·화질 `90`으로 바꾸도록 요청하는 것은 반영 요청으로 자동화한다. 자동화하려면 기기별 실제 이미지 처리 수단으로 바꾼 결과의 크기와 화소를 원본과 비교하는 수단과, 여러 장면이 이어지는 테스트용 사진을 만드는 수단이 필요하다.

### TC-PROFILE-IMAGE-DOMAIN-003: 계정마다 마지막으로 반영한 프로필 이미지 하나만 보관하고 주소만으로 조회할 수 있다

- 근거: `server > domain > 보관하는 프로필 이미지`
- Given: 계정 A가 프로필 이미지를 한 번 반영해 이전 주소를 갖고 있다.
- When: 계정 A가 새 프로필 이미지를 반영하고, 로그인 정보 없이 이전 주소와 새 주소를 조회한다.
- Then: 새 주소의 이미지는 조회되고 이전 주소의 이미지는 조회되지 않는다.
- 작성하지 않는 이유: 계정마다 이미지 하나만 남기는 것과 주소만으로 조회할 수 있는 것은 서버 보관 공간이 보장하는 결과라 앱 경계에서 관찰할 수 없다. 자동화하려면 실제 서버 보관 공간에 올린 뒤 이전 주소와 새 주소를 조회하는 수단이 필요하다.

### TC-PROFILE-IMAGE-DOMAIN-005: 이전 이미지를 지우지 못해도 반영은 성공하고 남은 이미지는 다음 반영 때 함께 지운다

- 근거: `server > domain > 보관하는 프로필 이미지`
- Given: 계정 A가 프로필 이미지를 한 번 반영해 이전 주소를 갖고 있고, 서버가 그 이전 이미지를 지우지 못하도록 설정되어 있다.
- When: 계정 A가 새 프로필 이미지를 반영하고, 지우지 못하는 설정을 푼 뒤 한 번 더 새 프로필 이미지를 반영한다.
- Then: 첫 반영은 성공으로 끝나고 이전 주소의 이미지가 남아 있으며, 두 번째 반영 뒤에는 처음 주소와 첫 반영 주소의 이미지가 모두 조회되지 않고 마지막 주소의 이미지만 조회된다.
- 작성하지 않는 이유: 이전 이미지를 지우는 데 실패하는 것과 남은 이미지를 다음 반영 때 지우는 것은 서버가 반영 한 요청 안에서 처리하는 결과라, 앱이 보낸 요청과 받은 성공 응답만으로는 이전 이미지가 남았는지 구분할 수 없다. 자동화하려면 실제 서버 보관 공간에서 이미지 지우기가 실패하도록 설정하고, 반영 뒤 남은 파일을 조회하는 수단이 필요하다.

### TC-PROFILE-IMAGE-DOMAIN-004: 로그인하면 반영한 프로필 이미지가 로그인 수단이 제공한 이미지보다 우선한다

- 근거: `server > domain > 로그인 시 프로필 이미지`
- Given: 계정의 프로필 이미지 상태와 로그인 수단이 제공하는 이미지가 테스트 데이터와 같다.
- When: 사용자가 그 로그인 수단으로 로그인한다.
- Then: 계정의 프로필 이미지가 테스트 데이터의 기대 결과가 된다.
- 테스트 데이터:

| 계정의 프로필 이미지 | 로그인 수단이 제공하는 이미지 | 기대 결과 |
| --- | --- | --- |
| 사용자가 반영한 이미지 | 다른 이미지 | 반영한 이미지 유지 |
| 반영한 이미지 없음 | 이미지 제공 | 로그인 수단이 제공한 이미지 |
| 반영한 이미지 없음 | 이미지 없음 | 직전 상태 유지 |

- 작성하지 않는 이유: 사용자가 반영한 이미지와 로그인 수단이 제공한 이미지 중 무엇을 계정의 프로필 이미지로 쓰는지는 서버가 로그인 한 요청 안에서 정하는 결과다. 앱은 어느 경우에도 같은 인증 결과를 보내고 같은 세션을 받으므로 앱 경계에서 두 경우를 구분할 수 없다. 자동화하려면 반영한 이미지가 있는 계정과 없는 계정으로 각각 실제 서버에 로그인한 뒤 인증 제공자의 사용자 정보를 조회하는 수단이 필요하다.

## data

### TC-PROFILE-IMAGE-DATA-006: 고른 사진을 JPEG로 바꾸지 못하면 반영을 요청하지 않고 실패한다

- 근거: `client > data > 반영 흐름`
- Given: 고른 사진의 위치에서 이미지를 읽지 못하거나, 읽은 이미지를 JPEG로 바꾸지 못한다.
- When: 그 위치와 남길 영역으로 프로필 이미지 반영을 시작한다.
- Then: 프로필 이미지 반영 요청이 이루어지지 않고 실패가 전달된다.

### TC-PROFILE-IMAGE-DATA-005: JPEG로 바꾼 이미지를 반영 요청에 담는다

- 근거: `client > data > 반영 흐름`
- Given: 고른 사진의 위치에서 이미지를 읽어 남길 영역을 남기고 JPEG로 바꿀 수 있다.
- When: 그 위치와 남길 영역으로 프로필 이미지 반영을 시작한다.
- Then: 반영 요청에 JPEG로 바꾼 이미지 내용이 담기고, 요청이 알리는 형식은 원본 사진의 형식과 무관하게 JPEG다.

### TC-PROFILE-IMAGE-DATA-007: 고른 사진의 위치와 남길 영역을 그대로 이미지 변환에 전달한다

- 근거: `client > data > 반영 흐름`
- Given: 고른 사진의 위치와 사진 전체를 기준으로 한 비율의 남길 영역이 있다.
- When: 그 위치와 남길 영역으로 프로필 이미지 반영을 시작한다.
- Then: 이미지를 읽어 JPEG로 바꾸는 요청에 그 위치와 남길 영역이 바뀌지 않고 그대로 담긴다.

### TC-PROFILE-IMAGE-DATA-009: 반영 자체는 사용자 정보를 다시 확인하지 않고, 다시 확인한 뒤 새 주소가 계정에 나타난다

- 근거: `client > data > 반영 결과의 전달`
- Given: 계정의 프로필 이미지가 직전 주소이고, 프로필 이미지 반영이 성공해 인증 제공자의 사용자 정보가 새 주소로 바뀐다.
- When: 반영이 끝나고, 그 뒤 앱이 인증 제공자의 사용자 정보를 다시 확인한다.
- Then: 반영이 끝난 직후에는 계정의 프로필 이미지가 직전 주소이고, 다시 확인한 뒤 새 주소로 바뀐다.

### TC-PROFILE-IMAGE-DATA-008: 바꾼 이미지는 반영의 성공이나 실패와 관계없이 올린 뒤 기기에서 지운다

- 근거: `client > data > 반영 흐름`
- Given: 고른 사진을 JPEG로 바꿔 기기에 임시로 두었고, 서버 반영이 테스트 데이터의 결과로 끝난다.
- When: 그 이미지를 올려 프로필 이미지 반영을 마친다.
- Then: 기기에 임시로 둔 바꾼 이미지가 한 번 지워진다.
- 테스트 데이터:

| 서버 반영 결과 |
| --- |
| 성공 |
| 실패 |

### TC-PROFILE-IMAGE-DATA-004: 반영에 실패하면 프로필 이미지가 직전 주소를 유지한다

- 근거: `client > domain > 반영 실패 시 상태`, `client > data > 반영 흐름`
- Given: 계정의 프로필 이미지가 직전 주소이고, 프로필 이미지 반영 요청이 실패한다.
- When: 고른 사진의 위치와 남길 영역으로 프로필 이미지 반영을 시작한다.
- Then: 실패가 전달되고 저장된 사용자 정보의 프로필 이미지가 직전 주소를 유지한다.

### TC-PROFILE-IMAGE-DATA-010: 계정에 반영하지 못한 이미지는 서버 보관 공간에 남기지 않는다

- 근거: `server > data > 반영 순서`
- Given: 서버가 받은 이미지를 보관한 뒤 테스트 데이터의 단계가 실패한다.
- When: 서버가 프로필 이미지 반영을 끝낸다.
- Then: 반영이 실패하고, 보관했던 이미지가 서버 보관 공간에 남지 않으며, 앱이 보는 프로필 이미지는 직전 주소를 유지한다.
- 테스트 데이터:

| 실패한 단계 |
| --- |
| 계정의 프로필 이미지를 새 주소로 바꾸기 |
| 인증 제공자의 사용자 정보를 새 주소로 바꾸기 |

- 작성하지 않는 이유: 올린 이미지를 버리는 것은 서버가 한 요청 안에서 처리하는 결과라 앱이 보낸 요청과 받은 응답만으로는 구분할 수 없다. 자동화하려면 실제 서버 보관 공간의 남은 파일을 조회하는 수단이 필요하다.

### TC-PROFILE-IMAGE-DATA-011: 로그인할 때 반영한 이미지로 되돌리고, 되돌리지 못해도 로그인은 성공한다

- 근거: `server > data > 로그인 시 프로필 이미지 유지`
- Given: 계정이 앱의 서버 보관 공간에 있는 프로필 이미지를 보관하고 있고, 인증 제공자의 사용자 정보를 되돌리는 것이 테스트 데이터의 결과로 끝난다.
- When: 사용자가 로그인한다.
- Then: 로그인 세션이 발급되고, 인증 제공자의 사용자 정보의 프로필 이미지가 테스트 데이터의 기대 결과가 된다.
- 테스트 데이터:

| 되돌리기 결과 | 기대 결과 |
| --- | --- |
| 성공 | 반영한 이미지 주소 |
| 실패 | 로그인 수단이 제공한 값. 다음 로그인에서 다시 되돌린다 |

- 작성하지 않는 이유: 반영한 이미지인지 판단해 인증 제공자의 사용자 정보를 되돌리는 것과, 되돌리지 못해도 세션을 전달하는 것은 모두 서버가 로그인 한 요청 안에서 처리하는 결과라 앱이 보낸 인증 결과와 받은 세션만으로는 구분할 수 없다. 로그인 뒤 앱이 인증 제공자의 사용자 정보를 계정 상태로 읽는 경로는 [계정 조회 테스트 케이스](./account.md)의 `TC-ACCOUNT-DATA-002`가 덮는다. 자동화하려면 실제 서버에서 되돌리기가 성공하거나 실패하도록 설정하고, 로그인한 뒤 인증 제공자의 사용자 정보를 조회하는 수단이 필요하다.

### TC-PROFILE-IMAGE-DATA-012: 서버는 받는 이미지 조건을 어긴 요청을 거절하고 이미지를 보관하지 않는다

- 근거: `server > data > 받는 이미지`, `common > data > 올리는 이미지`
- Given: 서버에 테스트 데이터의 요청이 도착한다.
- When: 서버가 요청을 처리한다.
- Then: 요청이 거절되고, 이미지가 보관되지 않으며 계정의 프로필 이미지는 직전 상태를 유지한다.
- 테스트 데이터:

| 요청 |
| --- |
| 인증된 로그인 세션 없이 보낸 요청 |
| 형식이 JPEG가 아닌 이미지 |
| 비어 있는 이미지 |
| 5MB를 넘는 이미지 |

- 작성하지 않는 이유: 서버의 요청 검증 규칙이어서 서버 함수 실행 환경에서만 판정할 수 있고, 그 환경은 저장소의 자동 검증 절차에 포함되어 있지 않다. 서버 함수 테스트 러너가 검증 절차에 들어오면 자동화한다.
