# 카메라 권한 요청 테스트 케이스

기준 스펙: [카메라 권한 요청 스펙](../spec/client/camera-permission.md)

모든 권한이 공유하는 요청 기준, 요청 결과는 [권한 요청 공통 스펙](../spec/client/permission.md)이 소유하고, 카메라 권한에 적용된 결과를 이 문서가 확인한다. 요청 결과에 따라 QrAdd 화면에서 보이는 결과는 [QrAdd 테스트 케이스](./qr-add.md)가 확인한다.

## feature

### TC-CAMERA-PERMISSION-FEATURE-001: 카메라 권한이 허용되어 있지 않으면 QR 스캔 시작 시 시스템 카메라 권한 요청이 시작된다

- 근거: `feature > QR 스캔 시작 시 카메라 권한 요청`
- Given: 카메라 권한 요청을 제공하는 환경에서 카메라 권한이 허용되어 있지 않고, QrAdd 화면이 표시되어 있다.
- When: 사용자가 QR 스캔 시작을 선택한다.
- Then: 시스템 카메라 권한 요청이 한 번 시작된다.

### TC-CAMERA-PERMISSION-FEATURE-002: 카메라 권한이 이미 허용되어 있으면 요청이 시작되지 않는다

- 근거: [권한 요청 공통 스펙의 요청 기준](../spec/client/permission.md#요청-기준)
- Given: 카메라 권한 요청을 제공하는 환경에서 카메라 권한이 이미 허용되어 있고, QrAdd 화면이 표시되어 있다.
- When: 사용자가 QR 스캔 시작을 선택한다.
- Then: 시스템 카메라 권한 요청이 시작되지 않는다.

## domain

### TC-CAMERA-PERMISSION-DOMAIN-001: QR 스캔 시작을 선택할 때마다 요청 조건을 다시 확인한다

- 근거: `domain > 요청 지점`
- Given: 카메라 권한 요청을 제공하는 환경에서 카메라 권한이 허용되어 있지 않고, 사용자가 QR 스캔 시작을 선택해 시작된 요청을 거부했다.
- When: 사용자가 같은 QrAdd 화면에서 QR 스캔 시작을 다시 선택한다.
- Then: 시스템 카메라 권한 요청이 다시 한 번 시작된다.

### TC-CAMERA-PERMISSION-DOMAIN-002: QrAdd 화면이나 QrScan 화면이 표시되는 것만으로는 요청하지 않는다

- 근거: `domain > 요청 지점`
- Given: 카메라 권한 요청을 제공하는 환경에서 카메라 권한이 허용되어 있지 않다.
- When: 테스트 데이터의 화면이 표시된다.
- Then: 시스템 카메라 권한 요청이 시작되지 않는다.
- 테스트 데이터:

  | 화면 |
  | --- |
  | QrAdd |
  | QrScan |

### TC-CAMERA-PERMISSION-DOMAIN-005: 데스크톱 앱에서도 시스템 카메라 권한 요청을 시작한다

- 근거: `domain > 요청 제공 범위`
- Given: 데스크톱 앱에서 시스템이 카메라 권한의 허용 여부를 테스트 데이터의 상태로 알려 주고, 요청을 표시하면 사용자가 테스트 데이터의 응답을 하도록 정해져 있다.
- When: 앱이 카메라 권한을 요청한다.
- Then: 테스트 데이터의 요청 표시 여부와 결과가 나온다.
- 테스트 데이터:

  | 허용 여부 | 사용자 응답 | 요청 표시 | 결과 |
  | --- | --- | --- | --- |
  | 허용됨 | — | 표시하지 않음 | 이미 허용 |
  | 아직 묻지 않음 | 허용 | 표시함 | 허용 |
  | 아직 묻지 않음 | 거부 | 표시함 | 거부 |
  | 거부됨 | — | 표시하지 않음 | 거부 |

### TC-CAMERA-PERMISSION-DOMAIN-006: 웹에서는 브라우저가 알려 주는 상태와 카메라 사용 요청의 응답으로 결과를 정한다

- 근거: `domain > 요청 제공 범위`
- Given: 웹에서 브라우저가 카메라 권한 상태를 테스트 데이터의 상태로 알려 주고, 카메라 사용을 요청하면 테스트 데이터의 응답을 하도록 정해져 있다.
- When: 앱이 카메라 권한을 요청한다.
- Then: 테스트 데이터의 결과가 나온다.
- 테스트 데이터:

  | 브라우저가 알려 주는 상태 | 카메라 사용 요청 응답 | 결과 |
  | --- | --- | --- |
  | 허용됨 | — | 이미 허용 |
  | 묻기 전 | 허용 | 허용 |
  | 알려 주지 않음 | 허용 | 허용 |
  | 알려 주지 않음 | 거부 | 거부 |
  | 알려 주지 않음 | 기기에 카메라가 없어 응할 수 없음 | 거부 |
  | 거부됨 | — | 거부 |

- 작성하지 않는 이유: 브라우저의 권한 상태와 카메라 사용 요청은 실제 브라우저에서만 재현되고, 현재 테스트 환경에는 웹 실행 환경이 없다. 브라우저에서 테스트를 실행할 수 있는 환경이 제공되면 자동화한다.

### TC-CAMERA-PERMISSION-DOMAIN-004: Android와 iOS에서 시스템이 더 이상 요청을 표시하지 않으면 거부와 같이 처리한다

- 근거: [권한 요청 공통 스펙의 요청 기준](../spec/client/permission.md#요청-기준)
- Given: Android 또는 iOS에서 사용자가 이전에 요청을 거부해 시스템이 더 이상 카메라 권한 요청을 표시하지 않는 상태다.
- When: 앱이 카메라 권한을 요청한다.
- Then: 사용자에게 요청이 표시되지 않고 거부로 처리된다.
- 작성하지 않는 이유: 요청을 더 이상 표시하지 않는 판단은 각 플랫폼의 권한 정책이 소유하며, 현재 테스트 환경은 Android와 iOS 플랫폼의 권한 상태를 그 상태로 만들 수 없다. 데스크톱 앱에서 거부된 상태의 결과는 TC-CAMERA-PERMISSION-DOMAIN-005가 확인한다. 플랫폼의 권한 표시 여부를 제어할 수 있는 테스트 환경이 제공되면 자동화한다.

### TC-CAMERA-PERMISSION-DOMAIN-007: Android에서는 기기에 카메라가 없어도 권한 요청이 진행되고 허용하면 허용으로 처리한다

- 근거: `domain > 요청 제공 범위`
- Given: Android에서 기기에 카메라가 없고 카메라 권한이 허용되어 있지 않으며, 요청을 표시하면 사용자가 허용하도록 정해져 있다.
- When: 앱이 카메라 권한을 요청한다.
- Then: 시스템 카메라 권한 요청이 한 번 시작되고 결과가 `허용`이다.

### TC-CAMERA-PERMISSION-DOMAIN-008: iOS와 데스크톱 앱에서도 기기에 카메라가 없어도 권한 요청이 진행된다

- 근거: `domain > 요청 제공 범위`
- Given: 테스트 데이터의 환경에서 기기에 카메라가 없고 카메라 권한이 허용되어 있지 않으며, 요청을 표시하면 사용자가 허용하도록 정해져 있다.
- When: 앱이 카메라 권한을 요청한다.
- Then: 시스템 카메라 권한 요청이 한 번 시작되고 결과가 `허용`이다.
- 테스트 데이터:

  | 환경 |
  | --- |
  | iOS |
  | 데스크톱 앱 |

- 작성하지 않는 이유: iOS는 현재 테스트 환경에서 실행하지 않고, 데스크톱 앱의 권한 요청은 시스템이 알려 주는 허용 여부와 사용자 응답만으로 결과가 정해져 카메라 유무를 조건으로 둘 수 있는 테스트 경계가 없다. 데스크톱 앱에서 허용 여부와 응답에 따른 결과는 TC-CAMERA-PERMISSION-DOMAIN-005가 확인한다. 실제 기기의 카메라 유무를 제어할 수 있는 테스트 환경이 제공되면 자동화한다.

## 작성하지 않는 케이스

- `이미 허용`과 `허용`을 구분하지 않는 결과는 두 결과에서 같은 화면 이동이 일어나는지로만 관찰되므로 [QrAdd 테스트 케이스](./qr-add.md)의 TC-QR-ADD-FEATURE-008에서 확인하고 여기서 중복 작성하지 않는다.
- 웹과 데스크톱 앱에서 요청 없이 거부로 처리한다던 TC-CAMERA-PERMISSION-DOMAIN-003은 두 환경에서도 카메라 권한 요청을 제공하게 되어 폐기하고, TC-CAMERA-PERMISSION-DOMAIN-005와 TC-CAMERA-PERMISSION-DOMAIN-006으로 대체했다.
