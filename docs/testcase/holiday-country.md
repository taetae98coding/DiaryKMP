# 공휴일 국가 설정 테스트 케이스

기준 스펙: [공휴일 국가 설정 스펙](../spec/holiday-country.md)

국가 설정이 동기화에 적용되는 결과는 [공휴일 동기화 테스트 케이스](./holiday-fetch.md)에서, 캘린더 공휴일 조회에 적용되는 결과는 [공휴일 노출 설정 테스트 케이스](./holiday-visibility.md)에서, 국가를 고르는 화면의 표시와 조작은 [SettingHoliday 테스트 케이스](./setting-holiday.md)에서 다룬다.

## domain

### TC-HOLIDAY-COUNTRY-DOMAIN-001: 국가 설정을 건드리지 않으면 기기값만 고른 상태다

- 근거: `domain > 기본값`
- Given: 국가 설정이 한 번도 저장되지 않았다.
- When: 고른 국가 선택지를 조회한다.
- Then: `기기값`만 고른 상태로 제공된다.

### TC-HOLIDAY-COUNTRY-DOMAIN-002: 고른 선택지와 기기 지역으로 적용 국가를 정한다

- 근거: `domain > 적용 국가`
- Given: 테스트 데이터의 선택지를 고른 상태이고 기기 지역이 테스트 데이터의 지역이다.
- When: 적용 국가를 조회한다.
- Then: 테스트 데이터의 적용 국가가 제공된다.
- 테스트 데이터:

  | 고른 선택지 | 기기 지역 | 적용 국가 |
  | --- | --- | --- |
  | `기기값` | 한국 | 한국 |
  | `기기값` | 미국 | 미국 |
  | `기기값` | 일본 | 없음 |
  | `한국` | 미국 | 한국 |
  | `미국` | 한국 | 미국 |
  | `한국`, `미국` | 일본 | 한국, 미국 |
  | `기기값`, `한국` | 한국 | 한국 |
  | `기기값`, `한국` | 미국 | 한국, 미국 |
  | 없음 | 한국 | 없음 |

### TC-HOLIDAY-COUNTRY-DOMAIN-003: 기기 지역이 바뀌면 다음 조회부터 바뀐 지역을 적용한다

- 근거: `domain > 적용 국가`, `data > 저장 시점`
- Given: `기기값`만 고른 상태이고 기기 지역이 한국이다.
- When: 기기 지역을 미국으로 바꾼 뒤 적용 국가를 다시 조회한다.
- Then: 적용 국가는 미국이다.

## data

### TC-HOLIDAY-COUNTRY-DATA-001: 선택지 하나를 바꾸면 그 선택지만 바뀌어 저장된다

- 근거: `data > 저장 시점`
- Given: 테스트 데이터의 선택지를 고른 상태다.
- When: 테스트 데이터의 선택지를 바꾼다.
- Then: 고른 선택지가 테스트 데이터의 결과로 저장되고, 이어지는 조회에서 그대로 제공된다.
- 테스트 데이터:

  | 처음 고른 선택지 | 바꾸는 선택지 | 결과 |
  | --- | --- | --- |
  | `기기값` | `한국` | `기기값`, `한국` |
  | `기기값`, `한국` | `기기값` | `한국` |
  | `한국`, `미국` | `미국` | `한국` |

### TC-HOLIDAY-COUNTRY-DATA-002: 모든 선택지를 해제한 상태도 그대로 저장된다

- 근거: `domain > 국가 선택지`, `data > 저장 시점`
- Given: `기기값`만 고른 상태다.
- When: `기기값`을 해제한다.
- Then: 고른 선택지가 없는 상태로 저장되고, 이어지는 조회에서 `기기값`으로 되돌아가지 않는다.

### TC-HOLIDAY-COUNTRY-DATA-003: 조회 중에 국가 설정이 바뀌면 이어서 새 결과를 제공한다

- 근거: `data > 설정 변경 반영`
- Given: 고른 선택지를 조회하고 있다.
- When: 선택지 하나를 바꾼다.
- Then: 바뀐 선택지가 이어서 제공된다.

### TC-HOLIDAY-COUNTRY-DATA-004: 국가 설정을 바꿔도 공휴일 노출 설정은 바뀌지 않는다

- 근거: `data > 저장 시점`
- Given: 숨긴 공휴일 key가 저장되어 있다.
- When: 국가 선택지를 바꾼다.
- Then: 저장된 숨김 key는 그대로 유지된다.

## 작성하지 않는 이유

- 앱을 종료하고 다시 시작한 뒤에도 국가 설정이 유지되는 규칙과 로그인·로그아웃·계정 전환 후에도 유지되는 규칙은 [공휴일 노출 설정 테스트 케이스](./holiday-visibility.md)의 `작성하지 않는 이유`와 같은 이유로 작성하지 않는다.
- 적용 국가에서 빠진 국가의 캐시가 남아 있다가 다시 쓰이는 규칙은 캐시 조회를 국가 집합으로 한정하는 [공휴일 로컬 캐시 테스트 케이스](./holiday-database.md)와 캘린더 조회를 적용 국가로 한정하는 [공휴일 노출 설정 테스트 케이스](./holiday-visibility.md)의 조합으로 덮이므로 중복 작성하지 않는다.
- 기기 지역이 언어 설정이 아니라 지역 설정을 기준으로 하는지는 실제 기기의 설정 화면과 플랫폼 SDK를 거쳐야 관찰할 수 있으므로 작성하지 않는다.
