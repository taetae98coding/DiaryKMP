# 공휴일 국가 설정 테스트 케이스

기준 스펙: [공휴일 국가 설정 스펙](../spec/client/holiday-country.md)

국가 설정이 동기화에 적용되는 결과는 [공휴일 동기화 테스트 케이스](./holiday-fetch.md)에서, 캘린더 공휴일 조회에 적용되는 결과는 [공휴일 노출 설정 테스트 케이스](./holiday-visibility.md)에서, 국가를 고르는 화면의 표시와 조작은 [SettingHoliday 테스트 케이스](./setting-holiday.md)에서 다룬다.

기기 지역을 바꾸고 다른 앱에 다녀왔을 때 화면이 바뀐 지역으로 다시 표시되는 시점은 [HolidayHome 테스트 케이스](./holiday-home.md)의 TC-a297cd36-c2ff-4065-9037-4c34460ef8b0, TC-254e8814-7a28-45bc-89f6-189a1792d1e1, TC-a8bb0295-cca6-41fa-9feb-3e2d8a6fa19a와 [SettingHoliday 테스트 케이스](./setting-holiday.md)의 TC-2fa1eea2-8ede-4799-b2e7-3a256656639b, TC-b5eb4725-954e-40a1-9757-74836d837235, [CalendarHome 테스트 케이스](./calendar-home.md)의 TC-8cbc8664-568f-41cf-b728-4fdcf8d58248에서 다룬다.

## domain

### TC-cd205cd1-fae2-4c27-8565-fb3a889c32df: 국가 설정을 건드리지 않으면 기기값만 고른 상태다

- 근거: `domain > 기본값`
- Given: 국가 설정이 한 번도 저장되지 않았다.
- When: 고른 국가 선택지를 조회한다.
- Then: `기기값`만 고른 상태로 제공된다.

### TC-809d9bb5-a454-4f34-81b5-91619a9881b9: 고른 선택지와 기기 지역으로 적용 국가를 정한다

- 근거: `domain > 적용 국가`
- Given: 테스트 데이터의 선택지를 고른 상태이고 기기 지역이 테스트 데이터의 지역이다.
- When: 적용 국가를 조회한다.
- Then: 테스트 데이터의 적용 국가가 제공된다.
- 테스트 데이터:

  | 고른 선택지 | 기기 지역 | 적용 국가 |
  | --- | --- | --- |
  | `기기값` | 한국 | 한국 |
  | `기기값` | 미국 | 미국 |
  | `기기값` | 일본 | 없음 |
  | `한국` | 미국 | 한국 |
  | `미국` | 한국 | 미국 |
  | `한국`, `미국` | 일본 | 한국, 미국 |
  | `기기값`, `한국` | 한국 | 한국 |
  | `기기값`, `한국` | 미국 | 한국, 미국 |
  | 없음 | 한국 | 없음 |

### TC-313e4e58-2c09-4cf8-98d3-fcb288929f01: 기기 지역이 바뀌면 다음 조회부터 바뀐 지역을 적용한다

- 근거: `domain > 적용 국가`, `data > 저장 시점`
- Given: `기기값`만 고른 상태이고 기기 지역이 한국이다.
- When: 기기 지역을 미국으로 바꾼 뒤 적용 국가를 다시 조회한다.
- Then: 적용 국가는 미국이다.

### TC-d26a6e51-fcef-49ea-ae2f-2dc707f70139: 두 국가에 같은 이름이 있으면 그 이름을 숨길 때 두 국가 모두 캘린더에서 빠진다

- 근거: `domain > 여러 국가의 공휴일`
- Given: 적용 국가가 한국과 미국이고, 같은 연도에 한국 공휴일과 미국 공휴일이 같은 이름으로 하나씩, 다른 이름의 공휴일이 하나 저장되어 있으며, 그 같은 이름을 숨김으로 골랐다.
- When: 그 연도의 캘린더용 공휴일을 조회한다.
- Then: 같은 이름의 한국 공휴일과 미국 공휴일이 모두 빠지고 다른 이름의 공휴일만 제공된다.

### TC-992f1222-917f-4fe8-b232-e182f67d5d9b: 두 국가에 같은 이름이 있으면 SettingHoliday에는 한 항목으로 나온다

- 근거: `domain > 여러 국가의 공휴일`
- Given: 적용 국가가 한국과 미국이고, 한국 공휴일과 미국 공휴일이 같은 이름으로 하나씩 저장되어 있다.
- When: SettingHoliday에 표시할 공휴일 항목을 구성한다.
- Then: 그 이름의 항목이 하나만 제공된다.

### TC-fb342438-e76c-4fc8-8bec-408e7a5226a7: 조회하는 동안 기기 지역만 바뀌면 새 결과를 제공하지 않는다

- 근거: `domain > 적용 국가`
- Given: `기기값`만 고른 상태이고 기기 지역이 한국인 채로 적용 국가를 계속 조회하고 있다.
- When: 고른 선택지는 그대로 둔 채 기기 지역을 미국으로 바꾼다.
- Then: 이어지는 결과가 제공되지 않아 적용 국가는 한국으로 남는다. 다시 조회하면 미국이 되는 결과는 TC-313e4e58-2c09-4cf8-98d3-fcb288929f01이 확인한다.

### TC-624458a6-d7b3-4d9e-9b51-ffbc2d1b8e14: 웹 앱에서는 브라우저 언어 설정에 적힌 지역을 기기 지역으로 쓴다

- 근거: `domain > 적용 국가`
- Given: 웹 앱에서 `기기값`만 고른 상태이고 브라우저 언어 설정이 테스트 데이터의 값이다.
- When: 적용 국가를 조회한다.
- Then: 테스트 데이터의 기기 지역을 기준으로 정한 적용 국가가 제공된다.
- 테스트 데이터:

  | 브라우저 언어 설정 | 기기 지역 | 적용 국가 |
  | --- | --- | --- |
  | `ko-KR` | 한국 | 한국 |
  | `en-US` | 미국 | 미국 |
  | `ja-JP` | 일본 | 없음 |
  | `ko` | 지원하지 않는 지역 | 없음 |

## data

### TC-30244e86-4f5d-431c-80d3-11ed649a4c1b: 선택지 하나를 바꾸면 그 선택지만 바뀌어 저장된다

- 근거: `data > 저장 시점`
- Given: 테스트 데이터의 선택지를 고른 상태다.
- When: 테스트 데이터의 선택지를 바꾼다.
- Then: 고른 선택지가 테스트 데이터의 결과로 저장되고, 이어지는 조회에서 그대로 제공된다.
- 테스트 데이터:

  | 처음 고른 선택지 | 바꾸는 선택지 | 결과 |
  | --- | --- | --- |
  | `기기값` | `한국` | `기기값`, `한국` |
  | `기기값`, `한국` | `기기값` | `한국` |
  | `한국`, `미국` | `미국` | `한국` |

### TC-5ee6a9fb-b7ed-4f21-88ed-c5a86e852215: 모든 선택지를 해제한 상태도 그대로 저장된다

- 근거: `domain > 국가 선택지`, `data > 저장 시점`
- Given: `기기값`만 고른 상태다.
- When: `기기값`을 해제한다.
- Then: 고른 선택지가 없는 상태로 저장되고, 이어지는 조회에서 `기기값`으로 되돌아가지 않는다.

### TC-404a8641-a0d5-463b-bc42-537e012fe935: 조회 중에 국가 설정이 바뀌면 이어서 새 결과를 제공한다

- 근거: `data > 설정 변경 반영`
- Given: 고른 선택지를 조회하고 있다.
- When: 선택지 하나를 바꾼다.
- Then: 바뀐 선택지가 이어서 제공된다.

### TC-7ce30960-3fc4-4288-8e02-5d517e5f78a3: 국가 설정을 바꿔도 공휴일 노출 설정은 바뀌지 않는다

- 근거: `data > 저장 시점`
- Given: 숨긴 공휴일 이름이 저장되어 있다.
- When: 국가 선택지를 바꾼다.
- Then: 저장된 숨긴 공휴일 이름은 그대로 유지된다.

### TC-0d734f0f-dd9e-4adc-9cbd-d6095ee05e47: 국가 설정을 바꿔도 기기에 저장된 공휴일은 바뀌지 않는다

- 근거: `data > 저장 시점`
- Given: 같은 연도의 한국 공휴일이 기기에 저장되어 있다.
- When: 국가 선택지를 바꾼 뒤 그 연도의 한국 공휴일을 조회한다.
- Then: 저장되어 있던 한국 공휴일이 그대로 제공된다.

## 작성하지 않는 이유

- 앱을 종료하고 다시 시작한 뒤에도 국가 설정이 유지되는 규칙과 로그인·로그아웃·계정 전환 후에도 유지되는 규칙은 [공휴일 노출 설정 테스트 케이스](./holiday-visibility.md)의 `작성하지 않는 이유`와 같은 이유로 작성하지 않는다.
- 적용 국가에서 빠진 국가의 공휴일이 기기에 남아 있다가 다시 쓰이는 규칙은 기기에 저장한 공휴일의 조회를 국가 집합으로 한정하는 [기기에 저장한 공휴일 테스트 케이스](./holiday-database.md)와 캘린더 조회를 적용 국가로 한정하는 [공휴일 노출 설정 테스트 케이스](./holiday-visibility.md)의 조합으로 덮이므로 중복 작성하지 않는다.
- 기기 지역이 언어 설정이 아니라 지역 설정을 기준으로 하는지는 실제 기기의 설정 화면과 플랫폼 SDK를 거쳐야 관찰할 수 있으므로 작성하지 않는다. 웹 앱이 브라우저 언어 설정에서 기기 지역을 정하는 규칙은 TC-624458a6-d7b3-4d9e-9b51-ffbc2d1b8e14이 언어 설정 값에서 기기 지역을 정하는 단계와 그 지역으로 적용 국가를 정하는 단계를 확인하고, 실제 브라우저가 언어 설정을 알려 주는 단계는 브라우저를 구동하는 테스트 환경이 갖춰지면 자동화한다.
