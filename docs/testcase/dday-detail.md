# DDayDetail 테스트 케이스

기준 스펙: [DDayDetail 화면 스펙](../spec/client/dday-detail.md)

진입할 때의 입력 초점, 조회 상태, 내용 수정의 반영과 성공·실패 결과, 삭제, 외부 변경, 태그 입력의 반영, 요청 제한과 저장·동기화 계약은 [항목 상세 화면 공통 스펙](../spec/client/entity-detail.md)에, 각 입력의 조작과 반복 간격을 기록하는 기준은 [DDayAdd 화면 스펙](../spec/client/dday-add.md)에 위임된 규칙을 이 화면에 적용한 결과를 이 문서가 확인한다. 케이스의 `근거`는 위임한 DDayDetail 화면 스펙의 절을 가리킨다.

태그 입력의 표시와 조작, 태그 선택 목록의 케이스는 [항목 태그 입력 컴포넌트 테스트 케이스](./entity-tag-input.md)에서 다룬다. `data > 결과의 표시`의 DDayHome 반영(카드 문구와 자리 이동)은 같은 저장 변경으로 [DDayHome 테스트 케이스](./dday-home.md)의 목록 갱신 케이스가, 캘린더 반영은 캘린더 디데이 표시 테스트 케이스가 확인한다. 목록과 상세 영역을 함께 표시하는 상태에서 삭제나 뒤로가기 뒤의 상세 영역은 [DDay 목록·상세 배치 테스트 케이스](./dday-list-detail.md)가 확인한다.

화면에 보이는 문구와 접근성 이름은 [DDayDetail 화면 디자인](../design/dday-detail.md)이 정한 문구를 기대 결과로 쓴다.
