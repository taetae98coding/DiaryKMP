# 메모 Gemini 작성 도우미 테스트 케이스

기준 스펙: [메모 Gemini 작성 도우미 스펙](../spec/client/memo-gemini.md)

MemoAdd 화면과 MemoDetail 화면이 같은 도우미를 제공하므로 이 문서의 케이스는 두 화면 모두에 적용된다. 반영한 내용으로 메모를 추가하거나 수정하는 케이스는 [MemoAdd 테스트 케이스](./memo-add.md)와 [MemoDetail 테스트 케이스](./memo-detail.md)에서 다룬다. Gemini 설정의 저장과 조회는 [SettingGemini 테스트 케이스](./setting-gemini.md)에서 다룬다.

## feature

### TC-MEMO-GEMINI-FEATURE-001: 설정이 갖춰져 있으면 프롬프트 입력으로 시작한다

- 근거: `feature > 도우미 시작`
- Given: 저장된 Gemini 설정의 인증 정보와 모델에 값이 있다.
- When: 사용자가 작성 도우미를 시작한다.
- Then: 도우미가 열리고 프롬프트를 입력할 수 있는 상태로 표시되며, 프롬프트는 비어 있다.

### TC-MEMO-GEMINI-FEATURE-002: 설정이 갖춰지지 않으면 열지 않고 설정 필요를 알린다

- 근거: `feature > 도우미 시작`
- Given: 저장된 Gemini 설정이 테스트 데이터의 상태다.
- When: 사용자가 작성 도우미를 시작한다.
- Then: 도우미가 열리지 않고 Gemini 설정이 필요하다는 안내가 표시되며, 생성 요청이 외부 경계로 나가지 않는다.
- 테스트 데이터:

| 인증 정보 | 모델 |
| --- | --- |
| 비어 있음 | 값 있음 |
| 값 있음 | 비어 있음 |
| 비어 있음 | 비어 있음 |

### TC-MEMO-GEMINI-FEATURE-003: 설정을 확인하지 못하면 시작 동작을 제공하지 않는다

- 근거: `feature > 도우미 시작`
- Given: 저장된 Gemini 설정을 아직 확인하지 못했거나 읽지 못한 상태다.
- When: 사용자가 화면을 확인한다.
- Then: 작성 도우미를 시작할 수 없고, 별도 로딩 또는 오류 상태도 제공되지 않는다.

### TC-MEMO-GEMINI-FEATURE-004: 프롬프트가 비어 있어도 생성을 실행할 수 있다

- 근거: `feature > 프롬프트 입력`
- Given: 도우미가 열려 있고 프롬프트가 비어 있다.
- When: 사용자가 생성을 실행한다.
- Then: 생성 요청이 외부 경계로 나가고 프롬프트 입력이 필요하다는 안내는 표시되지 않는다.

### TC-MEMO-GEMINI-FEATURE-005: 생성하는 동안 진행 상태를 표시한다

- 근거: `feature > 생성 실행`
- Given: 도우미가 열려 있고, 외부 응답이 아직 돌아오지 않도록 제어되어 있다.
- When: 사용자가 생성을 실행한다.
- Then: 생성이 진행 중임을 알리는 상태가 표시되고 생성을 취소할 수 있다.

### TC-MEMO-GEMINI-FEATURE-006: 생성 중에는 같은 생성 요청을 처리하지 않는다

- 근거: `feature > 생성 실행`, `domain > 요청 제한`
- Given: 외부 응답이 아직 돌아오지 않도록 제어된 상태에서 생성이 진행 중이다.
- When: 사용자가 생성을 다시 실행한다.
- Then: 생성 요청이 외부 경계로 한 번만 나간다.

### TC-MEMO-GEMINI-FEATURE-007: 생성에 성공하면 결과를 확인할 수 있다

- 근거: `feature > 결과 확인과 반영`
- Given: 도우미가 열려 있고, 생성 응답이 제목, 설명, 기간을 모두 담은 성공으로 제어되어 있다.
- When: 사용자가 생성을 실행한다.
- Then: 생성된 제목, 설명, 기간이 표시되고 각각을 따로 반영할 수 있다.

### TC-MEMO-GEMINI-FEATURE-008: 취소하면 요청을 멈추고 프롬프트를 유지한다

- 근거: `feature > 생성 취소`
- Given: 사용자가 프롬프트를 적고 생성을 실행했으며, 외부 응답이 아직 돌아오지 않도록 제어되어 있다.
- When: 사용자가 생성을 취소한다.
- Then: 프롬프트 입력 상태로 돌아가고 적었던 프롬프트가 그대로 표시되며, 결과가 표시되지 않고 메모의 제목, 설명, 기간 입력도 바뀌지 않는다.

### TC-MEMO-GEMINI-FEATURE-009: 취소한 뒤 다시 생성할 수 있다

- 근거: `feature > 생성 취소`, `domain > 요청 제한`
- Given: 사용자가 생성을 실행한 뒤 취소했다.
- When: 사용자가 생성을 다시 실행한다.
- Then: 생성 요청이 외부 경계로 다시 나간다.

### TC-MEMO-GEMINI-FEATURE-010: 생성 실패의 원인을 구분해 알린다

- 근거: `feature > 생성 실패`
- Given: 사용자가 프롬프트를 적었고, 생성 응답이 테스트 데이터의 실패로 제어되어 있다.
- When: 사용자가 생성을 실행한다.
- Then: 테스트 데이터의 안내가 표시되고 프롬프트 입력 상태로 돌아가며, 적었던 프롬프트와 메모의 제목, 설명, 기간 입력이 그대로 유지된다.
- 테스트 데이터:

| 생성 응답 | 표시되는 안내 |
| --- | --- |
| 인증 정보가 유효하지 않은 실패 | 인증 정보를 확인해야 한다는 안내 |
| 그 밖의 실패 | 생성에 실패했다는 안내 |

### TC-MEMO-GEMINI-FEATURE-011: 생성한 내용을 하나씩 따로 반영한다

- 근거: `feature > 결과 확인과 반영`, `domain > 반영 기준`
- Given: 제목, 설명, 기간이 모두 채워진 결과가 표시되어 있고, 메모의 제목, 설명, 기간 입력에 결과와 다른 값이 들어 있다.
- When: 사용자가 테스트 데이터의 하나만 반영한다.
- Then: 그 입력만 생성된 내용으로 바뀌고 나머지 두 입력은 반영 전 값을 그대로 유지한다.
- 테스트 데이터:

| 반영하는 결과 |
| --- |
| 제목 |
| 설명 |
| 기간 |

### TC-MEMO-GEMINI-FEATURE-012: 반영은 기존 입력을 덮어쓴다

- 근거: `domain > 반영 기준`
- Given: 제목과 설명이 채워진 결과가 표시되어 있고, 메모의 제목과 설명 입력에 다른 값이 들어 있다.
- When: 사용자가 제목과 설명을 차례로 반영한다.
- Then: 제목 입력과 설명 입력의 내용이 각각 생성된 내용만 담고, 반영 전 값이 남거나 이어 붙지 않는다.

### TC-MEMO-GEMINI-FEATURE-013: 기간을 반영하면 기간을 사용하는 상태가 된다

- 근거: `domain > 반영 기준`
- Given: 기간이 채워진 결과가 표시되어 있고, 메모의 날짜·시간 입력이 기간을 사용하지 않는 상태다.
- When: 사용자가 기간을 반영한다.
- Then: 날짜·시간 입력이 기간을 사용하는 상태가 되고 생성된 기간의 종일 여부, 시작, 종료가 표시된다.

### TC-MEMO-GEMINI-FEATURE-014: 반영해도 결과 확인 상태가 유지된다

- 근거: `feature > 결과 확인과 반영`
- Given: 제목, 설명, 기간이 모두 채워진 결과가 표시되어 있다.
- When: 사용자가 제목을 반영한다.
- Then: 도우미가 닫히지 않고 제목, 설명, 기간 결과가 그대로 표시되어 나머지도 반영할 수 있다.

### TC-MEMO-GEMINI-FEATURE-015: 같은 결과를 다시 반영할 수 있다

- 근거: `domain > 반영 기준`
- Given: 제목이 채워진 결과가 표시되어 있고, 사용자가 제목을 반영한 뒤 제목 입력을 다른 값으로 고쳤다.
- When: 사용자가 제목을 다시 반영한다.
- Then: 제목 입력의 내용이 생성된 제목으로 다시 바뀐다.

### TC-MEMO-GEMINI-FEATURE-016: 비어 있는 결과는 반영할 수 없다

- 근거: `feature > 결과 확인과 반영`
- Given: 생성 응답이 테스트 데이터의 결과를 담은 성공으로 제어되어 있다.
- When: 사용자가 생성을 실행한다.
- Then: 비어 있는 결과의 반영 동작이 제공되지 않고, 채워진 결과의 반영 동작만 제공된다.
- 테스트 데이터:

| 제목 | 설명 | 기간 |
| --- | --- | --- |
| 값 있음 | 비어 있음 | 없음 |
| 비어 있음 | 값 있음 | 없음 |
| 비어 있음 | 비어 있음 | 있음 |

### TC-MEMO-GEMINI-FEATURE-017: 생성된 내용이 하나도 없어도 실패로 다루지 않는다

- 근거: `domain > 생성 결과`
- Given: 생성 응답이 제목, 설명, 기간이 모두 비어 있는 성공으로 제어되어 있다.
- When: 사용자가 생성을 실행한다.
- Then: 실패 안내가 표시되지 않고 결과 확인 상태가 되며, 반영할 수 있는 결과가 하나도 제공되지 않는다.

### TC-MEMO-GEMINI-FEATURE-018: 결과 확인 상태에서는 다시 생성할 수 없다

- 근거: `feature > 결과 확인과 반영`
- Given: 결과가 표시되어 있다.
- When: 사용자가 결과를 확인한다.
- Then: 다시 생성하는 동작이 제공되지 않는다.

### TC-MEMO-GEMINI-FEATURE-019: 닫았다가 다시 열면 프롬프트와 결과를 버린다

- 근거: `feature > 도우미 닫기`
- Given: 사용자가 프롬프트를 적어 생성에 성공해 결과가 표시되어 있다.
- When: 사용자가 도우미를 닫고 다시 시작한다.
- Then: 프롬프트가 비어 있고 직전 결과가 표시되지 않는다.

### TC-MEMO-GEMINI-FEATURE-020: 생성 중에 닫으면 요청을 멈춘다

- 근거: `feature > 도우미 닫기`
- Given: 외부 응답이 아직 돌아오지 않도록 제어된 상태에서 생성이 진행 중이다.
- When: 사용자가 도우미를 닫는다.
- Then: 도우미가 닫히고, 이후 응답이 돌아와도 결과가 표시되지 않으며 메모의 입력도 바뀌지 않는다.

### TC-MEMO-GEMINI-FEATURE-021: 반영한 내용은 도우미를 닫아도 남는다

- 근거: `feature > 도우미 닫기`
- Given: 사용자가 결과에서 제목을 반영했다.
- When: 사용자가 도우미를 닫는다.
- Then: 제목 입력에 반영한 내용이 그대로 표시된다.

### TC-MEMO-GEMINI-FEATURE-022: 화면이 재생성되어도 도우미 상태를 유지한다

- 근거: `domain > 진행 상태 유지`
- Given: 사용자가 도우미를 열고 프롬프트를 적어 둔 상태다.
- When: 화면이 재생성된다.
- Then: 도우미가 열린 상태로 남고 적어 둔 프롬프트가 그대로 표시된다.

### TC-MEMO-GEMINI-FEATURE-023: 상세 대상이 바뀌면 도우미가 닫힌다

- 근거: `domain > 진행 상태 유지`
- Given: MemoDetail 화면에서 사용자가 도우미를 열고 프롬프트를 적어 둔 상태다.
- When: 상세 대상이 다른 메모로 바뀐다.
- Then: 도우미가 닫히고 적어 둔 프롬프트가 이어지지 않는다.

### TC-MEMO-GEMINI-FEATURE-024: 반영한 결과에 반영했다는 표시가 보인다

- 근거: `feature > 결과 확인과 반영`
- Given: 제목, 설명, 기간이 모두 채워진 결과가 표시되어 있다.
- When: 사용자가 제목만 반영한다.
- Then: 제목 결과에 반영했다는 표시가 보이고, 설명과 기간 결과에는 보이지 않는다.

### TC-MEMO-GEMINI-FEATURE-025: 도우미를 닫으면 반영 표시가 사라진다

- 근거: `feature > 결과 확인과 반영`
- Given: 사용자가 결과에서 제목을 반영해 반영했다는 표시가 보인다.
- When: 사용자가 도우미를 닫고 다시 시작해 생성에 성공한다.
- Then: 어느 결과에도 반영했다는 표시가 보이지 않는다.

### TC-MEMO-GEMINI-FEATURE-026: 다른 화면에서 저장한 설정으로 다음 시작을 판정한다

- 근거: `feature > 도우미 시작`
- Given: 저장된 Gemini 설정의 인증 정보가 비어 있는 상태로 화면이 표시되어 있고, 사용자가 도우미를 시작해 Gemini 설정이 필요하다는 안내를 받았다.
- When: 다른 화면에서 인증 정보와 모델을 채운 설정이 저장된 뒤, 사용자가 이 화면을 다시 열지 않고 도우미를 시작한다.
- Then: 도우미가 열리고 프롬프트를 입력할 수 있는 상태로 표시된다.

### TC-MEMO-GEMINI-FEATURE-027: 설명을 반영해도 보고 있던 입력·미리보기 상태가 바뀌지 않는다

- 근거: `domain > 반영 기준`
- Given: 설명이 채워진 결과가 표시되어 있고, 메모의 설명 입력이 테스트 데이터의 상태를 보고 있다.
- When: 사용자가 설명을 반영한다.
- Then: 설명 입력의 내용이 생성된 설명으로 바뀌고, 설명 입력은 반영 전에 보고 있던 상태를 그대로 보여 준다.
- 테스트 데이터:

| 반영 전에 보고 있던 상태 |
| --- |
| 입력 |
| 미리보기 |

### TC-MEMO-GEMINI-FEATURE-028: 화면이 재생성되어도 진행 중인 생성과 받아 둔 결과를 유지한다

- 근거: `domain > 진행 상태 유지`
- Given: 도우미가 테스트 데이터의 상태다.
- When: 화면이 재생성된다.
- Then: 도우미가 열린 상태로 남고 테스트 데이터의 표시가 그대로 보인다.
- 테스트 데이터:

| 도우미 상태 | 재생성 뒤 표시 |
| --- | --- |
| 생성 중 | 생성이 진행 중임을 알리는 상태와 취소 동작 |
| 결과 확인 | 받아 둔 제목, 설명, 기간과 각각의 반영 동작 |

### TC-MEMO-GEMINI-FEATURE-029: 도우미가 열려 있는 동안 뒤로가기를 하면 도우미만 닫힌다

- 근거: `feature > 도우미 시작`, `feature > 도우미 닫기`
- Given: MemoAdd 화면에서 사용자가 도우미를 열어 프롬프트 입력 상태가 표시되어 있다.
- When: 사용자가 뒤로가기를 한다.
- Then: MemoAdd 화면을 떠나지 않고 도우미만 닫힌다.

## domain

### TC-MEMO-GEMINI-DOMAIN-001: 인증 정보와 모델이 모두 있어야 시작할 수 있다

- 근거: `domain > 도우미를 시작할 수 있는 조건`
- Given: 저장된 Gemini 설정이 테스트 데이터의 상태다.
- When: 도우미를 시작할 수 있는지 판정한다.
- Then: 테스트 데이터의 결과가 된다.
- 테스트 데이터:

| 인증 정보 | 모델 | 시스템 프롬프트 | 결과 |
| --- | --- | --- | --- |
| 값 있음 | 값 있음 | 값 있음 | 시작할 수 있음 |
| 값 있음 | 값 있음 | 비어 있음 | 시작할 수 있음 |
| 비어 있음 | 값 있음 | 값 있음 | 시작할 수 없음 |
| 값 있음 | 비어 있음 | 값 있음 | 시작할 수 없음 |
| 비어 있음 | 비어 있음 | 비어 있음 | 시작할 수 없음 |

### TC-MEMO-GEMINI-DOMAIN-002: 공백뿐인 제목과 설명은 없는 결과로 본다

- 근거: `domain > 생성 결과`
- Given: 생성 응답이 제목과 설명이 공백 문자로만 이루어진 성공으로 제어되어 있다.
- When: 사용자가 생성을 실행한다.
- Then: 제목과 설명의 반영 동작이 제공되지 않는다.

### TC-MEMO-GEMINI-DOMAIN-003: 시작이 종료보다 늦은 기간은 없는 결과로 본다

- 근거: `domain > 생성 결과`
- Given: 생성 응답이 시작이 종료보다 늦은 기간을 담은 성공으로 제어되어 있다.
- When: 사용자가 생성을 실행한다.
- Then: 기간의 반영 동작이 제공되지 않는다.

### TC-MEMO-GEMINI-DOMAIN-004: 도우미는 컬러와 연결을 바꾸지 않는다

- 근거: `domain > 작성 도우미`
- Given: 메모에 컬러가 정해져 있고 태그, 대표 태그, 웹, 장소, 연락처가 선택되어 있으며, 제목, 설명, 기간이 모두 채워진 결과가 표시되어 있다.
- When: 사용자가 제목, 설명, 기간을 모두 반영한다.
- Then: 컬러와 태그, 대표 태그, 웹, 장소, 연락처 선택이 반영 전과 같다.

## data

### TC-MEMO-GEMINI-DATA-001: 저장된 인증 정보와 모델로 생성을 요청한다

- 근거: `data > 원격 생성`
- Given: Gemini 설정이 값이 있는 인증 정보와 모델로 저장되어 있다.
- When: 사용자가 생성을 실행한다.
- Then: 외부 경계로 나가는 생성 요청에 저장된 인증 정보와 모델이 포함된다.

### TC-MEMO-GEMINI-DATA-002: 프롬프트와 지금 입력 중인 내용을 함께 보낸다

- 근거: `domain > 생성에 보내는 내용`
- Given: 저장된 시스템 프롬프트에 값이 있고, 메모의 제목, 설명, 기간 입력에 저장된 메모와 다른 값이 들어 있다.
- When: 사용자가 프롬프트를 적고 생성을 실행한다.
- Then: 외부 경계로 나가는 생성 요청에 저장된 시스템 프롬프트, 사용자가 적은 프롬프트, 입력 중인 제목·설명·기간, 요청 시점의 날짜·시각과 시간대가 포함된다.

### TC-MEMO-GEMINI-DATA-003: 비어 있는 시스템 프롬프트와 프롬프트는 보내지 않는다

- 근거: `domain > 생성에 보내는 내용`
- Given: 저장된 시스템 프롬프트가 비어 있다.
- When: 사용자가 프롬프트를 비운 채 생성을 실행한다.
- Then: 외부 경계로 나가는 생성 요청에 시스템 프롬프트와 프롬프트가 포함되지 않는다.

### TC-MEMO-GEMINI-DATA-004: 컬러와 연결은 보내지 않는다

- 근거: `domain > 생성에 보내는 내용`
- Given: 메모에 컬러가 정해져 있고 태그, 웹, 장소, 연락처가 선택되어 있다.
- When: 사용자가 생성을 실행한다.
- Then: 외부 경계로 나가는 생성 요청에 컬러, 태그, 웹, 장소, 연락처와 그 밖에 메모를 가리키는 정보가 포함되지 않는다.

### TC-MEMO-GEMINI-DATA-005: 구조를 지키지 않은 응답은 그 밖의 실패로 알린다

- 근거: `data > 원격 생성`
- Given: 생성 응답이 요청한 구조를 지키지 않은 내용으로 제어되어 있다.
- When: 사용자가 생성을 실행한다.
- Then: 생성에 실패했다는 안내가 표시되고, 인증 정보를 확인해야 한다는 안내는 표시되지 않는다.

### TC-MEMO-GEMINI-DATA-006: 실패를 빈 결과로 바꾸지 않는다

- 근거: `data > 실패 처리`
- Given: 생성 응답이 실패로 제어되어 있다.
- When: 사용자가 생성을 실행한다.
- Then: 결과 확인 상태가 되지 않고 실패가 그대로 알려진다.

### TC-MEMO-GEMINI-DATA-007: 생성은 메모를 만들거나 바꾸지 않는다

- 근거: `data > 저장하지 않는 것`
- Given: 생성 응답이 제목, 설명, 기간을 모두 담은 성공으로 제어되어 있다.
- When: 사용자가 생성을 실행하고 제목, 설명, 기간을 모두 반영한다.
- Then: 기기에 저장된 메모가 새로 만들어지거나 바뀌지 않는다.
- 작성하지 않는 이유: 생성과 반영은 메모를 기기에 저장하는 과정을 거치지 않아 관찰할 저장 자체가 없다. 반영이 화면 입력만 바꾸는 것은 TC-MEMO-GEMINI-FEATURE-011이, 그 입력이 저장되는 시점은 [MemoAdd 테스트 케이스](./memo-add.md)와 [MemoDetail 테스트 케이스](./memo-detail.md)가 다룬다. 저장하지 않는다는 사실 자체를 검증하려면 기기에 저장된 메모 전체의 변화를 관찰하는 통합 테스트 환경이 필요하다.

### TC-MEMO-GEMINI-DATA-008: 공백뿐인 제목과 설명, 사용하지 않는 기간은 보내지 않는다

- 근거: `domain > 생성에 보내는 내용`
- Given: 메모의 제목과 설명 입력이 비어 있거나 공백뿐이고, 날짜·시간 입력에 기간이 들어 있지만 기간을 사용하지 않는 상태다.
- When: 사용자가 생성을 실행한다.
- Then: 외부 경계로 나가는 생성 요청에 입력 중인 제목, 설명, 기간이 포함되지 않는다.

## 작성하지 않는 이유

- `domain > 진행 상태 유지`의 화면 이탈과 앱 재실행 후 도우미가 닫히고 프롬프트와 결과가 남지 않는 규칙은 실제 앱의 실행 경계와 전환 이력을 함께 제어하고 관찰해야 하므로 현재 테스트 환경에서는 결정적으로 자동화할 수 없다. 해당 실행 경계를 제어하는 통합 테스트 환경이 갖춰지면 자동화한다. 화면 재생성 경계는 TC-MEMO-GEMINI-FEATURE-022에서 다룬다.
- `domain > 요청 제한`의 생성이 메모 추가·수정과 서로를 제한하지 않는다는 규칙은, 도우미가 열려 있으면 다른 동작을 실행할 수 없고(`feature > 도우미 시작`) 닫혀 있으면 생성이 진행 중일 수 없어 두 요청이 동시에 존재하는 상황을 만들 수 없다. 도우미를 연 채 메모 추가·수정을 실행하는 동작이 생기면 그때 자동화한다.
- `data > 저장하지 않는 것`의 프롬프트와 결과를 기기에 저장하지 않는 규칙은 저장하지 않는 대상에 대응하는 저장 영역 자체가 없어 관찰할 저장 상태가 없다. 도우미를 닫으면 사라지는 결과는 TC-MEMO-GEMINI-FEATURE-019에서 다룬다.
- `data > 저장하지 않는 것`의 동기화 대상이 아니라는 규칙은 동기화 전체를 거쳐야 관찰할 수 있으므로 유닛 테스트 케이스로 작성하지 않는다.
