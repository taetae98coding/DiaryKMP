# Login 테스트 케이스

기준 스펙: [Login 화면 스펙](../spec/client/login.md), [로그인 스펙(common)](../spec/common/login.md), [로그인 스펙(server)](../spec/server/login.md)

각 케이스의 `근거`는 절이 있는 스펙 폴더를 앞에 붙여 `client > domain > 절 이름`처럼 적는다.

`server > domain > 처음 로그인하는 사용자`의 계정 생성은 실제 서버 데이터베이스 동작이 필요하므로 유닛 테스트 범위에서 제외한다.

`server > domain > 인증 수단과 계정 동일성`의 계정 연결도 같은 이유로 제외한다. 이메일이 같은 다른 인증 수단이 기존 계정에 연결되는지는 실제 인증 제공자의 사용자 상태가 있어야 판정할 수 있다.

오류 보고가 남는 방식 자체의 케이스는 [기능 실패 로깅 테스트 케이스](./usecase-failure-logging.md)에서 다룬다. 이 문서에서는 앱 로그인이 오류 보고 대상인지를 다룬다.

## feature

### TC-LOGIN-FEATURE-001: 뒤로가기를 사용하면 이전 화면으로 돌아간다

- 근거: `client > feature > 진입과 종료`
- Given: Login 화면이 표시되어 있다.
- When: 사용자가 뒤로가기를 실행한다.
- Then: Login 화면이 닫히고 진입하기 전 화면이 표시된다.

### TC-LOGIN-FEATURE-020: Google 로그인과 Apple 로그인을 제공한다

- 근거: `client > feature > 로그인 수단`, `client > domain > 제공하는 로그인 수단`
- Given: Login 화면에 진입할 수 있다.
- When: 사용자가 Login 화면에 진입한다.
- Then: Google 로그인과 Apple 로그인 중 하나를 선택할 수 있다.

### TC-LOGIN-FEATURE-004: 선택한 수단의 로그인을 시작한다

- 근거: `client > feature > 로그인 진행과 완료`
- Given: 로그인 요청이 진행 중이지 않고 Login 화면에서 테스트 데이터의 로그인 수단을 선택할 수 있다.
- When: 사용자가 해당 로그인 수단을 선택한다.
- Then: 현재 플랫폼의 해당 수단 로그인 흐름이 한 번 시작되고, 다른 수단의 로그인 흐름은 시작되지 않는다.
- 테스트 데이터:

| 로그인 수단 |
| --- |
| Google |
| Apple |

### TC-LOGIN-FEATURE-006: 로그인 취소를 오류로 안내하지 않는다

- 근거: `client > feature > 취소와 오류`
- Given: 테스트 데이터의 수단 로그인 흐름이 사용자 취소 결과를 반환하도록 설정되어 있다.
- When: 사용자가 해당 수단의 로그인을 시작한 뒤 취소한다.
- Then: 로그인 실패 안내가 표시되지 않고 Login 화면에 머무르며 다시 로그인할 수 있다.
- 테스트 데이터:

| 로그인 수단 |
| --- |
| Google |
| Apple |

### TC-LOGIN-FEATURE-007: 로그인 실패를 안내한다

- 근거: `client > feature > 취소와 오류`
- Given: 로그인 수단과 실패 지점이 테스트 데이터와 같이 설정되어 있다.
- When: 사용자가 해당 수단으로 로그인을 시도하고 해당 지점에서 실패한다.
- Then: 로그인 실패 안내가 표시되고 진행 상태가 종료되어 다시 로그인할 수 있다.
- 테스트 데이터:

| 실패 지점 | 로그인 수단 |
| --- | --- |
| 인증 결과 획득 | Google |
| 인증 결과 획득 | Apple |
| 서버 인증 | 수단 무관 |
| 앱 세션 설정 | 수단 무관 |

### TC-LOGIN-FEATURE-009: 앱 로그인 처리 중 진행 표시를 유지한다

- 근거: `client > feature > 로그인 진행과 완료`
- Given: 인증 결과를 받은 뒤 앱 로그인 처리가 완료되지 않았다.
- When: 사용자가 Login 화면을 확인한다.
- Then: 앱 로그인 처리가 끝날 때까지 진행 중인 상태가 표시된다.

### TC-LOGIN-FEATURE-010: 앱 로그인 처리 중 추가 로그인을 시작할 수 없다

- 근거: `client > domain > 로그인 요청 제한`
- Given: 첫 번째 앱 로그인 요청이 처리 중이다.
- When: 같은 Login 화면에 테스트 데이터의 추가 로그인 요청이 전달된다.
- Then: 새로운 로그인 흐름이나 앱 로그인 요청이 시작되지 않는다.
- 테스트 데이터:

| 추가 로그인 요청 |
| --- |
| 처리 중인 수단과 같은 수단 |
| 처리 중인 수단과 다른 수단 |

### TC-LOGIN-FEATURE-013: 로그인 완료 시 이전 화면으로 돌아간다

- 근거: `client > feature > 로그인 진행과 완료`
- Given: 테스트 데이터의 수단으로 인증, 서버 인증, 앱 세션 설정이 모두 성공하도록 설정되어 있다.
- When: 사용자가 해당 수단의 로그인을 완료한다.
- Then: Login 화면이 닫히고 진입하기 전 화면이 표시된다.
- 테스트 데이터:

| 로그인 수단 |
| --- |
| Google |
| Apple |

### TC-LOGIN-FEATURE-014: 앱 로그인 처리 중에도 이전 화면으로 돌아갈 수 있다

- 근거: `client > feature > 진입과 종료`, `client > domain > 로그인 요청 제한`
- Given: 앱 로그인 요청이 처리 중이다.
- When: 사용자가 뒤로가기를 실행한다.
- Then: Login 화면이 닫히고 진입하기 전 화면이 표시된다.

### TC-LOGIN-FEATURE-015: 로그인 실패 후 다시 로그인할 수 있다

- 근거: `client > feature > 취소와 오류`, `client > domain > 제공하는 로그인 수단`
- Given: 첫 번째 로그인은 실패하고, 테스트 데이터의 두 번째 로그인은 성공하도록 설정되어 있다.
- When: 사용자가 실패 안내 후 테스트 데이터의 로그인 수단을 선택해 로그인을 완료한다.
- Then: 두 번째 로그인 요청이 시작되고, 성공하면 Login 화면이 닫힌 뒤 진입하기 전 화면이 표시된다.
- 테스트 데이터:

| 두 번째 로그인 수단 |
| --- |
| 실패한 수단과 같은 수단 |
| 실패한 수단과 다른 수단 |

### TC-LOGIN-FEATURE-017: 인증 정보와 로그인 세션 정보를 화면에 표시하지 않는다

- 근거: `client > data > 인증 결과 노출 제한`
- Given: 인증 결과 또는 로그인 세션 정보를 받은 로그인 시도가 진행 중이거나 완료되었다.
- When: 사용자가 Login 화면을 확인한다.
- Then: 인증 결과와 로그인 세션 정보가 화면에 표시되지 않는다.
- 작성하지 않는 이유: 인증 결과와 로그인 세션 정보는 화면 상태로 전달되지 않아 화면에서 관찰할 값 자체가 없다. 실제 인증 결과와 로그인 세션 정보를 주입해 화면 전체에서 노출 여부를 판정할 수 있는 테스트 환경이 갖춰지면 자동화한다.

### TC-LOGIN-FEATURE-021: 앱 로그인 전에 끝난 실패는 오류 보고를 남기지 않는다

- 근거: `client > domain > 앱 로그인 실패 보고`
- Given: 오류 보고 기록 수단이 등록되어 있고, 테스트 데이터의 수단과 실패 지점이 설정되어 있다.
- When: 사용자가 해당 수단의 로그인을 시도해 해당 지점에서 끝난다.
- Then: 오류 보고가 남지 않는다.
- 테스트 데이터:

| 실패 지점 | 로그인 수단 |
| --- | --- |
| 사용자 취소 | Google |
| 사용자 취소 | Apple |
| 인증 결과 획득 | Google |
| 인증 결과 획득 | Apple |


### TC-LOGIN-FEATURE-022: Android에서 로그인 브라우저 탭을 응답 없이 닫으면 취소로 처리한다

- 근거: `client > feature > 취소와 오류`
- Given: Android에서 Apple 로그인이 브라우저 탭에서 시작되어 앱이 화면 뒤로 물러났다.
- When: 사용자가 인증 결과 없이 브라우저 탭을 닫고 앱으로 돌아온다.
- Then: 로그인 실패 안내가 표시되지 않고 앱 로그인 요청이 시작되지 않으며, 사용자는 다시 로그인할 수 있다.

### TC-LOGIN-FEATURE-023: Android에서 앱으로 돌아온 뒤 도착한 인증 결과로 로그인한다

- 근거: `client > feature > 취소와 오류`, `client > feature > 로그인 진행과 완료`
- Given: Android에서 Apple 로그인이 브라우저 탭에서 시작되어 앱이 화면 뒤로 물러났다.
- When: 인증 결과가 앱 복귀 주소로 도착하고 앱이 다시 화면 앞으로 돌아온다.
- Then: 취소로 처리되지 않고 그 인증 결과로 앱 로그인이 진행된다.

### TC-LOGIN-FEATURE-024: 웹에서 로그인 창을 응답 없이 닫으면 취소로 처리한다

- 근거: `client > feature > 취소와 오류`
- Given: 웹에서 Apple 로그인이 별도 창에서 시작되었다.
- When: 사용자가 인증 결과 없이 로그인 창을 닫는다.
- Then: 로그인 실패 안내가 표시되지 않고 Login 화면에 머무르며 다시 로그인할 수 있다.
- 작성하지 않는 이유: 로그인 창이 닫혔는지는 실제 브라우저의 창 상태로만 관찰할 수 있다. 브라우저 창 상태를 제어할 수 있는 웹 테스트 환경이 갖춰지면 자동화한다.

### TC-LOGIN-FEATURE-025: 앱 로그인 처리 중에 화면이 재생성되어도 진행 표시가 이어진다

- 근거: `client > domain > 실행 경계`
- Given: 인증 결과를 받은 뒤 앱 로그인 처리가 완료되지 않았고, 진행 중인 상태가 표시되어 있다.
- When: 화면이 재생성된다.
- Then: 로그인 버튼 대신 진행 중인 상태가 계속 표시된다.

### TC-LOGIN-FEATURE-026: Login 화면에 다시 들어오면 로그인 수단 선택 대기 상태에서 시작한다

- 근거: `client > domain > 실행 경계`
- Given: 이전에 Login 화면에서 로그인을 시도해 테스트 데이터의 상태로 끝났고, 사용자가 Login 화면을 떠났다.
- When: 사용자가 Login 화면에 다시 들어온다.
- Then: 진행 중인 상태와 실패 안내가 표시되지 않고, 로그인 수단을 선택할 수 있다.
- 테스트 데이터:

| 이전 시도의 상태 |
| --- |
| 앱 로그인 처리 중 |
| 앱 로그인 실패 |

### TC-LOGIN-FEATURE-027: 웹에서 브라우저가 로그인 창을 막으면 로그인 실패를 안내한다

- 근거: `client > feature > 취소와 오류`
- Given: 웹에서 브라우저가 새 창을 열지 못하게 막는다.
- When: 사용자가 로그인 수단을 선택한다.
- Then: 로그인 실패 안내가 표시되고 앱 로그인 요청이 시작되지 않으며, 사용자는 다시 로그인할 수 있다.
- 작성하지 않는 이유: 로그인 창이 막혔는지는 실제 브라우저의 창 열기 결과로만 관찰할 수 있고, 저장소의 자동 검증 절차에는 웹 브라우저 테스트 환경이 없다. 브라우저의 창 열기 결과를 제어할 수 있는 웹 테스트 환경이 갖춰지면 자동화한다.

### TC-LOGIN-FEATURE-028: 끝을 알 수 있는 플랫폼 로그인 흐름이 진행 중이면 로그인 수단을 다시 선택해도 새 흐름을 시작하지 않는다

- 근거: `client > feature > 로그인 진행과 완료`, `client > domain > 로그인 요청 제한`
- Given: 흐름의 끝을 알 수 있는 플랫폼에서 사용자가 로그인 수단을 선택해 플랫폼 로그인 흐름이 시작되었고, 아직 끝나지 않았다.
- When: 사용자가 테스트 데이터의 로그인 수단을 다시 선택한다.
- Then: 새 플랫폼 로그인 흐름이 시작되지 않고, 진행 중인 흐름이 끝나 인증 결과를 받으면 그 결과로 앱 로그인 요청이 한 번만 시작된다.
- 테스트 데이터:

| 다시 선택한 로그인 수단 |
| --- |
| 진행 중인 흐름과 같은 수단 |
| 진행 중인 흐름과 다른 수단 |

### TC-LOGIN-FEATURE-029: 플랫폼 로그인 흐름 중에 화면이 재생성되면 흐름을 중단하고 안내하지 않는다

- 근거: `client > domain > 실행 경계`
- Given: 테스트 데이터의 플랫폼에서 사용자가 로그인 수단을 선택해 플랫폼 로그인 흐름이 시작되었고, 아직 끝나지 않았다.
- When: 화면이 재생성된다.
- Then: 진행 중이던 흐름이 중단되고, 로그인 실패 안내와 진행 중인 상태 없이 로그인 수단을 선택할 수 있는 상태가 되며, 다시 선택하면 새 플랫폼 로그인 흐름이 시작된다.
- 테스트 데이터:

| 플랫폼 |
| --- |
| 흐름의 끝을 알 수 있는 플랫폼 |
| 흐름의 끝을 알 수 없는 플랫폼 |

### TC-LOGIN-FEATURE-030: 끝을 알 수 있는 플랫폼 로그인 흐름이 진행되는 동안 진행 중인 상태를 표시한다

- 근거: `client > feature > 로그인 진행과 완료`
- Given: 흐름의 끝을 알 수 있는 플랫폼이다.
- When: 사용자가 테스트 데이터의 로그인 수단을 선택해 플랫폼 로그인 흐름이 진행된다.
- Then: 로그인 버튼 대신 진행 중인 상태가 표시되고, 상단 바의 뒤로가기는 계속 사용할 수 있다. 흐름이 취소로 끝나면 진행 중인 상태가 사라지고 로그인 버튼이 다시 보인다.
- 테스트 데이터:

| 로그인 수단 |
| --- |
| Google |
| Apple |

### TC-LOGIN-FEATURE-031: 끝을 알 수 있는 플랫폼 로그인 흐름이 인증 결과를 받으면 진행 중인 상태가 끊기지 않고 앱 로그인 처리로 이어진다

- 근거: `client > feature > 로그인 진행과 완료`
- Given: 흐름의 끝을 알 수 있는 플랫폼에서 플랫폼 로그인 흐름이 진행 중이고 진행 중인 상태가 표시되어 있다.
- When: 흐름이 인증 결과를 받아 앱 로그인 처리가 시작된다.
