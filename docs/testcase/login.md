# Login 테스트 케이스

기준 스펙: [Login 화면 스펙](../spec/login.md)

최초 로그인 사용자의 계정 생성은 실제 서버 데이터베이스 동작이 필요하므로 유닛 테스트 범위에서 제외한다.

`domain > 인증 수단과 계정 동일성`의 계정 연결도 같은 이유로 제외한다. 이메일이 같은 다른 인증 수단이 기존 계정에 연결되는지는 실제 인증 제공자의 사용자 상태가 있어야 판정할 수 있다.

오류 보고가 남는 방식 자체의 케이스는 [UseCase 실패 로깅 테스트 케이스](./usecase-failure-logging.md)에서 다룬다. 이 문서에서는 앱 로그인이 오류 보고 대상인지를 다룬다.

## feature

### TC-LOGIN-FEATURE-001: 뒤로가기를 사용하면 이전 화면으로 돌아간다

- 근거: `feature > 진입과 종료`
- Given: Login 화면이 표시되어 있다.
- When: 사용자가 뒤로가기를 실행한다.
- Then: Login 화면이 닫히고 진입하기 전 화면이 표시된다.

### TC-LOGIN-FEATURE-020: Google 로그인과 Apple 로그인을 제공한다

- 근거: `feature > 로그인 수단`, `domain > 제공하는 로그인 수단`
- Given: Login 화면에 진입할 수 있다.
- When: 사용자가 Login 화면에 진입한다.
- Then: Google 로그인과 Apple 로그인 중 하나를 선택할 수 있다.

### TC-LOGIN-FEATURE-004: 선택한 수단의 로그인을 시작한다

- 근거: `feature > 로그인 진행과 완료`
- Given: 로그인 요청이 진행 중이지 않고 Login 화면에서 테스트 데이터의 로그인 수단을 선택할 수 있다.
- When: 사용자가 해당 로그인 수단을 선택한다.
- Then: 현재 플랫폼의 해당 수단 로그인 흐름이 한 번 시작되고, 다른 수단의 로그인 흐름은 시작되지 않는다.
- 테스트 데이터:

| 로그인 수단 |
| --- |
| Google |
| Apple |

### TC-LOGIN-FEATURE-006: 로그인 취소를 오류로 안내하지 않는다

- 근거: `feature > 취소와 오류`
- Given: 테스트 데이터의 수단 로그인 흐름이 사용자 취소 결과를 반환하도록 설정되어 있다.
- When: 사용자가 해당 수단의 로그인을 시작한 뒤 취소한다.
- Then: 로그인 실패 안내가 표시되지 않고 Login 화면에 머무르며 다시 로그인할 수 있다.
- 테스트 데이터:

| 로그인 수단 |
| --- |
| Google |
| Apple |

### TC-LOGIN-FEATURE-007: 로그인 실패를 안내한다

- 근거: `feature > 취소와 오류`
- Given: 로그인 수단과 실패 지점이 테스트 데이터와 같이 설정되어 있다.
- When: 사용자가 해당 수단으로 로그인을 시도하고 해당 지점에서 실패한다.
- Then: 로그인 실패 안내가 표시되고 진행 상태가 종료되어 다시 로그인할 수 있다.
- 테스트 데이터:

| 실패 지점 | 로그인 수단 |
| --- | --- |
| 인증 결과 획득 | Google |
| 인증 결과 획득 | Apple |
| 서버 인증 | 수단 무관 |
| 앱 세션 설정 | 수단 무관 |

### TC-LOGIN-FEATURE-009: 앱 로그인 처리 중 진행 표시를 유지한다

- 근거: `feature > 로그인 진행과 완료`
- Given: 인증 결과를 받은 뒤 앱 로그인 처리가 완료되지 않았다.
- When: 사용자가 Login 화면을 확인한다.
- Then: 앱 로그인 처리가 끝날 때까지 진행 중인 상태가 표시된다.

### TC-LOGIN-FEATURE-010: 앱 로그인 처리 중 추가 로그인을 시작할 수 없다

- 근거: `domain > 로그인 요청 제한`
- Given: 첫 번째 앱 로그인 요청이 처리 중이다.
- When: 같은 Login 화면에 테스트 데이터의 추가 로그인 요청이 전달된다.
- Then: 새로운 로그인 흐름이나 앱 로그인 요청이 시작되지 않는다.
- 테스트 데이터:

| 추가 로그인 요청 |
| --- |
| 처리 중인 수단과 같은 수단 |
| 처리 중인 수단과 다른 수단 |

### TC-LOGIN-FEATURE-013: 로그인 완료 시 이전 화면으로 돌아간다

- 근거: `feature > 로그인 진행과 완료`
- Given: 테스트 데이터의 수단으로 인증, 서버 인증, 앱 세션 설정이 모두 성공하도록 설정되어 있다.
- When: 사용자가 해당 수단의 로그인을 완료한다.
- Then: Login 화면이 닫히고 진입하기 전 화면이 표시된다.
- 테스트 데이터:

| 로그인 수단 |
| --- |
| Google |
| Apple |

### TC-LOGIN-FEATURE-014: 앱 로그인 처리 중에도 이전 화면으로 돌아갈 수 있다

- 근거: `feature > 진입과 종료`, `domain > 로그인 요청 제한`
- Given: 앱 로그인 요청이 처리 중이다.
- When: 사용자가 뒤로가기를 실행한다.
- Then: Login 화면이 닫히고 진입하기 전 화면이 표시된다.

### TC-LOGIN-FEATURE-015: 로그인 실패 후 다시 로그인할 수 있다

- 근거: `feature > 취소와 오류`, `domain > 제공하는 로그인 수단`
- Given: 첫 번째 로그인은 실패하고, 테스트 데이터의 두 번째 로그인은 성공하도록 설정되어 있다.
- When: 사용자가 실패 안내 후 테스트 데이터의 로그인 수단을 선택해 로그인을 완료한다.
- Then: 두 번째 로그인 요청이 시작되고, 성공하면 Login 화면이 닫힌 뒤 진입하기 전 화면이 표시된다.
- 테스트 데이터:

| 두 번째 로그인 수단 |
| --- |
| 실패한 수단과 같은 수단 |
| 실패한 수단과 다른 수단 |

### TC-LOGIN-FEATURE-017: 인증 정보와 앱 세션 토큰을 화면에 표시하지 않는다

- 근거: `data > 인증 결과 노출 제한`
- Given: 인증 결과 또는 앱 세션 토큰을 받은 로그인 시도가 진행 중이거나 완료되었다.
- When: 사용자가 Login 화면을 확인한다.
- Then: 인증 결과와 앱 세션 토큰이 화면에 표시되지 않는다.
- 작성하지 않는 이유: 인증 결과와 앱 세션 토큰은 화면 상태로 전달되지 않아 화면에서 관찰할 값 자체가 없다. 실제 인증 결과와 세션 토큰을 주입해 화면 전체에서 노출 여부를 판정할 수 있는 테스트 환경이 갖춰지면 자동화한다.

### TC-LOGIN-FEATURE-021: 앱 로그인 전에 끝난 실패는 오류 보고를 남기지 않는다

- 근거: `domain > 앱 로그인 실패 보고`
- Given: 오류 보고 기록 수단이 등록되어 있고, 테스트 데이터의 수단과 실패 지점이 설정되어 있다.
- When: 사용자가 해당 수단의 로그인을 시도해 해당 지점에서 끝난다.
- Then: 오류 보고가 남지 않는다.
- 테스트 데이터:

| 실패 지점 | 로그인 수단 |
| --- | --- |
| 사용자 취소 | Google |
| 사용자 취소 | Apple |
| 인증 결과 획득 | Google |
| 인증 결과 획득 | Apple |

- 작성하지 않는 이유: Login 화면 테스트 환경에는 오류 보고 기록 수단을 등록해 남은 보고를 관찰할 수단이 없다. 화면 테스트에서 기록된 로그를 판정할 수 있는 환경이 갖춰지면 자동화한다.

### TC-LOGIN-FEATURE-022: Android에서 로그인 브라우저 탭을 응답 없이 닫으면 취소로 처리한다

- 근거: `feature > 취소와 오류`
- Given: Android에서 Apple 로그인이 브라우저 탭에서 시작되어 앱이 화면 뒤로 물러났다.
- When: 사용자가 인증 결과 없이 브라우저 탭을 닫고 앱으로 돌아온다.
- Then: 로그인 실패 안내가 표시되지 않고 앱 로그인 요청이 시작되지 않으며, 사용자는 다시 로그인할 수 있다.

### TC-LOGIN-FEATURE-023: Android에서 앱으로 돌아온 뒤 도착한 인증 결과로 로그인한다

- 근거: `feature > 취소와 오류`, `feature > 로그인 진행과 완료`
- Given: Android에서 Apple 로그인이 브라우저 탭에서 시작되어 앱이 화면 뒤로 물러났다.
- When: 인증 결과가 앱 복귀 주소로 도착하고 앱이 다시 화면 앞으로 돌아온다.
- Then: 취소로 처리되지 않고 그 인증 결과로 앱 로그인이 진행된다.

### TC-LOGIN-FEATURE-024: 웹에서 로그인 창을 응답 없이 닫으면 취소로 처리한다

- 근거: `feature > 취소와 오류`
- Given: 웹에서 Apple 로그인이 별도 창에서 시작되었다.
- When: 사용자가 인증 결과 없이 로그인 창을 닫는다.
- Then: 로그인 실패 안내가 표시되지 않고 Login 화면에 머무르며 다시 로그인할 수 있다.
- 작성하지 않는 이유: 로그인 창이 닫혔는지는 실제 브라우저의 창 상태로만 관찰할 수 있다. 브라우저 창 상태를 제어할 수 있는 웹 테스트 환경이 갖춰지면 자동화한다.

## domain

### TC-LOGIN-DOMAIN-001: 플랫폼이 제공하는 한 가지 Google 인증 결과로 로그인한다

- 근거: `domain > 허용되는 Google 인증 결과`
- Given: 현재 플랫폼이 테스트 데이터의 Google 인증 결과를 제공한다.
- When: 사용자가 Google 인증을 완료한다.
- Then: 제공된 인증 결과로 앱 로그인이 진행되며 다른 종류의 인증 결과를 추가로 요구하지 않는다.
- 테스트 데이터:

| Google 인증 결과 |
| --- |
| `idToken`과 nonce |
| authorization code |

### TC-LOGIN-DOMAIN-002: Apple 로그인은 `idToken`과 nonce만으로 로그인한다

- 근거: `domain > 허용되는 Apple 인증 결과`
- Given: Apple 로그인을 제공하는 환경이다.
- When: 사용자가 Apple 인증을 완료한다.
- Then: Apple이 발급한 `idToken`과 로그인 시도에 사용한 nonce로 앱 로그인이 진행되며, authorization code 등 다른 종류의 인증 결과를 요구하지 않는다.

### TC-LOGIN-DOMAIN-003: 앱 로그인이 실패하면 실패 원인을 담은 오류 보고가 남는다

- 근거: `domain > 앱 로그인 실패 보고`
- Given: 오류 보고 기록 수단이 등록되어 있고, 테스트 데이터의 수단으로 진행하는 앱 로그인이 특정 원인으로 실패하도록 준비되어 있다.
- When: 해당 수단의 인증 결과로 앱 로그인을 진행한다.
- Then: 그 원인을 담은 오류 보고가 한 번 남고, 보고 메시지로 어느 수단의 앱 로그인 실패인지 구분할 수 있다.
- 테스트 데이터:

| 로그인 수단 |
| --- |
| Google |
| Apple |

### TC-LOGIN-DOMAIN-004: 앱 로그인이 성공하면 오류 보고가 남지 않는다

- 근거: `domain > 앱 로그인 실패 보고`
- Given: 오류 보고 기록 수단이 등록되어 있고, 테스트 데이터의 수단으로 진행하는 앱 로그인이 성공하도록 준비되어 있다.
- When: 해당 수단의 인증 결과로 앱 로그인을 진행한다.
- Then: 오류 보고가 남지 않는다.
- 테스트 데이터:

| 로그인 수단 |
| --- |
| Google |
| Apple |

### TC-LOGIN-DOMAIN-005: 상태 값이 맞지 않는 Apple 웹 로그인 응답은 인증 결과로 받지 않는다

- 근거: `domain > 허용되는 Apple 인증 결과`
- Given: Apple 웹 로그인 시도가 시작되어 상태 값이 정해져 있다.
- When: 테스트 데이터의 상태 값을 가진 응답이 `idToken`과 함께 앱으로 돌아온다.
- Then: 인증 결과를 받지 못한 것으로 처리되어 앱 로그인이 진행되지 않고 로그인 실패로 안내된다.
- 테스트 데이터:

| 응답의 상태 값 |
| --- |
| 이번 시도와 다른 값 |
| 없음 |

### TC-LOGIN-DOMAIN-006: Apple 웹 로그인 응답을 인증 결과, 취소, 실패로 구분한다

- 근거: `domain > 허용되는 Apple 인증 결과`
- Given: Apple 웹 로그인 시도가 시작되어 상태 값과 nonce가 정해져 있다.
- When: 이번 시도의 상태 값과 테스트 데이터의 내용을 가진 응답이 앱으로 돌아온다.
- Then: 테스트 데이터의 결과로 처리된다.
- 테스트 데이터:

| 응답 내용 | 결과 |
| --- | --- |
| `idToken` 있음 | 그 `idToken`과 이번 시도의 nonce가 앱 로그인에 사용된다 |
| Apple의 사용자 취소 오류 | 사용자 취소로 처리되어 실패 안내가 없다 |
| 그 외 오류 | 인증 결과를 받지 못한 것으로 처리되어 로그인 실패로 안내된다 |
| `idToken`과 오류 모두 없음 | 인증 결과를 받지 못한 것으로 처리되어 로그인 실패로 안내된다 |

## data

### TC-LOGIN-DATA-001: authorization code 인증 결과로 앱 세션을 설정한다

- 근거: `data > Google 인증 결과 전달`, `data > 계정과 세션`
- Given: 플랫폼이 authorization code와 해당 플랫폼에 필요한 테스트 데이터의 인증 정보를 제공하고, 서버 인증이 접근 토큰과 갱신 토큰을 반환하도록 설정되어 있다.
- When: 앱 로그인을 진행한다.
- Then: 플랫폼이 제공한 인증 정보가 서버에 전달되고, 서버가 반환한 토큰이 현재 사용자의 앱 세션으로 설정된다.
- 테스트 데이터:

| 플랫폼 | 서버에 전달할 인증 정보 |
| --- | --- |
| JVM 데스크톱 | authorization code, 같은 로그인 시도의 code verifier, 발급 대상 클라이언트 및 리디렉션 정보 |
| 그 외 authorization code 제공 플랫폼 | authorization code, 발급 대상 클라이언트 및 리디렉션 정보 |

### TC-LOGIN-DATA-008: JVM authorization code를 같은 로그인 시도의 PKCE 값으로 교환한다

- 근거: `data > Google 인증 결과 전달`
- Given: JVM 데스크톱에서 Google 로그인을 시작하고 authorization code를 받도록 설정되어 있다.
- When: authorization code로 앱 로그인을 진행한다.

### TC-LOGIN-DATA-012: 서버 콜백은 허용된 앱 복귀 주소로만 인증 결과를 넘긴다

- Given: 서버의 Apple 콜백 주소로 테스트 데이터의 앱 복귀 주소를 담은 상태 값과 `idToken`이 도착한다.
- When: 서버가 응답을 처리한다.
- Then: 허용된 주소이면 그 주소로 `idToken`과 상태 값을 넘기고, 허용되지 않은 주소이면 어떤 값도 넘기지 않고 요청을 거절한다.
- 테스트 데이터:

| 앱 복귀 주소 | 허용 |
| --- | --- |
| 앱 식별자 scheme의 앱 링크 | O |
| `127.0.0.1`의 로컬 수신 주소 | O |
| `localhost` 웹 출처 | O |
| 허용 목록에 없는 웹 출처 | X |
| 다른 scheme의 앱 링크 | X |

- 작성하지 않는 이유: 서버 콜백은 서버 함수 실행 환경에서만 동작하고, 그 환경은 저장소의 자동 검증 절차에 포함되어 있지 않다. 서버 함수 테스트 러너가 검증 절차에 들어오면 자동화한다.
