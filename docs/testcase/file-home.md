# FileHome 테스트 케이스

기준 스펙: [FileHome 화면 스펙](../spec/client/file-home.md)

## feature

### TC-FILE-HOME-FEATURE-001: 상단 바에 화면 제목을 표시한다

- 근거: `feature > 진입`
- Given: 사용자 언어가 한국어다.
- When: 사용자가 FileHome 화면을 확인한다.
- Then: 상단 바에 제목 `파일` 문구가 표시된다.

### TC-FILE-HOME-FEATURE-003: 뒤로가기를 선택하면 이전 화면으로 돌아간다

- 근거: `feature > 뒤로가기`
- Given: 사용자가 `더보기`의 `파일` 바로가기로 FileHome 화면에 들어와 있다.
- When: 사용자가 뒤로가기를 선택한다.
- Then: 이전 화면으로 돌아가는 동작이 한 번 실행된다.

### TC-FILE-HOME-FEATURE-005: 게스트 상태에서는 로그인 안내만 표시한다

- 근거: `feature > 게스트 상태`, `domain > 계정 상태에 따른 화면`
- Given: 사용자 언어가 한국어이고 계정 상태가 게스트다.
- When: 사용자가 FileHome 화면을 확인한다.
- Then: 본문에 `로그인이 필요합니다` 안내가 표시되고, 파일 목록과 파일 추가 동작은 표시되지 않으며, 파일 목록을 서버에 요청하지 않는다.

### TC-FILE-HOME-FEATURE-006: 계정 상태를 확정하지 않은 동안에는 본문을 비운다

- 근거: `domain > 계정 상태에 따른 화면`
- Given: 계정 상태가 아직 게스트나 사용자로 확정되지 않았다.
- When: 사용자가 FileHome 화면을 확인한다.
- Then: 제목과 뒤로가기만 표시되고, 로그인 안내, 파일 목록, 파일 추가 동작은 표시되지 않는다.

### TC-FILE-HOME-FEATURE-007: 목록의 각 파일에 이름, 크기, 올린 날짜와 시각을 표시한다

- 근거: `feature > 파일 목록`
- Given: 사용자 언어가 한국어이고 계정 상태가 사용자이며, 서버가 테스트 데이터의 파일 하나를 돌려준다.
- When: 사용자가 FileHome 화면을 확인한다.
- Then: 목록에 그 파일의 이름, 크기, 올린 날짜와 시각이 표시된다.
- 테스트 데이터:

| 파일 이름 | 크기 |
| --- | --- |
| `memo.txt` | 512바이트 |
| `photo.jpg` | 1,024바이트 |
| `video.mp4` | 24,536,679바이트 |

### TC-FILE-HOME-FEATURE-008: 목록을 처음 불러오는 동안 불러오는 중임을 표시한다

- 근거: `feature > 목록 표시 조건`
- Given: 계정 상태가 사용자이고, 서버가 파일 목록 요청에 아직 응답하지 않았다.
- When: 사용자가 FileHome 화면을 확인한다.
- Then: 본문에 불러오는 중 표시가 나타나고, 빈 상태 안내와 불러오기 실패 안내는 표시되지 않는다.

### TC-FILE-HOME-FEATURE-009: 처음 불러오기에 실패하면 실패 안내와 다시 시도를 표시한다

- 근거: `feature > 목록 표시 조건`
- Given: 사용자 언어가 한국어이고 계정 상태가 사용자이며, 서버가 파일 목록 요청에 실패를 돌려준다.
- When: 사용자가 FileHome 화면을 확인한다.
- Then: 본문에 `파일을 불러오지 못했습니다` 안내와 `다시 시도` 동작이 표시되고, 빈 상태 안내는 표시되지 않는다.

### TC-FILE-HOME-FEATURE-010: 처음 불러오기 실패 후 다시 시도하면 목록을 다시 불러온다

- 근거: `feature > 목록 표시 조건`, `domain > 목록을 다시 불러오는 계기`
- Given: 처음 불러오기가 실패해 실패 안내가 표시되어 있고, 서버가 다음 요청에는 파일 하나를 돌려준다.
- When: 사용자가 `다시 시도`를 선택한다.
- Then: 다시 요청하는 동안 본문에 불러오는 중 표시가 나타나고, 파일 목록을 처음부터 다시 요청해 돌려받은 파일이 목록에 표시된다.

### TC-FILE-HOME-FEATURE-011: 올린 파일이 하나도 없으면 빈 상태 안내를 표시한다

- 근거: `feature > 목록 표시 조건`
- Given: 사용자 언어가 한국어이고 계정 상태가 사용자이며, 서버가 파일이 하나도 없는 목록을 돌려준다.
- When: 사용자가 FileHome 화면을 확인한다.
- Then: 본문에 `아직 올린 파일이 없습니다` 안내가 표시되고, 파일 추가 동작은 그대로 표시된다.

### TC-FILE-HOME-FEATURE-012: 목록의 끝으로 이동하면 다음 파일을 이어서 불러와 붙인다

- 근거: `feature > 파일 목록`
- Given: 계정 상태가 사용자이고, 서버에 올린 파일이 25개 있어 첫 요청에 20개를 돌려주었다.
- When: 사용자가 목록의 끝으로 이동한다.
- Then: 나머지 5개를 이어서 요청하고, 목록에 25개 파일이 순서대로 모두 표시된다.

### TC-FILE-HOME-FEATURE-013: 이어서 불러오기에 실패하면 목록 끝에 실패 안내와 다시 시도를 표시한다

- 근거: `feature > 목록 표시 조건`
- Given: 사용자 언어가 한국어이고, 첫 요청으로 파일 20개가 표시되어 있으며, 서버가 이어서 불러오는 요청에 실패를 돌려준다.
- When: 사용자가 목록의 끝으로 이동한다.
- Then: 목록 끝에 `더 불러오지 못했습니다` 안내와 `다시 시도` 동작이 표시되고, 이미 표시된 파일 20개는 그대로 남는다.

### TC-FILE-HOME-FEATURE-014: 이어서 불러오기 실패 후 다시 시도하면 이어서 다시 불러온다

- 근거: `feature > 목록 표시 조건`
- Given: 이어서 불러오기가 실패해 목록 끝에 실패 안내가 표시되어 있고, 서버가 다음 요청에는 남은 파일을 돌려준다.
- When: 사용자가 목록 끝의 `다시 시도`를 선택한다.
- Then: 실패했던 이어서 불러오기를 다시 요청하고, 돌려받은 파일이 기존 목록 뒤에 붙는다.

### TC-FILE-HOME-FEATURE-015: 파일 추가를 선택하면 파일 선택 도구를 연다

- 근거: `feature > 파일 추가`
- Given: 계정 상태가 사용자이고, 목록이 테스트 데이터의 상태다.
- When: 사용자가 파일 추가를 선택한다.
- Then: 파일 선택 도구가 한 번 열린다.
- 테스트 데이터:

| 목록 상태 |
| --- |
| 처음 불러오는 중 |
| 처음 불러오기 실패 |
| 빈 상태 |
| 파일 목록 표시 |

### TC-FILE-HOME-FEATURE-016: 파일을 고르지 않고 취소하면 아무것도 올리지 않는다

- 근거: `feature > 파일 추가`
- Given: 파일 목록이 표시되어 있고 사용자가 파일 선택 도구를 열었다.
- When: 사용자가 파일을 고르지 않고 선택 도구를 닫는다.
- Then: 파일을 올리지 않고, 진행 중 표시와 실패 안내가 나타나지 않으며, 목록은 그대로 유지된다.

### TC-FILE-HOME-FEATURE-017: 파일을 고르면 곧바로 올리고 올리는 동안 다시 추가할 수 없다

- 근거: `feature > 파일 추가`
- Given: 파일 목록이 표시되어 있고, 서버가 올리기 요청에 아직 응답하지 않는다.
- When: 사용자가 파일 선택 도구에서 파일 하나를 고른 뒤, 다시 파일 추가를 선택한다.
- Then: 고른 파일을 올리는 요청이 확인 단계 없이 한 번 시작되고, 파일 추가 자리에 진행 중 표시가 나타나며, 두 번째 선택으로는 파일 선택 도구가 열리지 않는다.

### TC-FILE-HOME-FEATURE-018: 올리기에 성공하면 목록을 처음부터 다시 불러온다

- 근거: `feature > 파일 추가`, `domain > 목록을 다시 불러오는 계기`
- Given: 파일 목록이 표시되어 있고 사용자가 목록을 아래로 내려 첫 파일이 보이지 않으며, 서버가 올리기 요청에 성공을 돌려주고 다음 목록 요청에는 방금 올린 파일을 맨 앞에 포함해 돌려준다.
- When: 사용자가 파일 하나를 골라 올리기가 끝난다.
- Then: 진행 중 표시가 사라지고, 파일 목록을 처음부터 다시 요청하며, 목록이 처음으로 돌아가 방금 올린 파일이 맨 앞에 보인다. 성공을 알리는 안내는 표시되지 않는다.

### TC-FILE-HOME-FEATURE-019: 올리기에 실패하면 실패 이유를 알리고 목록을 유지한다

- 근거: `feature > 파일 추가`
- Given: 사용자 언어가 한국어이고 파일 목록이 표시되어 있으며, 파일 올리기가 테스트 데이터의 이유로 실패한다.
- When: 사용자가 파일 하나를 골라 올리기가 끝난다.
- Then: 테스트 데이터의 안내가 표시되고, 진행 중 표시가 사라지며, 목록은 바뀌지 않고, 사용자는 파일 추가를 다시 선택할 수 있다.
- 테스트 데이터:

| 실패 이유 | 안내 |
| --- | --- |
| 고른 파일이 50MB를 넘는다 | `50MB 이하 파일만 올릴 수 있습니다.` |
| 그 밖의 이유로 올리지 못했다 | `파일을 올리지 못했습니다.` |

### TC-FILE-HOME-FEATURE-020: 이어서 불러오는 동안 목록 끝에 불러오는 중임을 표시한다

- 근거: `feature > 목록 표시 조건`
- Given: 첫 요청으로 파일 20개가 표시되어 있고, 서버가 이어서 불러오는 요청에 아직 응답하지 않았다.
- When: 사용자가 목록의 끝으로 이동한다.
- Then: 목록 끝에 불러오는 중 표시가 나타나고, 이미 표시된 파일은 그대로 남는다.

### TC-FILE-HOME-FEATURE-021: 올리는 동안에도 목록을 확인하고 이동할 수 있다

- 근거: `feature > 파일 추가`
- Given: 파일 30개가 표시되어 있고, 파일을 올리는 중이다.
- When: 사용자가 목록의 끝으로 이동한다.
- Then: 진행 중 표시가 유지된 채 목록 끝의 파일이 보인다.

### TC-FILE-HOME-FEATURE-022: 올리는 동안 뒤로가면 결과를 기다리지 않고 돌아간다

- 근거: `feature > 뒤로가기`, [파일 보관 스펙](../spec/client/file-storage.md)의 `data > 올리기 중단`
- Given: 파일을 올리는 중이고, 서버가 올리기 요청에 아직 응답하지 않았다.
- When: 사용자가 뒤로가기를 선택한다.
- Then: 올리기 결과를 기다리지 않고 이전 화면으로 돌아가는 동작이 한 번 실행된다.

### TC-FILE-HOME-FEATURE-023: 목록이 보이는 상태에서 다시 불러오기에 실패하면 이전 목록을 두고 실패를 알린다

- 근거: `feature > 목록 표시 조건`
- Given: 사용자 언어가 한국어이고 파일 목록이 표시되어 있으며, 올리기는 성공하지만 서버가 다음 목록 요청에 실패를 돌려준다.
- When: 사용자가 파일 하나를 골라 올리기가 끝난다.
- Then: 이전 파일 목록이 그대로 표시되고, `파일을 불러오지 못했습니다` 안내가 알려진다.

### TC-FILE-HOME-FEATURE-024: 올리는 동안 계정이 바뀌면 올리기를 중단하고 결과를 알리지 않는다

- 근거: `feature > 파일 추가`
- Given: 계정 A로 파일을 올리는 중이다.
- When: 계정 상태가 테스트 데이터의 상태로 바뀐다.
- Then: 진행 중 표시가 사라지고, 올리기 성공이나 실패를 알리는 안내가 표시되지 않으며, 테스트 데이터의 결과가 된다.
- 테스트 데이터:

| 바뀐 계정 상태 | 결과 |
| --- | --- |
| 계정 B의 사용자 | 파일 추가를 다시 선택할 수 있다 |
| 게스트 | 파일 추가가 사라지고 로그인 안내가 표시된다 |

## domain

### TC-FILE-HOME-DOMAIN-001: 목록의 계정이 바뀌면 그 계정의 목록을 처음부터 다시 불러온다

- 근거: `domain > 계정 상태에 따른 화면`, `domain > 목록을 다시 불러오는 계기`
- Given: 계정 A로 파일 목록이 표시되어 있다.
- When: 계정 상태가 계정 B의 사용자로 바뀐다.
- Then: 계정 A의 파일은 보이지 않고, 파일 목록을 처음부터 다시 요청해 계정 B의 파일이 표시된다.

### TC-FILE-HOME-DOMAIN-002: 사용자에서 게스트로 바뀌면 목록 대신 로그인 안내를 표시한다

- 근거: `domain > 계정 상태에 따른 화면`
- Given: 파일 목록이 표시되어 있다.
- When: 계정 상태가 게스트로 바뀐다.
- Then: 파일 목록과 파일 추가 동작이 사라지고 로그인 안내가 표시된다.

### TC-FILE-HOME-DOMAIN-003: 세션 갱신 여부와 관계없이 사용자 상태에서는 목록을 불러온다

- 근거: `domain > 계정 상태에 따른 화면`
- Given: 계정 상태가 사용자이고, 세션 갱신 여부가 테스트 데이터와 같다.
- When: 사용자가 FileHome 화면을 확인한다.
- Then: 파일 목록을 서버에 요청하고 파일 추가 동작이 표시된다.
- 테스트 데이터:

| 세션 갱신 여부 |
| --- |
| 세션 갱신됨 |
| 세션 확인 중 |
| 인증되지 않은 것으로 확인됨 |

### TC-FILE-HOME-DOMAIN-004: 화면이 재생성되거나 백그라운드에서 돌아와도 목록과 보던 자리를 유지한다

- 근거: `domain > 유지할 사용자 진행 상태`
- Given: 파일 30개를 불러와 표시하고 있고, 사용자가 목록을 아래로 내려 첫 파일이 보이지 않는다.
- When: 테스트 데이터의 일이 일어난 뒤 같은 화면이 다시 표시된다.
- Then: 파일 목록을 다시 요청하지 않고, 목록은 보던 자리를 그대로 보여 준다.
- 테스트 데이터:

| 일어난 일 |
| --- |
| 화면이 회전 등으로 재생성된다 |
| 앱이 백그라운드에 갔다가 돌아온다 |

### TC-FILE-HOME-DOMAIN-005: 화면을 떠났다가 다시 들어오면 목록을 처음부터 다시 불러온다

- 근거: `domain > 목록을 다시 불러오는 계기`, `domain > 유지할 사용자 진행 상태`
- Given: 파일 목록을 불러와 표시한 뒤 사용자가 화면을 떠났다.
- When: 사용자가 `파일` 바로가기로 FileHome 화면에 다시 들어온다.
- Then: 파일 목록을 처음부터 다시 요청한다.
- 작성하지 않는 이유: 화면을 떠나고 다시 들어오는 것은 여러 화면을 오가는 이동이라 한 화면 단위로 재현할 수 없다. 화면에 들어올 때 목록을 요청하는 것은 TC-FILE-HOME-FEATURE-008, TC-FILE-HOME-FEATURE-009, TC-FILE-HOME-FEATURE-011이 확인한다. 자동화하려면 MoreHome과 FileHome을 함께 띄워 오가는 화면 이동 테스트 환경이 필요하다.

### TC-FILE-HOME-DOMAIN-006: 올리는 동안 화면이 재생성되어도 올리기와 진행 표시가 이어진다

- 근거: `domain > 유지할 사용자 진행 상태`
- Given: 파일을 올리는 중이라 진행 중 표시가 나타나 있다.
- When: 화면이 회전 등으로 재생성되어 같은 화면이 다시 표시된다.
- Then: 진행 중 표시가 그대로 나타나고, 올리기가 끝나면 그 결과가 `feature > 파일 추가`에 따라 반영된다.

### TC-FILE-HOME-DOMAIN-007: 같은 계정의 세션 갱신 여부만 바뀌면 목록을 다시 불러오지 않는다

- 근거: `domain > 목록을 다시 불러오는 계기`
- Given: 계정 A로 파일 목록을 불러와 표시하고 있다.
- When: 계정 A의 세션 갱신 여부만 바뀐다.
- Then: 파일 목록을 다시 요청하지 않는다.

### TC-FILE-HOME-DOMAIN-008: 파일 선택 도구가 열린 동안 화면이 재생성되어도 고른 파일을 올린다

- 근거: `domain > 유지할 사용자 진행 상태`
- Given: 사용자가 파일 추가를 선택해 파일 선택 도구가 열려 있다.
- When: 화면이 회전 등으로 재생성된 뒤 사용자가 선택 도구에서 파일 하나를 고른다.
- Then: 고른 파일을 올리는 요청이 한 번 시작된다.
- 작성하지 않는 이유: 선택 결과를 다시 만들어진 화면에 넘기는 것은 기기의 선택 결과 전달 수단이 보장하는 동작이라, 화면 단위 테스트에서 선택 도구를 연 채 화면 전체를 다시 만들고 선택 결과를 돌려받는 과정을 재현할 수 없다. 자동화하려면 실제 기기 화면을 다시 만들고 선택 도구의 결과를 넣어 줄 수 있는 기기 테스트 환경이 필요하다. 고른 파일이 곧바로 올라가는 것은 TC-FILE-HOME-FEATURE-017이 확인한다.
