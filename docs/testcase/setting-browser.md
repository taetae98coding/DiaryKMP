# SettingBrowser 테스트 케이스

기준 스펙: [SettingBrowser 화면 스펙](../spec/client/setting-browser.md)

설정 화면 본문에서 `브라우저` 항목을 선택해 SettingBrowser로 이동하는 케이스와 제공하지 않는 환경에서 항목을 두지 않는 케이스는 [SettingHome 테스트 케이스](./setting-home.md)에서 다룬다. 설정 목록과 함께 표시되는 상태의 시스템 뒤로가기 결과는 [Setting 목록·상세 배치 테스트 케이스](./setting-list-detail.md)에서, 고른 프로필로 로그인 정보를 가져오는 케이스와 프로필 목록을 읽는 케이스는 [Chrome 로그인 이어받기 테스트 케이스](./chrome-session-import.md)에서 다룬다.

저장된 선택이 화면을 떠나거나 화면이 재생성되어도, 앱이 백그라운드에 다녀와도 유지되는 결과는 화면이 기기에 저장된 선택을 그대로 표시하는 `TC-b5e6028c-3c59-4b4c-9241-37eef4af381b`와, 저장한 선택을 이후 조회에서 제공하는 `TC-c247585a-0e54-480f-8d45-ae55450a14da`로 확인한다. 앱을 종료하고 다시 시작해도 유지되는 결과는 `TC-24ce5650-4241-4a4b-a51c-f6ba571c5ab1`이 확인한다.

## feature

### TC-ea755929-3e47-49eb-8fa6-fb8faafdb8e5: 단독 화면에서 뒤로가면 설정 목록으로 돌아간다

- 근거: `feature > 뒤로가기`
- Given: SettingBrowser 화면이 단독으로 표시되어 있다.
- When: 사용자가 뒤로간다.
- Then: 설정 목록으로 돌아가고 바꾼 선택은 유지되며 공통 내비게이션은 계속 제공되지 않는다.

### TC-8cdc4635-8aeb-4850-92b0-2cd25261574d: 설정 이름과 보조 문구, 선택 안 함과 프로필 목록을 정해진 순서로 제공한다

- 근거: `feature > Chrome 프로필 선택`
- Given: 저장된 선택이 확인된 상태고 Chrome 프로필이 두 개 있다.
- When: 사용자가 SettingBrowser 화면 본문을 확인한다.
- Then: `Chrome 로그인 이어받기` 설정 이름과 보조 문구가 표시되고, `선택 안 함`, 첫 프로필 이름, 둘째 프로필 이름 순서로 세 항목을 각각 선택할 수 있다.

### TC-b5e6028c-3c59-4b4c-9241-37eef4af381b: 저장된 선택만 선택된 상태로 표시한다

- 근거: `feature > Chrome 프로필 선택`
- Given: Chrome 프로필 A, B가 있고 선택이 테스트 데이터의 값으로 저장되어 있다.
- When: 사용자가 SettingBrowser 화면 본문을 확인한다.
- Then: 테스트 데이터의 항목만 선택된 상태로 표시되고 다른 항목은 선택되지 않은 상태로 표시된다.
- 테스트 데이터:

| 저장된 선택 | 선택된 항목 |
| --- | --- |
| 없음 | `선택 안 함` |
| 프로필 A | A |
| 프로필 B | B |

### TC-a79cbfd7-bc77-4bdf-83ab-cff15848077a: 선택하지 않은 항목을 고르면 저장되고 선택 상태가 옮겨진다

- 근거: `feature > Chrome 프로필 선택`
- Given: Chrome 프로필 A, B가 있고 선택이 테스트 데이터의 저장된 선택으로 저장되어 있다.
- When: 사용자가 테스트 데이터의 항목을 고른다.
- Then: 고른 항목이 선택 상태로 바뀌고 이전 항목은 선택 해제 상태가 되며, 선택은 고른 값으로 저장된다.
- 테스트 데이터:

| 저장된 선택 | 고르는 항목 | 저장 결과 |
| --- | --- | --- |
| 없음 | A | 프로필 A |
| 프로필 A | B | 프로필 B |
| 프로필 B | `선택 안 함` | 없음 |

### TC-a51906dc-7d78-497e-8c46-1fc27c846040: 이미 선택된 항목을 다시 고르면 아무것도 바뀌지 않는다

- 근거: `feature > Chrome 프로필 선택`
- Given: Chrome 프로필 A가 있고 선택이 프로필 A로 저장되어 있다.
- When: 사용자가 이미 선택된 A를 고른다.
- Then: 선택 상태가 그대로 유지되고 저장된 선택도 프로필 A로 유지되며, 오류 안내는 표시되지 않는다.

### TC-ddce5e6d-e969-4152-807a-0f24f18c9dec: 저장되지 않으면 선택 상태가 옮겨지지 않는다

- 근거: `feature > Chrome 프로필 선택`
- Given: Chrome 프로필 A가 있고 선택이 없음으로 저장되어 있으며, 저장이 이루어지지 않는 상태다.
- When: 사용자가 A를 고른다.
- Then: `선택 안 함`이 계속 선택된 상태로 표시되고 사용자에게 별도 오류 상태는 제공되지 않는다.

### TC-860439ee-3291-4fc1-a90a-643410f83eb2: 선택을 확인하지 못하면 선택 기능을 제공하지 않는다

- 근거: `feature > Chrome 프로필 선택`, `data > 저장 시점과 유지`
- Given: 저장된 선택을 아직 확인하지 못했거나 읽지 못한 상태다.
- When: 사용자가 SettingBrowser 화면 본문을 확인한다.
- Then: 항목을 고를 수 없고 `Chrome 로그인 이어받기` 설정 이름도 표시되지 않으며, 별도 로딩 또는 오류 상태도 제공되지 않는다.

### TC-9f140b04-1651-4b16-ad33-6b610ec8145e: Chrome 프로필이 없으면 선택 안 함만 제공한다

- 근거: `feature > Chrome 프로필 선택`
- Given: 저장된 선택이 확인된 상태고 Chrome 프로필이 하나도 없다.
- When: 사용자가 SettingBrowser 화면 본문을 확인한다.
- Then: 설정 이름과 `선택 안 함` 항목이 표시되고 `선택 안 함`이 선택된 상태이며, 프로필 항목은 표시되지 않는다.

### TC-18b66e7e-ec7e-4da4-b380-31f9b4c9bb60: 프로필 목록을 읽지 못하면 선택 안 함과 조회 실패 안내를 제공한다

- 근거: `feature > Chrome 프로필 선택`
- Given: 저장된 선택이 테스트 데이터의 값이고 Chrome 프로필 목록 읽기가 실패하도록 제어되어 있다.
- When: 사용자가 SettingBrowser 화면 본문을 확인한다.
- Then: 설정 이름과 `선택 안 함` 항목이 선택된 상태로 표시되고, 프로필을 조회할 수 없다는 안내가 표시되며, 프로필 항목은 표시되지 않는다. 사용자는 `선택 안 함`을 고를 수 있다.
- 테스트 데이터:

| 저장된 선택 |
| --- |
| 없음 |
| 프로필 A |

### TC-5d0bcb07-2d63-4a09-b4a4-dc74147478d0: 저장된 프로필이 있는데 선택 안 함으로 표시될 때 선택 안 함을 고르면 저장된 프로필을 지운다

- 근거: `feature > Chrome 프로필 선택`, `domain > 목록에 없는 프로필`
- Given: 선택이 프로필 X로 저장되어 있고, 테스트 데이터의 이유로 `선택 안 함`이 선택된 것으로 표시되어 있다.
- When: 사용자가 `선택 안 함`을 고른다.
- Then: 저장된 선택이 없음으로 바뀌고 `선택 안 함`이 계속 선택된 상태로 표시된다.
- 테스트 데이터:

| `선택 안 함`으로 표시되는 이유 |
| --- |
| Chrome 프로필 목록에 A만 있고 X가 없음 |
| Chrome 프로필 목록 읽기가 실패함 |

### TC-51a164ea-b9a3-4400-94fd-832351838d3e: 화면을 보는 동안에는 프로필 목록이 바뀌지 않는다

- 근거: `feature > 내용의 갱신`
- Given: Chrome 프로필 A와 B가 읽혀 SettingBrowser 화면에 표시되어 있고, 이후 다시 읽으면 프로필 A만 있도록 제어되어 있다.
- When: 사용자가 화면을 떠나지 않고 계속 본다.
- Then: 프로필 A와 B가 그대로 표시된다.

### TC-b6816f2a-6bf6-4cb8-9e97-96744fff6b6f: 화면을 떠났다가 다시 들어오면 프로필 목록을 다시 읽는다

- 근거: `feature > 내용의 갱신`
- Given: Chrome 프로필 A와 B가 읽혀 SettingBrowser 화면에 표시된 뒤 사용자가 화면을 떠났고, 이후 다시 읽으면 프로필 A만 있도록 제어되어 있다.
- When: 사용자가 SettingBrowser 화면에 다시 들어온다.
- Then: 프로필 A만 표시된다.

### TC-6c265216-4128-4284-80ab-c0f6b8c67feb: 다른 앱에 다녀온 지 5초가 지나 돌아오면 프로필 목록을 다시 읽는다

- 근거: `feature > 내용의 갱신`
- Given: Chrome 프로필 A와 B가 읽혀 SettingBrowser 화면에 표시되어 있고, 이후 다시 읽으면 프로필 A만 있도록 제어되어 있다.
- When: 사용자가 다른 앱으로 떠났다가 5초가 지난 뒤 돌아온다.
- Then: 프로필 A만 표시된다.

### TC-3d3ee40e-bf3d-4c03-b305-4a5e19100276: 다른 앱에 다녀온 지 5초 안에 돌아오면 읽어 둔 프로필 목록을 그대로 둔다

- 근거: `feature > 내용의 갱신`
- Given: Chrome 프로필 A와 B가 읽혀 SettingBrowser 화면에 표시되어 있고, 이후 다시 읽으면 프로필 A만 있도록 제어되어 있다.
- When: 사용자가 다른 앱으로 떠났다가 5초가 지나기 전에 돌아온다.
- Then: 프로필 A와 B가 그대로 표시되고 프로필 목록을 다시 읽지 않는다.

## domain

### TC-95d7f314-f066-4d1e-91e9-57ad37ec4a5f: 목록에 없는 프로필이 저장되어 있으면 선택 안 함으로 표시한다

- 근거: `domain > 목록에 없는 프로필`
- Given: Chrome 프로필 A만 있고 선택이 목록에 없는 프로필 X로 저장되어 있다.
- When: 사용자가 SettingBrowser 화면 본문을 확인한다.
- Then: `선택 안 함`이 선택된 상태로 표시되고 A는 선택되지 않은 상태로 표시된다.

### TC-e4e311b2-8208-4e78-b931-51ce7d3fec26: 목록에 없는 프로필이 다시 나타나면 이전 선택이 되살아난다

- 근거: `domain > 목록에 없는 프로필`
- Given: 선택이 프로필 X로 저장되어 있고 Chrome 프로필 목록에 X가 없다.
- When: Chrome 프로필 목록에 X가 다시 나타난 상태로 화면에 들어온다.
- Then: X가 선택된 상태로 표시된다.

## data

### TC-ff647b05-ab2d-4a7c-b4e2-1b777b23ff20: 저장된 값이 없으면 선택 안 함으로 제공한다

- 근거: `data > 저장 시점과 유지`, `domain > Chrome 로그인 이어받기 설정`
- Given: 선택이 한 번도 저장되지 않았다.
- When: 선택을 조회한다.
- Then: 고른 프로필이 없음을 제공한다.

### TC-c247585a-0e54-480f-8d45-ae55450a14da: 저장한 선택을 이후 조회에서 제공한다

- 근거: `data > 저장 시점과 유지`
- Given: 선택이 한 번도 저장되지 않았다.
- When: 테스트 데이터의 값을 저장한 뒤 선택을 조회한다.
- Then: 저장한 값을 제공한다.
- 테스트 데이터:

| 저장하는 값 |
| --- |
| 프로필 A |
| 없음 |

### TC-7c799f5a-7b25-4da6-b06d-fcd421e16a9a: 다시 저장하면 마지막에 저장한 선택을 제공한다

- 근거: `data > 저장 시점과 유지`
- Given: 선택이 프로필 A로 저장되어 있다.
- When: 없음을 저장한 뒤 다시 프로필 B를 저장하고 선택을 조회한다.
- Then: 프로필 B를 제공한다.

### TC-d5152151-dea2-4201-a096-de0744c604b6: 조회 중에 선택이 바뀌면 이어서 새 값을 제공한다

- 근거: `data > 저장 시점과 유지`
- Given: 선택이 없음으로 저장된 상태에서 선택을 계속 조회하고 있다.
- When: 프로필 A를 저장한다.
- Then: 기존 조회 결과에 이어 프로필 A를 제공한다.

### TC-05358690-676f-4acf-a76f-a2b14334d85a: 저장된 값을 읽을 수 없으면 확인하지 못한 상태로 제공한다

- 근거: `data > 저장 시점과 유지`
- Given: 선택 저장값을 읽을 수 없도록 제어되어 있다.
- When: 선택을 조회한다.
- Then: 없음을 기본값으로 제공하지 않고 선택을 아직 확인하지 못한 상태를 제공한다.

### TC-64e07364-2bf6-48ca-9310-24ba84efa879: 데스크톱 앱은 개발용 앱과 운영용 앱의 저장 영역을 구분한다

- 근거: `data > 환경별 저장 영역`
- Given: 데스크톱에서 개발용 앱과 운영용 앱을 각각 사용한다.
- When: 각 앱의 선택 저장 영역을 확인한다.
- Then: 두 앱은 각각 기본 지도와 같은 전용 저장 영역을 사용하며 서로의 선택 값을 공유하지 않는다.

### TC-24ce5650-4241-4a4b-a51c-f6ba571c5ab1: 앱을 종료하고 다시 시작해도 저장한 선택을 제공한다

- 근거: `data > 저장 시점과 유지`
- Given: 선택이 프로필 A로 저장되어 있다.
- When: 앱을 종료하고 다시 시작한 뒤 선택을 조회한다.
- Then: 프로필 A를 제공한다.

### TC-5d89c2b7-3fab-4055-b8e7-b1fa8782cf11: 로그인 상태가 바뀌어도 선택이 유지된다

- 근거: `data > 기기별 보관`
- Given: 선택이 프로필 A로 저장되어 있다.
- When: 사용자가 로그인하거나 로그아웃하거나 다른 계정으로 바꾼 뒤 선택을 조회한다.
- Then: 프로필 A를 그대로 제공하고, 선택은 서버와 동기화되지 않는다.
- 작성하지 않는 이유: 선택의 저장과 조회에 계정 구분이 없어 이 문서의 범위에서는 계정 전환을 일으킬 수 없고, 계정 흐름 전체를 거쳐야 관찰할 수 있다. 로그인·로그아웃·계정 전환을 제어된 응답으로 실행하면서 같은 기기 저장 영역을 이어서 조회할 수 있는 통합 테스트 환경이 갖춰지면 자동화한다.
