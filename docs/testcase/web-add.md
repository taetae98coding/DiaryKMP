# WebAdd 테스트 케이스

기준 스펙: [WebAdd 화면 스펙](../spec/web-add.md)

이 문서에서 `data > 동기화`, `data > 저장 실패`, `domain > 추가 요청 제한`, `domain > 추가되는 항목의 태그 연결`, `domain > 태그 선택과 추가 성립 조건`, `domain > 항목의 계정 연결`, `feature > 뒤로가기`, `feature > 작성 상태 유지`, `feature > 태그 입력` 절은 [항목 추가 화면 공통 스펙](../spec/entity-add.md)이 소유한다. 나머지 케이스의 절은 기준 스펙이 소유한다.

WebHome에서 웹 추가를 선택해 WebAdd로 이동하는 케이스는 [WebHome 테스트 케이스](./web-home.md)에서 다룬다. 설명 입력 자체의 케이스는 [설명 입력 테스트 케이스](./description-input.md)에서 다룬다. 추가한 웹 항목을 서버와 맞추는 흐름의 케이스는 [데이터 동기화 테스트 케이스](./data-sync.md)에서 다룬다.

태그 입력의 표시와 조작, 태그 선택 목록의 케이스는 [항목 태그 입력 컴포넌트 테스트 케이스](./entity-tag-input.md)에서 다룬다. 이 문서에는 WebAdd 화면에서만 다른 시작 상태와 추가 결과의 케이스만 둔다.

## feature

### TC-WEB-ADD-FEATURE-001: 화면에 처음 진입하면 입력이 모두 비어 있다

- 근거: `feature > 진입과 입력`
- Given: 사용자가 웹 추가를 선택했다.
- When: WebAdd 화면이 처음 표시된다.
- Then: 제목, 설명, URL이 비어 있고 요청 헤더 항목이 하나도 없다.

### TC-WEB-ADD-FEATURE-002: 제목, 설명, URL을 입력할 수 있다

- 근거: `feature > 진입과 입력`
- Given: WebAdd 화면이 표시되어 있다.
- When: 사용자가 제목, 설명, URL을 입력한다.
- Then: 입력한 제목, 설명, URL이 화면에 그대로 표시된다.

### TC-WEB-ADD-FEATURE-003: 요청 헤더 항목을 추가해 이름과 값을 입력할 수 있다

- 근거: `feature > 요청 헤더 입력`
- Given: WebAdd 화면이 표시되어 있다.
- When: 사용자가 헤더 항목을 추가하고 이름과 값을 입력한다.
- Then: 추가한 헤더 항목이 마지막 자리에 나타나고 입력한 이름과 값이 그대로 표시된다.

### TC-WEB-ADD-FEATURE-004: 헤더 항목을 삭제해도 다른 입력은 유지된다

- 근거: `feature > 요청 헤더 입력`
- Given: 제목, 설명, URL을 입력하고 헤더 항목을 두 개 이상 입력한 WebAdd 화면이 표시되어 있다.
- When: 사용자가 헤더 항목 하나를 삭제한다.
- Then: 삭제한 헤더 항목만 사라지고 남은 헤더 항목의 이름·값·순서와 제목, 설명, URL은 그대로 유지된다.

### TC-WEB-ADD-FEATURE-005: 추가에 성공하면 다음 웹 항목을 작성할 수 있는 상태로 초기화한다

- 근거: `feature > 웹 항목 추가`
- Given: 웹 항목 추가가 성공하도록 설정되어 있고, 제목, 설명, URL과 헤더 항목을 입력한 상태다.
- When: 사용자가 웹 항목 추가를 실행한다.
- Then: WebAdd 화면이 유지되고 제목, 설명, URL이 비워지며 헤더 항목이 하나도 남지 않는다.

### TC-WEB-ADD-FEATURE-006: 추가에 성공하면 성공 피드백을 제공한다

- 근거: `feature > 웹 항목 추가`
- Given: 웹 항목 추가가 성공하도록 설정되어 있고, 공백이 아닌 제목과 URL이 입력되어 있다.
- When: 사용자가 웹 항목 추가를 실행한다.
- Then: 웹 항목이 추가되었다는 성공 피드백이 제공된다.

### TC-WEB-ADD-FEATURE-007: 추가를 처리하는 동안 진행 상태를 표시한다

- 근거: `feature > 웹 항목 추가`
- Given: 웹 항목 추가 처리가 완료되지 않고 진행 중인 상태로 설정되어 있고, 공백이 아닌 제목과 URL이 입력되어 있다.
- When: 사용자가 웹 항목 추가를 실행한 뒤 화면을 확인한다.
- Then: 추가 처리가 끝날 때까지 진행 상태가 표시된다.

### TC-WEB-ADD-FEATURE-008: 성립하지 않는 입력으로 추가하면 필요한 입력을 알린다

- 근거: `feature > 제목 미입력`, `feature > URL 미입력`, `feature > 헤더 이름 미입력`
- Given: WebAdd 화면에 테스트 데이터의 입력 상태가 만들어져 있다.
- When: 사용자가 웹 항목 추가를 실행한다.
- Then: 웹 항목이 추가되지 않고 테스트 데이터의 피드백이 제공된다.
- 테스트 데이터:

| 입력 상태 | 피드백 |
| --- | --- |
| 제목이 비어 있음 | 제목 입력이 필요함 |
| 제목이 공백 문자뿐임 | 제목 입력이 필요함 |
| 제목은 있고 URL이 비어 있음 | URL 입력이 필요함 |
| 제목은 있고 URL이 공백 문자뿐임 | URL 입력이 필요함 |
| 제목과 URL은 있고 이름이 비어 있는 헤더 항목이 있음 | 헤더 이름 입력이 필요함 |
| 제목과 URL은 있고 이름이 공백 문자뿐인 헤더 항목이 있음 | 헤더 이름 입력이 필요함 |

### TC-WEB-ADD-FEATURE-009: 성립하지 않는 입력으로 추가해도 작성 내용은 유지된다

- 근거: `feature > 제목 미입력`, `feature > URL 미입력`, `feature > 헤더 이름 미입력`
- Given: 테스트 데이터의 성립하지 않는 입력 상태이고 나머지 입력과 헤더 항목이 채워진 WebAdd 화면이 표시되어 있다.
- When: 사용자가 웹 항목 추가를 실행한다.
- Then: 제목, 설명, URL과 헤더 항목의 이름·값·순서가 지워지거나 바뀌지 않는다.
- 테스트 데이터:

| 성립하지 않는 입력 |
| --- |
| 제목이 공백 |
| URL이 공백 |
| 헤더 이름이 공백 |

### TC-WEB-ADD-FEATURE-010: 화면이 재생성되어도 작성 중이던 내용을 유지한다

- 근거: `feature > 작성 상태 유지`
- Given: 제목, 설명, URL과 헤더 항목을 입력한 WebAdd 화면이 표시되어 있다.
- When: 화면이 재생성된다.
- Then: 제목, 설명, URL과 헤더 항목의 이름·값·순서가 그대로 표시된다.

### TC-WEB-ADD-FEATURE-011: 앱을 다시 실행해 진입하면 새 입력 상태로 시작한다

- 근거: `feature > 작성 상태 유지`
- Given: 이전 실행에서 WebAdd 화면에 제목, 설명, URL과 헤더 항목을 입력한 뒤 앱을 종료했다.
- When: 앱을 다시 실행해 WebAdd 화면에 진입한다.
- Then: 제목, 설명, URL이 비어 있고 헤더 항목이 하나도 없다.
- 작성하지 않는 이유: 앱 프로세스를 종료하고 다시 시작해야 확인할 수 있어 앱의 단위 테스트 환경에서 결정적으로 판정할 수 없다. 프로세스 재시작을 제어할 수 있는 테스트 환경이 마련되면 작성한다.

### TC-WEB-ADD-FEATURE-012: 뒤로가면 이전 화면으로 돌아간다

- 근거: `feature > 뒤로가기`
- Given: WebAdd 화면이 표시되어 있다.
- When: 사용자가 뒤로가기를 실행한다.
- Then: WebAdd 화면에 진입하기 전 화면으로 돌아간다.

### TC-WEB-ADD-FEATURE-013: 화면에 처음 진입하면 제목 입력에 초점이 있다

- 근거: `feature > 진입과 입력`
- Given: 사용자가 웹 추가를 선택했다.
- When: WebAdd 화면이 처음 표시된다.
- Then: 입력 초점이 제목 입력에 있다.

### TC-WEB-ADD-FEATURE-014: 헤더 항목을 추가하거나 삭제해도 초점을 옮기지 않는다

- 근거: `feature > 요청 헤더 입력`
- Given: 헤더 항목을 하나 입력했고 제목 입력에 초점이 있는 WebAdd 화면이 표시되어 있다.
- When: 사용자가 테스트 데이터의 행동을 실행한다.
- Then: 입력 초점이 제목 입력에 그대로 있다.
- 테스트 데이터:

| 행동 |
| --- |
| 헤더 항목을 추가함 |
| 헤더 항목을 삭제함 |

### TC-WEB-ADD-FEATURE-015: 추가에 성공하면 제목 입력으로 초점을 옮긴다

- 근거: `feature > 웹 항목 추가`
- Given: 웹 항목 추가가 성공하도록 설정되어 있고, 공백이 아닌 제목과 URL이 입력되어 있다.
- When: 사용자가 웹 항목 추가를 실행한다.
- Then: 입력 초점이 제목 입력으로 옮겨진다.

### TC-WEB-ADD-FEATURE-016: 성립하지 않는 입력으로 추가하면 고쳐야 할 입력으로 초점을 옮긴다

- 근거: `feature > 제목 미입력`, `feature > URL 미입력`, `feature > 헤더 이름 미입력`
- Given: WebAdd 화면에 테스트 데이터의 입력 상태가 만들어져 있고, 사용자가 마지막으로 입력한 자리에 초점이 있다.
- When: 사용자가 웹 항목 추가를 실행한다.
- Then: 입력 초점이 테스트 데이터의 자리에 있다.
- 테스트 데이터:

| 입력 상태 | 초점 |
| --- | --- |
| 제목이 비어 있음 | 제목 입력 |
| 제목은 있고 URL이 비어 있음 | URL 입력 |
| 제목과 URL은 있고 이름이 비어 있는 헤더 항목이 있음 | 추가를 실행하기 전에 있던 자리 |

### TC-WEB-ADD-FEATURE-017: WebHome에서 진입하면 태그를 하나도 고르지 않은 상태로 시작한다

- 근거: `feature > 진입과 입력`
- Given: 계정과 연결된 태그가 여러 개 저장되어 있다.
- When: 사용자가 WebHome에서 WebAdd 화면에 진입한다.
- Then: 태그 입력에 연결 대상으로 표시되는 태그가 없다.

### TC-WEB-ADD-FEATURE-018: 태그를 골라도 저장된 웹 항목의 연결은 바뀌지 않는다

- 근거: `feature > 태그 입력`
- Given: 계정과 연결된 태그가 여러 개 저장되어 있고 WebAdd 화면이 표시되어 있다.
- When: 사용자가 태그 선택 목록에서 태그를 고른다.
- Then: 태그 입력에는 고른 태그가 표시되지만 저장된 웹·태그 연결은 만들어지지 않는다.

### TC-WEB-ADD-FEATURE-019: 추가에 성공해도 고른 태그는 유지한다

- 근거: `feature > 웹 항목 추가`
- Given: 웹 항목 추가가 성공하도록 설정되어 있고, 제목과 URL을 입력하고 연결할 태그를 고른 상태다.
- When: 사용자가 웹 항목 추가를 실행한다.
- Then: 제목, 설명, URL과 헤더 항목은 비워지고 태그 입력에는 고른 태그가 그대로 표시된다.

### TC-WEB-ADD-FEATURE-020: 화면이 재생성되어도 고른 태그가 유지된다

- 근거: `feature > 작성 상태 유지`
- Given: WebAdd 화면에서 제목, 설명, URL을 입력하고 연결할 태그를 고른 상태다.
- When: 화면이 회전하거나 시스템에 의해 재생성된다.
- Then: 재생성 전의 제목, 설명, URL과 고른 태그가 그대로 표시된다.

## domain

### TC-WEB-ADD-DOMAIN-001: 성립하지 않는 입력은 웹 항목을 추가하지 않는다

- 근거: `domain > 추가 성립 조건`
- Given: 로그인한 사용자 계정이 있다.
- When: 테스트 데이터의 입력으로 웹 항목 추가를 실행한다.
- Then: 웹 항목이 추가되지 않고 테스트 데이터의 성립하지 않은 조건이 결과로 전달된다.
- 테스트 데이터:

| 입력 | 성립하지 않은 조건 |
| --- | --- |
| 제목이 빈 문자열 | 제목 |
| 제목이 공백 문자뿐 | 제목 |
| 제목은 있고 URL이 빈 문자열 | URL |
| 제목은 있고 URL이 공백 문자뿐 | URL |
| 제목과 URL은 있고 이름이 빈 헤더가 하나 있음 | 헤더 이름 |
| 제목과 URL은 있고 이름이 공백 문자뿐인 헤더가 하나 있음 | 헤더 이름 |

### TC-WEB-ADD-DOMAIN-002: 여러 조건이 성립하지 않으면 먼저 성립하지 않은 조건 하나만 알린다

- 근거: `domain > 추가 성립 조건`
- Given: 로그인한 사용자 계정이 있다.
- When: 테스트 데이터의 입력으로 웹 항목 추가를 실행한다.
- Then: 테스트 데이터의 조건 하나만 결과로 전달된다.
- 테스트 데이터:

| 입력 | 전달되는 조건 |
| --- | --- |
| 제목과 URL이 모두 공백 | 제목 |
| 제목이 공백이고 이름 없는 헤더가 있음 | 제목 |
| URL이 공백이고 이름 없는 헤더가 있음 | URL |

### TC-WEB-ADD-DOMAIN-003: 설명과 요청 헤더가 비어 있어도 웹 항목을 추가한다

- 근거: `domain > 추가 성립 조건`
- Given: 로그인한 사용자 계정이 있다.
- When: 공백이 아닌 제목과 URL, 빈 설명, 헤더 없는 목록으로 웹 항목 추가를 실행한다.
- Then: 웹 항목이 추가되고 빈 설명과 빈 헤더 목록으로 기록된다.

### TC-WEB-ADD-DOMAIN-004: 이름 없는 헤더를 빼고 추가하지 않는다

- 근거: `domain > 추가 성립 조건`
- Given: 로그인한 사용자 계정이 있다.
- When: 이름이 있는 헤더와 이름이 공백인 헤더를 함께 담아 웹 항목 추가를 실행한다.
- Then: 웹 항목이 추가되지 않고 이름이 있는 헤더만 남긴 웹 항목도 기록되지 않는다.

### TC-WEB-ADD-DOMAIN-005: 값이 비어 있는 헤더는 그대로 기록한다

- 근거: `domain > 요청 헤더`
- Given: 로그인한 사용자 계정이 있다.
- When: 이름은 있고 값이 빈 헤더를 담아 웹 항목 추가를 실행한다.
- Then: 그 헤더가 빈 값으로 기록된다.

### TC-WEB-ADD-DOMAIN-006: 이름이 같은 헤더를 합치지 않고 모두 기록한다

- 근거: `domain > 요청 헤더`
- Given: 로그인한 사용자 계정이 있다.
- When: 이름이 같고 값이 다른 헤더 두 개를 담아 웹 항목 추가를 실행한다.
- Then: 두 헤더가 모두 각각의 값으로 기록된다.

### TC-WEB-ADD-DOMAIN-007: 헤더는 배치한 순서대로 기록한다

- 근거: `domain > 요청 헤더`, `domain > 추가되는 웹 항목의 내용`

- When: 공백이 아닌 제목과 URL로 웹 항목 추가를 실행한다.
- Then: 웹 항목이 기록되지 않고 계정 조회의 실패가 그대로 전달된다.

### TC-WEB-ADD-DOMAIN-013: 추가를 처리하는 동안 전달된 추가 요청은 처리하지 않는다

### TC-WEB-ADD-DOMAIN-015: 태그를 하나도 연결하지 않아도 웹 항목을 추가할 수 있다

- 근거: `domain > 태그 선택과 추가 성립 조건`

## data

### TC-WEB-ADD-DATA-001: 추가한 웹 항목과 계정의 연결을 함께 로컬 저장한다

- 근거: `data > 웹 항목 생성과 저장`
- Given: 로그인한 사용자 계정이 있다.
- When: 성립 조건을 만족하는 내용으로 웹 항목 추가를 실행한다.
- Then: 그 웹 항목과 계정의 연결이 로컬 저장소에 함께 저장된다.

### TC-WEB-ADD-DATA-002: 같은 식별자의 웹 항목이 있으면 덮어쓴다

- 근거: `data > 웹 항목 생성과 저장`
- Given: 계정과 연결된 웹 항목이 로컬 저장소에 있다.
- When: 같은 식별자에 다른 내용을 담아 저장한다.
- Then: 웹 항목이 하나로 유지되고 내용이 새로 저장한 값으로 바뀐다.

### TC-WEB-ADD-DATA-003: 요청 헤더는 저장한 순서 그대로 함께 조회된다

- 근거: `data > 웹 항목 생성과 저장`
- Given: 헤더 여러 개를 가진 웹 항목이 저장되어 있다.
- When: 그 웹 항목을 조회한다.
- Then: 헤더 목록이 저장할 때의 순서 그대로 함께 조회된다.

### TC-WEB-ADD-DATA-004: 저장에 실패하면 실패를 그대로 알린다

- 근거: `data > 저장 실패`

- Then: 실패가 성공으로 바뀌지 않고 그대로 전달된다.

### TC-WEB-ADD-DATA-005: 로컬 저장이 끝나면 업로드 대기로 기록되고 동기화가 시작된다

- 근거: `data > 동기화`

- Then: 그 웹 항목이 계정의 업로드 대기 상태로 기록되고 백그라운드 동기화가 한 번 요청된다.

### TC-WEB-ADD-DATA-006: 추가의 성공 여부는 로컬 저장 결과로만 판단한다

- 근거: `data > 동기화`
- Given: 로컬 저장은 성공하고 서버 반영은 실패하도록 설정되어 있다.
- When: 웹 항목 추가를 실행한다.
- Then: 추가가 성공으로 전달되고 그 웹 항목은 기기에서 사라지지 않은 채 업로드 대기 상태로 남는다.

### TC-WEB-ADD-DATA-007: 로그인하지 않은 상태에서 추가한 웹 항목은 서버에 반영되지 않는다

- When: 웹 항목 추가를 실행한다.
- Then: 웹 항목은 기기에 저장되고 서버로 웹 항목 업로드 요청은 발생하지 않는다.
