# SettingMap 테스트 케이스

기준 스펙: [SettingMap 화면 스펙](../spec/client/setting-map.md)

설정 화면 본문에서 `지도` 항목을 선택해 SettingMap으로 이동하는 케이스는 [SettingHome 테스트 케이스](./setting-home.md)에서 다룬다. 설정 목록과 함께 표시되는 상태의 시스템 뒤로가기 결과는 [Setting 목록·상세 배치 테스트 케이스](./setting-list-detail.md)에서, 저장된 기본 지도를 지도 화면이 초기 제공자로 사용하는 케이스는 [PlaceHome 테스트 케이스](./place-home.md)에서 다룬다.

## feature

### TC-SETTING-MAP-FEATURE-003: 단독 화면에서 뒤로가면 설정 목록으로 돌아간다

- 근거: `feature > 뒤로가기`
- Given: SettingMap 화면이 단독으로 표시되어 있다.
- When: 사용자가 뒤로간다.
- Then: 설정 목록으로 돌아가고 바꾼 기본 지도는 유지되며 공통 내비게이션은 계속 제공되지 않는다.
- 작성하지 않는 이유: 설정 목록으로 돌아가는 화면 전환과 그동안 공통 내비게이션이 제공되지 않는 것은 설정 목록과 세부 화면, 내비게이션을 함께 구성해야 관찰할 수 있어 이 부분만 자동화하지 않고 [Setting 목록·상세 배치 테스트 케이스](./setting-list-detail.md)의 TC-SETTING-LIST-DETAIL-FEATURE-013이 다룬다. 뒤로가면 이전 화면으로 돌아가기를 한 번 요청하고 기본 지도를 바꾸지 않는 것은 자동화한다.

### TC-SETTING-MAP-FEATURE-005: 선택 가능한 지도를 정해진 순서로 제공한다

- 근거: `feature > 기본 지도 선택`
- Given: 저장된 기본 지도가 확인된 상태다.
- When: 사용자가 SettingMap 화면 본문을 확인한다.
- Then: `네이버`, `Google` 순서로 두 지도를 선택할 수 있다.

### TC-SETTING-MAP-FEATURE-006: 저장된 기본 지도만 선택된 상태로 표시한다

- 근거: `feature > 기본 지도 선택`
- Given: 기본 지도가 테스트 데이터의 지도로 저장되어 있다.
- When: 사용자가 SettingMap 화면 본문을 확인한다.
- Then: 테스트 데이터의 지도만 선택된 상태로 표시되고, 다른 지도는 선택되지 않은 상태로 표시된다.
- 테스트 데이터:

| 저장된 기본 지도 | 선택된 지도 | 선택되지 않은 지도 |
| --- | --- | --- |
| 네이버 지도 | `네이버` | `Google` |
| Google 지도 | `Google` | `네이버` |

### TC-SETTING-MAP-FEATURE-007: 각 지도를 선택할 수 있다

- 근거: `feature > 기본 지도 선택`
- Given: 저장된 기본 지도가 확인된 상태로 SettingMap 화면이 표시되어 있다.
- When: 사용자가 화면 본문을 확인한다.
- Then: `네이버`와 `Google` 지도를 각각 선택할 수 있다.

### TC-SETTING-MAP-FEATURE-008: 선택되어 있지 않은 지도를 선택하면 기본 지도가 바뀐다

- 근거: `feature > 기본 지도 선택`
- Given: 기본 지도가 테스트 데이터의 저장된 지도로 저장되어 있다.
- When: 사용자가 선택되어 있지 않은 테스트 데이터의 지도를 선택한다.
- Then: 선택한 지도가 선택 상태로 바뀌고 이전 지도는 선택 해제 상태가 되며, 기본 지도는 선택한 지도로 저장된다.
- 테스트 데이터:

| 저장된 기본 지도 | 선택하는 지도 | 저장 결과 |
| --- | --- | --- |
| 네이버 지도 | `Google` | Google 지도 |
| Google 지도 | `네이버` | 네이버 지도 |

### TC-SETTING-MAP-FEATURE-009: 이미 선택된 지도를 다시 선택하면 아무것도 바뀌지 않는다

- 근거: `feature > 기본 지도 선택`
- Given: 기본 지도가 네이버 지도로 저장되어 있다.
- When: 사용자가 이미 선택된 `네이버` 지도를 선택한다.
- Then: 선택 상태가 그대로 유지되고 저장된 기본 지도도 네이버 지도로 유지되며, 오류 안내는 표시되지 않는다.

### TC-SETTING-MAP-FEATURE-010: 저장되지 않으면 선택 상태가 옮겨지지 않는다

- 근거: `feature > 기본 지도 선택`
- Given: 기본 지도가 네이버 지도로 저장되어 있고, 저장이 이루어지지 않는 상태다.
- When: 사용자가 `Google` 지도를 선택한다.
- Then: `네이버` 지도가 계속 선택된 상태로 표시되고 사용자에게 별도 오류 상태는 제공되지 않는다.

### TC-SETTING-MAP-FEATURE-011: 기본 지도를 확인하지 못하면 선택 기능을 제공하지 않는다

- 근거: `feature > 기본 지도 선택`, `data > 저장 시점과 유지`
- Given: 저장된 기본 지도를 아직 확인하지 못했거나 읽지 못한 상태다.
- When: 사용자가 SettingMap 화면 본문을 확인한다.
- Then: 기본 지도를 선택할 수 없고 별도 로딩 또는 오류 상태도 제공되지 않는다.

### TC-SETTING-MAP-FEATURE-012: 본문에 지도를 표시하지 않는다

- 근거: `feature > 기본 지도 선택`
- Given: 저장된 기본 지도가 확인된 상태로 SettingMap 화면이 표시되어 있다.
- When: 사용자가 기본 지도를 다른 지도로 바꾼다.
- Then: 이 화면에는 지도가 표시되지 않는다.

## domain

### TC-SETTING-MAP-DOMAIN-001: 지도 위 전환은 기본 지도를 바꾸지 않는다

- 근거: `domain > 설정 적용 범위`
- Given: 기본 지도가 네이버 지도로 저장되어 있고, 사용자가 지도 화면에서 지도 제공자를 Google 지도로 전환했다.
- When: 사용자가 SettingMap 화면에 들어와 본문을 확인한다.
- Then: 네이버 지도가 기본 지도로 선택된 상태로 표시된다.
- 작성하지 않는 이유: 지도 화면에서 제공자를 전환한 뒤 SettingMap으로 이동하는 여러 화면 흐름을 결정적으로 제어할 수 있는 테스트 환경이 필요하다.

## data

### TC-SETTING-MAP-DATA-001: 저장된 기본 지도가 없으면 네이버 지도를 제공한다

- 근거: `data > 저장 시점과 유지`, `domain > 기본 지도`
- Given: 기본 지도가 한 번도 저장되지 않았다.
- When: 기본 지도를 조회한다.
- Then: 네이버 지도를 제공한다.

### TC-SETTING-MAP-DATA-002: 저장한 기본 지도를 이후 조회에서 제공한다

- 근거: `data > 저장 시점과 유지`
- Given: 기본 지도가 한 번도 저장되지 않았다.
- When: 테스트 데이터의 지도를 기본 지도로 저장한 뒤 기본 지도를 조회한다.
- Then: 저장한 지도를 제공한다.
- 테스트 데이터:

| 저장하는 지도 |
| --- |
| 네이버 지도 |
| Google 지도 |

### TC-SETTING-MAP-DATA-003: 다시 저장하면 마지막에 저장한 기본 지도를 제공한다

- 근거: `data > 저장 시점과 유지`
- Given: 기본 지도가 네이버 지도로 저장되어 있다.
- When: Google 지도를 기본 지도로 저장한 뒤 다시 네이버 지도를 기본 지도로 저장하고 기본 지도를 조회한다.
- Then: 네이버 지도를 제공한다.

### TC-SETTING-MAP-DATA-004: 조회 중에 기본 지도가 바뀌면 이어서 새 값을 제공한다

- 근거: `data > 저장 시점과 유지`
- Given: 기본 지도가 네이버 지도로 저장된 상태에서 기본 지도를 계속 조회하고 있다.
- When: Google 지도를 기본 지도로 저장한다.
- Then: 기존 조회 결과에 이어 Google 지도를 제공한다.

### TC-SETTING-MAP-DATA-006: 데스크톱 앱은 개발용 앱과 운영용 앱의 저장 영역을 구분한다

- 근거: `data > 환경별 저장 영역`
- Given: 데스크톱에서 개발용 앱과 운영용 앱을 각각 사용한다.
- When: 각 앱의 기본 지도 저장 영역을 확인한다.
- Then: 두 앱은 각각 기기에 저장한 자료와 같은 전용 저장 영역을 사용하며 서로의 기본 지도 값을 공유하지 않는다.

### TC-SETTING-MAP-DATA-007: 저장된 값을 읽을 수 없으면 기본 지도를 확인하지 못한 상태로 제공한다

- 근거: `data > 저장 시점과 유지`
- Given: 기본 지도 저장값을 읽을 수 없도록 제어되어 있다.
- When: 기본 지도를 조회한다.
- Then: 네이버 지도를 기본값으로 제공하지 않고 기본 지도를 아직 확인하지 못한 상태를 제공한다.

### TC-SETTING-MAP-DATA-011: 저장된 값이 알 수 없는 지도이면 네이버 지도를 제공한다

- 근거: `data > 저장 시점과 유지`
- Given: 기본 지도 저장값이 고를 수 있는 지도 중 어느 것에도 해당하지 않는 값으로 읽히도록 제어되어 있다.
- When: 기본 지도를 조회한다.
- Then: 네이버 지도를 제공한다.

### TC-SETTING-MAP-DATA-008: 앱을 종료하고 다시 시작해도 저장한 기본 지도를 제공한다

- 근거: `data > 저장 시점과 유지`
- Given: 기본 지도가 Google 지도로 저장되어 있다.
- When: 앱을 종료하고 다시 시작한 뒤 기본 지도를 조회한다.
- Then: Google 지도를 제공한다.
- 작성하지 않는 이유: 실제 저장 영역의 파일이나 브라우저 저장 영역을 닫았다 다시 열어야 관찰할 수 있다. 저장 영역을 임시 폴더에 만들고 닫았다 다시 여는 저장소 계층 테스트 환경이 제공되면 자동화한다.

### TC-SETTING-MAP-DATA-009: 로그인, 로그아웃, 계정 전환은 기본 지도를 바꾸지 않는다

- 근거: `data > 기기별 보관`
- Given: 기본 지도가 Google 지도로 저장되어 있다.
- When: 테스트 데이터의 계정 변화가 일어난 뒤 기본 지도를 조회한다.
- Then: Google 지도를 제공하고, 기본 지도가 서버와 주고받는 정보에 포함되지 않는다.
- 테스트 데이터:

| 계정 변화 |
| --- |
| 로그인 |
| 로그아웃 |
| 계정 전환 |

- 작성하지 않는 이유: 계정 흐름 전체를 거쳐야 관찰할 수 있다. 로그인·로그아웃·계정 전환을 제어된 응답으로 실행하면서 같은 기기 저장 영역을 이어서 조회할 수 있는 통합 테스트 환경이 제공되면 자동화한다.

### TC-SETTING-MAP-DATA-010: 저장 영역이 지워지면 네이버 지도를 기본으로 제공한다

- 근거: `data > 환경별 저장 영역`
- Given: 테스트 데이터의 환경에서 기본 지도가 Google 지도로 저장되어 있다.
- When: 그 환경의 저장 영역이 지워진 뒤 기본 지도를 조회한다.
- Then: 네이버 지도를 제공한다.
- 테스트 데이터:

| 환경 | 저장 영역이 지워지는 경우 |
| --- | --- |
| Android | 앱을 삭제하거나 앱 데이터를 지움 |
| iOS | 앱을 삭제함 |
| 웹 | 브라우저의 사이트 저장 영역을 지움 |

- 작성하지 않는 이유: 각 플랫폼의 실제 저장 영역에 의존한다. 각 플랫폼의 기기나 브라우저에서 앱 저장 영역을 지우고 다시 여는 기기 테스트 환경이 제공되면 자동화한다. 데스크톱 앱에서 개발용 앱과 운영용 앱의 저장 영역 구분은 TC-SETTING-MAP-DATA-006에서 다룬다.
