# 캘린더 메모 표시 테스트 케이스

기준 스펙: [캘린더 메모 표시 스펙](../spec/client/calendar-memo.md)

## domain

### TC-CALENDAR-MEMO-DOMAIN-001: 표시 대상 기간과 겹치는 메모만 표시 대상이 된다

- 근거: `domain > 표시 대상 기간`
- Given: 현재 사용자 계정에 기간이 있고 삭제되지 않은 메모가 저장되어 있다.
- When: 2026년 7월 5일부터 7월 11일까지를 표시 대상 기간으로 캘린더 메모를 조회한다.
- Then: 표시 대상 기간과 하루라도 겹치는 메모만 결과에 포함된다.
- 테스트 데이터:

| 메모의 기간 | 결과 포함 | 비고 |
| --- | --- | --- |
| 7월 1일부터 7월 4일까지 | 아님 | 표시 대상 기간보다 완전히 이전 |
| 7월 1일부터 7월 5일까지 | 포함 | 표시 대상 기간 시작일과 하루만 겹침 |
| 7월 6일부터 7월 8일까지 | 포함 | 표시 대상 기간 안에 완전히 들어감 |
| 7월 5일부터 7월 11일까지 | 포함 | 표시 대상 기간과 정확히 일치 |
| 7월 1일부터 7월 20일까지 | 포함 | 표시 대상 기간 전체를 감쌈 |
| 7월 11일부터 7월 15일까지 | 포함 | 표시 대상 기간 종료일과 하루만 겹침 |
| 7월 12일부터 7월 15일까지 | 아님 | 표시 대상 기간보다 완전히 이후 |

### TC-CALENDAR-MEMO-DOMAIN-002: 시각이 있는 기간의 겹침도 날짜만으로 판단한다

- 근거: `domain > 표시 대상 기간`
- Given: 현재 사용자 계정에 시각까지 있는 기간을 가진 메모가 저장되어 있다.
- When: 2026년 7월 5일부터 7월 11일까지를 표시 대상 기간으로 캘린더 메모를 조회한다.
- Then: 시각을 무시하고 시작일과 종료일만 비교한 결과가 나온다.
- 테스트 데이터:

| 메모의 기간 | 결과 포함 | 비고 |
| --- | --- | --- |
| 7월 4일 23시 59분부터 7월 4일 23시 59분까지 | 아님 | 종료일이 표시 대상 기간 시작일보다 이전 |
| 7월 4일 23시 0분부터 7월 5일 0시 0분까지 | 포함 | 종료일이 표시 대상 기간 시작일과 같음 |
| 7월 11일 23시 59분부터 7월 12일 1시 0분까지 | 포함 | 시작일이 표시 대상 기간 종료일과 같음 |
| 7월 12일 0시 0분부터 7월 12일 1시 0분까지 | 아님 | 시작일이 표시 대상 기간 종료일보다 이후 |

### TC-CALENDAR-MEMO-DOMAIN-003: 기간이 없는 메모는 표시하지 않는다

- 근거: `domain > 캘린더 메모`, `domain > 노출 기준`
- Given: 현재 사용자 계정에 기간이 없는 메모와, 표시 대상 기간과 겹치는 기간을 가진 메모가 함께 저장되어 있다.
- When: 표시 대상 기간으로 캘린더 메모를 조회한다.
- Then: 기간을 가진 메모만 결과에 포함되고 기간이 없는 메모는 포함되지 않는다.

### TC-CALENDAR-MEMO-DOMAIN-004: 삭제된 메모는 표시하지 않는다

- 근거: `domain > 노출 기준`
- Given: 현재 사용자 계정에 표시 대상 기간과 겹치는 기간을 가진 메모가 저장되어 있고, 그중 하나는 삭제된 상태다.
- When: 표시 대상 기간으로 캘린더 메모를 조회한다.
- Then: 삭제되지 않은 메모만 결과에 포함된다.

### TC-CALENDAR-MEMO-DOMAIN-005: 완료된 메모도 표시한다

- 근거: `domain > 노출 기준`
- Given: 현재 사용자 계정에 표시 대상 기간과 겹치는 기간을 가진 메모가 저장되어 있고, 그중 하나는 완료된 상태다.
- When: 표시 대상 기간으로 캘린더 메모를 조회한다.
- Then: 완료된 메모와 완료되지 않은 메모가 모두 결과에 포함된다.

### TC-CALENDAR-MEMO-DOMAIN-006: 현재 사용자 계정을 기준으로 표시할 메모를 정한다

- 근거: `domain > 노출 기준`
- Given: 두 계정에 각각 표시 대상 기간과 겹치는 서로 다른 메모가 저장되어 있고, 현재 사용자 계정은 첫 번째 계정이다.
- When: 표시 대상 기간으로 캘린더 메모를 조회한다.
- Then: 첫 번째 계정과 연결된 메모만 결과에 포함된다.

### TC-CALENDAR-MEMO-DOMAIN-007: 메모에 기록된 기간 형태를 그대로 유지한다

- 근거: `domain > 기간 형태`
- Given: 현재 사용자 계정에 종일 기간을 가진 메모와 시각까지 있는 기간을 가진 메모가 표시 대상 기간과 겹치도록 저장되어 있다.
- When: 표시 대상 기간으로 캘린더 메모를 조회한다.
- Then: 종일 기간 메모는 종일 기간으로, 시각이 있는 기간 메모는 시작·종료 시각이 보존된 기간으로 결과에 포함된다.

### TC-CALENDAR-MEMO-DOMAIN-008: 대표 태그가 있으면 대표 태그의 컬러를 표시 색상으로 사용한다

- 근거: `domain > 표시 색상`
- Given: 현재 사용자 계정에 표시 대상 기간과 겹치는 메모가 저장되어 있고, 메모의 컬러와 대표 태그 상태가 테스트 데이터로 주어진다.
- When: 표시 대상 기간으로 캘린더 메모를 조회한다.
- Then: 테스트 데이터의 표시 색상이 결과에 담긴다.
- 테스트 데이터:

| 대표 태그 상태 | 표시 색상 | 비고 |
| --- | --- | --- |
| 대표 태그 없음 | 메모 자신의 컬러 | 메모의 기본 상태 |
| 삭제되지 않은 대표 태그 있음 | 대표 태그의 컬러 | 대표 태그 우선 |
| 삭제된 대표 태그 있음 | 메모 자신의 컬러 | 삭제된 태그는 색상에 쓰지 않음 |
| 기기에 없는 태그가 대표 태그로 지정됨 | 메모 자신의 컬러 | 태그가 아직 내려받아지지 않은 경우 |
| 완료된 대표 태그 있음 | 대표 태그의 컬러 | 완료는 색상 기준을 바꾸지 않음 |

### TC-CALENDAR-MEMO-DOMAIN-009: 표시 대상 기간이 바뀌면 그 기간을 기준으로 다시 정해진다

- 근거: `domain > 표시 갱신`
- Given: 서로 겹치지 않는 두 기간에 각각 다른 메모가 저장되어 있고, 첫 번째 기간으로 캘린더 메모를 조회한 상태다.
- When: 표시 대상 기간을 두 번째 기간으로 바꿔 조회한다.
- Then: 두 번째 기간에 저장된 메모만 결과에 포함된다.

### TC-CALENDAR-MEMO-DOMAIN-010: 메모 제목이 바뀌면 조작 없이 결과에 반영된다

- 근거: `domain > 표시 갱신`
- Given: 제목이 `기존 제목`인 메모가 표시 대상 기간과 겹치고, 그 기간으로 캘린더 메모를 조회해 결과를 계속 관찰하고 있다.
- When: 조회를 다시 요청하지 않은 상태에서 그 메모의 제목이 `새 제목`으로 바뀐다.
- Then: 같은 메모의 제목이 `새 제목`으로 바뀐 결과가 이어서 전달된다.

### TC-CALENDAR-MEMO-DOMAIN-011: 현재 사용자 계정이 바뀌면 바뀐 계정을 기준으로 다시 정해진다

- 근거: `domain > 표시 갱신`
- Given: 두 계정에 각각 표시 대상 기간과 겹치는 메모가 저장되어 있고, 첫 번째 계정으로 캘린더 메모를 조회해 결과를 계속 관찰하고 있다.
- When: 현재 사용자 계정이 두 번째 계정으로 바뀐다.
- Then: 두 번째 계정과 연결된 메모만 담긴 결과가 이어서 전달된다.

### TC-CALENDAR-MEMO-DOMAIN-012: 표시할 메모가 없으면 빈 결과를 전달한다

- 근거: `domain > 표시할 메모가 없을 때`
- Given: 현재 사용자 계정에 표시 대상 기간과 겹치는 메모가 없다.
- When: 표시 대상 기간으로 캘린더 메모를 조회한다.
- Then: 조회가 성공하고 결과는 비어 있다.

### TC-CALENDAR-MEMO-DOMAIN-013: 메모를 가져오지 못하면 실패로 알린다

- 근거: `domain > 표시할 메모가 없을 때`, `data > 조회 실패`
- Given: 캘린더 메모 조회가 실패하도록 준비되어 있다.
- When: 표시 대상 기간으로 캘린더 메모를 조회한다.
- Then: 실패한 결과가 전달된다.

### TC-CALENDAR-MEMO-DOMAIN-014: 현재 사용자 계정을 확인하지 못하면 실패로 알린다

- 근거: `data > 조회 실패`
- Given: 현재 사용자 계정 확인이 실패하도록 준비되어 있다.
- When: 표시 대상 기간으로 캘린더 메모를 조회한다.
- Then: 실패한 결과가 전달된다.

### TC-CALENDAR-MEMO-DOMAIN-016: 같은 표시 대상 기간을 다시 조회해도 순서가 유지된다

- 근거: `domain > 조회 결과 정렬`
- Given: 현재 사용자 계정에 표시 대상 기간과 겹치는 메모 여러 건이 저장되어 있다.
- When: 같은 표시 대상 기간으로 캘린더 메모를 두 번 조회한다.
- Then: 두 결과의 메모 순서가 같다.

### TC-CALENDAR-MEMO-DOMAIN-018: 종일 메모를 우선하고 시작이 이른 순으로 전달한다

- 근거: `domain > 조회 결과 정렬`
- Given: 현재 사용자 계정에 표시 대상 기간과 겹치는 종일 기간 메모 여러 건과, 그 메모들보다 시작이 이른 시각이 있는 기간 메모가 저장되어 있다.
- When: 표시 대상 기간으로 캘린더 메모를 조회한다.
- Then: 종일 기간 메모가 시각이 있는 기간 메모보다 먼저 전달되며, 종일 기간 메모끼리는 시작이 이른 순, 시작이 같으면 종료가 늦은 순, 기간이 모두 같으면 제목의 오름차순으로 전달된다.

### TC-CALENDAR-MEMO-DOMAIN-019: 시각이 있는 메모는 시작과 종료가 이른 순으로 전달한다

- 근거: `domain > 조회 결과 정렬`
- Given: 현재 사용자 계정에 표시 대상 기간과 겹치는 시각이 있는 기간 메모 여러 건이 저장되어 있다.
- When: 표시 대상 기간으로 캘린더 메모를 조회한다.
- Then: 시각이 있는 기간 메모는 시각을 포함한 시작이 이른 순, 시작이 같으면 시각을 포함한 종료가 이른 순, 기간이 모두 같으면 제목의 오름차순으로 전달된다.

### TC-CALENDAR-MEMO-DOMAIN-020: 기간 형태·시작·종료·제목이 모두 같으면 식별값의 오름차순으로 전달한다

- 근거: `domain > 조회 결과 정렬`
- Given: 현재 사용자 계정에 표시 대상 기간과 겹치고 기간 형태·시작·종료·제목이 모두 같은 메모 여러 건이 저장되어 있다.
- When: 표시 대상 기간으로 캘린더 메모를 조회한다.
- Then: 메모가 식별값의 오름차순으로 전달된다.
- 테스트 데이터:

| 기간 형태 | 비고 |
| --- | --- |
| 종일 기간 | 종일 기간 메모끼리의 마지막 기준 |
| 시각이 있는 기간 | 시각이 있는 기간 메모끼리의 마지막 기준 |

## data

### TC-CALENDAR-MEMO-DATA-001: 대표 태그의 컬러가 바뀌면 조작 없이 표시 색상이 갱신된다

- 근거: `data > 저장된 내용 변경의 반영`
- Given: 표시 대상 기간과 겹치는 메모가 삭제되지 않은 대표 태그와 함께 저장되어 있고, 그 기간으로 캘린더 메모를 조회해 결과를 계속 관찰하고 있다.
- When: 조회를 다시 요청하지 않은 상태에서 대표 태그의 컬러가 바뀐다.
- Then: 바뀐 대표 태그의 컬러를 표시 색상으로 가진 결과가 이어서 전달된다.

### TC-CALENDAR-MEMO-DATA-002: 대표 태그가 나중에 저장되면 표시 색상이 대표 태그 컬러로 바뀐다

- 근거: `data > 표시 색상 해석`, `data > 저장된 내용 변경의 반영`
- Given: 표시 대상 기간과 겹치는 메모가 기기에 아직 없는 태그를 대표 태그로 지정한 상태로 저장되어 있고, 그 기간으로 캘린더 메모를 조회해 결과를 계속 관찰하고 있다.
- When: 조회를 다시 요청하지 않은 상태에서 대표 태그가 기기에 저장된다.
- Then: 대표 태그의 컬러를 표시 색상으로 가진 결과가 이어서 전달된다.

### TC-CALENDAR-MEMO-DATA-003: 메모의 기간이 겹치지 않게 바뀌면 결과에서 빠진다

- 근거: `data > 저장된 내용 변경의 반영`
- Given: 표시 대상 기간과 겹치는 메모가 저장되어 있고, 그 기간으로 캘린더 메모를 조회해 결과를 계속 관찰하고 있다.
- When: 조회를 다시 요청하지 않은 상태에서 그 메모의 기간이 표시 대상 기간과 겹치지 않게 바뀐다.
- Then: 그 메모가 빠진 결과가 이어서 전달된다.

### TC-CALENDAR-MEMO-DATA-004: 메모가 삭제되면 결과에서 빠진다
