# TagHome 목록 테스트 케이스

기준 스펙: [TagHome 목록 스펙](../spec/client/tag-home.md)

자리 표시 케이스의 `근거`가 가리키는 절은 공통 규칙을 [페이지 조회 목록의 자리 표시 스펙](../spec/client/paged-list-placeholder.md)에, 빈 상태 케이스의 `근거`가 가리키는 절은 [목록 빈 상태 스펙](../spec/client/list-empty-state.md)에 위임한다.

최상위 태그 필터를 바꾼 뒤 목록을 어디서부터 보는지는 [목록 필터 반영 스펙](../spec/client/list-filter.md)에 위임한다.

최상위 태그 필터 케이스의 `근거`가 가리키는 절 중 향해 오는 연결을 세는 기준은 [태그 연결 앱 스펙](../spec/client/tag-link.md)의 `향해 오는 연결의 존재 판정`에 위임하며, 그 기준 자체의 케이스는 [태그 연결 테스트 케이스](./tag-link.md)가 갖는다. 출발 태그를 삭제하거나 그 삭제를 되돌렸을 때 도착 태그의 판정이 바뀌는 케이스도 같은 문서의 `TC-TAG-LINK-DOMAIN-019`가 갖는다.

카드를 미는 상호작용 자체의 케이스는 [SwipeToFinishAndDelete 테스트 케이스](./swipe-to-finish-and-delete.md)에서 다룬다. 완료·삭제의 안내와 실행 취소 케이스의 `근거`가 가리키는 절은 공통 규칙을 [MemoHome 목록 스펙](../spec/client/memo-home.md)의 `안내와 실행 취소`에 위임한다. 태그를 완료하거나 삭제해도 연결이 해제되지 않는 케이스는 [태그 연결 테스트 케이스](./tag-link.md)의 `TC-TAG-LINK-DOMAIN-012`가 갖는다.

## feature

### TC-TAG-HOME-FEATURE-001: 목록에 태그 이모지, 제목과 컬러를 표시한다

- 근거: `feature > 목록 표시`, `domain > 태그 이모지 표시`
- Given: 현재 계정에 이모지가 저장된 목록 노출 대상 태그들이 저장되어 있다.
- When: 사용자가 TagHome 화면을 확인한다.
- Then: 각 태그의 이모지와 제목이 이모지, 제목 순서로 함께 표시되고 저장된 컬러도 표시된다.

### TC-TAG-HOME-FEATURE-012: 이모지가 비어 있으면 제목만 표시한다

- 근거: `domain > 태그 이모지 표시`
- Given: 현재 계정에 이모지가 비어 있는 목록 노출 대상 태그가 저장되어 있다.
- When: 사용자가 TagHome 화면을 확인한다.
- Then: 그 태그에는 앞선 공백 없이 제목만 표시되고 저장된 컬러는 그대로 표시된다.

### TC-TAG-HOME-FEATURE-015: 아직 준비되지 않은 자리는 자리 표시 카드로 표시한다

- 근거: `feature > 목록 표시`
- Given: 목록의 한 자리에 표시할 태그가 아직 준비되지 않았다.
- When: 사용자가 TagHome 화면을 확인한다.
- Then: 그 자리에는 이모지, 제목과 컬러가 비어 있는 카드가 표시된다.

### TC-TAG-HOME-FEATURE-016: 자리 표시 카드는 선택할 수 없다

- 근거: `feature > 목록 표시`
- Given: 목록에 태그가 준비되지 않은 자리 표시 카드가 표시되어 있다.
- When: 사용자가 그 카드를 선택하려 한다.
- Then: 상세 이동이 요청되지 않는다.

### TC-TAG-HOME-FEATURE-017: 목록을 내려 보면 아직 준비되지 않은 구간의 태그가 이어서 나타난다

- 근거: `feature > 목록 표시`
- Given: 현재 계정에 목록 노출 대상 태그가 한 번에 준비되는 양보다 많이 저장되어 있고 TagHome 목록이 표시되어 있다.
- When: 사용자가 목록을 아직 준비되지 않은 구간까지 내려 본다.
- Then: 그 구간의 태그가 제목 오름차순에 이어서 나타난다.

### TC-TAG-HOME-FEATURE-036: 태그를 선택하면 그 태그의 TagDetail 화면으로 이동한다

- 근거: `feature > 목록 표시`
- Given: 목록에 태그가 표시되어 있다.
- When: 사용자가 목록의 태그 하나를 선택한다.
- Then: 선택한 태그의 TagDetail 화면으로 이동한다.

### TC-TAG-HOME-FEATURE-013: 완료된 태그 확인을 선택하면 TagFinishedList 화면으로 이동한다

- 근거: `feature > 완료된 태그 확인`
- Given: 사용자가 TagHome 목록을 보고 있다.
- When: 사용자가 완료된 태그 확인을 선택한다.
- Then: TagFinishedList 화면으로 이동한다.

### TC-TAG-HOME-FEATURE-014: 완료된 태그가 없어도 완료된 태그 확인 동작을 제공한다

- 근거: `feature > 완료된 태그 확인`
- Given: 현재 계정에 완료된 태그가 하나도 없다.
- When: 사용자가 TagHome 목록에서 실행할 수 있는 동작을 확인한다.
- Then: 완료된 태그 확인 동작이 제공된다.

### TC-TAG-HOME-FEATURE-024: 검색을 선택하면 태그 유형으로 시작하는 SearchHome 화면으로 이동한다

- 근거: `feature > 검색으로 이동`
- Given: 사용자가 TagHome 목록을 보고 있다.
- When: 사용자가 검색을 선택한다.
- Then: SearchHome 화면으로 이동하는 동작이 한 번 실행된다.

지정하는 시작 유형은 화면 밖 내비게이션 배선이 정하므로 이 케이스에서 관찰하지 않는다. 시작 유형별 표시는 [SearchHome 테스트 케이스](./search-home.md)의 `TC-SEARCH-HOME-FEATURE-005`가 다룬다.

### TC-TAG-HOME-FEATURE-025: 표시할 태그가 없어도 검색 동작을 제공한다

- 근거: `feature > 검색으로 이동`, `feature > 빈 상태`
- Given: TagHome 목록에 빈 상태 안내가 표시되어 있다.
- When: 사용자가 화면에서 실행할 수 있는 동작을 확인한다.
- Then: 검색 동작이 제공된다.

### TC-TAG-HOME-FEATURE-018: 표시할 태그가 없으면 빈 상태 안내를 표시한다

- 근거: `feature > 빈 상태`
- Given: 현재 계정에 목록 노출 대상 태그가 하나도 없고 목록의 준비가 끝났다.
- When: 사용자가 TagHome 화면을 확인한다.
- Then: 태그 카드 대신 아직 태그가 없음을 알리는 안내가 표시된다.

### TC-TAG-HOME-FEATURE-019: 목록을 준비하는 동안에는 빈 상태 안내를 표시하지 않는다

- 근거: `feature > 빈 상태`
- Given: 목록에 표시된 태그가 아직 하나도 없고 목록의 준비가 끝나지 않았다.
- When: 사용자가 TagHome 화면을 확인한다.
- Then: 빈 상태 안내가 표시되지 않는다.

### TC-TAG-HOME-FEATURE-020: 표시할 태그가 있으면 빈 상태 안내를 표시하지 않는다

- 근거: `feature > 빈 상태`
- Given: 현재 계정에 목록 노출 대상 태그가 하나 이상 저장되어 있다.
- When: 사용자가 TagHome 화면을 확인한다.
- Then: 태그 카드가 표시되고 빈 상태 안내는 표시되지 않는다.

### TC-TAG-HOME-FEATURE-023: 빈 상태에서도 목록을 당겨 새로고침할 수 있다

- 근거: `feature > 빈 상태`
- Given: TagHome 목록에 빈 상태 안내가 표시되어 있다.
- When: 사용자가 빈 상태 영역을 아래로 당겨 새로고침을 요청한다.
- Then: 새로고침이 한 번 요청된다.

### TC-TAG-HOME-FEATURE-022: 목록을 조회하지 못하면 빈 상태 안내를 표시한다

- 근거: `feature > 불러오기 실패`, `feature > 빈 상태`
- Given: 목록 조회가 실패했고 표시된 태그가 하나도 없다.
- When: 사용자가 TagHome 화면을 확인한다.
- Then: 아직 태그가 없음을 알리는 안내가 표시되고 별도의 오류 안내는 표시되지 않는다.

### TC-TAG-HOME-FEATURE-038: 이어서 불러오지 못해도 이미 보이는 태그를 그대로 둔다

- 근거: `feature > 불러오기 실패`
- Given: TagHome 목록에 태그가 표시되어 있고, 이어서 불러오는 태그의 조회가 실패했다.
- When: 사용자가 TagHome 화면을 확인한다.
- Then: 이미 보이던 태그가 그대로 표시되고 빈 상태 안내는 표시되지 않는다.

### TC-TAG-HOME-FEATURE-021: 빈 상태에서도 태그 추가와 완료된 태그 확인을 실행할 수 있다

- 근거: `feature > 빈 상태`
- Given: TagHome 목록에 빈 상태 안내가 표시되어 있다.
- When: 사용자가 화면에서 실행할 수 있는 동작을 확인한다.
- Then: 태그 추가 동작과 완료된 태그 확인 동작이 모두 제공된다.

### TC-TAG-HOME-FEATURE-027: 필터를 열면 최상위 태그만 보기의 현재 상태가 표시된다

- 근거: `feature > 최상위 태그 필터`, `data > 필터 선택 조회`
- Given: 현재 계정에 최상위 태그만 보기를 한 번도 켜지 않았다.
- When: 사용자가 TagHome 목록에서 필터를 연다.
- Then: 최상위 태그만 보기 항목이 꺼진 상태로 표시된다.

### TC-TAG-HOME-FEATURE-028: 필터를 켜면 최상위 태그만 목록에 남는다

- 근거: `feature > 최상위 태그 필터`, `domain > 최상위 태그 판정 기준`
- Given: 현재 계정에 향해 오는 연결이 없는 태그와 다른 태그로부터 향해 오는 연결을 가진 태그가 함께 목록에 표시되어 있다.
- When: 사용자가 필터에서 최상위 태그만 보기를 켠다.
- Then: 별도의 확정 동작 없이 향해 오는 연결이 없는 태그만 목록에 남고, 향해 오는 연결을 가진 태그는 목록에서 사라진다.

### TC-TAG-HOME-FEATURE-029: 필터를 끄면 노출 대상 태그 전체가 다시 표시된다

- 근거: `feature > 최상위 태그 필터`
- Given: 최상위 태그만 보기를 켜 두어 일부 태그가 목록에서 빠진 상태다.
- When: 사용자가 필터에서 최상위 태그만 보기를 끈다.
- Then: 향해 오는 연결을 가진 태그까지 포함해 목록 노출 대상 태그 전체가 다시 표시된다.

### TC-TAG-HOME-FEATURE-030: 필터를 닫았다가 다시 열어도 켜 둔 상태를 표시한다

- 근거: `feature > 최상위 태그 필터`
- Given: 사용자가 필터에서 최상위 태그만 보기를 켰다.
- When: 사용자가 필터를 닫았다가 다시 연다.
- Then: 최상위 태그만 보기 항목이 켜진 상태로 표시되고 목록도 켜 둔 기준을 그대로 유지한다.

### TC-TAG-HOME-FEATURE-037: 최상위 태그만 보기를 켰을 때만 필터 열기 동작이 필터 적용 상태를 알린다

- 근거: `feature > 최상위 태그 필터`
- Given: 최상위 태그만 보기가 테스트 데이터의 상태로 선택되어 있다.
- When: 사용자가 TagHome 목록의 필터 열기 동작을 확인한다.
- Then: 테스트 데이터의 기대 결과대로 필터 열기 동작이 필터 적용 상태를 알리거나 알리지 않는다.
- 테스트 데이터:

| 최상위 태그만 보기 | 기대 결과 |
| --- | --- |
| 켜짐 | 필터가 적용되었음을 알린다 |
| 꺼짐 | 필터가 적용되었음을 알리지 않는다 |

### TC-TAG-HOME-FEATURE-031: 필터를 켠 채로 표시할 태그가 없으면 최상위 태그가 없음을 알린다

- 근거: `feature > 빈 상태`, `domain > 최상위 태그 판정 기준`
- Given: 최상위 태그만 보기를 켜 두었고, 목록 노출 대상 태그가 모두 향해 오는 연결을 가지며 목록의 준비가 끝났다.
- When: 사용자가 TagHome 화면을 확인한다.
- Then: 태그 카드 대신 최상위 태그가 없음을 알리는 안내가 표시되고, 아직 태그가 없음을 알리는 안내는 표시되지 않는다.

### TC-TAG-HOME-FEATURE-032: 필터를 끈 채로 표시할 태그가 없으면 아직 태그가 없음을 알린다

- 근거: `feature > 빈 상태`
- Given: 최상위 태그만 보기가 꺼져 있고, 목록 노출 대상 태그가 하나도 없으며 목록의 준비가 끝났다.
- When: 사용자가 TagHome 화면을 확인한다.
- Then: 아직 태그가 없음을 알리는 안내가 표시되고, 최상위 태그가 없음을 알리는 안내는 표시되지 않는다.

### TC-TAG-HOME-FEATURE-033: 필터를 켜 두어도 다른 동작을 그대로 실행할 수 있다

- 근거: `feature > 최상위 태그 필터`
- Given: 최상위 태그만 보기를 켜 두었다.
- When: 사용자가 화면에서 실행할 수 있는 동작을 확인한다.
- Then: 태그 추가, 완료된 태그 확인, 검색, 태그 선택, 태그 카드를 밀어 실행하는 완료와 삭제 동작이 모두 제공된다.

### TC-TAG-HOME-FEATURE-034: 필터를 바꾸면 목록을 처음부터 다시 본다

- 근거: `feature > 최상위 태그 필터`
- Given: 한 화면에 다 들어가지 않을 만큼 태그가 목록에 표시되어 있고, 사용자가 목록을 아래로 이동해 첫 태그 카드가 보이지 않는 상태다.
- When: 사용자가 필터에서 최상위 태그만 보기를 테스트 데이터의 방향으로 바꾸고, 좁힌 결과가 목록에 놓인다.
- Then: 첫 태그 카드가 다시 보이고, 사용자가 이동해 보고 있던 자리의 태그 카드는 보이지 않는다.
- 테스트 데이터:

| 바꾸는 방향 |
| --- |
| 꺼짐에서 켜짐으로 바꾼다 |
| 켜짐에서 꺼짐으로 바꾼다 |

### TC-TAG-HOME-FEATURE-035: 필터 선택을 저장하지 못하면 바꾸기 전의 선택을 그대로 보여 준다

- 근거: `domain > 필터 선택 유지`
- Given: 최상위 태그만 보기가 테스트 데이터의 상태로 저장되어 있고, 필터 선택을 저장하면 실패하도록 설정되어 있다.
- When: 사용자가 필터에서 최상위 태그만 보기를 반대 상태로 바꾼다.
- Then: 필터와 목록은 바꾸기 전의 선택을 그대로 보여 주고, 실패를 따로 알리지 않는다.
- 테스트 데이터: 꺼짐, 켜짐

- When: 테스트 데이터의 경계를 지난다.
- Then: 필터가 열린 채로 표시되고, 필터를 닫으면 TagHome 목록으로 돌아간다.
- 테스트 데이터:

| 경계 |
| --- |
| 화면 회전처럼 시스템이 화면을 재생성한다 |
| 앱이 종료되지 않은 채 백그라운드에 갔다가 돌아온다 |
| 앱이 백그라운드에 있는 동안 시스템이 앱을 정리했다가 다시 만든다 |

### TC-TAG-HOME-DOMAIN-020: 시스템이 앱을 정리한 뒤 다시 만들면 필터 선택은 이어지고 정렬은 처음으로 돌아가며 보던 위치는 다시 보인다

- 근거: `domain > 실행 경계`
- Given: 최상위 태그만 보기를 켜고 정렬을 최근 수정순으로 고른 목록에 한 화면에 다 들어가지 않는 수의 태그가 표시되어 있고, 사용자가 목록을 내려 뒤쪽의 태그를 보고 있다.
- When: 앱이 백그라운드에 있는 동안 시스템이 앱을 정리했다가 다시 만든다.
- Then: 필터를 여는 동작은 여전히 필터가 적용되었음을 알리고, 정렬 컨트롤은 제목순을 알리며, 처음 정렬로 놓인 목록에서 떠나기 전과 같은 위치의 태그가 보이고 첫 태그 카드는 보이지 않는다.

## data

### TC-TAG-HOME-DATA-001: 현재 계정과 연결된 미완료·미삭제 태그만 목록에서 조회한다

- 근거: `domain > 노출 기준`, `data > 목록 조회`
- Given: 현재 계정과 다른 계정에 각각 연결된 미완료·미삭제 태그, 완료된 태그, 삭제된 태그가 함께 저장되어 있다.
- When: 현재 계정의 태그 목록을 조회한다.
- Then: 현재 계정과 연결된 미완료·미삭제 태그만 조회된다.

### TC-TAG-HOME-DATA-002: 태그 목록을 제목 오름차순으로 조회한다

- 근거: `domain > 정렬`
- Given: 제목과 수정·생성 시각이 서로 다른 목록 노출 대상 태그들이 저장되어 있다.
- When: 태그 목록을 조회한다.
- Then: 수정·생성 시각과 관계없이 제목 오름차순으로 조회된다.

### TC-TAG-HOME-DATA-005: 목록을 페이지 단위로 조회한다

- 근거: `data > 목록 조회`
- Given: 현재 계정에 목록 노출 대상 태그가 한 번에 조회하는 범위보다 많이 저장되어 있다.
- When: 태그 목록을 조회한다.
- Then: 저장된 태그 전체가 아니라 제목 오름차순 앞쪽의 일부만 먼저 조회되고, 이어지는 조회에서 그다음 태그가 정렬 순서대로 조회된다.

### TC-TAG-HOME-DATA-003: 저장된 태그 변경을 목록에 자동으로 반영한다

- 근거: `data > 목록 조회`
- Given: 사용자가 TagHome 목록을 보고 있다.
- When: 현재 계정의 목록 노출 대상 태그가 추가되거나 저장된 태그의 제목 또는 노출 상태가 바뀐다.
- Then: 태그 목록이 노출 기준과 정렬 기준에 맞게 자동으로 갱신된다.

### TC-TAG-HOME-DATA-006: 필터를 켜 두면 향해 오는 연결이 없는 태그만 조회한다

- 근거: `data > 목록 조회`
- Given: 현재 계정에 향해 오는 연결이 없는 태그와 향해 오는 연결을 가진 태그가 함께 저장되어 있고 최상위 태그만 보기가 켜져 있다.
- When: 태그 목록을 조회한다.
- Then: 향해 오는 연결이 없는 태그만 제목 오름차순으로 조회된다.

### TC-TAG-HOME-DATA-007: 필터를 켠 목록은 연결 변경을 자동으로 반영한다

- 근거: `data > 목록 조회`
- Given: 최상위 태그만 보기를 켜 둔 태그 목록을 보고 있다.
- When: 표시된 태그를 향해 오는 연결이 만들어지거나 그 태그를 향해 오는 연결이 모두 해제된다.
- Then: 목록이 다시 판정되어 그 태그가 사라지거나 정렬 순서에 맞는 자리에 나타난다.

### TC-TAG-HOME-DATA-008: 필터 선택을 계정별로 저장하고 다시 조회해도 유지한다

- 근거: `data > 필터 선택 저장`, `data > 필터 선택 조회`, `domain > 필터 선택 유지`
- Given: 현재 계정에 저장된 필터 선택이 없다.
- When: 최상위 태그만 보기를 켠 뒤 그 계정의 필터 선택을 다시 조회한다.
- Then: 켜진 상태로 조회된다.

### TC-TAG-HOME-DATA-009: 저장된 선택이 없으면 꺼진 상태로 조회한다

- 근거: `data > 필터 선택 조회`, `domain > 필터 선택 유지`
- Given: 현재 계정에 저장된 필터 선택이 없다.
- When: 그 계정의 필터 선택을 조회한다.
- Then: 꺼진 상태로 조회된다.

### TC-TAG-HOME-DATA-010: 한 계정에서 켠 필터는 다른 계정에 적용되지 않는다

- 근거: `domain > 필터 선택 유지`, `data > 필터 선택 저장`
- Given: 한 계정에서 최상위 태그만 보기를 켜 두었다.
- When: 현재 사용자 계정이 다른 계정으로 바뀐 뒤 필터 선택을 조회한다.
- Then: 바뀐 계정의 선택이 꺼진 상태로 조회되고, 다시 이전 계정으로 바뀌면 켜진 상태로 조회된다.

### TC-TAG-HOME-DATA-011: 필터 선택은 서버와 동기화하지 않는다

- 근거: `data > 필터 선택 저장`
- Given: 로그인한 사용자 계정이 확인되어 있다.
- When: 최상위 태그만 보기를 켜거나 끈다.
- Then: 필터 선택을 반영하는 서버 요청이 발생하지 않는다.

### TC-TAG-HOME-DATA-012: 필터를 켜 두어도 다른 태그 조회는 좁혀지지 않는다

- 근거: `domain > 필터 적용 범위`
- Given: 현재 계정에 향해 오는 연결을 가진 미완료·미삭제 태그가 저장되어 있고 최상위 태그만 보기가 켜져 있다.
- When: 태그 검색 결과, 메모의 태그 선택 목록, 태그 연결 입력의 선택 목록, 항목 태그 입력의 선택 목록, 태그 필터에서 선택할 수 있는 태그를 각각 조회한다.
- Then: 다섯 조회 모두에서 그 태그가 그대로 조회된다.

### TC-TAG-HOME-DATA-013: 강제 전체 재동기화를 하면 그 계정의 필터 선택이 꺼진 상태로 돌아간다

- 근거: `domain > 필터 선택 유지`
- Given: 현재 계정과 다른 계정 모두 최상위 태그만 보기를 켜 두었다.
- When: 현재 계정의 강제 전체 재동기화로 그 계정의 기기 데이터를 지운다.
- Then: 현재 계정의 필터 선택은 꺼진 상태로 조회되고, 다른 계정의 필터 선택은 켜진 상태로 남는다.

### TC-TAG-HOME-DATA-014: 삭제의 실행 취소를 저장하면 동기화가 요청된다

- 근거: `data > 상태 변경의 저장`
- Given: 로그인한 사용자 계정이 있고 기기 저장이 성공한다.
- When: 목록에서 삭제한 태그의 실행 취소를 저장한다.
- Then: 기기 저장 결과로 성공이 전달되고, 서버와 맞추는 백그라운드 동기화가 요청된다.

### TC-TAG-HOME-DATA-015: 로그인하지 않은 상태의 실행 취소는 기기에만 저장된다

- 근거: `data > 상태 변경의 저장`
- Given: 로그인하지 않아 게스트 상태의 계정이 확인된다.
- When: 태그 삭제의 실행 취소를 저장한다.
- Then: 게스트 계정 기준으로 기기에 저장된다.

### TC-TAG-HOME-DATA-016: 실행 취소의 저장에 실패하면 실패를 전달하고 동기화를 요청하지 않는다

- 근거: `data > 상태 변경의 저장`
- Given: 기기 저장이 실패하도록 설정되어 있다.
- When: 태그 삭제의 실행 취소를 저장한다.
- Then: 실패가 그대로 전달되고 동기화는 요청되지 않는다.

### 작성하지 않는 이유

제목이 같은 태그끼리의 순서는 스펙에서 정하지 않으므로 기대 결과를 판정할 수 없어 작성하지 않는다.

앱을 종료하고 다시 실행하면 정렬이 처음 정렬로 돌아가고 목록이 맨 위부터 보이는 것은 앱을 실제로 종료하고 다시 실행해 앱 전체를 통과해야 판정할 수 있어 작성하지 않는다. 앱 종료와 재실행을 제어할 수 있는 앱 수준 화면 자동화 환경이 갖춰지면 작성한다.

앱을 종료하고 다시 실행한 뒤에도 필터 선택이 유지되는 것은 저장된 선택을 다시 조회하는 `TC-TAG-HOME-DATA-008`로 판정하며, 실제 앱 종료와 재실행은 앱 전체를 통과해야 하므로 별도 케이스로 작성하지 않는다.

태그 카드 제목의 한 줄 배치와 폭을 넘는 제목의 무한 반복 가로 이동은 시각적 레이아웃과 애니메이션이므로 현재 단위 테스트 환경에서 외부 결과로 결정적으로 판정할 수 없다. 제목 폭을 제어하고 여러 시점의 화면 프레임을 비교할 수 있는 시각 회귀 테스트 환경이 갖춰지면 자동화한다.
