# TagHome 목록 테스트 케이스

기준 스펙: [TagHome 목록 스펙](../spec/client/tag-home.md)

자리 표시 케이스의 `근거`가 가리키는 절은 공통 규칙을 [페이지 조회 목록의 자리 표시 스펙](../spec/client/paged-list-placeholder.md)에, 빈 상태 케이스의 `근거`가 가리키는 절은 [목록 빈 상태 스펙](../spec/client/list-empty-state.md)에 위임한다.

최상위 태그 필터를 바꾼 뒤 목록을 어디서부터 보는지는 [목록 필터 반영 스펙](../spec/client/list-filter.md)에 위임한다.

최상위 태그 필터 케이스의 `근거`가 가리키는 절 중 향해 오는 연결을 세는 기준은 [태그 연결 앱 스펙](../spec/client/tag-link.md)의 `향해 오는 연결의 존재 판정`에 위임하며, 그 기준 자체의 케이스는 [태그 연결 테스트 케이스](./tag-link.md)가 갖는다. 출발 태그를 삭제하거나 그 삭제를 되돌렸을 때 도착 태그의 판정이 바뀌는 케이스도 같은 문서의 `TC-7b5b43cb-6795-4605-adc2-7defb5d21740`가 갖는다.

카드를 미는 상호작용 자체의 케이스는 [SwipeToFinishAndDelete 테스트 케이스](./swipe-to-finish-and-delete.md)에서 다룬다. 완료·삭제의 안내와 실행 취소 케이스의 `근거`가 가리키는 절은 공통 규칙을 [MemoHome 목록 스펙](../spec/client/memo-home.md)의 `안내와 실행 취소`에 위임한다. 태그를 완료하거나 삭제해도 연결이 해제되지 않는 케이스는 [태그 연결 테스트 케이스](./tag-link.md)의 `TC-0d112bf8-cb8c-46f7-94e3-6d96086c1ebe`가 갖는다.

추가 단축키 케이스의 `근거`가 가리키는 절은 공통 규칙을 [목록 추가 단축키 스펙](../spec/client/list-add-shortcut.md)에 위임한다.

## feature

### TC-e6f864f3-7c11-46a2-ab25-a7d0c59047a2: 목록에 태그 이모지, 제목과 컬러를 표시한다

- 근거: `feature > 목록 표시`, `domain > 태그 이모지 표시`
- Given: 현재 계정에 이모지가 저장된 목록 노출 대상 태그들이 저장되어 있다.
- When: 사용자가 TagHome 화면을 확인한다.
- Then: 각 태그의 이모지와 제목이 이모지, 제목 순서로 함께 표시되고 저장된 컬러도 표시된다.

### TC-d254394e-155f-4402-a44c-e313e7a358c5: 이모지가 비어 있으면 제목만 표시한다

- 근거: `domain > 태그 이모지 표시`
- Given: 현재 계정에 이모지가 비어 있는 목록 노출 대상 태그가 저장되어 있다.
- When: 사용자가 TagHome 화면을 확인한다.
- Then: 그 태그에는 앞선 공백 없이 제목만 표시되고 저장된 컬러는 그대로 표시된다.

### TC-8df6f641-a6db-4d82-ba6e-289153d32335: 아직 준비되지 않은 자리는 자리 표시 카드로 표시한다

- 근거: `feature > 목록 표시`
- Given: 목록의 한 자리에 표시할 태그가 아직 준비되지 않았다.
- When: 사용자가 TagHome 화면을 확인한다.
- Then: 그 자리에는 이모지, 제목과 컬러가 비어 있는 카드가 표시된다.

### TC-f7afc78a-1b0f-48f3-b488-22d190b0130e: 자리 표시 카드는 선택할 수 없다

- 근거: `feature > 목록 표시`
- Given: 목록에 태그가 준비되지 않은 자리 표시 카드가 표시되어 있다.
- When: 사용자가 그 카드를 선택하려 한다.
- Then: 상세 이동이 요청되지 않는다.

### TC-baa3e174-a5b5-4d79-aa60-10b70e45c98d: 목록을 내려 보면 아직 준비되지 않은 구간의 태그가 이어서 나타난다

- 근거: `feature > 목록 표시`
- Given: 현재 계정에 목록 노출 대상 태그가 한 번에 준비되는 양보다 많이 저장되어 있고 TagHome 목록이 표시되어 있다.
- When: 사용자가 목록을 아직 준비되지 않은 구간까지 내려 본다.
- Then: 그 구간의 태그가 제목 오름차순에 이어서 나타난다.

### TC-958b9fa4-e244-4be6-86d5-865a55ca9637: 태그를 선택하면 그 태그의 TagDetail 화면으로 이동한다

### TC-f9ef0bbd-cc67-4cdf-a22f-58c75c647f0c: 완료된 태그 확인을 선택하면 TagFinishedList 화면으로 이동한다

### 작성하지 않는 이유

제목이 같은 태그끼리의 순서는 스펙에서 정하지 않으므로 기대 결과를 판정할 수 없어 작성하지 않는다.

앱을 종료하고 다시 실행하면 정렬이 처음 정렬로 돌아가고 목록이 맨 위부터 보이는 것은 앱을 실제로 종료하고 다시 실행해 앱 전체를 통과해야 판정할 수 있어 작성하지 않는다. 앱 종료와 재실행을 제어할 수 있는 앱 수준 화면 자동화 환경이 갖춰지면 작성한다.

앱을 종료하고 다시 실행한 뒤에도 필터 선택이 유지되는 것은 저장된 선택을 다시 조회하는 `TC-07ef4c1b-2b17-4fa8-a31b-5271c930eca6`로 판정하며, 실제 앱 종료와 재실행은 앱 전체를 통과해야 하므로 별도 케이스로 작성하지 않는다.

태그 카드 제목의 한 줄 배치와 폭을 넘는 제목의 무한 반복 가로 이동은 시각적 레이아웃과 애니메이션이므로 현재 단위 테스트 환경에서 외부 결과로 결정적으로 판정할 수 없다. 제목 폭을 제어하고 여러 시점의 화면 프레임을 비교할 수 있는 시각 회귀 테스트 환경이 갖춰지면 자동화한다.
