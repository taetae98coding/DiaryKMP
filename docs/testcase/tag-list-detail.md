# Tag 목록·상세 배치 테스트 케이스

기준 스펙: [Tag 목록·상세 배치 스펙](../spec/client/tag-list-detail.md)

## feature

### TC-TAG-LIST-DETAIL-FEATURE-001: 목록과 상세를 함께 쓰는 환경에서는 두 영역을 함께 표시한다

- 근거: `feature > 상세 영역의 구성`
- Given: 목록과 상세를 함께 사용할 수 있는 환경이다.
- When: 사용자가 태그 주요 목적지에 진입한다.
- Then: 태그 목록을 유지한 채 상세 영역을 함께 사용할 수 있다.

### TC-TAG-LIST-DETAIL-FEATURE-002: 선택한 태그가 없으면 상세 영역에 태그 추가 화면이 표시된다

- 근거: `feature > 상세 영역의 구성`
- Given: 목록과 상세를 함께 사용하고 있고 선택한 태그가 없다.
- When: 사용자가 태그 주요 목적지에 진입한다.
- Then: 상세 영역이 새 태그 추가 상태로 표시된다.

### TC-TAG-LIST-DETAIL-FEATURE-003: 태그를 선택하면 상세 영역에 해당 태그의 상세 화면이 표시된다

- 근거: `feature > 상세 영역의 구성`
- Given: 목록과 상세를 함께 사용하고 있고 태그 목록에 태그가 있다.
- When: 사용자가 목록에서 태그 하나를 선택한다.
- Then: 상세 영역에 선택한 태그의 상세 화면이 표시된다.

### TC-TAG-LIST-DETAIL-FEATURE-004: 한 화면만 제공하는 환경에서는 현재 화면만 단독으로 표시한다

- 근거: `feature > 상세 영역의 구성`
- Given: 목록과 상세를 함께 사용할 수 없는 환경이다.
- When: 사용자가 태그 목록, 태그 추가 또는 태그 상세를 사용한다.
- Then: 현재 사용하는 화면만 단독으로 표시된다.

### TC-TAG-LIST-DETAIL-FEATURE-014: 목록과 상세를 함께 쓰는 중 새 태그 추가를 선택하면 추가 상태로 전환한다

- 근거: `feature > 상세 영역의 구성`
- Given: 목록과 상세 영역이 함께 표시되고 상세 영역에 태그 상세 화면이 표시되어 있다.
- When: 사용자가 새 태그 추가를 선택한다.
- Then: 목록은 유지되고 상세 영역이 태그 추가 상태로 바뀐다.

### TC-TAG-LIST-DETAIL-FEATURE-015: 태그 목록에서 진입하지 않은 상세 화면은 목록과 함께 표시하지 않는다

- 근거: `feature > 상세 영역의 구성`
- Given: 목록과 상세를 함께 사용할 수 있는 환경이다.
- When: 사용자가 태그 목록이 아닌 화면에서 테스트 데이터의 화면으로 이동한다.
- Then: 해당 화면을 목록·상세 배치에 참여시키지 않아 단독으로 표시한다.
- 테스트 데이터: 메모 태그 필터에서 진입한 태그 추가, 캘린더 태그 필터에서 진입한 태그 추가, 메모 태그 입력에서 진입한 태그 추가, 메모 태그 입력에서 진입한 태그 상세

### TC-TAG-LIST-DETAIL-FEATURE-016: 태그 목록에서 이어 진입한 상세 화면은 목록과 함께 표시한다

- 근거: `feature > 상세 영역의 구성`
- Given: 목록과 상세를 함께 사용할 수 있는 환경이다.
- When: 사용자가 태그 목록에서 테스트 데이터의 순서로 상세 영역의 화면을 연다.
- Then: 각 화면을 목록·상세 배치의 상세 영역에 표시한다.
- 테스트 데이터: 태그 추가, 태그 상세, 태그 추가에 이어 선택한 태그 상세

### TC-TAG-LIST-DETAIL-FEATURE-017: 목록에서 태그를 고르면 상세 영역에 쌓인 화면을 정리하고 뒤로가면 고르기 전으로 돌아간다

- 근거: `feature > 상세 영역의 구성`
- Given: 목록과 상세를 함께 사용하고 있고, 상세 영역에 테스트 데이터의 화면들이 차례로 놓여 있다.
- When: 사용자가 목록에서 태그 A를 선택한 뒤 태그 A의 상세에서 뒤로간다.
- Then: 태그 A를 선택하면 상세 영역에는 태그 A의 상세만 놓이고, 뒤로가면 태그 상세를 고르기 전 상태로 돌아간다.
- 테스트 데이터:

| 상세 영역에 놓인 화면 |
| --- |
| 태그 B의 상세 |
| 태그 B의 상세, 연결한 태그 C의 상세 |
| 태그 B의 상세, 연결 입력으로 연 태그 추가, 그 태그 추가에서 연 태그 C의 상세 |
| 태그 추가, 태그 B의 상세, 연결한 태그 C의 상세 |

### TC-TAG-LIST-DETAIL-FEATURE-018: 선택한 태그가 없을 때 태그 추가에서 연결한 태그를 누르면 그 태그를 선택한 것과 같다

- 근거: `feature > 상세 영역의 구성`
- Given: 목록과 상세를 함께 사용하고 있고 선택한 태그가 없어 상세 영역에 태그 추가가 놓여 있으며, 그 연결 입력에 태그 A가 선택되어 있다.
- When: 사용자가 연결 입력의 태그 A를 누른다.
- Then: 상세 영역이 태그 A의 상세로 바뀌고, 그 상세에는 뒤로가기 동작이 제공되지 않는다.

### TC-TAG-LIST-DETAIL-FEATURE-019: 태그 상세가 놓인 동안 목록에서 태그 추가를 실행하면 뒤로가기로 그 상세에 돌아온다

- 근거: `feature > 상세 영역의 구성`
- Given: 목록에서 태그 A를 선택해 태그 A의 상세가 놓여 있다.
- When: 사용자가 목록에서 태그 추가를 실행한 뒤 태그 추가에서 뒤로간다.
- Then: 태그 추가는 태그 A의 상세 위에 놓이고, 뒤로가면 태그 A의 상세로 돌아온다.

## domain

### TC-TAG-LIST-DETAIL-DOMAIN-001: 다른 주요 목적지에 다녀오면 상세 영역이 선택 전 상태로 돌아간다

- 근거: `domain > 유지와 초기화 기준`
- Given: 목록과 상세를 함께 사용하고 있고 상세 영역에 테스트 데이터의 화면이 놓여 있다.
- When: 사용자가 공통 내비게이션에서 다른 주요 목적지로 이동했다가 태그를 다시 선택한다.
- Then: 태그 목록만 열린 상태로 돌아와 상세 영역에는 선택 전 화면인 태그 추가가 놓이고, 떠나기 전에 놓였던 화면은 남아 있지 않아 뒤로가면 `캘린더`로 돌아간다.
- 테스트 데이터:

| 상세 영역에 놓인 화면 | 다녀온 주요 목적지 |
| --- | --- |
| 태그 A의 상세 | `메모`, `캘린더`, `루틴`, `더보기` |
| 태그 A의 상세, 연결한 태그 B의 상세 | `메모`, `캘린더`, `루틴`, `더보기` |
| 태그 A의 상세 위에 목록에서 연 태그 추가 | `메모`, `캘린더`, `루틴`, `더보기` |

### TC-TAG-LIST-DETAIL-DOMAIN-002: 다른 주요 목적지에 다녀오면 상세 영역의 태그 추가는 입력과 연결이 모두 비어 있는 상태로 시작한다

- 근거: `domain > 유지와 초기화 기준`
- Given: 목록과 상세를 함께 사용하고 있고 선택한 태그가 없어 상세 영역에 태그 추가가 놓여 있다. 사용자가 태그 추가에 제목과 설명을 입력하고 연결할 태그 하나를 골랐다.
- When: 사용자가 공통 내비게이션에서 다른 주요 목적지로 이동했다가 태그를 다시 선택한다.
- Then: 상세 영역의 태그 추가는 제목과 설명이 비어 있고, 앞서 고른 연결이 하나도 남아 있지 않다.

### TC-TAG-LIST-DETAIL-DOMAIN-003: 배치를 떠나기 전에는 상세 영역에서 다른 화면에 다녀와도 태그 추가의 입력과 연결이 남는다

- 근거: `domain > 유지와 초기화 기준`
- Given: 목록과 상세를 함께 사용하고 있고 선택한 태그가 없어 상세 영역에 태그 추가가 놓여 있다. 사용자가 태그 추가에 제목과 설명을 입력하고 연결할 태그 하나를 골랐다.
- When: 사용자가 테스트 데이터의 화면으로 이동했다가 뒤로가기를 사용해 상세 영역의 태그 추가로 돌아온다.
- Then: 태그 추가에 입력하던 제목과 설명, 고른 연결이 그대로 남아 있다.
- 테스트 데이터: 목록에서 고른 태그 상세, 연결 입력으로 연 태그 추가

## 작성하지 않는 이유

두 영역의 표시 비율 조절과 조절 중 즉시 반영, 화면 재생성 후 비율 유지, 다른 주요 목적지에 다녀온 뒤와 앱 재실행 후 기본 비율 초기화는 실제 화면 크기와 실행 경계를 함께 판정해야 한다. 현재 테스트 환경에서는 결정적으로 자동화할 수 없으며, 화면 크기와 실행 경계를 제어·관찰할 수 있는 통합 UI 테스트 환경이 갖춰지면 자동화한다.
