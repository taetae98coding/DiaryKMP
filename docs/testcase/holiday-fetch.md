# 공휴일 동기화 테스트 케이스

기준 스펙: [공휴일 동기화 스펙](../spec/client/holiday-fetch.md)

오류 보고가 남는 방식 자체의 케이스는 [기능 실패 로깅 테스트 케이스](./usecase-failure-logging.md)에서 다룬다. 이 문서에서는 공휴일 동기화가 오류 보고 대상인지를 다룬다.

국가를 따로 적지 않은 케이스는 적용 국가가 한국 하나인 상태를 전제로 한다.

## domain

### TC-358d29f3-29e8-4f44-a03a-a5cfed370247: 동기화가 실패하면 실패 원인을 담은 오류 보고가 남는다

- 근거: `domain > 동기화 실패 보고`
- Given: 오류 보고 기록 수단이 등록되어 있고, 특정 연도의 공휴일 동기화가 특정 원인으로 실패하도록 준비되어 있다.
- When: 해당 연도의 공휴일 동기화를 요청한다.
- Then: 그 원인을 담은 오류 보고가 한 번 남고, 보고 메시지로 공휴일 동기화 실패임을 구분할 수 있다.

### TC-75aeb7c0-ad3a-4462-a042-81c9e9193458: 동기화가 성공하면 오류 보고가 남지 않는다

- 근거: `domain > 동기화 실패 보고`
- Given: 오류 보고 기록 수단이 등록되어 있고, 특정 연도의 공휴일 동기화가 성공하도록 준비되어 있다.
- When: 해당 연도의 공휴일 동기화를 요청한다.
- Then: 오류 보고가 남지 않는다.

### TC-4f57f965-fec8-4b60-97bc-aee44f273779: 공휴일을 제공하지 않는 연도도 성공으로 끝나고 오류 보고가 남지 않는다

- 근거: `domain > 동기화 실패 보고`, `domain > 공휴일을 제공하지 않는 연도`
- Given: 오류 보고 기록 수단이 등록되어 있고, 원격이 특정 연도의 공휴일을 제공하지 않도록 준비되어 있다.
- When: 해당 연도의 공휴일 동기화를 요청한다.
- Then: 동기화가 빈 공휴일 목록으로 성공하고 오류 보고는 남지 않는다.

### TC-b603a6c2-7ad9-4b9a-9da3-2ddac4f826ca: 받아오지 못한 결과와 제공하지 않는 결과를 구분해 알린다

- 근거: `domain > 공휴일을 제공하지 않는 연도`, `domain > 연도별 동기화`
- Given: 특정 연도의 원격 조회 결과가 테스트 데이터의 상태로 준비되어 있다.
- When: 해당 연도의 공휴일 동기화를 요청한다.
- Then: 동기화 결과로 공휴일을 제공하지 않는 연도인지 받아오지 못한 실패인지 구분할 수 있다.
- 테스트 데이터:

  | 원격 조회 결과 | 동기화 결과 |
  | --- | --- |
  | 원격 조회 실패 | 받아오지 못한 실패 |
  | 해당 연도 자료 없음 | 빈 공휴일 목록으로 성공 |
  | 빈 공휴일 목록 | 빈 공휴일 목록으로 성공 |

### TC-0b6eebe0-d03a-4889-b452-16e840d37ef6: 동기화가 성공하면 그 연도의 최신 공휴일을 결과로 알린다

- 근거: `domain > 연도별 동기화`, `data > 원격 공휴일 저장`
- Given: 특정 연도의 원격 조회가 공휴일이 있는 목록으로 성공하도록 준비되어 있다.
- When: 해당 연도의 공휴일 동기화를 요청한다.
- Then: 동기화 결과에 원격에서 받은 공휴일이 그대로 담겨 성공으로 끝난다.

### TC-45e9e289-bbf3-4520-bd05-99d9d0bd2030: 적용 국가가 둘이면 두 국가의 공휴일을 합쳐 결과로 알린다

- 근거: `domain > 연도별 동기화`
- Given: 적용 국가가 한국과 미국이고, 특정 연도의 두 국가 원격 조회가 각각 공휴일이 있는 목록으로 성공하도록 준비되어 있다.
- When: 해당 연도의 공휴일 동기화를 요청한다.
- Then: 동기화가 성공하고 결과에 두 국가의 공휴일이 모두 담긴다.

### TC-9e6ad71e-78b3-4790-ae5f-65c5202e004d: 적용 국가가 비어 있으면 원격 조회 없이 빈 결과로 성공한다

- 근거: `domain > 연도별 동기화`
- Given: 적용 국가가 없다.
- When: 특정 연도의 공휴일 동기화를 요청한다.
- Then: 원격 조회가 수행되지 않고 동기화가 빈 공휴일 목록으로 성공한다.

### TC-7182d3ff-07ce-496b-aa7d-3030eb9ad9e6: 한 국가가 실패해도 다른 국가는 동기화하고 연도 동기화는 실패한다

- 근거: `domain > 연도별 동기화`
- Given: 적용 국가가 한국과 미국이고, 특정 연도의 한국 원격 조회는 실패하고 미국 원격 조회는 성공하도록 준비되어 있다.
- When: 해당 연도의 공휴일 동기화를 요청한다.
- Then: 동기화는 실패하고, 미국의 해당 연도에 저장된 공휴일은 원격 공휴일로 교체된다.

### TC-edbe175e-0d29-4bcd-a7be-20a72a8a4d7f: 국가 설정을 읽지 못하면 원격 조회 없이 실패한다

- 근거: `data > 실패 처리`
- Given: 저장된 국가 설정을 읽을 수 없다.
- When: 특정 연도의 공휴일 동기화를 요청한다.
- Then: 원격 조회가 수행되지 않고 동기화가 실패한다.

## data

### TC-596be503-c5c1-4e43-833c-3b2b695cc42a: 원격 공휴일로 요청한 연도의 저장된 공휴일을 교체한다

- 근거: `data > 원격 공휴일 저장`
- Given: 서로 다른 두 연도의 공휴일이 기기에 저장되어 있고, 요청할 연도의 원격 공휴일 목록이 준비되어 있다.
- When: 해당 연도의 공휴일 동기화를 요청한다.
- Then: 요청한 연도에 저장된 공휴일은 원격 공휴일 전체로 교체되고, 다른 연도에 저장된 공휴일은 유지된다.

### TC-60c83dda-3b12-42e2-99a9-218819e7bc94: 원격이 공휴일을 제공하지 않으면 요청한 연도의 저장된 공휴일을 지운다

- 근거: `data > 원격 공휴일 저장`, `domain > 공휴일을 제공하지 않는 연도`
- Given: 특정 연도의 공휴일이 기기에 저장되어 있고, 해당 연도의 원격 조회 결과가 테스트 데이터의 상태다.
- When: 해당 연도의 공휴일 동기화를 요청한다.
- Then: 해당 연도에 저장된 공휴일은 비어 있고, 동기화는 빈 공휴일 목록을 결과로 성공한다.
- 테스트 데이터:

  | 원격 조회 결과 |
  | --- |
  | 해당 연도 자료 없음 |
  | 빈 공휴일 목록 |

### TC-fbbbe2cd-e57a-48ec-9679-fce9280196a8: 원격 조회가 실패하면 기존에 저장된 공휴일을 유지한다

- 근거: `data > 실패 처리`
- Given: 특정 연도의 공휴일이 기기에 저장되어 있고, 해당 연도의 원격 조회가 실패하도록 준비되어 있다.
- When: 해당 연도의 공휴일 동기화를 요청한다.
- Then: 동기화가 실패하고 해당 연도의 기존에 저장된 공휴일은 유지된다.

### TC-9a6535b9-36fd-4fc3-9b63-3aa541fe2e08: 기기 저장이 실패하면 동기화가 실패로 끝난다

- 근거: `data > 실패 처리`
- Given: 특정 연도의 공휴일 원격 조회는 성공하지만 기기 저장이 실패하도록 준비되어 있다.
- When: 해당 연도의 공휴일 동기화를 요청한다.
- Then: 동기화가 실패로 끝난다.

### TC-6e944960-6e21-4bb6-a0b6-ad8c1b8c8bcb: 이미 동기화에 성공한 연도는 다시 원격 조회하지 않는다

- 근거: `data > 성공한 국가·연도 재조회 생략`
- Given: 특정 연도의 공휴일 동기화가 이미 성공한 상태다.
- When: 같은 연도의 공휴일 동기화를 다시 요청한다.
- Then: 동기화가 성공하고, 해당 연도의 원격 조회는 처음 한 번만 수행되며 저장된 공휴일도 다시 교체되지 않는다.

### TC-944f146e-ab41-4e58-854e-d864d70267da: 동기화에 실패한 연도는 다시 요청하면 다시 원격 조회한다

- 근거: `data > 실패 처리`
- Given: 특정 연도의 첫 동기화 요청이 실패한 상태이고, 같은 연도의 원격 조회가 이후에는 성공하도록 준비되어 있다.
- When: 같은 연도의 공휴일 동기화를 다시 요청한다.
- Then: 해당 연도의 원격 조회가 다시 수행되고 동기화가 성공하며, 받은 공휴일 전체로 해당 연도에 저장된 공휴일이 교체된다.
- 테스트 데이터

  | 첫 요청의 실패 지점 |
  | --- |
  | 원격 조회 실패 |
  | 기기 저장 실패 |

### TC-0f3cd63d-cdca-4c37-b0bf-8db797ea540c: 한 연도의 동기화 이력은 다른 연도의 동기화를 막지 않는다

- 근거: `domain > 동기화 이력`
- Given: 특정 연도의 공휴일 동기화가 이미 성공한 상태다.
- When: 다른 연도의 공휴일 동기화를 요청한다.
- Then: 요청한 다른 연도의 원격 조회가 수행되고 해당 연도에 저장된 공휴일이 교체된다.

### TC-228f1b11-042c-4817-bac9-89bda80056fa: 공휴일을 제공하지 않은 연도도 다시 요청하면 원격 조회를 생략한다

- 근거: `domain > 동기화 이력`, `data > 성공한 국가·연도 재조회 생략`
- Given: 특정 연도의 첫 동기화 요청에서 원격이 공휴일을 제공하지 않아 그 연도에 저장된 공휴일이 비어 있다.
- When: 같은 연도의 공휴일 동기화를 다시 요청한다.
- Then: 해당 연도의 원격 조회는 처음 한 번만 수행되고, 동기화는 빈 공휴일 목록을 결과로 성공한다.

### TC-9020b622-07c7-43c0-a4e5-b86767c3a41a: 재조회를 생략한 연도는 기기에 저장된 공휴일을 결과로 알린다

- 근거: `data > 성공한 국가·연도 재조회 생략`
- Given: 특정 연도의 공휴일 동기화가 이미 성공해 그 연도의 공휴일이 기기에 저장되어 있다.
- When: 같은 연도의 공휴일 동기화를 다시 요청한다.
- Then: 원격 조회 없이 기기에 저장된 그 연도의 공휴일이 동기화 결과로 나온다.

### TC-c7ebdd34-cba3-4362-8c4b-3e4b55960d5a: 요청한 국가와 연도의 공휴일을 원격에 요청한다

- 근거: `data > 원격 제공처`, `data > 원격 공휴일 저장`
- Given: 동기화 이력이 비어 있다.
- When: 테스트 데이터의 국가와 연도로 공휴일 동기화를 요청한다.
- Then: 원격에 그 국가와 연도의 공휴일을 요청한다.
- 테스트 데이터:

  | 국가 | 연도 |
  | --- | --- |
  | 한국 | 2026 |
  | 미국 | 2027 |

### TC-a5369c65-33ef-4a70-89cf-d04dfccafa8c: 한 국가를 교체해도 같은 연도의 다른 국가 공휴일은 유지한다

- 근거: `data > 원격 공휴일 저장`
- Given: 같은 연도의 한국과 미국 공휴일이 기기에 저장되어 있고, 한국의 해당 연도 원격 공휴일 목록이 준비되어 있다.
- When: 한국의 해당 연도 공휴일 동기화를 요청한다.
- Then: 한국의 해당 연도에 저장된 공휴일은 원격 공휴일로 교체되고, 미국의 해당 연도에 저장된 공휴일은 유지된다.

### TC-d94f0abd-05e0-4c3c-859c-3e31a0af14d3: 한 국가의 동기화 이력은 같은 연도의 다른 국가 동기화를 막지 않는다

- 근거: `domain > 동기화 이력`

- When: 미국의 같은 연도 공휴일 동기화를 요청한다.
- Then: 미국의 해당 연도 원격 조회가 수행되고 미국의 해당 연도에 저장된 공휴일이 교체된다.

### TC-5bcf3e88-0091-49ed-a823-f72e9cb68b74: 한 국가가 실패한 연도를 다시 요청하면 실패한 국가만 다시 원격 조회한다

- 근거: `domain > 연도별 동기화`, `domain > 동기화 이력`
- Given: 적용 국가가 한국과 미국이고, 특정 연도의 첫 동기화에서 한국 원격 조회는 실패하고 미국 원격 조회는 성공했으며, 이후 한국 원격 조회는 성공하도록 준비되어 있다.
- When: 같은 연도의 공휴일 동기화를 다시 요청한다.

### TC-41421bc4-3c43-483f-9ae3-cf4d82d6c1bd: 앱을 다시 실행하면 동기화 이력이 비워진다

- 근거: `domain > 동기화 이력`
- Given: 특정 연도의 공휴일 동기화가 성공한 뒤 앱이 종료되었다.
- When: 앱을 다시 실행하고 같은 연도의 공휴일 동기화를 요청한다.
- Then: 해당 연도의 원격 조회가 다시 수행된다.

### TC-787ea215-93a2-4089-a694-d589db59f972: 앱을 업데이트하면 이전 제공처에서 받아 둔 공휴일을 쓰지 않고 새 제공처에서 다시 받는다

- 근거: `data > 원격 제공처`
- Given: 이전 버전의 앱이 이전 제공처에서 받아 둔 공휴일이 기기에 있고, 새 제공처가 같은 국가·연도의 공휴일을 돌려주도록 제어되어 있다.
