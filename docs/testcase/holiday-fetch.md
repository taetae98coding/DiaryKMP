# 공휴일 동기화 테스트 케이스

기준 스펙: [공휴일 동기화 스펙](../spec/holiday-fetch.md)

오류 보고가 남는 방식 자체의 케이스는 [UseCase 실패 로깅 테스트 케이스](./usecase-failure-logging.md)에서 다룬다. 이 문서에서는 공휴일 동기화가 오류 보고 대상인지를 다룬다.

## domain

### TC-HOLIDAY-FETCH-DOMAIN-001: 동기화가 실패하면 실패 원인을 담은 오류 보고가 남는다

- 근거: `domain > 동기화 실패 보고`
- Given: 오류 보고 기록 수단이 등록되어 있고, 특정 연도의 공휴일 동기화가 특정 원인으로 실패하도록 준비되어 있다.
- When: 해당 연도의 공휴일 동기화를 요청한다.
- Then: 그 원인을 담은 오류 보고가 한 번 남고, 보고 메시지로 공휴일 동기화 실패임을 구분할 수 있다.

### TC-HOLIDAY-FETCH-DOMAIN-002: 동기화가 성공하면 오류 보고가 남지 않는다

- 근거: `domain > 동기화 실패 보고`
- Given: 오류 보고 기록 수단이 등록되어 있고, 특정 연도의 공휴일 동기화가 성공하도록 준비되어 있다.
- When: 해당 연도의 공휴일 동기화를 요청한다.
- Then: 오류 보고가 남지 않는다.

### TC-HOLIDAY-FETCH-DOMAIN-003: 공휴일을 제공하지 않는 연도도 성공으로 끝나고 오류 보고가 남지 않는다

- 근거: `domain > 동기화 실패 보고`, `domain > 공휴일을 제공하지 않는 연도`
- Given: 오류 보고 기록 수단이 등록되어 있고, 원격이 특정 연도의 공휴일을 제공하지 않도록 준비되어 있다.
- When: 해당 연도의 공휴일 동기화를 요청한다.
- Then: 동기화가 빈 공휴일 목록으로 성공하고 오류 보고는 남지 않는다.

### TC-HOLIDAY-FETCH-DOMAIN-004: 받아오지 못한 결과와 제공하지 않는 결과를 구분해 알린다

- 근거: `domain > 공휴일을 제공하지 않는 연도`, `domain > 연도별 동기화`
- Given: 특정 연도의 원격 조회 결과가 테스트 데이터의 상태로 준비되어 있다.
- When: 해당 연도의 공휴일 동기화를 요청한다.
- Then: 동기화 결과로 공휴일을 제공하지 않는 연도인지 받아오지 못한 실패인지 구분할 수 있다.
- 테스트 데이터:

  | 원격 조회 결과 | 동기화 결과 |
  | --- | --- |
  | 원격 조회 실패 | 받아오지 못한 실패 |
  | 해당 연도 자료 없음 | 빈 공휴일 목록으로 성공 |
  | 빈 공휴일 목록 | 빈 공휴일 목록으로 성공 |

### TC-HOLIDAY-FETCH-DOMAIN-005: 동기화가 성공하면 그 연도의 최신 공휴일을 결과로 알린다

- 근거: `domain > 연도별 동기화`, `data > 원격 공휴일 저장`
- Given: 특정 연도의 원격 조회가 공휴일이 있는 목록으로 성공하도록 준비되어 있다.
- When: 해당 연도의 공휴일 동기화를 요청한다.
- Then: 동기화 결과에 원격에서 받은 공휴일이 그대로 담겨 성공으로 끝난다.

## data

### TC-HOLIDAY-FETCH-DATA-001: 원격 공휴일로 요청한 연도의 캐시를 교체한다

- 근거: `data > 원격 공휴일 저장`
- Given: 서로 다른 두 연도의 공휴일이 로컬에 저장되어 있고, 요청할 연도의 원격 공휴일 목록이 준비되어 있다.
- When: 해당 연도의 공휴일 동기화를 요청한다.
- Then: 요청한 연도의 로컬 캐시는 원격 공휴일 전체로 교체되고, 다른 연도의 로컬 캐시는 유지된다.

### TC-HOLIDAY-FETCH-DATA-002: 원격이 공휴일을 제공하지 않으면 요청한 연도의 캐시를 제거한다

- 근거: `data > 원격 공휴일 저장`, `domain > 공휴일을 제공하지 않는 연도`
- Given: 특정 연도의 공휴일이 로컬에 저장되어 있고, 해당 연도의 원격 조회 결과가 테스트 데이터의 상태다.
- When: 해당 연도의 공휴일 동기화를 요청한다.
- Then: 해당 연도의 로컬 캐시는 비어 있고, 동기화는 빈 공휴일 목록을 결과로 성공한다.
- 테스트 데이터:

  | 원격 조회 결과 |
  | --- |
  | 해당 연도 자료 없음 |
  | 빈 공휴일 목록 |

### TC-HOLIDAY-FETCH-DATA-003: 원격 조회가 실패하면 기존 캐시를 유지한다

- 근거: `data > 실패 처리`
- Given: 특정 연도의 공휴일이 로컬에 저장되어 있고, 해당 연도의 원격 조회가 실패하도록 준비되어 있다.
- When: 해당 연도의 공휴일 동기화를 요청한다.
- Then: 동기화가 실패하고 해당 연도의 기존 로컬 캐시는 유지된다.

### TC-HOLIDAY-FETCH-DATA-004: 로컬 캐시 교체가 실패하면 기존 캐시를 유지한다

- 근거: `data > 실패 처리`
- Given: 특정 연도의 공휴일이 로컬에 저장되어 있고, 원격 조회는 성공하지만 로컬 캐시 교체가 실패하도록 준비되어 있다.
- When: 해당 연도의 공휴일 동기화를 요청한다.
- Then: 동기화가 실패하고 해당 연도의 기존 로컬 캐시는 유지된다.

### TC-HOLIDAY-FETCH-DATA-005: 이미 동기화에 성공한 연도는 다시 원격 조회하지 않는다

- 근거: `data > 성공한 연도 재조회 생략`
- Given: 특정 연도의 공휴일 동기화가 이미 성공한 상태다.
- When: 같은 연도의 공휴일 동기화를 다시 요청한다.
- Then: 동기화가 성공하고, 해당 연도의 원격 조회는 처음 한 번만 수행되며 로컬 캐시도 다시 교체되지 않는다.

### TC-HOLIDAY-FETCH-DATA-006: 동기화에 실패한 연도는 다시 요청하면 다시 원격 조회한다

- 근거: `data > 실패 처리`
- Given: 특정 연도의 첫 동기화 요청이 실패한 상태이고, 같은 연도의 원격 조회가 이후에는 성공하도록 준비되어 있다.
- When: 같은 연도의 공휴일 동기화를 다시 요청한다.
- Then: 해당 연도의 원격 조회가 다시 수행되고 동기화가 성공하며, 받은 공휴일 전체로 해당 연도의 로컬 캐시가 교체된다.
- 테스트 데이터

  | 첫 요청의 실패 지점 |
  | --- |
  | 원격 조회 실패 |
  | 로컬 캐시 교체 실패 |

### TC-HOLIDAY-FETCH-DATA-007: 한 연도의 동기화 이력은 다른 연도의 동기화를 막지 않는다

- 근거: `domain > 동기화 이력`
- Given: 특정 연도의 공휴일 동기화가 이미 성공한 상태다.
- When: 다른 연도의 공휴일 동기화를 요청한다.
- Then: 요청한 다른 연도의 원격 조회가 수행되고 해당 연도의 로컬 캐시가 교체된다.

### TC-HOLIDAY-FETCH-DATA-009: 공휴일을 제공하지 않은 연도도 다시 요청하면 원격 조회를 생략한다

- 근거: `domain > 동기화 이력`, `data > 성공한 연도 재조회 생략`
- Given: 특정 연도의 첫 동기화 요청에서 원격이 공휴일을 제공하지 않아 그 연도의 로컬 캐시가 비어 있다.
- When: 같은 연도의 공휴일 동기화를 다시 요청한다.
- Then: 해당 연도의 원격 조회는 처음 한 번만 수행되고, 동기화는 빈 공휴일 목록을 결과로 성공한다.

### TC-HOLIDAY-FETCH-DATA-010: 재조회를 생략한 연도는 로컬 캐시에 저장된 공휴일을 결과로 알린다

- 근거: `data > 성공한 연도 재조회 생략`
- Given: 특정 연도의 공휴일 동기화가 이미 성공해 그 연도의 공휴일이 로컬에 저장되어 있다.
- When: 같은 연도의 공휴일 동기화를 다시 요청한다.
- Then: 원격 조회 없이 로컬에 저장된 그 연도의 공휴일이 동기화 결과로 나온다.

### TC-HOLIDAY-FETCH-DATA-008: 앱을 다시 실행하면 동기화 이력이 비워진다

- 근거: `domain > 동기화 이력`
- Given: 특정 연도의 공휴일 동기화가 성공한 뒤 앱이 종료되었다.
- When: 앱을 다시 실행하고 같은 연도의 공휴일 동기화를 요청한다.
- Then: 해당 연도의 원격 조회가 다시 수행된다.
- 작성하지 않는 이유: 앱 프로세스를 실제로 종료하고 다시 실행해야 확인할 수 있어 유닛 테스트 범위에서 결정적으로 자동화할 수 없다. 앱 실행 경계를 제어할 수 있는 테스트 환경이 준비되면 자동화한다.
