# 앱 안 웹 로그인 유지 테스트 케이스

기준 스펙: [앱 안 웹 로그인 유지 스펙](../spec/client/web-login-persistence.md)

되돌리는 동안 WebDetail이 웹 페이지 자리에 무엇을 보여 주는지의 케이스는 [WebDetail 테스트 케이스](./web-detail.md)에서, 기능 실패를 로그로 남기는 공통 케이스는 [기능 실패 로깅 테스트 케이스](./usecase-failure-logging.md)에서 다룬다.

## domain

### TC-908e16b2-fd82-4d9d-83b8-9d6431d795a4: 앱이 활성 상태에서 벗어나면 지금의 세션 쿠키를 보관한다

- 근거: `domain > 보관과 되돌리기 계기`, `data > 보관하는 정보`
- Given: iOS나 데스크톱 앱(macOS)에서 웹 표시 수단에 세션 쿠키 하나와 만료 시각이 있는 쿠키 하나가 있다.
- When: 앱이 활성 상태에서 벗어난다.
- Then: 세션 쿠키 하나만 이름, 값, 사이트, 경로, 보안 연결 전용 여부, 스크립트 접근 금지 여부, 사이트 간 전송 정책과 함께 보관되고, 만료 시각이 있는 쿠키는 보관되지 않는다.

### TC-f2f9cbff-6f3d-47fe-a8cd-e5e8a527031e: 앱이 활성 상태에서 벗어나면 웹 표시 수단의 로그인 정보를 기기에 바로 기록한다

- 근거: `domain > 보관과 되돌리기 계기`
- Given: 테스트 데이터의 플랫폼에서 앱이 활성 상태다.
- When: 앱이 활성 상태에서 벗어난다.
- Then: 웹 표시 수단에 로그인 정보를 기기에 바로 기록하도록 한 번 요청한다.
- 테스트 데이터:

| 플랫폼 |
| --- |
| Android |
| iOS |
| 데스크톱 앱(macOS) |

### TC-37352d53-356e-4e1e-9dc8-fdba8a414ecd: 앱이 종료되면 지금의 세션 쿠키를 보관한다

- 근거: `domain > 보관과 되돌리기 계기`
- Given: 데스크톱 앱(macOS)에서 웹 표시 수단에 세션 쿠키가 있다.
- When: 앱이 종료된다.
- Then: 그 세션 쿠키가 보관된다.

### TC-f5c2e8ed-f73a-45ee-93a8-359a500b39ef: 되돌리는 동안 보관할 계기가 오면 되돌리기가 끝난 뒤에 보관한다

- 근거: `domain > 보관과 되돌리기 계기`
- Given: 세션 쿠키가 보관되어 있고, 앱을 시작해 로그인 정보를 되돌리는 중이다.
- When: 되돌리기가 끝나기 전에 앱이 활성 상태에서 벗어나거나 종료되어 보관할 계기가 오고, 그 뒤 되돌리기가 끝난다.
- Then: 되돌리기가 끝나기 전에는 지금의 세션 쿠키를 읽거나 보관하지 않고, 끝난 뒤에 한 번 보관한다.

### TC-353204d8-2c5e-4805-93a5-d7dd0289d27b: 보관이 진행 중일 때 다시 벗어나면 진행 중인 보관 하나로 합친다

- 근거: `domain > 보관과 되돌리기 계기`
- Given: 앱이 활성 상태에서 벗어나 보관을 기다리거나 보관하는 중이다.
- When: 그 보관이 끝나기 전에 앱이 다시 활성 상태에서 벗어나고, 그 뒤 보관이 끝난다.
- Then: 보관은 한 번만 일어난다.

### TC-e6141c76-3fcc-4ccb-a23b-84439d5f9f35: 보관이 끝난 뒤 다시 벗어나면 다시 보관한다

- 근거: `domain > 보관과 되돌리기 계기`
- Given: 앱이 활성 상태에서 벗어나 보관이 끝났다.
- When: 앱이 다시 활성 상태에서 벗어난다.
- Then: 보관이 한 번 더 일어나 모두 두 번 보관한다.

### TC-d8af2d99-95b6-42e6-b4c4-a221586c9350: 보관할 때 이전에 보관해 둔 세션 쿠키를 모두 바꾼다

- 근거: `domain > 보관과 되돌리기 계기`
- Given: 세션 쿠키 A와 B가 보관되어 있고, 웹 표시 수단에는 지금 세션 쿠키 B와 C만 있다.
- When: 앱이 활성 상태에서 벗어나 다시 보관한다.
- Then: 보관된 세션 쿠키는 B와 C뿐이고 A는 남지 않는다.

### TC-8deae54a-4c48-42e5-ae00-37a42552acb5: 앱을 시작하면 보관해 둔 세션 쿠키를 웹 표시 수단에 되돌린다

- 근거: `domain > 보관과 되돌리기 계기`, `data > 보관하는 정보`
- Given: iOS나 데스크톱 앱(macOS)에서 세션 쿠키 하나가 이름, 값, 사이트, 경로, 보안 연결 전용 여부, 스크립트 접근 금지 여부, 사이트 간 전송 정책과 함께 보관되어 있다.
- When: 앱을 시작한다.
- Then: 웹 표시 수단에 그 세션 쿠키가 보관한 모든 정보 그대로 한 번 넣어진다.

### TC-a8c81333-f7af-4735-86ec-9a6a1a6e8c6d: 되돌릴 때 같은 쿠키가 이미 있으면 보관해 둔 값으로 바꾼다

- 근거: `domain > 보관과 되돌리기 계기`
- Given: 세션 쿠키 하나가 값 `saved`로 보관되어 있고, 웹 표시 수단에는 이름, 사이트, 경로가 같은 쿠키가 값 `old`로 있다.
- When: 앱을 시작한다.
- Then: 웹 표시 수단에서 그 쿠키의 값은 `saved`가 되고, 같은 이름, 사이트, 경로의 쿠키는 하나만 남는다.

### TC-6054d52b-e3a5-4e4f-beb3-856bf404688b: 되돌리기가 끝나기 전에는 되돌리는 중이고 끝나면 되돌리는 중이 아니다

- 근거: `domain > 되돌리는 동안`
- Given: 세션 쿠키가 보관되어 있고, 웹 표시 수단에 넣는 일이 끝나지 않도록 제어되어 있다.
- When: 앱을 시작하고, 그 뒤 넣는 일이 테스트 데이터의 결과로 끝난다.
- Then: 넣는 일이 끝나기 전에는 로그인 정보를 되돌리는 중이고, 끝난 뒤에는 되돌리는 중이 아니다.
- 테스트 데이터:

| 넣는 일의 결과 |
| --- |
| 성공 |
| 실패 |

### TC-44b89df3-9791-4f8f-8de6-048c4714a94a: 보관해 둔 세션 쿠키가 없으면 확인하는 대로 되돌리기가 끝난다

- 근거: `domain > 되돌리는 동안`
- Given: 보관된 세션 쿠키가 하나도 없다.
- When: 앱을 시작한다.
- Then: 보관된 세션 쿠키가 없음을 확인하는 대로 되돌리는 중이 끝나고, 웹 표시 수단에 쿠키를 넣지 않는다.

### TC-8586786d-e10a-4b27-a3f9-019d7104bd3c: 웹에서는 보관하거나 되돌리지 않는다

- 근거: `domain > 플랫폼별 유지 범위`
- Given: 웹에서 앱이 실행 중이다.
- When: 앱이 활성 상태에서 벗어난 뒤 앱을 다시 시작한다.
- Then: 세션 쿠키를 보관하지 않고 되돌리지도 않는다.
- 작성하지 않는 이유: 웹 플랫폼의 동작은 브라우저에서 실행해야 확인할 수 있는데, 저장소의 테스트는 브라우저에서 실행되지 않는다. 브라우저에서 실행하는 테스트 환경이 제공되면 작성한다.

### TC-4f4af7a4-f3ec-45bc-9a06-36ba0812e50d: Android에서는 웹 표시 수단이 직접 연 페이지의 주소에 해당하는 세션 쿠키만 보관한다

- 근거: `domain > 플랫폼별 유지 범위`, `data > 보관하는 정보`
- Given: Android에서 웹 표시 수단이 `https://a.example/page`를 직접 열었고, 웹 표시 수단에는 `a.example`의 세션 쿠키와 직접 연 적이 없는 `b.example`의 세션 쿠키가 있다. 기기의 웹 표시 수단은 세션 쿠키를 확인하는 기능을 제공한다.
- When: 앱이 활성 상태에서 벗어난다.
- Then: `a.example`의 세션 쿠키만 보관되고, 세션 쿠키가 있는 사이트의 주소로 `https://a.example/page`가 함께 보관된다.

### TC-5c2c51e7-49c1-4fd7-9f84-77c0426380ed: Android에서는 이전에 보관한 사이트의 주소에서도 세션 쿠키를 확인한다

- 근거: `domain > 플랫폼별 유지 범위`, `data > 보관하는 정보`
- Given: Android에서 사이트 주소 `https://a.example/page`와 그 사이트의 세션 쿠키가 보관되어 있고, 앱을 시작한 뒤 웹 표시 수단은 그 주소를 다시 열지 않았다. 웹 표시 수단에는 되돌린 `a.example`의 세션 쿠키가 그대로 있다.
- When: 앱이 활성 상태에서 벗어난다.
- Then: `a.example`의 세션 쿠키와 사이트 주소가 다시 보관된다.

### TC-e5c05f67-9b54-471d-9500-4976ff8cb13e: Android에서 세션 쿠키가 남지 않은 사이트의 주소는 보관하지 않는다

- 근거: `data > 보관하는 정보`
- Given: Android에서 웹 표시 수단이 `https://a.example/page`를 직접 열었지만 그 주소에 해당하는 세션 쿠키가 하나도 없다.
- When: 앱이 활성 상태에서 벗어난다.
- Then: `https://a.example/page`는 사이트 주소로 보관되지 않는다.

### TC-5af3c19f-698d-4340-bade-b68e163a5da9: Android에서 세션 쿠키를 확인하는 기능이 없으면 보관하지 않는다

- 근거: `domain > 플랫폼별 유지 범위`
- Given: Android에서 웹 표시 수단이 주소를 직접 열었고, 기기의 웹 표시 수단은 세션 쿠키를 확인하는 기능을 제공하지 않는다.
- When: 앱이 활성 상태에서 벗어난다.
- Then: 세션 쿠키를 보관하지 않고 실패로도 다루지 않으며, 웹 표시 수단에 로그인 정보를 기기에 바로 기록하도록 하는 요청은 그대로 한 번 일어난다.

### TC-31ff2113-2f58-4cb0-b0c3-3d0e4ed631ba: 보관에 실패하면 이전에 보관해 둔 세션 쿠키를 그대로 두고 알리지 않는다

- 근거: `domain > 실패`
- Given: 세션 쿠키 A가 보관되어 있고, 이번 보관이 테스트 데이터의 단계에서 실패하도록 제어되어 있다.
- When: 앱이 활성 상태에서 벗어난다.
- Then: 보관된 세션 쿠키는 A 그대로이고, 사용자에게 보이는 안내가 없으며, 보관 실패가 기능 실패로 한 번 기록된다.
- 테스트 데이터:

| 실패하는 단계 |
| --- |
| 웹 표시 수단에서 세션 쿠키를 읽음 |
| 앱 저장 영역에 씀 |

### TC-9ffe581d-39f9-4181-9ad3-b1e6aca53a53: 보관한 세션 쿠키를 읽지 못하면 되돌리지 않고 알리지 않는다

- 근거: `domain > 실패`
- Given: 앱 저장 영역에서 보관한 세션 쿠키를 읽지 못하도록 제어되어 있다.
- When: 앱을 시작한다.
- Then: 웹 표시 수단에 쿠키를 넣지 않고 되돌리는 중이 끝나며, 사용자에게 보이는 안내가 없고, 되돌리기 실패가 기능 실패로 한 번 기록된다.

### TC-b99d369e-7d38-4b6c-bb80-99d14f627f6f: Diary에서 로그아웃해도 보관한 세션 쿠키를 지우지 않는다

- 근거: `domain > 로그인 정보`
- Given: 세션 쿠키가 보관되어 있고 사용자가 Diary 계정으로 로그인해 있다.
- When: 사용자가 Diary에서 로그아웃한다.

### TC-b71008c6-8c4b-420b-9a29-541ebbbe014e: 보관한 세션 쿠키는 앱을 다시 시작해도 남는다

- 근거: `data > 저장 위치`

- Then: 보관한 세션 쿠키가 같은 정보로 읽힌다.

### TC-ec42851a-a2b1-458a-a869-f45a74c71c10: 만료 시각이 있는 쿠키와 사이트 저장 공간이 앱을 다시 시작해도 남는다

- 근거: `domain > 플랫폼별 유지 범위`
- Given: Android, iOS, 데스크톱 앱(macOS)의 웹 표시 수단에서 사이트가 만료 시각이 있는 쿠키와 사이트 저장 공간에 값을 남겼다.
- When: 앱을 종료하고 다시 시작해 같은 사이트를 연다.
- Then: 그 쿠키와 사이트 저장 공간의 값이 남아 있다.
- 작성하지 않는 이유: 웹 표시 수단이 기기에 기록한 결과는 실제 웹 표시 수단을 띄우고 앱을 다시 시작해야 확인할 수 있는데, 저장소의 테스트는 기기와 실제 웹 표시 수단 없이 실행된다. 기기에서 앱을 다시 시작하는 기기 테스트 환경이 마련되면 작성한다.
