# 파일 내려받기 테스트 케이스

기준 스펙: [파일 내려받기 스펙](../spec/client/file-download.md)

다운로드를 실행하는 자리와 결과 안내는 [FileDetail 테스트 케이스](./file-detail.md)에서, 저장 위치를 고르는 화면은 [SettingFile 테스트 케이스](./setting-file.md)에서 다룬다. 이 문서의 저장 위치는 기기의 폴더를 대신하는 제어된 저장 위치이며, 그 위치가 이미 가진 이름과 쓰기 결과를 테스트 데이터로 정한다.

## feature

### TC-fa368167-d81a-4307-a63d-7e49c56ec884: 고른 폴더가 있으면 그 폴더에, 없으면 기본 위치에 저장한다

- 근거: `feature > 제공 범위`
- Given: 서버가 내용 내려받기 요청에 성공하고, 다운로드 위치 설정이 테스트 데이터와 같다.
- When: 파일을 내려받는다.
- Then: 테스트 데이터의 위치에 파일을 저장한다.
- 테스트 데이터:

| 다운로드 위치 설정 | 저장 위치 |
| --- | --- |
| 고른 폴더 없음 | 플랫폼의 기본 위치 |
| 폴더 A를 고름 | 폴더 A |

### TC-fc37bb69-7a4c-4aac-821c-bfd475e902b5: 고른 폴더에 쓸 수 없으면 기본 위치에 대신 저장하지 않고 저장 위치 실패로 끝난다

- 근거: `feature > 내려받기 결과`
- Given: 다운로드 위치 설정이 폴더 A이고, 폴더 A에 파일을 쓸 수 없으며, 서버는 내용 내려받기 요청에 성공한다.
- When: 파일을 내려받는다.
- Then: 내려받기가 저장 위치에 저장하지 못한 실패로 끝나고, 기본 위치에도 파일을 저장하지 않는다.

### TC-eff813ca-20ff-4336-a492-fa49b3a3374e: 서버나 연결 문제로 받지 못하면 그 밖의 실패로 끝난다

- 근거: `feature > 내려받기 결과`, `domain > 내려받기 흐름`
- Given: 테스트 데이터의 상황이다.
- When: 파일을 내려받는다.
- Then: 내려받기가 그 밖의 실패로 끝나고, 저장 위치에 파일이 남지 않는다.
- 테스트 데이터:

| 상황 |
| --- |
| 서버가 내용 내려받기 요청에 찾을 수 없음을 돌려준다 |
| 서버가 내용 내려받기 요청에 연결 실패로 응답하지 못한다 |
| 임시 주소에서 내용을 받는 도중 연결이 끊긴다 |

### TC-1a092f4a-bcb1-4e4e-8178-9aa24eba7daf: 웹에서는 받은 파일을 브라우저에 넘긴다

- 근거: `feature > 제공 범위`, `domain > 내려받기 흐름`
- Given: 웹에서 서버가 내용 내려받기 요청에 성공한다.
- When: 파일을 내려받는다.
- Then: 받은 내용과 저장할 파일 이름을 브라우저에 넘기고 성공으로 끝난다.
- 작성하지 않는 이유: 브라우저에 파일을 넘기는 것은 웹 환경에서만 실행되고, 이 저장소의 자동화 테스트는 데스크톱과 Android 환경에서만 실행된다. 자동화하려면 웹 환경의 테스트 실행 환경이 필요하다.

### TC-b818094d-97c4-4dba-855b-39a9c9254572: iOS의 이 앱의 폴더에는 내려받은 파일만 보인다

- 근거: `feature > 제공 범위`
- Given: iOS에서 앱을 사용해 기기에 자료가 저장되어 있고, 파일을 기본 위치에 내려받았다.
- When: 사용자가 `파일` 앱의 `나의 iPhone`에서 이 앱의 폴더를 연다.
- Then: 내려받은 파일만 보이고 앱이 기기에 저장하는 다른 자료는 보이지 않는다.
- 작성하지 않는 이유: `파일` 앱에 보이는 폴더와 앱 자료의 위치는 iOS 기기에서만 정해지고, 저장소의 테스트는 JVM과 Android 환경에서만 실행된다. 자동화하려면 iOS 시뮬레이터에서 앱 폴더의 내용을 조회하는 기기 테스트 환경이 필요하다.

## domain

### TC-aebde2d9-41f7-47c1-bbb4-170835d3492c: 계정을 확인하지 못하면 서버에 요청하지 않고 그 밖의 실패로 끝난다

- 근거: `domain > 내려받기 흐름`
- Given: 로그인한 계정을 확인하지 못한 상태다.
- When: 파일을 내려받는다.
- Then: 서버에 내용 내려받기 요청을 보내지 않고, 그 밖의 실패로 끝난다.

### TC-c23b3f37-81ef-42d6-bcf3-5563583e7157: 받는 도중 실패하거나 멈추면 받던 내용을 저장 위치에 남기지 않는다

- 근거: `domain > 내려받기 흐름`
- Given: 저장 위치에 파일을 쓰기 시작한 뒤 테스트 데이터의 일이 일어난다.
- When: 내려받기가 끝난다.
- Then: 저장 위치에 쓰던 파일이 남지 않는다.
- 테스트 데이터:

| 일 |
| --- |
| 내용을 받는 도중 연결이 끊긴다 |
| 사용자가 화면을 떠나 내려받기가 멈춘다 |

### TC-bd547743-fcaa-4315-bc47-4e245b504ba3: 실패한 내려받기를 스스로 다시 시도하지 않는다

- 근거: `domain > 내려받기 흐름`
- Given: 서버가 내용 내려받기 요청에 실패를 돌려준다.
- When: 파일을 내려받아 실패로 끝난다.
- Then: 내용 내려받기 요청을 한 번만 보내고 다시 보내지 않는다.

### TC-f32cfd05-b47c-42da-b74c-0541b4e9d2ab: 파일 이름에 쓸 수 없는 글자는 `_`로 바꿔 저장한다

- 근거: `domain > 저장하는 파일 이름`
- Given: 서버에 저장된 파일 이름이 테스트 데이터와 같고, 저장 위치에 같은 이름의 파일이 없다.
- When: 파일을 내려받는다.
- Then: 테스트 데이터의 이름으로 저장한다.
- 테스트 데이터:

| 저장된 이름 | 저장하는 이름 |
| --- | --- |
| `report.pdf` | `report.pdf` |
| `a/b\c.txt` | `a_b_c.txt` |
| `what?:*.txt` | `what___.txt` |
| `"x"<y>\|z.txt` | `_x__y__z.txt` |
| 줄바꿈이 들어간 `line1⏎line2.txt` | `line1_line2.txt` |
| `.` | `_` |
| `..` | `_` |

### TC-f9cd7730-015c-4120-aa0a-dda6e46df8b0: 같은 이름이 있으면 덮어쓰지 않고 가장 작은 번호를 붙인다

- 근거: `domain > 이름이 겹칠 때`
- Given: 고른 폴더가 저장 위치이고, 그 위치에 테스트 데이터의 파일이 이미 있다.
- When: 테스트 데이터의 이름으로 저장된 파일을 내려받는다.
- Then: 이미 있는 파일을 덮어쓰지 않고 테스트 데이터의 이름으로 새로 저장한다.
- 테스트 데이터:

| 저장된 이름 | 이미 있는 파일 | 저장하는 이름 |
| --- | --- | --- |
| `report.pdf` | 없음 | `report.pdf` |
| `report.pdf` | `report.pdf` | `report (1).pdf` |
| `report.pdf` | `report.pdf`, `report (1).pdf` | `report (2).pdf` |
| `report.pdf` | `report.pdf`, `report (2).pdf` | `report (1).pdf` |
| `archive.tar.gz` | `archive.tar.gz` | `archive.tar (1).gz` |
| `README` | `README` | `README (1)` |
| `.env` | `.env` | `.env (1)` |

### TC-172654dc-6575-4fdf-82e7-9cac8d520b9c: 기본 Download 폴더에 저장할 때 겹치는 이름은 시스템이 정한다

- 근거: `domain > 이름이 겹칠 때`
- Given: Android에서 고른 폴더가 없고, 기기의 `Download` 폴더에 같은 이름의 파일이 이미 있다.
- When: 파일을 내려받는다.
- Then: 이미 있는 파일을 덮어쓰지 않고, 시스템이 정한 이름으로 새 파일을 저장한다.
- 작성하지 않는 이유: 이름을 정하는 것이 기기의 시스템이라 실제 기기의 공용 저장 공간 없이 결과를 관찰할 수 없다. 자동화하려면 실제 Android 기기나 에뮬레이터에서 실행하는 계측 테스트 환경이 필요하다.

## data

### TC-5591938c-4f65-42ea-b01d-98177ca0c509: 내려받을 때마다 그 시점의 저장 위치 설정을 읽는다

- 근거: `data > 저장 위치 설정`
- Given: 다운로드 위치 설정이 폴더 A일 때 파일을 한 번 내려받았고, 그 뒤 설정을 폴더 B로 바꿨다.
- When: 파일을 다시 내려받는다.
- Then: 폴더 B에 파일을 저장한다.

### TC-eecbd8ea-88d6-4533-b956-21bffb9ce0d2: 저장 위치 설정을 읽지 못하면 기본 위치에 저장하지 않고 그 밖의 실패로 끝난다

- 근거: `data > 저장 위치 설정`
- Given: 서버가 내용 내려받기 요청에 성공하고, 다운로드 위치 설정을 읽지 못한다.
- When: 파일을 내려받는다.
- Then: 어느 위치에도 파일을 저장하지 않고 그 밖의 실패로 끝난다.

### TC-c8dace87-717c-4c9c-a6af-7c9edef184b1: 서버에서 받은 임시 주소의 내용을 그대로 저장한다

- 근거: `data > 받는 내용`
- Given: 서버가 내용 내려받기 요청에 임시 주소를 돌려주고, 그 주소가 테스트용 내용을 돌려준다.
- When: 파일을 내려받는다.
- Then: 이 파일의 식별자로 내용 내려받기 요청을 한 번 보내고, 저장한 파일의 내용은 임시 주소가 돌려준 내용과 같다.
