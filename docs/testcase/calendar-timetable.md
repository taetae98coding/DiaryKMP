# CalendarTimetable 테스트 케이스

기준 스펙: [CalendarTimetable 화면 스펙](../spec/client/calendar-timetable.md)

시간표에 표시할 메모의 노출 기준, 표시 색상, 조회 결과 정렬, 로그인이나 로그아웃으로 계정이 바뀌었을 때 다시 조회하는 것은 [캘린더 메모 표시 테스트 케이스](calendar-memo.md)에서 다루므로 여기서 중복 작성하지 않는다. 날짜 구성, 좌우로 넘기는 이동과 이동 범위, 아이템의 시간대와 배치, 화면 재생성 때 시간대 유지, 기간 선택의 칸과 기간은 [Timetable 컴포넌트 스펙](../spec/client/timetable.md)에 위임되어 [Timetable 테스트 케이스](timetable.md)가 갖는다. 각 연도의 공휴일 동기화와 이미 성공한 연도의 재조회 생략, 노출 설정과 국가 설정을 반영한 조회는 [공휴일 동기화 테스트 케이스](holiday-fetch.md)와 [공휴일 노출 설정 테스트 케이스](holiday-visibility.md)가 갖는다. 이 문서는 시간표 화면이 정하는 형식과 시작 날짜, 년도와 월 안내, 공휴일 표시와 선택, 메모 자리, 메모 선택, 기간 선택 후 이동, 현재 시각 지정, 조회 기간과 공휴일 동기화 대상만 다룬다.

## 작성하지 않는 이유

- 시각 메모 블록과 종일 메모가 놓이는 높이와 가로 위치, 현재 시각 표시의 높이는 화면의 크기와 위치를 확인해야 하므로 작성하지 않는다. 시각 아이템과 종일 아이템의 시간대와 칸은 [Timetable 테스트 케이스](timetable.md)의 domain 케이스로 확인한다. 화면 크기를 고정하고 배치 좌표를 스펙의 시각으로 환산해 비교할 수 있는 화면 테스트 기준이 정해지면 자동화한다.
- 차지하는 시간대가 모두 같은 시각 아이템 메모가 조회 결과 정렬 순서대로 놓이는 것은 조회 결과 순서대로 아이템을 지정한 결과이므로 여기서 따로 작성하지 않는다. 지정한 순서대로 놓이는 것은 [Timetable 테스트 케이스](timetable.md)의 TC-105cbff4-a75e-4331-8d98-96428b748141로, 조회 결과 정렬은 [캘린더 메모 표시 테스트 케이스](calendar-memo.md)로 확인하며, 두 계층을 함께 실행하는 통합 테스트 환경이 갖춰지면 자동화한다.
- 오늘의 날짜가 주요 날짜로 강조되는 것은 색과 원형 배경으로만 드러나 화면 테스트에서 관찰할 수 있는 이름이나 상태가 없으므로 작성하지 않는다. 주요 날짜 강조를 접근성 상태로도 알리도록 디자인이 정해지면 자동화한다.
- 오늘에 해당하는 날짜에 현재 시각 위치를 표시하고 다른 날짜에는 표시하지 않는 것은 시간표가 기기의 현재 시각을 읽어 오늘을 정하고 화면 테스트가 그 시각을 정할 수 없어, 자정 무렵에 실행하면 같은 조건에서도 결과가 달라지므로 작성하지 않는다. 현재 시각을 지정했을 때의 표시는 [Timetable 테스트 케이스](timetable.md)의 TC-3615b3eb-deb8-477c-9994-a9cd2509e779과 TC-1d4ea0a9-c1af-432a-98ad-fe8cc4bc6624로 확인하며, 시각을 주입할 수 있는 화면 테스트 환경이 갖춰지면 자동화한다.
- 현재 시각이 1분마다 다시 정해지는 것, 자정이 지나 오늘의 열이 바뀌는 것, 다른 화면이나 다른 앱에서 돌아올 때 오늘을 다시 정하는 것은 실제 시계의 흐름에 의존해 결정적으로 재현하기 어려우므로 작성하지 않는다. 시각을 주입할 수 있는 화면 테스트 환경이 갖춰지면 자동화한다.
- 태그 필터의 선택이 시간표의 메모에 반영되는 것은 필터를 반영해 조회한 결과가 시간표 화면에 전달되기 전에 정해져, 시간표 화면이 받는 경계에서는 필터가 반영되었는지 구분할 관찰 지점이 없으므로 작성하지 않는다. 필터 선택과 기기에 저장된 메모 조회를 함께 실행하는 통합 테스트 환경이 갖춰지면 자동화한다. 시간표에서 필터를 열 수 없는 것은 TC-af8ca7cb-3853-4b83-a38e-198f7f8b571f으로 확인한다.
- 다른 앱에 다녀오는 동안 시스템이 앱을 정리했다가 다시 만든 뒤 보던 형식과 날짜, 시간대가 유지되는 것은 실제 프로세스 종료와 복원을 재현해야 하므로 작성하지 않는다. 화면 재생성 때 저장한 상태로 다시 그리는 결과는 TC-747c658f-80b2-49a1-8541-be4625f703f1과 [Timetable 테스트 케이스](timetable.md)의 TC-ffd99729-644c-4a05-9ce7-d328c2aa52a3로 확인하며, 프로세스 종료를 재현하는 계측 테스트 환경이 갖춰지면 자동화한다.
- MemoDetail 화면에서 돌아왔을 때와 캘린더 홈 화면으로 돌아갔을 때 보던 날짜나 달이 유지되는 것, 시간표에서 연 MemoDetail 화면이 메모 목록과 함께 표시되지 않는 것은 여러 화면을 통과하는 내비게이션 통합 동작이므로 작성하지 않는다. 시간표가 이동을 요청하는 것까지는 TC-0e302b13-4099-4c35-8eb9-8d55a3a8bc8b과 TC-a3d108ce-793d-40ec-8a34-52294a8e7a14로 확인하며, 앱 내비게이션 전체를 결정적으로 검증할 수 있는 테스트 환경이 갖춰지면 자동화한다.
- 연락처 생일과 날씨를 시간표에 표시하지 않는 것은 시간표 화면이 받는 경계에 메모 외의 자료가 들어갈 자리가 없어, 표시하지 않았다는 결과를 입력을 바꿔 가며 구분할 수 없으므로 작성하지 않는다. 앱 전체의 자료를 채운 채 화면을 여는 통합 테스트 환경이 갖춰지면 자동화한다.
- 시간표에 들어오는 것만으로 서버에서 메모를 다시 가져오지 않는 것은 서버와 맞추는 동기화가 시간표 화면 밖의 계기에서만 시작되어, 시간표 화면 테스트에서 동기화가 일어나지 않았음을 관찰할 경계가 없으므로 작성하지 않는다. 동기화 요청을 기록할 수 있는 앱 수준 통합 테스트 환경이 갖춰지면 자동화한다.
- 앱을 종료하고 다시 실행해 시간표를 새로 열면 오전 8시부터 보이는 것은 스크롤 위치를 확인해야 하고 실제 앱 재실행을 재현해야 하므로 작성하지 않는다. 처음 표시될 때의 시간대는 [Timetable 테스트 케이스](timetable.md)의 `작성하지 않는 이유`를 따르며, 앱 재실행을 재현하는 계측 테스트 환경이 갖춰지면 자동화한다.
- 공휴일 날짜가 일요일과 같은 색으로 강조되는 것은 색으로만 드러나므로 [Timetable 테스트 케이스](timetable.md)의 `작성하지 않는 이유`와 같은 이유로 작성하지 않는다. 날짜 강조 대상에 공휴일 여부가 참인 공휴일만 들어가는 것도 같은 이유로 작성하지 않으며, 강조를 접근성 상태로도 알리도록 디자인이 정해지면 자동화한다.
- 공휴일 여부가 참인 이름과 거짓인 이름이 서로 다른 배경으로 구분되는 것과, 차지하는 날짜가 같은 메모가 공휴일 이름보다 위쪽 줄에 놓이는 것은 색과 위치를 확인해야 하므로 작성하지 않는다. 먼저 지정한 종일 아이템이 위쪽 줄에 놓이는 것은 [Timetable 테스트 케이스](timetable.md)의 TC-490fdf03-15ff-43bc-bfe7-cc48930c8517으로 확인한다.
- 다른 앱에 다녀오는 것만으로 공휴일을 다시 동기화하지 않는 것은 앱의 시작과 정지 경계를 화면 단위로 재현할 때 화면이 다시 만들어지는 경우와 구분할 수 없어 작성하지 않는다. 앱 수명 주기를 제어할 수 있는 테스트 환경이 갖춰지면 자동화한다.
- MemoAdd 화면에서 돌아왔을 때 선택된 기간 없이 보던 날짜와 시간대가 유지되는 것과 시간표에서 연 MemoAdd 화면이 메모 목록과 함께 표시되지 않는 것은 여러 화면을 통과하는 내비게이션 통합 동작이므로 작성하지 않는다. 이동 요청은 TC-fd9b33ec-ecd4-41ec-a73e-8dc35c017ef7로, 선택 완료 후 선택 표시가 사라지는 것과 시스템 중단·화면 재생성 때의 처리는 [Timetable 테스트 케이스](timetable.md)로 확인한다.
- 브라우저를 열지 못한 것을 실행 환경이 알려 주지 않으면(웹 등) 안내하지 않는 결과는 그 실행 환경을 현재 테스트 환경에서 재현할 수 없어 작성하지 않는다. 알려 주는 환경의 안내는 TC-2302faa8-0e50-44f8-8bcb-d637e6159ecc로 확인한다. 그 실행 환경의 앱 밖 열기를 제어할 수 있는 테스트 환경이 마련되면 작성한다.
