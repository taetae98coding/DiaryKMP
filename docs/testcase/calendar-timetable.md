# CalendarTimetable 테스트 케이스

기준 스펙: [CalendarTimetable 화면 스펙](../spec/client/calendar-timetable.md)

시간표에 표시할 메모의 노출 기준, 표시 색상, 조회 결과 정렬, 로그인이나 로그아웃으로 계정이 바뀌었을 때 다시 조회하는 것은 [캘린더 메모 표시 테스트 케이스](calendar-memo.md)에서 다루므로 여기서 중복 작성하지 않는다. 날짜 구성, 좌우로 넘기는 이동과 이동 범위, 아이템의 시간대와 배치, 화면 재생성 때 시간대 유지는 [Timetable 컴포넌트 스펙](../spec/client/timetable.md)에 위임되어 [Timetable 테스트 케이스](timetable.md)가 갖는다. 이 문서는 시간표 화면이 정하는 형식과 시작 날짜, 년도와 월 안내, 메모 자리, 메모 선택, 현재 시각 지정과 조회 기간만 다룬다.

## feature

### TC-CALENDAR-TIMETABLE-FEATURE-001: 하루 형식은 시작 날짜 하나를 표시한다

- 근거: `feature > 형식과 시작 날짜`
- Given: 시작 날짜가 2026년 9월 23일(수)인 하루 형식 시간표를 연다.
- When: 시간표가 표시된다.
- Then: 날짜 머리줄에 `Wed`와 `23` 하나만 표시되고, 상단 바 제목은 `September 2026`이다.

### TC-CALENDAR-TIMETABLE-FEATURE-002: 주간 형식은 시작 주의 일요일부터 토요일까지 표시한다

- 근거: `feature > 형식과 시작 날짜`
- Given: 2026년 9월 20일(일)부터 26일(토)까지의 주로 주간 형식 시간표를 연다.
- When: 시간표가 표시된다.
- Then: 날짜 머리줄에 `20`부터 `26`까지 일곱 날짜가 일요일부터 차례로 표시된다.

### TC-CALENDAR-TIMETABLE-FEATURE-003: 두 달에 걸친 주는 일요일이 속한 달을 안내한다

- 근거: `feature > 년도와 월 안내`
- Given: 2026년 9월 27일(일)부터 10월 3일(토)까지의 주로 주간 형식 시간표를 연다.
- When: 시간표가 표시된다.
- Then: 상단 바 제목은 `September 2026`이고, 날짜 머리줄에는 `27`, `28`, `29`, `30`, `1`, `2`, `3`이 모두 표시된다.

### TC-CALENDAR-TIMETABLE-FEATURE-004: 다음 날로 넘기면 년도와 월 안내가 이동한 날짜 기준으로 바뀐다

- 근거: `feature > 년도와 월 안내`
- Given: 2026년 9월 30일(수)의 하루 형식 시간표가 표시되어 있다.
- When: 사용자가 시간표를 오른쪽에서 왼쪽으로 넘긴다.
- Then: 날짜 머리줄이 `Thu`, `1`로 바뀌고 상단 바 제목이 `October 2026`으로 바뀐다.

### TC-CALENDAR-TIMETABLE-FEATURE-008: 하루 일정은 시간대 영역에, 그 밖의 메모는 종일 영역에 표시된다

- 근거: `feature > 메모 표시`, `domain > 메모 자리`
- Given: 2026년 9월 23일의 하루 형식 시간표를 열고, 조회 결과에 다음 메모가 있다.
- When: 시간표가 표시된다.
- Then: 각 메모가 표의 자리에 제목으로 표시된다.

| 메모 제목 | 기간 | 자리 |
| --- | --- | --- |
| 회의 | 2026-09-23 10:00 ~ 2026-09-23 11:00 | 시간대 영역 |
| 휴가 | 2026-09-22 ~ 2026-09-24 종일 | 종일 영역 |
| 출장 | 2026-09-22 09:00 ~ 2026-09-23 18:00 | 종일 영역 |

### TC-CALENDAR-TIMETABLE-FEATURE-010: 메모를 선택하면 그 메모의 MemoDetail 화면으로 이동을 요청한다

- 근거: `feature > 메모 선택`
- Given: 하루 일정 `회의`와 종일 메모 `휴가`가 표시된 시간표가 있다.
- When: 사용자가 각 메모를 선택한다.
- Then: 선택한 메모의 MemoDetail 화면으로 이동이 한 번씩 요청된다.

### TC-CALENDAR-TIMETABLE-FEATURE-011: 메모가 준비되면 별도 조작 없이 표시된다

- 근거: `feature > 메모 표시 갱신`
- Given: 조회 결과가 비어 있는 하루 형식 시간표가 표시되어 있다.
- When: 조회 결과에 그 날짜의 하루 일정 `회의`가 들어온다.
- Then: 사용자가 별도 조작을 하지 않아도 `회의`가 표시된다.

### TC-CALENDAR-TIMETABLE-FEATURE-012: 메모가 없어도 빈 상태 안내 없이 시간대 안내를 보여 준다

- 근거: `feature > 메모 표시 갱신`
- Given: 조회 결과가 비어 있다.
- When: 하루 형식 시간표가 표시된다.
- Then: 빈 상태 안내 문구 없이 날짜 머리줄과 시간대 안내가 표시된다.

### TC-CALENDAR-TIMETABLE-FEATURE-015: 뒤로가기를 누르면 이전 화면으로 돌아가기를 요청한다

- 근거: `feature > 시간표 닫기`
- Given: 시간표가 표시되어 있다.
- When: 사용자가 상단 바의 뒤로가기 버튼을 누른다.
- Then: 이전 화면으로 돌아가기가 한 번 요청된다.

### TC-CALENDAR-TIMETABLE-FEATURE-016: 화면이 재생성되어도 보던 형식과 날짜를 유지한다

- 근거: `domain > 보던 날짜와 시간대 유지`
- Given: 2026년 9월 23일로 연 하루 형식 시간표에서 사용자가 다음 날로 넘겨 9월 24일을 보고 있다.
- When: 화면 재생성이 일어난다.
- Then: 하루 형식으로 `24`가 표시된다.

### TC-CALENDAR-TIMETABLE-FEATURE-019: 주간 형식에서 여러 날에 걸친 종일 메모는 어느 날짜 부분을 선택해도 같은 메모로 이동을 요청한다

- 근거: `feature > 메모 선택`
- Given: 2026년 9월 20일부터 26일까지의 주간 형식 시간표에 9월 21일부터 24일까지의 종일 메모 `Vacation`이 표시되어 있다.
- When: 사용자가 `Vacation`의 9월 21일 부분과 9월 24일 부분을 차례로 선택한다.
- Then: 두 번 모두 `Vacation`의 MemoDetail 화면으로 이동이 요청된다.

### TC-CALENDAR-TIMETABLE-FEATURE-020: 시간표에서는 태그 필터를 열 수 없다

- 근거: `feature > 태그 필터`
- Given: 시간표가 표시되어 있다.
- When: 사용자가 화면을 살펴본다.
- Then: 태그 필터를 여는 수단이 없다.

### TC-CALENDAR-TIMETABLE-FEATURE-021: 메모의 기간이 바뀌어 자리가 달라지면 별도 조작 없이 바뀐 자리에 표시된다

- 근거: `domain > 메모 자리`
- Given: 2026년 9월 23일의 하루 형식 시간표에 하루 일정 `Meeting`이 시간대 영역에 표시되어 있다.
- When: `Meeting`의 기간이 9월 23일 종일로 바뀐 조회 결과가 들어온다.
- Then: 사용자가 별도 조작을 하지 않아도 `Meeting`이 종일 영역에 표시된다.

### TC-CALENDAR-TIMETABLE-FEATURE-022: 다른 앱에 다녀와도 보던 형식과 날짜를 유지한다

- 근거: `domain > 보던 날짜와 시간대 유지`
- Given: 2026년 9월 23일로 연 하루 형식 시간표에서 사용자가 다음 날로 넘겨 9월 24일을 보고 있다.
- When: 사용자가 다른 앱에 다녀온다.
- Then: 하루 형식으로 `24`가 표시된다.

### TC-CALENDAR-TIMETABLE-FEATURE-023: 시간표를 아래로 당겨도 새로고침이 시작되지 않는다

- 근거: `feature > 메모 표시 갱신`
- Given: 하루 형식 시간표가 시간대 영역의 맨 위를 보여 준다.
- When: 사용자가 시간표를 아래로 당긴다.
- Then: 새로고침 진행 표시가 나타나지 않는다.

## domain

### TC-CALENDAR-TIMETABLE-DOMAIN-011: 메모 조회에 실패하면 메모 없이 표시한다

- 근거: `domain > 메모 조회 실패`
- Given: 메모 조회가 실패로 응답한다.
- When: 시간표의 메모 목록을 받는다.
- Then: 빈 메모 목록이 전달된다.


## data

### TC-CALENDAR-TIMETABLE-DATA-001: 날짜를 옮기면 옮긴 날짜의 조회 기간으로 메모를 다시 조회한다

- 근거: `data > 표시 중인 날짜의 메모 조회`
- Given: 2026년 9월 23일을 표시하는 하루 형식 시간표의 메모 조회가 2026-09-22 ~ 2026-09-24로 이루어졌다.
- When: 표시 날짜가 2026년 9월 24일로 바뀐다.
- Then: 2026-09-23 ~ 2026-09-25로 메모가 조회되고, 그 결과가 전달된다.

### TC-CALENDAR-TIMETABLE-DATA-003: 조회 기간은 표시 날짜와 앞뒤로 한 번 넘겼을 때 보이는 날짜를 포함한다

- 근거: `data > 표시 중인 날짜의 메모 조회`
- Given: 시간표 형식과 표시 날짜가 주어진다.
- When: 조회 기간을 정한다.
- Then: 표의 기간이 된다.

| 형식 | 표시 날짜 | 조회 기간 |
| --- | --- | --- |
| 하루 | 2026-09-23 | 2026-09-22 ~ 2026-09-24 |
| 주간 | 2026-09-20 ~ 2026-09-26 | 2026-09-13 ~ 2026-10-03 |


## 작성하지 않는 이유

- 하루 일정 블록과 종일 메모가 놓이는 높이와 가로 위치, 현재 시각 표시의 높이는 화면의 크기와 위치를 확인해야 하므로 작성하지 않는다. 시각 아이템과 종일 아이템의 시간대와 칸은 [Timetable 테스트 케이스](timetable.md)의 domain 케이스로 확인한다. 화면 크기를 고정하고 배치 좌표를 스펙의 시각으로 환산해 비교할 수 있는 화면 테스트 기준이 정해지면 자동화한다.
- 차지하는 시간대가 모두 같은 하루 일정이 조회 결과 정렬 순서대로 놓이는 것은 조회 결과 순서대로 아이템을 지정한 결과이므로 여기서 따로 작성하지 않는다. 지정한 순서대로 놓이는 것은 [Timetable 테스트 케이스](timetable.md)의 TC-TIMETABLE-DOMAIN-008로, 조회 결과 정렬은 [캘린더 메모 표시 테스트 케이스](calendar-memo.md)로 확인하며, 두 계층을 함께 실행하는 통합 테스트 환경이 갖춰지면 자동화한다.
- 오늘의 날짜가 주요 날짜로 강조되는 것은 색과 원형 배경으로만 드러나 화면 테스트에서 관찰할 수 있는 이름이나 상태가 없으므로 작성하지 않는다. 주요 날짜 강조를 접근성 상태로도 알리도록 디자인이 정해지면 자동화한다.
- 오늘에 해당하는 날짜에 현재 시각 위치를 표시하고 다른 날짜에는 표시하지 않는 것은 시간표가 기기의 현재 시각을 읽어 오늘을 정하고 화면 테스트가 그 시각을 정할 수 없어, 자정 무렵에 실행하면 같은 조건에서도 결과가 달라지므로 작성하지 않는다. 현재 시각을 지정했을 때의 표시는 [Timetable 테스트 케이스](timetable.md)의 TC-TIMETABLE-FEATURE-007과 TC-TIMETABLE-FEATURE-008로 확인하며, 시각을 주입할 수 있는 화면 테스트 환경이 갖춰지면 자동화한다.
- 현재 시각이 1분마다 다시 정해지는 것, 자정이 지나 오늘의 열이 바뀌는 것, 다른 화면이나 다른 앱에서 돌아올 때 오늘을 다시 정하는 것은 실제 시계의 흐름에 의존해 결정적으로 재현하기 어려우므로 작성하지 않는다. 시각을 주입할 수 있는 화면 테스트 환경이 갖춰지면 자동화한다.
- 태그 필터의 선택이 시간표의 메모에 반영되는 것은 필터를 반영해 조회한 결과가 시간표 화면에 전달되기 전에 정해져, 시간표 화면이 받는 경계에서는 필터가 반영되었는지 구분할 관찰 지점이 없으므로 작성하지 않는다. 필터 선택과 기기에 저장된 메모 조회를 함께 실행하는 통합 테스트 환경이 갖춰지면 자동화한다. 시간표에서 필터를 열 수 없는 것은 TC-CALENDAR-TIMETABLE-FEATURE-020으로 확인한다.
- 다른 앱에 다녀오는 동안 시스템이 앱을 정리했다가 다시 만든 뒤 보던 형식과 날짜, 시간대가 유지되는 것은 실제 프로세스 종료와 복원을 재현해야 하므로 작성하지 않는다. 화면 재생성 때 저장한 상태로 다시 그리는 결과는 TC-CALENDAR-TIMETABLE-FEATURE-016과 [Timetable 테스트 케이스](timetable.md)의 TC-TIMETABLE-FEATURE-015로 확인하며, 프로세스 종료를 재현하는 계측 테스트 환경이 갖춰지면 자동화한다.
- MemoDetail 화면에서 돌아왔을 때와 캘린더 홈 화면으로 돌아갔을 때 보던 날짜나 달이 유지되는 것, 시간표에서 연 MemoDetail 화면이 메모 목록과 함께 표시되지 않는 것은 여러 화면을 통과하는 내비게이션 통합 동작이므로 작성하지 않는다. 시간표가 이동을 요청하는 것까지는 TC-CALENDAR-TIMETABLE-FEATURE-010과 TC-CALENDAR-TIMETABLE-FEATURE-015로 확인하며, 앱 내비게이션 전체를 결정적으로 검증할 수 있는 테스트 환경이 갖춰지면 자동화한다.
- 공휴일, 연락처 생일, 날씨를 시간표에 표시하지 않는 것은 시간표 화면이 받는 경계에 메모 외의 자료가 들어갈 자리가 없어, 표시하지 않았다는 결과를 입력을 바꿔 가며 구분할 수 없으므로 작성하지 않는다. 앱 전체의 자료를 채운 채 화면을 여는 통합 테스트 환경이 갖춰지면 자동화한다.
- 시간표에 들어오는 것만으로 서버에서 메모를 다시 가져오지 않는 것은 서버와 맞추는 동기화가 시간표 화면 밖의 계기에서만 시작되어, 시간표 화면 테스트에서 동기화가 일어나지 않았음을 관찰할 경계가 없으므로 작성하지 않는다. 동기화 요청을 기록할 수 있는 앱 수준 통합 테스트 환경이 갖춰지면 자동화한다.
- 앱을 종료하고 다시 실행해 시간표를 새로 열면 오전 8시부터 보이는 것은 스크롤 위치를 확인해야 하고 실제 앱 재실행을 재현해야 하므로 작성하지 않는다. 처음 표시될 때의 시간대는 [Timetable 테스트 케이스](timetable.md)의 `작성하지 않는 이유`를 따르며, 앱 재실행을 재현하는 계측 테스트 환경이 갖춰지면 자동화한다.
