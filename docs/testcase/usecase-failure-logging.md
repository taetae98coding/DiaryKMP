# 기능 실패 로깅 테스트 케이스

기준 스펙: [기능 실패 로깅 스펙](../spec/client/usecase-failure-logging.md)

## domain

### TC-4fc2499b-f700-42cd-a3b9-493ab186dc7d: 한 번 실행하는 기능이 실패하면 콘솔에 실패 로그가 남는다

- 근거: `domain > 콘솔 기록`
- Given: 콘솔 기록 수단이 등록되어 있다.
- When: 한 번 실행하고 끝나는 기능이 실패한다.
- Then: 실패한 기능의 이름이 출처 이름으로, 실패 원인이 오류 정보로 개발 콘솔에 남는다.

### TC-28ec08f7-b94c-40aa-a1b8-fd3d949171ad: 내용을 계속 지켜보며 가져오는 기능이 실패하면 콘솔에 실패 로그가 남는다

- 근거: `domain > 콘솔 기록`
- Given: 콘솔 기록 수단이 등록되어 있다.
- When: 내용을 계속 지켜보며 가져오는 기능이 실패한다.
- Then: 실패한 기능의 이름이 출처 이름으로, 실패 원인이 오류 정보로 개발 콘솔에 남는다.

### TC-6562f13e-51d3-4c9c-a1c9-604783c587e8: 한 번 시작한 지켜보기에서 실패 로그는 한 번만 남는다

- 근거: `domain > 기능 실패`
- Given: 콘솔 기록 수단이 등록되어 있고, 내용을 계속 지켜보며 가져오는 기능이 내용을 몇 번 보낸 뒤 실패하도록 제어되어 있다.
- When: 그 기능의 지켜보기를 한 번 시작한다.
- Then: 실패를 전달받은 뒤 지켜보기가 끝나 더 이상 내용을 받지 않고, 개발 콘솔에 실패 로그가 한 번만 남는다.

### TC-f8ba9a1c-4bbe-4a12-9e00-527a7a8fdcd6: 지켜보던 다른 기능의 실패를 그대로 전달하는 기능은 따로 로그를 남기지 않는다

- 근거: `domain > 기능 실패`
- Given: 콘솔 기록 수단이 등록되어 있고, 내용을 계속 지켜보는 기능이 지켜보던 다른 기능의 실패를 결과로 그대로 전달하도록 준비되어 있다.
- When: 바깥 기능의 지켜보기를 시작해 안쪽 기능이 실패한다.
- Then: 바깥 기능은 실패를 결과로 전달하고, 개발 콘솔에는 안쪽 기능의 이름으로 된 실패 로그 하나만 남는다.

### TC-75ca3733-21b8-4f5c-9416-eb6754875509: 다른 기능의 실패를 이어받아 실패한 한 번 실행하는 기능은 두 이름으로 각각 로그를 남긴다

- 근거: `domain > 기능 실패`
- Given: 콘솔 기록 수단이 등록되어 있고, 한 번 실행하고 끝나는 기능이 실행 중에 부른 다른 기능의 실패를 이어받아 실패하도록 준비되어 있다.
- When: 바깥 기능을 실행한다.
- Then: 개발 콘솔에 안쪽 기능의 이름과 바깥 기능의 이름으로 된 실패 로그가 하나씩 남는다.

### TC-ffab2916-0d70-4877-b321-ec59083a40e9: 같은 기능이 여러 번 실패하면 실패할 때마다 로그가 남는다

- 근거: `domain > 기능 실패`
- Given: 콘솔 기록 수단이 등록되어 있다.
- When: 한 번 실행하고 끝나는 같은 기능을 두 번 실행해 두 번 모두 실패한다.
- Then: 개발 콘솔에 실패 로그가 두 번 남는다.

### TC-ab12ade8-95b3-443e-ba83-0b1fda65f82a: 성공한 기능은 실패 로그를 남기지 않는다

- 근거: `domain > 기능 실패`
- Given: 콘솔 기록 수단이 등록되어 있다.
- When: 기능이 성공한다.
- Then: 개발 콘솔에 실패 로그가 남지 않는다.

### TC-9f2cf9fb-cb64-462f-a7e3-efc210cd71ce: 중간에 멈춘 기능은 실패 로그를 남기지 않는다

- 근거: `domain > 기능 실패`
- Given: 콘솔 기록 수단이 등록되어 있다.
- When: 화면을 떠나는 등으로 진행 중이던 기능이 중간에 멈춘다.
- Then: 개발 콘솔에 실패 로그가 남지 않는다.

### TC-7d961071-3576-4a0b-8b28-21d4cf998249: 실패 로그에 기능 입력 값이 담기지 않는다

- 근거: `domain > 실패 로그 내용`
- Given: 콘솔 기록 수단이 등록되어 있다.
- When: 특정 문자열을 입력 값으로 받은 기능이 실패한다.
- Then: 개발 콘솔에 남은 실패 로그에 그 입력 값이 포함되지 않는다.

### TC-0f78fa8d-126c-4ac3-b98c-f6dbdd373790: 실패 로그를 남겨도 실패는 그대로 전달된다

- 근거: `domain > 기능 실패`
- Given: 콘솔 기록 수단이 등록되어 있다.
- When: 기능이 특정 원인으로 실패한다.
- Then: 그 기능을 실행한 화면이나 작업은 그 원인을 담은 실패를 그대로 받는다.

### TC-b976a725-ee2a-41b6-b7e8-8df3f47c0c0d: 기록 수단이 없어도 실패는 그대로 전달된다

- 근거: `domain > 콘솔 기록`
- Given: 어떤 기록 수단도 등록되어 있지 않다.
- When: 기능이 특정 원인으로 실패한다.
- Then: 실패 로그는 어디에도 남지 않고, 그 기능을 실행한 화면이나 작업은 그 원인을 담은 실패를 그대로 받는다.

### TC-117c1b06-4930-4a5e-acd3-d7895901b0b7: 오류 보고 대상 기능이 실패하면 콘솔 로그와 오류 보고가 함께 남는다

- 근거: `domain > 오류 보고`
- Given: 콘솔 기록 수단과 오류 보고 기록 수단이 등록되어 있다.
- When: 오류 보고 대상인 기능이 특정 원인으로 실패한다.
- Then: 실패한 기능의 이름과 그 원인이 담긴 콘솔 로그가 남고, 같은 원인을 담고 메시지에 실패한 기능의 이름이 들어간 오류 보고도 함께 남는다.

### TC-318e8f13-7bf1-403a-986d-9bc10d750dcc: 오류 보고 대상이 아닌 기능의 실패는 콘솔 로그로만 남는다

- 근거: `domain > 오류 보고`
- Given: 콘솔 기록 수단과 오류 보고 기록 수단이 등록되어 있다.
- When: 오류 보고 대상이 아닌 기능이 실패한다.
- Then: 콘솔 로그만 남고 오류 보고는 남지 않는다.

### TC-c31898f9-0147-4546-a29e-c9f84d5cc9c2: 오류 보고 대상 기능이 중간에 멈추면 아무 로그도 남지 않는다

- 근거: `domain > 오류 보고`, `domain > 기능 실패`
- Given: 콘솔 기록 수단과 오류 보고 기록 수단이 등록되어 있다.
- When: 화면을 떠나는 등으로 진행 중이던 오류 보고 대상 기능이 중간에 멈춘다.
- Then: 콘솔 로그와 오류 보고가 모두 남지 않는다.

### TC-a020b1f1-8af2-4d01-a99d-691411e6575f: 오류 보고를 남겨도 실패는 그대로 전달된다
