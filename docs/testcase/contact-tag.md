# 연락처 태그 테스트 케이스

기준 스펙: [연락처 태그 앱 스펙](../spec/client/contact-tag.md), [연락처 태그 스펙](../spec/common/contact-tag.md)

이 문서에서 `data > 연결의 저장` 절은 [항목 연결 앱 스펙](../spec/client/entity-link.md)이 소유한다. `data > 공유되는 연결`, `data > 내려받기 순서와 표시`, `data > 동기화`, `domain > 연결의 상태와 시각` 절은 [항목 연결 공통 스펙](../spec/common/entity-link.md)이 소유한다. `domain > 연결된 태그의 조회` 절은 [항목 태그 연결 앱 스펙](../spec/client/entity-tag.md)이, `domain > 대상 항목과 태그의 연결`, `domain > 연결할 수 있는 태그`, `domain > 태그와 대상 항목의 상태 변화` 절은 [항목 태그 연결 공통 스펙](../spec/common/entity-tag.md)이 소유한다. `domain > 연결의 의미` 절은 [연락처 태그 앱 스펙](../spec/client/contact-tag.md)이 소유한다. 다만 태그와 태그의 연결을 따라 조회되지 않는 규칙은 [태그 연결 스펙](../spec/common/tag-link.md)의 `연결의 의미`가, 그 규칙이 앱의 조회 결과에 적용되는 범위는 [태그 연결 앱 스펙](../spec/client/tag-link.md)의 `연결의 의미`가 소유하므로, 그 케이스의 근거는 해당 절을 직접 링크한다. 나머지 케이스의 절은 [연락처 태그 스펙](../spec/common/contact-tag.md)이 소유한다.

서버가 계정과 연결되지 않은 항목을 가리키는 연결을 받아들이지 않는 것은 [데이터 동기화 테스트 케이스](./data-sync.md)의 `TC-d0f9a9e3-564c-4cfe-85ac-0b73339e2903`가 연결 종류별로 다룬다.

## domain

### TC-7f6c44b9-1420-40bd-9fdc-57039b498d7d: 하나의 연락처에 여러 태그를 연결할 수 있다

- 근거: `domain > 대상 항목과 태그의 연결`
- Given: 계정과 연결된 연락처 하나와 태그 여러 개가 저장되어 있다.
- When: 그 연락처에 태그를 하나씩 모두 연결한다.
- Then: 그 연락처의 연결된 태그를 조회하면 연결한 태그 전체가 조회된다.
