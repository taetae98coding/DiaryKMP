# TagDetail 웹 탭 테스트 케이스

기준 스펙: [TagDetail 웹 탭 스펙](../spec/tag-detail-web.md)

자리 표시 케이스의 `근거`가 가리키는 절은 공통 규칙을 [페이지 조회 목록의 자리 표시 스펙](../spec/paged-list-placeholder.md)에, 빈 상태 케이스의 `근거`가 가리키는 절은 [목록 빈 상태 스펙](../spec/list-empty-state.md)에, 새로고침 케이스의 `근거`가 가리키는 절은 [새로고침 스펙](../spec/sync-refresh.md)에 위임한다.

## feature

### TC-TAG-DETAIL-WEB-FEATURE-001: 대상 태그와 연결된 웹 항목만 목록에 표시한다

- 근거: `feature > 목록 표시`
- Given: 표시 범위가 `이 태그만`이고, 상세 대상 태그와 연결된 웹 항목과 다른 태그에만 연결된 웹 항목이 저장되어 있다.
- When: 사용자가 TagDetail 화면에서 웹 탭을 연다.
- Then: 대상 태그와 연결된 웹 항목만 목록에 표시된다.

### TC-TAG-DETAIL-WEB-FEATURE-002: 목록은 제목 오름차순으로 표시한다

- 근거: `feature > 목록 표시`
- Given: 상세 대상 태그에 제목이 서로 다른 웹 항목 여러 개가 연결되어 있다.
- When: 사용자가 TagDetail 화면에서 웹 탭을 연다.
- Then: 웹 항목이 제목 오름차순으로 표시된다.

### TC-TAG-DETAIL-WEB-FEATURE-003: 자리 표시 상태의 웹 항목은 선택할 수 없다

- 근거: `feature > 목록 표시`
- Given: 목록의 웹 항목이 아직 준비되지 않아 자리 표시 상태로 제공되어 있다.
- When: 사용자가 해당 자리를 선택하려 한다.
- Then: 웹 상세 이동이 요청되지 않는다.

### TC-TAG-DETAIL-WEB-FEATURE-004: 목록 조회 실패에 별도의 오류나 재시도 동작을 표시하지 않는다

- 근거: `feature > 목록 표시`
- Given: 목록 조회가 테스트 데이터의 시점에 실패하도록 설정되어 있다.
- When: 사용자가 TagDetail 화면의 웹 탭을 확인한다.
- Then: 별도 재시도 동작 없이 테스트 데이터의 기존 표시 결과를 유지한다.
- 테스트 데이터:

| 실패 시점 | 기존 표시 결과 |
| --- | --- |
| 최초 조회 | 표시된 웹 항목 없음. 이때의 빈 상태 안내는 `TC-TAG-DETAIL-WEB-FEATURE-010`이 다룬다 |
| 추가 조회 | 이미 표시된 웹 항목 |

### TC-TAG-DETAIL-WEB-FEATURE-005: 웹 항목을 선택하면 그 웹 항목의 상세로 이동한다

- 근거: `feature > 웹 상세 확인`
- Given: 상세 대상 태그에 연결된 웹 항목이 표시되어 있다.
- When: 사용자가 그 웹 항목을 선택한다.
- Then: 선택한 웹 항목의 WebDetail 화면으로 이동한다.

### TC-TAG-DETAIL-WEB-FEATURE-006: 대상 태그의 상태와 무관하게 웹 항목 추가를 시작할 수 있다

- 근거: `feature > 웹 항목 추가`, `domain > 웹 항목 추가의 초기값`
- Given: 웹 탭의 상세 대상 태그 상태가 테스트 데이터의 상태다.
- When: 사용자가 TagDetail 화면의 웹 탭에서 가능한 동작을 확인한다.
- Then: 웹 항목 추가를 시작할 수 있다.
- 테스트 데이터:

| 대상 태그 상태 |
| --- |
| 현재 사용자 계정과 연결되어 있고 미완료·미삭제 |
| 현재 사용자 계정과 연결되지 않음 |
| 완료 |
| 삭제 |

### TC-TAG-DETAIL-WEB-FEATURE-007: 웹 항목 추가를 선택하면 WebAdd 화면으로 이동한다

- 근거: `feature > 웹 항목 추가`
- Given: 완료되지 않고 삭제되지 않은 태그의 TagDetail 화면의 웹 탭이 표시되어 있다.
- When: 사용자가 웹 항목 추가를 선택한다.
- Then: WebAdd 화면으로 이동한다.

### TC-TAG-DETAIL-WEB-FEATURE-008: 웹 추가 화면은 대상 태그를 초기 선택한 상태로 시작한다

- 근거: `feature > 웹 항목 추가`, `domain > 웹 항목 추가의 초기값`
- Given: 미완료·미삭제 상태인 태그 A의 TagDetail 화면의 웹 탭이 표시되어 있다.
- When: 사용자가 웹 항목 추가를 선택한다.
- Then: WebAdd 화면에서 태그 A가 최초 선택되어 있고, 사용자는 저장 전까지 태그 A를 해제하거나 다른 태그를 선택할 수 있다.

### TC-TAG-DETAIL-WEB-FEATURE-009: 완료되었거나 삭제된 대상 태그는 선택되지 않은 상태로 웹 추가를 시작한다

- 근거: `domain > 웹 항목 추가의 초기값`
- Given: 대상 태그가 테스트 데이터의 상태인 TagDetail 화면의 웹 탭이 표시되어 있다.
- When: 사용자가 웹 항목 추가를 선택한다.
- Then: WebAdd 화면에서 대상 태그가 선택된 것으로 표시되지 않는다.
- 테스트 데이터:

| 대상 태그 상태 |
| --- |
| 완료 |
| 삭제 |

### TC-TAG-DETAIL-WEB-FEATURE-010: 연결된 웹 항목이 없으면 빈 상태 안내를 표시한다

- 근거: `feature > 빈 상태`
- Given: 상세 대상 태그와 연결되고 노출 기준을 만족하는 웹 항목이 하나도 없고 목록의 준비가 끝났다.
- When: 사용자가 TagDetail 화면의 웹 탭을 확인한다.
- Then: 웹 카드 대신 이 태그에 연결된 웹 항목이 없음을 알리는 안내가 표시된다.

### TC-TAG-DETAIL-WEB-FEATURE-011: 목록을 준비하는 동안에는 빈 상태 안내를 표시하지 않는다

- 근거: `feature > 빈 상태`
- Given: 목록에 표시된 웹 항목이 아직 하나도 없고 목록의 준비가 끝나지 않았다.
- When: 사용자가 TagDetail 화면의 웹 탭을 확인한다.
- Then: 빈 상태 안내가 표시되지 않는다.

### TC-TAG-DETAIL-WEB-FEATURE-012: 대상 태그를 조회하지 못해도 빈 상태 안내는 같은 기준으로 표시한다

- 근거: `feature > 빈 상태`
- Given: 상세 대상 태그를 조회하지 못해 화면 제목이 표시되지 않고, 연결된 웹 항목이 하나도 없으며 목록의 준비가 끝났다.
- When: 사용자가 TagDetail 화면의 웹 탭을 확인한다.
- Then: 이 태그에 연결된 웹 항목이 없음을 알리는 안내가 표시된다.

### TC-TAG-DETAIL-WEB-FEATURE-013: 빈 상태에서도 웹 항목 추가를 실행할 수 있다

- 근거: `feature > 빈 상태`
- Given: TagDetail 화면의 웹 탭에 빈 상태 안내가 표시되어 있다.
- When: 사용자가 웹 항목 추가를 선택한다.
- Then: 상세 대상 태그를 초기값으로 하는 웹 추가 화면으로 이동한다.

### TC-TAG-DETAIL-WEB-FEATURE-014: 웹 항목 추가는 웹 탭에서만 제공된다

- 근거: `feature > 웹 항목 추가`
- Given: 태그가 조회된 TagDetail 화면에서 테스트 데이터의 탭이 선택되어 있다.
- When: 사용자가 화면에서 실행할 수 있는 동작을 확인한다.
- Then: 웹 항목 추가를 실행할 수 없고, 웹 탭으로 전환하면 웹 항목 추가를 실행할 수 있다.
- 테스트 데이터:

| 선택한 탭 |
| --- |
| 태그 디테일 탭 |
| 메모 탭 |
| 장소 탭 |

### TC-TAG-DETAIL-WEB-FEATURE-015: 대상 태그를 조회하지 못해도 웹 목록과 동작을 제공한다

- 근거: `feature > 진입`
- Given: 상세 대상 태그를 조회할 수 없고, 그 태그와 연결된 미삭제 웹 항목이 저장되어 있다.
- When: 사용자가 TagDetail 화면에서 웹 탭을 연다.
- Then: 연결된 웹 항목이 목록에 표시되고 웹 항목 추가를 실행할 수 있다.

### TC-TAG-DETAIL-WEB-FEATURE-016: 목록을 당기면 계정 데이터 동기화를 요청한다

- 근거: `feature > 새로고침`
- Given: 로그인한 계정의 TagDetail 화면에서 웹 탭이 선택되어 있고 목록이 테스트 데이터의 상태다.
- When: 사용자가 목록을 아래로 당긴다.
- Then: 계정 데이터의 서버 동기화가 한 번 요청되고 진행 중임이 표시된다.
- 테스트 데이터:

| 목록 상태 |
| --- |
| 연결된 웹 항목이 표시되어 있음 |
| 빈 상태 안내가 표시되어 있음 |

### TC-TAG-DETAIL-WEB-FEATURE-017: 목록에는 완료·삭제 제스처를 제공하지 않는다

- 근거: `domain > 태그 연결의 변경과 목록`
- Given: 상세 대상 태그에 연결된 웹 항목이 표시되어 있다.
- When: 사용자가 그 웹 항목을 좌우로 밀어 본다.
- Then: 어떤 상태 변경도 요청되지 않고 웹 항목이 목록에 그대로 남는다.

## domain

### TC-TAG-DETAIL-WEB-DOMAIN-001: 태그의 완료·삭제 상태는 연결된 웹 항목의 노출에 영향을 주지 않는다

- 근거: `domain > 상세 대상 태그와 연결`
- Given: 현재 계정의 태그와 미삭제 웹 항목이 해제되지 않은 연결로 저장되어 있다.
- When: 태그를 테스트 데이터의 상태로 바꾼 뒤 그 태그의 웹 목록을 조회한다.
- Then: 연결된 웹 항목이 목록에 계속 포함된다.
- 테스트 데이터:

| 태그 상태 |
| --- |
| 완료 |
| 삭제 |

### TC-TAG-DETAIL-WEB-DOMAIN-002: 상세 대상이 다른 태그로 바뀌면 목록이 새 태그의 웹 항목으로 바뀐다

- 근거: `domain > 상세 대상 태그와 연결`
- Given: 태그 A와 태그 B에 서로 다른 웹 항목이 연결되어 있고 태그 A의 웹 탭 목록을 보고 있다.
- When: 상세 대상이 태그 B로 바뀐다.
- Then: 목록에 태그 B와 연결된 웹 항목만 표시되고 태그 A의 웹 항목은 표시되지 않는다.

## data

### TC-TAG-DETAIL-WEB-DATA-001: 현재 계정의 대상 태그와 활성 연결을 가진 미삭제 웹 항목만 조회한다

- 근거: `data > 태그별 웹 항목 조회`, `domain > 상세 대상 태그와 연결`, `domain > 웹 항목 노출과 정렬`
- Given: 표시 범위가 `이 태그만`이고, 현재 계정과 다른 계정, 대상 태그와 다른 태그, 해제된 연결과 해제되지 않은 연결, 삭제 여부가 서로 다른 웹 항목이 함께 저장되어 있다.
- When: 현재 계정에서 대상 태그의 웹 목록을 조회한다.
- Then: 현재 계정과 연결되어 있고 대상 태그와 해제되지 않은 연결을 가지며 삭제되지 않은 웹 항목만 조회된다.

### TC-TAG-DETAIL-WEB-DATA-002: 태그별 웹 항목을 페이지 단위로 조회한다

- 근거: `data > 태그별 웹 항목 조회`
- Given: 대상 태그에 연결된 웹 항목이 한 페이지보다 많다.
- When: 사용자가 웹 탭에서 목록의 끝으로 이동한다.
- Then: 처음에는 첫 페이지의 웹 항목만 조회되고, 끝에 다가가면 다음 페이지가 이어서 조회된다.

### TC-TAG-DETAIL-WEB-DATA-003: 웹 항목이나 연결이 바뀌면 목록이 자동으로 갱신된다

- 근거: `data > 태그별 웹 항목 조회`
- Given: 대상 태그의 웹 목록을 조회하고 있고, 변경할 웹 항목과 연결이 준비되어 있다.
- When: 테스트 데이터의 변경을 저장한다.
- Then: 새로 목록을 요청하지 않아도 테스트 데이터의 기대 결과가 목록에 반영된다.
- 테스트 데이터:

| 변경 | 기대 결과 |
| --- | --- |
| 연결 해제 | 웹 항목이 목록에서 사라짐 |
| 연결 복구 | 노출 기준을 만족하는 웹 항목이 정렬 위치에 나타남 |
| 웹 항목 삭제 | 웹 항목이 목록에서 사라짐 |
| 웹 항목 제목 변경 | 변경된 제목의 정렬 위치로 이동 |

### TC-TAG-DETAIL-WEB-DATA-004: 웹 항목은 저장 시점의 태그 선택으로 저장된다

- 근거: `data > 웹 항목 추가 결과`, `domain > 웹 항목 추가의 초기값`
- Given: 태그 A의 웹 탭에서 웹 항목 추가를 시작했고 태그 B도 선택할 수 있으며, 새 웹 항목은 미삭제 상태다.
- When: 사용자가 테스트 데이터의 최종 선택 상태로 웹 항목을 저장한다.
- Then: 새 웹 항목의 태그 연결이 테스트 데이터의 기대 결과로 저장되고 웹 탭 노출 결과도 그 연결을 따른다.
- 테스트 데이터:

| 저장 시점의 선택 태그 | 기대 연결 | 태그 A의 웹 탭 결과 |
| --- | --- | --- |
| 태그 A | 태그 A와 연결 | 새 웹 항목이 나타남 |
| 태그 A, 태그 B | 태그 A·태그 B와 연결 | 새 웹 항목이 나타남 |
| 태그 B | 태그 B와만 연결하고 태그 A와 연결하지 않음 | 새 웹 항목이 나타나지 않음 |

### TC-TAG-DETAIL-WEB-DATA-005: 탭별 조회는 서로 독립이다

- 근거: `data > 탭별 조회`
- Given: 대상 태그 조회가 실패하도록 제어되어 있고, 그 태그와 연결된 미삭제 웹 항목이 저장되어 있다.
- When: 사용자가 웹 탭의 목록을 확인한다.
- Then: 태그 조회 실패와 무관하게 웹 목록이 노출 기준대로 조회되어 표시된다.

## 작성하지 않는 이유

웹 목록의 스크롤 위치를 탭 전환 후에도 유지하는 결과는 실제 스크롤 오프셋을 관찰해야 판정할 수 있어 현재 테스트 환경에서는 결정적으로 검증할 수 없다. 목록의 스크롤 위치를 외부에서 읽을 수 있는 테스트 환경이 갖춰지면 자동화한다.
