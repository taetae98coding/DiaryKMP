# TagDetail 장소 탭 테스트 케이스

기준 스펙: [TagDetail 장소 탭 스펙](../spec/client/tag-detail-place.md)

보기 모드 전환, 지도 표시, 두 보기 모드의 목록과 지도 핀, 장소 추가와 상세로 넘기는 것, 정렬과 새로고침을 다루는 케이스의 `근거`가 가리키는 절은 [장소 보기 모드 스펙](../spec/client/place-view-mode.md)이 소유하고, 나머지 케이스의 절은 기준 스펙이 소유한다. 자리 표시 케이스의 절은 공통 규칙을 [페이지 조회 목록의 자리 표시 스펙](../spec/client/paged-list-placeholder.md)에, 빈 상태 케이스의 절은 [목록 빈 상태 스펙](../spec/client/list-empty-state.md)에, 새로고침 케이스의 절은 [새로고침 스펙](../spec/client/sync-refresh.md)에 위임한다.

## feature

### TC-TAG-DETAIL-PLACE-FEATURE-001: 대상 태그와 연결된 장소만 목록에 표시한다

- 근거: `feature > 목록 모드의 장소 목록`, `domain > 노출 대상 장소`
- Given: 표시 범위가 `이 태그만`이고, 상세 대상 태그와 연결된 장소와 다른 태그에만 연결된 장소가 저장되어 있다.
- When: 사용자가 TagDetail 화면에서 장소 탭을 연다.
- Then: 대상 태그와 연결된 장소만 목록에 표시된다.

### TC-TAG-DETAIL-PLACE-FEATURE-002: 목록은 제목 오름차순으로 표시한다

- 근거: `domain > 목록 정렬`
- Given: 상세 대상 태그에 제목이 서로 다른 장소 여러 개가 연결되어 있다.
- When: 사용자가 TagDetail 화면에서 장소 탭을 연다.
- Then: 장소가 제목 오름차순으로 표시된다.

### TC-TAG-DETAIL-PLACE-FEATURE-003: 자리 표시 상태의 장소는 선택할 수 없다

- 근거: `domain > 상세로 이동하는 대상`
- Given: 목록 모드에서 목록의 장소가 아직 준비되지 않아 자리 표시 상태로 제공되어 있다.
- When: 사용자가 해당 자리를 선택하려 한다.
- Then: 장소 상세 이동이 요청되지 않는다.

### TC-TAG-DETAIL-PLACE-FEATURE-004: 목록 조회 실패에 별도의 오류나 재시도 동작을 표시하지 않는다

- 근거: `feature > 목록 모드의 장소 목록`
- Given: 목록 조회가 테스트 데이터의 시점에 실패하도록 설정되어 있다.
- When: 사용자가 TagDetail 화면의 장소 탭을 확인한다.
- Then: 별도 재시도 동작 없이 테스트 데이터의 기존 표시 결과를 유지한다.
- 테스트 데이터:

| 실패 시점 | 기존 표시 결과 |
| --- | --- |
| 최초 조회 | 표시된 장소 없음. 이때의 빈 상태 안내는 `TC-TAG-DETAIL-PLACE-FEATURE-010`이 다룬다 |
| 추가 조회 | 이미 표시된 장소 |

### TC-TAG-DETAIL-PLACE-FEATURE-005: 장소를 선택하면 그 장소의 상세로 이동한다

- 근거: `feature > 장소 상세 확인`
- Given: 상세 대상 태그에 연결된 장소가 테스트 데이터의 보기 모드에서 표시되어 있다.
- When: 사용자가 그 장소를 선택한다.
- Then: 선택한 장소의 PlaceDetail 화면으로 이동한다.
- 테스트 데이터:

| 보기 모드 |
| --- |
| 목록 모드 |
| 지도 모드 |

### TC-TAG-DETAIL-PLACE-FEATURE-006: 대상 태그의 상태와 무관하게 장소 추가를 시작할 수 있다

- 근거: `feature > 장소 추가`, `domain > 장소 추가의 초기값`
- Given: 장소 탭의 상세 대상 태그 상태가 테스트 데이터의 상태다.
- When: 사용자가 TagDetail 화면의 장소 탭에서 가능한 동작을 확인한다.
- Then: 장소 추가를 시작할 수 있다.
- 테스트 데이터:

| 대상 태그 상태 |
| --- |
| 현재 사용자 계정과 연결되어 있고 미완료·미삭제 |
| 현재 사용자 계정과 연결되지 않음 |
| 완료 |
| 삭제 |

### TC-TAG-DETAIL-PLACE-FEATURE-007: 장소 추가를 선택하면 PlaceAdd 화면으로 이동한다

- 근거: `feature > 장소 추가`
- Given: 완료되지 않고 삭제되지 않은 태그의 TagDetail 화면의 장소 탭이 표시되어 있다.
- When: 사용자가 장소 추가를 선택한다.
- Then: PlaceAdd 화면으로 이동한다.

### TC-TAG-DETAIL-PLACE-FEATURE-008: 장소 추가 화면은 대상 태그를 초기 선택한 상태로 시작한다

- 근거: `feature > 장소 추가`, `domain > 장소 추가의 초기값`
- Given: 미완료·미삭제 상태인 태그 A의 TagDetail 화면의 장소 탭이 표시되어 있다.
- When: 사용자가 장소 추가를 선택한다.
- Then: PlaceAdd 화면에서 태그 A가 최초 선택되어 있고, 사용자는 저장 전까지 태그 A를 해제하거나 다른 태그를 선택할 수 있다.

### TC-TAG-DETAIL-PLACE-FEATURE-009: 완료되었거나 삭제된 대상 태그는 선택되지 않은 상태로 장소 추가를 시작한다

- 근거: `domain > 장소 추가의 초기값`
- Given: 대상 태그가 테스트 데이터의 상태인 TagDetail 화면의 장소 탭이 표시되어 있다.
- When: 사용자가 장소 추가를 선택한다.
- Then: PlaceAdd 화면에서 대상 태그가 선택된 것으로 표시되지 않는다.
- 테스트 데이터:

| 대상 태그 상태 |
| --- |
| 완료 |
| 삭제 |

### TC-TAG-DETAIL-PLACE-FEATURE-010: 목록 모드에서 연결된 장소가 없으면 빈 상태 안내를 표시한다

- 근거: `feature > 빈 상태`
- Given: 장소 탭이 목록 모드이고, 상세 대상 태그와 연결되고 노출 기준을 만족하는 장소가 하나도 없으며 목록의 준비가 끝났다.
- When: 사용자가 TagDetail 화면의 장소 탭을 확인한다.
- Then: 장소 카드 대신 이 태그에 연결된 장소가 없음을 알리는 안내가 표시된다.

### TC-TAG-DETAIL-PLACE-FEATURE-011: 목록을 준비하는 동안에는 빈 상태 안내를 표시하지 않는다

- 근거: `feature > 빈 상태`
- Given: 목록에 표시된 장소가 아직 하나도 없고 목록의 준비가 끝나지 않았다.
- When: 사용자가 TagDetail 화면의 장소 탭을 확인한다.
- Then: 빈 상태 안내가 표시되지 않는다.

### TC-TAG-DETAIL-PLACE-FEATURE-012: 대상 태그를 조회하지 못해도 빈 상태 안내는 같은 기준으로 표시한다

- 근거: `feature > 빈 상태`
- Given: 상세 대상 태그를 조회하지 못해 화면 제목이 표시되지 않고, 연결된 장소가 하나도 없으며 목록의 준비가 끝났다.
- When: 사용자가 TagDetail 화면의 장소 탭을 확인한다.
- Then: 이 태그에 연결된 장소가 없음을 알리는 안내가 표시된다.

### TC-TAG-DETAIL-PLACE-FEATURE-013: 빈 상태에서도 장소 추가와 보기 모드 전환을 실행할 수 있다

- 근거: `feature > 빈 상태`
- Given: TagDetail 화면의 장소 탭에 빈 상태 안내가 표시되어 있다.
- When: 사용자가 장소 추가와 보기 모드 전환을 각각 실행한다.
- Then: 상세 대상 태그를 초기값으로 하는 장소 추가 화면으로 이동하고, 보기 모드 전환도 실행된다.

### TC-TAG-DETAIL-PLACE-FEATURE-014: 장소 추가는 장소 탭에서만 제공된다

- 근거: `feature > 장소 추가`
- Given: 태그가 조회된 TagDetail 화면에서 테스트 데이터의 탭이 선택되어 있다.
- When: 사용자가 화면에서 실행할 수 있는 동작을 확인한다.
- Then: 장소 추가를 실행할 수 없고, 장소 탭으로 전환하면 장소 추가를 실행할 수 있다.
- 테스트 데이터:

| 선택한 탭 |
| --- |
| 태그 디테일 탭 |
| 메모 탭 |
| 웹 탭 |

### TC-TAG-DETAIL-PLACE-FEATURE-015: 대상 태그를 조회하지 못해도 장소 목록과 동작을 제공한다

- 근거: `feature > 진입`
- Given: 상세 대상 태그를 조회할 수 없고, 그 태그와 연결된 미삭제 장소가 저장되어 있다.
- When: 사용자가 TagDetail 화면에서 장소 탭을 연다.
- Then: 연결된 장소가 목록에 표시되고 장소 추가와 보기 모드 전환을 실행할 수 있다.

### TC-TAG-DETAIL-PLACE-FEATURE-016: 목록을 당기면 계정 데이터 동기화를 요청한다

- 근거: `feature > 장소 목록 새로고침`
- Given: 로그인한 계정의 TagDetail 화면에서 장소 탭이 선택되어 있고, 테스트 데이터의 보기 모드와 목록 상태다.
- When: 사용자가 장소 목록 영역을 아래로 당긴다.
- Then: 계정 데이터의 서버 동기화가 한 번 요청되고 진행 중임이 표시된다.
- 테스트 데이터:

| 보기 모드 | 목록 상태 |
| --- | --- |
| 목록 모드 | 연결된 장소가 표시되어 있음 |
| 목록 모드 | 빈 상태 안내가 표시되어 있음 |
| 지도 모드 | 보이는 영역 안의 장소가 표시되어 있음 |

### TC-TAG-DETAIL-PLACE-FEATURE-038: 장소 카드를 삭제 방향으로 밀면 그 장소가 삭제되고 안내와 실행 취소가 표시된다

- 근거: `feature > 삭제와 실행 취소`
- Given: 장소 탭의 목록 모드에 상세 대상 태그와 연결된 장소가 표시되어 있고 삭제가 성공하도록 설정되어 있다.
- When: 사용자가 그 장소 카드를 오른쪽에서 왼쪽으로 민다.
- Then: 태그 연결 해제가 아니라 그 장소 자체의 삭제가 한 번 요청되고, TagDetail 화면에 삭제되었다는 안내와 실행 취소 동작이 표시된다.
- 테스트 데이터:

| 언어 환경 | 안내 | 실행 취소 동작 |
| --- | --- | --- |
| 한국어 | `장소가 삭제되었습니다.` | `실행 취소` |
| 그 외 기본 | `Place deleted.` | `Undo` |

### TC-TAG-DETAIL-PLACE-FEATURE-039: 지도 모드의 장소 목록에서 장소 카드를 삭제 방향으로 밀면 그 장소의 삭제가 요청된다

- 근거: `feature > 삭제와 실행 취소`
- Given: 장소 탭 지도 모드의 장소 목록에 보이는 영역 안의 장소가 표시되어 있다.
- When: 사용자가 그 장소 카드를 오른쪽에서 왼쪽으로 민다.
- Then: 그 장소의 삭제가 한 번 요청되고 상세 이동은 요청되지 않는다.

### TC-TAG-DETAIL-PLACE-FEATURE-040: 삭제를 실행 취소하면 그 장소의 삭제가 되돌려진다

- 근거: `feature > 삭제와 실행 취소`
- Given: 장소 탭에서 장소를 삭제해 안내와 실행 취소 동작이 표시되어 있다.
- When: 사용자가 실행 취소를 선택한다.
- Then: 그 장소를 삭제되지 않은 상태로 되돌리는 요청이 한 번 일어난다.

### TC-TAG-DETAIL-PLACE-FEATURE-041: 장소 카드를 반대 방향으로 밀면 아무 동작도 실행하지 않는다

- 근거: `feature > 삭제와 실행 취소`
- Given: 상세 대상 태그에 연결된 장소가 표시되어 있다.
- When: 사용자가 그 장소 카드를 왼쪽에서 오른쪽으로 민다.
- Then: 어떤 상태 변경도 요청되지 않고 장소가 목록에 그대로 남는다.

### TC-TAG-DETAIL-PLACE-FEATURE-042: 아직 준비되지 않은 자리는 밀어도 삭제되지 않는다

- 근거: `feature > 삭제와 실행 취소`
- Given: 장소 탭의 목록 모드에 아직 준비되지 않은 자리가 표시되어 있다.
- When: 사용자가 그 자리를 오른쪽에서 왼쪽으로 민다.
- Then: 삭제가 요청되지 않는다.

### TC-TAG-DETAIL-PLACE-FEATURE-043: 삭제가 저장되지 못하면 안내를 표시하지 않는다

- 근거: `feature > 삭제와 실행 취소`
- Given: 장소 삭제의 저장이 실패하도록 설정되어 있다.
- When: 사용자가 장소 탭 목록에서 장소를 삭제한다.
- Then: 삭제 안내와 실행 취소 동작이 제공되지 않는다.

### TC-TAG-DETAIL-PLACE-FEATURE-044: 안내가 보이는 동안 다른 장소를 삭제하면 마지막 삭제의 안내만 남는다

- 근거: `feature > 삭제와 실행 취소`
- Given: TagDetail 화면의 장소 탭에서 장소 A를 삭제해 안내가 표시되어 있다.
- When: 안내가 사라지기 전에 장소 B가 삭제되고, 이어서 사용자가 실행 취소를 선택한다.
- Then: TagDetail 화면의 안내 자리에는 삭제 안내 하나만 표시되고, 실행 취소는 장소 B에만 적용되며 장소 A는 되돌려지지 않는다.

### TC-TAG-DETAIL-PLACE-FEATURE-045: 실행 취소를 선택하지 않으면 안내가 잠시 뒤 사라지고 되돌릴 수 없다

- 근거: `feature > 삭제와 실행 취소`
- Given: TagDetail 화면의 장소 탭에서 장소를 삭제해 안내가 표시되어 있다.
- When: 사용자가 실행 취소를 선택하지 않고 안내가 저절로 사라질 때까지 기다린다.
- Then: 안내와 실행 취소 동작이 사라지고, 삭제를 되돌리는 요청은 일어나지 않는다.

### TC-TAG-DETAIL-PLACE-FEATURE-046: 안내가 보이는 동안 다른 탭으로 바꾸면 안내가 닫히고 되돌릴 수 없다

- 근거: `feature > 삭제와 실행 취소`
- Given: TagDetail 화면의 장소 탭에서 장소를 삭제해 안내와 실행 취소 동작이 표시되어 있다.
- When: 사용자가 웹 탭으로 바꾼 뒤 장소 탭으로 돌아온다.
- Then: 안내와 실행 취소 동작이 보이지 않고, 삭제를 되돌리는 요청은 일어나지 않는다.

### TC-TAG-DETAIL-PLACE-FEATURE-047: 안내가 보이는 동안 보기 모드를 바꿔도 안내가 남고 실행 취소할 수 있다

- 근거: `feature > 삭제와 실행 취소`

- Given: 현재 계정과 다른 계정, 대상 태그와 다른 태그, 해제된 연결과 해제되지 않은 연결, 삭제 여부와 좌표가 서로 다른 장소가 함께 저장되어 있다.

### TC-TAG-DETAIL-PLACE-DATA-007: 지도 모드의 조회는 날짜변경선을 걸친 영역의 양쪽 범위를 모두 포함한다

### TC-TAG-DETAIL-PLACE-DATA-008: 지도 모드의 목록은 페이지로 나누지 않는다

### TC-TAG-DETAIL-PLACE-DATA-009: 보기 모드를 바꾸는 것은 서버 조회를 일으키지 않는다

## 작성하지 않는 이유

앱을 종료하고 다시 실행하면 목록 모드의 목록을 맨 위부터 보여 주는 결과는 앱 프로세스를 새로 시작해 같은 화면까지 다시 진입해야 판정할 수 있어 현재 단위 테스트 환경에서는 작성하지 않는다. 다시 실행한 뒤의 화면은 저장 상태 없이 새로 구성되므로 `TC-TAG-DETAIL-PLACE-DOMAIN-014`의 다시 들어온 경우와 같은 결과이며, 앱 재실행을 제어하는 테스트 환경이 갖춰지면 자동화한다.

지도 모드에서 지도 영역과 장소 목록 영역이 창 너비에 따라 위아래 또는 좌우로 나뉘는 결과는 실제 화면의 크기와 위치를 판정해야 하므로 작성하지 않는다.

`TC-TAG-DETAIL-PLACE-FEATURE-027`의 핀 누르기와 `TC-TAG-DETAIL-PLACE-FEATURE-032`의 지도 끌기는 지도 제공자의 지도가 실제로 표시되어야 조작할 수 있고, 호스트 테스트 환경에서는 지도 제공자의 화면 요소를 만들 수 없어 자동화하지 않는다. 지도 없이 판정할 수 있는 부분은 나누어 다룬다. 핀이 어떤 장소를 가리키는지는 목록과 같은 장소가 핀으로 지정되는 것으로, 당기는 자리가 목록 영역에 한정되는 것은 목록 영역에서 당겼을 때 새로고침이 요청되는 것으로 검증한다. 지도 제공자의 화면 요소를 구성할 수 있는 테스트 환경이 갖춰지면 자동화한다.
