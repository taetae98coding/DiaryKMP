# DiaryDateTimeInput 테스트 케이스

기준 스펙: [날짜·시간 입력 컴포넌트 스펙](../spec/client/diary-date-time-input.md)

## feature

### TC-DIARY-DATE-TIME-INPUT-FEATURE-001: 초기 기간이 없으면 사용하지 않는 상태로 시작한다

- 근거: `feature > 사용 여부 전환`, `domain > 기본값`
- Given: 초기 기간이 제공되지 않은 컴포넌트가 표시된다.
- When: 사용자가 컴포넌트를 확인한다.
- Then: 날짜·시간 입력을 사용하지 않는 상태이며 선택된 기간이 없다.

### TC-DIARY-DATE-TIME-INPUT-FEATURE-002: 초기 기간이 제공되면 사용하는 상태로 해당 기간이 선택된다

- 근거: `feature > 사용 여부 전환`, `domain > 기본값`
- Given: 테스트 데이터의 초기 기간이 제공된 컴포넌트가 표시된다.
- When: 사용자가 컴포넌트를 확인한다.
- Then: 날짜·시간 입력을 사용하는 상태이며 제공된 종일 여부와 시작·종료 값이 선택된다.
- 테스트 데이터:

| 초기 기간 |
| --- |
| 종일, 2026-07-19 ~ 2026-07-20 |
| 종일 아님, 2026-07-19 13:30 ~ 2026-07-20 09:00 |

### TC-DIARY-DATE-TIME-INPUT-FEATURE-003: 처음 사용하도록 전환하면 오늘부터 오늘까지의 종일 기간이 선택된다

- 근거: `feature > 사용 여부 전환`, `domain > 기본값`
- Given: 초기 기간이 제공되지 않아 날짜·시간 입력을 사용하지 않는 상태다.
- When: 사용자가 처음으로 날짜·시간 입력을 사용하도록 전환한다.
- Then: 오늘부터 오늘까지의 종일 기간이 선택된다.

### TC-DIARY-DATE-TIME-INPUT-FEATURE-004: 사용을 껐다가 다시 켜면 직전 선택값이 복원된다

- 근거: `feature > 사용 여부 전환`, `domain > 상태 유지`
- Given: 날짜·시간 입력을 사용하고 있고 오늘이 아닌 날짜의 기간이 선택되어 있다.
- When: 사용자가 날짜·시간 입력을 사용하지 않도록 전환했다가 다시 사용하도록 전환한다.
- Then: 끄기 직전에 선택했던 종일 여부와 시작·종료 값이 그대로 복원된다.

### TC-DIARY-DATE-TIME-INPUT-FEATURE-035: 사용처가 제공하는 초기 기간이 바뀌면 바뀐 초기 기간으로 처음부터 시작한다

- 근거: `domain > 기본값`
- Given: 초기 기간이 제공된 컴포넌트가 표시되어 있고, 사용자가 날짜·시간 입력을 사용하지 않도록 전환해 두었다.
- When: 사용처가 제공하는 초기 기간이 다른 종일 기간으로 바뀐다.
- Then: 날짜·시간 입력을 사용하는 상태가 되고 바뀐 초기 기간의 종일 여부와 시작·종료가 선택되며, 사용자가 전환해 둔 상태는 이어지지 않는다.

### TC-DIARY-DATE-TIME-INPUT-FEATURE-030: 하루짜리 종일 기간을 해제하면 시작이 기본 시각, 종료가 1시간 뒤가 된다

- 근거: `feature > 종일 여부 전환`, `domain > 기본 시각`, `domain > 종일 전환 시 시간 처리`
- Given: 현재 시각이 테스트 데이터의 값이고, 날짜·시간 입력을 사용하고 있으며 시작일과 종료일이 같은 종일 기간이 선택되어 있다.
- When: 사용자가 종일이 아닌 기간으로 전환한다.
- Then: 시작이 기존 날짜의 테스트 데이터 시작 시각으로, 종료가 테스트 데이터의 종료 날짜와 시각으로 선택된다.
- 테스트 데이터:

| 현재 시각 | 기대 시작 시각 | 기대 종료 |
| --- | --- | --- |
| 오후 1:43 | 오후 2:00 | 같은 날 오후 3:00 |
| 오후 2:13 | 오후 2:30 | 같은 날 오후 3:30 |
| 오후 2:00 | 오후 2:00 | 같은 날 오후 3:00 |
| 오후 2:30 | 오후 2:30 | 같은 날 오후 3:30 |
| 오후 11:00 | 오후 11:00 | 다음 날 오전 12:00 |
| 오후 11:30 | 오후 11:30 | 다음 날 오전 12:30 |
| 오후 11:31 | 오전 12:00 | 같은 날 오전 1:00 |

### TC-DIARY-DATE-TIME-INPUT-FEATURE-031: 여러 날짜의 종일 기간을 해제하면 두 날짜가 유지되고 시각이 모두 기본 시각이 된다

- 근거: `feature > 종일 여부 전환`, `domain > 종일 전환 시 시간 처리`
- Given: 현재 시각이 오후 1시 43분이고, 날짜·시간 입력을 사용하고 있으며 시작일과 종료일이 서로 다른 종일 기간이 선택되어 있다.
- When: 사용자가 종일이 아닌 기간으로 전환한다.
- Then: 기존 시작일과 종료일이 그대로 유지되고 시작과 종료의 시간이 모두 오후 2시로 선택된다.

### TC-DIARY-DATE-TIME-INPUT-FEATURE-006: 종일로 전환하면 시간 정보가 버려진다

- 근거: `feature > 종일 여부 전환`, `domain > 종일 전환 시 시간 처리`
- Given: 날짜·시간 입력을 사용하고 있고 종일이 아닌 기간이 선택되어 있다.
- When: 사용자가 종일 기간으로 전환한다.
- Then: 기존 시작일과 종료일은 유지되고 시간 정보는 버려진다.

### TC-DIARY-DATE-TIME-INPUT-FEATURE-032: 종일로 전환한 뒤 다시 해제하면 시간이 기본 시각에서 다시 시작한다

- 근거: `domain > 종일 전환 시 시간 처리`
- Given: 현재 시각이 오후 1시 43분이고, 날짜·시간 입력을 사용하고 있으며 기본 시각이 아닌 시간과 같은 시작일·종료일을 가진 종일 아닌 기간이 선택되어 있다.
- When: 사용자가 종일 기간으로 전환했다가 다시 종일이 아닌 기간으로 전환한다.
- Then: 시작이 오후 2시로, 종료가 같은 날 오후 3시로 선택된다.

### TC-DIARY-DATE-TIME-INPUT-FEATURE-034: 시간이 흐른 뒤 종일을 해제하면 그 시점의 기본 시각을 사용한다

- 근거: `domain > 기본 시각`
- Given: 현재 시각이 오후 1시 43분일 때 컴포넌트가 표시되었고, 시작일과 종료일이 같은 기간에서 종일을 해제했다가 다시 종일로 되돌렸다.
- When: 현재 시각이 오후 4시 10분이 된 뒤 사용자가 다시 종일이 아닌 기간으로 전환한다.
- Then: 시작이 오후 4시 30분으로, 종료가 같은 날 오후 5시 30분으로 선택된다.

### TC-DIARY-DATE-TIME-INPUT-FEATURE-009: 날짜 선택을 확인하면 고른 날짜가 반영된다

- 근거: `feature > 날짜와 시간 선택`
- Given: 날짜·시간 입력을 사용하고 있고 기간이 선택되어 있다.
- When: 사용자가 시작 또는 종료에 기간 관계를 유지하는 다른 날짜를 고르고 선택을 확인한다.
- Then: 해당 시작일 또는 종료일이 고른 날짜로 바뀐다.

### TC-DIARY-DATE-TIME-INPUT-FEATURE-010: 날짜 선택을 취소하면 기존 값이 유지된다

- 근거: `feature > 날짜와 시간 선택`
- Given: 날짜·시간 입력을 사용하고 있고 시작 또는 종료의 다른 날짜를 골라 둔 상태다.
- When: 사용자가 날짜 선택을 취소한다.
- Then: 해당 시작일 또는 종료일이 기존 날짜를 유지한다.

### TC-DIARY-DATE-TIME-INPUT-FEATURE-012: 시간 선택을 확인하면 고른 시간이 반영된다

- 근거: `feature > 날짜와 시간 선택`
- Given: 날짜·시간 입력을 사용하고 있고 종일이 아닌 기간이 선택되어 있다.
- When: 사용자가 시작 또는 종료에 기간 관계를 유지하는 다른 시간을 고르고 선택을 확인한다.
- Then: 해당 시작 또는 종료의 시간이 고른 시간으로 바뀐다.

### TC-DIARY-DATE-TIME-INPUT-FEATURE-013: 시간 선택을 취소하면 기존 값이 유지된다

- 근거: `feature > 날짜와 시간 선택`
- Given: 날짜·시간 입력을 사용하고 있고 시작 또는 종료의 다른 시간을 골라 둔 상태다.
- When: 사용자가 시간 선택을 취소한다.
- Then: 해당 시작 또는 종료의 시간이 기존 값을 유지한다.

### TC-DIARY-DATE-TIME-INPUT-FEATURE-014: 시작을 종료보다 뒤로 선택하면 종료가 시작에 맞춰진다

- 근거: `feature > 기간 자동 보정`, `domain > 기간의 개념`
- Given: 날짜·시간 입력을 사용하고 있고 테스트 데이터의 기간이 선택되어 있다.
- When: 사용자가 시작을 테스트 데이터의 값으로 변경한다.
- Then: 종료가 변경된 시작과 같은 값으로 표시된다.
- 테스트 데이터:

| 종일 여부 | 기존 기간 | 변경한 시작 | 기대 종료 |
| --- | --- | --- | --- |
| 종일 | 2026-07-19 ~ 2026-07-20 | 2026-07-25 | 2026-07-25 |
| 종일 아님 | 2026-07-19 13:30 ~ 2026-07-20 09:00 | 2026-07-20 10:00 (시간 변경) | 2026-07-20 10:00 |

### TC-DIARY-DATE-TIME-INPUT-FEATURE-015: 종료를 시작보다 앞으로 선택하면 시작이 종료에 맞춰진다

- 근거: `feature > 기간 자동 보정`, `domain > 기간의 개념`
- Given: 날짜·시간 입력을 사용하고 있고 테스트 데이터의 기간이 선택되어 있다.
- When: 사용자가 종료를 테스트 데이터의 값으로 변경한다.
- Then: 시작이 변경된 종료와 같은 값으로 표시된다.
- 테스트 데이터:

| 종일 여부 | 기존 기간 | 변경한 종료 | 기대 시작 |
| --- | --- | --- | --- |
| 종일 | 2026-07-19 ~ 2026-07-20 | 2026-07-15 | 2026-07-15 |
| 종일 아님 | 2026-07-19 13:30 ~ 2026-07-20 09:00 | 2026-07-19 09:00 (시간 변경) | 2026-07-19 09:00 |

### TC-DIARY-DATE-TIME-INPUT-FEATURE-018: 화면이 재생성되어도 선택 상태가 유지된다

- 근거: `domain > 상태 유지`
- Given: 날짜·시간 입력을 사용하고 있고 종일이 아닌 기간이 선택되어 있다.
- When: 화면 재생성이 일어난다.
- Then: 사용 여부, 종일 여부, 시작·종료 값이 재생성 전과 동일하게 유지된다.

### TC-DIARY-DATE-TIME-INPUT-FEATURE-022: 고르는 중에 화면이 재생성되어도 같은 대상의 고르기가 열린 채로 유지된다

- 근거: `domain > 상태 유지`
- Given: 날짜·시간 입력을 사용하고 있고 테스트 데이터의 종일 여부로 시작과 종료가 서로 다른 기간이 선택되어 있다.
- When: 사용자가 테스트 데이터의 대상을 눌러 고르기를 연 뒤 화면 재생성이 일어난다.
- Then: 고르기가 열린 상태로 표시되고 그 안에는 재생성 전에 열었던 대상의 현재 값이 선택되어 있으며, 선택한 기간은 바뀌지 않는다.
- 테스트 데이터:

| 종일 여부 | 고르는 대상 |
| --- | --- |
| 종일 | 시작 날짜 |
| 종일 | 종료 날짜 |
| 종일 아님 | 시작 시간 |
| 종일 아님 | 종료 시간 |

### TC-DIARY-DATE-TIME-INPUT-FEATURE-021: 사용을 끄면 기간을 조작할 수 없다

- 근거: `feature > 사용 여부 전환`
- Given: 날짜·시간 입력을 사용하고 있고 기간이 선택되어 있다.
- When: 사용자가 날짜·시간 입력을 사용하지 않도록 전환한다.
- Then: 기간을 조작할 수 없다.

## domain

### TC-DIARY-DATE-TIME-INPUT-DOMAIN-001: 사용하지 않는 상태에서는 기간이 선택되지 않은 것으로 취급된다

- 근거: `feature > 사용 여부 전환`, `domain > 상태 유지`
- Given: 기간을 선택한 뒤 날짜·시간 입력을 사용하지 않도록 전환했다.
- When: 사용처가 컴포넌트의 선택 결과를 확인한다.
- Then: 선택된 기간이 없는 것으로 확인된다.

### TC-DIARY-DATE-TIME-INPUT-DOMAIN-002: 사용처가 기간을 채우면 채운 기간이 그대로 선택된다

- 근거: `domain > 사용처가 채우는 기간`
- Given: 컴포넌트가 테스트 데이터의 채우기 전 상태로 표시되어 있다.
- When: 사용처가 테스트 데이터의 기간을 채운다.
- Then: 날짜·시간 입력을 사용하는 상태가 되고, 선택 결과의 종일 여부와 시작·종료가 채운 기간과 같다. 자동 보정이나 기본 시각으로 바뀐 값이 없다.
- 테스트 데이터:

| 채우기 전 상태 | 채우는 기간 |
| --- | --- |
| 사용 중, 종일 아님, 다음 날 10:00 ~ 11:00 | 종일 아님, 오늘 13:00 ~ 15:00 (이전 기간보다 앞섬) |
| 사용 중, 종일 아님, 오늘 20:00 ~ 21:00 | 종일 아님, 2일 뒤 09:00 ~ 3일 뒤 08:00 (이전 기간보다 뒤) |
| 사용하지 않음, 종일, 현재 시각 09:40 | 종일 아님, 오늘 13:00 ~ 15:00 |
| 사용 중, 종일 아님 | 종일, 이전 기간보다 앞선 날짜 범위 |
