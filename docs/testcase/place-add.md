# PlaceAdd 테스트 케이스

기준 스펙: [PlaceAdd 화면 스펙](../spec/place-add.md)

이 문서에서 `data > 동기화`, `data > 저장 실패`, `domain > 추가 요청 제한`, `domain > 추가되는 항목의 태그 연결`, `domain > 태그 선택과 추가 성립 조건`, `domain > 항목의 계정 연결`, `feature > 뒤로가기`, `feature > 작성 상태 유지`, `feature > 태그 입력` 절은 [항목 추가 화면 공통 스펙](../spec/entity-add.md)이 소유한다. 나머지 케이스의 절은 기준 스펙이 소유한다.

PlaceHome에서 장소 추가를 선택해 PlaceAdd로 이동하고 보고 있던 지도 위치를 넘기는 케이스는 [PlaceHome 테스트 케이스](./place-home.md)에서, 메모 장소 카드에서 같은 방식으로 이동하며 지도 위치를 넘기는 케이스는 [메모 장소 카드 테스트 케이스](./memo-place-card.md)에서 다룬다. 저장한 장소의 상세 확인과 수정·삭제 케이스는 [PlaceDetail 테스트 케이스](./place-detail.md)에서 다룬다. 지도 표시, 지도 제공자 전환, 지점 선택 자체의 케이스는 [DiaryMap 테스트 케이스](./diary-map.md)에서 다룬다. 설명과 컬러 입력 자체의 케이스는 [설명 입력 테스트 케이스](./description-input.md)와 [DiaryColorInput 테스트 케이스](./diary-color-input.md)에서 다룬다.

태그 입력의 표시와 조작, 태그 선택 목록의 케이스는 [항목 태그 입력 컴포넌트 테스트 케이스](./entity-tag-input.md)에서 다룬다. 이 문서에는 PlaceAdd 화면에서만 다른 시작 상태와 추가 결과의 케이스만 둔다.

## feature

### TC-PLACE-ADD-FEATURE-001: 화면에 처음 진입하면 무작위 컬러가 제시되고 좌표는 비어 있다

- 근거: `feature > 진입과 입력`
- Given: 사용자가 장소 추가를 선택했다.
- When: PlaceAdd 화면이 처음 표시된다.
- Then: 제목, 설명과 주소가 비어 있고, 위도와 경도가 비어 있으며, 컬러에는 무작위 값이 제시된다.

### TC-PLACE-ADD-FEATURE-002: 제목, 설명, 주소, 좌표와 컬러를 입력할 수 있다

- 근거: `feature > 진입과 입력`
- Given: PlaceAdd 화면이 표시되어 있다.
- When: 사용자가 제목, 설명, 주소, 위도, 경도를 입력하고 컬러를 고른다.
- Then: 입력한 제목, 설명, 주소, 위도, 경도와 고른 컬러가 화면에 그대로 표시된다.

### TC-PLACE-ADD-FEATURE-003: 좌표에 음수와 소수점을 입력할 수 있다

- 근거: `feature > 진입과 입력`
- Given: PlaceAdd 화면이 표시되어 있다.
- When: 사용자가 위도와 경도에 음수 기호와 소수점을 포함한 값을 입력한다.
- Then: 입력한 값이 그대로 표시된다.

### TC-PLACE-ADD-FEATURE-004: 추가에 성공하면 다음 장소를 작성할 수 있는 상태로 초기화한다

- 근거: `feature > 장소 추가`
- Given: 장소 추가가 성공하도록 설정되어 있고, 제목과 설명, 주소, 위도와 경도를 입력하고 컬러를 선택한 상태다.
- When: 사용자가 장소 추가를 실행한다.
- Then: PlaceAdd 화면이 유지되고 제목, 설명, 주소, 위도, 경도가 비워지며 다음 장소를 위한 새 무작위 컬러가 제시된다.

### TC-PLACE-ADD-FEATURE-005: 추가에 성공하면 성공 피드백을 제공한다

- 근거: `feature > 장소 추가`
- Given: 장소 추가가 성공하도록 설정되어 있고, 공백이 아닌 제목과 유효한 좌표가 입력되어 있다.
- When: 사용자가 장소 추가를 실행한다.
- Then: 장소가 추가되었다는 성공 피드백이 제공된다.

### TC-PLACE-ADD-FEATURE-006: 추가를 처리하는 동안 진행 상태를 표시한다

- 근거: `feature > 장소 추가`
- Given: 장소 추가 처리가 완료되지 않고 진행 중인 상태로 설정되어 있고, 공백이 아닌 제목과 유효한 좌표가 입력되어 있다.
- When: 사용자가 장소 추가를 실행한 뒤 화면을 확인한다.
- Then: 추가 처리가 끝날 때까지 진행 상태가 표시된다.

### TC-PLACE-ADD-FEATURE-007: 제목을 입력하지 않으면 작성 내용을 유지한다

- 근거: `feature > 제목 미입력`
- Given: 제목이 테스트 데이터의 상태이고, 설명, 주소와 유효한 좌표를 입력하고 컬러를 선택한 PlaceAdd 화면이 표시되어 있다.
- When: 사용자가 장소 추가를 실행한다.
- Then: 장소가 추가되지 않고 설명, 주소, 위도, 경도와 컬러가 지워지거나 바뀌지 않는다.
- 테스트 데이터:

| 제목 상태 |
| --- |
| 비어 있음 |
| 공백 문자만 입력됨 |

### TC-PLACE-ADD-FEATURE-008: 제목이 없으면 제목 입력 필요 피드백을 제공한다

- 근거: `feature > 제목 미입력`
- Given: 제목이 비어 있거나 공백 문자만 입력되어 있고 유효한 좌표가 입력되어 있다.
- When: 사용자가 장소 추가를 실행한다.
- Then: 제목 입력이 필요하다는 피드백이 제공된다.

### TC-PLACE-ADD-FEATURE-009: 좌표가 성립하지 않으면 좌표 오류 피드백을 제공한다

- 근거: `feature > 좌표 오류`
- Given: 공백이 아닌 제목이 입력되어 있고, 위도와 경도가 테스트 데이터의 상태다.
- When: 사용자가 장소 추가를 실행한다.
- Then: 장소가 추가되지 않고 위도와 경도의 유효 범위를 알리는 같은 피드백이 제공된다.
- 테스트 데이터:

| 위도 | 경도 |
| --- | --- |
| 비어 있음 | 비어 있음 |
| `37.5` | 비어 있음 |
| 비어 있음 | `127.0` |
| `abc` | `127.0` |
| `37.5` | `--1` |
| `90.1` | `127.0` |
| `-90.1` | `127.0` |
| `37.5` | `180.1` |
| `37.5` | `-180.1` |

### TC-PLACE-ADD-FEATURE-010: 좌표가 성립하지 않아도 작성 내용을 유지한다

- 근거: `feature > 좌표 오류`
- Given: 공백이 아닌 제목, 설명과 주소를 입력하고 컬러를 선택했으며, 위도가 테스트 데이터의 값이다.
- When: 사용자가 장소 추가를 실행한다.
- Then: 장소가 추가되지 않고 제목, 설명, 주소, 위도, 경도와 컬러가 지워지거나 바뀌지 않는다.
- 테스트 데이터:

| 위도 |
| --- |
| `abc` |
| `90.1` |

### TC-PLACE-ADD-FEATURE-013: 화면이 재생성되어도 작성 중인 내용을 유지한다

- 근거: `feature > 작성 상태 유지`
- Given: PlaceAdd 화면에서 제목, 설명, 주소, 위도, 경도를 입력하고 컬러를 선택한 상태다.
- When: 시스템이 화면을 재생성한다.
- Then: 재생성 전의 제목, 설명, 주소, 위도, 경도와 선택한 컬러가 그대로 표시된다.

### TC-PLACE-ADD-FEATURE-014: 앱을 다시 실행한 뒤 새로 진입하면 새로운 입력 상태로 시작한다

- 근거: `feature > 작성 상태 유지`
- Given: PlaceAdd 화면에서 제목, 설명과 좌표를 입력한 뒤 앱을 종료했다.
- When: 사용자가 앱을 다시 실행하고 PlaceAdd 화면에 새로 진입한다.
- Then: 이전 제목, 설명과 좌표는 표시되지 않고 새로운 무작위 컬러가 제시된다.
- 작성하지 않는 이유: 실제 앱 종료와 재실행을 결정적으로 제어할 수 있는 테스트 환경이 필요하다.

### TC-PLACE-ADD-FEATURE-015: 뒤로가면 이전 화면으로 돌아간다

- 근거: `feature > 뒤로가기`
- Given: PlaceAdd 화면이 표시되어 있다.
- When: 사용자가 뒤로간다.
- Then: PlaceAdd 화면에 진입하기 전 화면으로 돌아간다.

### TC-PLACE-ADD-FEATURE-016: 지도에서 위치를 고르면 위도와 경도가 채워진다

- 근거: `feature > 지도에서 좌표 선택`
- Given: 위도와 경도가 비어 있는 PlaceAdd 화면이 표시되어 있다.
- When: 사용자가 지도에서 테스트 데이터의 위도와 경도에 해당하는 위치를 고른다.
- Then: 위도 입력과 경도 입력에 고른 위치의 위도와 경도가 함께 채워진다.
- 테스트 데이터:

| 고른 위도 | 고른 경도 |
| --- | --- |
| 서울 도심의 위도 | 서울 도심의 경도 |
| 남반구 도시의 위도 | 서반구 도시의 경도 |
- 작성하지 않는 이유: 현재 호스트 테스트 환경은 지도 제공자의 실제 표시 요소와 지도 누르기 입력을 제공하지 않아 지도가 붙은 PlaceAdd 화면을 결정적으로 구성할 수 없다. 지도 표시와 지도 입력을 대체할 수 있는 테스트 환경이 제공되면 자동화한다.

### TC-PLACE-ADD-FEATURE-017: 지도에서 다른 위치를 고르면 좌표가 새 위치로 바뀐다

- 근거: `feature > 지도에서 좌표 선택`
- Given: 사용자가 지도에서 한 위치를 골라 위도와 경도가 그 위치의 값으로 채워져 있다.
- When: 사용자가 지도에서 다른 위치를 고른다.
- Then: 위도와 경도가 새로 고른 위치의 값으로 바뀌고, 고른 지점은 하나만 남는다.
- 작성하지 않는 이유: 현재 호스트 테스트 환경은 지도 제공자의 실제 표시 요소와 지도 누르기 입력을 제공하지 않아 지도가 붙은 PlaceAdd 화면을 결정적으로 구성할 수 없다. 지도 표시와 지도 입력을 대체할 수 있는 테스트 환경이 제공되면 자동화한다.

### TC-PLACE-ADD-FEATURE-018: 지도에서 고친 좌표를 이어서 직접 고칠 수 있다

- 근거: `feature > 지도에서 좌표 선택`
- Given: 사용자가 지도에서 위치를 골라 위도와 경도가 채워져 있다.
- When: 사용자가 위도 입력의 값을 다른 값으로 고친다.
- Then: 고친 값이 위도 입력에 그대로 표시되고 경도 입력의 값은 바뀌지 않는다.
- 작성하지 않는 이유: 현재 호스트 테스트 환경은 지도 제공자의 실제 표시 요소와 지도 누르기 입력을 제공하지 않아 지도가 붙은 PlaceAdd 화면을 결정적으로 구성할 수 없다. 지도 표시와 지도 입력을 대체할 수 있는 테스트 환경이 제공되면 자동화한다.

### TC-PLACE-ADD-FEATURE-019: 지도에서 고른 좌표로 장소를 추가한다

- 근거: `feature > 지도에서 좌표 선택`, `feature > 장소 추가`

- When: 사용자가 지도에서 한 위치를 고른 뒤 장소 추가를 실행한다.

- 작성하지 않는 이유: 현재 호스트 테스트 환경은 지도 제공자의 실제 표시 요소와 지도 누르기 입력을 제공하지 않아 지도가 붙은 PlaceAdd 화면을 결정적으로 구성할 수 없다. 지도 표시와 지도 입력을 대체할 수 있는 테스트 환경이 제공되면 자동화한다.
