# FileAdd 테스트 케이스

기준 스펙: [FileAdd 화면 스펙](../spec/client/file-add.md)

## feature

### TC-FILE-ADD-FEATURE-001: 처음 진입하면 비어 있는 입력으로 시작하고 제목에 초점을 둔다

- 근거: `feature > 진입`
- Given: 사용자 언어가 한국어이고 계정 상태가 사용자다.
- When: 사용자가 FileAdd 화면에 들어온다.
- Then: 상단 바에 `파일 추가` 제목이 표시되고, 제목과 설명이 비어 있으며, 파일 카드에 `고른 파일 없음`이 표시되고, 입력 초점이 제목 입력에 있다.

### TC-FILE-ADD-FEATURE-002: 파일을 고르면 이름과 크기를 표시한다

- 근거: `feature > 파일 고르기`
- Given: 사용자 언어가 한국어이고 FileAdd 화면이 표시되어 있으며, 기기가 테스트 데이터의 이름과 크기를 알려 주는 파일이 있다.
- When: 사용자가 `파일 고르기`를 선택해 그 파일을 고른다.
- Then: 파일 카드에 테스트 데이터의 이름과 크기가 표시된다.
- 테스트 데이터:

| 이름 | 크기 | 표시되는 크기 |
| --- | --- | --- |
| `보고서.pdf` | 1,024바이트 | `1.0 KB` |
| `빈 파일.txt` | 0바이트 | `0 B` |

### TC-FILE-ADD-FEATURE-003: 이미 고른 파일이 있어도 다시 고르면 새 파일로 바뀐다

- 근거: `feature > 파일 고르기`
- Given: FileAdd 화면에서 `a.txt`를 골라 두었다.
- When: 사용자가 `파일 고르기`를 선택해 `b.txt`를 고른다.
- Then: 파일 카드에 `b.txt`가 표시된다.

### TC-FILE-ADD-FEATURE-004: 파일을 고르지 않고 선택 도구를 닫으면 고른 파일이 바뀌지 않는다

- 근거: `feature > 파일 고르기`
- Given: FileAdd 화면에서 고른 파일이 테스트 데이터와 같다.
- When: 사용자가 `파일 고르기`를 선택한 뒤 파일을 고르지 않고 선택 도구를 닫는다.
- Then: 파일 카드가 테스트 데이터의 표시 그대로 남고, 안내가 표시되지 않는다.
- 테스트 데이터:

| 고른 파일 | 파일 카드 |
| --- | --- |
| 없음 | `고른 파일 없음` |
| `a.txt` | `a.txt` |

### TC-FILE-ADD-FEATURE-005: 고를 수 없는 파일을 고르면 이유를 알리고 이전 선택을 둔다

- 근거: `feature > 파일 고르기`, `domain > 고를 수 있는 파일`
- Given: 사용자 언어가 한국어이고 FileAdd 화면에서 `a.txt`를 골라 두었다.
- When: 사용자가 `파일 고르기`를 선택해 테스트 데이터의 파일을 고른다.
- Then: 테스트 데이터의 안내가 표시되고, 파일 카드에는 `a.txt`가 그대로 표시된다.
- 테스트 데이터:

| 고른 파일 | 안내 |
| --- | --- |
| 이름이나 크기를 읽을 수 없는 파일 | `파일을 읽지 못했습니다.` |
| 크기가 52,428,801바이트인 파일 | `50MB 이하 파일만 올릴 수 있습니다.` |

### TC-FILE-ADD-FEATURE-006: 제목 없이 올리기를 실행하면 제목을 요청하고 초점을 옮긴다

- 근거: `feature > 올리기 실행`, `domain > 올리기 성립 조건`
- Given: 사용자 언어가 한국어이고 FileAdd 화면에서 제목이 테스트 데이터와 같으며, 설명 `메모`를 적고 `a.txt`를 골라 두었다.
- When: 사용자가 올리기를 실행한다.
- Then: 올리기를 시작하지 않고, `제목을 입력해 주세요.` 안내가 표시되며, 입력 초점이 제목 입력으로 옮겨지고, 제목, 설명 `메모`와 `a.txt`는 그대로 남는다.
- 테스트 데이터:

| 제목 |
| --- |
| 빈 값 |
| 공백 두 칸 |

### TC-FILE-ADD-FEATURE-007: 파일 없이 올리기를 실행하면 파일을 요청한다

- 근거: `feature > 올리기 실행`, `domain > 올리기 성립 조건`
- Given: 사용자 언어가 한국어이고 FileAdd 화면에서 제목 `회의록`과 설명 `메모`를 적었고 고른 파일이 없다.
- When: 사용자가 올리기를 실행한다.
- Then: 올리기를 시작하지 않고, `파일을 골라 주세요.` 안내가 표시되며, 제목 `회의록`과 설명 `메모`는 그대로 남는다.

### TC-FILE-ADD-FEATURE-008: 제목도 파일도 없으면 제목을 먼저 요청한다

- 근거: `domain > 올리기 성립 조건`
- Given: 사용자 언어가 한국어이고 FileAdd 화면에서 제목이 비어 있고 고른 파일이 없다.
- When: 사용자가 올리기를 실행한다.
- Then: `제목을 입력해 주세요.` 안내가 표시되고 `파일을 골라 주세요.` 안내는 표시되지 않는다.

### TC-FILE-ADD-FEATURE-009: 올리기를 시작하면 입력을 비우고 제목에 초점을 옮기며 화면을 유지한다

- 근거: `feature > 올리기 실행`
- Given: FileAdd 화면에서 제목 `회의록`, 설명 `메모`를 적고 `a.txt`를 골랐으며, 올리는 중인 파일이 없다.
- When: 사용자가 올리기를 실행한다.
- Then: `a.txt`를 제목 `회의록`, 설명 `메모`로 올리는 요청이 한 번 시작되고, 화면은 닫히지 않으며, 제목과 설명이 비고 파일 카드에 `고른 파일 없음`이 표시되고, 입력 초점이 제목 입력으로 옮겨지며, 안내는 표시되지 않는다.

### TC-FILE-ADD-FEATURE-010: 설명을 미리보기로 보던 중 올리기를 시작하면 설명 입력 상태로 돌아간다

- 근거: `feature > 올리기 실행`
- Given: FileAdd 화면에서 제목 `회의록`, 설명 `# 메모`를 적고 설명 미리보기를 보고 있으며 `a.txt`를 골랐다.
- When: 사용자가 올리기를 실행한다.
- Then: 설명이 비고 설명 입력이 입력 상태로 표시된다.

### TC-FILE-ADD-FEATURE-011: 올리는 중에는 진행 표시를 보이고 올리기를 실행할 수 없다

- 근거: `feature > 올리는 중`, `domain > 올리기 성립 조건`
- Given: 테스트 데이터의 올리기가 아직 끝나지 않았고, FileAdd 화면에서 제목 `다음`을 적고 `b.txt`를 골라 두었다.
- When: 사용자가 올리기를 실행한다.
- Then: 올리기 자리에 진행 중 표시가 나타나 있고, 새 올리기를 요청하지 않으며, 제목 `다음`과 `b.txt`는 그대로 남는다.
- 테스트 데이터:

| 끝나지 않은 올리기 |
| --- |
| 이 화면에서 시작한 올리기 |
| 화면에 들어오기 전에 시작한 올리기 |

### TC-FILE-ADD-FEATURE-012: 올리는 중에도 입력하고 파일을 고를 수 있다

- 근거: `feature > 올리는 중`
- Given: 파일을 올리는 중이고 FileAdd 화면이 표시되어 있다.
- When: 사용자가 제목 `다음`을 입력하고 `b.txt`를 고른다.
- Then: 제목 입력에 `다음`이, 파일 카드에 `b.txt`가 표시된다.

### TC-FILE-ADD-FEATURE-013: 화면을 보고 있는 동안 올리기가 끝나면 결과를 알리고 적어 둔 내용은 둔다

- 근거: `feature > 올리기 결과`
- Given: 사용자 언어가 한국어이고 파일을 올리는 중이며, FileAdd 화면에서 제목 `다음`을 적고 `b.txt`를 골라 두었다.
- When: 올리기가 테스트 데이터의 결과로 끝난다.
- Then: 테스트 데이터의 안내가 표시되고, 진행 중 표시가 사라지며, 제목 `다음`과 `b.txt`는 그대로 남는다.
- 테스트 데이터:

| 결과 | 안내 |
| --- | --- |
| 성공 | `파일을 올렸습니다.` |
| 크기 초과로 실패 | `50MB 이하 파일만 올릴 수 있습니다.` |
| 그 밖의 이유로 실패 | `파일을 올리지 못했습니다.` |

### TC-FILE-ADD-FEATURE-014: 올리는 동안 계정이 바뀌어 중단되면 결과를 알리지 않는다

- 근거: `feature > 올리기 결과`
- Given: FileAdd 화면을 보는 동안 계정 A로 파일을 올리는 중이다.
- When: 계정 상태가 계정 B의 사용자로 바뀌어 올리기가 중단된다.
- Then: 진행 중 표시가 사라지고, 올리기 결과를 알리는 안내가 표시되지 않는다.

### TC-FILE-ADD-FEATURE-015: 계정 상태가 바뀌면 상태에 따라 화면을 닫거나 유지한다

- 근거: `feature > 계정 상태`
- Given: FileAdd 화면에서 제목 `회의록`을 적고 `a.txt`를 골라 두었다.
- When: 계정 상태가 테스트 데이터의 상태로 바뀐다.
- Then: 테스트 데이터의 결과가 된다.
- 테스트 데이터:

| 바뀐 계정 상태 | 결과 |
| --- | --- |
| 게스트 | 이전 화면으로 돌아가는 동작이 한 번 실행된다 |
| 계정 B의 사용자 | 화면이 유지되고 제목 `회의록`과 `a.txt`가 그대로 남는다 |
| 게스트·사용자로 확정하지 않음 | 화면이 유지되고 제목 `회의록`과 `a.txt`가 그대로 남는다 |

### TC-FILE-ADD-FEATURE-016: 계정을 확정하지 않은 동안 올리기를 실행하면 올리지 못했다고 알린다

- 근거: `feature > 계정 상태`
- Given: 사용자 언어가 한국어이고 계정 상태가 게스트·사용자로 확정되지 않았으며, FileAdd 화면에서 제목 `회의록`을 적고 `a.txt`를 골라 두었다.
- When: 사용자가 올리기를 실행한다.
- Then: 올리기를 시작하지 않고, `파일을 올리지 못했습니다.` 안내가 표시되며, 제목 `회의록`과 `a.txt`는 그대로 남는다.

### TC-FILE-ADD-FEATURE-017: 뒤로가기를 선택하면 이전 화면으로 돌아간다

- 근거: `feature > 뒤로가기`
- Given: FileAdd 화면이 테스트 데이터의 상태로 표시되어 있다.
- When: 사용자가 뒤로가기를 선택한다.
- Then: 이전 화면으로 돌아가는 동작이 한 번 실행된다. 화면을 떠난 뒤에도 올리기가 이어지는 것은 [파일 보관 테스트 케이스](./file-storage.md)의 TC-FILE-STORAGE-DATA-024가 확인한다.
- 테스트 데이터:

| 상태 |
| --- |
| 올리는 중인 파일이 없다 |
| 파일을 올리는 중이다 |

### TC-FILE-ADD-FEATURE-018: Android에서 붙들어 둘 수 없는 파일을 올리면 올리지 못했다고 알린다

- 근거: `feature > 올리기 결과`, [파일 보관 스펙](../spec/client/file-storage.md)의 `data > 기기에 두는 것`
- Given: 사용자 언어가 한국어이고 FileAdd 화면에서 제목 `회의록`을 적고, 제공하는 앱이 붙들어 두는 것을 허용하지 않는 파일을 골랐다.
- When: 사용자가 올리기를 실행한다.
- Then: `파일을 올리지 못했습니다.` 안내가 표시되고, 진행 중 표시는 남지 않는다.

## domain

### TC-FILE-ADD-DOMAIN-001: 고를 때 통과한 파일도 올리기를 시작한 뒤 다시 확인한다

- 근거: `domain > 고를 수 있는 파일`
- Given: FileAdd 화면에서 1,024바이트로 읽힌 `a.txt`를 골랐고, 그 뒤 `a.txt`의 크기가 52,428,801바이트로 바뀌었다.
- When: 사용자가 제목을 적고 올리기를 실행한다.
- Then: 서버에 요청하지 않고 크기 초과로 올리기가 실패한다.

### TC-FILE-ADD-DOMAIN-002: 제목과 설명을 입력한 그대로 보내고 설명이 없으면 빈 설명으로 보낸다

- 근거: `domain > 올리기 성립 조건`, `data > 올리는 내용`
- Given: FileAdd 화면에서 테스트 데이터의 제목과 설명을 적고 `a.txt`를 골랐다.
- When: 사용자가 올리기를 실행한다.
- Then: 테스트 데이터의 제목과 설명으로 `a.txt`를 올리는 요청이 시작된다.
- 테스트 데이터:

| 제목 | 설명 | 보내는 제목 | 보내는 설명 |
| --- | --- | --- | --- |
| ` 회의록 ` | `첫 줄`, 줄바꿈, `둘째 줄` | ` 회의록 ` | `첫 줄`, 줄바꿈, `둘째 줄` |
| `회의록` | 빈 값 | `회의록` | 빈 값 |

### TC-FILE-ADD-DOMAIN-003: 화면이 재생성되거나 백그라운드에서 돌아와도 입력과 고른 파일을 유지한다

- 근거: `domain > 유지할 사용자 진행 상태`
- Given: FileAdd 화면에서 제목 `회의록`, 설명 `메모`를 적고 설명 미리보기를 보고 있으며 `a.txt`를 골라 두었다.
- When: 테스트 데이터의 일이 일어난 뒤 같은 화면이 다시 표시된다.
- Then: 제목 `회의록`, 설명 `메모`, 설명 미리보기 상태와 `a.txt`가 그대로 표시된다.
- 테스트 데이터:

| 일어난 일 |
| --- |
| 화면이 회전 등으로 재생성된다 |
| 앱이 백그라운드에 갔다가 돌아온다 |

### TC-FILE-ADD-DOMAIN-004: 시스템이 앱을 정리했다가 복원하면 제목과 설명만 되살린다

- 근거: `domain > 유지할 사용자 진행 상태`
- Given: FileAdd 화면에서 제목 `회의록`, 설명 `메모`를 적고 `a.txt`를 골라 두었다.
- When: 앱이 백그라운드에 있는 동안 시스템이 앱을 정리했다가 화면을 복원한다.
- Then: 제목 `회의록`과 설명 `메모`가 표시되고, 파일 카드에는 `고른 파일 없음`이 표시된다.

### TC-FILE-ADD-DOMAIN-005: 파일 선택 도구가 열린 동안 화면이 다시 만들어져도 고른 파일이 고른 파일이 된다

- 근거: `domain > 유지할 사용자 진행 상태`
- Given: Android에서 FileAdd 화면에 제목 `회의록`을 적고 `파일 고르기`를 선택해 파일 선택 도구가 열려 있다.
- When: 테스트 데이터의 일로 화면이 다시 만들어진 뒤 사용자가 선택 도구에서 `a.txt`를 고른다.
- Then: 제목 `회의록`이 남아 있고 파일 카드에 `a.txt`가 표시된다.
- 테스트 데이터:

| 일어난 일 |
| --- |
| 화면이 회전 등으로 재생성된다 |
| 앱이 백그라운드에 있는 동안 시스템이 앱을 정리했다가 다시 만든다 |

### TC-FILE-ADD-DOMAIN-006: 화면을 떠났다가 다시 들어오면 처음 상태로 시작한다

- 근거: `domain > 유지할 사용자 진행 상태`, `feature > 뒤로가기`
- Given: FileAdd 화면에서 제목 `회의록`, 설명 `메모`를 적고 `a.txt`를 골라 둔 뒤 뒤로가 FileHome으로 돌아갔다.
- When: 사용자가 FileAdd 화면에 다시 들어온다.
- Then: 제목과 설명이 비어 있고 파일 카드에 `고른 파일 없음`이 표시된다.

## data

### TC-FILE-ADD-DATA-001: 올리기를 시작한 뒤 입력을 바꿔도 시작할 때의 제목과 설명으로 올린다

- 근거: `data > 올리는 내용`
- Given: FileAdd 화면에서 제목 `회의록`, 설명 `메모`로 `a.txt`의 올리기를 시작했고, 서버가 아직 응답하지 않았다.
- When: 사용자가 제목 입력에 `다른 제목`을 적는다.
- Then: 서버에 보낸 요청의 제목은 `회의록`, 설명은 `메모`다.
