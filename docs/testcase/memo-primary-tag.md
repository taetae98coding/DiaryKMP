# 메모 대표 태그 테스트 케이스

기준 스펙: [메모 대표 태그 스펙](../spec/memo-primary-tag.md)

## domain

### TC-MEMO-PRIMARY-TAG-DOMAIN-001: 대표 태그를 다시 지정하면 이전 대표 태그를 대체한다

- 근거: `domain > 대표 태그`
- Given: 대표 태그로 한 태그가 지정된 메모가 기기에 저장되어 있다.
- When: 같은 메모의 대표 태그를 다른 태그로 지정해 저장한다.
- Then: 조회한 메모의 대표 태그는 새로 지정한 태그 하나이고, 이전에 지정되어 있던 태그는 대표 태그로 남지 않는다.

### TC-MEMO-PRIMARY-TAG-DOMAIN-002: 태그를 삭제해도 그 태그를 대표 태그로 가진 메모의 지정이 유지된다

- 근거: `domain > 삭제와 대표 태그`
- Given: 한 태그가 메모의 대표 태그로 지정되어 있고 두 항목이 모두 기기에 저장되어 있다.
- When: 그 태그를 삭제 상태로 바꾼다.
- Then: 메모를 조회하면 삭제한 태그의 대표 태그 지정이 그대로 남아 있다.

### TC-MEMO-PRIMARY-TAG-DOMAIN-003: 메모를 완료하거나 삭제해도 대표 태그 지정이 유지된다

- 근거: `domain > 삭제와 대표 태그`
- Given: 대표 태그가 지정된 메모가 기기에 저장되어 있다.
- When: 그 메모를 완료하거나 삭제한다.
- Then: 메모를 조회하면 대표 태그 지정이 바뀌지 않고 그대로 남아 있다.
- 테스트 데이터:

| 동작 |
| --- |
| 완료 |
| 다시 시작 |
| 삭제 |

### TC-MEMO-PRIMARY-TAG-DOMAIN-004: 메모의 제목·설명·컬러·기간 수정은 대표 태그를 바꾸지 않는다

- 근거: `domain > 메모 변경과 대표 태그`
- Given: 대표 태그가 지정된 메모가 기기에 저장되어 있다.
- When: 그 메모의 제목, 설명, 컬러, 기간을 다른 내용으로 수정한다.
- Then: 수정한 내용은 반영되고 대표 태그 지정은 수정 전과 같은 태그로 남는다.

### TC-MEMO-PRIMARY-TAG-DOMAIN-005: 캘린더는 대표 태그가 있으면 대표 태그의 컬러로 메모를 표시한다

- 근거: `domain > 캘린더 표시 색상`
- Given: 캘린더에 표시되는 메모가 있고 그 메모의 대표 태그 지정 상태가 아래와 같다.
- When: 캘린더가 그 메모를 색상으로 표시한다.
- Then: 아래 표의 컬러가 사용된다.
- 테스트 데이터:

| 대표 태그 지정 상태 | 사용하는 컬러 |
| --- | --- |
| 지정 없음 | 메모 자신의 컬러 |
| 삭제되지 않은 태그가 지정됨 | 대표 태그의 컬러 |
| 지정된 태그가 기기에 없음 | 메모 자신의 컬러 |
| 지정된 태그가 삭제 상태임 | 메모 자신의 컬러 |

### TC-MEMO-PRIMARY-TAG-DOMAIN-006: 삭제한 태그를 되살려도 대표 태그 지정이 유지된다

- 근거: `domain > 삭제와 대표 태그`
- Given: 한 태그가 메모의 대표 태그로 지정된 채 삭제 상태로 저장되어 있다.
- When: 사용자가 태그 삭제를 실행 취소해 그 태그를 되살린다.
- Then: 메모를 조회하면 되살린 태그가 같은 메모의 대표 태그로 유지되어 있다.

## data

### TC-MEMO-PRIMARY-TAG-DATA-001: 대표 태그는 메모와 함께 저장되고 조회된다

- 근거: `data > 대표 태그의 저장`
- Given: 아래 대표 태그 상태를 가진 메모가 준비되어 있다.
- When: 그 메모를 기기에 저장한 뒤 다시 조회한다.
- Then: 조회한 메모의 대표 태그가 저장한 상태와 같다.
- 테스트 데이터:

| 저장한 대표 태그 | 조회한 대표 태그 |
| --- | --- |
| 지정 없음 | 지정 없음 |
| 태그 하나 지정 | 지정한 그 태그 |

### TC-MEMO-PRIMARY-TAG-DATA-002: 대표 태그가 가리키는 태그가 기기에 없어도 메모가 저장되고 조회된다

- 근거: `data > 내려받기 순서와 표시`
- Given: 기기에 저장되어 있지 않은 태그를 대표 태그로 가진 메모가 준비되어 있다.
- When: 그 메모를 기기에 저장한 뒤 다시 조회한다.
- Then: 메모가 실패 없이 저장되고, 조회한 메모의 대표 태그가 저장한 태그 그대로 남는다.

### TC-MEMO-PRIMARY-TAG-DATA-003: 메모 업로드 요청에 대표 태그가 포함된다

- 근거: `data > 동기화`
- Given: 아래 대표 태그 상태를 가진 메모가 업로드 대기 상태다.
- When: 동기화의 업로드 단계가 진행된다.
- Then: 서버로 보내는 메모 항목에 아래 대표 태그가 함께 담긴다.
- 테스트 데이터:

| 기기의 대표 태그 | 업로드 항목의 대표 태그 |
| --- | --- |
| 지정 없음 | 지정 없음 |
| 태그 하나 지정 | 지정한 그 태그 |

### TC-MEMO-PRIMARY-TAG-DATA-004: 내려받은 메모의 대표 태그가 기기에 반영된다

- 근거: `data > 동기화`
- Given: 서버가 아래 대표 태그를 가진 메모를 응답하도록 제어되어 있고, 그 메모의 서버 수정 시각이 기기보다 늦다.
- When: 동기화의 메모 내려받기가 진행된다.
- Then: 기기에 저장된 그 메모의 대표 태그가 응답의 대표 태그로 반영된다.
- 테스트 데이터:

| 응답의 대표 태그 | 기기에 반영된 대표 태그 |
| --- | --- |
| 지정 없음 | 지정 없음 |
| 태그 하나 지정 | 응답의 그 태그 |

### TC-MEMO-PRIMARY-TAG-DATA-005: 대표 태그는 메모와 같은 종류로만 동기화된다

- 근거: `data > 동기화`
- Given: 대표 태그를 가진 메모가 업로드 대기 상태다.
- When: 동기화의 업로드와 내려받기가 진행된다.
- Then: 대표 태그는 메모 항목에 담겨 오가고, 대표 태그만을 위한 별도 종류의 업로드 요청이나 내려받기 요청, 별도의 내려받기 위치는 발생하지 않는다.

### TC-MEMO-PRIMARY-TAG-DATA-006: 대표 태그가 바뀌면 메모의 수정 시각이 갱신된다

- 근거: `data > 대표 태그의 저장`
- Given: 대표 태그와 수정 시각이 기록된 메모가 기기에 저장되어 있다.
- When: 그 메모의 대표 태그를 다른 태그로 바꾸거나 해제한다.
- Then: 그 메모의 수정 시각이 대표 태그를 바꾼 시점으로 갱신되고, 메모가 업로드 대기 상태가 된다.

### TC-MEMO-PRIMARY-TAG-DATA-007: 연결되지 않은 태그를 대표 태그로 지정한 업로드는 반영되지 않는다

- 근거: `domain > 대표 태그 지정 권한`, `data > 동기화`
- Given: 업로드하는 계정과 연결되어 있지 않은 태그를 대표 태그로 지정한 메모가 업로드 대기 상태다.
- When: 그 메모를 서버에 업로드한다.
- Then: 서버의 메모에 그 대표 태그가 반영되지 않는다.
- 작성하지 않는 이유: 서버 저장소의 연결 검증 규칙이어서 앱의 단위 테스트 환경에서 결정적으로 판정할 수 없다. 서버 정책 테스트 환경이 마련되면 작성한다.
