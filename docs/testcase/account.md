# 계정 조회 테스트 케이스

기준 스펙: [계정 조회 스펙](../spec/client/account.md)

## domain

### TC-ACCOUNT-DOMAIN-001: 저장된 사용자 정보가 없으면 게스트다

- 근거: `domain > 계정 상태 결정 기준`
- Given: 저장된 사용자 정보가 없고, 로그인 세션이 테스트 데이터의 인증 상태다.
- When: 현재 계정 상태를 확인한다.
- Then: 계정이 게스트로 확정된다.
- 테스트 데이터:

| 로그인 세션 인증 상태 |
| --- |
| 인증된 상태 |
| 인증되지 않은 상태 |

### TC-ACCOUNT-DOMAIN-002: 저장된 사용자 정보가 있으면 사용자이며 이메일과 프로필 이미지를 가진다

- 근거: `domain > 계정 상태`, `domain > 계정 상태 결정 기준`
- Given: 이메일과 테스트 데이터의 프로필 이미지를 가진 사용자 정보가 저장되어 있다.
- When: 현재 계정 상태를 확인한다.
- Then: 계정이 사용자로 확정되고, 해당 사용자 정보의 이메일과 프로필 이미지를 그대로 가진다.
- 테스트 데이터:

| 프로필 이미지 |
| --- |
| 프로필 이미지가 있음 |
| 프로필 이미지가 없음 |

### TC-ACCOUNT-DOMAIN-003: 사용자 상태의 세션 갱신 여부는 로그인 세션 인증 여부를 따른다

- 근거: `domain > 세션 갱신 여부`
- Given: 사용자 정보가 저장되어 있고, 로그인 세션이 테스트 데이터의 인증 상태다.
- When: 현재 계정 상태를 확인한다.
- Then: 계정이 사용자로 확정되고, 세션 갱신 여부가 테스트 데이터와 같다.
- 테스트 데이터:

| 로그인 세션 인증 상태 | 세션 갱신 여부 |
| --- | --- |
| 인증된 상태 | 갱신됨 |
| 인증되지 않은 상태 | 갱신되지 않음 |

### TC-ACCOUNT-DOMAIN-004: 두 정보 중 하나라도 확인되기 전에는 계정 상태를 확정하지 않는다

- 근거: `domain > 계정 정보 조합`
- Given: 로그인 세션과 저장된 사용자 정보 중 한쪽만 첫 값을 확인한 상태다.
- When: 현재 계정 상태를 확인한다.
- Then: 계정 상태가 게스트나 사용자로 확정되지 않는다.

### TC-ACCOUNT-DOMAIN-005: 사용자 정보가 저장되면 게스트에서 사용자로 바뀐다

- 근거: `domain > 계정 정보 변화 반영`
- Given: 저장된 사용자 정보가 없어 계정이 게스트로 확정되어 있다.
- When: 사용자 정보가 새로 저장된다.
- Then: 계정 상태가 사용자로 바뀐다.

### TC-ACCOUNT-DOMAIN-006: 사용자 정보가 사라지면 사용자에서 게스트로 바뀐다

- 근거: `domain > 계정 정보 변화 반영`
- Given: 사용자 정보가 저장되어 계정이 사용자로 확정되어 있다.
- When: 저장된 사용자 정보가 사라진다.
- Then: 계정 상태가 게스트로 바뀐다.

### TC-ACCOUNT-DOMAIN-007: 사용자 정보가 유지된 채 세션 인증 여부만 바뀌면 사용자로 유지되고 세션 갱신 여부만 바뀐다

- 근거: `domain > 계정 정보 변화 반영`
- Given: 사용자 정보가 저장되어 있고, 로그인 세션이 인증되지 않은 상태여서 계정이 세션 갱신되지 않은 사용자로 확정되어 있다.
- When: 사용자 정보는 그대로인 채 로그인 세션이 인증된 상태로 바뀐다.
- Then: 계정이 계속 사용자로 유지되고, 세션 갱신 여부만 갱신됨으로 바뀐다.

### TC-ACCOUNT-DOMAIN-008: 계정 정보 확인 중 오류가 발생하면 실패를 알린다

- 근거: `domain > 조회 실패 처리`
- Given: 로그인 세션이나 저장된 사용자 정보를 확인하는 중 오류가 발생한다.
- When: 현재 계정 상태를 확인한다.
- Then: 계정 상태가 확정되지 않고 조회 실패가 전달된다.

## data

### TC-ACCOUNT-DATA-001: 인증 제공자에 사용자 정보가 없으면 저장된 사용자 정보도 없다

- 근거: `data > 저장된 사용자 정보의 출처`
- Given: 인증 제공자에 사용자 정보가 없다.
- When: 저장된 사용자 정보를 확인한다.
- Then: 저장된 사용자 정보가 없다.

### TC-ACCOUNT-DATA-002: 인증 제공자의 사용자 정보를 저장된 사용자 정보로 사용한다

- 근거: `data > 저장된 사용자 정보의 출처`
- Given: 인증 제공자에 계정 구분 값, 이메일, 테스트 데이터의 프로필 이미지를 가진 사용자 정보가 있다.
- When: 저장된 사용자 정보를 확인한다.
- Then: 저장된 사용자 정보가 인증 제공자의 계정 구분 값, 이메일, 프로필 이미지를 그대로 가진다.
- 테스트 데이터:

| 프로필 이미지 |
| --- |
| 프로필 이미지가 있음 |
| 프로필 이미지가 없음 |
