# 공휴일 노출 설정 테스트 케이스

기준 스펙: [공휴일 노출 설정 스펙](../spec/client/holiday-visibility.md)

연도별 공휴일의 저장과 조회 자체는 [기기에 저장한 공휴일 테스트 케이스](./holiday-database.md)에서, 캘린더가 조회한 공휴일을 화면에 표시하는 결과는 [CalendarHome 테스트 케이스](./calendar-home.md)에서 다룬다.

캘린더용 공휴일을 조회하면 숨기지 않은 공휴일만 제공된다.

## domain

### TC-a7ffbff2-87bb-450a-b08d-0ec3cd03753c: 한 번도 고르지 않은 공휴일은 캘린더에 제공된다

- 근거: `domain > 기본 노출`
- Given: 2026년 공휴일로 공휴일 여부가 참인 7월 17일 `제헌절`과 공휴일 여부가 거짓인 7월 20일 `초복`이 저장되어 있고, 노출 설정을 한 번도 고르지 않았다.
- When: 2026년의 캘린더용 공휴일을 조회한다.
- Then: `제헌절`과 `초복`이 모두 제공된다.

### TC-08cfa73e-dc3b-4d9c-a7d5-cf361ac863d0: 같은 이름은 연도가 달라도 하나의 항목으로 적용된다

- 근거: `domain > 노출 설정`
- Given: 2025년과 2026년에 각각 `초복`이 저장되어 있고, `초복`을 숨김으로 골랐다.
- When: 2025년과 2026년의 캘린더용 공휴일을 각각 조회한다.
- Then: 두 연도 모두 `초복`이 제공되지 않는다.

### TC-b6020ac2-ca51-49ef-a009-894019f9ec3c: 이름이 다른 공휴일은 서로 다른 항목으로 적용된다

- 근거: `domain > 노출 설정`
- Given: 2026년 공휴일로 3월 1일 `삼일절`과 3월 2일 `대체공휴일(삼일절)`이 저장되어 있고, `삼일절`만 숨김으로 골랐다.
- When: 2026년의 캘린더용 공휴일을 조회한다.
- Then: `대체공휴일(삼일절)`만 제공되고 `삼일절`은 제공되지 않는다.

### TC-8d52ec80-8f44-46a8-8b24-c5e8763c13b5: 숨긴 공휴일도 황금연휴 계산에는 그대로 사용된다

- 근거: `domain > 노출 설정 적용 범위`
- Given: 2026년 공휴일이 저장되어 있고 그중 한 공휴일이 황금연휴에 포함된다. 그 공휴일을 숨김으로 골랐다.
- When: 2026년의 캘린더용 공휴일과 황금연휴 목록을 각각 조회한다.
- Then: 캘린더용 공휴일에는 그 공휴일이 제공되지 않지만, 황금연휴 목록에는 그 공휴일을 포함한 연휴가 그대로 나온다.

### 작성하지 않는 이유

- 숨긴 공휴일의 이름이 표시되지 않고 날짜 숫자도 강조되지 않는 결과는 캘린더용 공휴일 조회 결과에서 제외되는 것으로 결정되므로, 이름과 날짜 강조를 나눈 별도 케이스를 두지 않는다. 실제 이름 표시와 색상 적용은 [CalendarHome 테스트 케이스](./calendar-home.md)와 그 문서의 작성하지 않는 이유를 따른다.
- 숨긴 공휴일은 캘린더에 표시되지 않아 눌러서 검색을 열 대상이 없다는 규칙은 조회 결과에서 제외되는 결과와 같으므로 별도 케이스로 중복 작성하지 않는다.
- 노출 설정이 화면 재생성 뒤에도 유지되는 규칙은, 재생성된 화면이 기기에 저장된 노출 설정을 다시 조회하는 것과 같으므로 숨김으로 고른 뒤의 조회 결과를 확인하는 TC-f78d63e6-cf9e-45d2-bdc4-7cabe36dbbf5, TC-f31ab00e-4ed7-4b72-9a63-cbc86a39a8cb로 확인하고 별도 케이스로 중복 작성하지 않는다.
- `TC-9ca7d6e5-7702-4b25-ab92-42cbeeb99ae5`은 공백만 다른 이름을 같은 항목으로 합치는 규칙이 스펙에서 사라져 검증할 행동이 없어졌다. 남은 케이스의 ID를 옮기지 않으려고 번호는 비워 둔다.

## data

### TC-f78d63e6-cf9e-45d2-bdc4-7cabe36dbbf5: 숨김으로 고른 공휴일은 이후 조회에서 제외된다

- 근거: `data > 저장 시점과 유지`, `data > 캘린더 공휴일 조회`
- Given: 2026년 공휴일로 `제헌절`과 `초복`이 저장되어 있고, 노출 설정을 한 번도 고르지 않았다.
- When: `초복`을 숨김으로 고른 뒤 2026년의 캘린더용 공휴일을 조회한다.
- Then: `제헌절`만 제공된다.

### TC-f31ab00e-4ed7-4b72-9a63-cbc86a39a8cb: 노출로 되돌린 공휴일은 다시 제공된다

- When: `초복`과 `중복`을 한 번에 숨김으로 고른 뒤 2026년의 캘린더용 공휴일을 조회한다.

### TC-176127a1-5d2b-4d9e-ab70-e87a3846b96e: 조회 중에 노출 설정이 바뀌면 이어서 새 결과를 제공한다

- 근거: `data > 캘린더 공휴일 조회`
- Given: 2026년 공휴일로 `제헌절`과 `초복`이 저장되어 있고 노출 설정을 한 번도 고르지 않은 상태에서, 2026년의 캘린더용 공휴일을 계속 조회하고 있다.

### TC-4c46ba8f-559f-4d1f-a0ef-e3b053a6df0a: 조회 중에 저장된 공휴일이 바뀌면 노출 설정을 반영한 새 결과를 제공한다

- Then: 기존 조회 결과에 이어 `제헌절`만 담긴 결과가 제공된다.

### 작성하지 않는 이유

- 앱을 종료하고 다시 시작한 뒤나 백그라운드에 다녀온 뒤에도 노출 설정이 유지되는 규칙은 실제 저장 영역의 파일이나 브라우저 저장 영역을 닫았다가 다시 열어야 관찰할 수 있어 작성하지 않는다. 한 테스트 안에서 같은 저장 영역을 닫고 다시 열 수 있는 저장소 테스트 환경이 갖춰지면 자동화한다.
- 로그인, 로그아웃, 계정 전환 후에도 노출 설정이 유지되는 규칙은 계정 흐름 전체를 거쳐야 관찰할 수 있어 작성하지 않는다. 로그인 상태 전환과 설정 저장을 함께 실행하는 통합 테스트 환경이 갖춰지면 자동화한다.
- 각 환경에서 노출 설정을 보관하는 영역은 기본 지도 설정과 같은 저장 영역이므로 [SettingMap 테스트 케이스](./setting-map.md)의 TC-ed3a40a4-f5dd-4773-a6c9-98521ec66ec8에서 다루며, 중복 작성하지 않는다.
- 노출 설정을 고르는 화면의 표시와 조작은 [SettingHoliday 테스트 케이스](./setting-holiday.md)에서 다루므로 중복 작성하지 않는다.
