# 공휴일 노출 설정 테스트 케이스

기준 스펙: [공휴일 노출 설정 스펙](../spec/holiday-visibility.md)

연도별 공휴일의 저장과 조회 자체는 [공휴일 로컬 캐시 테스트 케이스](./holiday-database.md)에서, 캘린더가 조회한 공휴일을 화면에 표시하는 결과는 [CalendarHome 테스트 케이스](./calendar-home.md)에서 다룬다.

캘린더용 공휴일을 조회하면 숨기지 않은 공휴일만 제공된다.

## domain

### TC-HOLIDAY-VISIBILITY-DOMAIN-001: 한 번도 고르지 않은 공휴일은 캘린더에 제공된다

- 근거: `domain > 기본 노출`
- Given: 2026년 공휴일로 공휴일 여부가 참인 7월 17일 `제헌절`과 공휴일 여부가 거짓인 7월 20일 `초복`이 저장되어 있고, 노출 설정을 한 번도 고르지 않았다.
- When: 2026년의 캘린더용 공휴일을 조회한다.
- Then: `제헌절`과 `초복`이 모두 제공된다.

### TC-HOLIDAY-VISIBILITY-DOMAIN-002: 같은 key는 연도가 달라도 하나의 항목으로 적용된다

- 근거: `domain > 노출 설정`
- Given: 2025년과 2026년에 각각 `초복`이 저장되어 있고, `초복`을 숨김으로 골랐다.
- When: 2025년과 2026년의 캘린더용 공휴일을 각각 조회한다.
- Then: 두 연도 모두 `초복`이 제공되지 않는다.

### TC-HOLIDAY-VISIBILITY-DOMAIN-003: key가 다른 공휴일은 서로 다른 항목으로 적용된다

- 근거: `domain > 노출 설정`
- Given: 2026년 공휴일로 3월 1일 `삼일절`과 3월 2일 `대체공휴일(삼일절)`이 저장되어 있고, `삼일절`만 숨김으로 골랐다.
- When: 2026년의 캘린더용 공휴일을 조회한다.
- Then: `대체공휴일(삼일절)`만 제공되고 `삼일절`은 제공되지 않는다.

### TC-HOLIDAY-VISIBILITY-DOMAIN-005: 숨긴 공휴일도 황금연휴 계산에는 그대로 사용된다

- 근거: `domain > 노출 설정 적용 범위`
- Given: 2026년 공휴일이 저장되어 있고 그중 한 공휴일이 황금연휴에 포함된다. 그 공휴일을 숨김으로 골랐다.
- When: 2026년의 캘린더용 공휴일과 황금연휴 목록을 각각 조회한다.
- Then: 캘린더용 공휴일에는 그 공휴일이 제공되지 않지만, 황금연휴 목록에는 그 공휴일을 포함한 연휴가 그대로 나온다.

### TC-HOLIDAY-VISIBILITY-DOMAIN-006: 공백만 다른 이름에도 같은 숨김 key를 적용한다

- 근거: `domain > 노출 설정`, `data > 캘린더 공휴일 조회`
- Given: `대체 공휴일` key를 숨김으로 골랐고, 서로 다른 연도에 `대체 공휴일`과 `대체공휴일`이 각각 저장되어 있다.
- When: 두 연도의 캘린더용 공휴일을 각각 조회한다.
- Then: 두 이름의 공휴일 모두 제공되지 않는다.

### 작성하지 않는 이유

- 숨긴 공휴일의 이름이 표시되지 않고 날짜 숫자도 강조되지 않는 결과는 캘린더용 공휴일 조회 결과에서 제외되는 것으로 결정되므로, 이름과 날짜 강조를 나눈 별도 케이스를 두지 않는다. 실제 이름 표시와 색상 적용은 [CalendarHome 테스트 케이스](./calendar-home.md)와 그 문서의 작성하지 않는 이유를 따른다.
- 숨긴 공휴일은 캘린더에 표시되지 않아 눌러서 검색을 열 대상이 없다는 규칙은 조회 결과에서 제외되는 결과와 같으므로 별도 케이스로 중복 작성하지 않는다.
- 노출 설정이 화면 재생성 뒤에도 유지되는 규칙은 설정을 기기에 보관하는 저장 계약이 보장하며, 현재 테스트 환경에서 화면 재생성을 결정적으로 재현할 수 없어 별도 케이스로 작성하지 않는다.

## data

### TC-HOLIDAY-VISIBILITY-DATA-001: 숨김으로 고른 공휴일은 이후 조회에서 제외된다

- 근거: `data > 저장 시점과 유지`, `data > 캘린더 공휴일 조회`
- Given: 2026년 공휴일로 `제헌절`과 `초복`이 저장되어 있고, 노출 설정을 한 번도 고르지 않았다.
- When: `초복`을 숨김으로 고른 뒤 2026년의 캘린더용 공휴일을 조회한다.
- Then: `제헌절`만 제공된다.

### TC-HOLIDAY-VISIBILITY-DATA-002: 노출로 되돌린 공휴일은 다시 제공된다

- 근거: `data > 저장 시점과 유지`
- Given: 2026년 공휴일로 `초복`이 저장되어 있고, `초복`을 숨김으로 골랐다.
- When: `초복`을 노출로 되돌린 뒤 2026년의 캘린더용 공휴일을 조회한다.
- Then: `초복`이 제공된다.

### TC-HOLIDAY-VISIBILITY-DATA-003: 여러 key를 숨기면 각각 제외된다

- 근거: `data > 저장 시점과 유지`
- Given: 2026년 공휴일로 `제헌절`, `초복`, `중복`이 저장되어 있고, 노출 설정을 한 번도 고르지 않았다.
- When: `초복`과 `중복`을 한 번에 숨김으로 고른 뒤 2026년의 캘린더용 공휴일을 조회한다.
- Then: `제헌절`만 제공된다.

### TC-HOLIDAY-VISIBILITY-DATA-004: 조회 중에 노출 설정이 바뀌면 이어서 새 결과를 제공한다

- 근거: `data > 캘린더 공휴일 조회`
- Given: 2026년 공휴일로 `제헌절`과 `초복`이 저장되어 있고 노출 설정을 한 번도 고르지 않은 상태에서, 2026년의 캘린더용 공휴일을 계속 조회하고 있다.
- When: `초복`을 숨김으로 고른다.
- Then: 기존 조회 결과에 이어 `제헌절`만 담긴 결과가 제공된다.

### TC-HOLIDAY-VISIBILITY-DATA-005: 조회 중에 저장된 공휴일이 바뀌면 노출 설정을 반영한 새 결과를 제공한다

- 근거: `data > 캘린더 공휴일 조회`
- Given: `초복`을 숨김으로 고른 상태에서 2026년의 캘린더용 공휴일을 계속 조회하고 있다.
- When: 2026년에 저장된 공휴일이 `초복`과 `제헌절`을 담은 다른 목록으로 교체된다.
- Then: 기존 조회 결과에 이어 `제헌절`만 담긴 결과가 제공된다.

### TC-HOLIDAY-VISIBILITY-DATA-007: 어느 공휴일에도 없는 key를 숨겨도 조회 결과가 달라지지 않는다

- 근거: `data > 저장 시점과 유지`
- Given: 2026년 공휴일로 `제헌절`만 저장되어 있다.
- When: 저장된 공휴일에 없는 이름을 숨김으로 고른 뒤 2026년의 캘린더용 공휴일을 조회한다.
- Then: `제헌절`이 제공된다.

### TC-HOLIDAY-VISIBILITY-DATA-008: 숨긴 key가 다시 등장하면 이전에 고른 설정이 그대로 적용된다

- 근거: `data > 저장 시점과 유지`
- Given: `초복`을 숨김으로 골랐고, 2026년에 저장된 공휴일에는 `초복`이 없다.
- When: 2026년에 저장된 공휴일이 `초복`을 포함한 목록으로 교체된 뒤 2026년의 캘린더용 공휴일을 조회한다.
- Then: `초복`은 제공되지 않고 나머지 공휴일만 제공된다.

### TC-HOLIDAY-VISIBILITY-DATA-009: 노출 설정을 바꿔도 저장된 공휴일은 바뀌지 않는다

- 근거: `data > 저장 시점과 유지`
- Given: 2026년 공휴일로 `제헌절`과 `초복`이 저장되어 있다.
- When: `초복`을 숨김으로 고른 뒤 2026년에 저장된 공휴일을 조회한다.
- Then: 2026년에 저장된 공휴일은 `제헌절`과 `초복` 두 항목 그대로다.

### TC-HOLIDAY-VISIBILITY-DATA-010: 저장된 공휴일이 교체되어도 노출 설정은 유지된다

- 근거: `data > 저장 시점과 유지`
- Given: `초복`을 숨김으로 골랐다.
- When: 2026년에 저장된 공휴일을 다른 목록으로 교체한 뒤 노출 설정을 조회한다.
- Then: `초복`이 숨김 상태로 유지된다.

### TC-HOLIDAY-VISIBILITY-DATA-011: 숨김 key 집합을 교체하면 기존 값과 중간 상태가 남지 않는다

- 근거: `data > 저장 시점과 유지`
- Given: 현재 공휴일 캐시에 없는 key와 현재 공휴일의 한 key가 숨김으로 저장된 상태에서 노출 설정을 계속 조회하고 있다.
- When: 기존 두 key를 포함하지 않은 세 key의 숨김 집합으로 전체 교체한다.
- Then: 새 세 key만 숨김인 상태가 한 번 제공되고, 기존 key나 일부 새 key가 남은 중간 상태는 제공되지 않는다.

### TC-HOLIDAY-VISIBILITY-DATA-012: 노출 설정을 읽을 수 없으면 조회를 실패로 끝낸다

- 근거: `data > 캘린더 공휴일 조회`
- Given: 2026년 공휴일로 `제헌절`과 `초복`이 저장되어 있고, 보관된 노출 설정을 읽을 수 없는 상태다.
- When: 2026년의 캘린더용 공휴일을 조회한다.
- Then: 읽지 못한 원인을 담은 실패가 제공되고, 어떤 공휴일도 성공 결과로 제공되지 않는다.

### TC-HOLIDAY-VISIBILITY-DATA-013: 개별 변경은 대상이 아닌 숨김 key를 유지한다

- 근거: `data > 저장 시점과 유지`
- Given: 현재 공휴일 캐시에 없는 key와 현재 목록의 한 key가 숨김으로 저장되어 있다.
- When: 현재 목록의 다른 key 하나를 개별적으로 숨김으로 바꾼다.
- Then: 기존 두 숨김 key와 새로 숨긴 key가 모두 유지된다.

### 작성하지 않는 이유

- 앱을 종료하고 다시 시작한 뒤나 백그라운드에 다녀온 뒤에도 노출 설정이 유지되는 규칙은 실제 저장 영역의 파일이나 브라우저 저장 영역을 다시 열어야 관찰할 수 있으므로 유닛 테스트 케이스로 작성하지 않는다.
- 로그인, 로그아웃, 계정 전환 후에도 노출 설정이 유지되는 규칙은 계정 흐름 전체를 거쳐야 관찰할 수 있으므로 유닛 테스트 케이스로 작성하지 않는다.
- 각 환경에서 노출 설정을 보관하는 영역은 기본 지도 설정과 같은 저장 영역이므로 [SettingMap 테스트 케이스](./setting-map.md)의 TC-SETTING-MAP-DATA-006에서 다루며, 중복 작성하지 않는다.
- 노출 설정을 고르는 화면의 표시와 조작은 [SettingHoliday 테스트 케이스](./setting-holiday.md)에서 다루므로 중복 작성하지 않는다.
