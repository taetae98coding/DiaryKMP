# MusicAdd 테스트 케이스

기준 스펙: [MusicAdd 화면 스펙](../spec/music-add.md)

이 문서에서 `data > 동기화`, `data > 저장 실패`, `domain > 추가 요청 제한`, `domain > 항목의 계정 연결`, `feature > 뒤로가기`, `feature > 작성 상태 유지` 절은 [항목 추가 화면 공통 스펙](../spec/entity-add.md)이 소유한다. 나머지 케이스의 절은 기준 스펙이 소유한다.

PlaylistHome에서 곡 추가를 선택해 MusicAdd로 이동하는 케이스는 [PlaylistHome 테스트 케이스](./playlist-home.md)에서 다룬다. 추가한 곡을 서버와 맞추는 흐름의 케이스는 [데이터 동기화 테스트 케이스](./data-sync.md)에서 다룬다. 이 화면에는 태그 입력이 없으므로 태그 연결 케이스는 두지 않는다.

## feature

### TC-MUSIC-ADD-FEATURE-001: 화면에 처음 진입하면 입력이 모두 비어 있다

- 근거: `feature > 진입과 입력`
- Given: 사용자가 곡 추가를 선택했다.
- When: MusicAdd 화면이 처음 표시된다.
- Then: 제목과 가수가 비어 있다.

### TC-MUSIC-ADD-FEATURE-002: 제목과 가수를 입력할 수 있다

- 근거: `feature > 진입과 입력`
- Given: MusicAdd 화면이 표시되어 있다.
- When: 사용자가 제목과 가수를 입력한다.
- Then: 입력한 제목과 가수가 화면에 그대로 표시된다.

### TC-MUSIC-ADD-FEATURE-003: 화면에 처음 진입하면 제목 입력에 초점이 있다

- 근거: `feature > 진입과 입력`
- Given: 사용자가 곡 추가를 선택했다.
- When: MusicAdd 화면이 처음 표시된다.
- Then: 입력 초점이 제목 입력에 있다.

### TC-MUSIC-ADD-FEATURE-004: 추가에 성공하면 다음 곡을 작성할 수 있는 상태로 초기화한다

- 근거: `feature > 곡 추가`
- Given: 곡 추가가 성공하도록 설정되어 있고, 제목과 가수를 입력한 상태다.
- When: 사용자가 곡 추가를 실행한다.
- Then: MusicAdd 화면이 유지되고 제목과 가수가 비워진다.

### TC-MUSIC-ADD-FEATURE-005: 추가에 성공하면 성공 피드백을 제공한다

- 근거: `feature > 곡 추가`
- Given: 곡 추가가 성공하도록 설정되어 있고, 공백이 아닌 제목과 가수가 입력되어 있다.
- When: 사용자가 곡 추가를 실행한다.
- Then: 곡이 추가되었다는 성공 피드백이 제공된다.

### TC-MUSIC-ADD-FEATURE-006: 추가에 성공하면 제목 입력으로 초점을 옮긴다

- 근거: `feature > 곡 추가`
- Given: 곡 추가가 성공하도록 설정되어 있고, 공백이 아닌 제목과 가수가 입력되어 있다.
- When: 사용자가 곡 추가를 실행한다.
- Then: 입력 초점이 제목 입력으로 옮겨진다.

### TC-MUSIC-ADD-FEATURE-007: 추가를 처리하는 동안 진행 상태를 표시한다

- 근거: `feature > 곡 추가`
- Given: 곡 추가 처리가 완료되지 않고 진행 중인 상태로 설정되어 있고, 공백이 아닌 제목과 가수가 입력되어 있다.
- When: 사용자가 곡 추가를 실행한 뒤 화면을 확인한다.
- Then: 추가 처리가 끝날 때까지 진행 상태가 표시된다.

### TC-MUSIC-ADD-FEATURE-008: 성립하지 않는 입력으로 추가하면 필요한 입력을 알린다

- 근거: `feature > 제목 미입력`, `feature > 가수 미입력`
- Given: MusicAdd 화면에 테스트 데이터의 입력 상태가 만들어져 있다.
- When: 사용자가 곡 추가를 실행한다.
- Then: 곡이 추가되지 않고 테스트 데이터의 피드백이 제공된다.
- 테스트 데이터:

| 입력 상태 | 피드백 |
| --- | --- |
| 제목이 비어 있음 | 제목 입력이 필요함 |
| 제목이 공백 문자뿐임 | 제목 입력이 필요함 |
| 제목은 있고 가수가 비어 있음 | 가수 입력이 필요함 |
| 제목은 있고 가수가 공백 문자뿐임 | 가수 입력이 필요함 |

### TC-MUSIC-ADD-FEATURE-009: 성립하지 않는 입력으로 추가해도 작성 내용은 유지된다

- 근거: `feature > 제목 미입력`, `feature > 가수 미입력`
- Given: 테스트 데이터의 성립하지 않는 입력 상태이고 나머지 입력이 채워진 MusicAdd 화면이 표시되어 있다.
- When: 사용자가 곡 추가를 실행한다.
- Then: 성립하지 않은 입력 외의 작성 내용이 지워지거나 바뀌지 않는다.
- 테스트 데이터:

| 성립하지 않는 입력 |
| --- |
| 제목이 공백 |
| 가수가 공백 |

### TC-MUSIC-ADD-FEATURE-010: 성립하지 않는 입력으로 추가하면 고쳐야 할 입력으로 초점을 옮긴다

- 근거: `feature > 제목 미입력`, `feature > 가수 미입력`
- Given: MusicAdd 화면에 테스트 데이터의 입력 상태가 만들어져 있다.
- When: 사용자가 곡 추가를 실행한다.
- Then: 입력 초점이 테스트 데이터의 자리에 있다.
- 테스트 데이터:

| 입력 상태 | 초점 |
| --- | --- |
| 제목이 비어 있음 | 제목 입력 |
| 제목은 있고 가수가 비어 있음 | 가수 입력 |

### TC-MUSIC-ADD-FEATURE-013: 화면이 재생성되어도 작성 중이던 내용을 유지한다

- 근거: `feature > 작성 상태 유지`
- Given: 제목과 가수를 입력한 MusicAdd 화면이 표시되어 있다.
- When: 화면이 회전하거나 시스템에 의해 재생성된다.
- Then: 재생성 전의 제목과 가수가 그대로 표시된다.

### TC-MUSIC-ADD-FEATURE-014: 앱을 다시 실행해 진입하면 새 입력 상태로 시작한다

- 근거: `feature > 작성 상태 유지`
- Given: 이전 실행에서 MusicAdd 화면에 제목과 가수를 입력한 뒤 앱을 종료했다.
- When: 앱을 다시 실행해 MusicAdd 화면에 진입한다.
- Then: 제목과 가수가 비어 있다.
- 작성하지 않는 이유: 앱 프로세스를 종료하고 다시 시작해야 확인할 수 있어 앱의 단위 테스트 환경에서 결정적으로 판정할 수 없다. 프로세스 재시작을 제어할 수 있는 테스트 환경이 마련되면 작성한다.

### TC-MUSIC-ADD-FEATURE-015: 뒤로가면 이전 화면으로 돌아간다

- 근거: `feature > 뒤로가기`
- Given: MusicAdd 화면이 표시되어 있다.
- When: 사용자가 뒤로가기를 실행한다.
- Then: MusicAdd 화면에 진입하기 전 화면으로 돌아간다.

## domain

### TC-MUSIC-ADD-DOMAIN-001: 성립하지 않는 입력은 곡을 추가하지 않는다

- 근거: `domain > 추가 성립 조건`
- Given: 로그인한 사용자 계정이 있다.
- When: 테스트 데이터의 입력으로 곡 추가를 실행한다.
- Then: 곡이 추가되지 않고 테스트 데이터의 성립하지 않은 조건이 결과로 전달된다.
- 테스트 데이터:

| 입력 | 성립하지 않은 조건 |
| --- | --- |
| 제목이 빈 문자열 | 제목 |
| 제목이 공백 문자뿐 | 제목 |
| 제목은 있고 가수가 빈 문자열 | 가수 |
| 제목은 있고 가수가 공백 문자뿐 | 가수 |

### TC-MUSIC-ADD-DOMAIN-002: 두 조건이 함께 성립하지 않으면 제목을 먼저 알린다

- 근거: `domain > 추가 성립 조건`
- Given: 로그인한 사용자 계정이 있다.
- When: 제목과 가수가 모두 공백인 입력으로 곡 추가를 실행한다.
- Then: 제목 조건 하나만 결과로 전달된다.

### TC-MUSIC-ADD-DOMAIN-003: 제목과 가수가 같은 곡도 새 곡으로 추가한다

- 근거: `domain > 추가 성립 조건`
- Given: 로그인한 사용자 계정이 있고 같은 제목과 가수의 곡이 이미 저장되어 있다.
- When: 같은 제목과 가수로 곡 추가를 실행한다.
- Then: 곡이 추가되고 저장된 곡이 두 개가 된다.

### TC-MUSIC-ADD-DOMAIN-004: 새 곡에는 겹치지 않는 식별자를 부여한다

- 근거: `domain > 추가되는 곡의 내용`
- Given: 로그인한 사용자 계정이 있다.
- When: 같은 내용으로 곡 추가를 두 번 실행한다.
- Then: 두 곡의 식별자가 서로 다르다.

### TC-MUSIC-ADD-DOMAIN-005: 새 곡은 미삭제 상태로 같은 생성·수정 시각을 갖는다

- 근거: `domain > 추가되는 곡의 내용`
- Given: 로그인한 사용자 계정이 있고 현재 시각이 고정되어 있다.
- When: 공백이 아닌 제목과 가수로 곡 추가를 실행한다.
- Then: 기록된 곡은 삭제되지 않은 상태이며 생성 시각과 수정 시각이 모두 고정된 현재 시각이다.

### TC-MUSIC-ADD-DOMAIN-006: 입력한 제목과 가수를 그대로 기록한다

- 근거: `domain > 추가되는 곡의 내용`
- Given: 로그인한 사용자 계정이 있다.
- When: 앞뒤 공백이 있는 제목과 가수로 곡 추가를 실행한다.
- Then: 기록된 곡의 제목과 가수가 입력한 값과 같고 앞뒤 공백도 그대로 남는다.

### TC-MUSIC-ADD-DOMAIN-007: 새 곡은 현재 계정과 연결한다

- 근거: `domain > 항목의 계정 연결`
- Given: 로그인한 사용자 계정이 있다.
- When: 공백이 아닌 제목과 가수로 곡 추가를 실행한다.
- Then: 그 계정과 연결된 곡으로 기록된다.

### TC-MUSIC-ADD-DOMAIN-008: 현재 계정을 확인할 수 없으면 곡을 추가하지 않는다

- 근거: `domain > 항목의 계정 연결`
- Given: 현재 계정 조회가 실패하도록 설정되어 있다.
- When: 공백이 아닌 제목과 가수로 곡 추가를 실행한다.
- Then: 곡이 기록되지 않고 계정 조회의 실패가 그대로 전달된다.

### TC-MUSIC-ADD-DOMAIN-009: 추가를 처리하는 동안 전달된 추가 요청은 처리하지 않는다

- 근거: `domain > 추가 요청 제한`
- Given: 곡 추가 처리가 완료되지 않고 진행 중이다.
- When: 같은 화면에서 곡 추가를 다시 실행한다.
- Then: 추가는 한 번만 수행되고, 처리가 끝난 뒤 실행한 추가는 다시 수행된다.

## data

### TC-MUSIC-ADD-DATA-001: 추가한 곡과 계정의 연결을 함께 로컬 저장한다

- 근거: `data > 곡 생성과 저장`
- Given: 로그인한 사용자 계정이 있다.
- When: 성립 조건을 만족하는 내용으로 곡 추가를 실행한다.
- Then: 그 곡과 계정의 연결이 로컬 저장소에 함께 저장된다.

### TC-MUSIC-ADD-DATA-003: 같은 식별자의 곡이 있으면 덮어쓴다

- 근거: `data > 곡 생성과 저장`
- Given: 계정과 연결된 곡이 로컬 저장소에 있다.
- When: 같은 식별자에 다른 내용을 담아 저장한다.
- Then: 곡이 하나로 유지되고 내용이 새로 저장한 값으로 바뀐다.

### TC-MUSIC-ADD-DATA-004: 저장에 실패하면 실패를 그대로 알린다

- 근거: `data > 저장 실패`
- Given: 로컬 저장이 실패하도록 설정되어 있다.
- When: 성립 조건을 만족하는 내용으로 곡 추가를 실행한다.
- Then: 실패가 성공으로 바뀌지 않고 그대로 전달된다.

### TC-MUSIC-ADD-DATA-005: 로컬 저장이 끝나면 업로드 대기로 기록되고 동기화가 시작된다

- 근거: `data > 동기화`
- Given: 로그인한 사용자 계정이 있고 로컬 저장이 성공한다.
- When: 곡 추가를 실행한다.
- Then: 그 곡이 계정의 업로드 대기 상태로 기록되고 백그라운드 동기화가 한 번 요청된다.

### TC-MUSIC-ADD-DATA-006: 추가의 성공 여부는 로컬 저장 결과로만 판단한다

- 근거: `data > 동기화`
- Given: 로컬 저장은 성공하고 서버 반영은 실패하도록 설정되어 있다.
- When: 곡 추가를 실행한다.
- Then: 추가가 성공으로 전달되고 그 곡은 기기에서 사라지지 않은 채 업로드 대기 상태로 남는다.
