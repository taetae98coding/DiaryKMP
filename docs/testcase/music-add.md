# MusicAdd 테스트 케이스

기준 스펙: [MusicAdd 화면 스펙](../spec/music-add.md)

이 문서에서 `data > 동기화`, `data > 저장 실패`, `domain > 추가 요청 제한`, `domain > 항목의 계정 연결`, `feature > 뒤로가기`, `feature > 작성 상태 유지` 절은 [항목 추가 화면 공통 스펙](../spec/entity-add.md)이 소유한다. 나머지 케이스의 절은 기준 스펙이 소유한다.

PlaylistHome에서 곡 추가를 선택해 MusicAdd로 이동하는 케이스는 [PlaylistHome 테스트 케이스](./playlist-home.md)에서, 곡 목록과 함께 표시할 때의 케이스는 [Playlist 목록·상세 배치 테스트 케이스](./playlist-list-detail.md)에서 다룬다. 추가한 곡을 서버와 맞추는 흐름의 케이스는 [데이터 동기화 테스트 케이스](./data-sync.md)에서 다룬다. 이 화면에는 태그 입력이 없으므로 태그 연결 케이스는 두지 않는다.

## feature

### TC-MUSIC-ADD-FEATURE-001: 화면에 처음 진입하면 입력이 모두 비어 있다

- 근거: `feature > 진입과 입력`
- Given: 사용자가 곡 추가를 선택했다.
- When: MusicAdd 화면이 처음 표시된다.
- Then: 링크, 제목과 가수가 비어 있고 썸네일 미리보기가 표시되지 않는다.

### TC-MUSIC-ADD-FEATURE-002: 링크, 제목과 가수를 입력할 수 있다

- 근거: `feature > 진입과 입력`
- Given: MusicAdd 화면이 표시되어 있다.
- When: 사용자가 링크, 제목과 가수를 입력한다.
- Then: 입력한 링크, 제목과 가수가 화면에 그대로 표시된다.

### TC-MUSIC-ADD-FEATURE-003: 화면에 처음 진입하면 링크 입력에 초점이 있다

- 근거: `feature > 진입과 입력`
- Given: 사용자가 곡 추가를 선택했다.
- When: MusicAdd 화면이 처음 표시된다.
- Then: 입력 초점이 링크 입력에 있다.

### TC-MUSIC-ADD-FEATURE-004: 추가에 성공하면 다음 곡을 작성할 수 있는 상태로 초기화한다

- 근거: `feature > 곡 추가`
- Given: 곡 추가가 성공하도록 설정되어 있고, 링크와 제목과 가수를 입력하고 썸네일을 불러온 상태다.
- When: 사용자가 곡 추가를 실행한다.
- Then: MusicAdd 화면이 유지되고 링크, 제목과 가수가 비워지며 썸네일 미리보기가 사라진다.

### TC-MUSIC-ADD-FEATURE-005: 추가에 성공하면 성공 피드백을 제공한다

- 근거: `feature > 곡 추가`
- Given: 곡 추가가 성공하도록 설정되어 있고, YouTube 영상 링크와 공백이 아닌 제목과 가수가 입력되어 있다.
- When: 사용자가 곡 추가를 실행한다.
- Then: 곡이 추가되었다는 성공 피드백이 제공된다.

### TC-MUSIC-ADD-FEATURE-006: 추가에 성공하면 링크 입력으로 초점을 옮긴다

- 근거: `feature > 곡 추가`
- Given: 곡 추가가 성공하도록 설정되어 있고, YouTube 영상 링크와 공백이 아닌 제목과 가수가 입력되어 있다.
- When: 사용자가 곡 추가를 실행한다.
- Then: 입력 초점이 링크 입력으로 옮겨진다.

### TC-MUSIC-ADD-FEATURE-007: 추가를 처리하는 동안 진행 상태를 표시한다

- 근거: `feature > 곡 추가`
- Given: 곡 추가 처리가 완료되지 않고 진행 중인 상태로 설정되어 있고, YouTube 영상 링크와 공백이 아닌 제목과 가수가 입력되어 있다.
- When: 사용자가 곡 추가를 실행한 뒤 화면을 확인한다.
- Then: 추가 처리가 끝날 때까지 진행 상태가 표시된다.

### TC-MUSIC-ADD-FEATURE-008: 성립하지 않는 입력으로 추가하면 필요한 입력을 알린다

- 근거: `feature > 링크 미입력`, `feature > 링크 형식 불만족`, `feature > 제목 미입력`, `feature > 가수 미입력`
- Given: MusicAdd 화면에 테스트 데이터의 입력 상태가 만들어져 있다.
- When: 사용자가 곡 추가를 실행한다.
- Then: 곡이 추가되지 않고 테스트 데이터의 피드백이 제공된다.
- 테스트 데이터:

| 입력 상태 | 피드백 |
| --- | --- |
| 링크가 비어 있음 | 링크 입력이 필요함 |
| 링크가 공백 문자뿐임 | 링크 입력이 필요함 |
| 링크가 YouTube 주소가 아님 | YouTube 영상 링크가 필요함 |
| 링크는 있고 제목이 비어 있음 | 제목 입력이 필요함 |
| 링크는 있고 제목이 공백 문자뿐임 | 제목 입력이 필요함 |
| 링크와 제목은 있고 가수가 비어 있음 | 가수 입력이 필요함 |
| 링크와 제목은 있고 가수가 공백 문자뿐임 | 가수 입력이 필요함 |

### TC-MUSIC-ADD-FEATURE-009: 성립하지 않는 입력으로 추가해도 작성 내용은 유지된다

- 근거: `feature > 링크 미입력`, `feature > 링크 형식 불만족`, `feature > 제목 미입력`, `feature > 가수 미입력`
- Given: 테스트 데이터의 성립하지 않는 입력 상태이고 나머지 입력이 채워진 MusicAdd 화면이 표시되어 있다.
- When: 사용자가 곡 추가를 실행한다.
- Then: 링크, 제목과 가수가 지워지거나 바뀌지 않는다.
- 테스트 데이터:

| 성립하지 않는 입력 |
| --- |
| 링크가 공백 |
| 링크가 YouTube 주소가 아님 |
| 제목이 공백 |
| 가수가 공백 |

### TC-MUSIC-ADD-FEATURE-010: 성립하지 않는 입력으로 추가하면 고쳐야 할 입력으로 초점을 옮긴다

- 근거: `feature > 링크 미입력`, `feature > 링크 형식 불만족`, `feature > 제목 미입력`, `feature > 가수 미입력`
- Given: MusicAdd 화면에 테스트 데이터의 입력 상태가 만들어져 있다.
- When: 사용자가 곡 추가를 실행한다.
- Then: 입력 초점이 테스트 데이터의 자리에 있다.
- 테스트 데이터:

| 입력 상태 | 초점 |
| --- | --- |
| 링크가 비어 있음 | 링크 입력 |
| 링크가 YouTube 주소가 아님 | 링크 입력 |
| 링크는 있고 제목이 비어 있음 | 제목 입력 |
| 링크와 제목은 있고 가수가 비어 있음 | 가수 입력 |

### TC-MUSIC-ADD-FEATURE-013: 화면이 재생성되어도 작성 중이던 내용을 유지한다

- 근거: `feature > 작성 상태 유지`
- Given: 링크, 제목과 가수를 입력하고 썸네일을 불러온 MusicAdd 화면이 표시되어 있다.
- When: 화면이 회전하거나 시스템에 의해 재생성된다.
- Then: 재생성 전의 링크, 제목, 가수와 썸네일 미리보기가 그대로 표시된다.

### TC-MUSIC-ADD-FEATURE-014: 앱을 다시 실행해 진입하면 새 입력 상태로 시작한다

- 근거: `feature > 작성 상태 유지`
- Given: 이전 실행에서 MusicAdd 화면에 링크, 제목과 가수를 입력한 뒤 앱을 종료했다.
- When: 앱을 다시 실행해 MusicAdd 화면에 진입한다.
- Then: 링크, 제목과 가수가 비어 있다.
- 작성하지 않는 이유: 앱 프로세스를 종료하고 다시 시작해야 확인할 수 있어 앱의 단위 테스트 환경에서 결정적으로 판정할 수 없다. 프로세스 재시작을 제어할 수 있는 테스트 환경이 마련되면 작성한다.

### TC-MUSIC-ADD-FEATURE-015: 뒤로가면 이전 화면으로 돌아간다

- 근거: `feature > 뒤로가기`
- Given: MusicAdd 화면이 단독으로 표시되어 있다.
- When: 사용자가 뒤로가기를 실행한다.
- Then: MusicAdd 화면에 진입하기 전 화면으로 돌아간다.

### TC-MUSIC-ADD-FEATURE-016: 불러오기에 성공하면 비어 있는 제목과 가수와 썸네일을 채운다

- 근거: `feature > 링크로 곡 정보 불러오기`
- Given: YouTube 영상 링크가 입력되어 있고 제목과 가수가 비어 있으며 썸네일을 불러온 적이 없고, 영상 정보 조회가 영상 제목과 채널 이름과 썸네일 주소를 돌려주도록 설정되어 있다.
- When: 사용자가 불러오기를 실행한다.
- Then: 제목에 영상 제목이, 가수에 채널 이름이 표시되고 썸네일 미리보기가 나타나며 링크 입력은 바뀌지 않는다.

### TC-MUSIC-ADD-FEATURE-017: 불러오기에 성공해도 이미 채워진 값은 바꾸지 않는다

- 근거: `feature > 링크로 곡 정보 불러오기`
- Given: YouTube 영상 링크와 테스트 데이터의 제목·가수 상태가 만들어져 있고, 영상 정보 조회가 성공하도록 설정되어 있다.
- When: 사용자가 불러오기를 실행한다.
- Then: 테스트 데이터의 결과대로 표시된다.
- 테스트 데이터:

| 제목 | 가수 | 결과 |
| --- | --- | --- |
| 비어 있음 | 사용자가 입력한 값 | 제목만 영상 제목으로 채워지고 가수는 그대로다 |
| 사용자가 입력한 값 | 비어 있음 | 가수만 채널 이름으로 채워지고 제목은 그대로다 |
| 사용자가 입력한 값 | 사용자가 입력한 값 | 제목과 가수가 모두 그대로다 |
| 공백 문자뿐임 | 공백 문자뿐임 | 제목과 가수가 모두 영상 제목과 채널 이름으로 채워진다 |

### TC-MUSIC-ADD-FEATURE-022: 불러오기에 성공해도 이미 불러온 썸네일은 바꾸지 않는다

- 근거: `domain > 불러온 값을 채우는 기준`
- Given: 이미 불러오기에 성공해 썸네일이 채워져 있고, 영상 정보 조회가 다른 썸네일 주소를 돌려주도록 설정되어 있다.
- When: 사용자가 링크를 바꾸고 불러오기를 다시 실행한다.
- Then: 썸네일 미리보기가 처음 불러온 썸네일 주소를 그대로 유지한다.

### TC-MUSIC-ADD-FEATURE-018: 불러오기를 처리하는 동안 진행 상태를 표시한다

- 근거: `feature > 링크로 곡 정보 불러오기`
- Given: YouTube 영상 링크가 입력되어 있고 영상 정보 조회가 완료되지 않고 진행 중인 상태로 설정되어 있다.
- When: 사용자가 불러오기를 실행한 뒤 화면을 확인한다.
- Then: 조회가 끝날 때까지 불러오기의 진행 상태가 표시된다.

### TC-MUSIC-ADD-FEATURE-019: 링크가 성립하지 않으면 불러오지 않고 링크 입력을 알린다

- 근거: `feature > 불러오기 실패`
- Given: MusicAdd 화면에 테스트 데이터의 링크 상태가 만들어져 있다.
- When: 사용자가 불러오기를 실행한다.
- Then: 테스트 데이터의 피드백이 제공되고 입력 초점이 링크 입력으로 옮겨지며, 제목과 가수가 바뀌지 않는다.
- 테스트 데이터:

| 링크 상태 | 피드백 |
| --- | --- |
| 비어 있음 | 링크 입력이 필요함 |
| 공백 문자뿐임 | 링크 입력이 필요함 |
| YouTube 주소가 아님 | YouTube 영상 링크가 필요함 |

### TC-MUSIC-ADD-FEATURE-020: 영상 정보를 가져오지 못하면 실패를 알리고 입력을 유지한다

- 근거: `feature > 불러오기 실패`
- Given: YouTube 영상 링크가 입력되어 있고 영상 정보 조회가 실패하도록 설정되어 있다.
- When: 사용자가 불러오기를 실행한다.
- Then: 불러오지 못했다는 피드백이 제공되고 링크, 제목, 가수와 이미 불러온 썸네일이 지워지거나 바뀌지 않는다.

### TC-MUSIC-ADD-FEATURE-021: 곡 추가로 입력을 비운 뒤에는 앞선 불러오기 결과를 채우지 않는다

- 근거: `domain > 불러온 값을 채우는 기준`
- Given: YouTube 영상 링크와 공백이 아닌 제목과 가수가 입력되어 있고, 영상 정보 조회가 완료되지 않고 진행 중이다.
- When: 사용자가 불러오기를 실행한 뒤 곡 추가를 실행해 성공하고, 그 다음에 영상 정보 조회가 성공으로 끝난다.
- Then: 링크, 제목과 가수가 비어 있는 상태로 유지되고 조회 결과가 채워지지 않는다.

### TC-MUSIC-ADD-FEATURE-023: 썸네일만 바꾸거나 지우는 조작을 두지 않는다

- 근거: `feature > 썸네일 확인`
- Given: 불러오기에 성공해 썸네일 미리보기가 표시된 MusicAdd 화면이 표시되어 있다.
- When: 사용자가 썸네일 미리보기를 확인한다.
- Then: 썸네일 미리보기에 선택할 수 있는 동작이 없다.

## domain

### TC-MUSIC-ADD-DOMAIN-001: 성립하지 않는 입력은 곡을 추가하지 않는다

- 근거: `domain > 추가 성립 조건`
- Given: 로그인한 사용자 계정이 있다.
- When: 테스트 데이터의 입력으로 곡 추가를 실행한다.
- Then: 곡이 추가되지 않고 테스트 데이터의 성립하지 않은 조건이 결과로 전달된다.
- 테스트 데이터:

| 입력 | 성립하지 않은 조건 |
| --- | --- |
| 링크가 빈 문자열 | 링크 미입력 |
| 링크가 공백 문자뿐 | 링크 미입력 |
| 링크가 YouTube 주소가 아닌 주소 | 링크 형식 |
| 링크가 주소 형식이 아닌 문자열 | 링크 형식 |
| 링크는 있고 제목이 빈 문자열 | 제목 |
| 링크는 있고 제목이 공백 문자뿐 | 제목 |
| 링크와 제목은 있고 가수가 빈 문자열 | 가수 |
| 링크와 제목은 있고 가수가 공백 문자뿐 | 가수 |

### TC-MUSIC-ADD-DOMAIN-002: 여러 조건이 함께 성립하지 않으면 앞선 조건 하나만 알린다

- 근거: `domain > 추가 성립 조건`
- Given: 로그인한 사용자 계정이 있다.
- When: 테스트 데이터의 입력으로 곡 추가를 실행한다.
- Then: 테스트 데이터의 조건 하나만 결과로 전달된다.
- 테스트 데이터:

| 입력 | 전달되는 조건 |
| --- | --- |
| 링크, 제목, 가수가 모두 공백 | 링크 미입력 |
| 링크가 YouTube 주소가 아니고 제목과 가수가 공백 | 링크 형식 |
| 링크는 있고 제목과 가수가 모두 공백 | 제목 |

### TC-MUSIC-ADD-DOMAIN-003: 링크, 제목과 가수가 같은 곡도 새 곡으로 추가한다

- 근거: `domain > 추가 성립 조건`
- Given: 로그인한 사용자 계정이 있고 같은 링크, 제목과 가수의 곡이 이미 저장되어 있다.
- When: 같은 링크, 제목과 가수로 곡 추가를 실행한다.
- Then: 곡이 추가되고 저장된 곡이 두 개가 된다.

### TC-MUSIC-ADD-DOMAIN-004: 새 곡에는 겹치지 않는 식별자를 부여한다

- 근거: `domain > 추가되는 곡의 내용`
- Given: 로그인한 사용자 계정이 있다.
- When: 같은 내용으로 곡 추가를 두 번 실행한다.
- Then: 두 곡의 식별자가 서로 다르다.

### TC-MUSIC-ADD-DOMAIN-005: 새 곡은 미삭제 상태로 같은 생성·수정 시각을 갖는다

- 근거: `domain > 추가되는 곡의 내용`
- Given: 로그인한 사용자 계정이 있고 현재 시각이 고정되어 있다.
- When: 성립 조건을 만족하는 링크와 공백이 아닌 제목과 가수로 곡 추가를 실행한다.
- Then: 기록된 곡은 삭제되지 않은 상태이며 생성 시각과 수정 시각이 모두 고정된 현재 시각이다.

### TC-MUSIC-ADD-DOMAIN-006: 입력한 제목과 가수를 그대로 기록한다

- 근거: `domain > 추가되는 곡의 내용`
- Given: 로그인한 사용자 계정이 있다.
- When: 앞뒤 공백이 있는 제목과 가수로 곡 추가를 실행한다.
- Then: 기록된 곡의 제목과 가수가 입력한 값과 같고 앞뒤 공백도 그대로 남는다.

### TC-MUSIC-ADD-DOMAIN-007: 새 곡은 현재 계정과 연결한다

- 근거: `domain > 항목의 계정 연결`
- Given: 로그인한 사용자 계정이 있다.
- When: 성립 조건을 만족하는 내용으로 곡 추가를 실행한다.
- Then: 그 계정과 연결된 곡으로 기록된다.

### TC-MUSIC-ADD-DOMAIN-008: 현재 계정을 확인할 수 없으면 곡을 추가하지 않는다

- 근거: `domain > 항목의 계정 연결`
- Given: 현재 계정 조회가 실패하도록 설정되어 있다.
- When: 성립 조건을 만족하는 내용으로 곡 추가를 실행한다.
- Then: 곡이 기록되지 않고 계정 조회의 실패가 그대로 전달된다.

### TC-MUSIC-ADD-DOMAIN-009: 추가를 처리하는 동안 전달된 추가 요청은 처리하지 않는다

- 근거: `domain > 추가 요청 제한`
- Given: 곡 추가 처리가 완료되지 않고 진행 중이다.
- When: 같은 화면에서 곡 추가를 다시 실행한다.
- Then: 추가는 한 번만 수행되고, 처리가 끝난 뒤 실행한 추가는 다시 수행된다.

### TC-MUSIC-ADD-DOMAIN-013: 썸네일이 비어 있어도 곡을 추가한다

- 근거: `domain > 추가 성립 조건`
- Given: 로그인한 사용자 계정이 있다.
- When: 성립 조건을 만족하는 링크와 제목과 가수로, 썸네일 없이 곡 추가를 실행한다.
- Then: 곡이 추가되고 기록된 곡의 썸네일이 비어 있다.

### TC-MUSIC-ADD-DOMAIN-014: 불러온 썸네일 주소를 그대로 기록한다

- 근거: `domain > 추가되는 곡의 내용`
- Given: 로그인한 사용자 계정이 있다.
- When: 불러온 썸네일 주소를 담아 곡 추가를 실행한다.
- Then: 기록된 곡의 썸네일이 그 주소와 같다.

### TC-MUSIC-ADD-DOMAIN-010: 링크는 앞뒤 공백을 없앤 값으로 기록한다

- 근거: `domain > 추가되는 곡의 내용`
- Given: 로그인한 사용자 계정이 있다.
- When: 앞뒤에 공백이 있는 YouTube 영상 링크로 곡 추가를 실행한다.
- Then: 곡이 추가되고 기록된 링크에 앞뒤 공백이 남지 않는다.

### TC-MUSIC-ADD-DOMAIN-011: 여러 형태의 YouTube 주소를 곡의 링크로 받는다

- 근거: `domain > 링크의 판정`
- Given: 로그인한 사용자 계정이 있고 공백이 아닌 제목과 가수가 함께 주어진다.
- When: 테스트 데이터의 링크로 곡 추가를 실행한다.
- Then: 곡이 추가된다.
- 테스트 데이터:

| 링크 |
| --- |
| `www.youtube.com`의 영상 주소 |
| `youtu.be`의 짧은 주소 |
| `m.youtube.com`의 영상 주소 |
| `music.youtube.com`의 영상 주소 |
| 호스트에 대문자가 섞인 `youtube.com`의 영상 주소 |
| 재생 목록과 시작 시각이 함께 붙은 `youtube.com`의 영상 주소 |
| 방식이 `http`인 `youtube.com`의 영상 주소 |

### TC-MUSIC-ADD-DOMAIN-012: 불러오기를 처리하는 동안 전달된 불러오기 요청은 처리하지 않는다

- 근거: `domain > 불러오기 성립 조건`
- Given: 영상 정보 조회가 완료되지 않고 진행 중이다.
- When: 같은 화면에서 불러오기를 다시 실행한다.
- Then: 영상 정보 조회는 한 번만 요청되고, 처리가 끝난 뒤 실행한 불러오기는 다시 요청된다.

## data

### TC-MUSIC-ADD-DATA-001: 추가한 곡과 계정의 연결을 함께 로컬 저장한다

- 근거: `data > 곡 생성과 저장`
- Given: 로그인한 사용자 계정이 있다.
- When: 성립 조건을 만족하는 내용으로 곡 추가를 실행한다.
- Then: 그 곡과 계정의 연결이 로컬 저장소에 함께 저장된다.

### TC-MUSIC-ADD-DATA-003: 같은 식별자의 곡이 있으면 덮어쓴다

- 근거: `data > 곡 생성과 저장`
- Given: 계정과 연결된 곡이 로컬 저장소에 있다.
- When: 같은 식별자에 다른 내용을 담아 저장한다.
- Then: 곡이 하나로 유지되고 내용이 새로 저장한 값으로 바뀐다.

### TC-MUSIC-ADD-DATA-004: 저장에 실패하면 실패를 그대로 알린다

- 근거: `data > 저장 실패`
- Given: 로컬 저장이 실패하도록 설정되어 있다.
- When: 성립 조건을 만족하는 내용으로 곡 추가를 실행한다.
- Then: 실패가 성공으로 바뀌지 않고 그대로 전달된다.

### TC-MUSIC-ADD-DATA-005: 로컬 저장이 끝나면 업로드 대기로 기록되고 동기화가 시작된다

- 근거: `data > 동기화`
- Given: 로그인한 사용자 계정이 있고 로컬 저장이 성공한다.
- When: 곡 추가를 실행한다.
- Then: 그 곡이 계정의 업로드 대기 상태로 기록되고 백그라운드 동기화가 한 번 요청된다.

### TC-MUSIC-ADD-DATA-006: 추가의 성공 여부는 로컬 저장 결과로만 판단한다

- 근거: `data > 동기화`
- Given: 로컬 저장은 성공하고 서버 반영은 실패하도록 설정되어 있다.
- When: 곡 추가를 실행한다.
- Then: 추가가 성공으로 전달되고 그 곡은 기기에서 사라지지 않은 채 업로드 대기 상태로 남는다.

### TC-MUSIC-ADD-DATA-007: 곡의 링크와 썸네일을 제목·가수와 함께 저장하고 조회한다

- 근거: `data > 곡 생성과 저장`
- Given: 로그인한 사용자 계정이 있다.
- When: 링크, 제목, 가수와 썸네일을 담은 곡을 저장한 뒤 그 곡을 조회한다.
- Then: 저장한 링크와 썸네일이 제목, 가수와 함께 조회된다.

### TC-MUSIC-ADD-DATA-008: 불러오기를 실행하면 입력한 링크로 영상 정보를 조회한다

- 근거: `data > 영상 정보 조회`
- Given: YouTube 영상 링크가 입력되어 있다.
- When: 사용자가 불러오기를 실행한다.
- Then: 그 링크로 영상 정보 조회가 한 번 요청되고, 응답의 영상 제목과 채널 이름과 썸네일 주소가 결과로 전달된다.

### TC-MUSIC-ADD-DATA-009: 조회할 수 없는 링크는 모두 같은 실패로 다룬다

- 근거: `data > 영상 정보 조회`
- Given: 영상 정보 조회가 테스트 데이터의 방식으로 실패하도록 설정되어 있고 YouTube 영상 링크가 입력되어 있다.
- When: 사용자가 불러오기를 실행한다.
- Then: 실패 방식과 관계없이 같은 불러오기 실패가 전달된다.
- 테스트 데이터:

| 실패 방식 |
| --- |
| 영상을 찾을 수 없는 응답 |
| 볼 수 없는 영상이라는 응답 |
| 서버 오류 응답 |
| 네트워크를 사용할 수 없음 |

### TC-MUSIC-ADD-DATA-010: 화면에 진입하거나 링크를 입력하는 것만으로는 조회하지 않는다

- 근거: `data > 영상 정보 조회`
- Given: MusicAdd 화면이 표시되어 있다.
- When: 사용자가 링크를 입력하고 불러오기를 실행하지 않는다.
- Then: 영상 정보 조회 요청이 발생하지 않는다.
