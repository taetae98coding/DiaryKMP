# MemoFinishedList 화면 테스트 케이스

기준 스펙: [MemoFinishedList 화면 스펙](../spec/memo-finished-list.md)

이 문서에서 `domain > 노출 기준`, `feature > 빈 상태`, `feature > 상세 확인`, `feature > 진입과 이동` 절은 [완료 목록 공통 스펙](../spec/finished-list.md)이 소유한다. `domain > 날짜 그룹과 오늘 기준` 절은 [MemoHome 목록 스펙](../spec/memo-home.md)이 소유한다. 나머지 케이스의 절은 기준 스펙이 소유한다.

자리 표시 케이스의 `근거`가 가리키는 절은 공통 규칙을 [페이지 조회 목록의 자리 표시 스펙](../spec/paged-list-placeholder.md)에, 빈 상태 케이스의 `근거`가 가리키는 절은 [목록 빈 상태 스펙](../spec/list-empty-state.md)에 위임한다.

## feature

### TC-MEMO-FINISHED-LIST-FEATURE-001: 완료되고 삭제되지 않은 메모만 목록에 표시한다

- 근거: `feature > 목록 표시`, `domain > 노출 기준`
- Given: 현재 계정에 완료·미삭제 메모, 미완료·미삭제 메모, 완료·삭제 메모, 미완료·삭제 메모가 함께 저장되어 있다.
- When: 사용자가 MemoFinishedList 화면을 연다.
- Then: 완료되고 삭제되지 않은 메모만 표시된다.

### TC-MEMO-FINISHED-LIST-FEATURE-002: 목록에 메모 제목이 표시된다

- 근거: `feature > 목록 표시`
- Given: 현재 계정에 목록 노출 대상인 완료된 메모가 저장되어 있다.
- When: 사용자가 MemoFinishedList 화면을 연다.
- Then: 각 메모의 제목이 표시된다.

### TC-MEMO-FINISHED-LIST-FEATURE-003: 기간이 있는 메모에는 기간이 함께 표시된다

- 근거: `feature > 목록 표시`
- Given: 목록 노출 대상 완료 메모에 기간이 저장되어 있다.
- When: 사용자가 MemoFinishedList 화면을 연다.
- Then: 해당 메모에는 제목과 함께 기간이 표시된다.

### TC-MEMO-FINISHED-LIST-FEATURE-004: 기간이 없는 메모에는 기간이 표시되지 않는다

- 근거: `feature > 목록 표시`
- Given: 목록 노출 대상 완료 메모에 기간이 저장되어 있지 않다.
- When: 사용자가 MemoFinishedList 화면을 연다.
- Then: 해당 메모에는 제목만 표시되고 기간은 표시되지 않는다.

### TC-MEMO-FINISHED-LIST-FEATURE-005: 아직 준비되지 않은 메모는 선택하거나 상태를 바꿀 수 없다

- 근거: `feature > 목록 표시`
- Given: 목록의 메모가 아직 준비되지 않아 로딩 상태로 표시되어 있다.
- When: 사용자가 해당 자리를 선택하거나 다시 시작·삭제하려 한다.
- Then: 메모 상세 이동, 다시 시작, 삭제가 요청되지 않는다.

### TC-MEMO-FINISHED-LIST-FEATURE-007: 완료된 메모가 없어도 화면에 진입할 수 있다

- 근거: `feature > 진입과 이동`
- Given: 현재 계정에 완료된 메모가 하나도 없다.
- When: 사용자가 MemoHome 목록에서 완료된 메모 확인을 선택한다.
- Then: MemoFinishedList 화면으로 이동한다.

### TC-MEMO-FINISHED-LIST-FEATURE-008: 태그 필터 선택은 목록 표시에 영향을 주지 않는다

- 근거: `feature > 태그 필터 미적용`, `domain > 노출 기준`
- Given: 현재 계정에 태그 A와 연결된 완료 메모와 어떤 태그에도 연결되지 않은 완료 메모가 저장되어 있고, MemoHome 목록의 태그 필터에서 태그 A만 선택되어 있다.
- When: 사용자가 MemoFinishedList 화면을 연다.
- Then: 태그 A와 연결된 메모와 연결되지 않은 메모가 모두 표시된다.

### TC-MEMO-FINISHED-LIST-FEATURE-009: 이 화면에는 태그 필터를 제공하지 않는다

- 근거: `feature > 태그 필터 미적용`
- Given: 사용자가 MemoFinishedList 화면을 보고 있다.
- When: 사용자가 화면에서 실행할 수 있는 동작을 확인한다.
- Then: 태그 필터를 여는 동작이 제공되지 않는다.

### TC-MEMO-FINISHED-LIST-FEATURE-010: 기간이 있는 메모에는 시작 날짜 헤더가 표시된다

- 근거: `feature > 날짜 헤더`
- Given: 시작 날짜가 서로 다른 기간을 가진 목록 노출 대상 완료 메모들이 저장되어 있다.
- When: 사용자가 MemoFinishedList 화면을 연다.
- Then: 각 메모 묶음 위에 해당 시작 날짜의 헤더가 표시된다.

### TC-MEMO-FINISHED-LIST-FEATURE-011: 시작 날짜가 같은 메모들에는 날짜 헤더가 하나만 표시된다

- 근거: `feature > 날짜 헤더`
- Given: 시작 날짜가 같고 시작 시각이 서로 다른 기간을 가진 목록 노출 대상 완료 메모들이 저장되어 있다.
- When: 사용자가 MemoFinishedList 화면을 연다.
- Then: 그 메모들은 하나의 묶음으로 모이고 날짜 헤더가 하나만 표시된다.

### TC-MEMO-FINISHED-LIST-FEATURE-012: 기간이 없는 메모에는 날짜 헤더가 표시되지 않는다

- 근거: `feature > 날짜 헤더`
- Given: 기간이 없는 목록 노출 대상 완료 메모가 저장되어 있다.
- When: 사용자가 MemoFinishedList 화면을 연다.
- Then: 그 메모는 목록 맨 위에 날짜 헤더 없이 표시된다.

### TC-MEMO-FINISHED-LIST-FEATURE-013: 시작 날짜가 오늘인 메모의 날짜 헤더는 오늘임을 알린다

- 근거: `feature > 날짜 헤더`
- Given: 시작 날짜가 오늘인 기간을 가진 목록 노출 대상 완료 메모가 저장되어 있다.
- When: 사용자가 MemoFinishedList 화면을 연다.
- Then: 그 묶음의 날짜 헤더는 날짜 대신 오늘임을 알린다.

### TC-MEMO-FINISHED-LIST-FEATURE-014: 화면을 벗어난 사이 날짜가 바뀌면 복귀 시 오늘 날짜 헤더가 옮겨진다

- 근거: `domain > 날짜 그룹과 오늘 기준`
- Given: MemoFinishedList 화면을 벗어난 사이 날짜가 바뀌어 새 오늘과 이전 오늘에 시작하는 완료 메모가 각각 있다.
- When: 사용자가 MemoFinishedList 화면으로 복귀한다.
- Then: 새 오늘에 해당하는 날짜 헤더가 오늘로 표시되고 이전 오늘의 날짜 헤더는 더 이상 오늘로 표시되지 않는다.
- 작성하지 않는 이유: [MemoHome 목록 테스트 케이스](./memo-home.md)의 `TC-MEMO-HOME-FEATURE-018`과 같은 제약으로, 오늘 판정이 시스템 시계를 따르는데 현재 테스트 환경에서는 시스템 시계를 제어할 수 없어 화면을 벗어난 사이 날짜가 바뀌는 상황을 결정적으로 재현할 수 없다. 오늘 판정에 사용하는 시계를 테스트에서 주입할 수 있는 구조가 마련되면 자동화한다.

### TC-MEMO-FINISHED-LIST-FEATURE-015: 메모를 다시 시작하면 목록에서 사라지고 실행 취소를 제공한다

- 근거: `feature > 다시 시작`
- Given: 완료된 메모가 목록에 표시되어 있고 상태 변경이 성공하도록 설정되어 있다.
- When: 사용자가 해당 메모를 다시 시작한다.
- Then: 메모가 목록에서 사라지고 다시 시작 안내와 실행 취소 동작이 제공된다.

### TC-MEMO-FINISHED-LIST-FEATURE-016: 다시 시작을 실행 취소하면 메모가 목록에 다시 나타난다

- 근거: `feature > 다시 시작`
- Given: 메모를 다시 시작해 목록에서 사라지고 실행 취소 동작이 제공되어 있다.
- When: 사용자가 실행 취소를 선택한다.
- Then: 메모가 완료 상태로 되돌아가 정렬 기준에 맞는 위치에 다시 나타난다.

### TC-MEMO-FINISHED-LIST-FEATURE-017: 메모를 삭제하면 목록에서 사라지고 실행 취소를 제공한다

- 근거: `feature > 삭제`
- Given: 완료되고 삭제되지 않은 메모가 목록에 표시되어 있고 상태 변경이 성공하도록 설정되어 있다.
- When: 사용자가 해당 메모를 삭제한다.
- Then: 메모가 목록에서 사라지고 삭제 안내와 실행 취소 동작이 제공된다.

### TC-MEMO-FINISHED-LIST-FEATURE-018: 삭제를 실행 취소하면 메모가 목록에 다시 나타난다

- 근거: `feature > 삭제`
- Given: 메모를 삭제해 목록에서 사라지고 실행 취소 동작이 제공되어 있다.
- When: 사용자가 실행 취소를 선택한다.
- Then: 메모가 미삭제 상태로 되돌아가 정렬 기준에 맞는 위치에 다시 나타난다.

### TC-MEMO-FINISHED-LIST-FEATURE-019: 메모를 선택하면 그 메모의 상세로 이동한다

- 근거: `feature > 상세 확인`
- Given: 완료된 메모가 목록에 표시되어 있다.
- When: 사용자가 그 메모를 선택한다.
- Then: 선택한 메모의 MemoDetail 화면으로 이동한다.

### TC-MEMO-FINISHED-LIST-FEATURE-020: 뒤로가기를 사용하면 이전 MemoHome 목록으로 돌아간다

- 근거: `feature > 진입과 이동`
- Given: MemoHome 목록에서 진입한 MemoFinishedList 화면이 표시되어 있다.
- When: 사용자가 뒤로간다.
- Then: MemoFinishedList 화면이 닫히고 이전 MemoHome 목록이 표시된다.

### TC-MEMO-FINISHED-LIST-FEATURE-021: 이 화면에서는 메모를 추가할 수 없다

- 근거: `feature > 진입과 이동`
- Given: 사용자가 MemoFinishedList 화면을 보고 있다.
- When: 사용자가 화면에서 실행할 수 있는 동작을 확인한다.
- Then: 메모 추가 동작이 제공되지 않는다.

### TC-MEMO-FINISHED-LIST-FEATURE-022: 완료된 메모가 없으면 빈 상태 안내를 표시한다

- 근거: `feature > 빈 상태`
- Given: 현재 계정에 완료되었고 삭제되지 않은 메모가 하나도 없고 목록의 준비가 끝났다.
- When: 사용자가 MemoFinishedList 화면을 확인한다.
- Then: 메모 카드 대신 완료한 메모가 없음을 알리는 안내가 표시되고, 메모 추가를 권하는 안내는 표시되지 않는다.

### TC-MEMO-FINISHED-LIST-FEATURE-023: 목록을 준비하는 동안에는 빈 상태 안내를 표시하지 않는다

- 근거: `feature > 빈 상태`
- Given: 목록에 표시된 메모가 아직 하나도 없고 목록의 준비가 끝나지 않았다.
- When: 사용자가 MemoFinishedList 화면을 확인한다.
- Then: 빈 상태 안내가 표시되지 않는다.

### TC-MEMO-FINISHED-LIST-FEATURE-024: 마지막 메모를 다시 시작하면 빈 상태 안내가 나타난다

- 근거: `feature > 빈 상태`, `feature > 다시 시작`
- Given: 목록에 완료된 메모가 하나만 표시되어 있다.
- When: 사용자가 그 메모를 다시 시작한다.
- Then: 목록에 메모가 남지 않고 완료한 메모가 없음을 알리는 안내가 표시된다.
- 작성하지 않는 이유: 마지막 항목이 사라지는 전환을 만들려면 화면에 연결된 페이지 조회 결과를 도중에 바꿔야 하는데, 현재 호스트 테스트 환경은 바뀐 페이지 조회 결과의 수집을 결정적으로 진행시키지 못해 전체 테스트를 함께 실행하면 결과가 갈린다. 두 끝 상태는 각각 별도 케이스로 검증한다. 페이지 조회 결과의 반영 시점을 제어할 수 있는 테스트 환경이 제공되면 자동화한다.

## domain

### TC-MEMO-FINISHED-LIST-DOMAIN-001: 다시 시작은 메모를 제거하지 않고 미완료 상태로 바꾼다

- 근거: `domain > 다시 시작과 삭제의 상태 전이`
- Given: 완료 상태의 메모가 저장되어 있다.
- When: 사용자가 목록에서 메모를 다시 시작한다.
- Then: 메모는 저장소에 남아 있고 미완료 상태로 조회된다.

### TC-MEMO-FINISHED-LIST-DOMAIN-002: 삭제는 메모를 제거하지 않고 삭제 상태로 바꾼다

- 근거: `domain > 다시 시작과 삭제의 상태 전이`
- Given: 완료되고 삭제되지 않은 메모가 저장되어 있다.
- When: 사용자가 목록에서 메모를 삭제한다.
- Then: 메모는 저장소에 남아 있고 삭제 상태로 조회된다.

### TC-MEMO-FINISHED-LIST-DOMAIN-003: 다시 시작 실행 취소는 메모를 완료 상태로 되돌린다

- 근거: `domain > 다시 시작과 삭제의 상태 전이`
- Given: 목록에서 다시 시작해 미완료 상태가 된 메모가 저장되어 있다.
- When: 사용자가 다시 시작을 실행 취소한다.
- Then: 메모는 완료 상태로 조회된다.

### TC-MEMO-FINISHED-LIST-DOMAIN-004: 삭제 실행 취소는 메모를 미삭제 상태로 되돌린다

- 근거: `domain > 다시 시작과 삭제의 상태 전이`
- Given: 목록에서 삭제해 삭제 상태가 된 완료 메모가 저장되어 있다.
- When: 사용자가 삭제를 실행 취소한다.
- Then: 메모는 완료되고 삭제되지 않은 상태로 조회된다.

### TC-MEMO-FINISHED-LIST-DOMAIN-005: 상태 변경은 수정 시각을 동작 시점으로 갱신한다

- 근거: `domain > 다시 시작과 삭제의 상태 전이`
- Given: 과거 수정 시각을 가진 완료 메모가 저장되어 있다.
- When: 사용자가 테스트 데이터의 동작을 실행한다.
- Then: 메모의 수정 시각이 동작 시점으로 갱신되어 조회된다.
- 테스트 데이터:

  | 동작 |
  | --- |
  | 다시 시작 |
  | 삭제 |
  | 다시 시작 실행 취소 |
  | 삭제 실행 취소 |

### TC-MEMO-FINISHED-LIST-DOMAIN-006: 상태 변경은 메모 내용과 태그 연결을 바꾸지 않는다

- 근거: `domain > 다시 시작과 삭제의 상태 전이`
- Given: 제목, 설명, 컬러, 기간과 태그 연결, 대표 태그가 저장된 완료 메모가 있다.
- When: 사용자가 목록에서 그 메모를 다시 시작하거나 삭제한다.
- Then: 제목, 설명, 컬러, 기간, 태그 연결과 대표 태그는 그대로 조회된다.

### TC-MEMO-FINISHED-LIST-DOMAIN-007: 완료 시점은 목록 순서에 영향을 주지 않는다

- 근거: `domain > 정렬과 날짜 그룹`
- Given: 기간 기준 정렬 순서와 완료된 순서가 서로 반대인 완료 메모들이 저장되어 있다.
- When: 목록을 확인한다.
- Then: 완료된 순서와 관계없이 기간 기준 정렬 순서로 표시된다.

## data

### TC-MEMO-FINISHED-LIST-DATA-001: 현재 계정의 완료·미삭제 메모만 목록에서 조회한다

- 근거: `domain > 노출 기준`, `domain > 대상 메모`, `data > 목록 조회`
- Given: 현재 계정과 다른 계정에 각각 연결된 완료·미삭제 메모, 미완료·미삭제 메모, 완료·삭제 메모가 함께 저장되어 있다.
- When: 현재 계정의 완료된 메모 목록을 조회한다.
- Then: 현재 계정과 연결된 완료·미삭제 메모만 조회된다.

### TC-MEMO-FINISHED-LIST-DATA-002: 태그 필터 선택을 조회 조건에 넣지 않는다

- 근거: `feature > 태그 필터 미적용`, `data > 목록 조회`
- Given: 현재 계정의 태그 필터에 태그 A만 선택되어 있고, 태그 A와 연결된 완료 메모와 어떤 태그에도 연결되지 않은 완료 메모가 저장되어 있다.
- When: 현재 계정의 완료된 메모 목록을 조회한다.
- Then: 두 메모가 모두 조회된다.

### TC-MEMO-FINISHED-LIST-DATA-003: 목록은 기간, 시작 시점, 종료 시점, 제목 순으로 정렬해 조회한다

- 근거: `domain > 정렬과 날짜 그룹`, `data > 목록 조회`
- Given: 테스트 데이터의 완료 메모들이 저장되어 있다.
- When: 완료된 메모 목록을 조회한다.

  | F | Delta | 종일 아님 | 2026-07-19 09:00 | 2026-07-20 10:00 | 6 |

### TC-MEMO-FINISHED-LIST-DATA-004: 저장된 메모 변경을 목록에 자동으로 반영한다

- 근거: `data > 목록 조회`
- Given: 사용자가 완료된 메모 목록을 보고 있고, 변경할 메모가 준비되어 있다.
- When: 테스트 데이터의 변경을 저장한다.
- Then: 새로 목록을 요청하지 않아도 테스트 데이터의 기대 결과가 목록에 반영된다.
- 테스트 데이터:

  | 변경 | 기대 결과 |
  | --- | --- |
  | 완료 메모를 다시 시작 | 메모가 목록에서 사라짐 |
  | 완료 메모를 삭제 | 메모가 목록에서 사라짐 |
  | 미완료 메모를 완료 | 메모가 정렬 위치에 나타남 |
  | 완료 메모의 기간 변경 | 변경된 기간의 정렬 위치로 이동 |

### TC-MEMO-FINISHED-LIST-DATA-005: 목록 조회 실패에 별도의 오류나 재시도 동작을 제공하지 않는다

- 근거: `data > 목록 조회`
- Given: 목록 조회가 테스트 데이터의 시점에 실패하도록 설정되어 있다.

- Then: 별도 재시도 동작 없이 테스트 데이터의 기존 표시 결과를 유지한다.
- 테스트 데이터:

  | 실패 시점 | 기존 표시 결과 |
  | --- | --- |
  | 최초 조회 | 표시된 메모 없음 |
  | 추가 조회 | 이미 표시된 메모 |

### TC-MEMO-FINISHED-LIST-DATA-006: 상태 변경을 현재 계정의 메모에 즉시 저장한다

- 근거: `data > 상태 변경의 저장`, `domain > 대상 메모`
- Given: 현재 계정과 연결된 완료 메모와 다른 계정에만 연결된 완료 메모가 저장되어 있다.

- Then: 현재 계정과 연결된 메모의 상태만 즉시 저장되고 다른 계정의 메모는 바뀌지 않는다.

  | 다시 시작 실행 취소 |
  | 삭제 실행 취소 |

## 작성하지 않는 이유

시작 시점, 종료 시점, 제목이 모두 같은 메모끼리의 순서는 기준 스펙이 따르는 [MemoHome 목록 스펙](../spec/memo-home.md)에서 정하지 않으므로 기대 결과를 판정할 수 없어 작성하지 않는다.

메모 카드 제목의 한 줄 배치와 폭을 넘는 제목의 무한 반복 가로 이동, 날짜 헤더의 스크롤 고정은 시각적 레이아웃과 애니메이션이므로 현재 단위 테스트 환경에서 외부 결과로 결정적으로 판정할 수 없다. 제목 폭을 제어하고 여러 시점의 화면 프레임을 비교할 수 있는 시각 회귀 테스트 환경이 갖춰지면 자동화한다.

당겨서 새로고침과 진행 표시는 [새로고침 테스트 케이스](./sync-refresh.md)에서 다루므로 이 문서에서 다시 작성하지 않는다.
