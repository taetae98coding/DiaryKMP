# TagRoutineFinishedList 화면 테스트 케이스

기준 스펙: [TagRoutineFinishedList 화면 스펙](../spec/client/tag-routine-finished-list.md)

진입과 이동, 빈 상태, 추가 미제공, 불러오기 실패, 새로고침, 상세 확인, 다시 시작과 삭제, 노출 기준과 실행 경계의 공통 규칙은 기준 스펙이 [완료 목록 공통 스펙](../spec/client/finished-list.md)에, 카드의 내용, 빠른 기록과 정렬 선택 미제공, 순서와 오늘, 다시 시작과 삭제의 상태 전이와 저장은 [RoutineFinishedList 화면 스펙](../spec/client/routine-finished-list.md)에, 화면 제목의 이모지 표시와 갱신, 한 줄 표시는 [TagMemoFinishedList 화면 스펙](../spec/client/tag-memo-finished-list.md)에 위임하므로, 그 규칙을 다루는 케이스의 `근거`는 그 스펙의 절을 가리킨다.

자리 표시 케이스의 `근거`가 가리키는 절은 공통 규칙을 [페이지 조회 목록의 자리 표시 스펙](../spec/client/paged-list-placeholder.md)에, 빈 상태 케이스의 `근거`가 가리키는 절은 [목록 빈 상태 스펙](../spec/client/list-empty-state.md)에 위임한다.

카드 문구와 목록 순서의 계산 규칙은 [루틴 테스트 케이스](./routine.md)가, 당겨서 새로고침과 진행 표시는 [새로고침 테스트 케이스](./sync-refresh.md)가, 계정의 완료된 루틴 전체를 모으는 화면은 [RoutineFinishedList 화면 테스트 케이스](./routine-finished-list.md)가, 루틴 상세를 목록과 함께 표시하는 배치와 그 뒤로가기는 [TagRoutineFinishedList 목록·상세 배치 테스트 케이스](./tag-routine-finished-list-detail.md)가 다룬다. 이 문서는 대상 태그로 좁힌 완료된 루틴 목록에서 그 문구와 순서가 표시되는 것과 이 화면에서 실행하는 동작을 다룬다.

- Then: 태그의 이모지와 제목이 여러 줄로 나뉘지 않고 한 줄로 표시되며, 전체를 확인할 수 있도록 가로로 반복해서 이동한다.
- 작성하지 않는 이유: 태그 이모지와 제목이 한 줄에 생략 없이 담기는 것은 자동화하고, 가로로 반복해서 이동하는 것만 자동화하지 않는다. 가로 이동은 그려지는 위치만 바뀌는 애니메이션이라 화면의 공개된 상태로 드러나지 않고, 여러 시점의 화면 프레임을 비교해야 판정할 수 있다. 표시 폭을 제어하고 여러 시점의 화면 프레임을 비교할 수 있는 시각 회귀 테스트 환경이 갖춰지면 자동화한다.
