# 파일 올리기 알림 테스트 케이스

기준 스펙: [파일 올리기 알림 스펙](../spec/client/file-upload-notification.md)

## feature

### TC-FILE-UPLOAD-NOTIFICATION-FEATURE-001: Android에서 올리는 동안 파일 이름과 진행을 보여 주는 알림을 표시한다

- 근거: `feature > 진행 알림`
- Given: Android에서 사용자 언어가 한국어이고 알림 권한이 허용되어 있으며, `보고서.pdf` 파일을 올리는 중이다.
- When: 서버에 보낸 양이 테스트 데이터와 같아진다.
- Then: 제목 `파일 올리는 중`, 본문 `보고서.pdf`인 진행 알림이 진행 중 알림으로 표시되고, 진행은 테스트 데이터와 같다.
- 테스트 데이터:

| 보낸 양 | 진행 |
| --- | --- |
| 아직 보내지 않음 | 백분율 없이 진행 중 |
| 전체의 40% | 40% |

### TC-FILE-UPLOAD-NOTIFICATION-FEATURE-002: FileHome 화면을 보고 있어도 진행 알림을 표시한다

- 근거: `feature > 진행 알림`
- Given: Android에서 알림 권한이 허용되어 있고 사용자가 FileHome 화면을 보고 있다.
- When: 파일 올리기가 시작된다.
- Then: 진행 알림이 표시된다.

### TC-FILE-UPLOAD-NOTIFICATION-FEATURE-003: 올리기가 끝나거나 중단되면 진행 알림이 사라진다

- 근거: `feature > 진행 알림`
- Given: Android에서 파일을 올리는 중이라 진행 알림이 표시되어 있다.
- When: 올리기가 테스트 데이터의 결과로 끝난다.
- Then: 진행 알림이 사라진다.
- 테스트 데이터:

| 결과 |
| --- |
| 성공 |
| 크기 초과로 실패 |
| 그 밖의 이유로 실패 |
| 계정이 바뀌어 중단 |

- 작성하지 않는 이유: 진행 알림은 올리는 동안 앱을 붙잡아 두는 운영체제의 전경 실행과 함께 표시되고, 올리기가 끝나면 운영체제가 그 실행을 끝내면서 알림을 거둔다. 저장소의 테스트 환경은 이 전경 실행을 시작하거나 끝내지 않아 진행 알림이 사라지는 순간을 관찰할 수 없다. 진행 알림의 내용은 TC-FILE-UPLOAD-NOTIFICATION-FEATURE-001이, 끝난 뒤의 결과 알림은 TC-FILE-UPLOAD-NOTIFICATION-FEATURE-004가 확인한다. 자동화하려면 실제 기기에서 알림 표시 영역을 조회할 수 있는 기기 테스트 환경이 필요하다.

### TC-FILE-UPLOAD-NOTIFICATION-FEATURE-004: FileHome 화면을 보고 있지 않을 때 올리기가 끝나면 결과 알림을 보낸다

- 근거: `feature > 결과 알림`
- Given: Android에서 사용자 언어가 한국어이고 알림 권한이 허용되어 있으며, 사용자가 FileHome 화면을 보고 있지 않은 동안 `보고서.pdf` 파일을 올리는 중이다.
- When: 올리기가 테스트 데이터의 결과로 끝난다.
- Then: 테스트 데이터의 제목과 본문을 가진 결과 알림이 표시된다.
- 테스트 데이터:

| 결과 | 제목 | 본문 |
| --- | --- | --- |
| 성공 | `파일을 올렸습니다` | `보고서.pdf` |
| 크기 초과로 실패 | `파일을 올리지 못했습니다` | `50MB 이하 파일만 올릴 수 있습니다.` |
| 그 밖의 이유로 실패 | `파일을 올리지 못했습니다` | `보고서.pdf` |

### TC-FILE-UPLOAD-NOTIFICATION-FEATURE-005: FileHome 화면을 보고 있을 때 올리기가 끝나면 결과 알림을 보내지 않는다

- 근거: `feature > 결과 알림`
- Given: Android에서 알림 권한이 허용되어 있고 사용자가 FileHome 화면을 보고 있는 동안 파일을 올리는 중이다.
- When: 올리기가 테스트 데이터의 결과로 끝난다.
- Then: 결과 알림이 표시되지 않는다.
- 테스트 데이터:

| 결과 |
| --- |
| 성공 |
| 크기 초과로 실패 |
| 그 밖의 이유로 실패 |

### TC-FILE-UPLOAD-NOTIFICATION-FEATURE-006: 올리기가 중단되면 결과 알림을 보내지 않는다

- 근거: `feature > 결과 알림`
- Given: Android에서 사용자가 FileHome 화면을 보고 있지 않은 동안 계정 A로 파일을 올리는 중이다.
- When: 계정 상태가 게스트로 바뀌어 올리기가 중단된다.
- Then: 결과 알림이 표시되지 않는다.

### TC-FILE-UPLOAD-NOTIFICATION-FEATURE-007: 결과 알림은 마지막 결과 하나만 남는다

- 근거: `feature > 결과 알림`
- Given: Android에서 앞선 올리기의 실패 결과 알림이 남아 있고, 사용자가 FileHome 화면을 보고 있지 않은 동안 다른 파일을 올리는 중이다.
- When: 그 올리기가 성공으로 끝난다.
- Then: 결과 알림은 하나만 남고, 그 알림은 성공 결과를 보여 준다.

### TC-FILE-UPLOAD-NOTIFICATION-FEATURE-008: 알림을 선택하면 더보기 위에 FileHome 화면을 연다

- 근거: `feature > 알림에서 앱 열기`
- Given: 앱이 실행 중이고 사용자가 테스트 데이터의 화면을 보고 있다.
- When: 사용자가 파일 올리기 알림을 선택한다.
- Then: 테스트 데이터의 결과가 되고, 그 뒤 뒤로가면 `더보기` 화면이 보인다.
- 테스트 데이터:

| 보고 있던 화면 | 결과 |
| --- | --- |
| `캘린더` | `더보기`로 이동한 뒤 그 위에 FileHome 화면이 열린다 |
| `메모` 목적지 위에 열어 둔 세부 화면 | 그 세부 화면이 닫히고 `더보기`로 이동한 뒤 그 위에 FileHome 화면이 열린다 |
| `더보기` | 그 위에 FileHome 화면이 열린다 |
| `더보기` 위에 열어 둔 FileHome이 아닌 화면 | 그 화면이 닫히고 `더보기` 위에 FileHome 화면이 열린다 |

### TC-FILE-UPLOAD-NOTIFICATION-FEATURE-009: 이미 FileHome 화면을 보고 있으면 알림을 선택해도 새로 열지 않는다

- 근거: `feature > 알림에서 앱 열기`
- Given: 앱이 실행 중이고 앱의 상태가 테스트 데이터와 같다.
- When: 사용자가 파일 올리기 알림을 선택한다.
- Then: FileHome 화면이 그대로 유지되고, 뒤로가면 `더보기` 화면이 보인다.
- 테스트 데이터:

| 앱의 상태 |
| --- |
| 사용자가 FileHome 화면을 보고 있다 |
| 앱이 화면 뒤에 있고 마지막으로 보던 화면이 FileHome이다 |

### TC-FILE-UPLOAD-NOTIFICATION-FEATURE-010: 앱이 실행 중이 아닐 때 알림을 선택하면 앱이 시작되며 FileHome 화면을 연다

- 근거: `feature > 알림에서 앱 열기`
- Given: 앱이 실행 중이 아니다.
- When: 사용자가 파일 올리기 알림을 선택해 앱이 시작된다.
- Then: FileHome 화면이 보이고, 뒤로가면 `더보기` 화면이 보인다.

### TC-FILE-UPLOAD-NOTIFICATION-FEATURE-011: 결과 알림을 선택하면 알림 목록에서 사라진다

- 근거: `feature > 알림에서 앱 열기`
- Given: 결과 알림이 알림 목록에 있다.
- When: 사용자가 그 알림을 선택한다.
- Then: 앱이 열리고 결과 알림이 알림 목록에서 사라진다.
- 작성하지 않는 이유: 선택한 알림을 알림 목록에서 지우는 것은 운영체제의 알림 표시 영역이 처리하는 결과라 저장소의 테스트 환경에서 관찰할 수 없다. 자동화하려면 실제 기기의 알림 표시 영역을 조작하고 조회할 수 있는 기기 테스트 환경이 필요하다.

### TC-FILE-UPLOAD-NOTIFICATION-FEATURE-012: iOS에서 FileHome 화면을 보고 있지 않을 때 올리기가 끝나면 결과 알림을 보낸다

- 근거: `feature > 제공 범위`, `feature > 결과 알림`
- Given: iOS에서 알림 권한이 허용되어 있고, 사용자가 FileHome 화면을 보고 있지 않은 동안 파일을 올리는 중이다.
- When: 올리기가 성공이나 실패로 끝난다.
- Then: TC-FILE-UPLOAD-NOTIFICATION-FEATURE-004와 같은 제목과 본문의 결과 알림이 표시되고, 진행 알림은 표시되지 않는다.
- 작성하지 않는 이유: iOS의 알림은 iOS 기기의 알림 센터에만 표시되고, 저장소의 테스트는 JVM과 Android 환경에서만 실행되므로 관찰할 수 없다. 결과 알림의 문구와 보낼지의 판정은 TC-FILE-UPLOAD-NOTIFICATION-FEATURE-004, TC-FILE-UPLOAD-NOTIFICATION-FEATURE-005와 TC-FILE-UPLOAD-NOTIFICATION-DOMAIN-001이 확인한다. 자동화하려면 iOS 기기에서 알림 센터를 조회할 수 있는 기기 테스트 환경이 필요하다.

### TC-FILE-UPLOAD-NOTIFICATION-FEATURE-013: 데스크톱 앱과 웹에서는 알림을 보내지 않는다

- 근거: `feature > 제공 범위`
- Given: 데스크톱 앱이나 웹에서 사용자가 FileHome 화면을 보고 있지 않은 동안 파일을 올리는 중이다.
- When: 올리기가 끝난다.
- Then: 알림이 표시되지 않고 알림을 제공하지 않는다는 안내도 표시되지 않는다.
- 작성하지 않는 이유: 두 환경에는 앱이 알림을 보내는 수단이 없어 테스트가 관찰할 알림 표시 영역 자체가 없다. 자동화하려면 데스크톱 운영체제와 브라우저의 알림 표시 영역을 조회할 수 있는 테스트 환경이 필요하다.

### TC-FILE-UPLOAD-NOTIFICATION-FEATURE-014: 진행 알림은 선택해도 알림 목록에 남는다

- 근거: `feature > 알림에서 앱 열기`
- Given: Android에서 파일을 올리는 중이라 진행 알림이 표시되어 있다.
- When: 사용자가 진행 알림을 선택한다.
- Then: 앱이 열리고, 진행 알림은 올리기가 끝날 때까지 알림 목록에 남는다.

### TC-FILE-UPLOAD-NOTIFICATION-FEATURE-015: 이름을 알 수 없는 파일의 실패 결과 알림은 안내만 담는다

- 근거: `feature > 결과 알림`
- Given: Android에서 사용자 언어가 한국어이고, 사용자가 FileHome 화면을 보고 있지 않은 동안 파일 이름을 읽을 수 없는 파일의 올리기가 시작되었다.
- When: 올리기가 실패로 끝난다.
- Then: 제목 `파일을 올리지 못했습니다`만 있고 본문이 없는 결과 알림이 표시된다.

### TC-FILE-UPLOAD-NOTIFICATION-FEATURE-016: 시스템이 앱을 정리한 뒤 다시 올리면 진행 알림이 처음부터 다시 나타난다

- 근거: `feature > 진행 알림`
- Given: Android에서 파일을 올리는 중이다.
- When: 시스템이 앱을 정리한 뒤 앱이 다시 살아나 같은 파일을 처음부터 다시 올린다.
- Then: 진행 알림이 다시 나타나고 백분율 없이 다시 시작한다.
- 작성하지 않는 이유: 시스템이 앱을 정리하고 다시 살리는 것은 운영체제가 일으키는 실행 경계라 테스트 환경에서 결정적으로 재현할 수 없다. 진행 알림의 내용과 백분율 없는 시작은 TC-FILE-UPLOAD-NOTIFICATION-FEATURE-001이 확인한다. 자동화하려면 실제 기기에서 앱 프로세스를 종료하고 다시 살리는 기기 테스트 환경이 필요하다.

### TC-FILE-UPLOAD-NOTIFICATION-FEATURE-017: Android 14 이상에서 진행 알림을 지워도 올리기는 이어진다

- 근거: `feature > 진행 알림`
- Given: Android 14 이상에서 파일을 올리는 중이라 진행 알림이 표시되어 있다.
- When: 사용자가 진행 알림을 지운다.
- Then: 올리기는 멈추지 않고 이어지며, FileHome 화면에는 진행 중 표시가 그대로 보인다.
- 작성하지 않는 이유: 진행 알림을 지우는 조작은 운영체제의 알림 표시 영역에서만 일어나 저장소의 테스트 환경에서 재현할 수 없다. 자동화하려면 실제 기기의 알림 표시 영역을 조작할 수 있는 기기 테스트 환경이 필요하다.

### TC-FILE-UPLOAD-NOTIFICATION-FEATURE-018: 진행 알림을 띄우지 못해도 올리기는 끝까지 진행되고 결과가 알려진다

- 근거: `feature > 진행 알림`
- Given: Android에서 앱이 화면 뒤에 있는 동안 올리기가 시작되어 시스템이 진행 알림을 띄우지 못하게 했고, 사용자가 FileHome 화면을 보고 있지 않다.
- When: 서버가 올리기 요청에 성공을 돌려준다.
- Then: 올리기가 성공으로 끝나고 성공 결과 알림이 표시된다.

### TC-FILE-UPLOAD-NOTIFICATION-FEATURE-019: FileAdd 화면을 보고 있을 때 올리기가 끝나면 결과 알림을 보내지 않는다

- Given: Android에서 알림 권한이 허용되어 있고 사용자가 FileHome에서 연 FileAdd 화면을 보고 있는 동안 파일을 올리는 중이다.
- When: 올리기가 테스트 데이터의 결과로 끝난다.
- Then: 결과 알림이 표시되지 않는다.
- 테스트 데이터:

| 결과 |
| --- |
| 성공 |
| 크기 초과로 실패 |

### TC-FILE-UPLOAD-NOTIFICATION-FEATURE-020: FileAdd 화면을 보고 있으면 알림을 선택해도 FileAdd와 적어 둔 내용을 유지한다

- 근거: `feature > 알림에서 앱 열기`

- When: 사용자가 파일 올리기 알림을 선택한다.
- Then: FileAdd 화면과 제목 `회의록`이 그대로 유지되고, 뒤로가면 FileHome 화면이 보인다.
- 테스트 데이터:

| 앱의 상태 |
| --- |
| 사용자가 FileAdd 화면을 보고 있다 |
| 앱이 화면 뒤에 있고 마지막으로 보던 화면이 FileAdd다 |

## domain

### TC-FILE-UPLOAD-NOTIFICATION-DOMAIN-001: 앱이 화면 앞에 있고 FileHome을 표시할 때만 FileHome을 보고 있는 것으로 본다

- 근거: `domain > 파일 화면을 보고 있는 상태`
- Given: 앱의 상태가 테스트 데이터와 같다.
- When: 올리기가 끝나 FileHome을 보고 있는지 판정한다.
- Then: 테스트 데이터의 판정 결과가 된다.
- 테스트 데이터:

| 앱이 화면 앞에 있음 | 표시 중인 화면 | 판정 |
| --- | --- | --- |
| 예 | FileHome | 보고 있음 |
| 예 | `더보기` | 보고 있지 않음 |
| 아니오 | FileHome | 보고 있지 않음 |

### TC-FILE-UPLOAD-NOTIFICATION-DOMAIN-002: 올리기를 시작할 때가 아니라 끝나는 순간 파일 화면을 보고 있는지로 판정한다

- 근거: `domain > 파일 화면을 보고 있는 상태`, `feature > 앱을 사용하는 중에 받은 알림`
- Given: Android에서 알림 권한이 허용되어 있고, 사용자가 FileAdd 화면에서 파일 올리기를 시작한 뒤 FileHome을 거쳐 `더보기` 화면으로 돌아갔다.
- When: 올리기가 성공으로 끝난다.
- Then: 성공 결과 알림이 표시되고, 앱 화면 안에는 따로 안내가 표시되지 않으며 보고 있던 화면도 바뀌지 않는다.

### TC-FILE-UPLOAD-NOTIFICATION-DOMAIN-003: 알림 권한이 없어도 올리기는 그대로 진행된다

- 근거: `domain > 알림 권한`
- Given: 알림 권한이 허용되어 있지 않다.
- When: 파일 하나로 올리기를 시작하고 서버가 성공을 돌려준다.
- Then: 알림은 사용자에게 보이지 않고, 올리기는 성공으로 끝난다.
- 작성하지 않는 이유: 알림이 사용자에게 보이는지는 운영체제가 권한 상태로 정하는 결과라 저장소의 테스트 환경에서 관찰할 수 없다. 올리기의 성공과 실패는 알림과 관계없이 [파일 보관 테스트 케이스](./file-storage.md)가 확인한다. 자동화하려면 알림 권한을 바꾸고 알림 표시 영역을 조회할 수 있는 기기 테스트 환경이 필요하다.

### TC-FILE-UPLOAD-NOTIFICATION-DOMAIN-004: Android에서 파일 올리기 알림은 다른 알림과 따로 끌 수 있다

- 근거: `domain > 알림 그만 받기`
- Given: Android 기기다.
- When: 파일 올리기의 진행 알림과 결과 알림이 표시된다.
- Then: 두 알림은 일일 메모 알림과 다른, 파일 올리기 전용 알림 설정 항목으로 표시된다.

### TC-FILE-UPLOAD-NOTIFICATION-DOMAIN-005: 데스크톱 앱과 웹에서 앱이 화면 앞에 있는지를 창과 탭의 상태로 판정한다

- 근거: `domain > 파일 화면을 보고 있는 상태`
- Given: 데스크톱 앱이나 웹에서 FileHome 화면을 표시하고 있고, 창이나 탭의 상태가 테스트 데이터와 같다.
- When: 올리기가 끝나 FileHome을 보고 있는지 판정한다.
- Then: 테스트 데이터의 판정 결과가 된다.
- 테스트 데이터:

| 플랫폼 | 창이나 탭의 상태 | 판정 |
| --- | --- | --- |
| 데스크톱 앱 | 창이 다른 창 뒤에 가려 있다 | 보고 있음 |
| 데스크톱 앱 | 창이 최소화되어 있다 | 보고 있지 않음 |
| 웹 | 앱을 연 탭이 보인다 | 보고 있음 |
| 웹 | 다른 탭을 보고 있다 | 보고 있지 않음 |

- 작성하지 않는 이유: 창을 최소화하거나 가리고 탭을 바꾸는 일은 운영체제와 브라우저가 일으키는 상태라 저장소의 테스트 환경에서 재현할 수 없다. 화면 앞에 있는지와 표시 중인 화면으로 보고 있는지를 가르는 판정 자체는 TC-FILE-UPLOAD-NOTIFICATION-DOMAIN-001이 확인한다. 자동화하려면 데스크톱 창과 브라우저 탭의 상태를 조작할 수 있는 테스트 환경이 필요하다.
