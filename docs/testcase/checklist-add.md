# ChecklistAdd 테스트 케이스

기준 스펙: [ChecklistAdd 화면 스펙](../spec/client/checklist-add.md)

작성 상태 유지, 뒤로가기, 저장 실패, 추가 요청 제한, 계정 연결과 저장 계약은 [항목 추가 화면 공통 스펙](../spec/client/entity-add.md)에 위임된 규칙을 이 화면에 적용한 결과를 이 문서가 확인한다.

화면에 보이는 문구와 접근성 이름은 [ChecklistAdd 화면 디자인](../design/checklist-add.md)이 정한 문구를 기대 결과로 쓴다.

## feature

### TC-CHECKLIST-ADD-FEATURE-001: 상단 바에 화면 제목을 표시한다

- 근거: `feature > 화면 내용`
- Given: 사용자 언어가 테스트 데이터의 언어다.
- When: 사용자가 ChecklistAdd 화면을 확인한다.
- Then: 상단 바에 디자인이 정한 그 언어의 화면 제목이 표시된다.
- 테스트 데이터:

  | 언어 |
  | --- |
  | 한국어 |
  | 그 외 기본 |

### TC-CHECKLIST-ADD-FEATURE-002: 처음 들어오면 입력이 비어 있고 넣어 둔 항목이 없으며 제목 입력에 초점이 있다

- 근거: `feature > 진입`
- Given: ChecklistHome 화면이 표시되어 있다.
- When: 사용자가 체크리스트 추가로 ChecklistAdd 화면에 진입한다.
- Then: 제목, 설명과 항목 입력이 비어 있고, 넣어 둔 체크 항목이 하나도 없으며, 입력 초점이 제목 입력에 있다.

### TC-CHECKLIST-ADD-FEATURE-003: 화면에는 정해진 입력과 동작만 둔다

- 근거: `feature > 화면 내용`
- Given: ChecklistAdd 화면에 체크 항목 하나를 넣어 두었다.
- When: 사용자가 화면에서 확인할 수 있는 정보와 동작을 확인한다.
- Then: 화면 제목, 뒤로가기, 제목 입력, 설명 입력, 넣어 둔 체크 항목 목록, 항목 입력, 항목 넣기와 체크리스트 추가만 있고 그 밖의 동작은 없다.

### TC-CHECKLIST-ADD-FEATURE-004: 항목 넣기를 실행하면 목록 맨 끝에 놓이고 항목 입력이 비워진다

- 근거: `feature > 체크 항목 넣기`
- Given: ChecklistAdd 화면에 체크 항목 `여권`을 넣어 두었고 항목 입력에 `충전기`를 적었다.
- When: 사용자가 테스트 데이터의 방법으로 항목을 넣는다.
- Then: 넣어 둔 체크 항목이 `여권`, `충전기` 순서로 보이고, 항목 입력이 비워지며 입력 초점이 항목 입력에 남는다.
- 테스트 데이터:

  | 넣는 방법 |
  | --- |
  | 항목 넣기 선택 |
  | 입력을 마치는 키 |

### TC-CHECKLIST-ADD-FEATURE-005: 항목 입력이 비어 있거나 공백뿐이면 항목을 넣지 않는다

- 근거: `feature > 체크 항목 넣기`
- Given: ChecklistAdd 화면의 항목 입력이 테스트 데이터의 값이다.
- When: 사용자가 항목 넣기를 찾고 입력을 마치는 키를 누른다.
- Then: 항목 넣기가 제공되지 않고, 넣어 둔 체크 항목이 늘어나지 않는다.
- 테스트 데이터:

  | 항목 입력 |
  | --- |
  | 비어 있음 |
  | 공백 문자뿐 |

### TC-CHECKLIST-ADD-FEATURE-006: 같은 내용의 항목도 새 항목으로 넣는다

- 근거: `feature > 체크 항목 넣기`
- Given: ChecklistAdd 화면에 체크 항목 `여권`을 넣어 두었고 항목 입력에 `여권`을 적었다.
- When: 사용자가 항목 넣기를 실행한다.
- Then: 넣어 둔 체크 항목에 `여권`이 두 개 보인다.

### TC-CHECKLIST-ADD-FEATURE-007: 넣어 둔 항목을 빼면 사라지고 남은 항목의 순서는 그대로다

- 근거: `feature > 넣어 둔 체크 항목`
- Given: ChecklistAdd 화면에 체크 항목 `여권`, `충전기`, `우산`을 차례로 넣어 두었다.
- When: 사용자가 `충전기`를 뺀다.
- Then: 확인을 되묻지 않고 넣어 둔 체크 항목이 `여권`, `우산` 순서로 보인다.

### TC-CHECKLIST-ADD-FEATURE-008: 넣어 둔 항목은 체크할 수 없다

- 근거: `feature > 넣어 둔 체크 항목`
- Given: ChecklistAdd 화면에 체크 항목 하나를 넣어 두었다.
- When: 사용자가 그 항목을 확인한다.
- Then: 그 항목에는 체크하는 동작이 제공되지 않는다.

### TC-CHECKLIST-ADD-FEATURE-009: 넣어 둔 항목이 없으면 안내 없이 목록 자리를 비워 둔다

- 근거: `feature > 넣어 둔 체크 항목`
- Given: ChecklistAdd 화면에 넣어 둔 체크 항목이 없다.
- When: 사용자가 화면을 확인한다.
- Then: 체크 항목도 빈 상태 안내도 표시되지 않는다.

### TC-CHECKLIST-ADD-FEATURE-010: 추가에 성공하면 화면에 머문 채 입력과 넣어 둔 항목을 비우고 성공 피드백을 제공한다

- 근거: `feature > 체크리스트 추가`
- Given: ChecklistAdd 화면에 제목 `여행 준비`, 설명 `주말`, 넣어 둔 체크 항목 `여권`과 항목 입력 `우산`이 있고 저장이 성공하도록 설정되어 있다.
- When: 사용자가 체크리스트 추가를 실행한다.
- Then: 체크리스트 추가가 한 번 요청되고, ChecklistAdd 화면에 머무르며 제목, 설명, 항목 입력과 넣어 둔 체크 항목이 모두 비워지고, 입력 초점이 제목 입력으로 옮겨지며 성공 피드백이 제공된다. ChecklistHome 화면으로 이동하는 동작은 실행되지 않는다.

### TC-CHECKLIST-ADD-FEATURE-011: 추가를 처리하는 동안 진행 상태를 표시한다

- 근거: `feature > 체크리스트 추가`
- Given: 체크리스트 추가 처리가 완료되지 않고 진행 중인 상태로 설정되어 있고, 제목이 입력되어 있다.
- When: 사용자가 체크리스트 추가를 실행한 뒤 화면을 확인한다.
- Then: 추가 처리가 끝날 때까지 진행 상태가 표시된다.

### TC-CHECKLIST-ADD-FEATURE-012: 저장에 실패하면 안내 없이 작성 내용을 유지하고 진행 상태만 해제한다

- 근거: `feature > 체크리스트 추가`
- Given: ChecklistAdd 화면에 제목, 설명, 넣어 둔 체크 항목과 항목 입력이 있고 저장이 실패하도록 설정되어 있다.
- When: 사용자가 체크리스트 추가를 실행한다.
- Then: 화면에 머무르고 제목, 설명, 넣어 둔 체크 항목과 항목 입력이 그대로 남으며, 진행 상태가 해제되고 실패 안내는 표시되지 않는다.

### TC-CHECKLIST-ADD-FEATURE-013: 제목 없이 추가하면 제목 입력을 알리고 초점을 옮긴다

- 근거: `feature > 제목 미입력`
- Given: ChecklistAdd 화면의 제목이 테스트 데이터의 값이고, 설명 `주말`, 넣어 둔 체크 항목 `여권`과 항목 입력 `우산`이 있다.
- When: 사용자가 체크리스트 추가를 실행한다.
- Then: 체크리스트가 추가되지 않고, 제목 입력이 필요하다는 피드백이 제공되며 입력 초점이 제목 입력에 있고, 설명, 넣어 둔 체크 항목과 항목 입력은 그대로다.
- 테스트 데이터:

  | 제목 |
  | --- |
  | 비어 있음 |
  | 공백 문자뿐 |

### TC-CHECKLIST-ADD-FEATURE-014: 뒤로가기를 선택하면 ChecklistHome 화면으로 돌아가고 아무것도 저장하지 않는다

- 근거: `feature > 뒤로가기`
- Given: ChecklistAdd 화면에 제목과 넣어 둔 체크 항목이 있다.
- When: 사용자가 뒤로가기를 선택한다.
- Then: ChecklistHome 화면으로 돌아가는 동작이 한 번 실행되고, 체크리스트 추가는 요청되지 않는다.

## domain

### TC-CHECKLIST-ADD-DOMAIN-001: 화면이 재생성되어도 입력과 넣어 둔 항목을 유지한다

- 근거: `feature > 작성 상태 유지 대상`
- Given: ChecklistAdd 화면에 제목 `여행 준비`, 설명 `주말`, 넣어 둔 체크 항목 `여권`, `충전기`와 항목 입력 `우산`이 있다.
- When: 테스트 데이터의 실행 경계 변화가 일어난다.
- Then: 제목 `여행 준비`, 설명 `주말`, 넣어 둔 체크 항목 `여권`, `충전기`의 순서와 항목 입력 `우산`이 그대로다.
- 테스트 데이터:

  | 실행 경계 변화 |
  | --- |
  | 화면이 재생성됨 |
  | 시스템이 앱을 되살리며 이 화면을 다시 보여 줌 |

### TC-CHECKLIST-ADD-DOMAIN-002: 화면이 재생성되면 표시 중이던 안내와 피드백을 다시 표시하지 않는다

- 근거: `feature > 작성 상태 유지 대상`
- Given: ChecklistAdd 화면에 테스트 데이터의 피드백이 표시되어 있다.
- When: 화면이 재생성된다.
- Then: 그 피드백이 다시 표시되지 않는다.
- 테스트 데이터:

  | 피드백 |
  | --- |
  | 제목 없이 추가를 실행해 표시된 제목 미입력 피드백 |
  | 추가에 성공해 표시된 성공 피드백 |

### TC-CHECKLIST-ADD-DOMAIN-003: 앱을 다시 실행해 진입하면 새 입력 상태로 시작한다

- 근거: `feature > 작성 상태 유지 대상`
- Given: 이전 실행에서 ChecklistAdd 화면에 제목, 설명과 체크 항목을 넣고 추가 결과 피드백이 표시된 채 앱을 종료했다.
- When: 앱을 다시 실행해 ChecklistAdd 화면에 진입한다.
- Then: 제목, 설명, 항목 입력이 비어 있고 넣어 둔 체크 항목이 없으며, 이전 실행의 피드백이 표시되지 않는다.
- 작성하지 않는 이유: 앱 프로세스를 종료하고 다시 시작해야 확인할 수 있어 앱의 단위 테스트 환경에서 결정적으로 판정할 수 없다. 프로세스 재시작을 제어할 수 있는 테스트 환경이 마련되면 작성한다.

### TC-CHECKLIST-ADD-DOMAIN-004: 제목이 비어 있거나 공백뿐이면 체크리스트를 추가하지 않는다

- 근거: `domain > 추가 성립 조건`
- Given: 제목이 테스트 데이터의 값이다.
- When: 체크리스트 추가를 요청한다.
- Then: 체크리스트와 체크 항목이 저장되지 않고 제목 미입력으로 거절된다.
- 테스트 데이터:

  | 제목 |
  | --- |
  | 비어 있음 |
  | 공백 문자뿐 |

### TC-CHECKLIST-ADD-DOMAIN-005: 설명과 체크 항목이 없어도 체크리스트를 추가한다

- 근거: `domain > 추가 성립 조건`
- Given: 제목 `여행 준비`가 있고 설명과 넣어 둔 체크 항목, 항목 입력이 비어 있다.
- When: 체크리스트 추가를 요청한다.
- Then: 빈 설명의 체크리스트가 체크 항목 없이 저장된다.

### TC-CHECKLIST-ADD-DOMAIN-006: 같은 내용의 체크리스트도 서로 다른 새 체크리스트로 추가한다

- 근거: `domain > 추가 성립 조건`
- Given: 제목, 설명과 체크 항목이 같은 체크리스트가 이미 저장되어 있다.
- When: 같은 내용으로 체크리스트 추가를 요청한다.
- Then: 기존 체크리스트를 덮어쓰지 않고 다른 식별 정보를 가진 새 체크리스트와 새 체크 항목이 저장된다.

### TC-CHECKLIST-ADD-DOMAIN-007: 입력한 제목과 설명을 그대로 기록한다

- 근거: `domain > 추가되는 체크리스트의 내용`
- Given: 제목 ` 여행 준비 `와 줄바꿈이 있는 설명이 입력되어 있다.
- When: 체크리스트 추가를 요청한다.
- Then: 제목과 설명이 앞뒤 공백과 줄바꿈을 포함해 입력한 그대로 저장된다.

### TC-CHECKLIST-ADD-DOMAIN-008: 넣어 둔 항목을 체크되지 않고 삭제되지 않은 새 체크 항목으로 함께 만든다

- 근거: `domain > 추가되는 체크리스트의 내용`
- Given: 넣어 둔 체크 항목 `여권`, `충전기`가 있다.
- When: 체크리스트 추가를 요청한다.
- Then: 새 체크리스트에 속한 체크 항목 `여권`, `충전기`가 넣을 때의 내용 그대로, 체크되지 않고 삭제되지 않은 상태로 저장된다.

### TC-CHECKLIST-ADD-DOMAIN-009: 항목 입력에 남은 내용을 맨 끝 항목으로 함께 만든다

- 근거: `domain > 추가되는 체크리스트의 내용`
- Given: 넣어 둔 체크 항목 `여권`이 있고 항목 입력이 테스트 데이터의 값이다.
- When: 체크리스트 추가를 요청한다.
- Then: 저장된 체크 항목이 추가순으로 테스트 데이터의 기대 결과와 같다.
- 테스트 데이터:

  | 항목 입력 | 기대 결과 |
  | --- | --- |
  | `우산` | `여권`, `우산` |
  | 비어 있음 | `여권` |
  | 공백 문자뿐 | `여권` |

### TC-CHECKLIST-ADD-DOMAIN-010: 새 체크리스트는 미삭제 상태로 같은 생성·수정 시각을 갖는다

- 근거: `domain > 추가되는 체크리스트의 내용`
- Given: 현재 시각이 고정되어 있다.
- When: 체크리스트 추가를 요청한다.
- Then: 새 체크리스트는 삭제되지 않은 상태이고, 생성 시각과 수정 시각이 모두 고정된 현재 시각이다.

### TC-CHECKLIST-ADD-DOMAIN-011: 함께 만드는 체크 항목은 넣어 둔 순서대로 생성 시각이 늦어진다

- 근거: `domain > 추가되는 체크리스트의 내용`, `domain > 체크 항목의 정보`
- Given: 현재 시각이 고정되어 있고 넣어 둔 체크 항목 `여권`, `충전기`, `우산`이 있다.
- When: 체크리스트 추가를 요청한다.
- Then: 저장된 체크 항목의 생성 시각이 `여권`, `충전기`, `우산` 순서로 차례로 늦고, 각 항목의 수정 시각은 그 항목의 생성 시각과 같으며, 추가순으로 조회하면 `여권`, `충전기`, `우산` 순서다.

### TC-CHECKLIST-ADD-DOMAIN-012: 새 체크리스트와 체크 항목은 모두 현재 계정과 연결한다

- 근거: `domain > 항목의 계정 연결`
- Given: 현재 사용자 계정이 확인된다.
- When: 체크 항목이 있는 체크리스트 추가를 요청한다.
- Then: 새 체크리스트와 모든 체크 항목이 현재 계정과 연결되어 저장된다.

### TC-CHECKLIST-ADD-DOMAIN-013: 현재 계정을 확인할 수 없으면 체크리스트를 추가하지 않는다

- 근거: `domain > 항목의 계정 연결`
- Given: 현재 계정 조회가 실패하도록 설정되어 있다.
- When: 체크리스트 추가를 요청한다.
- Then: 체크리스트와 체크 항목이 저장되지 않고 추가가 실패로 전달된다.

### TC-CHECKLIST-ADD-DOMAIN-014: 추가를 처리하는 동안 전달된 추가 요청은 처리하지 않는다

- 근거: `feature > 체크리스트 추가`
- Given: 체크리스트 추가 처리가 진행 중인 상태로 설정되어 있다.
- When: 처리가 끝나기 전에 사용자가 체크리스트 추가를 다시 실행한다.
- Then: 체크리스트 추가는 한 번만 요청된다.

## data

### TC-CHECKLIST-ADD-DATA-001: 체크리스트, 체크 항목과 계정의 연결을 한 번에 함께 기기에 저장한다

- 근거: `data > 체크리스트 생성과 저장`
- Given: 로그인한 사용자 계정이 있다.
- When: 체크 항목이 있는 체크리스트 추가를 실행한다.
- Then: 체크리스트, 모든 체크 항목과 그 모두의 계정 연결이 기기에 함께 저장된다.

### TC-CHECKLIST-ADD-DATA-002: 저장에 실패하면 추가가 성공으로 다뤄지지 않고 아무것도 저장되지 않는다

- 근거: `data > 체크리스트 생성과 저장`
- Given: 기기 저장이 실패하도록 설정되어 있다.
- When: 체크 항목이 있는 체크리스트 추가를 실행한다.
- Then: 추가가 성공한 것으로 다뤄지지 않고, 체크리스트, 체크 항목과 계정 연결 중 어느 것도 기기에 남지 않는다.

### TC-CHECKLIST-ADD-DATA-003: 저장한 체크리스트와 그 체크 항목을 함께 조회할 수 있다

- 근거: `data > 체크리스트 생성과 저장`
- Given: 로그인한 사용자 계정이 있다.
- When: 제목, 설명과 체크 항목을 담은 체크리스트를 저장한 뒤 그 체크리스트와 체크 항목을 조회한다.
- Then: 저장한 제목, 설명과 각 체크 항목의 내용, 체크 여부가 조회된다.

### TC-CHECKLIST-ADD-DATA-004: 기기에 저장이 끝나면 체크리스트와 체크 항목이 업로드 대기로 기록되고 동기화가 시작된다

- 근거: `data > 동기화`
- Given: 로그인한 사용자 계정이 있고 기기 저장이 성공한다.
- When: 체크 항목이 있는 체크리스트 추가를 실행한다.
- Then: 체크리스트와 모든 체크 항목이 각각 계정의 업로드 대기 상태로 기록되고 백그라운드 동기화가 한 번 요청된다.

### TC-CHECKLIST-ADD-DATA-005: 추가의 성공 여부는 기기에 저장한 결과로만 판단한다

- 근거: `data > 동기화`
- Given: 기기 저장은 성공하고 서버 반영은 실패하도록 설정되어 있다.
- When: 체크리스트 추가를 실행한다.
- Then: 추가가 성공으로 전달되고 체크리스트와 체크 항목은 기기에서 사라지지 않은 채 업로드 대기 상태로 남는다.

### TC-CHECKLIST-ADD-DATA-006: 로그인하지 않은 상태에서 추가한 체크리스트는 서버에 반영되지 않는다

- 근거: `data > 동기화`
- Given: 로그인하지 않아 게스트 상태의 계정이 확인된다.
- When: 체크리스트 추가를 실행한다.
- Then: 체크리스트와 체크 항목은 게스트 계정 기준으로 기기에 저장되고 서버 동기화는 요청되지 않는다.

## 작성하지 않는 케이스

- 백그라운드에 다녀온 뒤 입력한 내용이 유지되는 결과는 따로 작성하지 않는다. 앱이 백그라운드에 다녀오는 동안 이 화면은 그대로 남아 있어 다녀오기 전과 후를 구분할 관찰 결과가 없고, 시스템이 그사이 앱을 정리한 경우는 TC-CHECKLIST-ADD-DOMAIN-001이 확인한다.
- 체크 항목이 체크리스트보다 먼저 서버에 올라가지 않는 순서는 [데이터 동기화 테스트 케이스](./data-sync.md)가 확인한다.
