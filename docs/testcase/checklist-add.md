# ChecklistAdd 테스트 케이스

기준 스펙: [ChecklistAdd 화면 스펙](../spec/client/checklist-add.md)

작성 상태 유지, 뒤로가기, 저장 실패, 추가 요청 제한, 계정 연결과 저장 계약은 [항목 추가 화면 공통 스펙](../spec/client/entity-add.md)에 위임된 규칙을 이 화면에 적용한 결과를 이 문서가 확인한다. 체크 항목이 체크리스트보다 먼저 서버에 올라가지 않는 순서는 [데이터 동기화 테스트 케이스](./data-sync.md)의 TC-674eebce-610c-4b46-8dce-79aef5252327이 확인한다.

화면에 보이는 문구와 접근성 이름은 [ChecklistAdd 화면 디자인](../design/checklist-add.md)이 정한 문구를 기대 결과로 쓴다.

## feature

### TC-df04c07e-5719-446d-b2c9-8c7fbc5243d0: 상단 바에 화면 제목을 표시한다

- 근거: `feature > 화면 내용`
- Given: 사용자 언어가 테스트 데이터의 언어다.
- When: 사용자가 ChecklistAdd 화면을 확인한다.
- Then: 상단 바에 디자인이 정한 그 언어의 화면 제목이 표시된다.
- 테스트 데이터:

  | 언어 |
  | --- |
  | 한국어 |
  | 그 외 기본 |

### TC-47727fb9-7734-4141-a2df-45f1ca768e92: 처음 들어오면 입력이 비어 있고 넣어 둔 항목이 없으며 제목 입력에 초점이 있다

- 근거: `feature > 진입`
- Given: ChecklistHome 화면이 표시되어 있다.
- When: 사용자가 체크리스트 추가로 ChecklistAdd 화면에 진입한다.
- Then: 제목, 설명과 항목 입력이 비어 있고, 넣어 둔 체크 항목이 하나도 없으며, 입력 초점이 제목 입력에 있다.

### TC-4e01a6c9-4a71-4a11-a11e-6455743b9833: 화면에는 정해진 입력과 동작만 둔다

- 근거: `feature > 화면 내용`
- Given: ChecklistAdd 화면에 체크 항목 하나를 넣어 두었다.
- When: 사용자가 화면에서 확인할 수 있는 정보와 동작을 확인한다.
- Then: 화면 제목, 뒤로가기, 제목 입력, 설명 입력, 넣어 둔 체크 항목 목록, 항목 입력, 항목 넣기와 체크리스트 추가만 있고 그 밖의 동작은 없다.

### TC-ef7ce65b-6841-4f5c-a688-c6368a1906d5: 항목 넣기를 실행하면 목록 맨 끝에 놓이고 항목 입력이 비워진다

- 테스트 데이터:

  | 넣는 방법 |

### TC-4008f7b3-8cd2-42b4-9a15-fe00d5eed0ee: 넣어 둔 항목을 빼면 사라지고 남은 항목의 순서는 그대로다

### TC-a2bdef97-6d51-4129-87da-2df44ee12c76: 넣어 둔 항목이 없으면 안내 없이 목록 자리를 비워 둔다

### TC-bc713440-0005-43de-9923-2097f1f33358: 추가에 성공하면 화면에 머문 채 입력과 넣어 둔 항목을 비우고 성공 피드백을 제공한다

- Then: 체크리스트 추가가 한 번 요청되고, ChecklistAdd 화면에 머무르며 제목, 설명, 항목 입력과 넣어 둔 체크 항목이 모두 비워지고, 입력 초점이 제목 입력으로 옮겨지며 성공 피드백이 제공된다. ChecklistHome 화면으로 이동하는 동작은 실행되지 않는다.

### TC-fb408e72-941f-425f-91a2-d88d18702f7f: 저장에 실패하면 안내 없이 작성 내용을 유지하고 진행 상태만 해제한다

### TC-e59eaf14-df79-4587-a34f-775b4ffa7492: 제목 없이 추가하면 제목 입력을 알리고 초점을 옮긴다
