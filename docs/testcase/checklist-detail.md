# ChecklistDetail 테스트 케이스

기준 스펙: [ChecklistDetail 화면 스펙](../spec/client/checklist-detail.md)

진입할 때의 입력 초점, 내용 수정의 반영과 성공 결과, 요청 제한과 저장 계약은 [항목 상세 화면 공통 스펙](../spec/client/entity-detail.md)에, 정렬을 고르고 바꾸는 행동은 [목록 정렬 스펙](../spec/client/list-sort.md)에 위임된 규칙을 이 화면에 적용한 결과를 이 문서가 확인한다.

화면에 보이는 문구와 접근성 이름은 [ChecklistDetail 화면 디자인](../design/checklist-detail.md)이 정한 문구를 기대 결과로 쓴다.

## feature

### TC-CHECKLIST-DETAIL-FEATURE-001: 조회에 성공하면 저장된 내용으로 화면을 채운다

- 근거: `feature > 진입과 내용`, `domain > 입력 내용 채우기`
- Given: 현재 계정에 제목 `여행 준비`, 설명 `주말`과 체크 항목 `여권`(체크함), `충전기`(체크 안 함)가 있는 체크리스트가 저장되어 있다.
- When: 사용자가 그 체크리스트의 ChecklistDetail 화면에 진입한다.
- Then: 화면 제목 `여행 준비`, 제목 입력 `여행 준비`, 설명 입력 `주말`이 표시되고, 체크 항목 `여권`이 체크된 상태로, `충전기`가 체크되지 않은 상태로 보이며, 항목 입력은 비어 있다.

### TC-CHECKLIST-DETAIL-FEATURE-002: 진입할 때 어느 입력에도 초점을 두지 않는다

- 근거: `feature > 진입과 내용`
- Given: 현재 계정에 체크리스트가 저장되어 있다.
- When: 사용자가 그 체크리스트의 ChecklistDetail 화면에 진입한다.
- Then: 제목 입력, 설명 입력, 항목 입력 어디에도 입력 초점이 없다.

### TC-CHECKLIST-DETAIL-FEATURE-003: 조회 중에는 입력과 동작을 실행할 수 없다

- 근거: `feature > 조회 상태`
- Given: 체크리스트 조회가 끝나지 않은 상태로 설정되어 있다.
- When: 사용자가 ChecklistDetail 화면을 확인한다.
- Then: 조회 중 상태가 표시되고, 입력, 체크, 항목 넣기와 빼기, 리셋, 정렬 선택, 수정과 삭제를 실행할 수 없다.

### TC-CHECKLIST-DETAIL-FEATURE-004: 조회할 수 없으면 조회 중 상태를 유지한다

- 근거: `feature > 조회 상태`
- Given: 대상 체크리스트 조회가 테스트 데이터의 결과로 끝나도록 설정되어 있다.
- When: 사용자가 ChecklistDetail 화면에 진입한다.
- Then: 조회 중 상태가 유지되고 오류 안내는 표시되지 않는다.
- 테스트 데이터:

  | 조회 결과 |
  | --- |
  | 대상 체크리스트가 없음 |
  | 조회 실패 |

### TC-CHECKLIST-DETAIL-FEATURE-005: 화면에는 정해진 입력과 동작만 둔다

- 근거: `feature > 화면 내용`
- Given: 체크된 항목이 있는 체크리스트의 ChecklistDetail 화면이 내용 표시 상태이고, 입력이 저장된 내용과 다르다.
- When: 사용자가 화면에서 확인할 수 있는 정보와 동작을 확인한다.
- Then: 화면 제목, 뒤로가기, 리셋, 삭제, 제목 입력, 설명 입력, 수정 반영, 정렬 선택, 체크 항목 목록, 각 체크 항목의 항목 빼기, 항목 입력과 항목 넣기만 있고 그 밖의 동작은 없다.

### TC-CHECKLIST-DETAIL-FEATURE-006: 체크 항목이 없으면 빈 상태 안내를 표시하고 다른 동작은 그대로 쓸 수 있다

- 근거: `feature > 체크 항목 목록`
- Given: 노출할 체크 항목이 없는 체크리스트의 조회가 끝났다.
- When: 사용자가 ChecklistDetail 화면을 확인한다.
- Then: 목록 자리에 아직 체크 항목이 없으며 항목 입력으로 넣을 수 있음을 알리는 안내가 표시되고, 항목 넣기, 제목·설명 수정과 삭제를 실행할 수 있다.

### TC-CHECKLIST-DETAIL-FEATURE-007: 체크 항목을 불러오는 동안에는 빈 상태 안내를 표시하지 않는다

- 근거: `feature > 체크 항목 목록`
- Given: 체크리스트 조회는 끝났지만 체크 항목 조회가 끝나지 않은 상태로 설정되어 있다.
- When: 사용자가 ChecklistDetail 화면을 확인한다.
- Then: 빈 상태 안내가 표시되지 않는다.

### TC-CHECKLIST-DETAIL-FEATURE-008: 체크 항목을 선택하면 체크 상태가 바뀌어 즉시 저장된다

- 근거: `feature > 체크와 체크 해제`
- Given: ChecklistDetail 화면에 테스트 데이터의 체크 상태인 체크 항목이 있고 저장이 성공하도록 설정되어 있다.
- When: 사용자가 그 항목을 선택한다.
- Then: 확인을 되묻지 않고 그 항목의 체크 변경이 한 번 요청되어, 항목이 테스트 데이터의 기대 상태로 보인다. 수정 반영 동작은 나타나지 않는다.
- 테스트 데이터:

  | 처음 상태 | 기대 상태 |
  | --- | --- |
  | 체크 안 함 | 체크함 |
  | 체크함 | 체크 안 함 |

### TC-CHECKLIST-DETAIL-FEATURE-009: 체크 안 된 항목 우선에서 체크 상태를 바꾸면 해당 묶음으로 옮겨진다

- 근거: `feature > 체크와 체크 해제`
- Given: 정렬이 테스트 데이터의 정렬이고, 체크 항목 `A`, `B`, `C`가 추가순으로 있으며 모두 체크되지 않았다.
- When: 사용자가 `A`를 체크한다.
- Then: 목록이 테스트 데이터의 기대 순서로 보인다.
- 테스트 데이터:

  | 정렬 | 기대 순서 |
  | --- | --- |
  | 추가순 | `A`, `B`, `C` |
  | 체크 안 된 항목 우선 | `B`, `C`, `A` |

### TC-CHECKLIST-DETAIL-FEATURE-010: 체크 변경을 저장하지 못하면 안내 없이 저장된 상태를 보여 준다

- 근거: `feature > 체크와 체크 해제`
- Given: ChecklistDetail 화면에 체크되지 않은 항목이 있고 체크 변경 저장이 실패하도록 설정되어 있다.
- When: 사용자가 그 항목을 선택한다.
- Then: 그 항목은 체크되지 않은 상태로 보이고 안내는 표시되지 않으며, 사용자는 다시 선택할 수 있다.

### TC-CHECKLIST-DETAIL-FEATURE-011: 항목 넣기를 실행하면 새 항목이 나타나고 항목 입력이 비워진다

- 근거: `feature > 항목 넣기`
- Given: ChecklistDetail 화면의 항목 입력에 `우산`을 적었고 저장이 성공하도록 설정되어 있다.
- When: 사용자가 테스트 데이터의 방법으로 항목을 넣는다.
- Then: 항목 넣기가 한 번 요청되고, `우산`이 체크되지 않은 상태로 목록에 나타나며, 항목 입력이 비워지고 입력 초점이 항목 입력에 남는다. 수정 반영 동작은 나타나지 않는다.
- 테스트 데이터:

  | 넣는 방법 |
  | --- |
  | 항목 넣기 선택 |
  | 입력을 마치는 키 |

### TC-CHECKLIST-DETAIL-FEATURE-012: 항목 입력이 비어 있거나 공백뿐이면 항목을 넣지 않는다

- 근거: `feature > 항목 넣기`
- Given: ChecklistDetail 화면의 항목 입력이 테스트 데이터의 값이다.
- When: 사용자가 항목 넣기를 찾고 입력을 마치는 키를 누른다.
- Then: 항목 넣기가 제공되지 않고, 항목 넣기가 요청되지 않는다.
- 테스트 데이터:

  | 항목 입력 |
  | --- |
  | 비어 있음 |
  | 공백 문자뿐 |

### TC-CHECKLIST-DETAIL-FEATURE-013: 항목 넣기를 저장하지 못하면 항목 입력을 그대로 둔다

- 근거: `feature > 항목 넣기`
- Given: ChecklistDetail 화면의 항목 입력에 `우산`을 적었고 항목 넣기 저장이 실패하도록 설정되어 있다.
- When: 사용자가 항목 넣기를 실행한다.
- Then: 목록에 `우산`이 나타나지 않고, 항목 입력에 `우산`이 그대로 남으며 안내는 표시되지 않는다.

### TC-CHECKLIST-DETAIL-FEATURE-014: 항목을 빼면 확인 없이 목록에서 사라진다

- 근거: `feature > 항목 빼기`
- Given: ChecklistDetail 화면에 체크 항목 `여권`, `충전기`, `우산`이 추가순으로 있고 저장이 성공하도록 설정되어 있다.
- When: 사용자가 `충전기`를 뺀다.
- Then: 확인을 되묻지 않고 `충전기`의 빼기가 한 번 요청되며, 목록이 `여권`, `우산` 순서로 보이고 실행 취소 동작은 제공되지 않는다.

### TC-CHECKLIST-DETAIL-FEATURE-015: 항목 빼기를 저장하지 못하면 안내 없이 항목이 남는다

- 근거: `feature > 항목 빼기`
- Given: ChecklistDetail 화면에 체크 항목이 있고 빼기 저장이 실패하도록 설정되어 있다.
- When: 사용자가 그 항목을 뺀다.
- Then: 그 항목이 목록에 그대로 남고 안내는 표시되지 않는다.

### TC-CHECKLIST-DETAIL-FEATURE-016: 체크된 항목이 있을 때만 리셋을 실행할 수 있다

- 근거: `feature > 리셋`
- Given: ChecklistDetail 화면의 체크 항목이 테스트 데이터의 상태다.
- When: 사용자가 리셋을 확인한다.
- Then: 리셋 실행 가능 여부가 테스트 데이터의 기대 결과와 같다.
- 테스트 데이터:

  | 체크 항목 | 리셋 |
  | --- | --- |
  | 체크된 항목이 하나 이상 있음 | 실행할 수 있음 |
  | 모두 체크 안 함 | 실행할 수 없음 |
  | 항목이 없음 | 실행할 수 없음 |

### TC-CHECKLIST-DETAIL-FEATURE-017: 리셋을 선택하면 되묻고, 확정하면 모든 체크가 해제된다

- 근거: `feature > 리셋`
- Given: ChecklistDetail 화면에 체크된 항목이 있고 리셋 저장이 성공하도록 설정되어 있다.
- When: 사용자가 리셋을 선택하고 표시된 확인에서 해제를 확정한다.
- Then: 리셋을 선택했을 때 모든 체크를 해제할지 묻는 확인이 표시되고, 확정하면 리셋이 한 번 요청되어 모든 항목이 체크되지 않은 상태로 보인다.

### TC-CHECKLIST-DETAIL-FEATURE-018: 리셋 확인을 취소하거나 닫으면 아무것도 바꾸지 않는다

- 근거: `feature > 리셋`
- Given: ChecklistDetail 화면에 체크된 항목이 있고 리셋 확인이 표시되어 있다.
- When: 사용자가 테스트 데이터의 방법으로 확인을 끝낸다.
- Then: 확인이 닫히고 리셋이 요청되지 않으며 체크 상태는 그대로다.
- 테스트 데이터:

  | 끝내는 방법 |
  | --- |
  | 취소 선택 |
  | 확인 바깥을 눌러 닫음 |

### TC-CHECKLIST-DETAIL-FEATURE-019: 리셋을 처리하는 동안 진행 상태를 표시한다

- 근거: `feature > 리셋`
- Given: 리셋 처리가 완료되지 않고 진행 중인 상태로 설정되어 있다.
- When: 사용자가 리셋을 확정한 뒤 화면을 확인한다.
- Then: 리셋 처리가 끝날 때까지 진행 상태가 표시된다.

### TC-CHECKLIST-DETAIL-FEATURE-020: 리셋은 입력 중이던 내용을 바꾸지 않는다

- 근거: `feature > 리셋`
- Given: ChecklistDetail 화면에서 제목 입력을 `새 제목`, 항목 입력을 `우산`으로 고쳤고 체크된 항목이 있다.
- When: 사용자가 리셋을 확정해 리셋이 성공한다.
- Then: 제목 입력 `새 제목`과 항목 입력 `우산`이 그대로 남고 수정 반영 동작도 그대로 제공된다.

### TC-CHECKLIST-DETAIL-FEATURE-021: 리셋을 저장하지 못하면 안내 없이 진행 상태만 해제한다

- 근거: `feature > 리셋`
- Given: ChecklistDetail 화면에 체크된 항목이 있고 리셋 저장이 실패하도록 설정되어 있다.
- When: 사용자가 리셋을 확정한다.
- Then: 진행 상태가 해제되고, 항목은 체크된 상태 그대로 보이며 안내는 표시되지 않고, 리셋을 다시 실행할 수 있다.

### TC-CHECKLIST-DETAIL-FEATURE-022: 처음 정렬은 추가순이고 체크 안 된 항목 우선으로 바꿀 수 있다

- 근거: `feature > 정렬`
- Given: ChecklistDetail 화면에 체크 항목 `A`(체크함), `B`(체크 안 함), `C`(체크함)가 추가순으로 있다.
- When: 사용자가 처음 화면을 확인한 뒤 정렬을 체크 안 된 항목 우선으로 바꾼다.
- Then: 처음에는 추가순이 선택되어 `A`, `B`, `C` 순서로 보이고, 바꾼 뒤에는 체크 안 된 항목 우선이 선택되어 `B`, `A`, `C` 순서로 보인다.

### TC-CHECKLIST-DETAIL-FEATURE-023: 고를 수 있는 정렬은 추가순과 체크 안 된 항목 우선뿐이다

- 근거: `feature > 정렬`
- Given: ChecklistDetail 화면에 체크 항목이 있다.
- When: 사용자가 정렬 선택을 연다.
- Then: 추가순과 체크 안 된 항목 우선 두 기준만 고를 수 있다.

### TC-CHECKLIST-DETAIL-FEATURE-024: 체크 항목이 없으면 정렬을 바꿀 수 없다

- 근거: `feature > 정렬`
- Given: 노출할 체크 항목이 없는 체크리스트의 ChecklistDetail 화면이 표시되어 있다.
- When: 사용자가 정렬 선택을 찾는다.
- Then: 정렬 기준을 확인하거나 바꿀 수 없다.

### TC-CHECKLIST-DETAIL-FEATURE-025: 입력이 저장된 내용과 다를 때만 수정 동작을 제공한다

- 근거: `feature > 내용 수정`, `domain > 수정 동작의 제공 기준`
- Given: 제목 `여행 준비`, 설명 `주말`로 저장된 체크리스트의 ChecklistDetail 화면이 표시되어 있다.
- When: 사용자가 입력을 테스트 데이터처럼 바꾼다.
- Then: 수정 반영 동작의 제공 여부가 테스트 데이터의 기대 결과와 같다.
- 테스트 데이터:

  | 입력 변경 | 수정 반영 동작 |
  | --- | --- |

- When: 체크리스트 수정, 체크 변경, 항목 넣기, 항목 빼기, 리셋 중 하나를 실행한다.
- Then: 게스트 계정 기준으로 기기에 저장되고 서버 동기화는 요청되지 않는다.

### TC-CHECKLIST-DETAIL-DATA-007: ChecklistDetail 진입만으로는 서버에서 다시 가져오지 않는다

- 근거: `data > 대상 체크리스트와 체크 항목 조회`
- Given: 진행 중인 동기화가 없다.
- When: 사용자가 ChecklistDetail 화면에 진입한다.
- Then: 계정 데이터의 서버 동기화가 요청되지 않는다.

### TC-CHECKLIST-DETAIL-DATA-008: 체크 항목을 조회하지 못하면 항목이 없는 것으로 표시한다

- 근거: `data > 대상 체크리스트와 체크 항목 조회`
- Given: 체크리스트 조회는 성공하고 체크 항목 조회가 실패하도록 설정되어 있다.
- When: 사용자가 ChecklistDetail 화면에 진입한다.
- Then: 체크 항목이 하나도 표시되지 않고 빈 상태 안내가 표시되며 오류 안내는 표시되지 않는다.

## 작성하지 않는 케이스

- 같은 체크리스트의 서로 다른 항목을 여러 기기에서 바꾸면 각 변경이 모두 남는 결과는 서버가 항목마다 충돌을 판정한 결과이므로 앱의 단위 테스트로 확인할 수 없다. 앱이 체크 항목을 항목마다 따로 올리는 요청 구성만 [데이터 동기화 테스트 케이스](./data-sync.md)의 TC-DATA-SYNC-DOMAIN-096이 확인하며, 서버가 항목마다 충돌을 판정하는 결과를 확인하는 케이스는 없다. 서버 함수를 실행할 수 있는 테스트 환경이 마련되면 작성한다.
- 백그라운드에 다녀온 뒤 입력이 유지되는 결과는 이 화면이 그대로 남아 있어 화면 재생성과 구분할 관찰 결과가 없으므로 작성하지 않는다. 백그라운드 복귀만 따로 일으키고 그 사이의 화면 상태를 관찰할 수 있는 테스트 환경이 마련되면 작성한다. 시스템이 그사이 앱을 정리한 경우는 TC-CHECKLIST-DETAIL-DOMAIN-015가 확인한다.
- `data > 결과의 표시`의 ChecklistHome 반영(제목에 따른 자리 이동, 진행 정도 변경)은 같은 저장 변경으로 [ChecklistHome 테스트 케이스](./checklist-home.md)의 TC-CHECKLIST-HOME-DOMAIN-005가 확인하므로 이 문서에 따로 두지 않는다.
