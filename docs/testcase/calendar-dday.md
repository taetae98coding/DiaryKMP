# 캘린더 디데이 표시 테스트 케이스

기준 스펙: [캘린더 디데이 표시 스펙](../spec/client/calendar-dday.md)

기준일 당일과 기념일이 차지하는 날짜, 기념일 문구와 같은 날짜의 기념일을 합치는 계산 규칙은 [디데이 앱 스펙](../spec/client/dday.md)이 소유하므로 그 테스트 케이스 문서에서 다룬다. 이 문서는 그 결과가 표시 대상 기간에 따라 캘린더 디데이로 전달되는 것만 다루며, 케이스에 적은 날짜와 문구는 디데이 앱 스펙의 예시와 규칙을 따른 값이다.

## domain

### TC-bbd24f37-a550-4615-9b94-11b4c8506186: 표시 대상 기간에 드는 날짜를 차지하는 디데이만 표시 대상이 된다

- 근거: `domain > 표시 대상 기간`, `domain > 노출 기준`
- Given: 현재 사용자 계정에 반복 간격이 없고 기준일이 테스트 데이터와 같은 디데이가 저장되어 있다.
- When: 2026년 6월 28일부터 8월 8일까지를 표시 대상 기간으로 캘린더 디데이를 조회한다.
- Then: 기준일이 표시 대상 기간에 드는 디데이만 그 기준일을 차지하는 문구 `D-Day`의 캘린더 디데이로 결과에 포함된다.
- 테스트 데이터:

| 기준일 | 결과 포함 | 비고 |
| --- | --- | --- |
| 2026년 6월 27일 | 아님 | 표시 대상 기간보다 하루 이전 |
| 2026년 6월 28일 | 포함 | 표시 대상 기간 시작일, 표시 중인 달에 속하지 않는 이웃 달의 날짜 |
| 2026년 7월 15일 | 포함 | 표시 대상 기간 안 |
| 2026년 8월 8일 | 포함 | 표시 대상 기간 종료일, 이웃 달의 날짜 |
| 2026년 8월 9일 | 아님 | 표시 대상 기간보다 하루 이후 |

- Given: 현재 사용자 계정에 기준일이 2026년 1월 1일, 기준일을 1일로 세기가 켜져 있고 반복 간격이 100일인 디데이가 저장되어 있어, 2026년 3월 29일부터 5월 9일까지의 조회 결과에 4월 10일 `100일`이 담겨 있고 그 결과를 계속 관찰하고 있다.
- When: 조회를 다시 요청하지 않은 상태에서 테스트 데이터의 변경이 저장된다.
- Then: 테스트 데이터의 결과가 이어서 전달된다.
- 테스트 데이터:

| 변경 | 결과 |
| --- | --- |
| 기준일을 1일로 세기를 끔 | 4월 11일 `100일`, 4월 10일은 빠짐 |
| 기준일을 2026년 1월 2일로 바꿈 | 4월 11일 `100일`, 4월 10일은 빠짐 |
| 반복 간격을 비움 | 결과가 비어 있음 |
| 종료일을 2026년 4월 9일로 정함 | 결과가 비어 있음 |

### TC-e5986f21-11df-4faa-ab95-c93dc4733401: 달력에 없는 날짜 처리가 바뀌면 그 처리로 정한 날짜가 전달된다

### TC-728c3b7d-44de-447d-8c67-67f96b353dc6: 캘린더 디데이 조회는 원격에서 디데이를 따로 받아 오지 않는다

- 근거: `data > 캘린더 디데이 조회`
- Given: 현재 사용자 계정의 기기에 디데이가 저장되어 있고, 원격에는 기기에 아직 반영되지 않은 다른 디데이가 있다.
- When: 표시 대상 기간으로 캘린더 디데이를 조회한다.
- Then: 기기에 저장된 디데이의 캘린더 디데이만 결과에 담기고, 원격으로 디데이를 요청하지 않는다.
- 작성하지 않는 이유: 캘린더 디데이 조회는 원격과 이어지는 경계를 거치지 않으므로, 원격으로 요청하지 않았다는 결과를 테스트가 관찰할 대상이 없어 결정적으로 판정할 수 없다. 원격 요청을 기록할 수 있는 앱 수준 통합 테스트 환경이 갖춰지면 자동화한다.
