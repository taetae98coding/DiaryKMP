# MoreHome 테스트 케이스

기준 스펙: [MoreHome 화면 스펙](../spec/more-home.md)

## feature

### TC-MORE-HOME-FEATURE-003: 확인 중 상태에서는 라벨과 계정 동작을 표시하지 않는다

- 근거: `feature > 계정 상태와 행동`
- Given: 계정 정보가 확인 중이다.
- When: 사용자가 계정 상태를 확인한다.
- Then: 게스트 라벨과 이메일이 표시되지 않고, 로그인 동작과 로그아웃 동작도 선택할 수 없다.

### TC-MORE-HOME-FEATURE-004: 게스트 상태에서 게스트 라벨과 로그인 동작을 표시한다

- 근거: `feature > 계정 상태와 행동`
- Given: 로그인한 사용자 정보가 없어 계정 상태가 게스트다.
- When: 사용자가 계정 상태를 확인한다.
- Then: 게스트 상태가 표시되고 로그인 동작을 선택할 수 있다.

### TC-MORE-HOME-FEATURE-005: 사용자 상태에서 이메일과 로그아웃 동작을 표시한다

- 근거: `feature > 계정 상태와 행동`
- Given: 이메일 `diary@example.com`을 가진 로그인 사용자 정보가 있다.
- When: 사용자가 계정 상태를 확인한다.
- Then: `diary@example.com`이 표시되고 게스트 상태는 표시되지 않으며 로그아웃 동작을 선택할 수 있다.

### TC-MORE-HOME-FEATURE-006: 로그인 동작을 선택하면 Login 화면으로 이동한다

- 근거: `feature > 계정 상태와 행동`

### TC-MORE-HOME-FEATURE-007: 업로드 대기 항목이 없으면 확인 없이 로그아웃한다

- 근거: `feature > 계정 상태와 행동`, `feature > 로그아웃 확인`
- Given: 계정 상태가 사용자로 표시되어 있고, 계정에 업로드 대기 항목이 없으며, 로그아웃이 성공하도록 제어되어 있다.
- When: 사용자가 로그아웃 동작을 선택한다.
- Then: 확인 다이얼로그가 표시되지 않고 계정 상태가 게스트로 바뀌며 로그인 동작을 선택할 수 있다.

### TC-MORE-HOME-FEATURE-008: 한글이 아닌 이름을 앞에 두고 가나다순으로 표시한다

- When: 사용자가 MoreHome 화면을 확인한다.

- When: 사용자가 다이얼로그의 취소를 고른다.
- Then: 다이얼로그가 닫히고 로그아웃이 실행되지 않으며 `diary@example.com`과 로그아웃 동작이 그대로 표시된다.

### TC-MORE-HOME-FEATURE-029: 확인 다이얼로그를 고르지 않고 닫으면 로그아웃하지 않는다

- 근거: `feature > 로그아웃 확인`
- 작성하지 않는 이유: 다이얼로그 바깥 누름과 뒤로가기는 앱이 아니라 플랫폼 창이 일으키는 조작이라 현재 화면 테스트 환경에서 결정적으로 발생시킬 수 없다. 자동화하려면 실제 Activity 창을 띄워 뒤로가기와 창 바깥 입력을 보낼 수 있는 테스트 환경이 필요하다.

## domain

### TC-MORE-HOME-DOMAIN-001: 로그인한 사용자 정보가 없으면 게스트 상태로 표시한다

- 근거: `domain > 계정 표시 상태`
- Given: 로그인한 사용자 정보가 없다.
- When: 사용자가 MoreHome 화면을 확인한다.
- Then: 계정 상태가 게스트로 표시되고 로그인 동작이 제공된다.

### TC-MORE-HOME-DOMAIN-002: 로그인한 사용자 정보가 있으면 사용자 상태로 표시한다

- 근거: `domain > 계정 표시 상태`
- Given: 이메일과 프로필 이미지를 가진 로그인 사용자 정보가 있다.
- When: 사용자가 MoreHome 화면을 확인한다.
- Then: 계정 상태가 사용자로 표시되고 해당 사용자 정보의 이메일과 프로필 이미지가 사용되며 로그아웃 동작이 제공된다.

### TC-MORE-HOME-DOMAIN-003: 계정 정보를 확인하기 전이나 확인에 실패하면 확인 중 상태를 유지한다

- When: 사용자가 MoreHome 화면을 확인한다.
- Then: 오류 안내 없이 계정 상태가 확인 중으로 유지되고 게스트나 사용자 상태로 확정되지 않는다.

### TC-MORE-HOME-DOMAIN-008: 다이얼로그가 열린 뒤 업로드 대기 항목이 해제되어도 다이얼로그를 닫지 않는다

- 근거: `domain > 로그아웃 확인 조건`
- Given: 로그아웃 확인 다이얼로그가 표시되어 있다.
- When: 계정의 업로드 대기 항목이 모두 해제된다.
- Then: 다이얼로그가 그대로 표시되고 로그아웃이 실행되지 않는다.

### TC-MORE-HOME-DOMAIN-009: 화면이 재생성되어도 다이얼로그가 열린 상태를 유지한다

- 근거: `domain > 로그아웃 확인 실행 경계`
- Given: 로그아웃 확인 다이얼로그가 표시되어 있다.
- When: 화면이 시스템에 의해 재생성된다.
- Then: 로그아웃 확인 다이얼로그가 계속 표시된다.

### TC-MORE-HOME-DOMAIN-010: 화면을 떠난 뒤 다시 들어오면 다이얼로그가 닫힌 상태로 시작한다

- 근거: `domain > 로그아웃 확인 실행 경계`
- 작성하지 않는 이유: 다른 화면으로 이동했다가 돌아오는 흐름과 앱을 다시 시작하는 흐름은 MoreHome 한 화면만으로 재현할 수 없어 통합 또는 E2E 항목이 된다. 자동화하려면 여러 목적지를 오가는 내비게이션과 앱 재시작을 제어할 수 있는 테스트 환경이 필요하다.

## data

### TC-MORE-HOME-DATA-001: 로그아웃하면 저장된 로그인 세션이 제거된다

- 근거: `data > 로그아웃 시 데이터 처리`
- Given: 로그인 세션이 저장되어 있고 계정에 업로드 대기 항목이 없다.
- When: 사용자가 로그아웃한다.
- Then: 저장된 로그인 세션을 제거하는 요청이 한 번 이루어진다.

### TC-MORE-HOME-DATA-002: 고른 사진으로 저장된 프로필 이미지를 바꾸도록 요청한다

- 근거: `data > 프로필 이미지 반영 요청`
- Given: 계정 상태가 사용자다.
- When: 사용자가 사진 선택에서 사진을 고른다.
- Then: 고른 사진의 위치로 저장된 사용자 정보의 프로필 이미지를 바꾸는 요청이 한 번 이루어진다.

### TC-MORE-HOME-DATA-003: 로그아웃 동작을 선택하면 업로드 대기 항목 존재 여부를 기기 저장소에서 조회한다

- 근거: `data > 업로드 대기 항목 조회`
- Given: 계정 상태가 사용자다.
- When: 사용자가 로그아웃 동작을 선택한다.
- Then: 그 계정의 업로드 대기 항목이 있는지를 기기 저장소에 조회하는 요청이 한 번 이루어지고, 서버에는 아무 요청도 하지 않는다.

### TC-MORE-HOME-DATA-004: 로그아웃해도 기기에 저장된 업로드 대기 상태가 지워지지 않는다

- 근거: `data > 로그아웃 시 데이터 처리`
- 작성하지 않는 이유: 로그아웃은 로그인 세션만 제거하고 기기 저장소를 건드리는 경계 자체가 없어, 기기 데이터가 남아 있다는 것을 관찰할 요청이나 응답이 없다. 자동화하려면 로그아웃과 기기 저장소를 함께 통과시키는 통합 테스트 환경이 필요하다.
