# TagDetail 테스트 케이스

기준 스펙: [TagDetail 화면 스펙](../spec/client/tag-detail.md)

연결 입력의 공통 표시와 조작, 태그 선택 목록의 케이스는 [태그 연결 입력 컴포넌트 테스트 케이스](./tag-link-input.md)에서 다룬다. 이 문서에는 연결 조작이 저장된 태그 연결에 반영되는 케이스와, TagDetail 화면에서만 다른 연결 입력의 표시 기준 케이스를 둔다.

메모·웹·장소 탭 안의 목록, 빈 상태와 추가 동작 케이스는 각각 [TagDetail 메모 탭 테스트 케이스](./tag-detail-memo.md), [TagDetail 웹 탭 테스트 케이스](./tag-detail-web.md), [TagDetail 장소 탭 테스트 케이스](./tag-detail-place.md)에서 다룬다. 이 문서에는 화면 전체와 태그 디테일 탭의 케이스를 둔다.

## feature

### TC-TAG-DETAIL-FEATURE-001: 조회에 성공하면 태그의 이모지, 제목, 설명과 컬러를 표시한다

- 근거: `feature > 진입과 내용`, `feature > 조회 상태`
- Given: 선택한 태그의 이모지, 제목, 설명, 컬러를 조회할 수 있도록 설정되어 있다.
- When: 사용자가 해당 태그의 TagDetail 화면에 진입한다.
- Then: 조회 중 상태가 끝나고 이모지 입력에 조회한 이모지가, 제목 입력에 조회한 제목이, 설명 입력에 조회한 설명이, 컬러 입력에 조회한 컬러가 표시되며, 화면 제목에는 조회한 이모지와 제목이 함께 표시된다.

### TC-TAG-DETAIL-FEATURE-029: 이모지가 비어 있으면 화면 제목에 제목만 표시한다

- 근거: `domain > 상세 대상과 내용 표시`
- Given: 이모지가 비어 있고 제목이 있는 태그를 조회할 수 있도록 설정되어 있다.
- When: 사용자가 해당 태그의 TagDetail 화면에 진입한다.
- Then: 화면 제목에 앞선 공백 없이 제목만 표시된다.

### TC-TAG-DETAIL-FEATURE-003: 뒤로가기를 사용하면 이전 화면으로 돌아간다

- 근거: `feature > 뒤로가기`
- Given: TagDetail 화면이 표시되어 있다.
- When: 사용자가 뒤로간다.
- Then: TagDetail 화면에 진입하기 전 화면으로 돌아간다.

### TC-TAG-DETAIL-FEATURE-004: 저장 전 제목을 수정해도 화면 제목은 저장 제목을 유지한다

- 근거: `feature > 외부 변경과 대상 전환`, `domain > 상세 대상과 내용 표시`
- Given: 처음 진입해 화면 제목과 제목 입력에 조회한 태그의 제목이 표시되어 있다.
- When: 사용자가 제목 입력 칸의 내용을 다른 값으로 수정한다.
- Then: 제목 입력에는 수정한 값이 표시되고 화면 제목은 아직 저장된 제목을 유지한다.

### TC-TAG-DETAIL-FEATURE-005: 화면 재생성 후에도 수정 중이던 내용이 유지된다

- 근거: `feature > 진행 상태 유지`
- Given: 첫진입해 이모지, 제목, 설명, 컬러가 채워진 뒤 사용자가 이모지 입력, 제목 입력 칸과 설명 입력의 내용을 다른 값으로 수정했다.
- When: 시스템에 의해 화면이 재생성된다.
- Then: 이모지 입력, 제목 입력 칸과 설명 입력에 수정 중이던 내용이 유지되고, 조회한 내용으로 다시 덮어쓰이지 않는다.

### TC-TAG-DETAIL-FEATURE-007: 다른 태그를 선택하면 새 태그의 내용으로 바뀐다

- 근거: `feature > 외부 변경과 대상 전환`
- Given: 첫진입한 태그의 제목 입력 칸과 설명 입력을 수정한 상태다.
- When: 사용자가 목록에서 다른 태그를 선택한다.
- Then: 화면 제목과 제목 입력, 설명 입력, 컬러 입력에 새로 선택한 태그의 내용이 표시되고, 이전 태그에서 수정 중이던 내용은 표시되지 않는다.

### TC-TAG-DETAIL-FEATURE-008: 같은 태그의 저장 이모지나 제목이 변경되면 화면 제목만 갱신된다

- 근거: `feature > 외부 변경과 대상 전환`
- Given: 첫진입한 태그의 이모지 입력과 제목 입력 칸을 수정한 상태다.
- When: 같은 태그의 저장된 이모지나 제목이 다른 경로로 변경된다.
- Then: 화면 제목에는 변경된 저장 이모지와 제목이 표시되고 이모지 입력과 제목 입력에는 수정 중인 내용이 유지된다.

### TC-TAG-DETAIL-FEATURE-009: 수정을 실행해도 수정 중이던 내용이 유지된다

- 근거: `feature > 내용 수정`
- Given: 태그 수정이 성공하도록 설정되어 있고, 첫진입한 태그의 입력 내용을 저장된 내용과 다르게 수정했다.
- When: 사용자가 변경한 내용의 반영을 실행한다.
- Then: TagDetail 화면이 그대로 유지되고, 이모지 입력, 제목 입력 칸, 설명 입력, 컬러 입력의 수정 중이던 내용이 유지된다.

### TC-TAG-DETAIL-FEATURE-010: 수정에 성공하면 성공 피드백을 제공한다

- 근거: `feature > 내용 수정`
- Given: 태그 수정이 성공하도록 설정되어 있고 입력 내용이 저장된 내용과 다르게 수정되어 있다.
- When: 사용자가 수정을 실행한다.
- Then: 태그가 수정되었다는 성공 피드백이 제공된다.

### TC-TAG-DETAIL-FEATURE-011: 수정을 처리하는 동안 진행 상태를 표시한다

- 근거: `feature > 내용 수정`
- Given: 태그 수정 처리가 완료되지 않고 진행 중인 상태로 설정되어 있고, 입력 내용이 저장된 내용과 다르게 수정되어 있다.
- When: 사용자가 수정을 실행한 뒤 화면을 확인한다.
- Then: 수정 처리가 끝날 때까지 진행 상태가 표시된다.

### TC-TAG-DETAIL-FEATURE-013: 수정에 성공하면 화면 제목이 새로 저장된 이모지와 제목으로 갱신된다

- 근거: `feature > 내용 수정`
- Given: 첫진입해 이모지와 제목이 채워진 뒤 사용자가 이모지 입력과 제목 입력 칸을 공백이 아닌 다른 값으로 수정했고, 수정이 성공하도록 설정되어 있다.
- When: 사용자가 수정을 실행한다.
- Then: 화면 제목이 새로 저장된 이모지와 제목으로 갱신된다.

### TC-TAG-DETAIL-FEATURE-014: 수정 반영 동작은 입력 내용이 저장된 내용과 다를 때만 제공된다

- 근거: `feature > 내용 수정`
- Given: 첫진입해 이모지, 제목, 설명, 컬러가 저장된 내용으로 채워져 있다.
- When: 사용자가 이모지, 제목, 설명, 컬러 중 하나를 저장된 내용과 다르게 수정한다.
- Then: 입력 내용이 저장된 내용과 같은 동안에는 수정 반영 동작이 제공되지 않고, 이모지를 포함해 하나라도 달라지면 제공된다.

### TC-TAG-DETAIL-FEATURE-015: 완료 상태에 맞는 상태 변경 동작을 제공한다

- 근거: `feature > 완료와 다시 시작`
- Given: 조회한 태그의 저장된 완료 상태가 테스트 데이터의 상태다.
- When: 사용자가 TagDetail 화면에서 가능한 상태 변경을 확인한다.
- Then: 테스트 데이터의 동작이 제공되고 반대 상태의 동작은 제공되지 않는다.
- 테스트 데이터:

| 완료 상태 | 제공되는 동작 | 제공되지 않는 동작 |
| --- | --- | --- |
| 완료되지 않음 | 완료 | 다시 시작 |
| 완료됨 | 다시 시작 | 완료 |

### TC-TAG-DETAIL-FEATURE-016: 완료되지 않은 태그를 완료하면 다시 시작할 수 있다

- 근거: `feature > 완료와 다시 시작`
- Given: 완료되지 않은 태그의 TagDetail 화면에 첫진입해 내용이 채워져 있고, 사용자가 제목 입력 칸을 다른 값으로 수정했으며, 완료가 성공하도록 설정되어 있다.
- When: 사용자가 완료를 실행한다.
- Then: TagDetail 화면과 수정 중인 내용이 유지되고 태그가 완료 상태가 되며 다시 시작 동작이 제공된다.

### TC-TAG-DETAIL-FEATURE-017: 완료된 태그를 다시 시작하면 다시 완료할 수 있다

- 근거: `feature > 완료와 다시 시작`
- Given: 완료된 태그의 TagDetail 화면에 첫진입해 내용이 채워져 있고, 사용자가 제목 입력 칸을 다른 값으로 수정했으며, 다시 시작이 성공하도록 설정되어 있다.
- When: 사용자가 다시 시작을 실행한다.
- Then: TagDetail 화면과 수정 중인 내용이 유지되고 태그가 미완료 상태가 되며 완료 동작이 제공된다.

### TC-TAG-DETAIL-FEATURE-019: 태그를 삭제하면 상세 화면에서 빠져나간다

- 근거: `feature > 삭제`
- Given: 태그의 TagDetail 화면에 내용이 채워져 있고 삭제가 성공하도록 설정되어 있다.
- When: 사용자가 태그 삭제를 실행한다.
- Then: 뒤로가기와 같은 결과로 TagDetail 화면에서 빠져나가 진입하기 전 화면으로 돌아가고 삭제된 태그의 수정 중이던 내용은 유지하지 않는다.

### TC-TAG-DETAIL-FEATURE-021: 완료·다시 시작·삭제를 처리하는 동안 진행 상태를 표시한다

- 근거: `feature > 완료와 다시 시작`, `feature > 삭제`
- Given: 테스트 데이터의 동작 처리가 완료되지 않고 진행 중인 상태로 설정되어 있고, 태그가 조회되어 내용이 채워져 있다.
- When: 사용자가 화면을 확인한다.
- Then: 처리가 끝날 때까지 해당 동작의 진행 상태가 표시된다.
- 테스트 데이터:

| 처리 중인 동작 |
| --- |
| 완료 |
| 다시 시작 |
| 삭제 |

### TC-TAG-DETAIL-FEATURE-022: 태그 내용이 준비되지 않으면 조회 중 상태를 유지한다

- 근거: `feature > 조회 상태`
- Given: 선택한 태그의 조회 상태가 테스트 데이터의 상태로 유지되도록 설정되어 있다.
- When: 사용자가 TagDetail 화면에 진입한다.
- Then: 조회 중 상태가 유지되고 상세 내용 수정, 완료·다시 시작과 삭제를 실행할 수 없다.
- 테스트 데이터:

| 조회 상태 |
| --- |
| 조회가 아직 완료되지 않음 |
| 선택한 태그를 조회할 수 없음 |
| 태그 조회 실패 |

### TC-TAG-DETAIL-FEATURE-030: 저장된 연결이 연결 입력에 표시된다

- 근거: `feature > 태그 연결 입력`, `domain > 연결 입력에 표시하는 태그`
- Given: 상세 대상 태그를 출발 태그로 하는 연결이 저장되어 있고, 상세 대상 태그를 향해 오는 연결도 저장되어 있다.
- When: 사용자가 TagDetail 화면을 확인한다.
- Then: 상세 대상 태그가 출발 태그인 연결의 도착 태그만 연결 입력에 표시된다.

### TC-TAG-DETAIL-FEATURE-031: 태그를 연결하면 저장된 연결에 즉시 반영된다

- 근거: `feature > 태그 연결 입력`, `domain > 연결의 반영`
- Given: 상세 대상 태그에 연결이 없고 태그 선택 목록이 열려 있다.
- When: 사용자가 목록에서 태그 하나를 누른다.
- Then: 상세 대상 태그를 출발 태그로 하는 연결된 태그를 조회하면 그 태그가 조회된다.

### TC-TAG-DETAIL-FEATURE-032: 연결을 해제하면 저장된 연결에 즉시 반영된다

- 근거: `feature > 태그 연결 입력`, `domain > 연결의 반영`
- Given: 상세 대상 태그가 태그 두 개와 연결되어 있고 태그 선택 목록이 열려 있다.
- When: 사용자가 목록에서 연결된 태그 하나를 누른다.
- Then: 상세 대상 태그의 연결된 태그를 조회하면 누른 태그만 조회되지 않고 다른 태그는 그대로 조회된다.

### TC-TAG-DETAIL-FEATURE-033: 연결과 해제는 수정 반영 동작을 제공하지 않는다

- 근거: `feature > 태그 연결 입력`
- Given: 입력 내용이 저장된 내용과 같은 TagDetail 화면이 표시되어 있다.
- When: 사용자가 태그를 연결하거나 연결을 해제한다.
- Then: 수정 반영 동작이 제공되지 않고 입력 중이던 이모지, 제목, 설명과 컬러도 바뀌지 않는다.

### TC-TAG-DETAIL-FEATURE-034: 조회 중에는 연결 입력을 표시하지 않는다

- 근거: `feature > 조회 상태`
- Given: 상세 대상 태그를 조회할 수 없도록 제어되어 있다.
- When: 사용자가 TagDetail 화면을 확인한다.
- Then: 연결 입력이 표시되지 않는다.

### TC-TAG-DETAIL-FEATURE-035: 같은 태그의 연결이 다른 경로에서 바뀌면 연결 입력에 반영된다

- 근거: `feature > 외부 변경과 대상 전환`
- Given: TagDetail 화면이 표시되어 있다.
- When: 상세 대상 태그의 연결이 다른 경로에서 추가되거나 해제된다.
- Then: 연결 입력에 최신 연결이 표시된다.

### TC-TAG-DETAIL-FEATURE-036: 다른 태그를 선택하면 연결 입력도 새 태그의 연결로 바뀐다

- 근거: `feature > 외부 변경과 대상 전환`
- Given: 서로 다른 연결을 가진 태그 두 개가 저장되어 있고 그중 하나의 TagDetail 화면이 표시되어 있다.
- When: 사용자가 다른 태그를 선택한다.
- Then: 연결 입력에 새 태그의 연결만 표시된다.

### TC-TAG-DETAIL-FEATURE-037: 화면에 처음 진입하면 태그 디테일 탭이 선택된다

- 근거: `feature > 탭 전환`
- Given: 태그가 저장되어 있다.
- When: 사용자가 그 태그의 TagDetail 화면에 진입한다.
- Then: 태그 디테일 탭이 선택되어 있고 이모지·제목·설명·컬러 입력과 태그 연결 입력이 표시된다.

### TC-TAG-DETAIL-FEATURE-038: 탭을 선택하면 그 탭의 내용을 표시한다

### TC-TAG-DETAIL-DOMAIN-002: 수정을 처리하는 동안 전달된 수정 요청은 처리하지 않는다

- 근거: `domain > 요청 제한`
- Given: 앞선 수정이 아직 처리 중이고, 입력 내용이 저장된 내용과 다르게 수정되어 있다.
- When: 같은 화면에서 수정 요청이 한 번 더 전달된다.
- Then: 수정 요청이 한 번만 처리되어 같은 수정이 중복 실행되지 않는다.

### TC-TAG-DETAIL-DOMAIN-003: 같은 종류의 동작을 처리하는 동안 전달된 같은 종류의 요청만 처리하지 않는다

- 근거: `domain > 요청 제한`
- Given: 테스트 데이터의 앞선 요청이 아직 처리 중이다.
- When: 같은 화면에서 테스트 데이터의 뒤이은 요청이 전달된다.
- Then: 뒤이은 요청은 테스트 데이터의 기대 결과대로 처리되고, 앞선 요청의 처리가 끝나면 사용자는 다시 요청할 수 있다.
- 테스트 데이터:

| 앞선 요청 | 뒤이은 요청 | 기대 결과 |
| --- | --- | --- |
| 완료 | 완료 | 처리하지 않음 |
| 완료 | 다시 시작 | 처리하지 않음 |
| 삭제 | 삭제 | 처리하지 않음 |
| 완료 | 삭제 | 처리함 |
| 완료 | 수정 | 처리함 |
| 삭제 | 완료 | 처리함 |
| 수정 | 완료 | 처리함 |

## data

### TC-TAG-DETAIL-DATA-001: 공백이 아닌 제목으로 수정하면 이모지, 제목, 설명, 컬러와 수정 시각이 저장되고 나머지 속성은 유지된다

- 근거: `data > 태그 수정과 저장`, `domain > 수정되는 내용`
- Given: 로그인한 계정에 완료 여부, 삭제 여부, 생성 시각을 가진 태그가 있고, 수정한 이모지와 공백이 아닌 제목, 수정한 설명, 컬러로 수정을 실행할 수 있다.
- When: 사용자가 해당 내용으로 수정을 실행한다.
- Then: 그 태그의 이모지, 제목, 설명, 컬러가 수정한 내용으로 저장되고 수정 시각이 수정 시점으로 갱신되며, 완료 여부, 삭제 여부, 생성 시각, 계정·그룹 연결은 바뀌지 않는다.

### TC-TAG-DETAIL-DATA-002: 완료·다시 시작·삭제의 상태 변경이 저장되고 나머지 속성은 유지된다

- 근거: `data > 상태 변경의 저장`, `domain > 완료·다시 시작·삭제`
- Given: 로그인한 계정에 테스트 데이터의 사전 상태를 가진 태그가 있고, 그 태그의 TagDetail 화면이 표시되어 있다.
- When: 사용자가 테스트 데이터의 동작을 실행한다.
- Then: 그 태그가 테스트 데이터의 기대 저장 결과로 저장되고 수정 시각이 동작 시점으로 갱신되며, 태그와 계정·그룹 연결은 지워지지 않고 제목, 설명, 컬러, 생성 시각도 바뀌지 않는다.
- 테스트 데이터:

| 사전 상태 | 동작 | 기대 저장 결과 |
| --- | --- | --- |
| 완료되지 않음 | 완료 | 완료 여부가 완료 상태로 저장 |
| 완료됨 | 다시 시작 | 완료 여부가 미완료 상태로 저장 |
| 삭제되지 않음 | 삭제 | 삭제 여부가 삭제 상태로 저장 |

### TC-TAG-DETAIL-DATA-003: 상태 변경은 현재 계정과 연결된 태그에만 적용된다

- 근거: `domain > 완료·다시 시작·삭제`, `data > 상태 변경의 저장`
- Given: 현재 계정과 연결된 태그와 다른 계정에만 연결된 태그가 저장되어 있다.
- When: 사용자가 완료, 다시 시작 또는 삭제를 실행한다.
- Then: 현재 계정과 연결된 태그의 상태만 바뀌고 다른 계정의 태그는 바뀌지 않는다.

### TC-TAG-DETAIL-DATA-004: 표시 범위를 바꿔도 기기에 기록하지 않는다

- 근거: `data > 탭별 조회`
- Given: TagDetail 화면이 표시되어 있다.
- When: 사용자가 표시 범위를 `모든 하위까지`로 바꾼다.
- Then: 태그, 태그 연결과 그 밖의 저장 내용이 바뀌지 않고 서버로 보내는 요청도 발생하지 않는다.

### TC-TAG-DETAIL-DATA-005: 표시 범위를 바꾸면 세 목록을 새 기준으로 다시 조회한다

- 근거: `data > 탭별 조회`
- Given: 상세 대상 태그 A에서 B로 향하는 연결이 저장되어 있고, 태그 A와 태그 B에 각각 메모, 웹 항목, 장소가 연결되어 있다.
- When: 사용자가 표시 범위를 `이 태그만`에서 `직속 하위까지`로 바꿨다가 다시 `이 태그만`으로 되돌린다.
- Then: 넓힌 동안에는 세 목록에 태그 B의 항목이 함께 조회되고, 되돌린 뒤에는 다시 태그 A의 항목만 조회된다.

## 작성하지 않는 이유

상단 제목의 한 줄 배치와 폭을 넘는 제목의 무한 반복 가로 이동은 시각적 레이아웃과 애니메이션이므로 현재 단위 테스트 환경에서 외부 결과로 결정적으로 판정할 수 없다. 제목 폭을 제어하고 여러 시점의 화면 프레임을 비교할 수 있는 시각 회귀 테스트 환경이 갖춰지면 자동화한다.
