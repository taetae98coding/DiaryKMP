# 앱 이름 테스트 케이스

기준 스펙: [앱 이름 스펙](../spec/client/app-name.md)

## domain

### TC-APP-NAME-DOMAIN-001: Android와 iOS 앱은 환경과 빌드 조합에 맞는 이름으로 보인다

- 근거: `domain > 빌드 환경별 앱 이름`, `domain > 앱 이름이 보이는 곳`
- Given: 테스트 데이터의 환경과 빌드로 만든 Android 또는 iOS 앱이 설치되어 있다.
- When: 사용자가 런처나 홈 화면, 시스템 설정에서 앱 이름을 확인한다.
- Then: 테스트 데이터의 앱 이름이 표시된다.
- 테스트 데이터:

| 환경 | 빌드 | 앱 이름 |
| --- | --- | --- |
| 개발 | 내부 확인용 | `DiaryDev` |
| 개발 | 배포용 | `DiaryDev` |
| 운영 | 내부 확인용 | `DiaryRealDebug` |
| 운영 | 배포용 | `Diary` |

- 작성하지 않는 이유: 앱 이름은 환경과 빌드 조합마다 만든 설치 파일에 담겨 런처, 홈 화면, 시스템 설정에서만 관찰된다. 현재 자동화 환경은 앱의 동작을 확인할 뿐 환경별 설치 파일을 만들거나 설치된 앱의 이름을 읽지 못한다. 환경과 빌드 조합마다 설치 파일을 만들어 담긴 앱 이름을 읽어 비교하는 빌드 검증 단계가 갖춰지면 자동화한다.

### TC-APP-NAME-DOMAIN-002: 데스크톱 앱과 웹은 환경에 맞는 이름으로 보인다

- 근거: `domain > 빌드 환경별 앱 이름`, `domain > 앱 이름이 보이는 곳`
- Given: 테스트 데이터의 환경으로 만든 데스크톱 앱이나 웹이 실행되어 있다.
- When: 사용자가 데스크톱 앱의 창 제목과 설치 파일, 웹의 브라우저 탭 제목을 확인한다.
- Then: 테스트 데이터의 앱 이름이 표시된다.
- 테스트 데이터:

| 환경 | 앱 이름 |
| --- | --- |
| 개발 | `DiaryDev` |
| 운영 | `Diary` |

- 작성하지 않는 이유: 데스크톱 앱과 웹의 앱 이름은 환경마다 만든 설치 파일과 웹 페이지에 담겨 창 제목, 설치 파일, 브라우저 탭에서만 관찰된다. 현재 자동화 환경은 환경별 설치 파일이나 웹 페이지를 만들지 않고, 실제 창이나 브라우저를 띄우지 않는다. 환경마다 설치 파일과 웹 페이지를 만들어 담긴 앱 이름을 읽어 비교하는 빌드 검증 단계가 갖춰지면 자동화한다.

## 작성하지 않는 이유

- `domain > 앱 이름이 보이는 곳`의 앱 이름이 데이터 저장 위치를 정하지 않는다는 문장은 저장 위치를 [데스크톱 앱 데이터 저장 위치 스펙](../spec/client/jvm-database-storage.md)에 맡기는 경계이며 이 문서가 판정할 결과가 없다. 환경별 저장 위치는 [데스크톱 앱 데이터 저장 위치 테스트 케이스](./jvm-database-storage.md)가 다룬다.
