# SettingGemini 테스트 케이스

기준 스펙: [SettingGemini 화면 스펙](../spec/setting-gemini.md)

설정 화면 본문에서 `Gemini` 항목을 선택해 SettingGemini로 이동하는 케이스는 [SettingHome 테스트 케이스](./setting-home.md)에서 다룬다. 설정 목록과 함께 표시되는 상태의 시스템 뒤로가기 결과는 [Setting 목록·상세 배치 테스트 케이스](./setting-list-detail.md)에서, 모델 목록을 받아 오는 원격 조회 계약은 [Gemini 모델 목록 조회 테스트 케이스](./gemini-model-list.md)에서 다룬다.

## feature

### TC-SETTING-GEMINI-FEATURE-001: 저장된 설정을 입력된 상태로 시작한다

- 근거: `feature > 진입과 이동`
- Given: 인증 정보, 모델, 시스템 프롬프트가 각각 값이 있는 상태로 저장되어 있다.
- When: 사용자가 SettingGemini 화면에 진입한다.
- Then: 저장된 인증 정보, 모델, 시스템 프롬프트가 각각 입력된 상태로 표시된다.

### TC-SETTING-GEMINI-FEATURE-002: 저장된 설정이 없으면 비어 있는 상태로 시작한다

- 근거: `feature > 진입과 이동`, `domain > Gemini 설정`
- Given: Gemini 설정을 한 번도 저장하지 않았다.
- When: 사용자가 SettingGemini 화면에 진입한다.
- Then: 인증 정보와 시스템 프롬프트가 비어 있고 모델은 고르지 않은 상태로 표시되며, 시스템 프롬프트에 기본 문구가 채워지지 않는다.

### TC-SETTING-GEMINI-FEATURE-022: 설정을 확인하지 못하면 입력과 저장 기능을 제공하지 않는다

- 근거: `feature > 진입과 이동`, `data > 저장 시점과 유지`
- Given: 저장된 Gemini 설정을 아직 확인하지 못했거나 읽지 못한 상태다.
- When: 사용자가 SettingGemini 화면 본문을 확인한다.
- Then: 인증 정보, 모델, 시스템 프롬프트를 입력할 수 없고 저장도 실행할 수 없으며, 별도 로딩 또는 오류 상태도 제공되지 않는다.

### TC-SETTING-GEMINI-FEATURE-003: 화면에 진입하는 것만으로는 모델을 받아 오지 않는다

- 근거: `feature > 모델 선택`
- Given: 인증 정보가 값이 있는 상태로 저장되어 있다.
- When: 사용자가 SettingGemini 화면에 진입한다.
- Then: 모델 목록 조회가 외부 경계로 나가지 않고, 사용자는 모델을 고를 수 없다.

### TC-SETTING-GEMINI-FEATURE-004: 인증 정보가 비어 있으면 조회하지 않고 입력 필요를 알린다

- 근거: `feature > 모델 선택`
- Given: 인증 정보 입력이 비어 있고 시스템 프롬프트에 입력한 값이 있다.
- When: 사용자가 모델 조회를 실행한다.
- Then: 모델 목록 조회가 외부 경계로 나가지 않고 인증 정보 입력이 필요하다는 안내가 표시되며, 입력한 시스템 프롬프트는 그대로 유지된다.

### TC-SETTING-GEMINI-FEATURE-005: 저장된 인증 정보가 아니라 입력한 인증 정보로 조회한다

- 근거: `feature > 모델 선택`, `data > 모델 목록 조회`
- Given: 인증 정보가 저장되어 있고, 사용자가 인증 정보 입력을 저장된 값과 다른 값으로 바꿨다.
- When: 사용자가 모델 조회를 실행한다.
- Then: 외부 경계로 나가는 조회 요청에 사용자가 입력한 인증 정보가 포함되고 저장된 인증 정보는 포함되지 않는다.

### TC-SETTING-GEMINI-FEATURE-006: 조회하는 동안 진행 상태를 표시한다

- 근거: `feature > 모델 선택`
- Given: 인증 정보 입력에 값이 있고, 외부 응답이 아직 돌아오지 않도록 제어되어 있다.
- When: 사용자가 모델 조회를 실행한다.
- Then: 모델을 불러오는 중임을 알리는 진행 상태가 표시된다.

### TC-SETTING-GEMINI-FEATURE-007: 조회 중에는 같은 조회 요청을 처리하지 않는다

- 근거: `feature > 모델 선택`
- Given: 인증 정보 입력에 값이 있고, 외부 응답이 아직 돌아오지 않도록 제어된 상태에서 모델 조회가 진행 중이다.
- When: 사용자가 모델 조회를 다시 실행한다.
- Then: 모델 목록 조회가 외부 경계로 한 번만 나간다.

### TC-SETTING-GEMINI-FEATURE-008: 조회에 성공하면 받아 온 모델을 고를 수 있다

- 근거: `feature > 모델 선택`
- Given: 인증 정보 입력에 값이 있고, 조회 응답이 내용 생성에 쓸 수 있는 모델 여러 개를 담은 성공으로 제어되어 있다.
- When: 사용자가 모델 조회를 실행한다.
- Then: 받아 온 모델이 모두 고를 수 있는 상태로 표시된다.

### TC-SETTING-GEMINI-FEATURE-009: 고를 수 있는 모델이 없으면 안내를 표시한다

- 근거: `feature > 모델 선택`
- Given: 인증 정보 입력에 값이 있고, 조회 응답이 빈 목록을 담은 성공으로 제어되어 있다.
- When: 사용자가 모델 조회를 실행한다.
- Then: 고를 모델이 없다는 안내가 표시되고 실패 안내는 표시되지 않는다.

### TC-SETTING-GEMINI-FEATURE-010: 조회 실패의 원인을 구분해 알린다

- 근거: `feature > 모델 선택`
- Given: 인증 정보 입력에 값이 있고, 조회 응답이 테스트 데이터의 실패로 제어되어 있다.
- When: 사용자가 모델 조회를 실행한다.
- Then: 테스트 데이터의 안내가 표시되고 입력 중이던 값은 그대로 유지된다.
- 테스트 데이터:

| 조회 응답 | 표시되는 안내 |
| --- | --- |
| 인증 정보가 유효하지 않은 실패 | 인증 정보를 확인해야 한다는 안내 |
| 그 밖의 실패 | 조회에 실패했다는 안내 |

### TC-SETTING-GEMINI-FEATURE-011: 조회에 실패해도 받아 둔 목록과 고른 모델을 유지한다

- 근거: `feature > 모델 선택`
- Given: 사용자가 모델 조회에 성공해 목록을 받아 두고 그중 한 모델을 고른 상태이며, 다음 조회 응답이 실패로 제어되어 있다.
- When: 사용자가 모델 조회를 다시 실행한다.
- Then: 직전에 받아 둔 모델을 계속 고를 수 있고 고른 모델도 그대로 유지된다.

### TC-SETTING-GEMINI-FEATURE-012: 목록에 없는 모델을 알리되 선택은 유지한다

- 근거: `domain > 선택한 모델과 조회한 목록`
- Given: 저장된 모델이 있는 상태로 화면에 진입했고, 조회 응답이 그 모델을 포함하지 않는 모델 목록을 담은 성공으로 제어되어 있다.
- When: 사용자가 모델 조회를 실행한다.
- Then: 그 모델을 목록에서 찾을 수 없다는 안내가 표시되고, 현재 선택은 저장된 모델 그대로 유지된다.

### TC-SETTING-GEMINI-FEATURE-013: 목록을 받아 오기 전에도 저장된 모델을 현재 선택으로 표시한다

- 근거: `domain > 선택한 모델과 조회한 목록`
- Given: 모델이 값이 있는 상태로 저장되어 있다.
- When: 사용자가 모델 조회를 실행하지 않은 채 SettingGemini 화면 본문을 확인한다.
- Then: 저장된 모델이 현재 선택으로 표시되고, 목록에 없는 모델이라는 안내는 표시되지 않는다.

### TC-SETTING-GEMINI-FEATURE-014: 모델을 골라도 저장하기 전에는 저장된 설정이 바뀌지 않는다

- 근거: `feature > 설정 저장`, `domain > 편집 상태와 저장된 설정`
- Given: 모델이 값이 있는 상태로 저장되어 있고 사용자가 모델 목록을 받아 두었다.
- When: 사용자가 저장된 모델과 다른 모델을 고른다.
- Then: 고른 모델이 현재 선택으로 표시되고, 저장된 설정은 바뀌지 않는다.

### TC-SETTING-GEMINI-FEATURE-024: 편집 값이 저장된 설정과 모두 같으면 저장 동작을 제공하지 않는다

- 근거: `feature > 설정 저장`, `domain > 저장 가능 상태`
- Given: Gemini 설정이 테스트 데이터의 상태이고 사용자가 SettingGemini 화면에 진입했다.
- When: 사용자가 어떤 값도 바꾸지 않는다.
- Then: 저장 동작이 제공되지 않는다.
- 테스트 데이터:

| 저장된 설정 |
| --- |
| 세 값이 모두 값 있음 |
| 한 번도 저장하지 않음 |

### TC-SETTING-GEMINI-FEATURE-025: 한 값만 저장된 설정과 달라져도 저장 동작을 제공한다

- 근거: `feature > 설정 저장`, `domain > 저장 가능 상태`
- Given: Gemini 설정이 세 값 모두 값이 있는 상태로 저장되어 있고 사용자가 SettingGemini 화면에 진입했다.
- When: 사용자가 테스트 데이터의 값 하나만 바꾼다.
- Then: 저장 동작이 제공된다.
- 테스트 데이터:

| 바꾸는 값 |
| --- |
| 인증 정보를 다른 값으로 바꿈 |
| 모델을 다른 모델로 바꿈 |
| 시스템 프롬프트를 다른 값으로 바꿈 |
| 인증 정보 뒤에 공백만 덧붙임 |

### TC-SETTING-GEMINI-FEATURE-026: 바꾼 값을 저장된 값으로 되돌리면 저장 동작을 다시 제공하지 않는다

- 근거: `feature > 설정 저장`, `domain > 저장 가능 상태`
- Given: Gemini 설정이 세 값 모두 값이 있는 상태로 저장되어 있고, 사용자가 인증 정보를 다른 값으로 바꿔 저장 동작이 제공되고 있다.
- When: 사용자가 인증 정보를 저장된 값과 같은 값으로 되돌린다.
- Then: 저장 동작이 다시 제공되지 않는다.

### TC-SETTING-GEMINI-FEATURE-015: 저장하면 세 값이 함께 저장된다

- 근거: `feature > 설정 저장`
- Given: 사용자가 인증 정보, 모델, 시스템 프롬프트를 모두 저장된 값과 다르게 정했다.
- When: 사용자가 저장을 실행한다.
- Then: 세 값이 사용자가 정한 값으로 함께 저장된다.

### TC-SETTING-GEMINI-FEATURE-016: 저장하는 동안 진행 상태를 표시한다

- 근거: `feature > 설정 저장`
- Given: 사용자가 세 값 중 하나 이상을 저장된 값과 다르게 정했고, 저장이 아직 끝나지 않도록 제어되어 있다.
- When: 사용자가 저장을 실행한다.
- Then: 저장이 진행 중임을 알리는 상태가 표시된다.

### TC-SETTING-GEMINI-FEATURE-017: 저장 중에는 같은 저장 요청을 처리하지 않는다

- 근거: `feature > 설정 저장`
- Given: 사용자가 세 값 중 하나 이상을 저장된 값과 다르게 정했고, 저장이 아직 끝나지 않도록 제어된 상태에서 저장이 진행 중이다.
- When: 사용자가 저장을 다시 실행한다.
- Then: 저장이 한 번만 수행된다.

### TC-SETTING-GEMINI-FEATURE-029: 저장을 처리하는 동안에도 저장 동작의 제공 기준을 그대로 적용한다

- 근거: `domain > 저장 가능 상태`
- Given: Gemini 설정이 세 값 모두 값이 있는 상태로 저장되어 있고, 사용자가 인증 정보를 다른 값으로 바꿔 저장을 실행했으며 저장이 아직 끝나지 않도록 제어되어 있다.
- When: 사용자가 인증 정보를 저장된 값과 같은 값으로 되돌린다.
- Then: 진행 중임을 알리는 상태를 포함해 저장 동작이 제공되지 않는다.

### TC-SETTING-GEMINI-FEATURE-018: 저장에 성공하면 입력을 비우지 않고 성공을 알린다

- 근거: `feature > 설정 저장`
- Given: 사용자가 세 값을 모두 저장된 값과 다르게 입력했고 저장이 성공하도록 제어되어 있다.
- When: 사용자가 저장을 실행한다.
- Then: 저장되었다는 안내가 표시되고 화면이 유지되며, 입력한 세 값이 비워지지 않고 그대로 표시된다.

### TC-SETTING-GEMINI-FEATURE-019: 저장에 실패하면 입력을 유지하고 실패를 알린다

- 근거: `feature > 설정 저장`
- Given: 사용자가 세 값을 모두 저장된 값과 다르게 입력했고 저장이 실패하도록 제어되어 있다.
- When: 사용자가 저장을 실행한다.
- Then: 저장에 실패했다는 안내가 표시되고 입력한 세 값이 그대로 유지되어 다시 저장할 수 있다.

### TC-SETTING-GEMINI-FEATURE-027: 저장에 성공하면 저장 동작을 더 제공하지 않는다

- 근거: `feature > 설정 저장`, `domain > 저장 가능 상태`
- Given: 사용자가 세 값을 모두 저장된 값과 다르게 입력했고 저장이 성공하도록 제어되어 있다.
- When: 사용자가 저장을 실행한다.
- Then: 입력한 세 값이 그대로 표시된 채 저장 동작이 제공되지 않는다.

### TC-SETTING-GEMINI-FEATURE-028: 저장에 실패하면 저장 동작을 계속 제공한다

- 근거: `feature > 설정 저장`, `domain > 저장 가능 상태`
- Given: 사용자가 세 값을 모두 저장된 값과 다르게 입력했고 저장이 실패하도록 제어되어 있다.
- When: 사용자가 저장을 실행한다.
- Then: 저장 동작이 그대로 제공되어 사용자가 다시 실행할 수 있다.

### TC-SETTING-GEMINI-FEATURE-020: 단독 화면에서 뒤로가면 설정 목록으로 돌아간다

- 근거: `feature > 뒤로가기`
- Given: SettingGemini 화면이 단독으로 표시되어 있다.
- When: 사용자가 뒤로간다.
- Then: 설정 목록으로 돌아가고 공통 내비게이션은 계속 제공되지 않는다.

### TC-SETTING-GEMINI-FEATURE-023: 화면이 재생성되어도 입력 중이던 값을 유지한다

- 근거: `feature > 입력 상태 유지`, `domain > 유지와 초기화 기준`
- Given: 사용자가 인증 정보, 모델, 시스템 프롬프트를 저장하지 않은 채 입력해 둔 상태다.
- When: 화면이 재생성된다.
- Then: 입력해 둔 세 값이 그대로 표시된다.

### TC-SETTING-GEMINI-FEATURE-021: 저장하지 않고 떠날 때 확인을 요구하지 않는다

- 근거: `feature > 뒤로가기`
- Given: SettingGemini 화면이 단독으로 표시되어 있고 사용자가 저장하지 않은 입력 내용을 가지고 있다.
- When: 사용자가 뒤로간다.
- Then: 저장하지 않은 내용이 있다는 확인을 요구하지 않고 곧바로 설정 목록으로 돌아간다.

## domain

### TC-SETTING-GEMINI-DOMAIN-001: 세 값이 비어 있어도 저장할 수 있다

- 근거: `domain > 저장 성립 조건`
- Given: Gemini 설정이 테스트 데이터와 다른 세 값으로 저장되어 있고, 사용자가 테스트 데이터의 조합으로 값을 정했다.
- When: 사용자가 저장을 실행한다.
- Then: 저장이 수행되고 입력이 필요하다는 안내는 표시되지 않는다.
- 테스트 데이터:

| 인증 정보 | 모델 | 시스템 프롬프트 |
| --- | --- | --- |
| 비어 있음 | 고르지 않음 | 비어 있음 |
| 값 있음 | 고르지 않음 | 비어 있음 |
| 비어 있음 | 고름 | 비어 있음 |
| 비어 있음 | 고르지 않음 | 값 있음 |

### TC-SETTING-GEMINI-DOMAIN-002: 저장할 때 인증 정보와 모델의 유효성을 확인하지 않는다

- 근거: `domain > 저장 성립 조건`
- Given: 사용자가 유효하지 않은 인증 정보를 입력하고 모델을 고른 상태다.
- When: 사용자가 저장을 실행한다.
- Then: 저장을 위해 외부 경계로 어떤 요청도 나가지 않고 저장이 그대로 수행된다.

### TC-SETTING-GEMINI-DOMAIN-003: 저장된 설정이 바뀌어도 편집 중인 값을 덮어쓰지 않는다

- 근거: `domain > 편집 상태와 저장된 설정`
- Given: 사용자가 세 값을 저장된 값과 다르게 입력한 상태다.
- When: 저장된 설정이 다른 값으로 바뀐다.
- Then: 사용자가 입력한 세 값이 그대로 유지된다.

## data

### TC-SETTING-GEMINI-DATA-001: 저장된 설정이 없으면 비어 있는 설정을 제공한다

- 근거: `data > 저장 시점과 유지`
- Given: Gemini 설정이 한 번도 저장되지 않았다.
- When: Gemini 설정을 조회한다.
- Then: 인증 정보와 시스템 프롬프트가 비어 있고 모델이 정해지지 않은 설정을 제공한다.

### TC-SETTING-GEMINI-DATA-002: 저장한 설정을 이후 조회에서 제공한다

- 근거: `data > 저장 시점과 유지`
- Given: Gemini 설정이 한 번도 저장되지 않았다.
- When: 테스트 데이터의 값으로 Gemini 설정을 저장한 뒤 Gemini 설정을 조회한다.
- Then: 저장한 세 값을 그대로 제공한다.
- 테스트 데이터:

| 인증 정보 | 모델 | 시스템 프롬프트 |
| --- | --- | --- |
| 값 있음 | 값 있음 | 값 있음 |
| 값 있음 | 값 있음 | 여러 줄 값 있음 |
| 비어 있음 | 비어 있음 | 비어 있음 |

### TC-SETTING-GEMINI-DATA-003: 다시 저장하면 마지막에 저장한 설정을 제공한다

- 근거: `data > 저장 시점과 유지`
- Given: Gemini 설정이 값이 있는 세 값으로 저장되어 있다.
- When: 다른 세 값으로 저장한 뒤 또 다른 세 값으로 저장하고 Gemini 설정을 조회한다.
- Then: 마지막에 저장한 세 값을 제공한다.

### TC-SETTING-GEMINI-DATA-004: 값 하나만 바꿔 저장해도 세 값이 함께 기록된다

- 근거: `data > 저장 시점과 유지`, `feature > 설정 저장`
- Given: Gemini 설정이 값이 있는 세 값으로 저장되어 있다.
- When: 시스템 프롬프트만 다른 값으로 바꾼 세 값을 저장하고 Gemini 설정을 조회한다.
- Then: 시스템 프롬프트는 바뀐 값으로, 인증 정보와 모델은 함께 저장한 값으로 제공된다.

### TC-SETTING-GEMINI-DATA-005: 조회 중에 설정이 바뀌면 이어서 새 값을 제공한다

- 근거: `data > 저장 시점과 유지`
- Given: Gemini 설정이 저장된 상태에서 설정을 계속 조회하고 있다.
- When: 다른 세 값으로 Gemini 설정을 저장한다.
- Then: 기존 조회 결과에 이어 새로 저장한 세 값을 제공한다.

### TC-SETTING-GEMINI-DATA-006: 저장된 값을 읽을 수 없으면 확인하지 못한 상태로 제공한다

- 근거: `data > 저장 시점과 유지`
- Given: Gemini 설정 저장값을 읽을 수 없도록 제어되어 있다.
- When: Gemini 설정을 조회한다.
- Then: 비어 있는 설정을 제공하지 않고 설정을 아직 확인하지 못한 상태를 제공한다.

### TC-SETTING-GEMINI-DATA-007: 모델 조회에 성공해도 인증 정보가 저장되지 않는다

- 근거: `data > 모델 목록 조회`
- Given: Gemini 설정이 한 번도 저장되지 않았고 사용자가 인증 정보를 입력했다.
- When: 사용자가 모델 조회를 실행해 성공한다.
- Then: 저장된 Gemini 설정의 인증 정보는 여전히 비어 있다.

## 작성하지 않는 이유

- `feature > 뒤로가기`의 저장하지 않은 편집 내용을 버리는 규칙과 `feature > 입력 상태 유지`, `domain > 유지와 초기화 기준`의 백그라운드 복귀 후 유지, 화면 이탈·앱 재실행 후 초기화는 실제 앱의 실행 경계와 전환 이력을 함께 제어하고 관찰해야 한다. 현재 테스트 환경에서는 결정적으로 자동화할 수 없으며, 해당 실행 경계를 제어하는 통합 테스트 환경이 갖춰지면 자동화한다. 화면 재생성 후 유지는 TC-SETTING-GEMINI-FEATURE-023에서 다룬다.
- `feature > 입력 상태 유지`의 받아 둔 모델 목록 유지는 목록을 기기에 저장하지 않고 화면의 진행 상태로만 두므로, 화면 재생성 경계에서 관찰할 저장 상태가 없다.
- 앱을 종료하고 다시 시작한 뒤에도 저장된 설정이 유지되는 규칙은 실제 저장 영역의 파일이나 브라우저 저장 영역을 다시 열어야 관찰할 수 있으므로 유닛 테스트 케이스로 작성하지 않는다.
- `data > 기기별 보관`의 로그인, 로그아웃, 계정 전환 후에도 설정이 유지되고 동기화 대상이 아니라는 규칙은 계정 흐름과 동기화 전체를 거쳐야 관찰할 수 있으므로 유닛 테스트 케이스로 작성하지 않는다.
- `data > 기기별 보관`이 참조하는 환경별 저장 영역은 [SettingMap 테스트 케이스](./setting-map.md)가 같은 저장 영역을 대상으로 다루므로 여기에서 다시 다루지 않는다.
