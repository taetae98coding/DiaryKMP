# 음력 자료 동기화 테스트 케이스

기준 스펙: [음력 자료 동기화 스펙](../spec/client/lunar-fetch.md)

오류 보고가 남는 방식 자체의 케이스는 [기능 실패 로깅 테스트 케이스](./usecase-failure-logging.md)에서 다룬다. 이 문서에서는 음력 자료 동기화가 오류 보고 대상인지를 다룬다. 음력 자료로 음력 생일이 놓이는 날짜는 [캘린더 연락처 생일 표시 테스트 케이스](./calendar-contact-birthday.md)에서 다룬다.

## domain

### TC-LUNAR-FETCH-DOMAIN-001: 동기화가 실패하면 실패 원인을 담은 오류 보고가 남는다

- 근거: `domain > 동기화 실패 보고`
- Given: 오류 보고 기록 수단이 등록되어 있고, 특정 연도의 음력 자료 동기화가 특정 원인으로 실패하도록 준비되어 있다.
- When: 해당 연도의 음력 자료 동기화를 요청한다.
- Then: 그 원인을 담은 오류 보고가 한 번 남고, 보고 메시지로 음력 자료 동기화 실패임을 구분할 수 있다.

### TC-LUNAR-FETCH-DOMAIN-002: 동기화가 성공하면 오류 보고가 남지 않는다

- 근거: `domain > 동기화 실패 보고`
- Given: 오류 보고 기록 수단이 등록되어 있고, 특정 연도의 음력 자료 동기화가 성공하도록 준비되어 있다.
- When: 해당 연도의 음력 자료 동기화를 요청한다.
- Then: 오류 보고가 남지 않는다.

### TC-LUNAR-FETCH-DOMAIN-003: 받아오지 못한 결과와 제공하지 않는 결과를 구분해 알린다

- 근거: `domain > 자료를 제공하지 않는 연도`, `domain > 연도별 동기화`
- Given: 특정 연도의 원격 조회 결과가 테스트 데이터의 상태로 준비되어 있다.
- When: 해당 연도의 음력 자료 동기화를 요청한다.
- Then: 동기화 결과로 자료를 제공하지 않는 연도인지 받아오지 못한 실패인지 구분할 수 있고, 자료를 제공하지 않는 연도는 오류 보고 대상이 아니다.
- 테스트 데이터:

  | 원격 조회 결과 | 동기화 결과 |
  | --- | --- |
  | 원격 조회 실패 | 받아오지 못한 실패 |
  | 해당 연도 자료 없음 | 빈 음력 날짜로 성공 |
  | 빈 음력 날짜 목록 | 빈 음력 날짜로 성공 |

### TC-LUNAR-FETCH-DOMAIN-004: 동기화가 성공하면 그 연도의 음력 날짜를 결과로 알린다

- 근거: `domain > 연도별 동기화`, `data > 원격 자료 저장`
- Given: 특정 연도의 원격 조회가 음력 날짜가 있는 목록으로 성공하도록 준비되어 있다.
- When: 해당 연도의 음력 자료 동기화를 요청한다.
- Then: 동기화 결과에 원격에서 받은 음력 날짜가 그대로 담겨 성공으로 끝난다.

## data

### TC-LUNAR-FETCH-DATA-001: 원격 음력 자료로 요청한 연도의 저장된 음력 자료를 교체한다

- 근거: `data > 원격 자료 저장`
- Given: 서로 다른 두 연도의 음력 날짜가 기기에 저장되어 있고, 요청할 연도의 원격 음력 자료가 준비되어 있다.
- When: 해당 연도의 음력 자료 동기화를 요청한다.
- Then: 요청한 연도의 저장된 음력 자료는 원격 음력 날짜 전체로 교체되고, 다른 연도의 저장된 음력 자료는 유지된다.

### TC-LUNAR-FETCH-DATA-002: 원격이 자료를 제공하지 않으면 요청한 연도의 저장된 음력 자료를 지운다

- 근거: `data > 원격 자료 저장`, `domain > 자료를 제공하지 않는 연도`
- Given: 특정 연도의 음력 날짜가 기기에 저장되어 있고, 해당 연도의 원격 조회 결과가 테스트 데이터의 상태다.
- When: 해당 연도의 음력 자료 동기화를 요청한다.
- Then: 해당 연도의 저장된 음력 자료는 비어 있고, 동기화는 빈 음력 날짜를 결과로 성공한다.
- 테스트 데이터:

  | 원격 조회 결과 |
  | --- |
  | 해당 연도 자료 없음 |
  | 빈 음력 날짜 목록 |

### TC-LUNAR-FETCH-DATA-003: 원격 조회가 실패하면 저장된 음력 자료를 유지한다

- 근거: `data > 실패 처리`
- Given: 특정 연도의 음력 날짜가 기기에 저장되어 있고, 해당 연도의 원격 조회가 실패하도록 준비되어 있다.
- When: 해당 연도의 음력 자료 동기화를 요청한다.
- Then: 동기화가 실패하고 해당 연도의 기존에 저장된 음력 자료는 유지된다.

### TC-LUNAR-FETCH-DATA-004: 기기 저장이 실패하면 동기화가 실패로 끝난다

- 근거: `data > 실패 처리`
- Given: 특정 연도의 음력 자료 원격 조회는 성공하지만 기기 저장이 실패하도록 준비되어 있다.
- When: 해당 연도의 음력 자료 동기화를 요청한다.
- Then: 동기화가 실패로 끝난다.

### TC-LUNAR-FETCH-DATA-005: 이미 동기화에 성공한 연도는 다시 원격 조회하지 않는다

- 근거: `data > 성공한 연도 재조회 생략`
- Given: 특정 연도의 음력 자료 동기화가 이미 성공한 상태다.
- When: 같은 연도의 음력 자료 동기화를 다시 요청한다.
- Then: 동기화가 성공하고, 해당 연도의 원격 조회는 처음 한 번만 수행되며 저장된 음력 자료도 다시 교체되지 않는다. 결과로는 기기에 저장된 그 연도의 음력 날짜가 나온다.

### TC-LUNAR-FETCH-DATA-006: 동기화에 실패한 연도는 다시 요청하면 다시 원격 조회한다

- 근거: `data > 실패 처리`
- Given: 특정 연도의 첫 동기화 요청이 실패한 상태이고, 같은 연도의 원격 조회가 이후에는 성공하도록 준비되어 있다.
- When: 같은 연도의 음력 자료 동기화를 다시 요청한다.
- Then: 해당 연도의 원격 조회가 다시 수행되고 동기화가 성공하며, 받은 음력 날짜 전체로 해당 연도의 저장된 음력 자료가 교체된다.
- 테스트 데이터:

  | 첫 요청의 실패 지점 |
  | --- |
  | 원격 조회 실패 |
  | 기기 저장 실패 |

### TC-LUNAR-FETCH-DATA-007: 한 연도의 동기화 이력은 다른 연도의 동기화를 막지 않는다

- 근거: `domain > 동기화 이력`
- Given: 특정 연도의 음력 자료 동기화가 이미 성공한 상태다.
- When: 다른 연도의 음력 자료 동기화를 요청한다.
- Then: 요청한 다른 연도의 원격 조회가 수행되고 해당 연도의 저장된 음력 자료가 교체된다.

### TC-LUNAR-FETCH-DATA-008: 자료를 제공하지 않은 연도도 다시 요청하면 원격 조회를 생략한다

- 근거: `domain > 동기화 이력`, `data > 성공한 연도 재조회 생략`
- Given: 특정 연도의 첫 동기화 요청에서 원격이 자료를 제공하지 않아 그 연도의 저장된 음력 자료가 비어 있다.
- When: 같은 연도의 음력 자료 동기화를 다시 요청한다.
- Then: 해당 연도의 원격 조회는 처음 한 번만 수행되고, 동기화는 빈 음력 날짜를 결과로 성공한다.

### TC-LUNAR-FETCH-DATA-009: 요청한 연도의 한국 음력 자료를 원격에 요청한다

- 근거: `data > 원격 제공처`, `data > 원격 자료 저장`
- Given: 동기화 이력이 비어 있다.
- When: 테스트 데이터의 연도로 음력 자료 동기화를 요청한다.
- Then: 원격에 그 연도의 한국 음력 자료를 요청한다.
- 테스트 데이터:

  | 연도 |
  | --- |
  | 2026 |
  | 2027 |

### TC-LUNAR-FETCH-DATA-010: 원격 응답을 양력 날짜별 음력 날짜로 읽는다

- 근거: `domain > 음력 날짜`, `data > 원격 제공처`
- Given: 원격이 2026년 음력 자료를 제공하도록 준비되어 있다.
- When: 2026년의 음력 자료를 원격에서 조회한다.
- Then: 양력 2026년 1월 1일은 음력 2025년 11월 13일 평달로, 양력 2026년 2월 17일은 음력 2026년 1월 1일 평달로 읽힌다.

### TC-LUNAR-FETCH-DATA-011: 기간에 드는 양력 날짜의 음력 날짜만 양력 날짜 순으로 제공한다

- 근거: `data > 기간별 음력 날짜 조회`
- Given: 2026년과 2027년의 음력 날짜가 기기에 저장되어 있다.
- When: 2026년 12월 30일부터 2027년 1월 2일까지를 기간으로 음력 날짜를 조회한다.
- Then: 두 연도에 걸친 나흘의 음력 날짜만 양력 날짜 순으로 제공되고, 기간 밖의 날짜는 제공되지 않는다.

### TC-LUNAR-FETCH-DATA-012: 아직 저장되지 않은 연도의 날짜는 결과에 들지 않는다

- 근거: `data > 기간별 음력 날짜 조회`
- Given: 2026년의 음력 날짜만 기기에 저장되어 있다.
- When: 2026년 12월 30일부터 2027년 1월 2일까지를 기간으로 음력 날짜를 조회한다.
- Then: 2026년의 이틀만 제공되고 2027년의 날짜는 제공되지 않는다.

### TC-LUNAR-FETCH-DATA-013: 조회 중인 기간의 저장된 음력 자료가 바뀌면 새 목록을 제공한다

- 근거: `data > 기간별 음력 날짜 조회`
- Given: 기기에 저장된 음력 날짜가 없는 상태로 특정 기간의 음력 날짜를 계속 조회하고 있다.
- When: 그 기간이 속한 연도의 저장된 음력 자료가 원격 음력 자료로 교체된다.
- Then: 빈 목록에 이어 그 기간의 음력 날짜가 담긴 목록이 제공된다.

### TC-LUNAR-FETCH-DATA-014: 앱을 다시 실행하면 동기화 이력이 비워진다

- 근거: `domain > 동기화 이력`
- Given: 특정 연도의 음력 자료 동기화가 성공한 뒤 앱이 종료되었다.
- When: 앱을 다시 실행하고 같은 연도의 음력 자료 동기화를 요청한다.
- Then: 해당 연도의 원격 조회가 다시 수행된다.

### TC-LUNAR-FETCH-DATA-015: 교체하는 동안 일부만 바뀐 음력 자료가 보이지 않는다

- 근거: `data > 원격 자료 저장`, `data > 기간별 음력 날짜 조회`
- Given: 한 연도에 음력 날짜 여러 개가 저장되어 있고, 그 연도를 담은 기간의 음력 날짜를 계속 조회하고 있다.
- When: 그 연도의 음력 자료를 일부 날짜가 다른 새 목록으로 교체한다.
- Then: 기존 조회 결과에 이어 교체된 목록만 제공되고, 기존 날짜가 일부만 지워진 목록이나 빈 목록은 제공되지 않는다.

## 작성하지 않는 이유

- 교체가 끝까지 완료되지 못했을 때 그 연도의 기존 음력 자료가 그대로 남는 결과는, 지우기를 마친 뒤 새로 저장하는 도중에 실제 저장소의 쓰기를 실패시켜야 확인할 수 있어 작성하지 않는다. 저장 도중의 쓰기 실패를 주입할 수 있는 저장소 테스트 환경이 갖춰지면 자동화한다. 저장 실패가 동기화 실패로 끝나고 다시 요청하면 원격 조회하는 결과는 TC-LUNAR-FETCH-DATA-004, TC-LUNAR-FETCH-DATA-006으로 확인한다.
- 음력 자료가 사용자 계정과 무관해 로그인, 로그아웃, 계정 전환에도 그대로 남는 결과는, 음력 자료의 저장과 조회에 계정 구분이 없어 이 문서의 범위에서는 계정 전환을 일으킬 수 없으므로 작성하지 않는다. 로그인 상태 전환과 기기 저장을 함께 실행하는 통합 테스트 환경이 갖춰지면 자동화한다.
- Android, iOS, 데스크톱 앱에서 저장한 음력 자료가 앱을 다시 실행해도 남아 있고 웹에서는 페이지를 새로 열면 비워지는 결과는, 앱 프로세스를 다시 시작하거나 웹 페이지를 새로 열어 플랫폼별 실제 저장소를 다시 열어야 확인할 수 있어 작성하지 않는다. 플랫폼별 저장소를 닫았다가 다시 여는 실행 경계를 제어할 수 있는 테스트 환경이 갖춰지면 자동화한다.
