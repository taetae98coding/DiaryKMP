# 음력 자료 동기화 테스트 케이스

기준 스펙: [음력 자료 동기화 스펙](../spec/client/lunar-fetch.md)

오류 보고가 남는 방식 자체의 케이스는 [기능 실패 로깅 테스트 케이스](./usecase-failure-logging.md)에서 다룬다. 이 문서에서는 음력 자료 동기화가 오류 보고 대상인지를 다룬다. 음력 자료로 음력 생일이 놓이는 날짜는 [캘린더 연락처 생일 표시 테스트 케이스](./calendar-contact-birthday.md)에서 다룬다.

## domain

### TC-c41ea30b-6edc-478b-b8b3-f85b335e61fe: 동기화가 실패하면 실패 원인을 담은 오류 보고가 남는다

- 근거: `domain > 동기화 실패 보고`
- Given: 오류 보고 기록 수단이 등록되어 있고, 특정 연도의 음력 자료 동기화가 특정 원인으로 실패하도록 준비되어 있다.
- When: 해당 연도의 음력 자료 동기화를 요청한다.
- Then: 그 원인을 담은 오류 보고가 한 번 남고, 보고 메시지로 음력 자료 동기화 실패임을 구분할 수 있다.

### TC-2fbda8e9-2020-4454-a510-e4e54d2711c1: 동기화가 성공하면 오류 보고가 남지 않는다

- 근거: `domain > 동기화 실패 보고`
- Given: 오류 보고 기록 수단이 등록되어 있고, 특정 연도의 음력 자료 동기화가 성공하도록 준비되어 있다.
- When: 해당 연도의 음력 자료 동기화를 요청한다.
- Then: 오류 보고가 남지 않는다.

### TC-16f767f7-bf9a-4111-ba16-fb3e808cd5b5: 받아오지 못한 결과와 제공하지 않는 결과를 구분해 알린다

- 근거: `domain > 자료를 제공하지 않는 연도`, `domain > 연도별 동기화`
- Given: 특정 연도의 원격 조회 결과가 테스트 데이터의 상태로 준비되어 있다.
- When: 해당 연도의 음력 자료 동기화를 요청한다.
- Then: 동기화 결과로 자료를 제공하지 않는 연도인지 받아오지 못한 실패인지 구분할 수 있고, 자료를 제공하지 않는 연도는 오류 보고 대상이 아니다.
- 테스트 데이터:

  | 원격 조회 결과 | 동기화 결과 |
  | --- | --- |
  | 원격 조회 실패 | 받아오지 못한 실패 |
  | 해당 연도 자료 없음 | 빈 음력 날짜로 성공 |
  | 빈 음력 날짜 목록 | 빈 음력 날짜로 성공 |

### TC-e6f699a2-bd9c-4a3a-9d54-dccbcb829194: 동기화가 성공하면 그 연도의 음력 날짜를 결과로 알린다

- 근거: `domain > 연도별 동기화`, `data > 원격 자료 저장`
- Given: 특정 연도의 원격 조회가 음력 날짜가 있는 목록으로 성공하도록 준비되어 있다.
- When: 해당 연도의 음력 자료 동기화를 요청한다.
- Then: 동기화 결과에 원격에서 받은 음력 날짜가 그대로 담겨 성공으로 끝난다.

## data

### TC-3e9afe01-23d6-4f46-8445-bf9a9a75408e: 원격 음력 자료로 요청한 연도의 저장된 음력 자료를 교체한다

- 근거: `data > 원격 자료 저장`
- Given: 서로 다른 두 연도의 음력 날짜가 기기에 저장되어 있고, 요청할 연도의 원격 음력 자료가 준비되어 있다.
- When: 해당 연도의 음력 자료 동기화를 요청한다.
- Then: 요청한 연도의 저장된 음력 자료는 원격 음력 날짜 전체로 교체되고, 다른 연도의 저장된 음력 자료는 유지된다.

### TC-77a8f0ae-7aa7-4553-a40a-d70cca1e0f3d: 원격이 자료를 제공하지 않으면 요청한 연도의 저장된 음력 자료를 지운다

- 근거: `data > 원격 자료 저장`, `domain > 자료를 제공하지 않는 연도`
- Given: 특정 연도의 음력 날짜가 기기에 저장되어 있고, 해당 연도의 원격 조회 결과가 테스트 데이터의 상태다.
- When: 해당 연도의 음력 자료 동기화를 요청한다.
- Then: 해당 연도의 저장된 음력 자료는 비어 있고, 동기화는 빈 음력 날짜를 결과로 성공한다.
- 테스트 데이터:

  | 원격 조회 결과 |
  | --- |
  | 해당 연도 자료 없음 |
  | 빈 음력 날짜 목록 |

### TC-bb5e708d-6bdc-4f75-8de8-e595ef74089c: 원격 조회가 실패하면 저장된 음력 자료를 유지한다

- 근거: `data > 실패 처리`
- Given: 특정 연도의 음력 날짜가 기기에 저장되어 있고, 해당 연도의 원격 조회가 실패하도록 준비되어 있다.
- When: 해당 연도의 음력 자료 동기화를 요청한다.
- Then: 동기화가 실패하고 해당 연도의 기존에 저장된 음력 자료는 유지된다.

### TC-b51289c8-284c-4230-9b59-888fffa5251e: 기기 저장이 실패하면 동기화가 실패로 끝난다

- 근거: `data > 실패 처리`
- Given: 특정 연도의 음력 자료 원격 조회는 성공하지만 기기 저장이 실패하도록 준비되어 있다.
- When: 해당 연도의 음력 자료 동기화를 요청한다.
- Then: 동기화가 실패로 끝난다.

### TC-405372aa-8b92-4b88-8a3e-d17620142a52: 이미 동기화에 성공한 연도는 다시 원격 조회하지 않는다

- 근거: `data > 성공한 연도 재조회 생략`
- Given: 특정 연도의 음력 자료 동기화가 이미 성공한 상태다.
- When: 같은 연도의 음력 자료 동기화를 다시 요청한다.
- Then: 동기화가 성공하고, 해당 연도의 원격 조회는 처음 한 번만 수행되며 저장된 음력 자료도 다시 교체되지 않는다. 결과로는 기기에 저장된 그 연도의 음력 날짜가 나온다.

### TC-5adc31f5-980a-44e7-a704-261fa601dc5c: 동기화에 실패한 연도는 다시 요청하면 다시 원격 조회한다

- Then: 해당 연도의 원격 조회가 다시 수행되고 동기화가 성공하며, 받은 음력 날짜 전체로 해당 연도의 저장된 음력 자료가 교체된다.
- 테스트 데이터:

  | 첫 요청의 실패 지점 |
  | --- |
  | 원격 조회 실패 |
  | 기기 저장 실패 |

### TC-0cc93d30-6dbd-4063-85a8-51b277f5629e: 한 연도의 동기화 이력은 다른 연도의 동기화를 막지 않는다

### TC-ef5c929c-1109-4b24-bc30-910e078d33eb: 앱 업데이트로 저장 형식이 바뀌면 저장된 음력 자료가 비워진다

- 근거: `data > 기기 보관`
- Given: 이전 버전의 앱이 저장해 둔 음력 자료가 기기에 있다.
- When: 저장 형식이 바뀐 버전으로 앱을 업데이트한 뒤 저장해 둔 연도가 드는 기간의 음력 날짜를 조회한다.
- Then: 빈 목록이 제공된다.
- 작성하지 않는 이유: 저장 형식이 아직 한 가지뿐이라 바뀌기 전 형식의 저장소를 만들어 열어 볼 수 없다. 저장 형식이 처음 바뀌어 이전 형식의 저장소를 테스트에서 만들 수 있게 되면, 이전 형식으로 자료를 저장한 뒤 새 형식으로 열어 비워지는지 확인하는 테스트로 자동화한다.

## 작성하지 않는 이유

- 교체가 끝까지 완료되지 못했을 때 그 연도의 기존 음력 자료가 그대로 남는 결과는, 지우기를 마친 뒤 새로 저장하는 도중에 실제 저장소의 쓰기를 실패시켜야 확인할 수 있어 작성하지 않는다. 저장 도중의 쓰기 실패를 주입할 수 있는 저장소 테스트 환경이 갖춰지면 자동화한다. 저장 실패가 동기화 실패로 끝나고 다시 요청하면 원격 조회하는 결과는 TC-b51289c8-284c-4230-9b59-888fffa5251e, TC-5adc31f5-980a-44e7-a704-261fa601dc5c으로 확인한다.
- 음력 자료가 사용자 계정과 무관해 로그인, 로그아웃, 계정 전환에도 그대로 남는 결과는, 음력 자료의 저장과 조회에 계정 구분이 없어 이 문서의 범위에서는 계정 전환을 일으킬 수 없으므로 작성하지 않는다. 로그인 상태 전환과 기기 저장을 함께 실행하는 통합 테스트 환경이 갖춰지면 자동화한다.
- Android, iOS, 데스크톱 앱에서 저장한 음력 자료가 앱을 다시 실행해도 남아 있고 웹에서는 페이지를 새로 열면 비워지는 결과는, 앱 프로세스를 다시 시작하거나 웹 페이지를 새로 열어 플랫폼별 실제 저장소를 다시 열어야 확인할 수 있어 작성하지 않는다. 플랫폼별 저장소를 닫았다가 다시 여는 실행 경계를 제어할 수 있는 테스트 환경이 갖춰지면 자동화한다.
