# 메모 연락처 입력 컴포넌트 테스트 케이스

기준 스펙: [메모 연락처 입력 컴포넌트 스펙](../spec/client/memo-contact-input.md)

이 문서에서 목록이 나타나는 순서와 아직 준비되지 않은 자리를 다루는 케이스의 절은 [페이지 조회 목록의 자리 표시 스펙](../spec/client/paged-list-placeholder.md)이, 검색어의 정규화와 일치 판정 케이스의 절은 [검색어 일치 판정 스펙](../spec/client/search-match.md)이 소유한다. 나머지 케이스의 절은 기준 스펙이 소유한다.

메모와 연락처의 연결 자체의 케이스는 [메모 연락처 테스트 케이스](./memo-contact.md)에서, 선택이 추가할 메모나 상세 대상 메모에 반영되는 케이스는 [MemoAdd 테스트 케이스](./memo-add.md)와 [MemoDetail 테스트 케이스](./memo-detail.md)에서 다룬다.

## feature

### TC-MEMO-CONTACT-INPUT-FEATURE-001: 연락처 선택 목록을 열면 목록에 나타나는 연락처가 표시된다

- 근거: `feature > 연락처 선택 목록`
- Given: 계정과 연결되고 삭제되지 않은 연락처가 여러 개 저장되어 있고 연락처 선택 목록이 닫혀 있다.
- When: 연락처 입력의 추가 항목을 누른다.
- Then: 연락처 선택 목록이 열리고 저장된 연락처가 각각의 선택 여부와 함께 나타난다.

### TC-MEMO-CONTACT-INPUT-FEATURE-002: 연락처 추가 항목이 연락처 입력에 항상 표시된다

- 근거: `feature > 연락처 선택 목록`
- Given: 연락처 입력이 표시되어 있고 선택 상태가 테스트 데이터와 같다.
- When: 연락처 입력을 확인한다.
- Then: 연락처 추가 항목이 표시된다.
- 테스트 데이터:

| 선택 상태 |
| --- |
| 선택한 연락처 없음 |
| 선택한 연락처 하나 |
| 선택한 연락처 여러 개 |

### TC-MEMO-CONTACT-INPUT-FEATURE-003: 선택할 수 있는 연락처가 없는 것으로 확정되면 추가 항목이 ContactAdd 이동을 요청한다

- 근거: `feature > 연락처 선택 목록`, `domain > 추가 항목의 동작 판정`
- Given: 선택할 수 있는 연락처가 하나도 없는 것으로 확정되어 있다.
- When: 연락처 입력의 추가 항목을 누른다.
- Then: 연락처 선택 목록이 열리지 않고 ContactAdd 화면으로의 이동이 요청된다.

### TC-MEMO-CONTACT-INPUT-FEATURE-004: 목록의 대상을 확인하는 중에는 추가 항목이 목록을 연다

- 근거: `domain > 추가 항목의 동작 판정`
- Given: 선택할 수 있는 연락처를 아직 확인하는 중이다.
- When: 연락처 입력의 추가 항목을 누른다.
- Then: 연락처 선택 목록이 열리고 ContactAdd 화면으로의 이동이 요청되지 않는다.

### TC-MEMO-CONTACT-INPUT-FEATURE-005: 확인 중에 연 목록이 대상 없음으로 확정되면 목록 영역이 비어 있는 채로 유지된다

- 근거: `feature > 연락처 선택 목록`
- Given: 선택할 수 있는 연락처를 확인하는 중에 연락처 선택 목록을 열어 두었다.
- When: 선택할 수 있는 연락처가 하나도 없는 것으로 확정된다.
- Then: 목록이 닫히지 않고 목록 영역이 비어 있는 채로 유지되며 빈 상태 안내가 표시되지 않는다.

### TC-MEMO-CONTACT-INPUT-FEATURE-006: 연락처 선택 목록에 연락처 추가 항목이 항상 표시된다

- 근거: `feature > 연락처 선택 목록`
- Given: 연락처 선택 목록이 열려 있고 목록의 상태가 테스트 데이터와 같다.
- When: 목록을 확인한다.
- Then: 연락처 추가 항목이 표시된다.
- 테스트 데이터:

| 목록 상태 |
| --- |
| 나타낼 연락처 없음 |
| 나타낼 연락처 여러 개 |
| 목록을 끝까지 확인함 |

### TC-MEMO-CONTACT-INPUT-FEATURE-007: 목록의 연락처 추가 항목을 누르면 목록이 닫히고 ContactAdd 이동이 요청된다

- 근거: `feature > 연락처 선택 목록`, `feature > 연락처 추가 이동`
- Given: 연락처 선택 목록이 열려 있고 선택할 수 있는 연락처가 테스트 데이터와 같다.
- When: 목록의 연락처 추가 항목을 누른다.
- Then: 목록이 닫히고 ContactAdd 화면으로의 이동이 요청된다.
- 테스트 데이터:

| 선택할 수 있는 연락처 |
| --- |
| 하나도 없음 |
| 여러 개 있음 |

### TC-MEMO-CONTACT-INPUT-FEATURE-008: ContactAdd 화면에서 추가한 연락처가 돌아왔을 때 선택된다

- 근거: `feature > 연락처 추가 이동`, `domain > 추가한 연락처의 자동 선택`
- Given: 연락처 입력에서 ContactAdd 화면으로 이동해 연락처를 테스트 데이터만큼 추가했고, 이동 전에 선택한 연락처가 있다.
- When: 연락처 입력이 있는 화면으로 돌아온다.
- Then: 이동 전 선택은 그대로 유지되고 추가한 연락처가 모두 선택에 더해진다.
- 테스트 데이터:

| 추가한 연락처 수 |
| --- |
| 하나 |
| 여러 개 |

### TC-MEMO-CONTACT-INPUT-FEATURE-009: 연락처를 추가하지 않고 돌아오면 선택이 그대로 유지된다

- 근거: `feature > 연락처 추가 이동`
- Given: 연락처 입력에서 ContactAdd 화면으로 이동했고 연락처를 하나도 추가하지 않았다.
- When: 연락처 입력이 있는 화면으로 돌아온다.
- Then: 선택한 연락처가 이동 전과 같다.

### TC-MEMO-CONTACT-INPUT-FEATURE-010: ContactAdd 화면에서 돌아와도 연락처 선택 목록이 저절로 열리지 않는다

- 근거: `feature > 연락처 추가 이동`
- Given: 연락처 선택 목록에서 ContactAdd 화면으로 이동했다.
- When: 연락처 입력이 있는 화면으로 돌아온다.
- Then: 연락처 선택 목록이 닫힌 상태로 유지된다.

### TC-MEMO-CONTACT-INPUT-FEATURE-011: 목록에서 연락처를 선택하면 선택 상태로 표시된다

- 근거: `feature > 연락처 선택과 해제`
- Given: 연락처 선택 목록이 열려 있고 선택되지 않은 연락처가 나타나 있다.
- When: 그 연락처를 누른다.
- Then: 별도의 확정 동작 없이 그 연락처가 목록에서 선택된 것으로 표시되고 연락처 입력에도 나타난다.

### TC-MEMO-CONTACT-INPUT-FEATURE-012: 목록에서 선택을 해제하면 선택 상태에서 제외된다

- 근거: `feature > 연락처 선택과 해제`
- Given: 연락처 선택 목록이 열려 있고 선택된 연락처가 나타나 있다.
- When: 그 연락처를 누른다.
- Then: 별도의 확정 동작 없이 그 연락처가 목록에서 선택되지 않은 것으로 표시되고 연락처 입력에서도 사라진다.

### TC-MEMO-CONTACT-INPUT-FEATURE-013: 한 번에 여러 연락처를 선택할 수 있다

- 근거: `feature > 연락처 선택과 해제`
- Given: 연락처 선택 목록이 열려 있고 선택되지 않은 연락처가 여러 개 나타나 있다.
- When: 그 연락처를 차례로 누른다.
- Then: 누른 연락처가 모두 선택 상태로 표시되고, 앞서 선택한 연락처의 선택이 해제되지 않는다.

### TC-MEMO-CONTACT-INPUT-FEATURE-014: 목록을 닫아도 반영된 선택이 유지된다

- 근거: `feature > 연락처 선택 목록`
- Given: 연락처 선택 목록에서 연락처를 선택했다.
- When: 목록을 닫는다.
- Then: 선택한 연락처가 연락처 입력에 그대로 나타난다.

### TC-MEMO-CONTACT-INPUT-FEATURE-015: 선택한 연락처의 이름이 바뀌면 연락처 입력에 반영된다

- 근거: `feature > 선택 상태 표시`
- Given: 연락처 하나가 선택되어 연락처 입력에 나타나 있다.
- When: 그 연락처의 저장된 이름이 다른 경로로 바뀐다.
- Then: 연락처 입력에 바뀐 이름이 표시된다.

### TC-MEMO-CONTACT-INPUT-FEATURE-016: 연락처 칩을 누르면 그 연락처의 ContactDetail 화면으로 이동한다

- 근거: `feature > 연락처 상세 이동`
- Given: 연락처 하나가 선택되어 연락처 입력에 나타나 있다.
- When: 그 연락처를 누른다.
- Then: 그 연락처를 대상으로 하는 ContactDetail 화면으로의 이동이 요청된다.

### TC-MEMO-CONTACT-INPUT-FEATURE-017: 연락처 칩을 눌러도 선택 상태와 연락처 선택 목록은 바뀌지 않는다

- 근거: `feature > 연락처 상세 이동`
- Given: 연락처 하나가 선택되어 연락처 입력에 나타나 있고 연락처 선택 목록이 닫혀 있다.
- When: 그 연락처를 누른다.
- Then: 그 연락처의 선택이 유지되고 연락처 선택 목록이 열리지 않는다.

### TC-MEMO-CONTACT-INPUT-FEATURE-018: 목록의 끝으로 이동하면 다음 연락처가 이어서 나타난다

- 근거: `feature > 연락처 선택 목록`
- Given: 연락처 선택 목록이 열려 있고 한 번에 준비되는 수보다 많은 연락처가 저장되어 있다.
- When: 목록을 끝까지 내린다.
- Then: 다음 구간의 연락처가 정렬 순서에 이어서 나타난다.
- 작성하지 않는 이유: 목록을 끝으로 옮긴 뒤 다음 연락처가 준비되는 과정은 화면 테스트 환경에서 배경 조회가 끝나는 시점을 제어할 수 없어 같은 조건에서 결과가 일정하지 않다. 조회가 정렬 순서 앞쪽부터 나뉘어 이루어지고 이어지는 조회가 그다음 연락처를 가져온다는 결과는 `TC-MEMO-CONTACT-INPUT-DATA-001`로 검증한다. 화면 테스트에서 배경 조회 완료 시점을 제어할 수 있게 되면 작성한다.

### TC-MEMO-CONTACT-INPUT-FEATURE-019: 다음 연락처를 불러오는 동안에도 이미 나타난 연락처를 조작할 수 있다

- 근거: `feature > 연락처 선택 목록`
- Given: 연락처 선택 목록이 열려 있고 다음 구간의 조회가 끝나지 않도록 제어되어 있다.
- When: 이미 나타난 연락처를 누른다.
- Then: 그 연락처의 선택 여부가 바뀐다.

### TC-MEMO-CONTACT-INPUT-FEATURE-020: 목록을 불러오지 못해도 이미 나타난 연락처를 유지한다

- 근거: `feature > 연락처 선택 목록`
- Given: 연락처 선택 목록에 연락처가 나타나 있고 다음 구간의 조회가 실패하도록 제어되어 있다.
- When: 목록을 끝까지 내린다.
- Then: 이미 나타난 연락처가 그대로 유지되고 오류 안내나 재시도 동작이 표시되지 않는다.

### TC-MEMO-CONTACT-INPUT-FEATURE-021: 목록을 닫았다가 다시 열면 앞부분부터 나타난다

- 근거: `feature > 연락처 선택 목록`
- Given: 연락처 선택 목록을 끝까지 내린 뒤 목록을 닫았다.
- When: 연락처 입력의 추가 항목을 눌러 목록을 다시 연다.
- Then: 목록이 정렬 순서의 앞부분부터 나타난다.
- 작성하지 않는 이유: 뒷부분까지 확인한 상태를 만들려면 목록의 다음 구간이 준비되기를 기다려야 하고, 그 시점을 화면 테스트 환경에서 제어할 수 없어 결과가 일정하지 않다. 목록을 다시 열면 검색어가 비워지고 대상 전체를 앞부분부터 다시 조회한다는 결과는 `TC-MEMO-CONTACT-INPUT-FEATURE-029`와 `TC-MEMO-CONTACT-INPUT-DATA-004`로 검증한다. 화면 테스트에서 배경 조회 완료 시점을 제어할 수 있게 되면 작성한다.

### TC-MEMO-CONTACT-INPUT-FEATURE-022: 목록의 연락처를 눌러도 연락처 상세로 이동하지 않는다

- 근거: `feature > 연락처 선택 목록`
- Given: 연락처 선택 목록이 열려 있고 연락처가 나타나 있다.
- When: 목록의 연락처를 누른다.
- Then: ContactDetail 화면으로의 이동이 요청되지 않고 그 연락처의 선택 여부만 바뀐다.

### TC-MEMO-CONTACT-INPUT-FEATURE-023: 목록을 열면 검색어가 비어 있고 대상 전체가 나타난다

- 근거: `feature > 연락처 검색`
- Given: 계정과 연결되고 삭제되지 않은 연락처가 여러 개 저장되어 있다.
- When: 연락처 선택 목록을 연다.
- Then: 검색어 입력이 비어 있고 선택할 수 있는 연락처가 정렬 순서의 앞부분부터 나타난다.

### TC-MEMO-CONTACT-INPUT-FEATURE-030: 목록을 열면 검색어 입력에 초점이 놓인다

- 근거: `feature > 연락처 검색`
- Given: 계정과 연결되고 삭제되지 않은 연락처가 여러 개 저장되어 있고 연락처 선택 목록이 닫혀 있다.
- When: 사용자가 연락처 선택 목록을 연다.
- Then: 검색어 입력이 입력 초점을 받아, 입력을 따로 누르지 않고 입력한 글자가 검색어 입력에 들어간다.

### TC-MEMO-CONTACT-INPUT-FEATURE-024: 검색어를 입력하면 목록이 좁혀진다

- 근거: `feature > 연락처 검색`
- Given: 연락처 선택 목록이 열려 있고 검색어를 만족하는 연락처와 만족하지 않는 연락처가 함께 저장되어 있다.
- When: 검색어를 입력한다.
