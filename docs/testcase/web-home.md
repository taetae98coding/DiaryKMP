# WebHome 테스트 케이스

기준 스펙: [WebHome 화면 스펙](../spec/client/web-home.md)

목록이 나타나는 순서와 아직 준비되지 않은 자리를 다루는 규칙은 [페이지 조회 목록의 자리 표시 스펙](../spec/client/paged-list-placeholder.md)에, 빈 상태의 판정과 행동은 [목록 빈 상태 스펙](../spec/client/list-empty-state.md)에, 당김으로 시작하는 동기화와 진행 표시는 [새로고침 스펙](../spec/client/sync-refresh.md)에 위임되어 있으며, 이 문서의 케이스는 WebHome에서 관찰하는 결과를 기준으로 한다. `더보기`에서 WebHome으로 이동하는 케이스는 [MoreHome 테스트 케이스](./more-home.md)에서, 웹 항목을 작성해 추가하는 케이스는 [WebAdd 테스트 케이스](./web-add.md)에서, 선택한 웹 항목의 상세와 웹 페이지 불러오기 케이스는 [WebDetail 테스트 케이스](./web-detail.md)에서, 검색으로 이동한 뒤 결과를 확인하고 선택하는 케이스는 [SearchHome 테스트 케이스](./search-home.md)에서, 웹 항목을 서버와 맞추는 케이스는 [데이터 동기화 테스트 케이스](./data-sync.md)에서, 화면과 무관한 새로고침 공통 규칙의 케이스는 [새로고침 테스트 케이스](./sync-refresh.md)에서 다룬다. 카드를 미는 상호작용 자체의 케이스는 [SwipeToFinishAndDelete 테스트 케이스](./swipe-to-finish-and-delete.md)에서 다룬다.

## feature

### TC-WEB-HOME-FEATURE-001: 계정에 저장된 웹 항목을 목록으로 표시한다

- 근거: `feature > 웹 목록`
- Given: 현재 계정에 노출 기준을 만족하는 웹 항목이 여러 개 있다.
- When: WebHome 화면이 표시된다.
- Then: 그 웹 항목이 모두 목록에 나타나고 각 항목의 제목과 URL을 확인할 수 있다.

### TC-WEB-HOME-FEATURE-009: 웹 항목의 설명은 목록에 표시하지 않는다

- 근거: `feature > 웹 목록`
- Given: 현재 계정에 설명이 있는 웹 항목과 설명이 빈 웹 항목이 있다.
- When: WebHome 화면이 표시된다.
- Then: 두 항목 모두 제목과 URL만 표시되고 어느 항목에도 설명이 표시되지 않는다.

### TC-WEB-HOME-FEATURE-004: 웹 항목을 추가하면 목록에 나타난다

- 근거: `feature > 웹 목록`
- Given: WebHome 화면에 웹 목록이 표시되어 있다.
- When: 노출 기준을 만족하는 웹 항목이 새로 저장된다.
- Then: 별도 조작 없이 그 웹 항목이 목록에 나타난다.

### TC-WEB-HOME-FEATURE-005: 웹 추가를 선택하면 WebAdd로 이동한다

- 근거: `feature > 웹 추가로 이동`
- Given: WebHome 화면이 표시되어 있고 목록이 테스트 데이터의 상태다.
- When: 사용자가 웹 추가를 선택한다.
- Then: WebAdd 화면으로 이동한다.
- 테스트 데이터:

| 목록 상태 |
| --- |
| 웹 항목이 있음 |
| 웹 항목이 없어 빈 상태 안내가 표시됨 |

### TC-WEB-HOME-FEATURE-016: 검색을 선택하면 웹 유형으로 시작하는 SearchHome 화면으로 이동한다

- 근거: `feature > 검색으로 이동`
- Given: WebHome 화면이 표시되어 있고 목록이 테스트 데이터의 상태다.
- When: 사용자가 검색을 선택한다.
- Then: SearchHome 화면으로 이동하는 동작이 한 번 실행된다.
- 테스트 데이터:

| 목록 상태 |
| --- |
| 웹 항목이 있음 |
| 웹 항목이 없어 빈 상태 안내가 표시됨 |

지정하는 시작 유형은 화면 밖 내비게이션 배선이 정하므로 이 케이스에서 관찰하지 않는다. 시작 유형별 표시는 [SearchHome 테스트 케이스](./search-home.md)의 `TC-SEARCH-HOME-FEATURE-005`가 다룬다.

### TC-WEB-HOME-FEATURE-017: 웹 항목을 선택하면 그 웹 항목의 WebDetail로 이동한다

- 근거: `feature > 웹 상세로 이동`
- Given: WebHome 화면에 웹 항목이 표시되어 있다.
- When: 사용자가 목록의 웹 항목을 선택한다.
- Then: 그 웹 항목의 WebDetail 화면으로 한 번 이동한다.

### TC-WEB-HOME-FEATURE-007: 아직 준비되지 않은 자리는 선택할 수 없다

- 근거: `feature > 웹 상세로 이동`
- Given: WebHome 화면에 아직 준비되지 않은 자리가 표시되어 있다.
- When: 사용자가 그 자리를 선택한다.
- Then: WebDetail 화면으로 이동하지 않는다.

### TC-WEB-HOME-FEATURE-008: 뒤로가면 `더보기`로 돌아간다

- 근거: `feature > 뒤로가기`
- Given: WebHome 화면이 표시되어 있다.
- When: 사용자가 뒤로가기를 실행한다.
- Then: 이전 화면인 `더보기`로 돌아간다.

### TC-WEB-HOME-FEATURE-010: 표시할 웹 항목이 없으면 빈 상태 안내를 표시한다

- 근거: `feature > 빈 상태`
- Given: 현재 계정에 노출 기준을 만족하는 웹 항목이 하나도 없고 목록의 준비가 끝났다.
- When: WebHome 화면이 표시된다.
- Then: 목록 자리에 아직 웹 항목이 없으며 새로 추가할 수 있음을 알리는 안내가 표시된다.

### TC-WEB-HOME-FEATURE-011: 목록을 준비하는 동안에는 빈 상태 안내를 표시하지 않는다

- 근거: `feature > 빈 상태`
- Given: 웹 목록의 준비가 아직 끝나지 않아 표시된 웹 항목이 하나도 없다.
- When: WebHome 화면이 표시된다.
- Then: 빈 상태 안내가 표시되지 않는다.

### TC-WEB-HOME-FEATURE-012: 표시할 웹 항목이 있으면 빈 상태 안내를 표시하지 않는다

- 근거: `feature > 빈 상태`
- Given: 현재 계정에 노출 기준을 만족하는 웹 항목이 있다.
- When: WebHome 화면이 표시된다.
- Then: 웹 항목이 목록에 표시되고 빈 상태 안내는 표시되지 않는다.

### TC-WEB-HOME-FEATURE-013: 목록을 당기면 계정 데이터의 서버 동기화가 요청된다

- 근거: `feature > 새로고침`
- Given: 인증된 사용자 계정이 확인된 상태로 WebHome 화면에 웹 목록이 표시되어 있고 진행 중인 동기화가 없다.
- When: 사용자가 목록을 아래로 당겨 새로고침을 요청한다.
- Then: 계정 데이터의 서버 동기화가 한 번 요청된다.

### TC-WEB-HOME-FEATURE-014: 빈 상태에서도 목록을 당겨 새로고침할 수 있다

- 근거: `feature > 빈 상태`
- Given: WebHome 화면에 빈 상태 안내가 표시되어 있다.
- When: 사용자가 빈 상태 영역을 아래로 당겨 새로고침을 요청한다.
- Then: 계정 데이터의 서버 동기화가 한 번 요청된다.

### TC-WEB-HOME-FEATURE-015: 새로고침이 실행되는 동안 진행이 표시된다

- 근거: `feature > 새로고침`
- Given: WebHome 화면이 표시되어 있고 진행 중인 동기화가 없다.
- When: 사용자가 당겨서 요청한 동기화가 실행되기 시작한 뒤 성공 또는 실패로 끝난다.
- Then: 실행되는 동안 목록 영역에 진행 표시가 나타나고, 끝나면 사라진다.

### TC-WEB-HOME-FEATURE-018: 목록 위에 현재 정렬을 표시한다

- 근거: `feature > 정렬 선택`
- Given: 현재 계정에 웹 항목이 있고 사용자가 정렬을 고르지 않았다.
- When: WebHome 화면이 표시된다.
- Then: 목록 위에 현재 정렬이 제목순임을 알리는 컨트롤이 표시된다.

### TC-WEB-HOME-FEATURE-019: 정렬 컨트롤을 누르면 고를 수 있는 정렬이 나타난다

- 근거: `feature > 정렬 선택`
- Given: WebHome 화면에 정렬 컨트롤이 표시되어 있다.
- When: 사용자가 정렬 컨트롤을 선택한다.
- Then: 제목순과 최근 수정순을 고를 수 있는 목록이 나타나고 제목순이 선택 상태로 표시된다.

### TC-WEB-HOME-FEATURE-020: 최근 수정순을 고르면 목록이 수정 시각 내림차순으로 바뀐다

- 근거: `feature > 정렬 선택`
- Given: 제목 오름차순과 수정 시각 내림차순의 순서가 서로 다른 웹 항목이 목록에 표시되어 있다.
- When: 사용자가 정렬 컨트롤을 열어 최근 수정순을 고른다.
- Then: 선택 목록이 닫히고 웹 항목이 수정 시각이 늦은 것부터 표시되며 정렬 컨트롤이 최근 수정순을 알린다.

### TC-WEB-HOME-FEATURE-021: 지금 선택된 정렬을 다시 골라도 순서가 바뀌지 않는다

- 근거: `feature > 정렬 선택`
- Given: WebHome 화면에서 정렬 선택 목록을 열었고 현재 정렬이 제목순이다.
- When: 사용자가 제목순을 고른다.
- Then: 선택 목록이 닫히고 목록의 순서가 그대로 유지된다.

### TC-WEB-HOME-FEATURE-024: 목록이 비어 있으면 정렬 컨트롤이 표시되지 않는다

- 근거: `feature > 정렬 선택`
- Given: 현재 계정에 표시할 웹 항목이 없다.
- When: WebHome 화면이 표시된다.
- Then: 빈 상태 안내가 표시되고 정렬 컨트롤은 표시되지 않는다.

### TC-WEB-HOME-FEATURE-023: 정렬을 바꾸면 목록이 맨 위에서 다시 시작한다

- 근거: `feature > 정렬 선택`
- Given: 한 화면에 모두 보이지 않을 만큼 많은 웹 항목이 목록에 표시되어 있고, 사용자가 목록을 아래로 스크롤해 첫 항목이 보이지 않는 상태다.
- When: 사용자가 정렬 컨트롤을 열어 최근 수정순을 고른다.
- Then: 사용자가 스크롤해 둔 자리는 유지되지 않고 새 순서의 첫 항목이 목록 맨 위에 보인다.
- 작성하지 않는 이유: 이 결과는 정렬을 바꾼 뒤 새 순서로 다시 조회한 목록이 화면에 놓이는 시점에 나타난다. 현재 화면 테스트 환경은 화면이 표시된 상태에서 목록을 다시 조회해 놓는 과정을 결정적으로 재현하지 못해, 새 목록이 놓이지 않은 채로 판정이 끝난다. 표시 중인 목록을 다시 조회해 교체하는 시점을 제어할 수 있는 테스트 환경이 갖춰지면 자동화한다.


### TC-WEB-HOME-FEATURE-025: 웹 카드를 삭제 방향으로 밀면 삭제되고 안내와 실행 취소가 표시된다

- 근거: `feature > 삭제`
- Given: WebHome 화면에 웹 항목이 표시되어 있고 삭제가 성공하도록 설정되어 있다.
- When: 사용자가 그 웹 카드를 오른쪽에서 왼쪽으로 민다.
- Then: 그 웹 항목의 삭제가 한 번 요청되고, 삭제되었다는 안내와 실행 취소 동작이 표시된다.
- 테스트 데이터:

| 언어 환경 | 안내 | 실행 취소 동작 |
| --- | --- | --- |
| 한국어 | `웹이 삭제되었습니다.` | `실행 취소` |
| 그 외 기본 | `Web deleted.` | `Undo` |

### TC-WEB-HOME-FEATURE-026: 삭제를 실행 취소하면 그 웹 항목의 삭제가 되돌려진다

- 근거: `feature > 삭제`
- Given: WebHome 화면에서 웹 항목을 삭제해 안내와 실행 취소 동작이 표시되어 있다.
- When: 사용자가 실행 취소를 선택한다.
- Then: 그 웹 항목을 삭제되지 않은 상태로 되돌리는 요청이 한 번 일어난다.

### TC-WEB-HOME-FEATURE-027: 웹 카드를 반대 방향으로 밀면 아무 동작도 실행하지 않는다

- 근거: `feature > 삭제`
- Given: WebHome 화면에 웹 항목이 표시되어 있다.
- When: 사용자가 그 웹 카드를 왼쪽에서 오른쪽으로 민다.
- Then: 삭제가 요청되지 않고 웹 항목이 목록에 그대로 남으며 안내도 표시되지 않는다.

### TC-WEB-HOME-FEATURE-028: 아직 준비되지 않은 자리는 밀어도 삭제되지 않는다

- 근거: `feature > 삭제`
- Given: WebHome 화면에 아직 준비되지 않은 자리가 표시되어 있다.
- When: 사용자가 그 자리를 오른쪽에서 왼쪽으로 민다.
- Then: 삭제가 요청되지 않는다.

### TC-WEB-HOME-FEATURE-029: 안내가 보이는 동안 다른 웹 항목을 삭제하면 마지막 삭제의 안내만 남는다

- 근거: `feature > 안내와 실행 취소`
- Given: WebHome 화면에서 웹 항목 A를 삭제해 안내가 표시되어 있다.
- When: 안내가 사라지기 전에 웹 항목 B가 삭제되고, 이어서 사용자가 실행 취소를 선택한다.
- Then: 삭제 안내는 하나만 표시되고, 실행 취소는 웹 항목 B에만 적용되며 웹 항목 A는 되돌려지지 않는다.

### TC-WEB-HOME-FEATURE-030: 실행 취소를 선택하지 않으면 안내가 잠시 뒤 사라지고 되돌릴 수 없다

- 근거: `feature > 안내와 실행 취소`
- Given: WebHome 화면에서 웹 항목을 삭제해 안내가 표시되어 있다.
- When: 사용자가 실행 취소를 선택하지 않고 안내가 저절로 사라질 때까지 기다린다.
- Then: 안내와 실행 취소 동작이 사라지고, 삭제를 되돌리는 요청은 일어나지 않는다.

### TC-WEB-HOME-FEATURE-031: 삭제가 저장되지 못하면 안내를 표시하지 않는다

- 근거: `feature > 안내와 실행 취소`
- Given: 웹 항목 삭제의 저장이 실패하도록 설정되어 있다.
- When: 사용자가 목록에서 웹 항목을 삭제한다.
- Then: 삭제 안내와 실행 취소 동작이 제공되지 않는다.

### TC-WEB-HOME-FEATURE-032: 안내가 보이는 동안 화면을 떠나면 안내가 닫히고 되돌릴 수 없다

- 근거: `feature > 안내와 실행 취소`
- Given: WebHome 화면에서 웹 항목을 삭제해 안내와 실행 취소 동작이 표시되어 있다.
- When: 사용자가 WebHome 화면을 떠났다가 다시 돌아온다.
- Then: 안내와 실행 취소 동작이 보이지 않고, 삭제를 되돌리는 요청은 일어나지 않는다.
