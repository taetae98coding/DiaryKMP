# WebHome 테스트 케이스

기준 스펙: [WebHome 화면 스펙](../spec/web-home.md)

목록이 나타나는 순서와 아직 준비되지 않은 자리를 다루는 규칙은 [페이지 조회 목록의 자리 표시 스펙](../spec/paged-list-placeholder.md)에, 빈 상태의 판정과 행동은 [목록 빈 상태 스펙](../spec/list-empty-state.md)에, 당김으로 시작하는 동기화와 진행 표시는 [새로고침 스펙](../spec/sync-refresh.md)에 위임되어 있으며, 이 문서의 케이스는 WebHome에서 관찰하는 결과를 기준으로 한다. `더보기`에서 WebHome으로 이동하는 케이스는 [MoreHome 테스트 케이스](./more-home.md)에서, 웹 항목을 작성해 추가하는 케이스는 [WebAdd 테스트 케이스](./web-add.md)에서, 선택한 웹 항목의 상세와 웹 페이지 불러오기 케이스는 [WebDetail 테스트 케이스](./web-detail.md)에서, 검색으로 이동한 뒤 결과를 확인하고 선택하는 케이스는 [SearchHome 테스트 케이스](./search-home.md)에서, 웹 항목을 서버와 맞추는 케이스는 [데이터 동기화 테스트 케이스](./data-sync.md)에서, 화면과 무관한 새로고침 공통 규칙의 케이스는 [새로고침 테스트 케이스](./sync-refresh.md)에서 다룬다.

## feature

### TC-WEB-HOME-FEATURE-001: 계정에 저장된 웹 항목을 목록으로 표시한다

- 근거: `feature > 웹 목록`
- Given: 현재 계정에 노출 기준을 만족하는 웹 항목이 여러 개 있다.
- When: WebHome 화면이 표시된다.
- Then: 그 웹 항목이 모두 목록에 나타나고 각 항목의 제목과 URL을 확인할 수 있다.

### TC-WEB-HOME-FEATURE-009: 웹 항목의 설명은 목록에 표시하지 않는다

- 근거: `feature > 웹 목록`
- Given: 현재 계정에 설명이 있는 웹 항목과 설명이 빈 웹 항목이 있다.
- When: WebHome 화면이 표시된다.
- Then: 두 항목 모두 제목과 URL만 표시되고 어느 항목에도 설명이 표시되지 않는다.

### TC-WEB-HOME-FEATURE-004: 웹 항목을 추가하면 목록에 나타난다

- 근거: `feature > 웹 목록`
- Given: WebHome 화면에 웹 목록이 표시되어 있다.
- When: 노출 기준을 만족하는 웹 항목이 새로 저장된다.
- Then: 별도 조작 없이 그 웹 항목이 목록에 나타난다.
- 작성하지 않는 이유: 화면을 구성한 뒤 목록이 갱신되는 전환은 자동화하지 않는다. 호스트 테스트는 한 JVM에서 여러 화면 테스트를 이어서 실행하는데, 앞 테스트가 초기화한 코루틴 메인 디스패처 바인딩이 남아 뒤 테스트에서는 컴포지션 이후의 페이지 조회 갱신이 전달되지 않아 실행 순서에 따라 결과가 달라진다. 저장 전후의 목록 표시는 각각의 목록으로 구성해 확인하고, 갱신 전환은 테스트 클래스마다 실행 환경을 격리할 수 있게 되면 작성한다.

### TC-WEB-HOME-FEATURE-005: 웹 추가를 선택하면 WebAdd로 이동한다

- 근거: `feature > 웹 추가로 이동`
- Given: WebHome 화면이 표시되어 있고 목록이 테스트 데이터의 상태다.
- When: 사용자가 웹 추가를 선택한다.
- Then: WebAdd 화면으로 이동한다.
- 테스트 데이터:

| 목록 상태 |
| --- |
| 웹 항목이 있음 |
| 웹 항목이 없어 빈 상태 안내가 표시됨 |

### TC-WEB-HOME-FEATURE-016: 검색을 선택하면 웹 유형으로 시작하는 SearchHome 화면으로 이동한다

- 근거: `feature > 검색으로 이동`
- Given: WebHome 화면이 표시되어 있고 목록이 테스트 데이터의 상태다.
- When: 사용자가 검색을 선택한다.
- Then: SearchHome 화면으로 이동하는 동작이 한 번 실행된다.
- 테스트 데이터:

| 목록 상태 |
| --- |
| 웹 항목이 있음 |
| 웹 항목이 없어 빈 상태 안내가 표시됨 |

지정하는 시작 유형은 화면 밖 내비게이션 배선이 정하므로 이 케이스에서 관찰하지 않는다. 시작 유형별 표시는 [SearchHome 테스트 케이스](./search-home.md)의 `TC-SEARCH-HOME-FEATURE-005`가 다룬다.

### TC-WEB-HOME-FEATURE-017: 웹 항목을 선택하면 그 웹 항목의 WebDetail로 이동한다

- 근거: `feature > 웹 상세로 이동`
- Given: WebHome 화면에 웹 항목이 표시되어 있다.
- When: 사용자가 목록의 웹 항목을 선택한다.
- Then: 그 웹 항목의 WebDetail 화면으로 한 번 이동한다.

### TC-WEB-HOME-FEATURE-007: 아직 준비되지 않은 자리는 선택할 수 없다

- 근거: `feature > 웹 상세로 이동`
- Given: WebHome 화면에 아직 준비되지 않은 자리가 표시되어 있다.
- When: 사용자가 그 자리를 선택한다.
- Then: WebDetail 화면으로 이동하지 않는다.

### TC-WEB-HOME-FEATURE-008: 뒤로가면 `더보기`로 돌아간다

- 근거: `feature > 뒤로가기`
- Given: WebHome 화면이 표시되어 있다.
- When: 사용자가 뒤로가기를 실행한다.
- Then: 이전 화면인 `더보기`로 돌아간다.

### TC-WEB-HOME-FEATURE-010: 표시할 웹 항목이 없으면 빈 상태 안내를 표시한다

- 근거: `feature > 빈 상태`
- Given: 현재 계정에 노출 기준을 만족하는 웹 항목이 하나도 없고 목록의 준비가 끝났다.
- When: WebHome 화면이 표시된다.
- Then: 목록 자리에 아직 웹 항목이 없으며 새로 추가할 수 있음을 알리는 안내가 표시된다.

### TC-WEB-HOME-FEATURE-011: 목록을 준비하는 동안에는 빈 상태 안내를 표시하지 않는다

- 근거: `feature > 빈 상태`
- Given: 웹 목록의 준비가 아직 끝나지 않아 표시된 웹 항목이 하나도 없다.
- When: WebHome 화면이 표시된다.
- Then: 빈 상태 안내가 표시되지 않는다.

### TC-WEB-HOME-FEATURE-012: 표시할 웹 항목이 있으면 빈 상태 안내를 표시하지 않는다

- 근거: `feature > 빈 상태`
- Given: 현재 계정에 노출 기준을 만족하는 웹 항목이 있다.
- When: WebHome 화면이 표시된다.
- Then: 웹 항목이 목록에 표시되고 빈 상태 안내는 표시되지 않는다.

### TC-WEB-HOME-FEATURE-013: 목록을 당기면 계정 데이터의 서버 동기화가 요청된다

- 근거: `feature > 새로고침`
- Given: 인증된 사용자 계정이 확인된 상태로 WebHome 화면에 웹 목록이 표시되어 있고 진행 중인 동기화가 없다.
- When: 사용자가 목록을 아래로 당겨 새로고침을 요청한다.
- Then: 계정 데이터의 서버 동기화가 한 번 요청된다.

### TC-WEB-HOME-FEATURE-014: 빈 상태에서도 목록을 당겨 새로고침할 수 있다

- 근거: `feature > 빈 상태`
- Given: WebHome 화면에 빈 상태 안내가 표시되어 있다.
- When: 사용자가 빈 상태 영역을 아래로 당겨 새로고침을 요청한다.
- Then: 계정 데이터의 서버 동기화가 한 번 요청된다.

### TC-WEB-HOME-FEATURE-015: 새로고침이 실행되는 동안 진행이 표시된다

- 근거: `feature > 새로고침`
- Given: WebHome 화면이 표시되어 있고 진행 중인 동기화가 없다.
- When: 사용자가 당겨서 요청한 동기화가 실행되기 시작한 뒤 성공 또는 실패로 끝난다.
- Then: 실행되는 동안 목록 영역에 진행 표시가 나타나고, 끝나면 사라진다.

### TC-WEB-HOME-FEATURE-018: 목록 위에 현재 정렬을 표시한다

- 근거: `feature > 정렬 선택`
- Given: 현재 계정에 웹 항목이 있고 사용자가 정렬을 고르지 않았다.
- When: WebHome 화면이 표시된다.
- Then: 목록 위에 현재 정렬이 제목순임을 알리는 컨트롤이 표시된다.

### TC-WEB-HOME-FEATURE-019: 정렬 컨트롤을 누르면 고를 수 있는 정렬이 나타난다

- 근거: `feature > 정렬 선택`
- Given: WebHome 화면에 정렬 컨트롤이 표시되어 있다.
- When: 사용자가 정렬 컨트롤을 선택한다.
- Then: 제목순과 최근 수정순을 고를 수 있는 목록이 나타나고 제목순이 선택 상태로 표시된다.

### TC-WEB-HOME-FEATURE-020: 최근 수정순을 고르면 목록이 수정 시각 내림차순으로 바뀐다

- 근거: `feature > 정렬 선택`
- Given: 제목 오름차순과 수정 시각 내림차순의 순서가 서로 다른 웹 항목이 목록에 표시되어 있다.
- When: 사용자가 정렬 컨트롤을 열어 최근 수정순을 고른다.
- Then: 선택 목록이 닫히고 웹 항목이 수정 시각이 늦은 것부터 표시되며 정렬 컨트롤이 최근 수정순을 알린다.

### TC-WEB-HOME-FEATURE-021: 지금 선택된 정렬을 다시 골라도 순서가 바뀌지 않는다

- 근거: `feature > 정렬 선택`
- Given: WebHome 화면에서 정렬 선택 목록을 열었고 현재 정렬이 제목순이다.
- When: 사용자가 제목순을 고른다.
- Then: 선택 목록이 닫히고 목록의 순서가 그대로 유지된다.

### TC-WEB-HOME-FEATURE-022: 목록이 비어 있어도 정렬을 고를 수 있다

- 근거: `feature > 정렬 선택`
- Given: 표시할 웹 항목이 없어 빈 상태 안내가 표시되어 있다.
- When: 사용자가 정렬 컨트롤을 선택해 최근 수정순을 고른다.
- Then: 정렬 컨트롤이 최근 수정순을 알리고 빈 상태 안내는 그대로 유지된다.

### TC-WEB-HOME-FEATURE-023: 정렬을 바꾸면 목록이 맨 위에서 다시 시작한다

- 근거: `feature > 정렬 선택`
- Given: 한 화면에 모두 보이지 않을 만큼 많은 웹 항목이 목록에 표시되어 있고, 사용자가 목록을 아래로 스크롤해 첫 항목이 보이지 않는 상태다.
- When: 사용자가 정렬 컨트롤을 열어 최근 수정순을 고른다.
- Then: 사용자가 스크롤해 둔 자리는 유지되지 않고 새 순서의 첫 항목이 목록 맨 위에 보인다.
- 작성하지 않는 이유: 이 결과는 정렬을 바꾼 뒤 새 순서로 다시 조회한 목록이 화면에 놓이는 시점에 나타난다. 현재 화면 테스트 환경은 화면이 표시된 상태에서 목록을 다시 조회해 놓는 과정을 결정적으로 재현하지 못해, 새 목록이 놓이지 않은 채로 판정이 끝난다. 표시 중인 목록을 다시 조회해 교체하는 시점을 제어할 수 있는 테스트 환경이 갖춰지면 자동화한다.


## domain

### TC-WEB-HOME-DOMAIN-001: 현재 계정과 연결되고 삭제되지 않은 웹 항목만 노출한다

- 근거: `domain > 목록에 노출하는 웹 항목`
- Given: 현재 계정과 연결된 웹 항목, 삭제된 웹 항목, 다른 계정과 연결된 웹 항목이 저장되어 있다.
- When: 웹 목록을 조회한다.
- Then: 현재 계정과 연결되고 삭제되지 않은 웹 항목만 조회된다.

### TC-WEB-HOME-DOMAIN-002: 현재 계정을 확인할 수 없으면 노출하는 웹 항목이 없다

- 근거: `domain > 목록에 노출하는 웹 항목`
- Given: 현재 계정 조회가 실패하도록 설정되어 있다.
- When: 웹 목록을 조회한다.
- Then: 노출하는 웹 항목이 없고 계정 조회의 실패가 그대로 전달된다.

### TC-WEB-HOME-DOMAIN-003: 목록은 제목 오름차순으로 정렬한다

- 근거: `domain > 목록 정렬`
- Given: 현재 계정에 제목이 서로 다른 웹 항목이 여러 개 있고 사용자가 정렬을 고르지 않았다.
- When: 웹 목록을 조회한다.
- Then: 웹 항목이 제목 오름차순으로 조회된다.

### TC-WEB-HOME-DOMAIN-004: 저장 상태가 바뀌면 노출 기준과 정렬 기준으로 목록을 갱신한다

- 근거: `domain > 목록 갱신`
- Given: 웹 목록이 조회되어 있다.
- When: 테스트 데이터의 변경이 저장된다.
- Then: 목록이 테스트 데이터의 기대 결과로 갱신된다.
- 테스트 데이터:

| 저장 변경 | 기대 결과 |
| --- | --- |
| 노출 기준을 만족하는 웹 항목 추가 | 제목 순서에 맞는 자리에 나타남 |
| 목록에 있는 웹 항목의 제목 변경 | 새 제목과 정렬 기준으로 나타남 |
| 목록에 있는 웹 항목이 삭제 상태로 변경 | 목록에서 사라짐 |
| 서버에서 내려받은 웹 항목이 기기에 반영됨 | 노출 기준과 정렬 기준에 따라 목록에 반영됨 |

### TC-WEB-HOME-DOMAIN-005: 최근 수정순은 수정 시각 내림차순으로 정렬하고 같으면 제목 오름차순으로 정렬한다

- 근거: `domain > 목록 정렬`
- Given: 테스트 데이터의 웹 항목이 저장되어 있다.
- When: 최근 수정순으로 웹 목록을 조회한다.
- Then: 테스트 데이터의 기대 순서로 조회된다.
- 테스트 데이터:

  | 웹 항목 | 제목 | 수정 시각 | 기대 순서 |
  | --- | --- | --- | --- |
  | A | Charlie | 2026-07-20T10:00:00Z | 1 |
  | B | Bravo | 2026-07-19T10:00:00Z | 2 |
  | C | Alpha | 2026-07-19T10:00:00Z | 3 |

  기대 순서 2와 3은 수정 시각이 같으므로 제목 오름차순으로 정해진다.

### TC-WEB-HOME-DOMAIN-006: 정렬을 바꿔도 노출하는 웹 항목은 달라지지 않는다

- 근거: `domain > 목록 정렬`
- Given: 현재 계정에 노출 기준을 만족하는 웹 항목과 삭제된 웹 항목이 저장되어 있다.
- When: 정렬을 최근 수정순으로 바꿔 웹 목록을 조회한다.
- Then: 제목순일 때와 같은 웹 항목만 순서만 달라져 조회된다.


## data

### TC-WEB-HOME-DATA-001: 현재 계정 기준으로 저장소에서 페이지 단위로 조회한다

- 근거: `data > 목록 조회`
- Given: 현재 계정과 연결된 웹 항목이 한 페이지보다 많이 저장되어 있다.
- When: 웹 목록을 조회한다.
- Then: 노출 기준과 정렬 순서를 만족하는 웹 항목이 페이지 단위로 조회되고, 사용자가 목록을 계속 확인하면 다음 페이지가 이어서 조회된다.

### TC-WEB-HOME-DATA-002: 저장된 웹 항목이 바뀌면 조회 결과가 갱신된다

- 근거: `data > 목록 조회`
- Given: 웹 목록이 조회되어 있다.
- When: 조회 기준을 만족하는 웹 항목이 로컬에 새로 저장된다.
- Then: 조회 결과에 그 웹 항목이 반영된다.

### TC-WEB-HOME-DATA-003: 목록을 조회하지 못하면 빈 상태로 표시한다

- 근거: `data > 목록 조회`
- Given: 웹 목록 조회가 실패하도록 설정되어 있다.
- When: WebHome 화면이 표시된다.
- Then: 목록에 웹 항목이 하나도 표시되지 않고 빈 상태 안내가 표시되며 오류 안내는 표시되지 않는다.

### TC-WEB-HOME-DATA-004: WebHome 진입만으로는 서버 조회를 일으키지 않는다

- 근거: `data > 목록 조회`
- Given: 진행 중인 동기화가 없다.
- When: 사용자가 WebHome 화면에 진입하고 새로고침을 요청하지 않는다.
- Then: 계정 데이터의 서버 동기화가 요청되지 않는다.

### TC-WEB-HOME-DATA-005: 선택한 정렬을 조회 조건으로 넘겨 정렬된 순서로 조회한다

- 근거: `data > 목록 조회`
- Given: 현재 계정에 웹 항목이 여러 개 저장되어 있다.
- When: 사용자가 정렬을 최근 수정순으로 바꾼다.
- Then: 목록 조회가 최근 수정순으로 다시 시작되어 저장소에서 그 순서로 조회된다.

### TC-WEB-HOME-DATA-006: 정렬 선택은 저장소에 남기지 않는다

- 근거: `data > 목록 조회`
- Given: 사용자가 WebHome 화면에서 정렬을 최근 수정순으로 바꿨다.
- When: 화면을 떠났다가 다시 들어온다.
- Then: 정렬이 제목순으로 되돌아간다.
