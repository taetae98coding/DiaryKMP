# 새로고침 테스트 케이스

기준 스펙: [새로고침 스펙](../spec/client/sync-refresh.md)

TagDetail 웹·장소 탭, PlaceHome, WebHome, ContactHome, PlaylistHome, QrHome, ChecklistHome에서 당겨 동기화를 요청하고 진행을 표시하는 케이스는 각 화면의 테스트 케이스 문서가 그 화면에서 관찰하는 결과로 자동화한다.

`feature > 당겨서 새로고침`의 새로 받은 내용이 별도 조작 없이 화면에 반영되는 결과는 각 대상 화면의 테스트 케이스 문서가 그 화면의 저장된 내용 변경이 자동으로 반영되는 케이스로 다룬다. RoutineHome은 노출할 루틴이 없어 새로고침 중에도 빈 상태 안내를 유지하는 케이스만 둔다.

### TC-cfac82d4-8af3-4b80-ab6b-ca2c2b56fde5: 위치 권한 허용으로 시작한 날씨 동기화도 끝날 때까지 진행을 표시한다

### TC-6c9103e0-62b8-4abe-98bb-dbd98e9a377c: 진행 중인 공휴일·날씨 동기화가 있으면 당김은 새 동기화를 시작하지 않는다

### TC-32901c46-d015-48a7-8670-935bf75d1290: 앱을 다시 실행해 계정을 확인하면 표시 대상이 된다

- 근거: `domain > 실행 경계`
- Given: 앱을 다시 실행해 새로고침 대상 화면이 표시되어 있고 진행 표시가 없다.

- Then: 진행 표시가 나타난다.

## 작성하지 않는 이유

- 진행 표시의 위치, 크기, 색, 회전 모션과 당김 임계값은 시각 판단이 필요해 결정적으로 판정할 수 없다. 표현 기준은 [새로고침 디자인](../design/sync-refresh.md)에서 관리한다. 실제 화면을 캡처해 기준 이미지와 비교하고 당김 제스처의 이동 거리를 기기에서 재현할 수 있는 테스트 환경이 갖춰지면 작성한다.
