# 새로고침 테스트 케이스

기준 스펙: [새로고침 스펙](../spec/client/sync-refresh.md)

TagDetail 웹·장소 탭, PlaceHome, WebHome, ContactHome, PlaylistHome, QrHome에서 당겨 동기화를 요청하고 진행을 표시하는 케이스는 각 화면의 테스트 케이스 문서가 그 화면에서 관찰하는 결과로 자동화한다.

`feature > 당겨서 새로고침`의 새로 받은 내용이 별도 조작 없이 화면에 반영되는 결과는 각 대상 화면의 테스트 케이스 문서가 그 화면의 저장된 내용 변경이 자동으로 반영되는 케이스로 다룬다. RoutineHome은 노출할 루틴이 없어 새로고침 중에도 빈 상태 안내를 유지하는 케이스만 둔다.

## feature

### TC-SYNC-REFRESH-FEATURE-001: 당기면 화면의 새로고침 대상이 다시 동기화된다

- 근거: `feature > 당겨서 새로고침`
- Given: 인증된 사용자 계정이 확인된 상태로 새로고침 대상 화면이 표시되어 있고 진행 중인 동기화가 없다.
- When: 사용자가 화면을 당겨 새로고침을 요청한다.
- Then: 해당 화면의 새로고침 대상 동기화가 요청된다.
- 테스트 데이터:

| 화면 | 요청되는 동기화 |
| --- | --- |
| CalendarHome | 계정 데이터 서버 동기화, 표시 중인 달의 공휴일 동기화, 현재 위치의 날씨 동기화 |
| MemoHome | 계정 데이터 서버 동기화 |
| MemoFinishedList | 계정 데이터 서버 동기화 |
| TagHome | 계정 데이터 서버 동기화 |
| TagFinishedList | 계정 데이터 서버 동기화 |
| TagDetail 메모 탭 | 계정 데이터 서버 동기화 |
| TagMemoFinishedList | 계정 데이터 서버 동기화 |
| ContactDetail 메모 탭 | 계정 데이터 서버 동기화 |
| PlaceDetail 메모 탭 | 계정 데이터 서버 동기화 |
| WebDetail 메모 탭 | 계정 데이터 서버 동기화 |
| RoutineHome | 계정 데이터 서버 동기화 |

### TC-SYNC-REFRESH-FEATURE-002: 당겨서 요청한 동기화가 실행되는 동안 진행이 표시된다

- 근거: `feature > 진행 표시`
- Given: 새로고침 대상 화면이 표시되어 있고 진행 중인 동기화가 없다.
- When: 사용자가 화면을 당겨 새로고침을 요청하고 동기화가 실행되기 시작한다.
- Then: 해당 화면에 진행 표시가 나타난다.

### TC-SYNC-REFRESH-FEATURE-003: 계정 확인 계기로 시작된 동기화가 실행되는 동안 진행이 표시된다

- 근거: `feature > 진행 표시`, `domain > 새로고침 계기`
- Given: 새로고침 대상 화면이 표시되어 있고 진행 중인 동기화가 없다.
- When: 테스트 데이터의 계정 확인으로 앱이 계정 데이터 서버 동기화를 시작하고 그 동기화가 실행되기 시작한다.
- Then: 해당 화면에 진행 표시가 나타난다.
- 테스트 데이터:

| 계정 확인 |
| --- |
| 앱이 시작되거나 다시 활성 상태가 된 뒤 인증된 사용자 계정을 처음 확인 |
| 앱 화면이 다시 만들어진 뒤 인증된 사용자 계정을 처음 확인 |
| 확인된 계정이 다른 계정으로 바뀜 |
| 게스트 상태에서 로그인해 인증된 계정을 확인 |

### TC-SYNC-REFRESH-FEATURE-011: 주기 동기화는 진행을 표시하지 않는다

- 근거: `feature > 진행 표시`, `domain > 새로고침 계기`
- Given: 새로고침 대상 화면이 표시되어 있고 진행 중인 동기화와 진행 표시가 없다.
- When: 4시간 간격의 주기 동기화가 돌아와 실행된다.
- Then: 진행 표시가 나타나지 않는다.

### TC-SYNC-REFRESH-FEATURE-012: 같은 계정의 정보만 바뀌어 시작된 동기화는 진행을 표시하지 않는다

- 근거: `domain > 새로고침 계기`
- Given: 인증된 사용자 계정이 확인되어 그 계정의 동기화가 끝났고, 새로고침 대상 화면에 진행 표시가 없다.
- When: 같은 계정에 테스트 데이터의 변경만 일어나 서버 동기화가 시작되고 실행된다.
- Then: 진행 표시가 나타나지 않는다.
- 테스트 데이터:

| 변경 |
| --- |
| 이메일 변경 |
| 프로필 이미지 변경 |
| 로그인 세션이 인증되지 않은 것으로 확인되었다가 다시 인증됨 |

### TC-SYNC-REFRESH-FEATURE-005: 동기화가 끝나면 진행 표시가 사라진다

- 근거: `domain > 진행 표시 기준`
- Given: 새로고침 대상 화면에 진행 표시가 나타나 있다.
- When: 표시 대상 동기화가 성공 또는 실패로 끝난다.
- Then: 진행 표시가 사라진다.
- 테스트 데이터:

| 동기화 결과 |
| --- |
| 성공 |
| 실패 |

### TC-SYNC-REFRESH-FEATURE-006: 새로고침이 실패해도 표시 중인 내용은 유지된다

- 근거: `feature > 당겨서 새로고침`
- Given: 새로고침 대상 화면에 메모 또는 태그가 표시되어 있다.
- When: 사용자가 당겨서 요청한 동기화가 실패한다.
- Then: 화면에 표시되던 내용이 그대로 유지되고 실패 안내가 표시되지 않는다.

### TC-SYNC-REFRESH-FEATURE-007: 진행 표시 중에도 화면 조작을 계속할 수 있다

- 근거: `feature > 진행 표시`
- Given: 새로고침 대상 화면에 진행 표시가 나타나 있고 목록에 항목이 표시되어 있다.
- When: 사용자가 항목을 선택하거나 완료 또는 삭제한다.
- Then: 진행 표시가 없을 때와 같은 결과가 발생한다.

### TC-SYNC-REFRESH-FEATURE-008: 로그인하지 않은 상태에서 당기면 서버 동기화도 진행 표시도 없다

- 근거: `feature > 로그인하지 않은 상태`
- Given: 테스트 데이터의 계정 상태로 CalendarHome을 제외한 새로고침 대상 화면이 표시되어 있다.
- When: 사용자가 화면을 당겨 새로고침을 요청한다.
- Then: 계정 데이터 서버 동기화가 요청되지 않고 진행 표시가 나타나지 않는다.
- 테스트 데이터:

| 계정 상태 |
| --- |
| 로그인하지 않음 |
| 로그인한 계정이 있지만 로그인 정보가 확인되지 않았거나 더 이상 유효하지 않음 |

### TC-SYNC-REFRESH-FEATURE-010: PlaceHome에서는 장소 목록 영역에서만 당김이 시작된다

- 근거: `feature > 새로고침 대상 화면`
- Given: 인증된 사용자 계정이 확인된 상태로 PlaceHome이 표시되어 있고 진행 중인 동기화가 없다.
- When: 사용자가 테스트 데이터의 영역을 아래로 당긴다.
- Then: 장소 목록 영역을 당긴 경우에만 계정 데이터 서버 동기화가 요청되고 진행 표시가 나타난다.
- 테스트 데이터:

| 당긴 영역 | 기대 결과 |
| --- | --- |
| 장소 목록 영역 | 동기화 요청, 진행 표시 |
| 지도 영역 | 동기화 요청 없음, 진행 표시 없음 |

- 작성하지 않는 이유: 지도 영역의 당김 결과는 지도 제공자의 실제 표시 요소가 있어야 판정할 수 있어 현재 호스트 테스트 환경에서 결정적으로 구성할 수 없다. 장소 목록 영역의 당김은 [PlaceHome 테스트 케이스](./place-home.md)에서 자동화한다.

### TC-SYNC-REFRESH-FEATURE-009: 로그인하지 않은 상태에서도 공휴일과 날씨는 다시 가져온다

- 근거: `feature > 로그인하지 않은 상태`
- Given: 로그인하지 않은 상태로 CalendarHome이 표시되어 있고 진행 중인 공휴일·날씨 동기화가 없다.
- When: 사용자가 화면을 당겨 새로고침을 요청한다.
- Then: 표시 중인 달의 공휴일 동기화와 현재 위치의 날씨 동기화가 요청되고, 실행되는 동안 진행 표시가 나타난다.

## domain

### TC-SYNC-REFRESH-DOMAIN-001: 실행되지 않고 기다리는 동안에는 진행을 표시하지 않는다

- 근거: `domain > 진행 표시 기준`
- Given: 새로고침 대상 화면이 표시되어 있고 요청된 동기화 작업이 아직 실행되지 않고 대기 중이다.
- When: 사용자가 당기거나 계정 확인 계기로 동기화가 요청된다.
- Then: 진행 표시가 나타나지 않는다.

### TC-SYNC-REFRESH-DOMAIN-002: 기다리던 작업이 실행되기 시작하면 그때부터 진행을 표시한다

- 근거: `domain > 진행 표시 기준`
- Given: 표시 대상 동기화가 요청되었으나 실행되지 않고 대기 중이어서 진행 표시가 없다.
- When: 대기 중이던 동기화 작업이 실행되기 시작한다.
- Then: 진행 표시가 나타난다.

### TC-SYNC-REFRESH-DOMAIN-003: 대상 중 하나라도 실행 중이면 진행을 표시한다

- 근거: `domain > 진행 표시 기준`
- Given: CalendarHome이 표시되어 있고 새로고침 대상 중 일부만 실행 중이다.
- When: 실행 중인 동기화가 남아 있다.
- Then: 진행 표시가 유지된다.
- 테스트 데이터:

| 실행 중인 대상 |
| --- |
| 계정 데이터 서버 동기화만 |
| 공휴일 동기화만 |
| 날씨 동기화만 |
| 세 대상 모두 |

### TC-SYNC-REFRESH-DOMAIN-004: 모든 대상이 끝나면 진행 표시를 해제한다

- 근거: `domain > 진행 표시 기준`
- Given: CalendarHome이 표시되어 있고 새로고침 대상 세 가지가 모두 실행 중이어서 진행 표시가 나타나 있다.
- When: 세 대상이 모두 성공 또는 실패로 끝난다.
- Then: 진행 표시가 사라진다.

### TC-SYNC-REFRESH-DOMAIN-005: 표시 대상 동기화 중 진행을 표시하지 않는 계기가 생겨도 진행 표시를 유지한다

- 근거: `domain > 진행 표시 유지`
- Given: 표시 대상 계정 데이터 서버 동기화가 실행 중이어서 진행 표시가 나타나 있다.
- When: 테스트 데이터의 계기로 진행 중인 동기화가 취소되고 새 동기화가 시작되어 실행된다.
- Then: 진행 표시가 해제되지 않고 이어진 동기화가 끝날 때까지 유지된다.
- 테스트 데이터:

| 계기 |
| --- |
| 사용자가 메모나 태그를 변경 |
| 이미 확인된 같은 계정의 이메일·프로필 이미지·로그인 세션 인증 여부만 바뀜 |

### TC-SYNC-REFRESH-DOMAIN-006: 이어진 동기화가 끝난 뒤의 변경 계기는 표시하지 않는다

- 근거: `domain > 진행 표시 유지`
- Given: 표시 대상 동기화가 이어져 끝나 진행 표시가 사라진 상태다.
- When: 사용자가 메모나 태그를 변경해 새 서버 동기화가 시작되고 실행된다.
- Then: 진행 표시가 나타나지 않는다.

### TC-SYNC-REFRESH-DOMAIN-007: 공휴일과 날씨 동기화는 계기와 무관하게 진행을 표시한다

- 근거: `domain > 새로고침 계기`
- Given: CalendarHome이 표시되어 있고 진행 중인 공휴일·날씨 동기화가 없다.
- When: 화면이 표시되거나 표시 중인 달이 바뀌어 공휴일 동기화 또는 날씨 동기화가 시작되고 실행된다.
- Then: 진행 표시가 나타난다.

### TC-SYNC-REFRESH-DOMAIN-015: 위치 권한 허용으로 시작한 날씨 동기화도 끝날 때까지 진행을 표시한다

- 근거: `domain > 새로고침 계기`
- Given: CalendarHome이 표시되어 있고, 날씨 동기화의 진행 상태가 테스트 데이터와 같다.
- When: 사용자가 위치 권한 요청에서 새로 허용한다.
- Then: 진행 표시가 나타나고, 위치 권한 허용 계기의 날씨 동기화가 끝난 뒤에 해제된다.
- 테스트 데이터:

  | 허용 시점의 상태 | 진행 표시가 해제되는 시점 |
  | --- | --- |
  | 진행 중인 날씨 동기화가 없다 | 위치 권한 허용 계기의 날씨 동기화가 끝난 뒤 |
  | 날씨 동기화가 진행 중이다 | 진행 중이던 동기화에 이어 한 번 더 받는 날씨 동기화가 끝난 뒤 |

### TC-SYNC-REFRESH-DOMAIN-008: 진행 중인 공휴일·날씨 동기화가 있으면 당김은 새 동기화를 시작하지 않는다

- 근거: `domain > 중복 요청 처리`
- Given: CalendarHome이 표시되어 있고 공휴일 동기화 또는 날씨 동기화가 진행 중이다.
- When: 사용자가 화면을 당겨 새로고침을 요청한다.
- Then: 진행 중인 종류의 새 동기화가 시작되지 않고 진행 표시는 이어진다.

### TC-SYNC-REFRESH-DOMAIN-009: 당김은 진행 중인 서버 동기화를 취소하고 새로 시작한다

- 근거: `domain > 중복 요청 처리`
- Given: 계정 데이터 서버 동기화가 진행 중이다.
- When: 사용자가 화면을 당겨 새로고침을 요청한다.
- Then: 진행 중이던 서버 동기화가 취소되고 새 서버 동기화가 시작되며 진행 표시는 이어진다.

### TC-SYNC-REFRESH-DOMAIN-010: 화면이 재생성되면 그 시점의 실행 여부로 진행 표시를 다시 정한다

- 근거: `domain > 실행 경계`
- Given: 표시 대상 동기화의 실행 여부가 테스트 데이터로 주어진다.
- When: 새로고침 대상 화면이 재생성되어 다시 표시된다.
- Then: 실행 중이면 진행 표시가 나타나고, 실행 중이 아니면 나타나지 않는다.
- 테스트 데이터:

| 재생성 시점의 실행 여부 | 진행 표시 |
| --- | --- |
| 표시 대상 동기화가 실행 중 | 표시 |
| 실행 중인 동기화 없음 | 표시하지 않음 |
| 표시 대상이 아닌 동기화만 실행 중 | 표시하지 않음 |

### TC-SYNC-REFRESH-DOMAIN-013: 한 화면에서 당겨 시작한 동기화는 다른 새로고침 대상 화면에서도 진행이 이어서 표시된다

- 근거: `domain > 진행 표시 기준`
- Given: 한 새로고침 대상 화면에서 당겨 시작한 계정 데이터 서버 동기화가 실행 중이어서 진행 표시가 나타나 있다.
- When: 사용자가 다른 새로고침 대상 화면으로 옮겨 간다.
- Then: 옮겨 간 화면에 진행 표시가 나타난다.

### TC-SYNC-REFRESH-DOMAIN-014: 다른 화면에 다녀오면 돌아온 시점의 실행 여부로 진행 표시를 다시 정한다

- 근거: `domain > 실행 경계`
- Given: 새로고침 대상 화면에서 떠나 있는 동안 동기화의 실행 여부가 테스트 데이터처럼 바뀌었다.
- When: 사용자가 그 화면으로 돌아온다.
- Then: 테스트 데이터의 진행 표시 결과가 된다.
- 테스트 데이터:

| 돌아온 시점의 실행 여부 | 진행 표시 |
| --- | --- |
| 떠나기 전부터 실행 중이던 표시 대상 동기화가 아직 실행 중 | 표시 |
| 떠나 있는 동안 표시 대상 동기화가 끝남 | 표시하지 않음 |
| 표시 대상이 아닌 동기화만 실행 중 | 표시하지 않음 |

### TC-SYNC-REFRESH-DOMAIN-011: 앱을 다시 실행하면 표시 대상 여부가 초기화된다

- 근거: `domain > 실행 경계`
- Given: 앱을 다시 실행해 표시 대상 여부가 초기화된 상태이고, 앱을 종료하기 전 실행에서 시작된 동기화가 계속 실행되고 있다.
- When: 앱을 다시 실행해 새로고침 대상 화면이 표시되고 아직 사용자 계정이 확인되지 않았다.
- Then: 진행 표시가 나타나지 않는다.

### TC-SYNC-REFRESH-DOMAIN-012: 앱을 다시 실행해 계정을 확인하면 표시 대상이 된다

- 근거: `domain > 실행 경계`
- Given: 앱을 다시 실행해 새로고침 대상 화면이 표시되어 있고 진행 표시가 없다.
- When: 앱이 인증된 사용자 계정을 확인해 서버 동기화가 시작되고 실행된다.
- Then: 진행 표시가 나타난다.

## 작성하지 않는 이유

- 진행 표시의 위치, 크기, 색, 회전 모션과 당김 임계값은 시각 판단이 필요해 결정적으로 판정할 수 없다. 표현 기준은 [새로고침 디자인](../design/sync-refresh.md)에서 관리한다. 실제 화면을 캡처해 기준 이미지와 비교하고 당김 제스처의 이동 거리를 기기에서 재현할 수 있는 테스트 환경이 갖춰지면 작성한다.
