## 작성하지 않는 이유

- 교체 실패 시 기존 공휴일을 유지하는 동작은 지우기를 마친 뒤 새로 저장하는 도중에 실제 저장소의 쓰기를 실패시켜야 확인할 수 있어 작성하지 않는다. 저장 도중의 쓰기 실패를 주입할 수 있는 저장소 테스트 환경이 갖춰지면 자동화한다.
- 기기에 저장한 공휴일이 사용자 계정과 무관해 로그인, 로그아웃, 계정 전환에도 그대로 남는 결과는, 공휴일 저장과 조회에 계정 구분이 없어 이 문서의 범위에서는 계정 전환을 일으킬 수 없으므로 작성하지 않는다. 로그인 상태 전환과 기기 저장을 함께 실행하는 통합 테스트 환경이 갖춰지면 자동화한다.
- Android, iOS, 데스크톱 앱에서 저장한 공휴일이 앱을 다시 실행해도 남아 있고 웹에서는 페이지를 새로 열면 비워지는 결과는, 앱 프로세스를 다시 시작하거나 웹 페이지를 새로 열어 플랫폼별 실제 저장소를 다시 열어야 확인할 수 있어 작성하지 않는다. 플랫폼별 저장소를 닫았다가 다시 여는 실행 경계를 제어할 수 있는 테스트 환경이 갖춰지면 자동화한다.
