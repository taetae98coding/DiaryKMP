# ContactAdd 테스트 케이스

기준 스펙: [ContactAdd 화면 스펙](../spec/contact-add.md)

이 문서에서 `data > 저장 실패`, `domain > 추가 요청 제한`, `domain > 항목의 계정 연결`, `feature > 작성 상태 유지` 절은 [항목 추가 화면 공통 스펙](../spec/entity-add.md)이 소유한다. 나머지 케이스의 절은 기준 스펙이 소유한다.

ContactHome에서 연락처 추가를 선택해 ContactAdd로 이동하는 케이스는 [ContactHome 테스트 케이스](./contact-home.md)에서 다룬다. 설명 입력 자체의 케이스는 [설명 입력 테스트 케이스](./description-input.md)에서 다룬다.

## feature

### TC-CONTACT-ADD-FEATURE-001: 화면에 처음 진입하면 입력이 모두 비어 있다

- 근거: `feature > 진입과 입력`
- Given: 사용자가 연락처 추가를 선택했다.
- When: ContactAdd 화면이 처음 표시된다.
- Then: 이름, 설명, 키, 신발 사이즈, 고향이 비어 있고 생일을 고르지 않았으며 전화번호 항목이 하나도 없다.

### TC-CONTACT-ADD-FEATURE-002: 이름과 설명을 입력할 수 있다

- 근거: `feature > 진입과 입력`
- Given: ContactAdd 화면이 표시되어 있다.
- When: 사용자가 이름과 설명을 입력한다.
- Then: 입력한 이름과 설명이 화면에 그대로 표시된다.

### TC-CONTACT-ADD-FEATURE-028: 고향을 입력하고 지울 수 있다

- 근거: `feature > 고향 입력`
- Given: ContactAdd 화면이 표시되어 있다.
- When: 사용자가 고향을 입력한 뒤 지우기를 실행한다.
- Then: 입력한 고향이 그대로 표시되었다가 비어 있는 상태로 되돌아간다.

### TC-CONTACT-ADD-FEATURE-029: 고향은 입력한 문자를 그대로 반영한다

- 근거: `feature > 고향 입력`
- Given: ContactAdd 화면이 표시되어 있다.
- When: 사용자가 테스트 데이터의 값을 고향에 입력한다.
- Then: 입력한 값이 그대로 표시되고 오류 안내나 반영되지 않는 문자가 없다.
- 테스트 데이터:

| 입력값 |
| --- |
| `서울` |
| `강원도 춘천시` |
| `Seoul, Korea` |
| `123-!@#` |

### TC-CONTACT-ADD-FEATURE-003: 전화번호 항목을 추가해 번호를 입력할 수 있다

- 근거: `feature > 전화번호 입력`
- Given: ContactAdd 화면이 표시되어 있다.
- When: 사용자가 전화번호 항목을 추가하고 번호를 입력한다.
- Then: 추가한 전화번호 항목이 마지막 자리에 나타나고 입력한 번호가 그대로 표시된다.

### TC-CONTACT-ADD-FEATURE-004: 전화번호 항목을 삭제해도 다른 입력은 유지된다

- 근거: `feature > 전화번호 입력`
- Given: 이름과 설명을 입력하고 전화번호 항목을 두 개 이상 입력한 ContactAdd 화면이 표시되어 있다.
- When: 사용자가 전화번호 항목 하나를 삭제한다.
- Then: 삭제한 전화번호 항목만 사라지고 남은 전화번호 항목의 번호·순서와 이름, 설명은 그대로 유지된다.

### TC-CONTACT-ADD-FEATURE-005: 추가에 성공하면 다음 연락처를 작성할 수 있는 상태로 초기화한다

- 근거: `feature > 연락처 추가`
- Given: 연락처 추가가 성공하도록 설정되어 있고, 이름, 설명, 키, 신발 사이즈, 생일과 전화번호 항목을 입력한 상태다.
- When: 사용자가 연락처 추가를 실행한다.
- Then: ContactAdd 화면이 유지되고 이름, 설명, 키, 신발 사이즈가 비워지며 생일이 고르지 않은 상태로 되돌아가고 전화번호 항목이 하나도 남지 않는다.

### TC-CONTACT-ADD-FEATURE-007: 추가에 성공하면 성공 피드백을 제공한다

- 근거: `feature > 연락처 추가`
- Given: 연락처 추가가 성공하도록 설정되어 있고, 공백이 아닌 이름이 입력되어 있다.
- When: 사용자가 연락처 추가를 실행한다.
- Then: 연락처가 추가되었다는 성공 피드백이 제공된다.

### TC-CONTACT-ADD-FEATURE-008: 추가를 처리하는 동안 진행 상태를 표시한다

- 근거: `feature > 연락처 추가`
- Given: 연락처 추가 처리가 완료되지 않고 진행 중인 상태로 설정되어 있고, 공백이 아닌 이름이 입력되어 있다.
- When: 사용자가 연락처 추가를 실행한 뒤 화면을 확인한다.
- Then: 추가 처리가 끝날 때까지 진행 상태가 표시된다.

### TC-CONTACT-ADD-FEATURE-009: 성립하지 않는 입력으로 추가하면 필요한 입력을 알린다

- 근거: `feature > 이름 미입력`, `feature > 전화번호 미입력`
- Given: ContactAdd 화면에 테스트 데이터의 입력 상태가 만들어져 있다.
- When: 사용자가 연락처 추가를 실행한다.
- Then: 연락처가 추가되지 않고 테스트 데이터의 피드백이 제공된다.
- 테스트 데이터:

| 입력 상태 | 피드백 |
| --- | --- |
| 이름이 비어 있음 | 이름 입력이 필요함 |
| 이름이 공백 문자로만 이루어짐 | 이름 입력이 필요함 |
| 번호가 비어 있는 전화번호 항목이 있음 | 전화번호 입력이 필요함 |
| 번호가 공백 문자로만 이루어진 전화번호 항목이 있음 | 전화번호 입력이 필요함 |

### TC-CONTACT-ADD-FEATURE-010: 이름 미입력 안내 뒤에도 입력 중이던 내용을 유지한다

- 근거: `feature > 이름 미입력`
- Given: 이름이 비어 있고 설명, 키, 신발 사이즈, 생일과 전화번호 항목을 입력한 상태다.
- When: 사용자가 연락처 추가를 실행한다.
- Then: 입력한 설명, 키, 신발 사이즈, 생일과 전화번호 항목이 그대로 유지된다.

### TC-CONTACT-ADD-FEATURE-011: 전화번호 미입력 안내 뒤에도 입력 중이던 내용을 유지한다

- 근거: `feature > 전화번호 미입력`
- Given: 공백이 아닌 이름과 설명을 입력했고 번호가 비어 있는 전화번호 항목이 있다.
- When: 사용자가 연락처 추가를 실행한다.
- Then: 입력한 이름, 설명과 전화번호 항목이 모두 그대로 유지된다.

### TC-CONTACT-ADD-FEATURE-012: 화면이 재생성되어도 작성 중이던 내용을 유지한다

- 근거: `feature > 작성 상태 유지`
- Given: 이름, 설명, 키, 신발 사이즈, 생일과 전화번호 항목을 입력한 상태다.
- When: 화면이 재생성된다.
- Then: 이름, 설명, 키, 신발 사이즈, 고른 생일과 전화번호 항목의 번호·순서가 그대로 유지된다.

### TC-CONTACT-ADD-FEATURE-013: 화면에 처음 진입하면 이름 입력에 초점이 있다

- 근거: `feature > 진입과 입력`
- Given: 사용자가 연락처 추가를 선택했다.
- When: ContactAdd 화면이 처음 표시된다.
- Then: 입력 초점이 이름 입력에 있다.

### TC-CONTACT-ADD-FEATURE-014: 전화번호 항목을 추가하거나 삭제해도 초점을 옮기지 않는다

- 근거: `feature > 전화번호 입력`
- Given: 이름 입력에 초점이 있는 ContactAdd 화면이 표시되어 있다.
- When: 사용자가 전화번호 항목을 추가하거나 삭제한다.
- Then: 입력 초점이 이름 입력에 그대로 있다.

### TC-CONTACT-ADD-FEATURE-015: 추가에 성공하면 이름 입력으로 초점을 옮긴다

- 근거: `feature > 연락처 추가`
- Given: 연락처 추가가 성공하도록 설정되어 있고, 공백이 아닌 이름이 입력되어 있다.
- When: 사용자가 연락처 추가를 실행한다.
- Then: 입력 초점이 이름 입력으로 옮겨진다.

### TC-CONTACT-ADD-FEATURE-016: 미입력 안내에 따라 초점을 옮기거나 그대로 둔다

- 근거: `feature > 이름 미입력`, `feature > 전화번호 미입력`

| 입력 상태 | 초점 |

| 이름이 비어 있음 | 이름 입력 |
| 번호가 비어 있는 전화번호 항목이 있음 | 실행 전에 보고 있던 입력 |

### TC-CONTACT-ADD-FEATURE-017: 키와 신발 사이즈를 입력할 수 있다

- 근거: `feature > 키와 신발 사이즈 입력`

- Then: 입력한 키와 신발 사이즈가 화면에 그대로 표시된다.

### TC-CONTACT-ADD-FEATURE-018: 키와 신발 사이즈는 정한 문자와 자리 수만 반영한다

- When: 사용자가 테스트 데이터의 값을 그 입력에 입력한다.

### TC-CONTACT-ADD-FEATURE-019: 생일을 골라 지정할 수 있다

- 근거: `feature > 생일 입력`
- Given: 생일을 고르지 않은 ContactAdd 화면이 표시되어 있다.

### TC-CONTACT-ADD-FEATURE-020: 생일 고르기를 취소하면 이전 상태를 유지한다

- 근거: `feature > 생일 입력`
- Given: 생일을 고르지 않은 ContactAdd 화면이 표시되어 있다.
- When: 사용자가 생일 고르기를 열어 취소한다.
- Then: 생일이 고르지 않은 상태로 그대로 남는다.

### TC-CONTACT-ADD-FEATURE-021: 고른 생일을 지울 수 있다

- 근거: `feature > 생일 입력`
- Given: 생일을 고른 ContactAdd 화면이 표시되어 있다.
- When: 사용자가 생일 지우기를 선택한다.
- Then: 생일이 고르지 않은 상태로 되돌아가고 지우기 수단이 사라진다.

### TC-CONTACT-ADD-FEATURE-022: 생일을 고르면 달력 구분이 양력으로 시작한다

- 근거: `feature > 생일 입력`
- Given: 생일을 고르지 않은 ContactAdd 화면이 표시되어 있다.
- When: 사용자가 생일 고르기를 열어 날짜를 고르고 확인한다.
- Then: 달력 구분을 고르는 수단이 나타나고 양력이 골라진 상태로 표시된다.

### TC-CONTACT-ADD-FEATURE-023: 고른 생일의 달력 구분을 바꿀 수 있다

- 근거: `feature > 생일 입력`
- Given: 생일을 골라 테스트 데이터의 현재 구분이 골라져 있다.
- When: 사용자가 테스트 데이터의 구분을 선택한다.
- Then: 선택한 구분이 골라진 상태로 표시되고 표시된 생일 날짜는 바뀌지 않는다.
- 테스트 데이터:

| 현재 구분 | 선택한 구분 |
| --- | --- |
| 양력 | 음력 |
| 음력 | 양력 |

### TC-CONTACT-ADD-FEATURE-024: 생일을 지우면 달력 구분을 고르는 수단도 사라진다

- 근거: `feature > 생일 입력`

### TC-CONTACT-ADD-FEATURE-025: 생일을 지운 뒤 다시 고르면 달력 구분이 양력으로 시작한다

- 근거: `feature > 생일 입력`

### TC-CONTACT-ADD-FEATURE-026: 화면이 재생성되어도 고른 달력 구분을 유지한다

- 근거: `feature > 작성 상태 유지 대상`
- Given: 생일을 골라 음력으로 바꾼 ContactAdd 화면이 표시되어 있다.

- Then: 고른 생일 날짜와 음력 구분이 그대로 유지된다.

### TC-CONTACT-ADD-FEATURE-027: 생일 날짜만 다시 골라도 달력 구분은 유지된다

- 근거: `feature > 생일 입력`
- Given: 생일을 골라 음력으로 바꾼 ContactAdd 화면이 표시되어 있다.
- When: 사용자가 생일 고르기를 열어 다른 날짜를 고르고 확인한다.
- Then: 고른 새 날짜가 생일로 표시되고 달력 구분이 음력으로 그대로 유지된다.

## domain

### TC-CONTACT-ADD-DOMAIN-001: 이름이 없으면 연락처를 추가하지 않는다

- 근거: `domain > 추가 성립 조건`
- Given: 이름이 테스트 데이터의 값이다.
- When: 연락처 추가를 실행한다.
- Then: 연락처가 저장되지 않고 이름이 필요하다는 실패가 전달된다.
- 테스트 데이터:

| 이름 |
| --- |
| 빈 문자열 |
| 공백 문자로만 이루어진 문자열 |

### TC-CONTACT-ADD-DOMAIN-002: 번호가 없는 전화번호 항목이 있으면 연락처를 추가하지 않는다

- 근거: `domain > 추가 성립 조건`
- Given: 공백이 아닌 이름과 번호가 비어 있는 전화번호 항목이 하나 이상 있다.
- When: 연락처 추가를 실행한다.
- Then: 연락처가 저장되지 않고 전화번호가 필요하다는 실패가 전달된다.

### TC-CONTACT-ADD-DOMAIN-003: 이름과 전화번호가 함께 성립하지 않으면 이름을 먼저 알린다

- 근거: `domain > 추가 성립 조건`
- Given: 이름이 비어 있고 번호가 비어 있는 전화번호 항목도 있다.
- When: 연락처 추가를 실행한다.
- Then: 이름이 필요하다는 실패만 전달된다.

### TC-CONTACT-ADD-DOMAIN-004: 설명과 전화번호가 비어 있어도 연락처를 추가한다

- 근거: `domain > 추가 성립 조건`
- Given: 공백이 아닌 이름만 입력되어 있고 설명이 비어 있으며 전화번호 항목이 하나도 없다.
- When: 연락처 추가를 실행한다.
- Then: 연락처가 저장된다.

### TC-CONTACT-ADD-DOMAIN-005: 같은 번호를 여러 개 입력해도 모두 각각 기록한다

- 근거: `domain > 전화번호`
- Given: 공백이 아닌 이름과 번호가 같은 전화번호 항목이 두 개 있다.
- When: 연락처 추가를 실행한다.
- Then: 두 전화번호가 모두 입력한 순서대로 기록된다.

### TC-CONTACT-ADD-DOMAIN-008: 처리 중에는 같은 화면의 추가 요청을 처리하지 않는다

- 근거: `domain > 추가 요청 제한`
- Given: 연락처 추가 처리가 진행 중이다.
- When: 사용자가 연락처 추가를 다시 실행한다.
- Then: 추가 요청이 한 번만 처리된다.

### TC-CONTACT-ADD-DOMAIN-009: 새 연락처에 사용자가 입력한 내용을 기록한다

- 근거: `domain > 추가되는 연락처의 내용`
- Given: 공백이 아닌 이름과 설명, 키, 신발 사이즈, 생일, 전화번호 항목을 입력했다.
- When: 연락처 추가를 실행한다.
- Then: 다른 연락처와 겹치지 않는 식별자를 가진 연락처가 입력한 이름, 설명, 키, 신발 사이즈, 생일, 고향과 전화번호를 배치한 순서대로 담아 삭제되지 않은 상태로 저장되고, 생성 시각과 수정 시각이 같게 기록된다.

### TC-CONTACT-ADD-DOMAIN-010: 설명을 입력하지 않으면 빈 설명으로 기록한다

- 근거: `domain > 추가되는 연락처의 내용`

- 근거: `domain > 항목의 계정 연결`
- Given: 현재 계정 조회가 실패하도록 설정되어 있고 공백이 아닌 이름이 입력되어 있다.

- Then: 연락처가 저장되지 않고 계정 조회의 실패가 그대로 전달된다.

### TC-CONTACT-ADD-DOMAIN-012: 키, 신발 사이즈, 생일, 고향을 비워도 연락처를 추가한다

### TC-CONTACT-ADD-DOMAIN-017: 고향은 형식을 검사하지 않고 그대로 기록한다

### TC-CONTACT-ADD-DOMAIN-018: 새 연락처는 즐겨찾기가 아닌 상태로 추가된다

- 근거: `domain > 즐겨찾기`, `domain > 추가되는 연락처의 내용`

- Then: 저장된 연락처의 즐겨찾기 여부가 즐겨찾기가 아닌 값으로 기록된다.
