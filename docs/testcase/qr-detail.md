# QrDetail 테스트 케이스

기준 스펙: [QrDetail 화면 스펙](../spec/client/qr-detail.md)

입력과 탭, 포맷별 입력, QR 스캔과 되돌리기의 세부 규칙은 [QrAdd 화면 스펙](../spec/client/qr-add.md)을 따르므로 [QrAdd 테스트 케이스](./qr-add.md)가 검증한다. 이 문서는 그 규칙이 이 화면에서 저장된 QR에서 시작하는 결과와, 이 화면에만 있는 수정·삭제를 확인한다. 진입할 때의 입력 초점, 내용 수정의 반영과 요청 제한은 [항목 상세 화면 공통 스펙](../spec/client/entity-detail.md)이 정한 규칙을 이 화면에 적용한 결과로 확인한다.

## feature

### TC-QR-DETAIL-FEATURE-001: 조회에 성공하면 저장된 내용으로 화면을 채운다

- 근거: `feature > 진입과 내용`, `feature > 입력과 탭`, `domain > 입력 내용 채우기`
- Given: 현재 계정에 제목 `회사`, 설명 `출입용`, QR 값이 테스트 데이터의 값인 QR이 저장되어 있다.
- When: 그 QR의 QrDetail 화면이 표시된다.
- Then: 화면 제목에 `회사`가 표시되고, 정보 탭이 선택되어 제목 입력에 `회사`, 설명 입력에 `출입용`이 채워지며, QR 그림 자리에 그 QR 값을 담은 QR이 그려진다. QR 탭으로 바꾸면 테스트 데이터의 포맷이 선택되어 있고 그 포맷의 입력이 테스트 데이터의 내용으로 채워져 있다. 되돌리기는 선택할 수 없다.
- 테스트 데이터:

  | QR 값 | 포맷 | 입력 내용 |
  | --- | --- | --- |
  | `hello` | 텍스트 | 내용 `hello` |
  | `https://example.com` | URL | URL `https://example.com` |
  | `WIFI:T:WPA;S:home;P:pw;;` | Wi-Fi | 네트워크 이름 `home`, 보안 방식 `WPA/WPA2/WPA3`, 비밀번호 `pw` |
  | `tel:010` | 전화 | 전화번호 `010` |
  | `geo:37.5665,126.978` | 위치 | 위도 `37.5665`, 경도 `126.978` |

### TC-QR-DETAIL-FEATURE-002: 진입할 때 어느 입력에도 초점을 두지 않는다

- 근거: `feature > 입력과 탭`, [항목 상세 화면 공통 스펙](../spec/client/entity-detail.md)의 `진입할 때의 입력 초점`
- Given: 현재 계정에 QR이 저장되어 있다.
- When: 그 QR의 QrDetail 화면이 표시되고 조회가 끝난다.
- Then: 제목 입력, 설명 입력과 포맷 입력 중 어느 것에도 입력 초점이 없다.

### TC-QR-DETAIL-FEATURE-003: 조회 중에는 입력과 동작을 실행할 수 없다

- 근거: `feature > 조회 상태`
- Given: QR 조회가 아직 끝나지 않았다.
- When: 사용자가 QrDetail 화면을 확인한다.
- Then: 조회 중 상태가 표시되고, 입력, 탭, 되돌리기, QR 스캔 시작, 수정과 삭제를 선택할 수 없다. 뒤로가기는 선택할 수 있다.

### TC-QR-DETAIL-FEATURE-004: 조회할 수 없으면 조회 중 상태를 유지한다

- 근거: `feature > 조회 상태`
- Given: 테스트 데이터의 이유로 대상 QR을 조회할 수 없다.
- When: QrDetail 화면이 표시된다.
- Then: 조회 중 상태가 계속 표시되고, 별도의 오류 안내는 표시되지 않는다.
- 테스트 데이터:

  | 이유 |
  | --- |
  | 현재 계정과 연결된 그 QR이 기기에 없음 |
  | 현재 계정을 확인할 수 없음 |
  | 조회에 실패함 |

### TC-QR-DETAIL-FEATURE-005: 화면에는 정해진 탭, 입력과 동작만 둔다

- 근거: `feature > 화면 내용`
- Given: 저장된 QR의 QrDetail 화면에 내용이 표시되어 있고, 입력이 저장 내용과 다르다.
- When: 사용자가 화면을 확인한다.
- Then: 화면에는 화면 제목, 뒤로가기, 삭제, 되돌리기, QR 그림, 정보 탭과 QR 탭, QR 스캔 시작과 수정만 있고, 정보 탭에는 제목 입력과 설명 입력이, QR 탭에는 포맷 선택과 선택한 포맷의 입력이 있다. 태그 입력은 없다.

### TC-QR-DETAIL-FEATURE-006: 입력이 저장된 내용과 다를 때만 수정 동작을 제공한다

- 근거: `feature > 내용 수정`, `domain > 수정 동작의 제공 기준`
- Given: 제목 `회사`, 설명 `출입용`, QR 값 `hello`인 QR의 QrDetail 화면에 내용이 표시되어 있다.
- When: 사용자가 테스트 데이터의 조작을 한다.
- Then: 수정 동작의 제공 여부가 테스트 데이터의 기대 결과와 같다.
- 테스트 데이터:

  | 조작 | 수정 동작 |
  | --- | --- |
  | 아무것도 바꾸지 않음 | 제공하지 않음 |
  | 제목을 `회사2`로 바꿈 | 제공함 |
  | 설명을 `출입용 ` (끝에 공백)으로 바꿈 | 제공함 |
  | 텍스트 포맷의 내용을 `hello!`로 바꿈 | 제공함 |
  | 제목을 `회사2`로 바꾼 뒤 다시 `회사`로 바꿈 | 제공하지 않음 |
  | QR 탭에서 포맷을 URL로 바꾸기만 함 | 제공하지 않음 |
  | 텍스트 포맷의 내용을 모두 지움 | 제공함 |

### TC-QR-DETAIL-FEATURE-007: 수정에 성공하면 화면과 입력을 유지하고 성공 피드백을 제공한다

- 근거: `feature > 내용 수정`
- Given: 사용자 언어가 한국어이고, 수정 저장이 성공하도록 설정되어 있으며, 제목 `회사`, QR 값 `hello`인 QR의 QrDetail 화면에서 제목을 `학교`로 바꾸고, 텍스트 포맷의 `hello`를 Wi-Fi 포맷에서 네트워크 이름 `home`으로 새로 써 QR 탭을 보고 있다.
- When: 사용자가 수정을 실행한다.
- Then: QrDetail 화면이 유지되고 `QR이 수정되었습니다.` 피드백이 제공되며, 화면 제목이 `학교`로 바뀐다. QR 탭과 Wi-Fi 포맷, 네트워크 이름 `home`은 그대로이고, 되돌리기를 선택하면 텍스트 포맷의 `hello`로 돌아간다.

### TC-QR-DETAIL-FEATURE-008: 수정을 처리하는 동안 진행 상태를 표시한다

- 근거: `feature > 내용 수정`, [항목 상세 화면 공통 스펙](../spec/client/entity-detail.md)의 `내용 수정`
- Given: 입력이 저장 내용과 다르고, 수정 저장이 끝나지 않도록 설정되어 있다.
- When: 사용자가 수정을 실행한다.
- Then: 수정 동작에 진행 상태가 표시되고, 그동안에도 입력, 탭, 되돌리기, QR 스캔 시작과 삭제를 그대로 선택할 수 있다.

### TC-QR-DETAIL-FEATURE-009: 수정에 실패하면 안내 없이 입력을 유지하고 다시 시도할 수 있다

- 근거: `feature > 내용 수정`, [항목 상세 화면 공통 스펙](../spec/client/entity-detail.md)의 `내용 수정`
- Given: 수정 저장이 실패하도록 설정되어 있고, 제목 `회사`인 QR의 QrDetail 화면에서 제목을 `학교`로 바꿨다.
- When: 사용자가 수정을 실행한다.
- Then: 진행 상태가 해제되고 실패 안내와 성공 피드백은 표시되지 않으며, 제목 입력의 `학교`와 수정 동작이 그대로 남아 수정을 다시 실행할 수 있다. 화면 제목은 `회사` 그대로다.

### TC-QR-DETAIL-FEATURE-010: 제목을 비운 채 수정하면 기존 제목이 유지되고 수정 동작이 계속 제공된다

- 근거: `feature > 내용 수정`, `domain > 수정 성립 조건`, `domain > 수정 동작의 제공 기준`
- Given: 수정 저장이 성공하도록 설정되어 있고, 제목 `회사`, 설명 `출입용`인 QR의 QrDetail 화면에서 제목을 테스트 데이터의 값으로, 설명을 `정문`으로 바꿨다.
- When: 사용자가 수정을 실행한다.
- Then: 성공 피드백이 제공되고 화면 제목은 `회사`로 남으며, 제목 입력은 바꾼 값 그대로이고 수정 동작이 계속 제공된다.
- 테스트 데이터:

  | 제목 |
  | --- |
  | 비어 있음 |
  | 공백 두 칸 |

### TC-QR-DETAIL-FEATURE-011: QR 값이 비어 있으면 수정하지 않고 QR 탭에서 선택한 포맷의 첫 입력을 알린다

- 근거: `feature > QR 내용 미입력`
- Given: 사용자 언어가 한국어이고, QR 값 `https://example.com`인 QR의 QrDetail 화면에서 URL 포맷의 URL을 모두 지운 뒤 정보 탭으로 바꿔 제목을 `학교`로 바꿨다.
- When: 사용자가 수정을 실행한다.
- Then: QR이 수정되지 않고, QR 탭이 선택되며 `URL을 입력해 주세요.` 피드백이 제공되고 입력 초점이 URL 입력에 있다. 제목 입력의 `학교`와 URL 포맷은 그대로 남고, 화면 제목은 바뀌지 않는다.

### TC-QR-DETAIL-FEATURE-012: QrScan 화면에서 QR을 읽어 돌아오면 QR 값을 바꾸고 수정 동작을 제공한다

- 근거: `feature > QR 스캔`
- Given: QR 값 `hello`인 QR의 QrDetail 화면에서 정보 탭을 보고 있고, 사용자가 QrScan 화면으로 이동해 있다.
- When: QrScan 화면이 `https://example.com`을 담은 QR을 읽어 QrDetail 화면으로 돌아온다.
- Then: QR 탭과 URL 포맷이 선택되고 QR 그림 자리에 `https://example.com`을 담은 QR이 그려지며, 되돌리기를 선택할 수 있고 수정 동작이 제공된다. 저장된 QR은 바뀌지 않는다.

### TC-QR-DETAIL-FEATURE-013: 카메라 권한을 쓸 수 있으면 QrScan 화면으로 이동하고, 허용되지 않으면 안내를 표시한다

- 근거: `feature > QR 스캔`
- Given: 사용자 언어가 한국어이고, QrDetail 화면에 내용이 표시되어 있으며, 카메라 권한 요청 결과가 테스트 데이터의 결과로 정해져 있다.
- When: 사용자가 QR 스캔 시작을 선택한다.
- Then: 테스트 데이터의 결과가 나타나고, 입력 내용은 그대로 남는다.
- 테스트 데이터:

  | 요청 결과 | 결과 |
  | --- | --- |
  | 이미 허용 | QrScan 화면으로 이동하는 동작이 한 번 실행됨 |
  | 허용 | QrScan 화면으로 이동하는 동작이 한 번 실행됨 |
  | 거부 | 이동하지 않고 `카메라 권한을 허용해야 QR을 스캔할 수 있습니다.` 안내가 표시됨 |

### TC-QR-DETAIL-FEATURE-014: 되돌리기는 저장된 QR을 바꾸지 않고 입력만 되돌린다

- 근거: `feature > 되돌리기`
- Given: QR 값 `hello`인 QR의 QrDetail 화면에서 Wi-Fi 포맷의 네트워크 이름에 `home`을 입력해 새로 썼다.
- When: 사용자가 되돌리기를 선택한다.
- Then: QR 탭과 텍스트 포맷이 선택되고 QR 그림이 `hello`로 돌아가며, 수정 동작은 제공되지 않는다. 저장된 QR은 바뀌지 않는다.

### TC-QR-DETAIL-FEATURE-015: 삭제에 성공하면 QrHome 화면으로 돌아간다

- 근거: `feature > 삭제`
- Given: 삭제 저장이 성공하도록 설정되어 있고, 입력이 저장 내용과 다르며, 테스트 데이터의 탭을 보고 있다.
- When: 사용자가 삭제를 선택한다.
- Then: 확인을 묻지 않고 삭제가 실행되며, QrDetail 화면에서 빠져나가 QrHome 화면으로 돌아가는 동작이 한 번 실행된다.
- 테스트 데이터:

  | 탭 |
  | --- |
  | 정보 탭 |
  | QR 탭 |

### TC-QR-DETAIL-FEATURE-016: 삭제를 처리하는 동안 진행 상태를 표시한다

- 근거: `feature > 삭제`
- Given: 삭제 저장이 끝나지 않도록 설정되어 있다.
- When: 사용자가 삭제를 선택한다.
- Then: 삭제 동작에 진행 상태가 표시되고, 그동안에도 입력과 수정을 그대로 실행할 수 있다.

### TC-QR-DETAIL-FEATURE-017: 삭제에 실패하면 화면에 머무르고 다시 시도할 수 있다

- 근거: `feature > 삭제`
- Given: 삭제 저장이 실패하도록 설정되어 있다.
- When: 사용자가 삭제를 선택한다.
- Then: QrHome 화면으로 돌아가지 않고 진행 상태만 해제되며, 삭제를 다시 선택할 수 있다.

### TC-QR-DETAIL-FEATURE-018: 저장된 제목이 다른 경로에서 바뀌면 화면 제목만 갱신한다

- 근거: `feature > 외부 변경`, `domain > 입력 내용 채우기`
- Given: 제목 `회사`, QR 값 `hello`인 QR의 QrDetail 화면에서 제목을 `학교`로, 텍스트 포맷의 내용을 `hi`로 바꿨다.
- When: 같은 QR의 제목이 `본사`, QR 값이 `bye`로 다른 경로에서 저장된다.
- Then: 화면 제목이 `본사`로 바뀌고, 제목 입력의 `학교`, 내용 입력과 QR 그림의 `hi`는 그대로 남는다.

### TC-QR-DETAIL-FEATURE-019: 대상 QR이 삭제 상태가 되어도 내용 표시 상태를 유지한다

- 근거: `feature > 외부 변경`, `domain > 상세 대상과 내용 표시`
- Given: QrDetail 화면에 내용이 표시되어 있고 제목을 바꿔 수정 동작이 제공되고 있다.
- When: 같은 QR이 다른 경로에서 삭제 상태로 저장된다.
- Then: 화면이 내용 표시 상태를 유지하고 QrHome으로 돌아가지 않으며, 바꾼 제목과 수정 동작, 삭제가 그대로 남는다.

### TC-QR-DETAIL-FEATURE-020: 뒤로가면 수정하지 않은 채 QrHome 화면으로 돌아간다

- 근거: `feature > 뒤로가기`
- Given: QrDetail 화면에서 제목을 바꿨고 테스트 데이터의 탭을 보고 있다.
- When: 사용자가 뒤로가기를 선택한다.
- Then: QrHome 화면으로 돌아가는 동작이 한 번 실행되고, 저장된 QR은 바뀌지 않는다.
- 테스트 데이터:

  | 탭 |
  | --- |
  | 정보 탭 |
  | QR 탭 |

### TC-QR-DETAIL-FEATURE-021: 화면을 떠났다가 다시 들어오면 저장된 내용으로 다시 시작한다

- 근거: `feature > 진행 상태 유지`
- Given: 제목 `회사`, QR 값 `hello`인 QR의 QrDetail 화면에서 제목을 `학교`로, 내용을 `hi`로 바꾸고 QR 탭을 보고 있다.
- When: 테스트 데이터의 경로로 떠났다가 같은 QR의 QrDetail 화면에 다시 진입한다.
- Then: 정보 탭이 선택되고 제목 입력에 `회사`가, QR 그림에 `hello`를 담은 QR이 보이며, 되돌리기를 선택할 수 없다.
- 테스트 데이터:

  | 떠났다 다시 진입하는 경로 |
  | --- |
  | 뒤로가기로 QrHome에 돌아간 뒤 그 QR을 다시 선택 |

### TC-QR-DETAIL-DOMAIN-006: 같은 종류의 요청은 처리 중에 다시 처리하지 않고 다른 종류는 제한하지 않는다

  | 삭제 | 수정 | 수정이 요청됨 |

## 작성하지 않는 케이스

- 백그라운드에 다녀온 뒤 입력한 내용이 유지되는 결과는 따로 작성하지 않는다. 앱이 백그라운드에 다녀오는 동안 이 화면은 그대로 남아 있어 다녀오기 전과 후를 구분할 관찰 결과가 없고, 시스템이 그사이 앱을 정리한 경우는 TC-QR-DETAIL-DOMAIN-007이 확인한다.
- 수정한 제목과 QR 값이 QrHome 목록의 자리와 QR 그림에 반영되는 결과(`data > 결과의 표시`)는 [QrHome 테스트 케이스](./qr-home.md)의 TC-QR-HOME-DOMAIN-008이 같은 저장 변경으로 확인한다.
- QR 그림의 색과 배치, 수정 버튼과 삭제 버튼의 자리는 화면의 색상과 배치를 확인해야 하므로 작성하지 않는다.
