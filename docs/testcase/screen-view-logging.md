# 화면 조회 로깅 테스트 케이스

기준 스펙: [화면 조회 로깅 스펙](../spec/client/screen-view-logging.md)

## domain

### TC-SCREEN-VIEW-LOGGING-DOMAIN-001: 화면을 표시하면 그 화면의 화면 조회가 남는다

- 근거: `domain > 화면 조회`
- Given: 화면 조회를 담당하는 기록 수단이 등록되어 있고, 아직 어떤 화면도 표시되지 않았다.
- When: 앱이 어떤 화면을 표시한다.
- Then: 그 화면의 이름을 담은 화면 조회가 한 번 남는다.

### TC-SCREEN-VIEW-LOGGING-DOMAIN-002: 다른 화면으로 이동하면 이동한 화면의 화면 조회가 남는다

- 근거: `domain > 화면 조회가 남는 시점`
- Given: 화면 조회를 담당하는 기록 수단이 등록되어 있고 어떤 화면이 표시되어 있다.
- When: 사용자가 다른 화면으로 이동한다.
- Then: 이동한 화면의 이름을 담은 화면 조회가 남는다.

### TC-SCREEN-VIEW-LOGGING-DOMAIN-003: 두 화면을 함께 표시해도 가장 나중에 진입한 화면만 남는다

- 근거: `domain > 화면 조회`
- Given: 화면 조회를 담당하는 기록 수단이 등록되어 있고 목록 화면이 표시되어 있다.
- When: 목록을 유지한 채 그 목록에서 상세 화면으로 진입한다.
- Then: 상세 화면의 이름을 담은 화면 조회만 남고, 함께 표시되고 있는 목록 화면의 화면 조회는 새로 남지 않는다.

### TC-SCREEN-VIEW-LOGGING-DOMAIN-004: 겹쳐 표시하는 화면도 화면 조회로 남는다

- 근거: `domain > 화면 조회`
- Given: 화면 조회를 담당하는 기록 수단이 등록되어 있고 어떤 화면이 표시되어 있다.
- When: 그 화면을 닫지 않고 위에 겹쳐 표시하는 화면을 연다.
- Then: 겹쳐 표시한 화면의 이름을 담은 화면 조회가 남는다.

### TC-SCREEN-VIEW-LOGGING-DOMAIN-005: 겹쳐 표시한 화면을 닫으면 아래 화면의 화면 조회가 다시 남는다

- 근거: `domain > 화면 조회`
- Given: 화면 조회를 담당하는 기록 수단이 등록되어 있고, 어떤 화면 위에 겹쳐 표시하는 화면이 열려 있다.
- When: 겹쳐 표시한 화면을 닫는다.
- Then: 다시 드러난 아래 화면의 이름을 담은 화면 조회가 남는다.

### TC-SCREEN-VIEW-LOGGING-DOMAIN-006: 백그라운드에서 돌아오면 같은 화면의 화면 조회가 다시 남는다

- 근거: `domain > 화면 조회가 남는 시점`
- Given: 화면 조회를 담당하는 기록 수단이 등록되어 있고, 어떤 화면이 표시된 채 앱이 백그라운드로 갔다.
- When: 앱이 다시 앞으로 돌아온다.
- Then: 현재 화면의 이름을 담은 화면 조회가 다시 남는다.

### TC-SCREEN-VIEW-LOGGING-DOMAIN-007: 화면이 재생성되어 복원되면 화면 조회가 남는다

- 근거: `domain > 화면 조회가 남는 시점`
- Given: 화면 조회를 담당하는 기록 수단이 등록되어 있고 어떤 화면이 표시되어 있다.
- When: 시스템이 화면을 재생성해 보던 화면이 복원된다.
- Then: 복원된 화면의 이름을 담은 화면 조회가 남는다.

### TC-SCREEN-VIEW-LOGGING-DOMAIN-008: 현재 화면이 바뀌지 않으면 화면 조회가 더 남지 않는다

- 근거: `domain > 화면 조회가 남는 시점`
- Given: 화면 조회를 담당하는 기록 수단이 등록되어 있고, 어떤 화면이 표시되어 그 화면의 화면 조회가 이미 남았다.
- When: 현재 화면은 그대로인 채 그 화면이 표시하는 내용만 바뀐다.
- Then: 화면 조회가 더 남지 않는다.

### TC-SCREEN-VIEW-LOGGING-DOMAIN-009: 항목이 달라도 같은 종류의 화면은 같은 이름으로 남는다

- 근거: `domain > 화면 이름`
- Given: 화면 조회를 담당하는 기록 수단이 등록되어 있다.
- When: 서로 다른 항목을 열어 같은 종류의 상세 화면을 차례로 표시한다.
- Then: 두 화면 조회 모두 같은 화면 이름으로 남는다.

### TC-SCREEN-VIEW-LOGGING-DOMAIN-010: 화면 이름에 그 화면에 전달된 값이 담기지 않는다

- 근거: `domain > 화면 이름`
- Given: 화면 조회를 담당하는 기록 수단이 등록되어 있다.
- When: 특정 항목을 가리키는 값을 전달받는 화면을 표시한다.
- Then: 남은 화면 이름에 그 값이 포함되지 않는다.

### TC-SCREEN-VIEW-LOGGING-DOMAIN-011: 각 화면은 목록에 정의된 이름으로 남는다

- 근거: `domain > 화면 이름 목록`
- Given: 화면 조회를 담당하는 기록 수단이 등록되어 있다.
- When: 화면 이름 목록에 있는 화면을 표시한다.
- Then: 그 화면에 대해 목록이 정의한 이름을 담은 화면 조회가 남는다.
- 테스트 데이터: [화면 조회 로깅 스펙](../spec/client/screen-view-logging.md)의 `화면 이름 목록`

### TC-SCREEN-VIEW-LOGGING-DOMAIN-012: 화면 조회는 오류 보고로 남지 않는다

- 근거: `domain > 기록 수단`
- Given: 화면 조회를 담당하는 기록 수단과 오류 보고 기록 수단이 등록되어 있다.
- When: 어떤 화면을 표시한다.
- Then: 화면 조회만 남고 오류 보고는 남지 않는다.

### TC-SCREEN-VIEW-LOGGING-DOMAIN-013: 기록에 실패해도 화면은 그대로 표시된다

- 근거: `domain > 화면 조회가 남는 시점`
- Given: 화면 조회를 남길 때마다 실패하는 기록 수단이 등록되어 있다.
- When: 어떤 화면을 표시한다.
- Then: 화면은 그대로 표시되고 사용자는 그 화면을 계속 사용할 수 있다.

## 작성하지 않는 이유

- `domain > 화면 조회가 남는 시점`의 앱 재실행 후 복원: 앱 프로세스 종료와 재시작이 필요해 유닛 테스트로 결정적으로 검증할 수 없다. 화면 재생성 경계는 TC-SCREEN-VIEW-LOGGING-DOMAIN-007이 덮는다. 앱 프로세스를 끝냈다가 이전 화면으로 되살릴 수 있는 테스트 환경이 갖춰지면 자동화한다.
- `domain > 화면 조회가 남는 시점`의 화면을 본 시간 파악: 화면을 본 시간은 남은 화면 조회들을 모아 Google Analytics 4가 집계하므로 앱에서 관찰할 결과가 없다. 집계 결과를 조회할 수 있는 테스트용 Google Analytics 4 속성이 갖춰지면 자동화한다.
- `domain > 화면 이름`의 이름을 바꾸지 않음: 한 시점의 실행에서 관찰할 결과가 없고, 이름을 바꾸지 않는 것은 문서와 리뷰로 지킬 약속이다. 이전 버전의 화면 이름 목록과 비교하는 검사가 갖춰지면 자동화한다.
- `domain > 화면 이름 목록`의 이름 없는 화면을 둘 수 없음: 이름 없는 화면은 만들 수 없으므로 실행 시점에 넣을 입력이 없다. 화면 이름을 실행 중에 정하게 되어 이름이 빠질 수 있는 입력이 생기면 자동화한다.
- `domain > 기록 수단`의 콘솔 기록: 콘솔 기록 수단이 모든 종류의 로그를 남기는 것은 [앱 로깅 테스트 케이스](./app-logging.md)의 TC-APP-LOGGING-DOMAIN-010이 덮는다.
- `domain > 기록 수단`의 Android·iOS에서 Google Analytics 4에 남는지: 해당 플랫폼 실행 환경과 실제 Google Analytics 4 속성이 필요해 현재 유닛 테스트 환경에서는 검증할 수 없다. Android·iOS 실행 환경과 결과를 조회할 수 있는 테스트용 Google Analytics 4 속성이 갖춰지면 자동화한다.
