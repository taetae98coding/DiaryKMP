# DDayAdd 테스트 케이스

기준 스펙: [DDayAdd 화면 스펙](../spec/client/dday-add.md)

작성 상태 유지, 뒤로가기, 태그 입력의 반영 시점, 저장 실패, 추가 요청 제한, 계정 연결과 저장·동기화 계약은 [항목 추가 화면 공통 스펙](../spec/client/entity-add.md)에 위임된 규칙을 이 화면에 적용한 결과를 이 문서가 확인한다. 이 문서에서 `feature > 태그 입력`, `domain > 추가 요청 제한`, `domain > 태그 선택과 추가 성립 조건`, `domain > 추가되는 항목의 태그 연결` 절은 그 공통 스펙이 소유하고, 나머지 케이스의 절은 기준 스펙이 소유한다.

제목 입력, 설명 입력, 컬러 입력 자체의 동작은 각 입력의 테스트 케이스가, 태그 입력의 표시와 조작, 태그 선택 목록은 [항목 태그 입력 컴포넌트 테스트 케이스](./entity-tag-input.md)가, 기준일을 1일로 세기와 달력에 없는 날짜 처리가 계산에 주는 영향은 [디데이 테스트 케이스](./dday.md)가 확인한다. 목록과 함께 표시되는 동안의 결과는 [DDay 목록·상세 배치 테스트 케이스](./dday-list-detail.md)가, 디데이와 태그 연결의 업로드 순서는 [디데이 태그 테스트 케이스](./dday-tag.md)가 확인한다.

화면에 보이는 문구와 접근성 이름은 [DDayAdd 화면 디자인](../design/dday-add.md)이 정한 문구를 기대 결과로 쓴다. 케이스의 `직접 입력 값`은 기준일을 1일로 세기 켬, 반복 간격 없음, 종료일 없음, 달력에 없는 날짜 처리 `말일로 당김`이다.
