# Web 목록·상세 배치 테스트 케이스

기준 스펙: [Web 목록·상세 배치 스펙](../spec/client/web-list-detail.md)

이 문서에서 `domain > 배치에 참여하는 화면`, `feature > 추가 진입 수단`, `feature > 함께 사용과 단독 사용`, `feature > 함께 사용할 때의 행동` 절은 [목록·상세 배치 공통 스펙](../spec/client/list-detail-pane.md)이 소유한다. 나머지 케이스의 절은 기준 스펙이 소유한다.

표시 비율 조절의 공통 행동과 유지 기준은 [목록·상세 배치 공통 스펙](../spec/client/list-detail-pane.md)에 위임되어 있다. 한 화면만 사용하는 환경에서 웹 목록에서 웹 추가와 웹 상세로 이동하는 케이스는 [WebHome 테스트 케이스](./web-home.md)에서 다룬다.

## feature

### TC-WEB-LIST-DETAIL-FEATURE-001: 목록과 상세를 함께 쓰는 환경에서는 두 영역을 함께 표시한다

- 근거: `feature > 함께 사용과 단독 사용`
- Given: 목록과 상세를 함께 사용할 수 있는 환경이다.
- When: 사용자가 WebHome 화면에 진입한다.
- Then: 웹 목록을 유지한 채 상세 영역에 웹 추가가 함께 표시된다.
- 작성하지 않는 이유: 목록과 상세를 함께 표시하는 창 환경과 두 영역의 전환 이력을 함께 구동해야 관찰할 수 있어 현재 단위 테스트 환경에서는 결정적으로 검증할 수 없다. 창 크기와 여러 화면의 전환 이력을 제어할 수 있는 통합 UI 테스트 환경이 갖춰지면 자동화한다.

### TC-WEB-LIST-DETAIL-FEATURE-002: 한 화면만 제공하는 환경에서는 현재 화면만 단독으로 표시한다

- 근거: `feature > 함께 사용과 단독 사용`
- Given: 목록과 상세를 함께 사용할 수 없는 환경이다.
- When: 사용자가 웹 목록 또는 웹 추가를 사용한다.
- Then: 현재 사용하는 화면만 단독으로 표시된다.
- 작성하지 않는 이유: 목록과 상세를 함께 표시하는 창 환경과 두 영역의 전환 이력을 함께 구동해야 관찰할 수 있어 현재 단위 테스트 환경에서는 결정적으로 검증할 수 없다. 창 크기와 여러 화면의 전환 이력을 제어할 수 있는 통합 UI 테스트 환경이 갖춰지면 자동화한다.

### TC-WEB-LIST-DETAIL-FEATURE-003: 상세 영역에 웹 추가가 놓이면 목록에서 추가 수단을 제공하지 않는다

- 근거: `feature > 추가 진입 수단`
- Given: 상세 영역에 웹 추가가 놓여 있다.
- When: 사용자가 웹 목록에서 실행할 수 있는 동작을 확인한다.
- Then: 웹 추가 동작이 제공되지 않는다.

### TC-WEB-LIST-DETAIL-FEATURE-004: 목록만 사용하는 환경에서는 목록에서 추가 수단을 제공한다

- 근거: `feature > 추가 진입 수단`
- Given: 상세 영역에 웹 추가가 놓여 있지 않다.
- When: 사용자가 웹 목록에서 실행할 수 있는 동작을 확인한다.
- Then: 웹 추가 동작이 제공된다.

### TC-WEB-LIST-DETAIL-FEATURE-005: 목록과 함께 표시되면 웹 추가에서 뒤로가기 수단을 제공하지 않는다

- 근거: `feature > 함께 사용할 때의 행동`
- Given: 웹 목록과 웹 추가가 함께 표시되어 있다.
- When: 사용자가 웹 추가에서 실행할 수 있는 동작을 확인한다.
- Then: 뒤로가기 동작이 제공되지 않는다.

### TC-WEB-LIST-DETAIL-FEATURE-006: 단독으로 표시되면 웹 추가에서 뒤로가기 수단을 제공한다

- 근거: `feature > 함께 사용과 단독 사용`, `feature > 함께 사용할 때의 행동`
- Given: 웹 추가가 단독으로 표시되어 있다.
- When: 사용자가 웹 추가에서 실행할 수 있는 동작을 확인한다.
- Then: 뒤로가기 동작이 제공된다.

### TC-WEB-LIST-DETAIL-FEATURE-007: 목록과 함께 표시되어도 목록의 검색 수단은 그대로 제공한다

- 근거: `feature > 검색으로 이동`
- Given: 웹 목록과 웹 추가가 함께 표시되어 있다.
- When: 사용자가 웹 목록에서 실행할 수 있는 동작을 확인한다.
- Then: 검색 동작이 제공된다.

## domain

### TC-WEB-LIST-DETAIL-DOMAIN-001: 웹 목록에서 진입하지 않은 웹 추가는 목록과 함께 표시하지 않는다

- 근거: `domain > 배치에 참여하는 화면`
- Given: 목록과 상세를 함께 사용할 수 있는 환경이다.
- When: 사용자가 웹 목록이 아닌 화면에서 웹 추가로 이동한다.
- Then: 웹 추가를 목록·상세 배치에 참여시키지 않아 단독으로 표시한다.

### TC-WEB-LIST-DETAIL-DOMAIN-002: 웹 목록에서 이어 진입한 웹 추가는 목록과 함께 표시한다

- 근거: `domain > 배치에 참여하는 화면`
- Given: 목록과 상세를 함께 사용할 수 있는 환경이다.
- When: 사용자가 웹 목록에서 웹 추가로 이동한다.
- Then: 웹 추가를 목록·상세 배치의 상세 영역에 표시한다.

### TC-WEB-LIST-DETAIL-DOMAIN-003: 웹 상세는 목록과 함께 표시하지 않는다

- 근거: `domain > 배치에 참여하는 화면`
- Given: 목록과 상세를 함께 사용할 수 있는 환경이다.
- When: 사용자가 웹 목록에서 웹 항목을 선택해 웹 상세로 이동한다.
- Then: 웹 상세를 목록·상세 배치에 참여시키지 않아 단독으로 표시한다.

### TC-WEB-LIST-DETAIL-DOMAIN-004: `더보기`로 돌아갔다가 다시 진입하면 상세 영역의 웹 추가는 입력과 태그 선택이 모두 비어 있는 상태로 시작한다

- 근거: `domain > 유지와 초기화 기준`
- Given: 목록과 상세 영역이 함께 표시되어 상세 영역에 웹 추가가 놓여 있다. 사용자가 웹 추가에 제목, 설명, URL과 요청 헤더 하나를 입력하고 태그 하나를 골랐다.
- When: 사용자가 `더보기` 화면으로 돌아갔다가 웹 화면에 다시 진입한다.
- Then: 상세 영역의 웹 추가는 제목, 설명, URL이 비어 있고 요청 헤더가 하나도 없으며, 앞서 고른 태그가 선택되어 있지 않다.

### TC-WEB-LIST-DETAIL-DOMAIN-005: 배치를 떠나기 전에는 다른 화면에 다녀와도 웹 추가의 입력과 태그 선택이 남는다

- 근거: `domain > 유지와 초기화 기준`
- Given: 목록과 상세 영역이 함께 표시되어 상세 영역에 웹 추가가 놓여 있다. 사용자가 웹 추가에 제목, 설명, URL과 요청 헤더 하나를 입력하고 태그 하나를 골랐다.
- When: 사용자가 테스트 데이터의 화면으로 이동했다가 뒤로가기를 사용해 상세 영역의 웹 추가로 돌아온다.
- Then: 웹 추가에 입력하던 제목, 설명, URL, 요청 헤더와 고른 태그가 그대로 남아 있다.
- 테스트 데이터: 목록에서 고른 웹 상세, 웹 추가의 태그 입력에서 연 태그 추가

## 작성하지 않는 이유

두 영역의 표시 비율 조절과 조절 중 즉시 반영, 화면 재생성·백그라운드 복귀 후 비율 유지, `더보기`로 돌아갔다가 다시 진입하거나 앱을 다시 실행한 뒤의 기본 비율 초기화는 실제 화면 크기와 실행 경계를 함께 판정해야 한다. 현재 테스트 환경에서는 결정적으로 자동화할 수 없으며, 화면 크기와 실행 경계를 제어·관찰할 수 있는 통합 UI 테스트 환경이 갖춰지면 자동화한다.

웹 상세에서 뒤로 돌아와 목록과 웹 추가를 다시 함께 사용하는 흐름은 여러 화면의 전환 이력과 창 환경을 함께 구동해야 하므로 같은 이유로 자동화하지 않는다.
