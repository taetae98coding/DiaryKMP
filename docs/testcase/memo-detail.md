# MemoDetail 테스트 케이스

기준 스펙: [MemoDetail 화면 스펙](../spec/memo-detail.md)

태그 입력의 공통 표시와 조작, 태그 관련 문구의 케이스는 [메모 태그 입력 컴포넌트 테스트 케이스](./memo-tag-input.md)에서, 웹 입력의 공통 표시와 조작, 웹 관련 문구의 케이스는 [메모 웹 입력 컴포넌트 테스트 케이스](./memo-web-input.md)에서, 연락처 입력의 공통 표시와 조작, 연락처 관련 문구의 케이스는 [메모 연락처 입력 컴포넌트 테스트 케이스](./memo-contact-input.md)에서 다룬다. 이 문서에는 MemoDetail 화면에서 태그 조작과 웹 조작과 연락처 조작이 저장된 메모에 반영되는 케이스와, MemoDetail 화면에서만 다른 태그 입력·웹 입력·연락처 입력의 표시 기준 케이스를 둔다.

## feature

### TC-MEMO-DETAIL-FEATURE-001: 첫진입 시 조회한 메모의 제목, 설명, 컬러가 채워진다

- 근거: `feature > 첫진입 시 내용 표시`
- Given: 선택한 메모의 제목, 설명, 컬러를 조회할 수 있도록 설정되어 있다.
- When: 사용자가 해당 메모의 MemoDetail 화면에 진입한다.
- Then: 로딩 상태가 끝나고, 화면 제목과 제목 입력 칸에 조회한 제목이, 설명 입력에 조회한 설명이, 컬러 입력에 조회한 컬러가 표시된다.

### TC-MEMO-DETAIL-FEATURE-005: 뒤로가기를 사용하면 이전 화면으로 돌아간다

- 근거: `feature > 뒤로가기`
- Given: 테스트 데이터의 화면에서 진입한 MemoDetail 화면이 표시되어 있다.
- When: 사용자가 뒤로가기를 실행한다.
- Then: MemoDetail 화면을 벗어나 테스트 데이터의 진입 화면으로 돌아간다.
- 테스트 데이터:

| 진입 화면 |
| --- |
| MemoHome 목록 |
| TagDetail 메모 탭 |
| TagMemoFinishedList |

- 작성하지 않는 이유: 뒤로가기로 MemoDetail 화면을 벗어나는 요청이 한 번 발생하는 것은 자동화한다. 테스트 데이터의 진입 화면별 실제 복귀 결과와 목록·상세 영역이 함께 표시될 때 상세 영역이 메모 추가 화면으로 되돌아가는 흐름은 단일 화면 테스트로 결정적으로 검증할 수 없다. 여러 화면과 전환 이력을 함께 제어할 수 있는 테스트 환경이 갖춰지면 자동화한다.

### TC-MEMO-DETAIL-FEATURE-006: 제목 입력을 수정해도 화면 제목은 유지된다

- 근거: `feature > 내용 수정과 반영`
- Given: 첫진입해 화면 제목과 제목 입력 칸에 조회한 메모의 제목이 채워져 있다.
- When: 사용자가 제목 입력 칸의 내용을 다른 값으로 수정한다.
- Then: 제목 입력 칸에는 수정한 값이 표시되고 화면 제목은 저장된 제목을 유지한다.

### TC-MEMO-DETAIL-FEATURE-007: 화면 재생성 후에도 수정 중이던 내용이 유지된다

- 근거: `domain > 진행 상태 유지`
- Given: 첫진입해 제목, 설명, 컬러가 채워진 뒤 사용자가 제목 입력 칸과 설명 입력의 내용을 다른 값으로 수정했다.
- When: 시스템에 의해 화면이 재생성된다.
- Then: 제목 입력 칸과 설명 입력에 수정 중이던 내용이 유지되고, 조회한 내용으로 다시 덮어쓰이지 않는다.

### TC-MEMO-DETAIL-FEATURE-009: 다른 메모를 선택하면 새 메모의 내용으로 바뀐다

- 근거: `feature > 다른 메모 선택`
- Given: 첫진입한 메모의 제목 입력 칸과 설명 입력을 수정한 상태다.
- When: 사용자가 목록에서 다른 메모를 선택한다.
- Then: 화면 제목과 제목, 설명, 컬러, 기간에 새로 선택한 메모의 내용이 표시되고, 이전 메모에서 수정 중이던 내용은 표시되지 않는다.

### TC-MEMO-DETAIL-FEATURE-010: 같은 메모의 저장 제목이 변경되면 화면 제목만 갱신된다

- 근거: `feature > 같은 메모의 변경`
- Given: 첫진입한 메모의 제목 입력 칸을 수정한 상태다.
- When: 같은 메모의 저장된 제목이 다른 경로로 변경된다.
- Then: 화면 제목에는 변경된 저장 제목이 표시되고 제목 입력 칸에는 수정 중인 내용이 유지된다.

### TC-MEMO-DETAIL-FEATURE-011: 수정을 실행해도 수정 중이던 내용이 유지된다

- 근거: `feature > 내용 수정과 반영`, `feature > 수정 성공`
- Given: 메모 수정이 성공하도록 설정되어 있고, 첫진입한 메모의 입력 내용을 저장된 내용과 다르게 수정했다.
- When: 사용자가 수정을 실행한다.
- Then: MemoDetail 화면이 그대로 유지되고, 제목 입력 칸, 설명 입력, 컬러 입력, 날짜·시간 입력의 수정 중이던 내용이 유지된다.

### TC-MEMO-DETAIL-FEATURE-012: 수정 성공을 안내한다

- 근거: `feature > 수정 성공`
- Given: 메모 수정이 성공하도록 설정되어 있고 입력 내용이 저장된 내용과 다르게 수정되어 있다.
- When: 사용자가 수정을 실행한다.
- Then: 메모가 수정되었음을 안내한다.

### TC-MEMO-DETAIL-FEATURE-013: 수정을 처리하는 동안 진행 중인 상태를 표시한다

- 근거: `feature > 내용 수정과 반영`
- Given: 메모 수정 처리가 완료되지 않고 진행 중인 상태로 설정되어 있고, 입력 내용이 저장된 내용과 다르게 수정되어 있다.
- When: 사용자가 수정을 실행한 뒤 화면을 확인한다.
- Then: 수정 처리가 끝날 때까지 진행 중인 상태가 표시된다.

### TC-MEMO-DETAIL-FEATURE-017: 수정에 성공하면 화면 제목이 새로 저장된 제목으로 갱신된다

- 근거: `feature > 내용 수정과 반영`
- Given: 첫진입해 제목이 채워진 뒤 사용자가 제목 입력 칸을 공백이 아닌 다른 제목으로 수정했고, 수정이 성공하도록 설정되어 있다.
- When: 사용자가 수정을 실행한다.
- Then: 화면 제목이 새로 저장된 제목으로 갱신된다.

### TC-MEMO-DETAIL-FEATURE-018: 입력 내용이 저장된 내용과 다를 때만 수정할 수 있다

- 근거: `feature > 수정 가능 상태`, `domain > 수정 반영 가능 기준`
- Given: 첫진입해 제목, 설명, 컬러가 저장된 내용으로 채워져 있다.
- When: 사용자가 입력 내용을 저장된 내용과 다르게 수정한다.
- Then: 입력 내용이 저장된 내용과 같은 동안에는 수정 동작이 제공되지 않고, 저장된 내용과 달라지면 수정 내용을 반영할 수 있다.

### TC-MEMO-DETAIL-FEATURE-019: 첫진입 시 저장된 기간이 날짜·시간 입력에 표시된다

- 근거: `feature > 첫진입 시 내용 표시`
- Given: 선택한 메모가 테스트 데이터의 기간 상태로 조회되도록 설정되어 있다.
- When: 사용자가 해당 메모의 MemoDetail 화면에 진입한다.
- Then: 기간이 테스트 데이터의 기대 상태로 나타난다.
- 테스트 데이터:

| 기간 상태 | 기대 상태 |
| --- | --- |
| 종일 기간 있음 | 기간 사용, 종일, 저장된 시작·종료 날짜 |
| 날짜·시간 기간 있음 | 기간 사용, 종일 아님, 저장된 시작·종료 날짜와 시간 |
| 기간 없음 | 기간을 사용하지 않음 |

### TC-MEMO-DETAIL-FEATURE-020: 기간을 수정하면 수정 내용을 반영할 수 있다

- 근거: `feature > 수정 가능 상태`, `domain > 수정 반영 가능 기준`
- Given: 첫진입해 제목, 설명, 컬러, 기간이 저장된 내용으로 채워져 있다.
- When: 사용자가 기간을 테스트 데이터의 방법으로 저장된 기간과 다르게 수정한다.
- Then: 수정 내용을 반영할 수 있다.
- 테스트 데이터:

| 기간 수정 방법 |
| --- |
| 기간 유무를 바꿈 |
| 종일 여부를 바꿈 |
| 시작 또는 종료를 바꿈 |

### TC-MEMO-DETAIL-FEATURE-023: 완료되지 않은 메모를 완료하면 다시 시작할 수 있다

- 근거: `feature > 완료와 다시 시작`
- Given: 완료되지 않은 메모의 MemoDetail 화면에 첫진입해 내용이 채워져 있고, 사용자가 제목 입력 칸을 다른 값으로 수정했으며, 완료가 성공하도록 설정되어 있다.
- When: 사용자가 메모를 완료한다.
- Then: MemoDetail 화면과 제목 입력 칸의 수정 중이던 내용이 유지되며 이후 다시 시작 동작을 사용할 수 있다.

### TC-MEMO-DETAIL-FEATURE-024: 완료된 메모를 다시 시작하면 다시 완료할 수 있다

- 근거: `feature > 완료와 다시 시작`
- Given: 완료된 메모의 MemoDetail 화면에 첫진입해 내용이 채워져 있고, 사용자가 제목 입력 칸을 다른 값으로 수정했으며, 다시 시작이 성공하도록 설정되어 있다.
- When: 사용자가 메모를 다시 시작한다.
- Then: MemoDetail 화면과 제목 입력 칸의 수정 중이던 내용이 유지되며 이후 완료 동작을 사용할 수 있다.

### TC-MEMO-DETAIL-FEATURE-026: 메모를 삭제하면 뒤로가기와 같은 동작으로 화면에서 빠져나간다

- 근거: `feature > 삭제`
- Given: 메모의 MemoDetail 화면에 첫진입해 내용이 채워져 있고, 삭제가 성공하도록 설정되어 있다.
- When: 사용자가 메모를 삭제한다.
- Then: MemoDetail 화면이 닫히고 진입하기 전 화면이 표시된다.
- 작성하지 않는 이유: 삭제에 성공하면 뒤로가기와 같은 요청이 한 번 발생하는 것은 자동화한다. 목록·상세 영역이 함께 표시될 때 상세 영역이 메모 추가 화면으로 되돌아가는 흐름은 단일 화면 테스트로 결정적으로 검증할 수 없다. 여러 화면과 전환 이력을 함께 제어할 수 있는 테스트 환경이 갖춰지면 자동화한다.

### TC-MEMO-DETAIL-FEATURE-028: 완료·다시 시작·복사·삭제를 처리하는 동안 진행 중인 상태를 표시한다

- 근거: `feature > 완료와 다시 시작`, `feature > 복사`, `feature > 삭제`
- Given: 테스트 데이터의 동작 처리가 완료되지 않고 진행 중인 상태로 설정되어 있고, 메모가 조회되어 내용이 채워져 있다.
- When: 사용자가 화면을 확인한다.
- Then: 처리가 끝날 때까지 해당 동작의 진행 중인 상태가 표시된다.
- 테스트 데이터:

| 처리 중인 동작 |
| --- |
| 완료 |
| 다시 시작 |
| 복사 |
| 삭제 |

### TC-MEMO-DETAIL-FEATURE-029: 메모 내용이 준비되지 않으면 로딩 상태를 유지한다

- 근거: `feature > 첫진입 시 내용 표시`, `domain > 내용 표시 기준`
- Given: 선택한 메모의 조회 상태가 테스트 데이터의 상태로 유지되도록 설정되어 있다.
- When: 사용자가 MemoDetail 화면에 진입한다.
- Then: 메모 내용 대신 로딩 상태가 계속 표시된다.
- 테스트 데이터:

| 조회 상태 |
| --- |
| 조회가 아직 완료되지 않음 |
| 선택한 메모를 조회할 수 없음 |
| 메모 조회 실패 |

### TC-MEMO-DETAIL-FEATURE-030: 조회가 완료되면 로딩 상태에서 메모 내용으로 바뀐다

- 근거: `feature > 첫진입 시 내용 표시`
- Given: 선택한 메모를 조회하는 동안 로딩 상태가 표시되어 있다.
- When: 선택한 메모의 조회가 완료된다.
- Then: 로딩 상태가 끝나고 조회한 제목, 설명, 컬러, 기간, 태그 연결과 대표 태그가 표시된다.

### TC-MEMO-DETAIL-FEATURE-033: 첫진입 시 저장된 태그 연결과 대표 태그가 태그 입력에 표시된다

- 근거: `feature > 첫진입 시 내용 표시`, `feature > 태그 연결과 대표 태그 변경`
- Given: 선택한 메모가 계정과 연결된 태그 두 개와 연결되어 있고 그중 하나가 그 메모의 대표 태그로 저장되어 있다.
- When: 사용자가 해당 메모의 MemoDetail 화면에 진입한다.
- Then: 저장된 두 태그가 연결된 상태로 표시되고 그중 저장된 대표 태그가 대표로 표시된다.

### TC-MEMO-DETAIL-FEATURE-047: 완료된 태그와의 연결도 태그 입력에 표시된다

- 근거: `feature > 태그 연결과 대표 태그 변경`, `domain > 태그 입력에 표시하는 태그`
- Given: 선택한 메모가 계정과 연결된 완료된 태그와 완료되지 않은 태그에 각각 연결되어 있다.
- When: 사용자가 해당 메모의 MemoDetail 화면에 진입한다.
- Then: 완료된 태그와 완료되지 않은 태그가 모두 연결된 상태로 표시된다.

### TC-MEMO-DETAIL-FEATURE-048: 완료된 태그가 대표 태그로 저장되어 있으면 대표로 표시된다

- 근거: `feature > 태그 연결과 대표 태그 변경`, `domain > 태그 입력에 표시하는 태그`
