# Setting 목록·상세 배치 테스트 케이스

기준 스펙: [Setting 목록·상세 배치 스펙](../spec/client/setting-list-detail.md)

설정 목록의 뒤로가기 동작으로 상세 선택 여부와 관계없이 `더보기` 화면으로 돌아가는 결과는 [SettingHome 테스트 케이스](./setting-home.md)의 TC-8b0d1845-ca88-4e89-a5f8-90c94870e004에서 다룬다.

## feature

### TC-42a673d0-57d5-4855-9dba-7089e7ace5bb: 설정 항목을 선택하면 해당 설정 화면이 현재 상세가 된다

- 근거: `feature > 상세 영역의 구성`
- Given: 목록과 상세를 함께 사용하고 있고 상세는 선택 전 상태다.
- When: 사용자가 테스트 데이터의 설정 항목을 선택한다.
- Then: 설정 목록은 유지되고 테스트 데이터의 설정 화면이 현재 상세가 된다.
- 테스트 데이터:

| 설정 항목 | 상세 화면 |
| --- | --- |
| `공휴일` | SettingHoliday 화면 |
| `지도` | SettingMap 화면 |
| `Gemini` | SettingGemini 화면 |
| `파일` | SettingFile 화면 |

### TC-c4c64de5-7a3c-4597-a53c-16431aa58cd0: 다른 설정 항목을 선택하면 현재 상세 화면을 교체한다

- 근거: `feature > 상세 영역의 구성`
- Given: 목록과 상세를 함께 사용하고 있고 테스트 데이터의 현재 상세가 선택되어 있다.
- When: 사용자가 설정 목록에서 테스트 데이터의 다른 설정 항목을 선택한다.
- Then: 현재 상세가 새로 선택한 설정 화면으로 교체된다.
- 테스트 데이터:

| 현재 상세 화면 | 다른 설정 항목 | 교체 후 상세 화면 |
| --- | --- | --- |
| SettingHoliday 화면 | `지도` | SettingMap 화면 |
| SettingMap 화면 | `공휴일` | SettingHoliday 화면 |
| SettingHoliday 화면 | `Gemini` | SettingGemini 화면 |
| SettingGemini 화면 | `지도` | SettingMap 화면 |
| SettingGemini 화면 | `파일` | SettingFile 화면 |
| SettingFile 화면 | `공휴일` | SettingHoliday 화면 |

### TC-d460b908-7f6d-45ff-87be-813e714c539b: 현재 상세인 설정 항목을 다시 선택하면 아무것도 바뀌지 않는다

- 근거: `feature > 상세 영역의 구성`
- Given: 목록과 상세를 함께 사용하고 있고 테스트 데이터의 설정 화면이 현재 상세다.
- When: 사용자가 설정 목록에서 현재 상세와 같은 설정 항목을 다시 선택한다.
- Then: 설정 목록과 현재 상세가 그대로 유지되고, 같은 상세가 전환 이력에 한 번 더 쌓이지 않으며, 그 설정 화면에서 입력 중이던 내용도 그대로 남는다.
- 테스트 데이터:

| 현재 상세 화면 | 다시 선택하는 설정 항목 |
| --- | --- |
| SettingHoliday 화면 | `공휴일` |
| SettingMap 화면 | `지도` |
| SettingGemini 화면 | `Gemini` |
| SettingFile 화면 | `파일` |

### TC-e907391d-f450-460c-a2d4-b45576a40fe9: 선택 전 상태에는 조작 가능한 동작이 없다

- 근거: `feature > 상세 영역의 구성`
- Given: 목록과 상세를 함께 사용할 수 있는 환경이고 설정 항목을 선택하지 않았다.
- When: 사용자가 설정 화면에 진입한다.
- Then: 상세는 선택 전 상태로 표시되고, 선택 전 상태에는 사용자가 실행할 수 있는 동작이 없다.

### TC-70fdb7cb-f9cb-4fb6-b787-e33c9e87c1fc: 설정 목록에서는 추가를 실행하는 수단을 제공하지 않는다

- 근거: `feature > 상세 영역의 구성`
- Given: 목록과 상세를 함께 사용하고 있고 상세 영역이 테스트 데이터의 상태다.
- When: 사용자가 설정 목록에서 실행할 수 있는 동작을 확인하고 추가 단축키를 누른다.
- Then: 설정 목록에는 추가 동작이 제공되지 않고, 추가 단축키를 눌러도 새 화면이 열리지 않아 설정 목록과 상세 영역이 그대로다.
- 테스트 데이터:

  | 상세 영역 |
  | --- |
  | 선택 전 상태 |
  | SettingMap 화면이 현재 상세 |

### TC-8bf5ef36-7ebb-40fc-8f89-e6d04aecc8c1: 설정 화면에 다시 진입하면 상세 선택을 초기화한다

- 근거: `domain > 유지와 초기화 기준`
- Given: 목록과 상세를 함께 사용하고 있고 상세 화면을 선택했다.
- When: 사용자가 `더보기` 화면으로 돌아갔다가 설정 화면에 다시 진입한다.
- Then: 상세 선택이 초기화되어 선택 전 상태로 표시된다.

### TC-7991766b-0000-4738-aa2d-27ff26d36bd5: 시스템 뒤로가기를 사용하면 상세가 선택 전 상태로 돌아간다

- 근거: `feature > 뒤로가기`
- Given: 목록과 상세를 함께 사용하고 있고 상세 화면이 선택되어 있다.
- When: 사용자가 시스템 뒤로가기를 사용한다.
- Then: 설정 목록은 유지되고 상세는 선택 전 상태로 돌아간다.

### TC-3a4ccfbf-2c11-4219-9cb6-66157dd4164a: 선택 전 상태에서 시스템 뒤로가기를 사용하면 `더보기`로 돌아간다

- 근거: `feature > 뒤로가기`
- Given: 목록과 상세를 함께 사용하고 있고 상세는 선택 전 상태다.
- When: 사용자가 시스템 뒤로가기를 사용한다.
- Then: 설정 화면 전체를 떠나 `더보기` 화면으로 돌아간다.

### TC-8cbf380d-d0b9-456a-a873-f94e35d5deea: 세부 설정이 단독으로 표시될 때 뒤로가면 설정 목록으로 돌아간다

- 근거: `feature > 뒤로가기`
- Given: 목록과 상세를 함께 사용할 수 없는 창에서 설정 목록이 표시되어 있고, 사용자가 테스트 데이터의 설정 항목을 선택해 그 설정 화면이 단독으로 표시되어 있다.
- When: 사용자가 시스템 뒤로가기를 사용한다.
- Then: 설정 화면이 닫히고 설정 목록이 표시되며, 설정 화면 전체를 떠나지 않는다.
- 테스트 데이터:

| 설정 항목 | 단독으로 표시된 설정 화면 |
| --- | --- |
| `공휴일` | SettingHoliday 화면 |
| `지도` | SettingMap 화면 |
| `Gemini` | SettingGemini 화면 |
| `파일` | SettingFile 화면 |

공통 내비게이션을 계속 제공하지 않는 결과는 [TopLevelNavigation 테스트 케이스](./top-level-navigation.md)의 TC-e499dc91-528f-4d46-a621-c4f9867ec27a가 다룬다.

### TC-7d9c2fbb-2838-4431-903e-e94079265930: 화면이 재생성되어도 상세 선택을 유지한다

- 근거: `domain > 유지와 초기화 기준`, [목록·상세 배치 공통 스펙](../spec/client/list-detail-pane.md)의 `domain > 유지와 초기화 기준`
- Given: 목록과 상세를 함께 사용하고 있고 사용자가 설정 항목을 선택해 그 설정 화면이 현재 상세다.
- When: 화면이 시스템에 의해 재생성된다.
- Then: 설정 목록과 같은 설정 화면이 계속 함께 표시되고, 시스템 뒤로가기를 사용하면 상세가 선택 전 상태로 돌아간다.

### TC-152b5755-8409-43bd-95bf-0db8426a0a60: 앱이 백그라운드에서 돌아와도 상세 선택을 유지한다

- 근거: `domain > 유지와 초기화 기준`, [목록·상세 배치 공통 스펙](../spec/client/list-detail-pane.md)의 `domain > 유지와 초기화 기준`
- Given: 목록과 상세를 함께 사용하고 있고 사용자가 설정 항목을 선택해 그 설정 화면이 현재 상세다.
- When: 앱이 백그라운드로 갔다가 시스템이 앱을 종료하지 않은 채 다시 앞으로 돌아온다.
- Then: 설정 목록과 같은 설정 화면이 계속 함께 표시되고, 시스템 뒤로가기를 사용하면 상세가 선택 전 상태로 돌아간다.

### TC-ad29bf0e-2beb-4725-952f-9b6b54ca1352: 시스템이 앱을 정리했다가 다시 만들어도 상세 선택과 뒤로가기 기록을 유지한다

- 근거: `domain > 유지와 초기화 기준`, [목록·상세 배치 공통 스펙](../spec/client/list-detail-pane.md)의 `domain > 유지와 초기화 기준`
- Given: 목록과 상세를 함께 사용하고 있고 사용자가 설정 항목을 선택해 그 설정 화면이 현재 상세다.
- When: 앱이 백그라운드에 있는 동안 시스템이 앱을 정리했다가 다시 만든다.
- Then: 설정 목록과 같은 설정 화면이 다시 함께 표시되고, 시스템 뒤로가기를 사용하면 상세가 선택 전 상태로 돌아간다.

### TC-fbb5259b-a56a-42b5-9520-dbe85b86f58c: 표시 비율을 조절하고 화면 재생성·백그라운드 복귀를 지나도 조절한 비율을 유지한다

- 근거: `domain > 유지와 초기화 기준`
- Given: 설정 목록과 상세 영역이 함께 표시되어 있다.
- When: 사용자가 두 영역의 표시 비율을 조절한 뒤 테스트 데이터의 경계를 지난다.
- Then: 조절하는 동안 결과가 즉시 반영되고, 경계를 지난 뒤에도 조절한 비율로 표시된다.
- 테스트 데이터:

| 경계 |
| --- |
| 화면 재생성 |
| 백그라운드 복귀 |
| 앱이 백그라운드에 있는 동안 시스템이 앱을 정리했다가 다시 만듦 |

- 작성하지 않는 이유: 표시 비율은 실제 창 크기에서 두 영역의 경계를 끌어야 조절되고 그 비율을 화면 밖에서 읽을 수 없어 현재 테스트 환경에서는 결정적으로 검증할 수 없다. 같은 경계의 상세 선택 유지는 화면 재생성을 TC-7d9c2fbb-2838-4431-903e-e94079265930가, 백그라운드 복귀를 TC-152b5755-8409-43bd-95bf-0db8426a0a60가, 시스템이 앱을 정리했다가 다시 만드는 경우를 TC-ad29bf0e-2beb-4725-952f-9b6b54ca1352가 따로 검증한다. 창 크기와 영역 경계 끌기를 제어·관찰할 수 있는 통합 UI 테스트 환경이 갖춰지면 자동화한다.

### TC-2d348036-9f87-4ece-b127-cf6f7324c0d8: 표시 비율을 조절한 뒤 다시 진입하거나 앱을 다시 실행하면 기본 비율로 초기화한다

- 근거: `domain > 유지와 초기화 기준`
- Given: 설정 목록과 상세 영역이 함께 표시되어 있고 사용자가 두 영역의 표시 비율을 조절했다.
- When: 테스트 데이터의 경계를 지난 뒤 설정 화면이 다시 표시된다.
- Then: 두 영역이 기본 비율로 표시된다.
- 테스트 데이터:

| 경계 |
| --- |
| `더보기`로 돌아갔다가 다시 진입 |
| 앱 종료 뒤 다시 실행 |

- 작성하지 않는 이유: 표시 비율은 실제 창 크기에서 두 영역의 경계를 끌어야 조절되고 그 비율을 화면 밖에서 읽을 수 없어 현재 테스트 환경에서는 결정적으로 검증할 수 없다. 같은 경계의 상세 선택 초기화는 TC-8bf5ef36-7ebb-40fc-8f89-e6d04aecc8c1와 TC-abd2391e-99ec-4aab-a8dd-e5249eaf8c86가 따로 검증한다. 창 크기와 영역 경계 끌기를 제어·관찰할 수 있는 통합 UI 테스트 환경이 갖춰지면 자동화한다.

### TC-abd2391e-99ec-4aab-a8dd-e5249eaf8c86: 앱을 종료하고 다시 실행하면 상세 선택이 초기화된다

- 근거: `domain > 유지와 초기화 기준`
- Given: 목록과 상세를 함께 사용하고 있고 상세 화면을 선택했다.
- When: 사용자가 앱을 종료하고 다시 실행한다.
- Then: 앱은 시작 화면 하나만 열린 상태로 시작하고, 종료 전에 열었던 설정 목록과 상세 화면은 남아 있지 않다. 이어 설정 화면에 진입했을 때 상세가 선택 전 상태로 표시되는 것은 남은 선택이 없을 때의 진입과 같아 `TC-8bf5ef36-7ebb-40fc-8f89-e6d04aecc8c1`가 검증한다.
