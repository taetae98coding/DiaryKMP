# CalendarHome 테스트 케이스

기준 스펙: [CalendarHome 스펙](../spec/client/calendar-home.md)

태그 필터 케이스의 `근거`가 가리키는 CalendarHome 스펙의 태그 필터 관련 절은 공통 규칙을 [태그 필터 스펙](../spec/client/tag-filter.md)에 위임하고, 필터가 적용되어 있는지 알리는 기준은 [목록 필터 반영 스펙](../spec/client/list-filter.md)에 위임한다.

## feature

### TC-CALENDAR-HOME-FEATURE-001: 캘린더 홈 화면에 오늘이 속한 달의 캘린더가 표시된다

- 근거: `feature > 캘린더 표시`
- Given: 사용자의 현재 시간대 기준 오늘이 정해져 있다.
- When: 캘린더 홈 화면이 표시된다.
- Then: 오늘이 속한 달의 1일이 포함된 주의 일요일부터 42개의 날짜 숫자가 순서대로 표시된다.

### TC-CALENDAR-HOME-FEATURE-002: 현재 표시 중인 달의 년도와 월을 확인할 수 있다

- 근거: `feature > 표시 중인 달 안내`
- Given: 사용자의 현재 시간대 기준 오늘이 정해져 있다.
- When: 캘린더 홈 화면이 표시된다.
- Then: 오늘이 속한 달의 년도와 월이 표시된다.

### TC-CALENDAR-HOME-FEATURE-003: 달을 이동하면 표시 중인 달 안내가 갱신된다

- 근거: `feature > 표시 중인 달 안내`
- Given: 캘린더 홈 화면에 오늘이 속한 달의 년도와 월이 표시되어 있다.
- When: 사용자가 다음 달로 이동한다.
- Then: 표시 중인 달 안내가 다음 달의 년도와 월로 바뀐다.

### TC-CALENDAR-HOME-FEATURE-005: 달 선택을 시작하면 현재 표시 중인 달의 1일이 선택된다

- 근거: `feature > 달 선택`
- Given: 캘린더 홈 화면에 2026년 7월이 표시되어 있다.
- When: 사용자가 달 선택을 시작한다.
- Then: 2026년 7월 1일이 선택된 상태로 시작한다.

### TC-CALENDAR-HOME-FEATURE-007: 날짜를 고르고 확인하면 캘린더가 고른 날짜가 속한 달로 이동한다

- 근거: `feature > 달 선택`
- Given: 캘린더 홈 화면에서 달 선택을 시작했다.
- When: 사용자가 현재 표시 중인 달과 다른 달의 날짜를 고르고 선택을 확인한다.
- Then: 캘린더와 표시 중인 달 안내가 고른 날짜가 속한 달로 바뀐다.

### TC-CALENDAR-HOME-FEATURE-008: 달 선택을 취소하면 보던 달이 유지된다

- 근거: `feature > 달 선택`
- Given: 캘린더 홈 화면에서 달 선택을 시작했다.
- When: 사용자가 다른 달의 날짜를 고른 뒤 선택을 취소한다.
- Then: 캘린더와 표시 중인 달 안내는 보던 달을 그대로 유지한다.

### TC-CALENDAR-HOME-FEATURE-066: 달 선택 중 화면이 재생성되어도 달 선택이 열린 채로 유지된다

- 근거: `domain > 달 선택 진행 유지`
- Given: 캘린더 홈 화면에서 달 선택을 시작했다.
- When: 화면 재생성이 일어난다.
- Then: 달 선택이 열린 상태로 표시되고, 캘린더와 표시 중인 달 안내는 보던 달을 그대로 유지한다.

### TC-CALENDAR-HOME-FEATURE-010: 이전 달로 이동한다

### TC-CALENDAR-HOME-FEATURE-011: 다음 달로 이동한다

### TC-CALENDAR-HOME-FEATURE-015: 다른 달을 보는 중에 오늘이 속한 달로 이동한다

- 근거: `feature > 오늘이 속한 달로 이동`
- Given: 캘린더 홈 화면이 표시되어 있고, 사용자가 캘린더를 이동해 오늘이 속한 달이 아닌 달을 보고 있다.

- 근거: `feature > 오늘이 속한 달로 이동`

- Then: 캘린더와 표시 중인 달 안내는 오늘이 속한 달을 그대로 유지한다.

### TC-CALENDAR-HOME-FEATURE-017: 화면을 벗어난 사이 날짜가 바뀌면 복귀 시 오늘 기준이 갱신된다

- 근거: `domain > 오늘 기준`
- Given: 캘린더 홈 화면이 표시된 뒤 사용자가 화면을 벗어나 있는 동안 자정이 지나 오늘 날짜가 바뀌었다.
- When: 사용자가 캘린더 홈 화면으로 복귀한다.
- Then: 바뀐 오늘이 주요 날짜가 되고, 오늘이 속한 달 이동의 목적지도 바뀐 오늘이 속한 달이 된다.
- 작성하지 않는 이유: 오늘 판정이 시스템 시계를 따르는데 현재 테스트 환경에서는 시스템 시계를 제어할 수 없어 화면을 벗어난 사이 날짜가 바뀌는 상황을 결정적으로 재현할 수 없다. 오늘 판정에 사용하는 시계를 테스트에서 주입할 수 있는 구조가 마련되면 자동화한다.

### TC-CALENDAR-HOME-FEATURE-030: 완료된 메모의 제목은 표시되고 삭제된 메모의 제목은 표시되지 않는다

- 근거: `feature > 메모 표시`

- Given: 캘린더 홈 화면에서 사용자가 2026년 12월에서 2027년 1월로 이동해 보고 있고, 2026년과 2027년 음력 자료 동기화를 한 번씩 요청한 상태다.
- When: 화면 재생성이 일어난다.
- Then: 2027년 1월의 생일 조회 기간이 속한 2026년과 2027년 음력 자료 동기화를 다시 요청한다.

### TC-CALENDAR-HOME-DATA-047: 당겨서 새로고침해도 음력 자료를 다시 동기화하지 않는다

- 근거: `data > 표시 중인 달의 음력 자료 동기화`
- Given: 캘린더 홈 화면에 2026년 7월이 표시되어 화면 표시로 2026년 음력 자료 동기화를 요청한 상태다.
- When: 사용자가 캘린더를 당겨 새로고침한다.
- Then: 음력 자료 동기화를 더 요청하지 않는다.

### TC-CALENDAR-HOME-DATA-048: 음력 자료 동기화가 진행 중이어도 새로 요청한다

- 근거: `data > 표시 중인 달의 음력 자료 동기화`
- Given: 캘린더 홈 화면에 2026년 7월이 표시되어 2026년 음력 자료 동기화를 요청했고, 그 동기화가 아직 끝나지 않았다.
- When: 사용자가 2026년 8월로 이동한다.
- Then: 진행 중인 동기화가 끝나기를 기다리지 않고 2026년 음력 자료 동기화를 한 번 더 요청한다.

## 작성하지 않는 이유

- 오늘 날짜가 주요 날짜로 강조되는 결과, 오늘이 속하지 않은 달에서 강조되는 날짜가 없는 결과와 이웃 달 날짜로 표시된 오늘의 강조는 실제 화면의 의미 표현을 판정해야 하므로 블랙박스 유닛 테스트 케이스로 작성하지 않는다. 의미 표현을 결정적으로 식별할 수 있는 테스트 환경이 갖춰지면 검증한다.
- 공휴일인 날짜의 강조와 공휴일 여부가 거짓인 항목의 날짜가 강조되지 않는 결과도 실제 화면의 의미 표현을 판정해야 하므로 작성하지 않는다. 표시 대상 공휴일이 정해지는 규칙은 TC-CALENDAR-HOME-DATA-008부터 TC-CALENDAR-HOME-DATA-016으로 확인한다.
- 공휴일 이름이 쉬는 날 여부에 따라 서로 다른 의미로 구분되는 결과도 같은 이유로 작성하지 않는다. 공휴일 여부와 관계없이 이름이 모두 표시되는 것은 TC-CALENDAR-HOME-FEATURE-019로 확인하고, 이름을 선택할 수 있는 것은 TC-CALENDAR-HOME-FEATURE-022로 확인한다.
- 사용자가 숨김으로 고른 공휴일을 표시 대상에서 제외하는 규칙은 [공휴일 노출 설정 테스트 케이스](holiday-visibility.md)에서 다루므로 여기서 중복 작성하지 않는다. 이 문서의 공휴일 케이스는 노출 설정을 한 번도 고르지 않은 상태를 전제한다.
- 캘린더에 표시할 메모를 정하는 조회 규칙(기간 겹침 판단, 삭제·완료 노출 기준, 계정 기준, 표시 색상, 표시 순서)은 [캘린더 메모 표시 테스트 케이스](calendar-memo.md)에서 다루므로 여기서 중복 작성하지 않는다. 이 문서의 메모 케이스는 캘린더 홈 화면이 정하는 조회 기간과 화면 노출 결과만 다룬다.
- 메모 제목의 표시 색상은 실제 색상을 판정해야 하므로 작성하지 않는다. 표시 색상이 정해지는 규칙은 TC-CALENDAR-MEMO-DOMAIN-008로 확인한다.
- 하루 일정인 메모를 색상 바가 있는 아이템으로, 그 밖의 메모를 색을 채운 아이템으로 구분해 표시하는 결과는 실제 화면의 색상과 형태를 판정해야 하므로 작성하지 않는다. 두 갈래의 메모가 모두 표시되고 같은 방식으로 선택되는 것은 TC-CALENDAR-HOME-FEATURE-060, TC-CALENDAR-HOME-FEATURE-061, TC-CALENDAR-HOME-FEATURE-064, TC-CALENDAR-HOME-FEATURE-065로 확인하며, 시각과 형태를 결정적으로 비교할 수 있는 테스트 환경이 갖춰지면 검증한다.
- 사용자가 메모의 기간을 바꿔 속하는 갈래가 달라졌을 때 표현이 갱신되는 결과도 같은 이유로 작성하지 않는다. 저장된 메모의 변경이 조작 없이 캘린더에 반영되는 것은 TC-CALENDAR-HOME-FEATURE-031로 확인한다.
- 같은 줄에 놓인 메모 제목과 공휴일 이름이 줄 위쪽에 정렬되는 결과는 실제 화면의 위치를 판정해야 하므로 작성하지 않는다. 화면의 실제 배치를 비교할 수 있는 스크린샷 테스트 환경이 갖춰지면 검증한다.
- 날씨 아이콘의 크기·간격·가운데 정렬과 대체 아이콘 표현, 온도 글자 크기, 날씨를 누를 때의 물결 효과는 실제 화면의 시각 속성을 판정해야 하므로 작성하지 않는다. 날씨를 선택할 수 있다는 것은 TC-CALENDAR-HOME-FEATURE-067부터 TC-CALENDAR-HOME-FEATURE-072로 확인한다.
- 날짜별 날씨를 만드는 묶음·온도 계산 규칙과 동기화 실패 시 이전에 저장된 날씨를 유지하는 규칙은 [현재 날씨 동기화 테스트 케이스](weather-fetch.md)에서 다루므로 여기서 중복 작성하지 않는다. 이 문서의 날씨 케이스는 캘린더 홈 화면이 동기화를 시작하는 조건과 화면 노출 결과만 다룬다.
- 위치 권한 요청을 시작하는 조건, 요청 범위와 요청 결과 판정은 [위치 권한 요청 테스트 케이스](location-permission.md)에서 다루므로 여기서 중복 작성하지 않는다. 이 문서의 위치 권한 케이스는 요청 결과가 캘린더 홈 화면의 날씨 동기화에 반영되는 결과만 다룬다.
- MemoDetail 화면에서 뒤로 갔을 때 캘린더가 보던 달을 유지하는 동작은 여러 화면을 통과하는 내비게이션 통합 동작이므로 블랙박스 유닛 테스트 케이스로 작성하지 않는다. 앱 내비게이션 전체를 결정적으로 검증할 수 있는 테스트 환경이 갖춰지면 자동화한다. 캘린더 홈 화면이 이동을 요청하는 것까지는 TC-CALENDAR-HOME-FEATURE-032로 확인한다.
- MemoAdd 화면에서 뒤로 갔을 때 캘린더가 선택된 날짜 없이 보던 달을 유지하는 동작과, 캘린더 홈 화면에서 이동한 MemoAdd 화면을 메모 목록과 함께 표시하지 않는 동작은 여러 화면을 통과하는 내비게이션 통합 동작이므로 블랙박스 유닛 테스트 케이스로 작성하지 않는다. 앱 내비게이션 전체를 결정적으로 검증할 수 있는 테스트 환경이 갖춰지면 자동화한다. 캘린더 홈 화면이 이동을 요청하는 것까지는 TC-CALENDAR-HOME-FEATURE-035와 TC-CALENDAR-HOME-FEATURE-036으로, 이동 시 선택이 해제되는 것은 TC-CALENDAR-HOME-FEATURE-047로 확인한다.
- 날짜 선택 자체의 행동과 정책은 [Calendar 날짜 선택 테스트 케이스](calendar-select.md)에서 다루므로 여기서 중복 작성하지 않는다. 이 문서에서는 선택 완료가 MemoAdd 화면 이동으로 이어지는 결과만 다룬다.
- 최초 진입 시점에 이미 표시할 날씨가 있어 아이템 스크롤을 되돌리지 않는 결과는 아직 사용자가 스크롤한 위치가 없어 되돌림 없이 처음부터 날씨가 보이는 상태와 관찰 결과가 같으므로 작성하지 않는다. 이 경우 날씨가 표시되는 것은 TC-CALENDAR-HOME-FEATURE-040으로 확인하고, 사용자가 스크롤해 둔 위치가 있는 재생성 시점의 결과는 TC-CALENDAR-HOME-DOMAIN-010으로 확인한다.
- 되돌림이 날씨가 차지하는 날짜가 없는 주에도 적용되는 결과는 그 주의 아이템이 이미 첫 줄부터 보이는 상태와 관찰 결과가 같아 작성하지 않는다.
- 되돌림에 안내 문구나 진행 표시를 두지 않는 것과 되돌림이 애니메이션 없이 적용되는 것은 실제 화면의 표현과 움직임을 판정해야 하므로 작성하지 않는다.
- 생일 아이템의 배경색, 생일 아이콘, 같은 하루에서 메모 제목보다 아래쪽·공휴일 이름보다 위쪽에 오는 줄 위치는 실제 화면의 색상과 위치를 판정해야 하므로 블랙박스 유닛 테스트 케이스로 작성하지 않는다. 생일이 표시되고 선택되는 것은 TC-CALENDAR-HOME-FEATURE-075부터 TC-CALENDAR-HOME-FEATURE-080으로 확인하며, 화면의 실제 배치를 비교할 수 있는 스크린샷 테스트 환경이 갖춰지면 검증한다.
- 캘린더에 표시할 생일을 정하는 조회 규칙(표시 대상 기간 판단, 생일 없음·삭제 노출 기준, 계정 기준, 반복 연도, 달력에 없는 날짜, 음력 생일이 놓이는 양력 날짜, 표시 순서)은 [캘린더 연락처 생일 표시 테스트 케이스](calendar-contact-birthday.md)에서 다루므로 여기서 중복 작성하지 않는다. 음력 생일이 놓이는 양력 날짜와 반복 연도, 윤달, 음력 자료가 없는 날짜의 규칙은 TC-CALENDAR-CONTACT-BIRTHDAY-DOMAIN-016부터 TC-CALENDAR-CONTACT-BIRTHDAY-DOMAIN-021로 확인한다. 이 문서의 생일 케이스는 캘린더 홈 화면이 정하는 조회 기간과 화면 노출 결과만 다룬다.
- 삭제된 연락처의 생일이 캘린더에서 사라지는 결과는 화면 테스트가 제어할 수 있는 경계에 이미 노출 기준이 반영된 조회 결과만 전달되어 결정적으로 구분할 수 없으므로 작성하지 않는다. 노출 기준은 TC-CALENDAR-CONTACT-BIRTHDAY-DOMAIN-003으로, 저장된 연락처의 변경이 조작 없이 캘린더에 반영되는 것은 TC-CALENDAR-HOME-FEATURE-077로 확인한다.
- ContactDetail 화면에서 뒤로 가거나 연락처를 삭제했을 때 캘린더가 보던 달을 유지하는 동작과, 캘린더에서 진입한 ContactDetail 화면을 연락처 목록과 함께 표시하지 않는 동작은 여러 화면을 통과하는 내비게이션 통합 동작이므로 블랙박스 유닛 테스트 케이스로 작성하지 않는다. 앱 내비게이션 전체를 결정적으로 검증할 수 있는 테스트 환경이 갖춰지면 자동화한다. 캘린더 홈 화면이 이동을 요청하는 것까지는 TC-CALENDAR-HOME-FEATURE-080으로 확인한다.
