# AI 도구 연결 테스트 케이스

기준 스펙: [AI 도구 연결 스펙](../spec/client/mcp-server.md)

AI 도구에 제공하는 각 기능이 무엇을 보여 주고 바꾸는지, 대상 계정을 어떻게 정하는지, 바뀐 내용이 어떻게 저장되고 동기화되는지는 그 기능의 스펙이 소유하므로 그 기능의 테스트 케이스가 다룬다. 이 문서는 연결의 동작 상태, 접속 허용 기준, 제공하는 기능의 범위, 그리고 화면이 없어서 달라지는 부분을 다룬다.

## domain

### TC-af4cbda8-1a65-4f20-bc57-160e76364072: 앱이 시작되면 켜 둔 설정에 따라 연결을 시작한다

- 근거: `domain > 연결 동작 상태`
- Given: 연결 사용 설정이 테스트 데이터의 값으로 저장되어 있고, 연결 주소를 열 수 있다.
- When: 앱이 시작된다.
- Then: 연결이 테스트 데이터의 상태가 된다.
- 테스트 데이터:

| 저장된 값 | 연결 상태 |
| --- | --- |
| 한 번도 바꾸지 않음 | 꺼짐 |
| 꺼짐 | 꺼짐 |
| 켬 | 동작 중 |

### TC-ed294eaa-40c8-48a5-b9d8-e5b2c70ccbdc: 앱이 실행되는 동안 설정을 바꾸면 연결이 바로 시작되거나 끝난다

- 근거: `domain > 연결 동작 상태`
- Given: 앱이 실행 중이고 연결이 테스트 데이터의 이전 상태다. 연결 주소를 열 수 있다.
- When: 연결 사용 설정이 테스트 데이터의 값으로 바뀐다.
- Then: 연결이 테스트 데이터의 다음 상태가 된다.
- 테스트 데이터:

| 이전 상태 | 바뀐 설정 | 다음 상태 |
| --- | --- | --- |
| 꺼짐 | 켬 | 동작 중 |
| 동작 중 | 꺼짐 | 꺼짐 |
| 시작 실패 | 꺼짐 | 꺼짐 |

### TC-e168b09e-2a42-46e5-a369-7338871dfde5: 연결 주소를 열지 못하면 이유를 구분해 시작 실패가 된다

- 근거: `domain > 연결 동작 상태`
- Given: 연결 사용 설정이 꺼짐이고, 연결 주소를 열면 테스트 데이터의 응답이 오도록 정해져 있다.
- When: 연결 사용 설정이 켬으로 바뀐다.
- Then: 연결이 테스트 데이터의 상태가 된다.
- 테스트 데이터:

| 주소 열기 응답 | 연결 상태 |
| --- | --- |
| 다른 프로그램이 주소를 쓰고 있음 | 시작 실패, 주소를 다른 프로그램이 씀 |
| 그 밖의 실패 | 시작 실패, 그 밖의 이유 |

### TC-bf7dadaf-e25a-402f-a814-ad600def73e4: 시작에 실패하면 저절로 다시 시도하지 않는다

- 근거: `domain > 연결 동작 상태`
- Given: 연결 주소를 다른 프로그램이 쓰고 있어 연결이 시작 실패 상태다.
- When: 그 주소를 쓰던 프로그램이 주소를 놓는다.
- Then: 연결은 시작 실패 상태로 남고 주소를 다시 열지 않는다.

### TC-641ab193-7241-40bc-8dbe-b972d7f8fb28: 켜 둔 설정을 확인하지 못하면 연결을 시작하지 않는다

- 근거: `domain > 연결 동작 상태`
- Given: 연결 사용 설정을 아직 확인하지 못했거나 읽지 못했다.
- When: 앱이 시작된다.
- Then: 연결은 꺼짐 상태로 남는다.

### TC-b7bae2a8-ca68-4e09-9edf-04843f1f51d6: 연결 주소는 환경마다 고정한다

- 근거: `domain > 연결 주소`
- Given: 테스트 데이터의 환경에서 앱이 실행된다.
- When: 연결이 동작 중이다.
- Then: 연결 주소는 테스트 데이터의 주소다.
- 테스트 데이터:

| 환경 | 연결 주소 |
| --- | --- |
| 운영 | `http://127.0.0.1:38450/mcp` |
| 개발 | `http://127.0.0.1:38451/mcp` |

- 작성하지 않는 이유: 환경은 빌드할 때 정해지므로 한 번의 테스트 실행에서 두 환경을 함께 만들 수 없다. 자동화하려면 환경마다 따로 빌드한 앱을 함께 띄우는 실행 환경이 필요하다.

### TC-b5f12a78-7ced-46c6-b06c-115f6379320f: 같은 Mac의 AI 도구는 인증 없이 접속한다

- 근거: `domain > 접속 허용 기준`
- Given: 연결이 동작 중이다.
- When: 브라우저를 거치지 않은 AI 도구가 인증 정보 없이 기능 목록을 요청한다.
- Then: 요청이 처리되어 제공하는 기능 목록을 받는다.

### TC-cc2c0f76-ead1-461a-a234-e97ca13f9c44: 웹 페이지가 브라우저를 통해 보낸 요청은 거절한다

- 근거: `domain > 접속 허용 기준`
- Given: 연결이 동작 중이다.
- When: 웹 페이지가 브라우저를 통해 요청을 보낸다.
- Then: 요청은 거절되고 어떤 기능도 실행되지 않는다.

### TC-c3ac3b36-0621-4123-838a-1cb57a17ccf8: 제공하는 기능만 목록에 둔다

- 근거: `domain > 제공하는 기능`
- Given: 연결이 동작 중이다.
- When: AI 도구가 기능 목록을 요청한다.
- Then: 목록에는 `제공하는 기능` 표의 대상마다 조회 기능이 있고, 바꾸기가 있는 대상에는 추가, 수정, 삭제, 되돌리기 기능이 있다. 기기 설정 변경, 로그인·로그아웃·계정 탈퇴·프로필 이미지 변경, 파일, 앱 밖 서비스 조회, 링크 열기, 기기 장치가 필요한 기능은 목록에 없다.

### TC-2512e6a0-0601-47e5-a441-a95b9c00a65f: 목록을 최대 100개씩 페이지로 나눠 준다

- 근거: `domain > 화면이 없어서 달라지는 부분`

- 테스트 데이터:

| 항목 수 | 결과 |
| --- | --- |
| 0 | 빈 목록, 다음 페이지 위치 없음 |
| 100 | 100개, 다음 페이지 위치 없음 |
| 101 | 앞의 100개와 다음 페이지 위치 |

### TC-5e76676b-ba84-45cd-9f2c-2d77bc71e555: 다음 페이지 위치로 이어서 받는다

- 근거: `domain > 화면이 없어서 달라지는 부분`
- Given: 목록 기능이 돌려줄 항목이 250개 있다.
- When: AI 도구가 첫 페이지에서 받은 다음 페이지 위치로 다음 페이지를 차례로 요청한다.
- Then: 두 번째 페이지에서 101번째부터 200번째 항목과 다음 페이지 위치를, 세 번째 페이지에서 201번째부터 250번째 항목을 받고 다음 페이지 위치는 받지 않는다. 각 페이지의 순서는 목록 기능이 돌려준 순서와 같다.

### TC-63d5cbe2-0359-4a08-8108-4f545e469af2: 계정이 확정되기 전에 받은 요청은 확정된 뒤의 결과로 처리한다

- 근거: `domain > 대상 계정`
- Given: 앱이 막 시작해 계정 상태가 아직 확정되지 않아, 요청한 기능의 결과가 계정이 확정된 뒤에 나오도록 정해져 있다.
- When: AI 도구가 메모 목록을 요청하고, 그 뒤 계정이 확정된다.
- Then: 요청은 실패로 끝나지 않고, 계정이 확정된 뒤의 메모 목록을 결과로 받는다.

### TC-13865563-40d3-4f3d-a063-b0e955d7ef6f: 연결이 동작하는 동안 계정이 바뀌면 다음 요청부터 바뀐 계정을 기준으로 처리한다

- 근거: `domain > 대상 계정`
- Given: 연결이 동작 중이고, AI 도구가 메모 목록을 한 번 받았다.
- When: 계정이 바뀐 뒤 AI 도구가 메모 목록을 다시 요청한다.
- Then: 연결을 다시 시작하지 않아도 바뀐 계정의 메모 목록을 받는다.

- When: AI 도구가 테스트 데이터의 정렬로 메모 목록을 요청한다.
- Then: 테스트 데이터의 결과를 받는다.

| 요청한 정렬 | 결과 |

| 담지 않음 | 기본순으로 조회한 목록 |

### TC-f61abd56-16fd-4232-8939-3191cee6d724: 빈 검색어로 검색하면 SearchHome과 같은 결과를 받는다

- 근거: `domain > 화면이 없어서 달라지는 부분`
- Given: SearchHome의 메모 검색이 빈 검색어에 돌려주는 결과가 정해져 있다.

### TC-78e9deb8-0990-4954-9903-4337415a5943: 기능이 실패하면 실패를 알린다

- 근거: `domain > 제공 원칙`, `domain > 대상 계정`
- Given: 계정 조회 실패처럼 AI 도구가 요청한 기능이 실패하도록 응답이 정해져 있다.
- When: AI 도구가 그 기능을 요청한다.
- Then: AI 도구는 요청이 실패했다는 결과를 받고, 연결은 동작 중 상태로 남는다.

### TC-77c32c1d-a54a-480f-9654-066a1f73fa1f: 삭제한 항목을 되돌린다

## data

### TC-1d07384f-ba83-4d6c-bf04-4af1b6013cc2: AI 도구가 바꾼 내용은 앱 화면에 바로 보인다

- 근거: `data > 저장과 화면 반영`
- Given: 앱에 메모 목록이 열려 있고 연결이 동작 중이다.
- When: AI 도구가 메모를 추가한다.
- Then: 메모 목록은 새로고침 없이 추가된 메모를 보여 준다.
- 작성하지 않는 이유: 실제 앱 화면과 연결을 함께 띄워야 관찰할 수 있는 통합 동작이다. AI 도구는 화면과 같은 앱 기능을 부르므로, 앱 기능이 바꾼 내용을 화면이 바로 보여 주는 것은 각 목록 화면의 테스트 케이스가 다룬다.
