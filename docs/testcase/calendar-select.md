# Calendar 날짜 선택 테스트 케이스

기준 스펙: [Calendar 날짜 선택 스펙](../spec/client/calendar-select.md)

아래 케이스는 한 달의 주를 모두 보여 주며 달을 넘겨 보는 화면에 배치한 경우를 기준으로 한다. 선택 영역의 주가 고정된 목록에 배치한 경우의 선택 영역 범위와 화면 이동 없음은 [HolidayHome 테스트 케이스](holiday-home.md)에서 다룬다.

## feature

### TC-CALENDAR-SELECT-FEATURE-001: 날짜 하나에서 선택을 시작하면 그 날짜 하루가 선택된다

- 근거: `feature > 선택 시작`
- Given: 날짜 선택을 사용하는 캘린더에 2026년 7월이 표시되어 있다.
- When: 사용자가 7월 15일에서 날짜 선택을 시작한다.
- Then: 7월 15일부터 7월 15일까지 하루가 선택된다.

### TC-CALENDAR-SELECT-FEATURE-002: 처음 날짜보다 이후 날짜로 기간을 확장하면 처음 날짜부터 현재 날짜까지 선택된다

- 근거: `feature > 기간 확장`
- Given: 날짜 선택을 사용하는 캘린더에 2026년 7월이 표시되어 있다.
- When: 사용자가 7월 14일에서 선택을 시작하고 현재 날짜를 같은 주의 7월 17일로 바꾼다.
- Then: 7월 14일부터 7월 17일까지가 선택된다.

### TC-CALENDAR-SELECT-FEATURE-003: 처음 날짜보다 이전 날짜로 기간을 확장하면 현재 날짜부터 처음 날짜까지 선택된다

- 근거: `feature > 기간 확장`
- Given: 날짜 선택을 사용하는 캘린더에 2026년 7월이 표시되어 있다.
- When: 사용자가 7월 17일에서 선택을 시작하고 현재 날짜를 같은 주의 7월 14일로 바꾼다.
- Then: 7월 14일부터 7월 17일까지가 선택된다.

### TC-CALENDAR-SELECT-FEATURE-004: 주 경계를 넘어 기간을 확장하면 여러 주에 걸친 기간이 선택된다

- 근거: `feature > 기간 확장`
- Given: 날짜 선택을 사용하는 캘린더에 2026년 7월이 표시되어 있다.
- When: 사용자가 7월 15일에서 선택을 시작하고 현재 날짜를 다음 주의 7월 22일로 바꾼다.
- Then: 7월 15일부터 7월 22일까지가 선택된다.

### TC-CALENDAR-SELECT-FEATURE-005: 선택 중 현재 날짜가 바뀌면 선택이 즉시 갱신된다

- 근거: `feature > 기간 확장`
- Given: 날짜 선택을 사용하는 캘린더에 2026년 7월이 표시되어 있고, 사용자가 7월 14일에서 선택을 시작해 현재 날짜를 7월 17일로 바꿔 7월 14일부터 7월 17일까지가 선택되어 있다.
- When: 사용자가 선택을 완료하지 않은 채 현재 날짜를 7월 15일로 바꾼다.
- Then: 선택이 7월 14일부터 7월 15일까지로 갱신된다.

### TC-CALENDAR-SELECT-FEATURE-006: 선택을 완료하면 그 시점의 기간이 전달된다

- 근거: `feature > 선택 완료`
- Given: 날짜 선택을 사용하는 캘린더에 2026년 7월이 표시되어 있다.
- When: 사용자가 7월 14일부터 7월 17일까지를 선택하고 선택을 완료한다.
- Then: 7월 14일부터 7월 17일까지의 기간으로 선택 완료가 배치하는 화면에 한 번 전달된다.

### TC-CALENDAR-SELECT-FEATURE-007: 기간을 확장하지 않고 완료하면 하루짜리 기간이 전달된다

- 근거: `feature > 선택 완료`
- Given: 날짜 선택을 사용하는 캘린더에 2026년 7월이 표시되어 있다.
- When: 사용자가 7월 15일에서 선택을 시작하고 기간을 확장하지 않은 채 완료한다.
- Then: 7월 15일부터 7월 15일까지의 기간으로 선택 완료가 배치하는 화면에 한 번 전달된다.

### TC-CALENDAR-SELECT-FEATURE-008: 배치하는 화면이 선택을 해제하면 선택된 기간이 없는 상태가 된다

- 근거: `feature > 선택 중단`
- Given: 날짜 선택을 사용하는 캘린더에 기간이 선택되어 있다.
- When: 배치하는 화면이 선택을 해제한다.
- Then: 선택된 기간이 없는 상태가 된다.

### TC-CALENDAR-SELECT-FEATURE-014: 선택 중 시스템이 조작을 중단하면 그 시점의 기간으로 선택이 완료된다

- 근거: `feature > 선택 중단`
- Given: 날짜 선택을 사용하는 캘린더에 2026년 7월이 표시되어 있고, 사용자가 7월 14일에서 선택을 시작해 손을 떼지 않은 채 7월 17일까지 기간을 확장했다.
- When: 화면 상태를 저장하지 않은 채 시스템이 선택 조작을 끊는다.
- Then: 7월 14일부터 7월 17일까지의 기간으로 선택 완료가 배치하는 화면에 한 번 전달된다.

### TC-CALENDAR-SELECT-FEATURE-009: 선택 중 오른쪽 가장자리 영역에 머무르면 다음 달로 이동하고 선택이 유지된다

- 근거: `feature > 선택 중 달 이동`
- Given: 날짜 선택을 사용하는 캘린더에 2026년 7월이 표시되어 있다.
- When: 사용자가 7월 15일에서 선택을 시작하고 현재 가리키는 위치를 오른쪽 가장자리 영역으로 옮겨 머무른다.
- Then: 캘린더가 2026년 8월로 이동하고, 선택은 중단되지 않으며 7월 15일부터 이동한 달에서 가리키는 날짜까지로 기간이 갱신된다.

### TC-CALENDAR-SELECT-FEATURE-010: 가장자리 영역에 머무는 동안 달 이동이 반복된다

- 근거: `feature > 선택 중 달 이동`
- Given: 날짜 선택을 사용하는 캘린더에 2026년 7월이 표시되어 있고, 사용자가 7월 15일에서 선택을 시작해 오른쪽 가장자리 영역에 머물러 2026년 8월로 이동한 상태다.
- When: 사용자가 달 전환이 끝난 뒤에도 오른쪽 가장자리 영역에 계속 머무른다.
- Then: 캘린더가 2026년 9월로 한 번 더 이동하고 선택은 유지된다.

### TC-CALENDAR-SELECT-FEATURE-011: 날짜 선택을 시작하면 촉각 피드백을 받는다

- 근거: `feature > 선택 피드백`
- Given: 촉각 피드백을 제공하도록 설정된 기기에서 날짜 선택을 사용하는 캘린더에 2026년 7월이 표시되어 있다.
- When: 사용자가 7월 15일에서 날짜 선택을 시작한다.
- Then: 선택 시작을 알리는 촉각 피드백이 한 번 제공된다.

### TC-CALENDAR-SELECT-FEATURE-012: 드래그로 선택 기간이 달라지면 추가 촉각 피드백을 받는다

- 근거: `feature > 선택 피드백`
- Given: 촉각 피드백을 제공하도록 설정된 기기의 캘린더에서 사용자가 7월 14일의 선택을 시작해 선택 시작 촉각 피드백을 받은 상태다.
- When: 사용자가 현재 날짜를 7월 17일로 바꿔 선택 기간이 7월 14일부터 7월 17일까지로 달라진다.
- Then: 선택 기간 변경을 알리는 촉각 피드백이 한 번 더 제공된다.

### TC-CALENDAR-SELECT-FEATURE-013: 드래그해도 선택 기간이 그대로이면 추가 촉각 피드백을 받지 않는다

- 근거: `feature > 선택 피드백`
- Given: 촉각 피드백을 제공하도록 설정된 기기의 캘린더에서 사용자가 7월 14일부터 7월 17일까지를 선택해 해당 선택 기간의 촉각 피드백까지 받은 상태다.
- When: 사용자가 7월 17일 날짜 칸 안에서 드래그해 선택 기간이 그대로 유지된다.
- Then: 추가 촉각 피드백이 제공되지 않는다.

## domain

### TC-CALENDAR-SELECT-DOMAIN-001: 이웃 달에 속한 날짜 칸도 실제 날짜 그대로 선택된다

- 근거: `domain > 선택 가능한 날짜`
- Given: 날짜 선택을 사용하는 캘린더에 2026년 7월이 표시되어 있다. 2026년 7월 화면의 첫 주에는 6월 28일부터 6월 30일까지가 이웃 달 날짜로 표시된다.
- When: 사용자가 6월 29일에서 선택을 시작하고 완료한다.
- Then: 6월 29일부터 6월 29일까지 하루가 선택되어 완료된다.

### TC-CALENDAR-SELECT-DOMAIN-003: 날짜 선택을 사용하지 않는 화면에서는 선택이 시작되지 않는다

- 근거: `domain > 선택 사용 여부`
- Given: 날짜 선택을 사용하지 않는 캘린더에 2026년 7월이 표시되어 있다.
- When: 사용자가 7월 15일부터 7월 17일까지의 날짜 선택을 시도한다.
- Then: 선택된 기간이 생기지 않는다.

### TC-CALENDAR-SELECT-DOMAIN-004: 가장자리 영역 밖에서는 선택 드래그로 달이 이동하지 않는다

- 근거: `domain > 선택 중 달 이동 기준`
- Given: 날짜 선택을 사용하는 캘린더에 2026년 7월이 표시되어 있다.
- When: 사용자가 7월 15일에서 선택을 시작하고 가장자리 영역에 들어가지 않은 채 현재 날짜를 바꾼다.
- Then: 캘린더는 2026년 7월을 그대로 유지한다.

### TC-CALENDAR-SELECT-DOMAIN-005: 왼쪽 가장자리 영역에 머무르면 이전 달로 이동한다

- 근거: `domain > 선택 중 달 이동 기준`
- Given: 날짜 선택을 사용하는 캘린더에 2026년 7월이 표시되어 있다.
- When: 사용자가 7월 15일에서 선택을 시작하고 현재 가리키는 위치를 왼쪽 가장자리 영역으로 옮겨 머무른다.
- Then: 캘린더가 2026년 6월로 이동하고 선택은 유지된다.

### TC-CALENDAR-SELECT-DOMAIN-006: 이동 범위를 벗어나는 방향으로는 이동하지 않고 선택이 유지된다

- 근거: `domain > 선택 중 달 이동 기준`
- Given: 날짜 선택을 사용하는 캘린더에 이동 범위의 첫 달인 1년 1월이 표시되어 있다.
- When: 사용자가 1년 1월 15일에서 선택을 시작하고 현재 가리키는 위치를 같은 주 일요일인 1월 14일 칸의 왼쪽 가장자리 영역으로 옮겨 머무른다.
- Then: 캘린더는 1년 1월을 그대로 유지하고, 선택은 중단되지 않으며 가리키는 날짜를 기준으로 1월 14일부터 1월 15일까지로 갱신된다.

### TC-CALENDAR-SELECT-DOMAIN-007: 선택 중 화면이 재생성되면 선택이 유지되지 않는다

- 근거: `domain > 유지 경계`
- Given: 날짜 선택을 사용하는 캘린더에 2026년 7월이 표시되어 있고, 사용자가 7월 14일에서 선택을 시작해 7월 17일까지 기간을 확장한 채 손을 떼지 않았다.
- When: 화면이 재생성된다.
- Then: 선택된 기간이 없는 상태가 된다.

### TC-CALENDAR-SELECT-DOMAIN-009: 선택 중 화면이 재생성되면 선택이 취소되고 선택 완료가 전달되지 않는다

- 근거: `domain > 유지 경계`, `feature > 선택 중단`
- Given: 날짜 선택을 사용하는 캘린더에 2026년 7월이 표시되어 있고, 사용자가 7월 14일에서 선택을 시작해 7월 17일까지 기간을 확장한 채 손을 떼지 않았다.
- When: 화면이 재생성된다.
- Then: 선택 완료가 배치하는 화면에 전달되지 않는다.

### TC-CALENDAR-SELECT-DOMAIN-010: 선택 중 앱이 백그라운드로 이동하면 그 시점의 기간으로 선택이 완료된다

- 근거: `domain > 유지 경계`, `feature > 선택 중단`
- Given: 날짜 선택을 사용하는 캘린더에 2026년 7월이 표시되어 있고, 사용자가 7월 14일에서 선택을 시작해 7월 17일까지 기간을 확장한 채 손을 떼지 않았다.
- When: 앱이 백그라운드로 이동해 화면 상태가 저장되고, 화면은 그대로 남은 채 선택 조작이 끊긴다.
- Then: 7월 14일부터 7월 17일까지의 기간으로 선택 완료가 배치하는 화면에 한 번 전달된다.

### TC-CALENDAR-SELECT-DOMAIN-011: 선택 중 화면을 벗어나면 그 시점의 기간으로 선택이 완료된다

- 근거: `domain > 유지 경계`, `feature > 선택 중단`
- Given: 날짜 선택을 사용하는 캘린더에 2026년 7월이 표시되어 있고, 사용자가 7월 14일에서 선택을 시작해 7월 17일까지 기간을 확장한 채 손을 떼지 않았다.
- When: 화면 상태를 저장하지 않은 채 캘린더가 화면에서 사라진다.
- Then: 7월 14일부터 7월 17일까지의 기간으로 선택 완료가 배치하는 화면에 한 번 전달된다.

### TC-CALENDAR-SELECT-DOMAIN-012: 캘린더 밖의 위치는 가장 가까운 날짜 칸을 가리킨다

- 근거: `domain > 선택 가능한 날짜`
- Given: 날짜 선택을 사용하는 캘린더에 2026년 7월이 표시되어 있다. 2026년 7월 화면의 마지막 주는 8월 2일부터 8월 8일까지다.
- When: 사용자가 7월 15일 수요일에서 선택을 시작해, 가리키는 위치를 같은 세로줄을 따라 캘린더 아래쪽 밖으로 옮긴 뒤 완료한다.
- Then: 캘린더 안에서 가장 가까운 날짜 칸인 마지막 주 수요일까지를 선택해, 7월 15일부터 8월 5일까지의 기간으로 선택 완료가 전달된다.

## 작성하지 않는 이유

- 선택 기간의 구체적인 시각 표현은 디자인 문서의 책임이며 실제 색상과 그리기 위치를 판정해야 하므로 블랙박스 유닛 테스트 케이스로 작성하지 않는다. 테마별 기준 이미지를 비교할 수 있는 스크린샷 테스트 환경이 갖춰지면 검증한다. 선택된 기간 자체가 맞는지는 TC-CALENDAR-SELECT-FEATURE-001부터 TC-CALENDAR-SELECT-FEATURE-005로 확인한다.
- 앱을 다시 실행했을 때 이전 선택을 복원하지 않는 동작은 컴포넌트 단독 테스트에서 선택을 유지한 채 앱 프로세스를 다시 시작하는 실행 경계를 재현할 수 없어 작성하지 않는다. 앱 프로세스 재시작을 제어할 수 있는 테스트 환경이 갖춰지면 자동화한다. 화면 재생성은 TC-CALENDAR-SELECT-DOMAIN-007과 TC-CALENDAR-SELECT-DOMAIN-009가, 백그라운드 이동과 화면 이탈은 TC-CALENDAR-SELECT-DOMAIN-010과 TC-CALENDAR-SELECT-DOMAIN-011이 확인한다.
- 날짜 선택을 사용하지 않는 화면은 선택 완료를 전달받을 곳을 두지 않으므로, 선택 완료가 전달되지 않는다는 결과는 따로 관찰할 수 없다. 선택된 기간이 생기지 않는 결과는 TC-CALENDAR-SELECT-DOMAIN-003이 확인한다.
