# TagAdd 테스트 케이스

기준 스펙: [TagAdd 화면 스펙](../spec/client/tag-add.md)

이 문서에서 `domain > 추가 요청 제한`, `domain > 항목의 계정 연결`, `feature > 뒤로가기`, `feature > 작성 상태 유지`, `data > 동기화` 절은 [항목 추가 화면 공통 스펙](../spec/client/entity-add.md)이 소유한다. 나머지 케이스의 절은 기준 스펙이 소유한다.

연결 입력의 표시와 조작, 태그 선택 목록의 케이스는 [태그 연결 입력 컴포넌트 테스트 케이스](./tag-link-input.md)에서 다룬다. 이 문서에는 TagAdd 화면에서만 다른 시작 상태와 추가 결과의 케이스만 둔다.

## feature

### TC-TAG-ADD-FEATURE-001: TagHome에서 태그 추가 행동을 실행하면 TagAdd 화면으로 이동한다

- 근거: `feature > 진입과 입력`
- Given: TagHome 화면이 표시되어 있다.
- When: 사용자가 태그 추가를 선택한다.
- Then: TagAdd 화면이 표시된다.

### TC-TAG-ADD-FEATURE-006: 뒤로가면 이전 화면으로 돌아간다

- 근거: `feature > 뒤로가기`
- Given: TagAdd 화면이 표시되어 있다.
- When: 사용자가 뒤로간다.
- Then: TagAdd 화면에 진입하기 전 화면으로 돌아간다.

### TC-TAG-ADD-FEATURE-007: 추가에 성공하면 다음 태그를 작성할 수 있는 상태로 초기화한다

- 근거: `feature > 태그 추가`
- Given: 태그 추가가 성공하도록 설정되어 있고, 이모지, 제목과 설명을 입력하고 컬러를 선택한 상태다.
- When: 사용자가 태그 추가를 실행한다.
- Then: TagAdd 화면이 유지되고 이모지, 제목과 설명이 비워지며 다음 태그를 위한 새 무작위 컬러가 제시된다.

### TC-TAG-ADD-FEATURE-018: 화면에 진입하면 연결을 하나도 고르지 않은 상태로 시작한다

- 근거: `feature > 태그 연결 입력`
- Given: 계정과 연결된 태그가 여러 개 저장되어 있다.
- When: 사용자가 TagAdd 화면에 진입한다.
- Then: 연결 입력에 연결 대상으로 표시되는 태그가 없다.

### TC-TAG-ADD-FEATURE-019: 연결을 골라도 저장된 태그의 연결은 바뀌지 않는다

- 근거: `feature > 태그 연결 입력`
- Given: 계정과 연결된 태그가 여러 개 저장되어 있고 TagAdd 화면이 표시되어 있다.
- When: 사용자가 태그 선택 목록에서 태그를 고른다.
- Then: 연결 입력에는 고른 태그가 표시되지만 저장된 태그 연결은 만들어지지 않는다.

### TC-TAG-ADD-FEATURE-020: 추가에 성공하면 고른 연결도 비운다

- 근거: `feature > 태그 추가`
- Given: 태그 추가가 성공하도록 설정되어 있고, 제목을 입력하고 연결할 태그를 고른 상태다.
- When: 사용자가 태그 추가를 실행한다.
- Then: 연결 입력에 연결 대상으로 표시되는 태그가 없다.

### TC-TAG-ADD-FEATURE-021: 연결 입력에서 태그 추가로 이동하면 TagAdd 화면이 하나 더 열린다

- 근거: `feature > 진입과 입력`, `feature > 연결 입력의 태그 추가 이동`
- Given: TagAdd 화면에서 이모지, 제목, 설명을 입력하고 연결할 태그를 하나 골랐다.
- When: 사용자가 연결 입력에서 태그 추가로 이동해 아무것도 추가하지 않고 돌아온다.
- Then: 이동하기 전에 입력한 내용과 고른 연결이 그대로 유지된다.

### TC-TAG-ADD-FEATURE-022: 연결 입력에서 이동해 추가한 태그가 연결 대상으로 선택된다

- 근거: `feature > 연결 입력의 태그 추가 이동`
- Given: TagAdd 화면에서 연결 입력의 태그 추가로 이동해 태그를 추가했다.
- When: 사용자가 먼저 있던 TagAdd 화면으로 돌아온다.
- Then: 추가한 태그가 그 화면의 연결 대상으로 표시된다.

### TC-TAG-ADD-FEATURE-023: 이 화면에서 추가한 태그는 연결 대상으로 선택되지 않는다

- 근거: `feature > 연결 입력의 태그 추가 이동`, `feature > 태그 추가 결과를 돌려줄 곳`
- Given: TagAdd 화면에서 제목을 입력했다.
- When: 사용자가 이 화면에서 태그 추가를 실행해 추가에 성공한다.
- Then: 방금 추가한 태그가 이 화면의 연결 대상으로 표시되지 않고 연결이 비어 있는 상태로 유지된다.

### TC-TAG-ADD-FEATURE-008: 추가에 성공하면 성공 피드백을 제공한다

- 근거: `feature > 태그 추가`
- Given: 태그 추가가 성공하도록 설정되어 있고 공백이 아닌 제목이 입력되어 있다.
- When: 사용자가 태그 추가를 실행한다.
- Then: 태그가 추가되었다는 성공 피드백이 제공된다.

### TC-TAG-ADD-FEATURE-009: 추가를 처리하는 동안 진행 상태를 표시한다

- 근거: `feature > 태그 추가`
- Given: 태그 추가 처리가 완료되지 않고 진행 중인 상태로 설정되어 있고, 공백이 아닌 제목이 입력되어 있다.
- When: 사용자가 태그 추가를 실행한 뒤 화면을 확인한다.
- Then: 추가 처리가 끝날 때까지 진행 상태가 표시된다.

### TC-TAG-ADD-FEATURE-010: 제목을 입력하지 않으면 작성 내용을 유지한다

- 근거: `feature > 제목 미입력`
- Given: 제목이 테스트 데이터의 상태이고, 이모지와 설명을 입력하고 컬러를 선택한 TagAdd 화면이 표시되어 있다.
- When: 사용자가 태그 추가를 실행한다.
- Then: 태그가 추가되지 않고 이모지, 제목, 설명, 컬러와 고른 연결이 지워지거나 바뀌지 않는다.
- 테스트 데이터:

| 제목 상태 |
| --- |
| 비어 있음 |
| 공백 문자만 입력됨 |

### TC-TAG-ADD-FEATURE-011: 제목이 없으면 제목 입력 필요 피드백을 제공한다

- 근거: `feature > 제목 미입력`
- Given: 제목이 비어 있거나 공백 문자만 입력되어 있다.
- When: 사용자가 태그 추가를 실행한다.
- Then: 제목 입력이 필요하다는 피드백이 제공된다.

### TC-TAG-ADD-FEATURE-012: 화면이 회전해도 작성 중인 내용을 유지한다

- 근거: `feature > 작성 상태 유지`
- Given: TagAdd 화면에서 이모지, 제목과 설명을 입력하고 컬러를 선택하고 연결할 태그를 고른 상태다.
- When: 화면이 회전하거나 창 크기가 바뀐다.
- Then: 이전의 이모지, 제목, 설명, 선택한 컬러와 고른 연결이 그대로 표시된다.

### TC-TAG-ADD-FEATURE-025: 메모리 정리 뒤 복원하면 입력 내용은 복원하고 고른 연결은 복원하지 않는다

- 근거: `feature > 작성 상태 유지 대상`
- Given: TagAdd 화면에서 이모지, 제목과 설명을 입력하고 컬러를 선택하고 연결할 태그를 고른 상태다.
- When: 시스템이 앱을 메모리에서 정리한 뒤 화면을 복원한다.
- Then: 이모지, 제목, 설명과 선택한 컬러는 복원되고, 고른 연결은 복원되지 않아 연결을 하나도 고르지 않은 상태로 시작한다.

### TC-TAG-ADD-FEATURE-014: 이모지 입력에는 문자 하나만 남는다

- 근거: `domain > 태그 이모지`
- Given: TagAdd 화면이 표시되어 있고 이모지 입력이 비어 있다.
- When: 사용자가 이모지 입력에 테스트 데이터의 값을 입력한다.
- Then: 이모지 입력에는 테스트 데이터의 남는 값만 표시된다.
- 테스트 데이터:

| 입력한 값 | 남는 값 |
| --- | --- |
| 이모지 한 개 | 입력한 이모지 |
| 여러 코드가 모여 하나로 보이는 이모지 한 개 | 입력한 이모지 전체 |
| 이모지 두 개를 이어 입력 | 두 번째 이모지 |
| 여러 글자로 된 문자열 | 마지막 글자 |
| 이모지가 아닌 문자 한 개 | 입력한 문자 |

### TC-TAG-ADD-FEATURE-024: 이모지 입력에 문자가 있으면 새로 입력한 문자로 대체된다

- 근거: `domain > 태그 이모지`
- Given: TagAdd 화면의 이모지 입력에 이모지 한 개가 입력되어 있다.
- When: 사용자가 이모지 입력에 다른 이모지 한 개를 이어서 입력한다.
- Then: 이모지 입력에는 새로 입력한 이모지만 표시되고 이전 이모지는 남지 않는다.

### TC-TAG-ADD-FEATURE-013: 앱을 다시 실행한 뒤 새로 진입하면 새로운 입력 상태로 시작한다

- 근거: `feature > 작성 상태 유지`
- Given: TagAdd 화면에서 제목과 설명을 입력하고 컬러를 선택한 뒤 앱을 종료했다.
- When: 사용자가 앱을 다시 실행하고 TagAdd 화면에 새로 진입한다.
- Then: 이전 제목과 설명은 표시되지 않고 새로운 무작위 컬러가 제시된다.
- 작성하지 않는 이유: 실제 앱 종료와 재실행을 결정적으로 제어할 수 있는 테스트 환경이 필요하다.

### TC-TAG-ADD-FEATURE-015: 화면에 처음 진입하면 제목 입력에 초점이 있다

- 근거: `feature > 진입과 입력`
- Given: 사용자가 태그 추가를 선택했다.
- When: TagAdd 화면이 처음 표시된다.
- Then: 입력 초점이 제목 입력에 있고 이모지 입력에는 없다.

### TC-TAG-ADD-FEATURE-016: 추가에 성공하면 제목 입력으로 초점을 옮긴다

- 근거: `feature > 태그 추가`
- Given: 태그 추가가 성공하도록 설정되어 있고, 공백이 아닌 제목이 입력되어 있다.
- When: 사용자가 태그 추가를 실행한다.
- Then: 입력 초점이 제목 입력으로 옮겨진다.

### TC-TAG-ADD-FEATURE-017: 제목 미입력으로 추가하면 제목 입력으로 초점을 옮긴다

- 근거: `feature > 제목 미입력`
- Given: 제목이 비어 있고 설명을 입력해 설명 입력에 초점이 있는 TagAdd 화면이 표시되어 있다.
- When: 사용자가 태그 추가를 실행한다.
- Then: 입력 초점이 제목 입력으로 옮겨진다.

## domain

### TC-TAG-ADD-DOMAIN-001: 제목이 없으면 태그를 추가하지 않는다

- 근거: `domain > 태그 추가 성립 조건`
- Given: 태그를 추가할 수 있는 상태다.
- When: 제목이 테스트 데이터인 상태로 태그 추가를 실행한다.
- Then: 태그 추가가 성립하지 않고 새 태그가 저장되지 않는다.
- 테스트 데이터:

| 제목 |
| --- |
| 빈 문자열 |
| 공백 문자로만 이루어진 값 |

### TC-TAG-ADD-DOMAIN-003: 이모지를 입력하지 않아도 태그를 추가할 수 있다

- 근거: `domain > 태그 추가 성립 조건`
- Given: 현재 계정이 있고 이모지 입력이 비어 있다.
- When: 공백이 아닌 제목으로 태그 추가를 실행한다.
- Then: 태그 추가가 성립하고 이모지가 비어 있는 태그가 저장된다.

### TC-TAG-ADD-DOMAIN-004: 연결 대상으로 표시하는 태그는 연결할 수 있는 태그와 같다

- 근거: `domain > 연결 대상 선택과 태그 추가 성립 조건`
- Given: TagAdd 화면에서 태그 하나를 연결 대상으로 골랐다.
- When: 그 태그가 완료되거나 삭제된다.
- Then: 연결 입력에서 그 태그가 제외된 것으로 표시된다.

### TC-TAG-ADD-DOMAIN-009: 설명을 입력하지 않아도 태그를 추가할 수 있다

- 근거: `domain > 태그 추가 성립 조건`, `domain > 추가되는 태그의 내용`
- Given: 현재 계정이 있고, 공백이 아닌 제목을 입력했으며 설명은 비어 있다.
- When: 사용자가 태그 추가를 실행한다.
- Then: 태그가 추가되고, 저장된 태그의 설명은 빈 값이다.

### TC-TAG-ADD-DOMAIN-005: 태그를 하나도 연결하지 않아도 태그를 추가할 수 있다

- 근거: `domain > 연결 대상 선택과 태그 추가 성립 조건`
- Given: 제목을 입력하고 연결할 태그를 하나도 고르지 않았다.
- When: 사용자가 태그 추가를 실행한다.
- Then: 태그가 추가되고 연결은 하나도 만들어지지 않는다.

### TC-TAG-ADD-DOMAIN-007: 추가 결과는 이 화면을 연 태그 입력에만 돌려준다

- 근거: `feature > 태그 추가 결과를 돌려줄 곳`
- Given: 태그 입력에서 이동해 연 TagAdd 화면이 표시되어 있다.
- When: 사용자가 태그를 테스트 데이터만큼 추가한다.
- Then: 추가한 태그가 모두 그 태그 입력에만 결과로 전달되고 다른 태그 입력에는 전달되지 않는다.
- 테스트 데이터:

| 추가한 태그 |
| --- |
| 한 개 |
| 여러 개 |

### TC-TAG-ADD-DOMAIN-008: 태그 입력에서 열지 않은 화면의 추가 결과는 어디에도 전달되지 않는다

- 근거: `feature > 태그 추가 결과를 돌려줄 곳`
- Given: 태그 목록에서 열어 돌려줄 곳이 없는 TagAdd 화면이 표시되어 있다.
- When: 사용자가 태그를 추가한다.
- Then: 추가한 태그가 어느 태그 입력에도 결과로 전달되지 않는다.

### TC-TAG-ADD-DOMAIN-002: 추가를 처리하는 동안 전달된 추가 요청은 처리하지 않는다

- 근거: `domain > 추가 요청 제한`
- Given: 앞선 태그 추가가 아직 처리 중이고, 공백이 아닌 제목이 입력되어 있다.
- When: 같은 화면에서 태그 추가 요청이 한 번 더 전달된다.
- Then: 추가 요청이 한 번만 처리되어 같은 입력으로 태그가 중복 저장되지 않는다.

### TC-TAG-ADD-DOMAIN-006: 현재 계정을 확인할 수 없으면 태그를 추가하지 않는다

- 근거: `domain > 항목의 계정 연결`
- Given: 현재 계정 조회가 실패하도록 설정되어 있다.
- When: 공백이 아닌 제목으로 태그 추가를 실행한다.
- Then: 태그가 기록되지 않고 계정 조회의 실패가 그대로 전달된다.

## data

### TC-TAG-ADD-DATA-001: 유효한 제목으로 추가하면 현재 계정과 연결된 고유한 태그로 저장된다

- 근거: `data > 태그 생성과 저장`, `domain > 추가되는 태그의 내용`, `domain > 항목의 계정 연결`
- Given: 현재 계정이 있고, 공백이 아닌 제목으로 태그 추가를 실행할 수 있다.
- When: 사용자가 태그 추가를 실행한다.
- Then: 새 태그 한 건이 현재 계정과 연결되어 기기에 저장되며, 저장된 태그는 기존 태그를 덮어쓰지 않고 다른 태그와 겹치지 않는 새 태그로 만들어진다.

### TC-TAG-ADD-DATA-002: 입력한 이모지, 제목, 설명, 컬러가 저장된 태그에 포함된다

- 근거: `data > 태그 생성과 저장`, `domain > 추가되는 태그의 내용`
- Given: 현재 계정이 있고, 입력한 이모지와 공백이 아닌 제목, 입력한 설명, 선택한 컬러로 태그 추가를 실행할 수 있다.
- When: 사용자가 해당 이모지, 제목, 설명, 컬러로 태그 추가를 실행한다.
- Then: 저장된 태그에 입력한 이모지, 제목, 설명, 선택한 컬러가 그대로 포함된다.

### TC-TAG-ADD-DATA-004: 고른 태그로 향하는 연결이 새 태그와 함께 저장된다

- 근거: `data > 태그 생성과 저장`, `domain > 추가되는 태그의 연결`
- Given: 계정과 연결된 태그 여러 개가 저장되어 있고 제목을 입력한 뒤 그중 두 태그를 연결 대상으로 골랐다.
- When: 사용자가 태그 추가를 실행한다.
- Then: 추가된 태그를 출발 태그로 하는 연결된 태그를 조회하면 고른 두 태그가 조회되고, 고르지 않은 태그는 조회되지 않는다.

### TC-TAG-ADD-DATA-005: 고른 뒤 완료되거나 삭제된 태그도 그대로 연결된다

- 근거: `domain > 추가되는 태그의 연결`
- Given: 제목을 입력하고 태그 하나를 연결 대상으로 고른 뒤 그 태그가 완료된다.
- When: 사용자가 태그 추가를 실행한다.
- Then: 추가된 태그를 출발 태그로 하는 연결된 태그를 조회하면 그 태그가 조회된다.

### TC-TAG-ADD-DATA-006: 태그와 연결이 하나의 저장 작업으로 반영된다

- 근거: `data > 태그 생성과 저장`
- Given: 제목을 입력하고 태그 두 개를 연결 대상으로 골랐다.
- When: 사용자가 태그 추가를 실행한다.
- Then: 태그와 계정 연결, 고른 태그로 향하는 연결이 한 번의 저장 작업으로 함께 반영된다.

### TC-TAG-ADD-DATA-003: 새 태그의 초기 상태와 시각을 기록한다

- 근거: `domain > 추가되는 태그의 내용`
- Given: 현재 계정이 있고, 공백이 아닌 제목으로 태그 추가를 실행할 수 있다.
- When: 사용자가 태그 추가를 실행한다.
- Then: 저장된 태그는 미완료·미삭제 상태이며, 생성 시각과 수정 시각은 태그를 추가한 시각과 같다.

### TC-TAG-ADD-DATA-007: 기기에 저장이 끝나면 태그와 연결이 업로드 대기로 기록되고 동기화가 시작된다

- 근거: `data > 동기화`
- Given: 로그인한 사용자 계정이 있고, 연결할 태그를 하나 고른 상태이며 기기 저장이 성공한다.
- When: 사용자가 태그 추가를 실행한다.
- Then: 새 태그와 고른 태그로 향하는 연결이 계정의 업로드 대기로 기록되고, 저장이 끝난 뒤 백그라운드 동기화가 한 번 요청된다.

### TC-TAG-ADD-DATA-008: 컬러를 바꾸지 않으면 처음 제시한 컬러로 추가된다

- 근거: `domain > 추가되는 태그의 내용`
- Given: TagAdd 화면에 처음 진입해 컬러 입력에 무작위 컬러가 제시되어 있고, 사용자는 컬러를 바꾸지 않은 채 제목만 입력했다.
- When: 사용자가 태그 추가를 실행한다.
- Then: 처음 제시된 컬러로 태그 추가가 요청된다.
