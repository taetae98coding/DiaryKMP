# SearchHome 테스트 케이스

기준 스펙: [SearchHome 화면 스펙](../spec/client/search-home.md)

자리 표시 케이스의 `근거`가 가리키는 절은 공통 규칙을 [페이지 조회 목록의 자리 표시 스펙](../spec/client/paged-list-placeholder.md)에, 결과 없음 안내 케이스의 `근거`가 가리키는 절은 [목록 빈 상태 스펙](../spec/client/list-empty-state.md)에 위임한다.

`더보기`에서 `검색` 항목을 선택하는 케이스는 [MoreHome 테스트 케이스](./more-home.md)에서, 목록 화면에서 검색을 선택하는 케이스는 [MemoHome 목록 테스트 케이스](./memo-home.md), [TagHome 목록 테스트 케이스](./tag-home.md), [PlaceHome 테스트 케이스](./place-home.md), [WebHome 테스트 케이스](./web-home.md)에서 다룬다. 이동한 상세 화면의 내용과 수정·삭제 케이스는 [MemoDetail 테스트 케이스](./memo-detail.md), [TagDetail 테스트 케이스](./tag-detail.md), [PlaceDetail 테스트 케이스](./place-detail.md)에서 다룬다.

## feature

### TC-SEARCH-HOME-FEATURE-001: 진입하면 질의가 비어 있고 네 유형의 결과가 모두 비어 있다

- 근거: `feature > 진입과 검색`
- Given: 저장된 메모, 태그, 장소, 웹 항목이 있다.
- When: 사용자가 SearchHome 화면에 진입한다.
- Then: 검색어 입력이 비어 있고 메모, 태그, 장소, 웹 네 유형의 결과에 항목이 하나도 표시되지 않는다.

### TC-SEARCH-HOME-FEATURE-002: 질의를 입력하면 확정 동작 없이 그 질의로 검색된다

- 근거: `feature > 진입과 검색`
- Given: SearchHome 화면이 표시되어 있고 질의가 비어 있다.
- When: 사용자가 검색어 입력에 `여행`을 입력하고 입력을 멈춘다.
- Then: 사용자가 검색을 확정하는 별도 동작을 하지 않아도 `여행`을 기준으로 한 결과가 표시된다.

### TC-SEARCH-HOME-FEATURE-023: 질의가 결과에 반영되기 전에는 결과 없음을 알리지 않는다

- 근거: `feature > 빈 결과와 실패`, `domain > 결과 없음 판정`
- Given: SearchHome 화면이 표시되어 있고 질의가 비어 결과가 하나도 없다.
- When: 사용자가 질의를 입력하고 그 질의가 결과에 반영되기 전 상태를 확인한다.
- Then: 결과 없음 안내가 표시되지 않는다.

### TC-SEARCH-HOME-FEATURE-003: 질의를 바꾸면 결과가 새 질의 기준으로 바뀐다

- 근거: `feature > 진입과 검색`, `domain > 결과 갱신`
- Given: 질의 `여행`의 결과가 표시되어 있다.
- When: 사용자가 질의를 `회의`로 바꾼다.
- Then: 보고 있는 유형의 결과가 `회의` 기준으로 바뀌고, 다른 유형으로 바꿔도 `회의` 기준의 결과가 표시된다.

### TC-SEARCH-HOME-FEATURE-026: 질의를 바꾸면 결과 목록의 처음부터 본다

- 근거: `feature > 진입과 검색`
- Given: 질의의 결과를 목록 아래쪽까지 내려 보고 있다.
- When: 사용자가 질의를 다른 질의로 바꾼다.
- Then: 결과 목록의 첫 항목부터 보인다.

### TC-SEARCH-HOME-FEATURE-027: 검색어가 그대로면 보던 자리를 유지한다

- 근거: `feature > 진입과 검색`
- Given: 질의 `여행`의 결과를 목록 아래쪽까지 내려 보고 있다.
- When: 사용자가 질의 끝에 글자를 하나 더 입력했다가, 그 질의가 결과에 반영되기 전에 그 글자를 지워 `여행`으로 되돌린다.
- Then: 결과 목록이 처음으로 돌아가지 않고 보던 자리가 그대로 유지된다.


### TC-SEARCH-HOME-FEATURE-028: 결과를 선택해 상세 화면에 다녀와도 보던 자리를 유지한다

- 근거: `feature > 진입과 검색`
- Given: 질의 `여행`의 메모 결과를 목록 아래쪽까지 내려 보고 있다.
- When: 사용자가 보이는 결과를 선택해 상세 화면으로 이동했다가 뒤로 돌아온다.
- Then: 결과 목록이 처음으로 돌아가지 않고 떠나기 전에 보던 결과가 그대로 보인다.

### TC-SEARCH-HOME-FEATURE-029: 고친 질의가 반영된 뒤 원래 검색어로 되돌리면 처음부터 본다

- 근거: `feature > 진입과 검색`
- Given: 질의 `여행`의 메모 결과를 목록 아래쪽까지 내려 보고 있다.
- When: 사용자가 질의 끝에 글자를 하나 더 입력해 그 질의가 결과에 반영된 뒤, 그 글자를 지워 `여행`으로 되돌린다.
- Then: 결과 목록의 처음부터 결과가 보인다.

### TC-SEARCH-HOME-FEATURE-004: 질의를 비우면 결과가 비워진다

- 근거: `feature > 진입과 검색`
- Given: 질의 `여행`의 결과가 표시되어 있다.
- When: 사용자가 질의를 모두 지운다.
- Then: 네 유형의 결과에 항목이 하나도 표시되지 않고, 결과가 없음을 알리는 안내도 표시되지 않는다.

### TC-SEARCH-HOME-FEATURE-005: 시작 유형의 결과를 먼저 본다

- 근거: `domain > 진입 경로와 시작 유형`
- Given: 저장된 메모, 태그, 장소, 웹 항목이 있다.
- When: 사용자가 시작 유형이 테스트 데이터의 유형으로 정해진 SearchHome 화면에 진입한다.
- Then: 보고 있는 유형이 그 유형이고 그 유형의 결과가 표시된다.
- 테스트 데이터:

| 시작 유형 |
| --- |
| 메모 |
| 태그 |
| 장소 |
| 웹 |

각 진입 경로가 어느 시작 유형을 지정하는지는 [MoreHome 테스트 케이스](./more-home.md), [MemoHome 목록 테스트 케이스](./memo-home.md), [TagHome 목록 테스트 케이스](./tag-home.md), [PlaceHome 테스트 케이스](./place-home.md), [WebHome 테스트 케이스](./web-home.md)에서 다룬다.

### TC-SEARCH-HOME-FEATURE-015: 시작 유형과 관계없이 네 유형의 결과를 같은 기준으로 채운다

- 근거: `domain > 진입 경로와 시작 유형`
- Given: 질의 `여행`을 만족하는 메모, 태그, 장소, 웹 항목이 각각 저장되어 있고, 웹 유형으로 시작해 진입했다.
- When: 사용자가 질의 `여행`을 입력하고 보고 있는 유형을 `메모`로 바꾼다.
- Then: `여행` 기준의 메모 결과가 표시된다.

### TC-SEARCH-HOME-FEATURE-006: 유형을 바꾸면 그 유형의 결과를 본다

- 근거: `feature > 유형별 결과 확인`
- Given: 질의의 결과가 네 유형에 각각 있고 메모 결과를 보고 있다.
- When: 사용자가 보고 있는 유형을 테스트 데이터의 유형으로 바꾼다.
- Then: 그 유형의 결과가 표시되고 다른 유형의 결과는 표시되지 않는다.
- 테스트 데이터:

| 바꾼 유형 |
| --- |
| 태그 |
| 장소 |
| 웹 |

### TC-SEARCH-HOME-FEATURE-007: 유형을 바꿔도 질의가 유지된다

- 근거: `feature > 유형별 결과 확인`
- Given: 질의 `여행`을 입력해 메모 결과를 보고 있다.
- When: 사용자가 보고 있는 유형을 `태그`로 바꾼다.
- Then: 검색어 입력에 `여행`이 그대로 남아 있고, 사용자가 검색을 다시 실행하지 않아도 `여행` 기준의 태그 결과가 표시된다.

### TC-SEARCH-HOME-FEATURE-008: 각 유형의 결과에서 정해진 내용을 확인한다

- 근거: `feature > 유형별 결과 확인`
- Given: 테스트 데이터의 유형에 결과가 하나 있다.
- When: 사용자가 그 유형의 결과를 확인한다.
- Then: 테스트 데이터의 내용이 결과에 표시된다.
- 테스트 데이터:

| 유형 | 표시되는 내용 |
| --- | --- |
| 메모 | 제목, 컬러, 기간이 있으면 기간 |
| 태그 | 이모지, 제목, 컬러 |
| 장소 | 제목, 주소, 컬러 |
| 웹 | 제목, URL |

### TC-SEARCH-HOME-FEATURE-016: 질의를 입력했는데 결과가 없으면 결과 없음 안내를 표시한다

- 근거: `feature > 빈 결과와 실패`, `domain > 결과 없음 판정`
- Given: 질의 `여행`을 입력했고, 테스트 데이터의 유형에 그 질의를 만족하는 항목이 없도록 조회 결과가 정해져 있으며 그 유형의 결과 준비가 끝났다.
- When: 사용자가 그 유형의 결과를 확인한다.
- Then: 결과 항목 대신 질의에 맞는 항목이 없으며 다른 질의로 다시 찾을 수 있음을 알리는 안내가 표시되고, 로딩 안내나 오류 안내는 표시되지 않는다.
- 테스트 데이터:

| 유형 |
| --- |
| 메모 |
| 태그 |
| 장소 |
| 웹 |

### TC-SEARCH-HOME-FEATURE-017: 결과를 조회하지 못하면 결과 없음 안내를 표시한다

- 근거: `feature > 빈 결과와 실패`, `domain > 결과 없음 판정`
- Given: 질의 `여행`을 입력했고 결과 조회가 실패하도록 정해져 있다.
- When: 사용자가 결과를 확인한다.
- Then: 결과가 없을 때와 같은 안내가 표시되고, 별도의 오류 안내나 다시 시도하는 동작은 표시되지 않는다.

### TC-SEARCH-HOME-FEATURE-018: 질의가 비어 있으면 결과 없음 안내를 표시하지 않는다

- 근거: `domain > 결과 없음 판정`
- Given: 질의가 비어 있고 어느 유형을 확인해도 그 유형의 결과 준비가 끝나도록 정해져 있다.
- When: 사용자가 네 유형의 결과를 차례로 확인한다.
- Then: 어느 유형에도 결과 없음 안내가 표시되지 않는다.

### TC-SEARCH-HOME-FEATURE-019: 결과를 준비하는 동안에는 결과 없음 안내를 표시하지 않는다

- 근거: `domain > 결과 없음 판정`
- Given: 질의 `여행`을 입력했고 그 유형의 결과 준비가 끝나지 않았다.
- When: 사용자가 그 유형의 결과를 확인한다.
- Then: 결과 없음 안내가 표시되지 않는다.

### TC-SEARCH-HOME-FEATURE-020: 결과가 있으면 결과 없음 안내를 표시하지 않는다

- 근거: `domain > 결과 없음 판정`
- Given: 질의 `여행`을 만족하는 메모가 하나 이상 있도록 조회 결과가 정해져 있다.
- When: 사용자가 메모 결과를 확인한다.
- Then: 메모 결과가 표시되고 결과 없음 안내는 표시되지 않는다.

### TC-SEARCH-HOME-FEATURE-011: 한 유형이 비어 있어도 다른 유형의 결과를 확인한다

- 근거: `feature > 빈 결과와 실패`
- Given: 질의 `여행`의 메모 결과는 없어 결과 없음 안내가 표시되어 있고 태그 결과는 있도록 조회 결과가 정해져 있다.
- When: 사용자가 보고 있는 유형을 `태그`로 바꾼다.
- Then: 태그 결과가 표시되고 결과 없음 안내는 표시되지 않으며, 검색어 입력에 `여행`이 그대로 남아 있다.

### TC-SEARCH-HOME-FEATURE-012: 결과를 선택하면 그 항목의 상세 화면으로 이동한다

- 근거: `feature > 상세로 이동`, `domain > 상세로 이동하는 대상`
- Given: 테스트 데이터의 유형에 결과가 하나 표시되어 있다.
- When: 사용자가 그 결과를 선택한다.
- Then: 그 항목을 대상으로 테스트 데이터의 상세 화면으로 이동하는 동작이 한 번 실행된다.
- 테스트 데이터:

| 유형 | 이동하는 화면 |
| --- | --- |
| 메모 | MemoDetail |
| 태그 | TagDetail |
| 장소 | PlaceDetail |
| 웹 | WebDetail |

### TC-SEARCH-HOME-FEATURE-013: 자리 표시 상태의 자리는 선택할 수 없다

- 근거: `domain > 상세로 이동하는 대상`
- Given: 결과에 아직 내용이 준비되지 않은 자리가 있다.
- When: 사용자가 그 자리를 선택한다.
- Then: 상세 화면으로 이동하는 동작이 실행되지 않는다.

### TC-SEARCH-HOME-FEATURE-014: 뒤로가기를 실행하면 이전 화면으로 돌아간다

- 근거: `feature > 뒤로가기`
- Given: SearchHome 화면이 표시되어 있다.
- When: 사용자가 뒤로가기를 실행한다.
- Then: 화면을 벗어나는 동작이 한 번 실행된다.

### TC-SEARCH-HOME-FEATURE-021: 화면에 처음 진입하면 질의 입력에 초점이 있다

- 근거: `feature > 진입과 검색`
- Given: 사용자가 검색을 선택했다.
- When: SearchHome 화면이 처음 표시된다.
- Then: 입력 초점이 질의 입력에 있다.

### TC-SEARCH-HOME-FEATURE-022: 상세에서 돌아오면 질의 입력에 초점을 다시 두지 않는다

- 근거: `feature > 상세로 이동`
- Given: 질의를 입력해 결과를 확인한 뒤 상세로 이동했고, 질의 입력에 초점이 없는 상태로 만들었다.
- When: 사용자가 상세에서 뒤로 돌아와 SearchHome 화면을 다시 본다.
- Then: 입력 초점이 질의 입력에 다시 놓이지 않는다.
- 작성하지 않는 이유: 상세로 이동했다가 돌아오는 내비게이션 전환과 그때 화면이 유지되는 범위를 호스트 테스트에서 결정적으로 재현할 수 없다. 내비게이션 전환을 제어할 수 있는 테스트 환경이 갖춰지면 작성한다.

### TC-SEARCH-HOME-FEATURE-024: 정렬은 유형마다 따로 고른다

- 근거: `feature > 정렬 선택`
- Given: SearchHome 화면에서 메모와 태그 유형의 결과가 모두 제목순이다.
- When: 사용자가 메모 유형에서 정렬을 최근 수정순으로 바꾼다.
- Then: 메모 유형의 결과는 최근 수정순으로 다시 놓이고, 태그 유형의 결과는 제목순 그대로다.

### TC-SEARCH-HOME-FEATURE-025: 질의를 바꿔도 각 유형에서 고른 정렬이 유지된다

- 근거: `feature > 정렬 선택`
- Given: SearchHome 화면의 메모 유형에서 정렬을 최근 수정순으로 바꿨다.
- When: 사용자가 질의를 `여행`으로 바꾼 뒤 다시 `회의`로 바꾼다.
- Then: 두 질의의 메모 결과가 모두 최근 수정순으로 놓인다.

## domain

### TC-SEARCH-HOME-DOMAIN-001: 빈 질의에서는 네 유형의 결과가 모두 비어 있다

- 근거: `domain > 질의`
