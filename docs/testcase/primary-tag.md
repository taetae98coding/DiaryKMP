# 대표 태그 테스트 케이스

기준 스펙: [대표 태그 앱 스펙](../spec/client/primary-tag.md), [대표 태그 공통 스펙](../spec/common/primary-tag.md)

이 문서에서 `domain > 캘린더 표시 색상`, `domain > 기기에서의 대표 태그 변경` 절은 [대표 태그 앱 스펙](../spec/client/primary-tag.md)이 소유한다. 나머지 케이스의 절은 [대표 태그 공통 스펙](../spec/common/primary-tag.md)이 소유한다.

대상 항목은 메모와 디데이다. 두 항목의 결과가 같은 규칙은 메모 케이스와 디데이 케이스를 따로 두어 각 항목의 저장과 동기화로 판정한다. `domain > 대표 태그와 연결의 관계`와 `data > 대표 태그를 함께 바꾸는 저장`은 [메모 태그 테스트 케이스](./memo-tag.md)와 [디데이 태그 테스트 케이스](./dday-tag.md)가 각 항목의 케이스로 덮는다.

## domain

### TC-722c3857-c84d-4d3c-b093-2b02d423b38b: 대표 태그를 다시 지정하면 이전 대표 태그를 대체한다

- 근거: `domain > 대표 태그`
- Given: 대표 태그로 한 태그가 지정된 메모가 기기에 저장되어 있다.
- When: 같은 메모의 대표 태그를 다른 태그로 지정해 저장한다.
- Then: 조회한 메모의 대표 태그는 새로 지정한 태그 하나이고, 이전에 지정되어 있던 태그는 대표 태그로 남지 않는다.

### TC-02c2e084-60aa-49d7-807a-d754c9f79926: 태그를 삭제해도 그 태그를 대표 태그로 가진 메모의 지정이 유지된다

- 근거: `domain > 삭제와 대표 태그`
- Given: 한 태그가 메모의 대표 태그로 지정되어 있고 두 항목이 모두 기기에 저장되어 있다.
- When: 그 태그를 삭제 상태로 바꾼다.
- Then: 메모를 조회하면 삭제한 태그의 대표 태그 지정이 그대로 남아 있다.

### TC-e945777c-6c14-4d7c-957f-02db8bb12237: 메모를 완료하거나 다시 시작하거나 삭제해도 대표 태그 지정이 유지된다

- 근거: `domain > 삭제와 대표 태그`, `domain > 항목 변경과 대표 태그`
- Given: 대표 태그가 지정된 메모가 기기에 저장되어 있다.

- Then: 메모를 조회하면 대표 태그 지정이 바뀌지 않고 그대로 남아 있다.

### TC-b4e056d4-5469-4f60-aca0-9cd6510a6ff7: 새 방식에서 대표 태그를 빠뜨린 디데이 업로드는 거절된다

- 근거: [데이터 동기화 서버 스펙의 이전 버전 앱의 디데이 요청](../spec/server/data-sync.md#이전-버전-앱의-디데이-요청)
- Given: 새 방식으로 디데이를 올리는 요청에 대표 태그 정보가 빠진 디데이가 담겨 있다.
- When: 서버가 그 요청을 받는다.
- Then: 요청 전체가 잘못된 요청으로 거절되어 아무것도 반영되지 않는다.
- 작성하지 않는 이유: 서버의 요청 확인 규칙이어서 서버의 응답과 저장 결과를 관찰해야 하므로 앱의 단위 테스트 환경에서 결정적으로 판정할 수 없다. 서버 정책 테스트 환경이 마련되면 작성한다. 앱이 대표 태그를 빠뜨리지 않고 담는 결과는 TC-ef9ab8da-d0ab-46fb-8a64-b2155478acfb로 확인한다.
