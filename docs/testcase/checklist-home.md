# ChecklistHome 테스트 케이스

기준 스펙: [ChecklistHome 화면 스펙](../spec/client/checklist-home.md)

목록 카드의 삭제 상호작용, 페이지 조회 자리 표시, 목록 빈 상태, 새로고침은 공통 스펙이 정한 규칙을 이 화면에 적용한 결과를 이 문서가 확인한다.

추가 단축키 케이스의 `근거`가 가리키는 절은 공통 규칙을 [목록 추가 단축키 스펙](../spec/client/list-add-shortcut.md)에 위임한다.

화면에 보이는 문구와 접근성 이름은 [ChecklistHome 화면 디자인](../design/checklist-home.md)이 정한 문구를 기대 결과로 쓴다.

## feature

### TC-CHECKLIST-HOME-FEATURE-001: 상단 바에 화면 제목을 표시한다

- 근거: `feature > 화면 내용`
- Given: 사용자 언어가 한국어다.
- When: 사용자가 ChecklistHome 화면을 확인한다.
- Then: 상단 바에 제목 `체크리스트` 문구가 표시된다.

### TC-CHECKLIST-HOME-FEATURE-005: 제목, 뒤로가기, 체크리스트 목록과 체크리스트 추가 외의 정보와 동작을 두지 않는다

- 근거: `feature > 화면 내용`
- Given: 사용자 언어가 한국어이고, 현재 계정에 체크리스트가 하나 있다.
- When: 사용자가 ChecklistHome 화면을 확인한다.
- Then: 화면에는 제목 `체크리스트`, 뒤로가기, 체크리스트 목록과 체크리스트 추가만 있고, 그 밖의 정보나 선택할 수 있는 동작은 없다.

### TC-CHECKLIST-HOME-FEATURE-006: 계정에 저장된 체크리스트를 제목과 진행 정도로 표시한다

- 근거: `feature > 체크리스트 목록`
- Given: 현재 계정에 노출 기준을 만족하는 체크리스트가 여러 개 있고, 각 체크리스트에 체크한 항목과 체크하지 않은 항목이 있다.
- When: ChecklistHome 화면이 표시된다.
- Then: 그 체크리스트가 모두 목록에 나타나고, 각 항목에서 제목과 그 체크리스트의 체크한 항목 수와 전체 항목 수를 확인할 수 있다.

### TC-CHECKLIST-HOME-FEATURE-007: 체크리스트 카드에는 제목과 진행 정도 외의 글을 표시하지 않는다

- 근거: `feature > 체크리스트 목록`
- Given: 현재 계정에 체크리스트가 있다.
- When: ChecklistHome 화면이 표시된다.
- Then: 그 체크리스트 카드에 보이는 글은 제목과 진행 정도뿐이며, 설명이나 체크 항목의 내용 같은 다른 글은 표시되지 않는다.

### TC-CHECKLIST-HOME-FEATURE-008: 체크리스트를 추가하면 목록에 나타난다

- 근거: `feature > 체크리스트 목록`
- Given: ChecklistHome 화면에 체크리스트 목록이 표시되어 있다.
- When: 노출 기준을 만족하는 체크리스트가 새로 저장된다.
- Then: 별도 조작 없이 그 체크리스트가 목록에 나타난다.

### TC-CHECKLIST-HOME-FEATURE-009: 목록의 체크리스트를 선택하면 그 체크리스트의 ChecklistDetail 화면으로 이동한다

- 근거: `feature > 체크리스트 목록`
- Given: ChecklistHome 화면에 체크리스트가 하나 이상 표시되어 있다.
- When: 사용자가 목록의 체크리스트 하나를 선택한다.
- Then: 선택한 그 체크리스트의 ChecklistDetail 화면으로 이동하는 동작이 한 번 실행된다.

### TC-CHECKLIST-HOME-FEATURE-010: 아직 준비되지 않은 자리는 선택해도 이동하지 않는다

- 근거: `feature > 체크리스트 목록`
- Given: ChecklistHome 목록에 아직 준비되지 않은 자리가 표시되어 있다.
- When: 사용자가 그 자리를 선택한다.
- Then: ChecklistDetail 화면으로 이동하는 동작이 실행되지 않는다.

### TC-CHECKLIST-HOME-FEATURE-011: 체크리스트 추가를 선택하면 ChecklistAdd 화면으로 이동한다

- 근거: `feature > 체크리스트 추가로 이동`
- Given: ChecklistHome 화면이 표시되어 있고 목록이 테스트 데이터의 상태다.
- When: 사용자가 체크리스트 추가를 선택한다.
- Then: ChecklistAdd 화면으로 이동하는 동작이 한 번 실행된다.
- 테스트 데이터:

  | 목록 상태 |
  | --- |
  | 체크리스트가 표시되어 있음 |
  | 빈 상태 안내가 표시되어 있음 |

### TC-CHECKLIST-HOME-FEATURE-012: 추가 단축키를 누르면 ChecklistAdd 화면으로 이동한다

- 근거: `feature > 체크리스트 추가로 이동`
- Given: 물리 키보드를 사용할 수 있고 ChecklistHome 화면이 표시되어 있다.
- When: 사용자가 추가 단축키를 누른다.
- Then: ChecklistAdd 화면으로 한 번 이동한다.

### TC-CHECKLIST-HOME-FEATURE-013: 체크리스트 추가는 접근성 이름으로 제공된다

- 근거: `feature > 화면 내용`
- Given: ChecklistHome 화면이 표시되어 있고, 사용자 언어가 테스트 데이터의 언어다.
- When: 사용자가 체크리스트 추가를 찾는다.
- Then: 체크리스트 추가가 디자인이 정한 그 언어의 접근성 이름으로 제공된다.
- 테스트 데이터:

  | 언어 |
  | --- |
  | 한국어 |
  | 그 외 기본 |

### TC-CHECKLIST-HOME-FEATURE-003: 뒤로가기를 선택하면 이전 화면으로 돌아간다

- 근거: `feature > 뒤로가기`
- Given: 사용자가 `더보기`의 `체크리스트` 바로가기로 ChecklistHome 화면에 들어와 있다.
- When: 사용자가 뒤로가기를 선택한다.
- Then: 이전 화면으로 돌아가는 동작이 한 번 실행된다.

### TC-CHECKLIST-HOME-FEATURE-014: 표시할 체크리스트가 없으면 빈 상태 안내를 표시한다

- 근거: `feature > 빈 상태`
- Given: 현재 계정에 노출 기준을 만족하는 체크리스트가 하나도 없으며 목록의 준비가 끝났다.
- When: ChecklistHome 화면이 표시된다.
- Then: 목록 자리에 아직 체크리스트가 없으며 새로 추가할 수 있음을 알리는 빈 상태 안내가 표시된다.

### TC-CHECKLIST-HOME-FEATURE-015: 목록을 준비하는 동안에는 빈 상태 안내를 표시하지 않는다

- 근거: `feature > 빈 상태`
- Given: 체크리스트 목록의 준비가 아직 끝나지 않아 표시된 체크리스트가 하나도 없다.
- When: ChecklistHome 화면이 표시된다.
- Then: 빈 상태 안내가 표시되지 않는다.

### TC-CHECKLIST-HOME-FEATURE-016: 표시할 체크리스트가 있으면 빈 상태 안내를 표시하지 않는다

- 근거: `feature > 빈 상태`
- Given: 현재 계정에 노출 기준을 만족하는 체크리스트가 있다.
- When: ChecklistHome 화면이 표시된다.
- Then: 체크리스트가 목록에 표시되고 빈 상태 안내는 표시되지 않는다.

### TC-CHECKLIST-HOME-FEATURE-017: 목록을 당기면 계정 데이터의 서버 동기화가 요청된다

- 근거: `feature > 새로고침`
- Given: 인증된 사용자 계정이 확인된 상태로 ChecklistHome 화면이 테스트 데이터의 상태로 표시되어 있고 진행 중인 동기화가 없다.
- When: 사용자가 목록 영역을 아래로 당겨 새로고침을 요청한다.
- Then: 계정 데이터의 서버 동기화가 한 번 요청된다.
- 테스트 데이터:

  | 목록 상태 |
  | --- |
  | 체크리스트가 표시되어 있음 |
  | 빈 상태 안내가 표시되어 있음 |

### TC-CHECKLIST-HOME-FEATURE-018: 새로고침이 실행되는 동안 진행이 표시된다

- 근거: `feature > 새로고침`
- Given: ChecklistHome 화면이 표시되어 있고 진행 중인 동기화가 없다.
- When: 사용자가 당겨서 요청한 동기화가 실행되기 시작한 뒤 성공 또는 실패로 끝난다.
- Then: 실행되는 동안 목록 영역에 진행 표시가 나타나고, 끝나면 사라진다.

### TC-CHECKLIST-HOME-FEATURE-019: 체크리스트 카드를 삭제 방향으로 밀면 삭제되고 안내와 실행 취소가 표시된다

- 근거: `feature > 삭제`
- Given: ChecklistHome 화면에 체크리스트가 표시되어 있으며 삭제가 성공하도록 설정되어 있다.
- When: 사용자가 그 체크리스트 카드를 오른쪽에서 왼쪽으로 민다.
- Then: 확인을 되묻지 않고 그 체크리스트의 삭제가 한 번 요청되며, 삭제되었음을 알리는 안내와 `실행 취소` 동작이 표시된다.

### TC-CHECKLIST-HOME-FEATURE-020: 삭제를 실행 취소하면 그 체크리스트의 삭제가 되돌려진다

- 근거: `feature > 삭제`
- Given: ChecklistHome 화면에서 체크리스트를 삭제해 안내와 실행 취소 동작이 표시되어 있다.
- When: 사용자가 실행 취소를 선택한다.
- Then: 그 체크리스트를 삭제되지 않은 상태로 되돌리는 요청이 한 번 일어난다.

### TC-CHECKLIST-HOME-FEATURE-021: 체크리스트 카드를 반대 방향으로 밀면 아무 동작도 실행하지 않는다

- 근거: `feature > 삭제`
- Given: ChecklistHome 화면에 체크리스트가 표시되어 있다.
- When: 사용자가 그 체크리스트 카드를 왼쪽에서 오른쪽으로 민다.
- Then: 삭제가 요청되지 않고 체크리스트가 목록에 그대로 남으며 안내도 표시되지 않는다.

### TC-CHECKLIST-HOME-FEATURE-022: 아직 준비되지 않은 자리는 밀어도 삭제되지 않는다

- 근거: `feature > 삭제`
- Given: ChecklistHome 화면에 아직 준비되지 않은 자리가 표시되어 있다.
- When: 사용자가 그 자리를 오른쪽에서 왼쪽으로 민다.
- Then: 삭제가 요청되지 않는다.

### TC-CHECKLIST-HOME-FEATURE-023: 안내가 보이는 동안 다른 체크리스트를 삭제하면 마지막 삭제의 안내만 남는다

- 근거: `feature > 안내와 실행 취소`
- Given: ChecklistHome 화면에서 체크리스트 A를 삭제해 안내가 표시되어 있다.
- When: 안내가 사라지기 전에 체크리스트 B가 삭제되고, 이어서 사용자가 실행 취소를 선택한다.
- Then: 삭제 안내는 하나만 표시되고, 실행 취소는 체크리스트 B에만 적용되며 체크리스트 A는 되돌려지지 않는다.

### TC-CHECKLIST-HOME-FEATURE-024: 삭제가 저장되지 못하면 안내를 표시하지 않는다

- 근거: `feature > 안내와 실행 취소`
- Given: 체크리스트 삭제의 저장이 실패하도록 설정되어 있다.
- When: 사용자가 목록에서 체크리스트를 삭제한다.
- Then: 삭제 안내와 실행 취소 동작이 제공되지 않는다.

### TC-CHECKLIST-HOME-FEATURE-025: 실행 취소를 선택하지 않으면 안내가 잠시 뒤 사라지고 되돌릴 수 없다

- 근거: `feature > 안내와 실행 취소`
- Given: ChecklistHome 화면에서 체크리스트를 삭제해 안내가 표시되어 있다.
- When: 사용자가 실행 취소를 선택하지 않고 안내가 저절로 사라질 때까지 기다린다.
- Then: 안내와 실행 취소 동작이 사라지고, 삭제를 되돌리는 요청은 일어나지 않는다.

### TC-CHECKLIST-HOME-FEATURE-026: 안내가 보이는 동안 화면을 떠나면 안내가 닫히고 되돌릴 수 없다

- 근거: `feature > 안내와 실행 취소`
- Given: ChecklistHome 화면에서 체크리스트를 삭제해 안내와 실행 취소 동작이 표시되어 있다.
- When: 사용자가 ChecklistHome 화면을 떠났다가 다시 돌아온다.
- Then: 안내와 실행 취소 동작이 보이지 않고, 삭제를 되돌리는 요청은 일어나지 않는다.

## domain

### TC-CHECKLIST-HOME-DOMAIN-001: 현재 계정과 연결되고 삭제되지 않은 체크리스트만 노출한다

- 근거: `domain > 목록에 노출하는 체크리스트`
- Given: 현재 계정과 연결된 체크리스트, 현재 계정과 연결되었지만 삭제된 체크리스트, 다른 계정과 연결된 체크리스트가 저장되어 있다.
- When: 체크리스트 목록을 조회한다.
- Then: 현재 계정과 연결되고 삭제되지 않은 체크리스트만 조회된다.

### TC-CHECKLIST-HOME-DOMAIN-002: 현재 계정을 확인할 수 없으면 노출하는 체크리스트가 없다

- 근거: `domain > 목록에 노출하는 체크리스트`
- Given: 현재 계정 조회가 실패하도록 설정되어 있다.
- When: 체크리스트 목록을 조회한다.
- Then: 노출하는 체크리스트가 없고 계정 조회의 실패가 그대로 전달된다.

### TC-CHECKLIST-HOME-DOMAIN-003: 진행 정도는 삭제되지 않은 체크 항목만 센다

- 근거: `domain > 진행 정도`
- Given: 체크리스트에 테스트 데이터의 체크 항목이 저장되어 있다.
- When: 체크리스트 목록을 조회한다.
- Then: 그 체크리스트의 체크한 항목 수와 전체 항목 수가 테스트 데이터의 기대 결과로 조회된다.
- 테스트 데이터:

  | 체크 항목 | 체크한 항목 수 | 전체 항목 수 |
  | --- | --- | --- |
  | 없음 | 0 | 0 |
  | 체크한 항목 2개, 체크하지 않은 항목 1개 | 2 | 3 |
  | 체크한 항목 1개, 체크하지 않은 항목 1개, 삭제된 체크한 항목 1개, 삭제된 체크하지 않은 항목 1개 | 1 | 2 |
  | 모두 체크함 3개 | 3 | 3 |

### TC-CHECKLIST-HOME-DOMAIN-004: 목록은 제목 오름차순으로 정렬하고 진행 정도는 순서에 영향을 주지 않는다

- 근거: `domain > 목록 정렬`
- Given: 현재 계정에 제목이 서로 다르고 진행 정도가 서로 다른 체크리스트가 여러 개 있다.
- When: 체크리스트 목록을 조회한다.
- Then: 체크리스트가 진행 정도와 관계없이 제목 오름차순으로 조회된다.

### TC-CHECKLIST-HOME-DOMAIN-005: 저장 상태가 바뀌면 노출 기준과 정렬 기준으로 목록과 진행 정도를 갱신한다

- 근거: `domain > 목록 갱신`
- Given: 체크리스트 목록이 조회되어 있다.
- When: 테스트 데이터의 변경이 저장된다.
- Then: 목록이 테스트 데이터의 기대 결과로 갱신된다.
- 테스트 데이터:

  | 저장 변경 | 기대 결과 |
  | --- | --- |
  | 노출 기준을 만족하는 체크리스트 추가 | 제목 순서에 맞는 자리에 나타남 |
  | 목록에 있는 체크리스트가 삭제 상태로 변경 | 목록에서 사라짐 |
  | 삭제 상태였던 체크리스트가 미삭제로 변경(실행 취소) | 제목 순서에 맞는 자리에 다시 나타남 |
  | 목록에 있는 체크리스트의 제목이 수정됨 | 바뀐 제목으로 제목 순서에 맞는 자리로 옮겨짐 |
  | 목록에 있는 체크리스트에 체크 항목이 추가됨 | 그 체크리스트의 전체 항목 수가 하나 늘어남 |
  | 목록에 있는 체크리스트의 체크 항목이 체크됨 | 그 체크리스트의 체크한 항목 수가 하나 늘어남 |
  | 목록에 있는 체크리스트의 체크 항목이 삭제됨 | 그 체크리스트의 진행 정도에서 그 항목이 빠짐 |
  | 서버에서 내려받은 체크리스트와 체크 항목이 기기에 반영됨 | 노출 기준과 정렬 기준, 진행 정도 기준에 따라 목록에 반영됨 |

### TC-CHECKLIST-HOME-DOMAIN-006: 목록의 삭제는 삭제 여부를 삭제로 바꾸고 수정 시각을 갱신한다

- 근거: `domain > 삭제와 실행 취소의 상태 전이`
- Given: 현재 계정과 연결된 체크리스트와 그 체크 항목이 저장되어 있고 현재 시각이 고정되어 있다.
- When: 목록에서 그 체크리스트를 삭제한다.
- Then: 현재 계정의 그 체크리스트만 삭제 여부가 삭제로, 수정 시각이 고정된 현재 시각으로 저장되고, 제목, 설명과 체크 항목의 체크 여부, 삭제 여부, 수정 시각은 바뀌지 않는다.

### TC-CHECKLIST-HOME-DOMAIN-007: 실행 취소는 삭제 여부를 미삭제로 되돌리고 체크 항목은 그대로다

- 근거: `domain > 삭제와 실행 취소의 상태 전이`
- Given: 현재 계정과 연결된 체크리스트가 체크한 항목과 함께 삭제되어 있고 현재 시각이 고정되어 있다.
- When: 그 삭제를 실행 취소한다.
- Then: 현재 계정의 그 체크리스트만 삭제 여부가 미삭제로, 수정 시각이 고정된 현재 시각으로 저장되고, 체크 항목과 체크 상태는 삭제 전과 같다.

### TC-CHECKLIST-HOME-DOMAIN-008: 현재 계정을 확인할 수 없으면 실행 취소가 저장되지 않아 체크리스트가 삭제된 채 남는다

- 근거: `domain > 삭제와 실행 취소의 상태 전이`, `data > 삭제와 실행 취소의 저장`
- Given: 체크리스트를 삭제했고, 현재 계정을 확인할 수 없는 상태다.
- When: 사용자가 그 삭제를 실행 취소한다.
- Then: 체크리스트의 삭제 여부가 바뀌지 않아 삭제된 채로 남고, 저장하지 못했다는 별도 안내도 표시되지 않는다.

### TC-CHECKLIST-HOME-DOMAIN-009: 화면이 재생성되어도 보던 목록 위치를 유지한다

- 근거: `domain > 화면 유지`
- Given: ChecklistHome 화면에 한 화면에 다 들어가지 않는 수의 체크리스트가 표시되어 있고, 사용자가 목록을 내려 뒤쪽의 체크리스트를 보고 있다.
- When: 화면 회전처럼 시스템이 화면을 재생성한다.
- Then: 재생성 전에 보던 체크리스트가 같은 위치에 그대로 표시되고, 목록의 맨 위로 돌아가지 않는다.

### TC-CHECKLIST-HOME-DOMAIN-010: 다른 화면이나 다른 앱에 다녀와도 보던 목록 위치를 유지한다

- 근거: `domain > 화면 유지`
- Given: ChecklistHome 화면에서 사용자가 목록을 내려 뒤쪽의 체크리스트를 보고 있다.
- When: 테스트 데이터의 경로로 나갔다가 ChecklistHome으로 돌아온다.
- Then: 나가기 전에 보던 체크리스트가 같은 위치에 그대로 표시되고, 목록의 맨 위로 돌아가지 않는다.
- 테스트 데이터:

  | 나갔다 돌아오는 경로 |
  | --- |
  | 체크리스트 추가로 이동한 뒤 뒤로가기 |
  | 체크리스트 상세로 이동한 뒤 뒤로가기 |
  | 앱이 백그라운드에 갔다가 같은 화면으로 돌아옴 |

### TC-CHECKLIST-HOME-DOMAIN-011: `더보기`로 나갔다 들어오거나 앱을 다시 실행하면 목록의 맨 위부터 보여 준다

- 근거: `domain > 화면 유지`
- Given: ChecklistHome 화면에서 사용자가 목록을 내려 뒤쪽의 체크리스트를 보고 있다.
- When: 테스트 데이터의 경로로 떠났다가 ChecklistHome에 다시 진입한다.
- Then: 목록의 맨 위 체크리스트부터 표시된다.
- 테스트 데이터:

  | 떠났다 다시 진입하는 경로 |
  | --- |
  | `더보기`로 돌아간 뒤 `체크리스트` 바로가기로 다시 진입 |
  | 앱을 종료한 뒤 다시 실행해 체크리스트 화면에 진입 |

## data

### TC-CHECKLIST-HOME-DATA-001: 현재 계정 기준으로 기기에 저장된 체크리스트를 나누어 불러온다

- 근거: `data > 목록 조회`
- Given: 현재 계정과 연결된 체크리스트가 한 페이지보다 많이 저장되어 있다.
- When: 체크리스트 목록을 조회한다.
- Then: 노출 기준과 정렬 순서를 만족하는 체크리스트가 진행 정도와 함께 페이지 단위로 조회되고, 사용자가 목록을 계속 확인하면 다음 페이지가 이어서 조회된다.

### TC-CHECKLIST-HOME-DATA-002: 목록을 조회하지 못하면 빈 상태로 표시한다

- 근거: `data > 목록 조회`
- Given: 체크리스트 목록 조회가 실패하도록 설정되어 있다.
- When: ChecklistHome 화면이 표시된다.
- Then: 목록에 체크리스트가 하나도 표시되지 않고 빈 상태 안내가 표시되며 오류 안내는 표시되지 않는다.

### TC-CHECKLIST-HOME-DATA-003: ChecklistHome 진입만으로는 서버 조회를 일으키지 않는다

- 근거: `data > 목록 조회`
- Given: 진행 중인 동기화가 없다.
- When: 사용자가 ChecklistHome 화면에 진입하고 새로고침을 요청하지 않는다.
- Then: 계정 데이터의 서버 동기화가 요청되지 않는다.

### TC-CHECKLIST-HOME-DATA-004: 삭제와 실행 취소를 기기에 저장하면 업로드 대기로 기록되고 동기화가 시작된다

- 근거: `data > 삭제와 실행 취소의 저장`
- Given: 로그인한 사용자 계정과 연결된 체크리스트가 저장되어 있고 기기 저장이 성공한다.
- When: 테스트 데이터의 동작을 실행한다.
- Then: 그 체크리스트의 삭제 여부와 수정 시각이 기기에 저장되고, 그 체크리스트가 계정의 업로드 대기 상태로 기록되며 백그라운드 동기화가 한 번 요청된다. 체크리스트 자체, 체크 항목과 계정 연결은 기기에서 지워지지 않고, 체크 항목은 업로드 대기가 되지 않는다.
- 테스트 데이터:

  | 동작 |
  | --- |
  | 삭제 |
  | 실행 취소 |

### TC-CHECKLIST-HOME-DATA-005: 로그인하지 않은 상태의 삭제와 실행 취소는 기기에만 저장된다

- 근거: `data > 삭제와 실행 취소의 저장`
- Given: 로그인하지 않아 게스트 상태의 계정이 확인된다.
- When: 테스트 데이터의 동작을 저장한다.
- Then: 게스트 계정 기준으로 기기에 저장되고 서버 동기화는 요청되지 않는다.
- 테스트 데이터:

  | 동작 |
  | --- |
  | 삭제 |
  | 실행 취소 |

## 작성하지 않는 케이스

- 시스템이 앱을 정리했다가 다시 만든 뒤 보던 목록 위치가 복원되는 결과는 [테스트 케이스 문서 목록](./README.md)에 따라 [MemoHome 테스트 케이스](./memo-home.md)가 대표로 확인한다.
- 데스크톱 앱과 웹에서 체크리스트 추가를 표시하고 선택하는 결과는 그 환경의 화면 테스트로만 관찰할 수 있고 현재 테스트 환경은 Android 화면 테스트만 실행하므로 작성하지 않는다. 데스크톱 앱과 웹의 화면 테스트를 실행할 수 있는 환경이 마련되면 작성한다. Android에서의 결과는 TC-CHECKLIST-HOME-FEATURE-011이 확인한다.
- 선택할 수 있는 동작이 뒤로가기뿐이라던 TC-CHECKLIST-HOME-FEATURE-002와 제목 외의 정보와 준비 중 안내를 표시하지 않는다던 TC-CHECKLIST-HOME-FEATURE-004는 화면에 체크리스트 목록, 추가와 삭제가 더해져 폐기했다. 화면에 두는 요소는 TC-CHECKLIST-HOME-FEATURE-005가, 체크리스트 추가의 접근성 이름은 TC-CHECKLIST-HOME-FEATURE-013이 확인한다.
