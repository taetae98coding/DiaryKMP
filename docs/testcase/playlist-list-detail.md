# Playlist 목록·상세 배치 테스트 케이스

기준 스펙: [Playlist 목록·상세 배치 스펙](../spec/client/playlist-list-detail.md)

이 문서에서 `domain > 배치에 참여하는 화면`, `feature > 추가 진입 수단`, `feature > 함께 사용과 단독 사용` 절은 [목록·상세 배치 공통 스펙](../spec/client/list-detail-pane.md)이 소유한다. 나머지 케이스의 절은 기준 스펙이 소유한다.

표시 비율 조절의 공통 행동과 유지 기준은 [목록·상세 배치 공통 스펙](../spec/client/list-detail-pane.md)에 위임되어 있다. 한 화면만 사용하는 환경에서 곡 목록에서 곡 추가나 곡 상세로 이동하는 케이스는 [PlaylistHome 테스트 케이스](./playlist-home.md)에서, 상세 영역에서 곡을 작성해 추가하는 케이스는 [MusicAdd 테스트 케이스](./music-add.md)에서, 상세 영역에서 곡을 확인하고 수정하고 삭제하는 케이스는 [MusicDetail 테스트 케이스](./music-detail.md)에서 다룬다.

## feature

### TC-PLAYLIST-LIST-DETAIL-FEATURE-001: 목록과 상세를 함께 쓰는 환경에서는 두 영역을 함께 표시한다

- 근거: `feature > 함께 사용과 단독 사용`
- Given: 목록과 상세를 함께 사용할 수 있는 환경이다.
- When: 사용자가 PlaylistHome 화면에 진입한다.
- Then: 곡 목록을 유지한 채 상세 영역에 곡 추가가 함께 표시된다.
- 작성하지 않는 이유: 목록과 상세를 함께 표시하는 창 환경과 두 영역의 전환 이력을 함께 구동해야 관찰할 수 있어 현재 단위 테스트 환경에서는 결정적으로 검증할 수 없다. 창 크기와 여러 화면의 전환 이력을 제어할 수 있는 통합 UI 테스트 환경이 갖춰지면 자동화한다.

### TC-PLAYLIST-LIST-DETAIL-FEATURE-002: 한 화면만 제공하는 환경에서는 현재 화면만 단독으로 표시한다

- 근거: `feature > 함께 사용과 단독 사용`
- Given: 목록과 상세를 함께 사용할 수 없는 환경이다.
- When: 사용자가 곡 목록 또는 곡 추가를 사용한다.
- Then: 현재 사용하는 화면만 단독으로 표시된다.
- 작성하지 않는 이유: 목록과 상세를 함께 표시하는 창 환경과 두 영역의 전환 이력을 함께 구동해야 관찰할 수 있어 현재 단위 테스트 환경에서는 결정적으로 검증할 수 없다. 창 크기와 여러 화면의 전환 이력을 제어할 수 있는 통합 UI 테스트 환경이 갖춰지면 자동화한다.

### TC-PLAYLIST-LIST-DETAIL-FEATURE-003: 상세 영역에 곡 추가가 놓이면 목록에서 추가 수단을 제공하지 않는다

- 근거: `feature > 추가 진입 수단`
- Given: 상세 영역에 곡 추가가 놓여 있다.
- When: 사용자가 곡 목록에서 실행할 수 있는 동작을 확인한다.
- Then: 곡 추가 동작이 제공되지 않는다.

### TC-PLAYLIST-LIST-DETAIL-FEATURE-004: 상세 영역에 곡 추가가 놓여 있지 않으면 목록에서 추가 수단을 제공한다

- 근거: `feature > 추가 진입 수단`
- Given: 상세 영역이 테스트 데이터의 상태다.
- When: 사용자가 곡 목록에서 실행할 수 있는 동작을 확인한다.
- Then: 곡 추가 동작이 제공된다.
- 테스트 데이터:

| 상세 영역 |
| --- |
| 상세 영역을 함께 표시하지 않음 |
| 곡 상세가 놓여 있음 |

### TC-PLAYLIST-LIST-DETAIL-FEATURE-008: 목록에서 곡을 선택하면 상세 영역이 그 곡의 상세로 바뀐다

- 근거: `feature > 상세 영역의 구성`

- When: 사용자가 목록에서 곡 하나를 선택한다.
- Then: 목록은 그대로 유지되고 상세 영역이 그 곡의 MusicDetail로 바뀐다.

### TC-PLAYLIST-LIST-DETAIL-FEATURE-010: 상세에서 곡을 삭제하면 상세 영역이 곡 추가로 되돌아간다

- 근거: `feature > 상세 영역의 구성`

### TC-PLAYLIST-LIST-DETAIL-FEATURE-011: 곡 상세가 놓인 동안 곡 추가를 실행하면 상세 영역이 곡 추가로 바뀐다

## domain

### TC-PLAYLIST-LIST-DETAIL-DOMAIN-001: 곡 목록에서 진입하지 않은 곡 추가는 목록과 함께 표시하지 않는다

- 근거: `domain > 배치에 참여하는 화면`
- Given: 목록과 상세를 함께 사용할 수 있는 환경이다.
- When: 사용자가 곡 목록이 아닌 화면에서 곡 추가로 이동한다.
- Then: 곡 추가를 목록·상세 배치에 참여시키지 않아 단독으로 표시한다.

### TC-PLAYLIST-LIST-DETAIL-DOMAIN-002: 곡 목록에서 이어 진입한 곡 추가는 목록과 함께 표시한다

- 근거: `domain > 배치에 참여하는 화면`
- Given: 목록과 상세를 함께 사용할 수 있는 환경이다.
- When: 사용자가 곡 목록에서 곡 추가로 이동한다.
- Then: 곡 추가를 목록·상세 배치의 상세 영역에 표시한다.

### TC-PLAYLIST-LIST-DETAIL-DOMAIN-003: 곡 목록에서 이어 진입한 곡 상세는 목록과 함께 표시한다

- 근거: `domain > 배치에 참여하는 화면`
- Given: 목록과 상세를 함께 사용할 수 있는 환경이다.
- When: 사용자가 곡 목록에서 곡 상세로 이동한다.
- Then: 곡 상세를 목록·상세 배치의 상세 영역에 표시한다.

### TC-PLAYLIST-LIST-DETAIL-DOMAIN-004: `더보기`로 돌아갔다가 다시 진입하면 상세 영역의 곡 추가는 입력이 모두 비어 있는 상태로 시작한다

- 근거: `domain > 유지와 초기화 기준`
- Given: 목록과 상세 영역이 함께 표시되고 선택한 곡이 없어 상세 영역에 곡 추가가 놓여 있다. 사용자가 곡 추가에 제목, 가수와 링크를 입력했다.
- When: 사용자가 `더보기` 화면으로 돌아갔다가 플레이리스트 화면에 다시 진입한다.
- Then: 상세 영역의 곡 추가는 제목, 가수와 링크가 비어 있다.

### TC-PLAYLIST-LIST-DETAIL-DOMAIN-005: 배치를 떠나기 전에는 상세 영역에서 곡 상세를 보고 돌아와도 곡 추가의 입력이 남는다

- 근거: `domain > 유지와 초기화 기준`
- Given: 목록과 상세 영역이 함께 표시되고 선택한 곡이 없어 상세 영역에 곡 추가가 놓여 있다. 사용자가 곡 추가에 제목, 가수와 링크를 입력했다.
- When: 사용자가 목록에서 곡을 골라 상세 영역에서 곡 상세를 본 뒤 뒤로가기를 사용해 곡 추가로 돌아온다.
- Then: 곡 추가에 입력하던 제목, 가수와 링크가 그대로 남아 있다.

## 작성하지 않는 이유

곡 목록의 뒤로가기 동작으로 상세 영역에 놓인 화면과 관계없이 `더보기` 화면으로 돌아가는 결과는 [PlaylistHome 테스트 케이스](./playlist-home.md)의 TC-PLAYLIST-HOME-FEATURE-014에서 다룬다.

`더보기`로 돌아갔다가 다시 진입하거나 앱을 다시 실행했을 때 상세 선택이 초기화되어 상세 영역이 곡 추가로 돌아가는 결과는 실행 경계를 함께 판정해야 하므로 아래 비율 초기화와 같은 이유로 자동화하지 않는다.

두 영역의 표시 비율 조절과 조절 중 즉시 반영, 화면 재생성·백그라운드 복귀 후 비율 유지, `더보기`로 돌아갔다가 다시 진입하거나 앱을 다시 실행한 뒤의 기본 비율 초기화는 실제 화면 크기와 실행 경계를 함께 판정해야 한다. 현재 테스트 환경에서는 결정적으로 자동화할 수 없으며, 화면 크기와 실행 경계를 제어·관찰할 수 있는 통합 UI 테스트 환경이 갖춰지면 자동화한다.
